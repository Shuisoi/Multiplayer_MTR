# 249 — 设计加速指标：0 → 100 km/h

用户口径（2026-09-23）：

> 按计划 0-100 加速多长时间？

"按计划"= 用 244 的 BR 101 真车数据 + 247 的编组聚合，满油门、干轨、平直道、不做手柄/定速限力。
算法就是实机在跑的那一条（`TrainPhysics.tractionAccelerationMps2`，10 ms 定步长积分到 100 km/h）：

```
a = ( min(F_max, P/v) − R(v) ) / (λ·m)          v: 0 → 27.78 m/s
```

## 1. 结论

| 车列 | 质量（惯性） | 0 → 100 km/h |
| --- | --- | --- |
| **BR 101 + 2×p1 客车**（现场编组） | 164 t（λ_eq 1.111 ⇒ **182.2 t**） | **17.7 s** |
| BR 101 单车 | 84 t（λ1.16 ⇒ 97.4 t） | 9.4 s |

差别 **8.3 s** —— 这就是"挂两节客车"在 0-100 上的代价（也是 notes/247 里那 30% 之外的另一半手感）。

## 2. 17.7 s 是怎么来的（两段）

| 段 | 速度区间 | 加速度 | 用时 |
| --- | --- | --- | --- |
| 恒力矩段 | 0 → 76.8 km/h | `(300 kN − R)/182.2 t` ≈ **1.63 m/s²** | **13.1 s** |
| 恒功率段 | 76.8 → 100 km/h | `(6.4 MW/v − R)/182.2 t`，1.62 → 1.22 m/s² | **4.6 s** |

折点 = `P/F_max` = 6.4 MW / 300 kN = **21.33 m/s = 76.8 km/h**。

**独立核对（能量下限）**：把 182.2 t 从静止推到 27.78 m/s 需要 `½mv²` = 70.3 MJ；
6.4 MW 全用来加速要 **11.0 s** —— 实际 17.7 s 比它长，正是因为 76.8 km/h 以下受 300 kN 恒力矩限制、
拿不到满功率。量级自洽（若算出小于 11 s 就一定是模型错了）。

## 3. 怎么钉住

`MmtrConsistTractionMappingTests.theDesignZeroToHundredTime()`（读随包配置，10 ms 积分为准）：

- 断言现场编组 **17–19 s**、单车 **8–11 s**、并且挂两节客车必须比单车慢 5 s 以上；
- 日志打印 `[TEST] 0→100 km/h：BR101+2×p1（164 t）= 17.7 s` / `BR101 单车（84 t）= 9.4 s`。

以后谁动了牵引曲线（`maxTractiveEffortN` / `maxPowerW`）、质量（`massKg` / λ）、阻力（A/B/C）
或编组聚合口径，这张表会立刻变 —— 这正是"设计指标"该起的作用。

## 4. 实机怎么对（与 notes/248 的实测一致）

248 里实机实测的两段加速度：起步 **1.640 m/s²**、72→83.6 km/h **1.605 m/s²**；设计值 1.63 / 1.63。
⇒ 实机与"按计划"同一条曲线。若实机的 0-100 明显慢于 17.7 s，只可能是三件事之一：

1. 司机没有给满（AFB 在削力 / 手柄没到底）；
2. 缸压没排空导致牵引被联锁按住一段时间（notes/248 §2，修前要等 ~10 s）；
3. 坡道（当前 `tractionAccelerationMps2` **不含坡度**，坡道项只在 `TrainPhysics.gradeForceN` 里备着，尚未接进控制器）。

## 5. 对照 TSW 的 38 s：反推出来的是什么

用户口径（2026-09-23）：

> 我去模拟火车世界里面开 br101，单车零百加速 38 秒，是不是咱们算的不对了

### 5.1 数据表核对（我们用的数没错）

德文维基百科 DB-Baureihe 101 的技术数据与我们配置里的完全一致：
**Dauerleistung 6400 kW、Anfahrzugkraft 300 kN、Dienstmasse 84 t、Radsatzfahrmasse 21 t（4 轴）、
Treibraddurchmesser 1250 mm（新）/1170 mm（磨耗）、Vmax 220 km/h、Leistungskennziffer 73.6 kW/t**
（[de.wikipedia.org/wiki/DB-Baureihe_101](https://de.wikipedia.org/wiki/DB-Baureihe_101)）。
轮径 1250 mm 也正好对上 S3 后半要用的 `r = 0.625 m`（notes/245）。

### 5.2 反推：38 s 对应什么

用同一套模型（`a = (min(F_max, P/v) − R(v))/(λm)`，10 ms 积分）：

| 假设 | 0-100 km/h |
| --- | --- |
| BR101 单车、数据表满值（300 kN / 6.4 MW / 84 t，λ1.16） | **9.4 s** |
| 单车、**只给连续牵引力 240 kN**（把 300 kN 的起动能力完全不算） | 11.3 s |
| 单车、削到 200 kN | 13.6 s |
| 单车、削到 100 kN | 27.4 s |
| 单车、削到 **70 kN** ⇒ 才等于 TSW 的 38 s | **39.3 s** |
| BR101 + 4×p1（244 t） | 25.9 s |
| BR101 + 6×p1（324 t） | 34.3 s |
| **BR101 + 约 7×p1（≈364 t）** | **≈38 s** |
| BR101 + 8×p1（404 t） | 42.7 s |

两个独立的下界也支持"数据表值"：

- **能量下界**：½mv² = 37.6 MJ，6.4 MW 全部用于加速也要 **5.9 s** —— 9.4 s 只是它的 1.6 倍；
- **黏着**：300 kN / (84 t·g) = **μ 0.364**，正好是干轨上限，也就是说 300 kN 这个数本来就是
  "按 21 t 轴重 × 干轨黏着"反算出来的（真车有 Einzelachsregelung 单轴控制 + 撒砂）。

⇒ **38 s 不能由任何"数据表自洽"的读法得到**：它等价于单机只给 **≈70 kN**（额定的 23%），
或者车列实际有 **≈360–400 t**。

### 5.3 因此要先排除的三件事（TSW 侧）

1. **车列并不"单车"**：TSW 的 BR 101 出场通常挂着客车；38 s 恰好等于"机车 + 6~8 节客车"。
   请看一下 TSW 里编组几节、总重多少（HUD/车辆信息）。
2. **手柄没到底 / AFB 在管**：手册（`BR 101 & Cab-Car Expert Manual`，已入知识库）里 AFB 一节写着
   "起步时牵引力要超过 10 kN、且要在限定时间内超过 2 km/h，否则 AFB 会切断" —— 说明它的 AFB 有自己的一套逻辑，
   司机用 AFB 起步时未必按满牵引走。
3. **空转保护/限流**：Expert 版带单轴控制与防空转，若它在降力，实际牵引会明显低于曲线值。

TSW 是游戏，它的机车加速是**调出来的**（Expert 手册里也没有任何牵引力曲线或加速度指标，
只有制动重量/AFB 操作那套程序）——所以它不能当物理判据。

### 5.5 旁证：TSW 车里的"牵引表"读数（用户 2026-09-23）

> 有个牵引表，上面读数最大 20 kN，但满格是 80 kN

**这块表不是我们的**：全仓检索 `Zugkraft / 牵引力表 / tractionGauge` 只命中本文件的资料行；
我们的 HUD（`MmtrHudLayout` 的 `gauge` 活控件）只做了一块**速度表**（`br101_hud.json` 里 `max: 160`），
没有任何牵引力读数。所以它是 TSW 车里那块。

读数怎么读：

| 假设 | 推论 | 与 38 s 是否自洽 |
| --- | --- | --- |
| 80 kN 是**整车**满量程 | 300 kN 的机车装一块 80 kN 的表 → 满牵引会把针打飞出表盘 | 不自洽 |
| 80 kN 是**每个牵引电机**（BR 101 有 4 台，4×80 = 320 kN ≈ 起动能力 300 kN） | 满格 ✓ 正是这台车的量级 | ✓ |
| 读到的 20 kN/电机 ⇒ **整车 80 kN** | 额定 300 kN 的 **27%** | ✓ 38 s 需要平均 ≈71 kN |

⇒ **两个 TSW 观测（38 s 与 20/80 kN）互相印证**：TSW 里那台 BR 101 只出了约 80 kN（四分之一），
而不是数据表的 300 kN。这不是我们算错，是 TSW 侧要么没给满、要么它自己的模型就这样。

我们自己这边：实机实测 164 t 车列起步 1.640 m/s² ⇒ 反推牵引力 ≈ 300 kN（满值），与设计一致。

**可选（待用户点头）**：

1. 给我们的 BR 101 驾驶台加一块**牵引力表**（0–300 kN，指针跟着**实际施加的**轮周力走）——
   `MmtrHudLayout` 的 `gauge` 现在写死跟速度，需要给它加一个"值来源"字段（speed / traction）；
   这样两边就能 1:1 对比，也省得以后再靠速度序列反推。
2. 车底加 `maxAccelerationMps2`（司机侧起步加速度上限，缺省不限），用来复刻 TSW 那种"轻车也起得温柔"的手感。

### 5.6 "会不会是单轮牵引力？"（用户 2026-09-23）

BR 101 是 **Bo'Bo'**：4 根动轴、4 台牵引电机、**Einzelachsregelung（单轴控制）**
（德文维基技术数据，与本次抓取一致）。所以"每电机 = 每轴 = 每轮对"，而"每车轮"是它的一半。

| 表盘读数口径 | 满量程对应整车 | 读 20 kN 对应整车 | 该整机力下 0-100 | 与实测 38 s |
| --- | --- | --- | --- | --- |
| 每电机 / **每轴**（4 份） | 4×80 = **320 kN** ≈ 起动能力 300 kN ✓ | **80 kN**（额定的 27%） | **≈34 s** | ✓ 同一量级 |
| **每车轮**（8 份） | 8×80 = 640 kN = 额定的 2 倍 ✗ | 160 kN（额定的 53%） | ≈17.6 s | ✗ 差一倍以上 |

⇒ 由"满格 80 kN"这个**量程选择**与"38 s"这个**实测**做交叉判据：
表盘只可能是**每轴/每电机**口径（80 kN 正好压住 75 kN 的额定单轴力），不可能是每车轮
（每车轮满量程该是 ~40 kN）。**两种口径算出的整车力差一倍，实测 38 s 只与"每轴"口径自洽。**
