# 74 - C10 调车进路增强（一）：反向行驶重规划 + 牵出—推进折返规划

> 实机（2026-09-09 19:28 起）：作业单 `loco` 在 aassdd 车场把机车放好、授了调车权、mission 开始自 arm，结果
> `target rail …FFFF24…83-…24…3E is not reachable from the vehicle` —— 进路直接失败。

## 第一层：停着朝向不对 → 反向行驶再规划

机车是车场式停放（`mmtrConsistWalkerFromYard` + A 端驾驶室），车头朝向自己股道的尽头，而它要去的股道在身后。
规划器只做"朝前"的图搜索，朝向反了自然一无所获。

`Vehicle.mmtrMotionSelfArmMission`：规划失败 + 停稳 + 本任务还没反过向时，用 **REV 机制**（同一驾驶室、尾端在前）
翻转行进方向，`mmtrMissionFlippedForTarget` 保证每个任务只反一次，然后下一 tick 用新朝向重新自 arm：

```java
if (!plan.feasible && speed <= 1e-9 && !mmtrMissionFlippedForTarget && selfArmConsistWalker != null) {
    mmtrMissionFlippedForTarget = true;
    applyMmtrTravelReversed(!selfArmConsistWalker.travelReversed());
    refreshMmtrMotionLegs();
    return;   // 下一 tick 重新规划
}
```

日志：`[MMTR-MSG] motion mission could not be planned facing this way (…) - reversed the travel direction on <rail> and retrying`。
（先试过 `changeEnds`：实机日志显示它只换"哪端在前"，walkers 的 `aheadNode` 仍指着尽头，所以改用 REV。）

## 第二层：牵出—推进（setback）规划

真实调车从一条尽头式股道去另一条，必须**先牵出到引线、再推进进另一条岔**——中途反向一次。`MmtrRunPlanner`
新增 `planToRailViaSetback`：BFS 状态 =（节点，来向轨，已反向次数），允许一次零长度的"反向转移"（在同一节点换端后
沿另一条轨出发，包括原路退出）。产出的 Plan 复用既有折返机制（`flipRailHex`/`flipCumulativeM`），车到点停稳、
换端后按已预设的道岔继续跑；停车点比节点回退 `SETBACK_EPS_M = 0.2 m`，避免 walker 提前越到下一轨。

刻意排除"在**起始节点**反向"：那是"停着朝向不对"，由第一层处理；否则规划器会悄悄把停着的车从车场尾部倒着开出去
（`MmtrRunPlannerTests.plannerReachesTheYardRearOnlyThroughAnExplicitReversal` 断言：能规划，但必须带显式折返点）。

## 实机验证（第二轮：进路已规划并开出去）

三个修正之后，实机 20:07 首次成功规划并执行折返进路：

1. **朝向修正**：`MmtrConsistWalker.aheadNode()/enteredFromPosition()` 返回的是 spine 腿的 B 侧/A 侧，**只有朝 B 行驶时才是行进方向**。
   直接改 walker 会破坏连挂闸门等既有语义，所以在规划器侧加了 `travelAheadNode/travelEntryNode`（`travelsTowardB()` 为假时交换），
   三处规划入口统一使用。
2. **道岔可driving性进搜索**：`computeOrderedLegs` 会丢掉折回腿（人字），原实现是"先重建整条路线再校验道岔，失败就整条放弃"；
   现在 BFS 扩展时就用 `turnoutAllows(...)` 过滤，于是能找到"先牵出过岔、再折返推进"的真实走法。

日志：

```

[MMTR-MSG] motion mission MANEUVER self-armed to rail …24…3E stop @395m
```

机车确实按进路开出去了：A 道南下 → 引线 → 南端引轨（计划折返点 154 m）……

## 实机验证（第三轮：作业单自己完成整条调车进路 ✅）

第三个修正：**剩余里程也假设了行进方向**。`offsetM()` 是沿 spine（A→B）量的，朝 A 走时"到前方节点的剩余距离"是
`offsetM()` 而不是 `length - offset`；原算法把折返点算远了一倍，机车因此冲过折返点。修好后实机 20:19:46：

```
[MMTR-RUN] planned via 牵出—推进 setback @138m (rail …4E…61)
[MMTR-MSG] motion mission MANEUVER self-armed to rail …24…3E stop @379m
[MMTR-DRV] flip 换端 at dead end of …4E…61 - continuing to stop target 379.24m
[MMTR-COUP] 连挂完成: …（3 节，48.0 m，车钩间隙 0.3 m）
[MMTR-COUP] 自动车钩挂上: … -> 3 节
[MMTR-JOB] COUPLE done by the automatic coupler (target job rake absorbed)
```

作业单 `loco` → **DONE（step 2/2）**，3 节编组停在新长道。整条链路：作业单放车 → 自动授调车权 →
规划"牵出—推进"折返进路 → 自己开出去 → 折返点换端 → 推进进新道 → 贴住客车 0.3 m → 自动车钩挂上 → 步骤完成。
