# 238 · 定速（AFB）不好用：两个根因与修法

日期：2026-09-23 · 现场（用户在车上跑）：「确实感觉不一样了，但是**定速不好用**」→ 追问后确认症状是
**接近设定速度后停不住、一直往上冲，或在设定值上下晃**；并且明确要求**保留"油门手柄当牵引上限"**的语义，
只调增益/门限。

结论：不是一个问题，是**两个**。第二个是这一轮才被"力模型"放大出来的（原来的加速度口径下，
残余气制动丢掉这件事看不出来）。

---

## 1. 用测试把现场复现出来（不是猜）

新加诊断用例（跑真实控制器 + `ConsistDynamics`，世界里的 BR101 参数）：

**复现 ①：拉过气制动再回"运行"，那几秒会发生什么**（修前）

```
[AFB2] 建满缸压：v=49.90 km/h 缸压=1.000
[AFB2] t=  0.0s v= 50.18 km/h 缸压=0.988 ratio=1.000 rheo=0.000 active=false
[AFB2] t=  5.0s v= 72.70 km/h 缸压=0.000 ratio=1.000 rheo=0.000 active=true   ← 5 s 冲了 22.5 km/h
```

缸压还是 **0.988（闸基本满着）**，牵引比却已经是 **1.000**，而且这 5 s 里**没有减速度**（加速度约 1.25 m/s²
= 功率受限后的满牵引）。定速 100 还挂着，但 AFB 因为"缸压没排空"处于让位状态 → 一路冲到设定速度以上才收。

**复现 ②：高出设定速度时几乎不刹车**（修前）

`AFB_BRAKE_THRESHOLD_MPS = 0.2`（0.72 km/h）才动电阻制动，且增益与牵引共用 `0.15`：
高出 1 km/h 时制动比例只有 `0.15 × 0.28 = 0.042` → 3 kN → 0.04 m/s²，等于没有。
而电阻制动本来就只有牵引力的三分之一（70 kN vs 200 kN），再软就没法保速 —— 现场就是"在设定值上下晃"。

## 2. 根因一：牵引联锁看错了量（**残余气制动被整段丢掉**）

`ThreeHandleDriveController` 原来的合成优先权是：

```java
final boolean pneumaticDemanded = brakePosition > runningPosition();   // 只看**手柄位置**
if (pneumaticDemanded || rheostaticDeceleration > 0) { 制动 } else if (traction > 0) { 牵引 } ...
```

手柄一回"运行"，`pneumaticDemanded` 立刻为假 ⇒ 走**牵引**那一支，而那一支**完全不含气制动力** ——
可是缸压还要按 `airBrakeReleaseRatePerSecond`（默认 0.25/s，满缸压 **4 s**）才排空。
于是"闸还压着、牵引已经满上"，而且残余制动力在物理里被丢了（不是被抵消，是根本没算）。

**修法**：联锁按**缸压**判，不按手柄位置 ——

```java
final boolean pneumaticHolding = pneumaticForceN > serviceForceN * PNEUMATIC_INTERLOCK_FORCE_RATIO; // 1%
if (pneumaticHolding) { tractionRatio = 0; }                 // 闸没松完不许出牵引（真车的牵引联锁）
...
if (pneumaticHolding || rheostaticForceN > 0) { acceleration = -brakingDecelerationMps2(气, 电阻, v); }
```

「刚拉到 8 档那一拍缸压还是 0，别让牵引偷偷生效」这条**原意保留**（缸压 0 ⇒ 联锁成立 ⇒ 不出牵引，
真正制动力那一支由 `rheostaticForceN > 0` 或缸压自己给出）。

修后同一段：

```
[AFB2] 松闸时 49.90 km/h → 5 s 后 48.65 km/h → 30 s 后 99.00 km/h    ← 松闸那 5 s 在**减速**
```

## 3. 根因二：AFB 的保速律太软、门限太大

修前：牵引 `min(cap, 0.15 × 误差)`；制动 **只在误差 > 0.2 m/s 时** 才给 `0.15 × 误差`（同一个增益）。
修后（三个旋钮都可配，默认值即下面这些）：

| 旋钮 | 默认 | 含义 |
| --- | --- | --- |
| `afbGainPerMps` | **0.3**（原 0.15） | 低于设定速度：牵引比例 = 增益 × 速度差，再取手柄上限 |
| `afbBrakeGainPerMps` | **1.0**（新） | 高于设定速度：电阻制动比例 = 增益 × 速度差（1 m/s 误差 = 满电阻制动） |
| `afbBrakeThresholdMps` | **0.05**（原硬编码 0.2） | 带内惰行（0.18 km/h），免得在设定速度附近反复点刹 |

**「手柄当牵引上限」（`afbUsesHandleAsCap=true`）按你的要求一字未改**：手柄在关闭位，AFB 这一侧依然推不动车。

修后（世界里那台 BR101 的参数）：

```
[AFB]  从 0 起步：120 s 后 99.25 km/h，峰值 99.25 km/h          ← 不超调，稳态差 0.75 km/h
[AFB3] 从 120 km/h 起：60 s 后 99.25 km/h，最低 99.25 km/h      ← 收得回来，也不下冲
```

## 4. 顺带修掉一个自己写出来的坑

力必须在 **AFB 定完比例之后**再算：我一开始把 `rheostaticForceN` 提前算（为了判联锁），
结果 AFB 写了 `rheostaticRatio = 1.0`、力却还是用司机手柄那份（0）—— 用例当场抓到
（"比例 1.0、力 0"），已在代码里留注释。

## 7. 遗留（下一件事）

**机辆列车的拖车质量还没有进物理**：`ThreeHandleDriveController` / `NotchedDriveController` / `SteplessDriveController`
都只用 `type.getPhysics()`（= 说话那节车自己的质量），`MmtrComposition`（按车求和力 ÷ 总惯性）**只在
`AIR_BRAKE` 那一路用**。于是 BR101 + 2×p1 实际按 82 t 在算（真实 162 t）：起步/制动都比真车灵一倍左右，
而且"拖车越多越不一样"。这与"力模型"这一轮的初衷（车列 = 各单元之和）是同一件事的收尾，值得单独立项。
