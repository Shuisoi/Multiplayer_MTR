# notes/03-M0 构建经验（2026-09）

## 关键：Gradle -P 参数必须加引号
在本机 pwsh 环境下 `-PminecraftVersion=1.20.4`（不带引号）会被吞掉点号变成 `1`，
导致 BuildTools `split("\\.")[1]` 抛 IndexOutOfBounds。正确写法：
    .\\gradlew.bat fabric:setupFiles fabric:build '-PminecraftVersion=1.20.4'
（任何含点号的 -P 值都要引号。）

## Composite 失败原因（已回退）
game 用 Gradle 8.14 + loom 1.10；engine 用 Gradle 9.5.1 + 新版 shadow/lombok 插件，
includeBuild 在宿主 Gradle 8.14 下不兼容（addVariantsFromConfiguration 等 API 缺失）。
=> 维持上游式集成：scripts/sync-engine.ps1 把 engine shadowJar 同步为
   game/libs/Transport-Simulation-Core-0.0.1.jar（改引擎后跑一次该脚本再构建 game）。

## 构建要点
- JDK21（game 的 BuildTools.javaLanguageVersion 为 17 目标，loom/engine 工具链 21；统一用 21 运行 gradle）
- fabric.mod.json 由模板生成（id=mmtr）；setupFiles 会在 fabric/src/main/java 下生成
  org/mtr/mod/generated/**、Keys.java、TranslationProvider.java 等（不入库，见 .gitignore 候选清单）

## M0b 进展（2026-09，第 2 轮）：引擎侧 bridge spike 通过

### 引擎 standalone 现暴露的 HTTP 面（实证）
- /            : Web 面板/资源包创建器等（MainWebServlet，301 到子路径）
- /mtr/api/map/*: stations-and-routes / departures / arrivals / clients（SystemMapServlet，map UI 用）
- /oba/api/where/* : OBA 实时接口
- /mmtr/api/bridge/* : 【MMTR 新增】BridgeServlet（本次 spike）
     ping    -> {"ok":true,"dimension":"test","vehicles":0}
     vehicles-> {"dimension":..., "vehicles":[...轻量快照...]}
  路由：/mmtr/api/bridge/<endpoint>?dimension=<n>，JSON（ServletBase 统一处理，维度=query）

### 实测延迟（本机 localhost，空世界）
20x ping：~15ms（首请求 11ms 预热）；空 vehicles 返回同样 ~15ms。

### 结论与后续（EngineBridge 剩余工作）
1. C2S 操作通道：引擎侧加 Operation 桥 servlet（把 OperationProcessor 的 QueueObject 语义暴露为
   POST /mmtr/api/bridge/op/<key>，payload=schema 对象 JSON/MessagePack）。
2. 快照完善：vehicles 增加速度/位置/乘客等字段（对齐 VehicleUpdate），按 dimension + 区域/增量。
3. MC 侧：game 增加 org.mtr.mod.bridge.EngineBridge 接口 + EmbeddedEngineBridge（现状）/NetworkEngineBridge
   （java.net.http + 心跳/重连 + 轮询或事件流），在 dev 跑通“外置引擎驱动列车→MC 渲染”的最小闭环。
4. 带宽基准：准备含 N 列车世界，测 vehicles 轮询 10/20Hz 的 bytes/pps/latency（记录 notes/04-带宽基准.md）。
