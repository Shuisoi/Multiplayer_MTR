# 72 - C8 自动车钩（贴上去停稳即挂）

> 用户设计意见（2026-09-09，notes/68、69 尾注）："感觉对准这个事情只适用于下车去连挂，很多动车组和调机
> 都是自动车钩。" → 自动车钩应"接触/停到车钩间距即挂"，K 瞄准保留给人工车钩与下车作业。

## 语义

| 场景 | 行为 |
| --- | --- |
| 机车/动车组（默认自动车钩）+ 活调车授权 + 停稳 + 车钩间距 ≤ 0.75 m + 对接两端都是自动车钩 | **自动挂**（无需 K） |
| 任一端是人工车钩（`mmtrAutoCoupler:false`） | 不自动，仍按 K（人工确认） |
| 混编（一端自动一端人工） | 不自动 |
| 没有活调车授权 | 不自动（站场里偶然停到一起不算连挂） |
| 解挂 | 永远要显式操作（车钩不能自己解） |

## 实现

1. **车底声明**：`VehicleCar.mmtrAutoCoupler`（schema `vehicleCar.json`，**默认 true**）+ `MmtrCarSpec.mmtrAutoCoupler`
   —— 清单 / 作业单 / 编组模板三条创作路径统一走 `MmtrCarSpec`，与 `mmtrCouplerAfter` 同一套路。
2. **判定层** `org.mtr.core.mmtr.MmtrAutoCoupler`：每 tick 一遍，
   - 候选：停稳 + 编组体 + `mmtrShuntAuthorities.active(id)` 且 `covers(当前轨)`；
   - 目标：同轨、同 `enteredFrom`（朝向相对）、车钩间距 ∈ [−0.05, 0.75] m、`MmtrCoupleSurgery.autoCouplersAtJoint`；
   - 取间距最近者，调 `MmtrCoupleSurgery.couple` —— **所有既有闸门照旧生效**（放置合并编组体、节数上限、同轨同向、停稳）。
3. **接缝判定** `MmtrCoupleSurgery.autoCouplersAtJoint`：接缝连接"一车 B 端 + 另一车 A 端"，车列按 A→B 排，
   所以 B 端对着接缝那列取**最后一节**，另一列取**第一节**；两端都自动才算自动车钩。
4. **调用点**：`Simulator.tick` 里 `sidings.forEach(simulateVehicles)` **之后**。手术会注销被并进来的那列车，
   放在 siding 迭代里改集合会破坏迭代。
5. `couplerGapM` 由 private 提为 public：自动车钩用它先筛目标，避免对每个候选都调手术而刷一屏拒绝日志。

日志：`[MMTR-COUP] 自动车钩挂上: <id> + <id> -> 3 节`。

## 实机配置

货车 `cargotest` 在滚动清单里声明 `"mmtrAutoCoupler": false`（L3、L5 两处）：货车用螺旋车钩，顺便给实机留一条
人工车钩路径。其余车底（saf101 / p1 / HST8）保持默认自动。

## 用例

`MmtrConsistBodyCouplingTests` 新增 4 条（复用既有 `Approached` 场景：机车在授权下贴到 2 节挂车停稳）：

- `anAutomaticCouplerLatchesOnWhenTheTrainStopsAtTheGap` —— 停稳即自动挂，3 节，钥匙留在编组内；
- `aManualCouplerWaitsForTheCrew` —— 人工车钩不自动挂，且**手动 K 仍然可用**（标志不挡人工路径）；
- `aMixedJointWaitsForTheCrew` —— 混编不自动挂；
- `anAutomaticCouplerWithoutAShuntAuthorityStaysOpen` —— 撤销授权后不自动挂。

## 验证

- `MmtrConsistBodyCouplingTests` 8/8；
- 全量引擎套件 **437/0/2**（本轮 433 → 437）；
- 实机：待验证（机车贴到客车停稳后应自动挂，不需要按 K）。

## 注意

自动挂成功后同样**撤销调车授权**（沿用 C4 语义：这段调车移动已经完成）。下一段调车要重新授权。
