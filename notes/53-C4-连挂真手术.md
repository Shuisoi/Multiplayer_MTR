# 53 - C4 连挂真手术：机车 + 挂车车列变成一列车

> 用户口径：连挂的终点是"机车与挂车车列成为一列车"。C3a 给了信号前提、C3b 给了同轨停放与
> 0.3 m 贴靠，这一片把 `MmtrCoupleControl` 从"只检查 + println"的桩变成**真手术**。

## 闸门（引擎强制，按序）

1. 两车都在 Motion Core 模式；
2. **都停稳**；
3. **同一条轨**；
4. **同向**（`enteredFromPosition` 相同 = A↔B 对接）；
5. **调车授权有效且覆盖该轨**；
6. **车钩接触**：间隙 ≤ `COUPLER_CONTACT_M = 0.75 m`（C3b 的贴靠停在 0.3 m），重叠 > 0.05 m 拒绝；
7. 合并后节数 ≤ `TransportMode.maxLength`、总长 ≤ 股道长度。

设计 O4 的"必须同一条股道注册"已放宽：闸门看的是**同一条轨 + 授权**，不再要求两列车注册在同一个
`siding`（机车从自己股道开过来，注册仍在原股道）。

## 手术

| 步骤 | 做法 |
| --- | --- |
| 判前后 | 比较两车在共享轨上的里程偏移，大者为物理前车 |
| 合并车列 | `前车.cars + 后车.cars`（MTR car 0 = 车头，列表即从前到后） |
| 保留谁 | **前车**——位置、走行器、身份参数全不动，列车不发生位移 |
| 重建数据 | 取前车 VED 的 JSON，替换 `vehicleCars` 与 `ridingEntities`（后车乘员 `ridingCar` += 前车节数），再 `new VehicleExtraData(JsonReader)` |
| 走行器 | 编组体：`engageMmtrConsistMotion(walker, NONE)` + `removeKey()`；legacy：`engageMmtrMotion(walker)` |
| 空管 | `mmtrSeedAirStateAfterCoupling`：新接入的**无动力**车 pipe=0，随后充风；有动力车自带压缩机 |
| 收尾 | 两车注销（不清空股道模板）、合并车登记到前车股道、撤销授权 |

**合并后无人持钥匙**：这台机车的驾驶室在合并后变成了**车厢内部**驾驶室（合并车列 = 挂车 + 机车，
机车 A 端在中间），现两驾驶室模型（CAB_A/CAB_B = 车列两端）表达不了。所以手术把钥匙拔掉，
船员**走到前车驾驶室重新插钥匙**——这是诚实的做法，不是遗漏；内部驾驶室建模属 C5（`cabAtArcM` 扩展点）。
油门档位同理不继承（`mmtrManualOverride` 是每车状态），船员重新推一下即可——乘员身份与座位都跟着过来了。

## 回归与证据

新增 `MmtrCoupleSurgeryTests` 3 例（合成世界：2 节挂车 + 1 节机车，机车在授权下贴靠）：

1. `couplingMergesTheRakeAndTheLocoIntoOneTrain`：合并后 3 节、顺序 **wagon,wagon,loco**、
   机车带动力 / 挂车不带、合并车**停在挂车原位**、两个原车在世界上消失、合并车登记在前车股道、授权被消费；
2. `theMergedTrainKeepsRunningAndCarriesTheCrew`：乘员跟过来且座位重编号（机车 car 0 → 合并 car 2）、
   重新推油门后合并车能走；
3. `theGatesRefuseAnIllegalCoupling`：撤销授权后拒（"调车授权"）、未接触/不同轨拒、任一方移动时拒（"停稳"）。

- 引擎全量 **413/0/2**（410 → +3，零新增失败）；引擎 jar 已重建同步；`:fabric:compileJava` 通过。

## 实机用法

```
shunt <机车id> <挂车所在轨hex> 5 25     # 授权
（开车贴上去，0.3 m 停住）
couple <机车id> <挂车id>                # 连挂 → 合并成一列车，钥匙被拔
（走到前车驾驶室重新插钥匙 → 继续开）
```
