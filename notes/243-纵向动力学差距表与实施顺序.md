## 2. 实施顺序（按"手感收益 ÷ 风险"，且保证每一步都能验证）

| 片 | 内容 | 为什么排这里 |
| --- | --- | --- |
| **S1** | **编组质量与惯性**：三手柄/有级/无级也接到"按车求和"的编组物理（挂车质量进惯性、牵引只算动力车、制动力/阻力按车求和） | 立刻修掉"现在就不对"的那件事；而且是 S3/S5 的地基（多体必须先有逐车质量） |
| S2 | 牵引三段式（弱磁 `∝1/v²`）+ 驱动延迟 `τ` | 纯函数/一阶滤波，风险低；直接影响起步与高速段的推背感 |
| S3 | **黏着与空转**（轮对角速度状态、`s`、`μ–s`、`WSP`、撒砂、天气/杂物给 `μ_max`） | 工作量最大、也是"真实驾驶手感"的核心；必须在 S1 之后（要逐轴/逐车质量） |
| S4 | 制动细化：列车管传播速度、闸瓦摩擦随速衰减 | 与 S3 独立，S4 可先做"闸瓦衰减"（一行曲线） |
| S5 | 车钩多体（间隙 + 缓冲器非线性刚度/迟滞阻尼） | 依赖 S1 的逐车质量；工作量大，但长编组质感全靠它 |
| S6 | 积分与数值稳定性（子步频率、半隐式、静止防震荡硬判据） | S3 来了以后必须一起做（微蠕滑刚度大） |

## 3. 本轮做的：S1（编组质量与惯性）—— 已完成

设计（尽量少动公共签名）：

1. `MmtrComposition.toConsistType(id)`：用**同一套操纵语义**（说话那节车的 `ControlMode` 与三手柄规格）
   但物理量取**按车求和**：`m = Σm_i`、`λ = Σλᵢmᵢ / Σmᵢ`、`F_max/P = Σ`（**只算 powered 单元**）、
   `F_常用/紧急 = Σ`、阻力 `A/B/C = Σ`；气路四项速率取**最慢的一节**（全列充气由最慢那节决定）。
   - 车列**一节都没声明 powered** 时按"说话那节车带动力"处理：用例里用 `VehicleCar` 拼的车列基本不写
     `powered`，不兜这一下整列会变成"没有牵引的死车"（实测 `MmtrCoupleSurgeryTests` 当场红）。
2. `Vehicle.tryInitMmtrController()`：车列 >1 节就用这份等效车底（单节时行为不变）；镜像里的物理量
   随之变成整列的量，客户端镜像与服务端一致。
3. 用例 `MmtrConsistInertiaTests`（3 条）：
   - `theConsistAggregatesMassTractionBrakesAndResistance`：82 t 机车 + 2×40 t 挂车 ⇒ 质量 162 t、
     牵引仍 200 kN（只来自动力车）、制动力 90+30+30 kN、阻力按车求和、操纵语义仍是三手柄；
   - `deadTrailingMassReducesTheAccelerationTowardsTheMassRatio`：同满牵引下编组加速度落在单机的
     40%…55%（惯性比 82/162 ≈ 50.6%；略低是因为 `tractionAccelerationMps2` 已扣运行阻力而挂车只加阻力）；
   - `anUndeclaredPoweredConsistStillHasTraction`：没声明 powered 的车列仍有牵引。
4. 全量：**790 条，失败 3 条**（仍是那 3 条世界存档漂移）。

**实机影响**：BR101+2×p1 从"按 82 t 算"变成"按 162 t 算" —— 起步/制动都慢一半、AFB 的补气量按真实惯性走。
这条正是用户前几轮反复感到"不一样"的结构性原因之一。

## 4. 下一片（建议 S2 → S3）

- **S2**（便宜、立刻有手感）：牵引第三段（弱磁 `F ∝ 1/v²`）+ 驱动延迟 `τ`（一阶滤波，电气 50–150 ms）。
- **S3**（最大一块、真实手感的核心）：黏着与空转 —— 轮对角速度状态、`s = (ωr−v)/max(...)`、
  `μ–s` 曲线（微滑线性 / 峰值 `s≈1–3%` / 打滑负斜率）、环境 `μ_max`（干 0.33–0.38 / 湿 0.15–0.25 /
  落叶油污 ≤0.08）、WSP 减转矩脉冲、撒砂 ×1.2–1.4。**必须在 S1 之后**（要逐车/逐轴质量与法向力）。
- 之后 **S4**（列车管传播速度 + 闸瓦摩擦随速衰减）、**S5**（车钩多体：间隙/缓冲器/迟滞阻尼）、
  **S6**（≥200 Hz 或半隐式 + 静止防震荡，S3 来了必须一起做）。
