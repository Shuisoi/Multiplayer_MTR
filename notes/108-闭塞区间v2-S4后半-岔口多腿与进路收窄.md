# 108 - 闭塞区间 v2 · S4（后半）：岔口多腿 + 有进路收窄

> 承接 notes/107（S4 前半：灯显可观测 + 实测暴露的缺口）。用户 2026-09-10 拍板**路线 B**：
> 岔口多腿（无进路时所有前向腿算同一区间，有进路时收窄到进路那条腿）。

## 1. 交付

| 件 | 内容 |
| --- | --- |
| `walk(...)` 重写 | 岔口处**对每一条保持行进方向的前向腿都继续走**（原来只跟"最直的一腿"）。用**每条分支自己的路径集合**做环保护（菱形拓扑——同一根轨可经两条路到达——因此用祖先路径而非全局去重） |
| `nextLegs(node, cameFromHex, heading)` | 返回节点处所有合格续轨（含"沿弧长正向/反向"），并按规则切换；`Leg` 记录 rail/forward/farEnd |
| `routeNextRailOn(curHex, node)` | **有进路时收窄**：某条 **MAIN** 进路从 `curHex` 经 `node` 走，就只跟进路的那一条腿。**PENDING 进路也算**（车已承诺该移动，即使还在等联锁；只认 SET 会让车一直背着"整个咽喉一个闭塞"） |
| `MmtrRouteRegistry.allRoutes()` | 取全部进路（SET + PENDING，确定性顺序），供上面的收窄使用 |

## 2. 用例（+1）

`atAForkTheSectionCoversEveryLegAndNarrowsToTheRouteWhenOneIsSet`：
咽喉 + 直股 + 岔股 —— 无进路时区间 = **3 段（咽喉 + 两条腿同属一个闭塞）**；
装上一条 MAIN 进路（咽喉→直股）后 = **2 段**，且走的正是进路那条腿。

全量 **511/0/2**（S4 前半后 510，+1 例，零新增失败）。**既有用例零期望值改动** ——
因为既有合成网络里没有"多前向腿"的岔口（单续向节点），多腿与单腿在那里等价。

## 3. 真实世界实测（新 jar）

| 灯 | 多腿前 | 多腿后 |
| --- | --- | --- |
| `-157,-59,-189` | 15 段 / 300.42 m | **30 段 / 600.85 m** |
| `-149,-60,-169` | 15 段 / 333.99 m | 15 段 / 333.99 m（该方向无岔口可分支） |
| `-163,-60,-189` | 15 段 / 300.42 m | 15 段 / 300.42 m |
| `-152/-160/-168/-175, z=-122` | 1 段 / 43.0 m | 1 段 / 43.0 m（**未变**） |

**多腿确实生效**：`-157` 那盏灯的区间从 15 段涨到 30 段（多出的一倍正是它前方岔口的另一条腿），
`lamps-v2` 同步显示 `30 段/长=600.85`。有向区间覆盖轨仍为 35 根（多出的腿与其它区间共享轨道）。

## 4. 车场那四盏灯"没变"的原因（已查清，不是 bug）

用 `mmtr-topology` 直接看节点邻轨：

```
节点 (-170,-79) 的邻轨：只有 (-170,-122)→(-170,-79) 一根        ← 尽头！
节点 (-170,-122) 的邻轨：(-170,-122)→(-170,-79)、(-170,-137)→(-170,-122)
```

车场那 6 条"平行股道"（x=-154…-193，z=-122→-79）在 **z=-79 端全是尽头**，
彼此只在 **z=-122 端**经斜向轨相连。而 `z=-122` 那四盏灯的保护轨是**向北的那一段（z=-122→-79）**，
它的远端就是**尽头** —— 所以无论走行规则怎么定，那一盏灯**都只能保护那 43 m**。

**结论：这是摆灯地形的结果，不是走行规则的结果。** 这四盏灯保护的是"各自的存车线"，
而不是咽喉；要让一盏灯保护整个车场咽喉，灯必须**站在咽喉节点上、朝咽喉方向**
（即 `z=-122` 这个岔群朝南的那一侧），而不是站在存车线股道端。
