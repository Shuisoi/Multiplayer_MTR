# 253 — "50% 油门也是 300 kN"的真因：AFB 盖掉了手柄（cap=false）

用户口径（2026-09-23）：

> 电机还是恒定 300kn，在油门设置在 50% 时也是 300kn

## 1. 日志直接给出了答案（notes/252 里加的诊断）

```
17:45:13 手柄=   0 定速= 130 牵引比=  32% 速度=   0.0km/h 电机=   97kN 镜像=    0kN
17:45:15 手柄=   0 定速= 130 牵引比= 100% 速度=  11.5km/h 电机=  300kN 镜像=  300kN
17:45:17 手柄=   0 定速= 130 牵引比= 100% 速度=  23.3km/h 电机=  300kN 镜像=  300kN
```

两件事一眼可见：

1. **`电机` 与 `镜像` 是同一个数** ⇒ 读数链路是好的（服务端算、快照发、客户端读，全对得上）。
   notes/252 的"值变了要标脏"也确实补上了传输那一环（11.5 km/h 那行两者一致）。
2. **`手柄=0` 而 `牵引比=100%`** ⇒ 出力不来自手柄，来自 **AFB**。所以"油门 50% 也是 300 kN"的真因是
   **配置里 `afbUsesHandleAsCap=false`：AFB 直接盖掉了手柄**（notes/241 第四次修订留下的口径）。
   这不是读数问题，是操纵语义与用户口径不一致。

补一句量纲上的事实：**76.8 km/h 以下、满牵引比时，力本来就该是 300 kN**（折点 = `P/F_max` =
6.4 MW/300 kN = 21.33 m/s = 76.8 km/h）。所以"低速 300 kN"不是卡住；真正不对的只有"半手柄也满力"。

## 2. 用户口径（原话，notes/239 起一直没变）

> 按牵引力来看，AFB 和动力手柄两个相互制约，**动力手柄决定当前输出的力**，AFB 根据速度来削减或反向电磁制动或应用气制动

⇒ `afbUsesHandleAsCap` 应当为 **true**。现行代码在 cap=true 时的语义正好是用户要的（`ThreeHandleDriveController`）：

```java
tractionRatio = handleTraction > 0 && spec.isAfbUsesHandleAsCap()
    ? Math.min(handleTraction, afbDemand)   // 手柄在牵引侧 ⇒ 手柄是上限，AFB 只削
    : afbDemand;                            // 手柄在关闭/电阻侧 ⇒ AFB 自己决定牵引
```

第二条分支就是"手柄关闭也能定速"的修法（notes/240/241 的"没法定速"事故）—— 它**不受**这次改动影响，
因为判据是"手柄比例 > 0"而不是"cap 开关"。
