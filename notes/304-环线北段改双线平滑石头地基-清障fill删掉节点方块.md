## 1. 先把"5 格"问清楚：**5 是空档，不是轴线间距**

用户说"5格与车站相同"，但实测两个数对不上：

| 对象 | 轨位置 | **轴线间距** | **中间空档** |
| --- | --- | --- | --- |
| 样板站两条站台轨 | `x=-43` / `x=-37` | **6** | **5** |
| 车场侧线 | `x=-142, -137, …` | 5 | 4 |

⇒ "5 格"指的是**空档**（`-42..-38` 共 5 格），"与车站相同"指的就是车站那对轨。
**用户选定了 B：轴线间距 6 格**（= 车站），并把理由说清了——**同间距才能把 220 m 标准站台样板直接放到环线上**。

**最终几何**：两轨在 `z=1800` 与 `z=1806`（轴线间距 6，空档 5）。

> 记一笔术语：中文"轨间距"既可指**轴线间距（线间距）**也可指**净空档**，
> 差 1 格。以后写需求直接写"两轨轴线相距 N 格"最省事。

## 3. ★ 事故：清障的 `/fill` 把**已铺好的节点方块删掉了**

### 3.1 经过

上一轮（notes/303）铺完 `z=1800` 那条轨、节点在 `(0,65,1800)` 与 `(100,65,1800)`。
本轮为了把地基加宽到 `z=1798..1808`，又跑了一次清障：

```
fill 0 65 1797 100 72 1809 minecraft:air replace     ← 191 个方块
```

**这一条的 `y=65` 正好就是轨面那一层** ⇒ **两个节点方块当场被替换成空气**。

### 3.2 现象有多隐蔽

L2 复查时：

```
(0,65,1800)   facing=true  -> 不匹配   facing=false -> 不匹配
(100,65,1800) facing=true  -> 不匹配   facing=false -> 不匹配
(0,65,1806)   facing=true  -> 命中 ✔   （新铺的那条没事）
```

而**引擎里那条轨好好的**：

```
共 64 条轨道：
  (0,65,1800)→(100,65,1800)  普通  限速 160/160  长 100 m
  (0,65,1806)→(100,65,1806)  普通  限速 160/160  长 100 m
```

⇒ **引擎有、方块没有**。这正是铁律 0 的反面形态：
notes/288 那次是"方块对了一半、引擎全对"；这次是"引擎全对、方块没了"。
**两种都只有 L2 查得出来。**

### 3.3 修法：重推 `rail add`（**原地替换，不会重复**）

```
rail add 0 65 1800 100 65 1800 --speed=160
```

— 同一对端点 + 同一朝向 ⇒ 同一个 `Rail` hex ⇒ 引擎**原地替换**。
实测：重推后 `rail list` **仍是 64 条（不是 65）**，四个节点也全部恢复：

```
(0,65,1800)  (100,65,1800)  (0,65,1806)  (100,65,1806)
  → 全部 mtr:rail[facing=true,is_22_5=false,is_45=false,is_connected=true,waterlogged=false]
```

### 3.4 教训（已写进 skill）

> **任何可能碰到 `y ≥ 65` 的 `/fill`，都必须在铺轨之前跑完。**
> `/fill` 不认识"这里有轨道"，它只按方块类型替换。
> 两个方向都会中招：**清障（air replace）会删掉节点**；**补路基会埋掉节点**。
