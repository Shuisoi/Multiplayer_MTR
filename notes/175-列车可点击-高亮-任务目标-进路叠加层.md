## 1. 这一轮拆成五件事

| 用户的话 | 落地 |
| --- | --- |
| 「样式和节点相同（颜色描边阴影）」 | 记号改用节点的 `--fg` 填充 / `--fg-dim` 描边 / 0.1 格描边宽，并加**同形状放大 2.5 倍**的外阴影（`VehiclesLayer`） |
| 「让列车图标能够点击」 | 自己做命中判定（**旋转矩形 + 屏幕像素余量**，`views/map/vehicleHit.ts`，纯函数 + 用例） |
| 「点击后高亮」 | 选中的**整列**车换成主题强调色（按 `vehicleId` 选，不按节 —— 一列 8 节一起亮） |
| 「提示任务目标」 | 左上角任务卡片（`layers/TrainCard.vue`）：任务 / **目标** / 起点 / 进路 |
| 「路线图叠加层」 | 新图层 `layers/TrainRouteLayer.vue`：把选中那列车的 `route.rails[]` 用强调色压在灰轨上 |

「游戏内的列车都是通过任务驱动的」这句是**设计前提**：所以卡片的主语是**任务**（谁派的、去哪、联锁排了哪条路），
而不是"这车多快"（那是悬浮提示里已有的东西）。

## 2. 样式 = 节点：三个数照抄，阴影的关系由倍数决定

节点那三个数（`RailNodesLayer`）：`fill: var(--fg)`（白）、`stroke: var(--fg-dim)`（灰）、描边宽 0.1 格，
外阴影 = 同形状放大 **2.5 倍**填一个径向渐变（实心到边缘、往外渐隐）。

记号直接照抄这三个数（描边宽从原来的 0.2 格改成 0.1 格），阴影用**同一个倍数**。为什么同一个倍数就够：

> 径向渐变的 stop 在 `objectBoundingBox` 单位里，实心部分到 `100 / 倍数`（= 40%）为止；
> 而阴影是"记号自己放大 2.5 倍"，记号边缘正好落在 40% 处 —— 于是"**记号底下实心黑、出了记号往外渐隐**"
> 这条关系**只由倍数决定**，与记号是圆点还是 13:1 的长条无关。

实测（探针逐位比）：8 个记号的 `fill`/`stroke`/`stroke-width` 与节点**完全相同**，两份渐变的 stop 偏移都是 `[0%, 40%, 100%]`。

**彩色的位置换了**：原先是"车是这一页唯一彩的东西"（一眼找车），现在彩色留给**选中**（无选中时全页只有灰白）。
这是用户要求的代价 —— 探针也把这条钉住了：选中的记号中心是 `rgb(0,120,215)`，别的仍然是 `rgb(255,255,255)`。

## 3. 点得动：旋转矩形 + 屏幕像素余量

命中判定是纯函数（`views/map/vehicleHit.ts`）：

- 把指针换算到记号的**局部坐标**（中心为原点、车头朝 +x）：平移 + 反向旋转；
- 判 `|局部 x| ≤ 车长/2 + 余量` 且 `|局部 y| ≤ 车宽/2 + 余量`；
- 余量按**屏幕像素**给（调用方算 `HIT_RADIUS_PX / 相机比例`），所以任何缩放级别手感一样；
- 重叠时取**中心离指针最近**的那一节。

两个"不能那么做"是量出来的：

| 做法 | 为什么不行 |
| --- | --- |
| 按元素监听（`path` 上挂事件） | 记号宽 1.2 格，默认取景下约 **1 px** —— 等于"拿鼠标去戳一条 1 px 宽的线"（节点层踩过同一个坑） |
| 按"到中心的距离"判 | 一列车 16 格长：只有车心那一小块点得动，而它明明画了一整条 |

**与节点层的仲裁**：两个图层挂在同一个舞台元素上各做各的命中判定，谁先收到事件不可依赖；
而车画在节点**上面**，所以"看得见谁就点到谁"。做法是**显式询问**：车辆层把命中判定注册到
`views/map/trainSelection.ts`（`registerVehicleHitTest`），节点层在开菜单前先问 `vehicleHitAt(x, y)`，
命中就让路。区间地图没有车辆层 ⇒ 钩子没注册 ⇒ 节点层行为与从前**一模一样**（探针 `node-ui-probe` 13/13 未变）。

## 4. 高亮与取消

- 选中存的是 **`vehicleId`**（`trainSelection.ts` 的模块级 ref，与节点那套 `nodeInteraction` 同一约定）。
  理由是用户点的是"这一列车"：一列编组的每一节一起亮、卡片写一份、路线画一套。
- 再点同一列车 = 取消；点空白 = 取消；点地图以外（上边栏/切页）= 取消。
- 浮层（卡片 / 节点菜单）里的点击**不算点空白** —— `event.target instanceof SVGElement` 这一道挡掉了它们
  （节点层为同一件事踩过"菜单看得见就是点不动"的坑）。

## 5. 路线图叠加层

- 数据源是 `route.rails[]`（**联锁实际给它排的那条路**，`state` 是 `SET` / `PENDING`），不是"应该走哪条"。
- 几何**必须与基础图层同源**：按**规范 hex 键**去那张 `alignRail()` 对齐过的折线表里查（引擎的采样走方块中心，
  少这一步整条线偏半格 —— 就是用户抓到的"信号灯左右分布不均匀"）。查不到那根轨就不画（宁可少画一根）。
- 叠放：`rail → node-shadow → node → **train-route** → signal → vehicle-shadow → vehicle`。
  进路是"这条轨属于哪条路"的信息，压在灰轨上、在灯与车下面；线宽 0.7 格（比轨道线 1 格细，底下的灰轨还看得见）。
- 实测：点中的那列车进路 10 根轨 ⇒ 图上 10 条线，**逐条逐点**等于接口那些轨按同一份 `alignRail` 算出来的点串。

## 6. 提示任务目标：那个字段名**骗人**

任务是引擎派的，卡片上"目标"那一行要写**人看得懂的名字**。这里有两条实测出来的事实：

1. **`mission.targetSidingId` 装的不一定是股道** —— `MmtrJobScheduler` 派任务时，目标要么是作业单步骤指的
   **股道**（调车/回段），要么是**站台**（客运任务就是在某个站台停一次），两条都走同一个 id 字段。
   现场实测：一辆车的 `targetSidingId = 954364252968674217`，它在 `/mmtr-platforms` 里是
   「站 1 · 站台 1 · 南行 · 20 米」；同一辆车的 `startSidingId` 才是真股道。**只查股道清单的话，卡片上写的是
   「股道 954364252968674217」这种没人看得懂的一行字。**
2. 所以 `domain/MissionTarget.ts` **两个清单都查**：股道优先（调车/回段），查不到当站台（客运），
   都没有就退回 `目标 <id>` 原文 —— 宁可难看也不要写"未知"：id 至少能拿去对数据。

站台清单从哪来：`/mmtr-platforms` 是**静态** feed，挂在 `liveFeeds` 里**只在声明了车辆的那一页**取一次
（区间地图的 `PlatformsLayer` 自己取一份，它要的是引擎原始形状）。股道清单与车辆**同一份响应**（`sidings[]`），不多发请求。

卡片四行：`任务`（种类 · 状态 · 执行者，失败时带原因）/ `目标`（**这一行的主语**，颜色比别的行亮一档）/
`起点` / `进路`（种类 · 状态 · 几根轨 · 几个岔，PENDING 时带原因）。速度/车门/下一区间**不在这里**重复
（记号的悬浮提示里已经有了；用户："不要加我要求以外任何元素"）。

### 一个顺手量出来的**取景事实**

**默认取景里一个列车记号都看不到**：车都在车辆段，位于线网中心**下方 200–1000 px**（探针必须先拖两次才把它拖进视野）。
这不是缺陷（取景窗 1000 单位、锚点是节点云中心），但"点列车"这件事的前提是"看得见列车" ——
要不要让开局取景把车辆段也框进来，留给用户定（本轮没动取景）。

顺带一条库的脾气：svg-pan-zoom 的拖拽平移**一次拖不了那么远**（实测拖 997 px，相机只走了 399），
所以探针的"拖进视野"是个循环（最多 6 次）。

## 8. 留给下一轮

- **取景要不要把车辆段框进来**（见上）。用户没要求，所以没动。
- **点进路高亮到区间**：现在只画进路的轨；要画"这条路会占哪几个闭塞区间"是另一件事（区间数据是另一路接口）。
- **卡片的动作**：现在只读（提示）。要在卡片上放"取消任务/手动接管"这类写操作，得先有一路写接口（`mmtr-command` 有，
  但用户没要求）。
- **选中态跨页**：切到区间地图时选中会被清掉（那一页没有车辆层，卡片也不在）；要保留就得把这一页也画上车
  （notes/173 §7 已记：那一页的轨是引擎原始形状，得换"不对齐"那一档）。
