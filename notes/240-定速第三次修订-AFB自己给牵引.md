# 240 · 定速（AFB）第三次修订：AFB 自己给牵引，手柄只在牵引侧当上限

日期：2026-09-23 · 现场第三轮：「还是不行，**没法定速**」→ 从服务端日志里抓到了确切原因。

---

## 1. 日志证据（不是猜）

`[MMTR-CONSIST]` 那几行把"手柄"和"控制器实际牵引比"摆在同一行：

```
手柄=48  → 牵引比=51%      ← 手柄要多少就是多少（AFB 原样放行）
手柄=-97 → 牵引比=0%       ← 手柄在电阻制动侧
手柄=81  → 牵引比=84%      ← 还是"手柄要多少就是多少"
```

**定速 65 挂着，但力完全由手柄决定**：手柄不给力（关闭 / 电阻制动侧）车就到不了设定速度，
而且 `afbGainPerMps = 0.3` 意味着**只有差 12 km/h 以内** AFB 才动手削一下 —— 从司机座位上看就是
"定速没反应、没法定速"。

上一版（notes/239）的口径"手柄决定要的力、AFB 只削不加"在**数学上**没错，但它有一个致命后果：
**手柄在关闭位 ⇒ 牵引恒 0** ⇒ 设了定速车一动不动。用户要的"定速"是"设了就得走"。

## 2. 这一版的口径（`docs/01-设计/驾驶输入与控制模型.md` §2 已同步）

| 分支 | 行为 |
| --- | --- |
| `error > 门限`（低于设定速度） | **AFB 自己给牵引**：`牵引 = min(手柄上限, clamp(afbGainPerMps × error, 0, 1))`；**手柄在关闭/电阻制动侧时上限视为满**（这是"没法定速"的修法） |
| `error < −门限`（高于设定速度） | **反向**：要的减速度 `a = afbBrakeDecelPerMps × |error|` → 电阻制动出 `min(需要, 可用)`，**缺口由 AFB 补气**；缸压目标与气制动手柄**取大耦合** |
| 带内 | 惰行 |

- **动力手柄在牵引侧时是上限**（`afbUsesHandleAsCap=true`）：司机要多少，AFB 最多给到多少 —— 保留用户
  "动力手柄决定当前输出的力"这一条；手柄在关闭/负侧时 AFB 自己决定牵引。
- `afbGainPerMps` **0.3 → 1.0**：差 3.6 km/h 以内才开始削（原来 12 km/h 就开始削，力量全由手柄决定）。
- 牵引联锁（气缸未排空 / 手柄要求气制动 ⇒ 牵引 0）不变；AFB 补气、司机手柄、电阻制动三条并存。

## 3. 量出来的行为（世界里那台 BR101 的参数）

```
[AFB5] 手柄关闭、定速 100：200 s 后 99.77 km/h          ← 新增用例：这就是"没法定速"的正面判据
[AFB]  手柄 97、定速 100：峰值 99.77，120 s 后 99.77    ← 不超调，稳态差 0.23 km/h
[AFB3] 从 120 起、定速 100：60 s 后 99.77，最低 99.77   ← 收得回、不下冲
[AFB4] 从 60 起、定速 20：最大缸压 1.000，90 s 后 19.83 ← 补气真的上了
[AFB2] 松闸后 5 s：49.90 → 48.65（在减速）              ← 牵引联锁
```

用例改动：`afbCannotAccelerateWithTheThrottleClosed`（钉"关闭位没牵引"，已与真车口径相反）
→ 改成 **`afbPullsTheTrainToTheSetSpeedWithTheThrottleClosed`**（钉"关闭位也要能保住设定速度"）。
其余用例（保速不超调 / 高出一段收回来 / 补气 / 耦合取大 / 牵引联锁）保持。
