# 165 = 尺寸与放置：方块网格 + 节点标记（用户三次纠正的收敛）

> 这一轮被用户纠正了三次，每次都是同一个根因的不同侧面：
> ① 「比例不对啊，而且**为什么全览 2px 写死？那么以后特别大的地图的话，岂不是线越来越粗？**」
> ② 「**我的世界的坐标永远都是 1x1x1，方块也是，就不能按 1x1x1 进行放置吗？**给屏幕加一个 1x1x1 的
> 半透明叠加底层。」
> ③ 「**信号灯，道岔是绑定在节点上的，直接固定显示在节点旁不行吗？不要掺活实际坐标进来。**」

## 一、三条口径（最终版）

### ① 有实际坐标的东西：**按格**（1 格 = 1 世界单位）

Minecraft 的世界坐标就是方块坐标，plane 坐标是方块中心 ⇒ **1 viewBox 单位 = 1 格**，
不需要任何换算。于是：

| 元素 | 规格 |
| --- | --- |
| 轨道线宽 | **1 格**（一根轨就是一条方块宽的线） |
| 轨道护套 / 可点区 | 1.8 / 3 格 |
| 区间线心 / 状态条 | 1.5 / 0.5 格（条中心在线心的 1/4 与 3/4 处 —— 用户那三个数"1-2、4-5"的比例） |
| 区间端点圆点（直径） | 1 格 |
| 轨道节点圆点（直径） | **1 格**（一个方块） |

### ② 绑在节点上的东西：**固定屏幕像素**

"信号灯，道岔是绑定在节点上的" —— 所以它们的锚点是**节点**，标记是节点旁的固定像素尺寸：

| 元素 | 规格 | 锚点 |
| --- | --- | --- |
| 信号灯图标 | **8 px**（屏幕固定） | 它绑定的**节点**（用"离它最近的节点"匹配） |
| 道岔菱形 | **8 px** | 它自己的 key —— **key 本身就是节点键** |
| 灯的偏移 | **0**（就贴在节点上） | — |
| 道岔偏移 / 引线 | 6 / 10 px | — |

实测依据：道岔 key = `-155,-60,-189`（节点键）；灯离最近节点 0–4.5 格
（灯守的是那根轨，不是那个点 —— 所以"最近的节点"就是它的归属）。

### ③ 半透明 1×1 格网格当底衬

`GridLayer.vue`：一个 SVG `pattern`（一格一个 tile，所以格数再多也只有三个 DOM 节点），
`patternUnits="userSpaceOnUse"` ⇒ 以世界坐标为单位、随相机缩放。格线落在**整数格**上，
所以它同时是**标尺**：轨宽是不是正好一条格带、节点是不是正好一格，屏幕上一眼能看出来。

## 二、两处换算（只有两处）

```
格        → 世界单位：specToWorld(spec)      = spec × WORLD_UNIT（= 1）
屏幕像素  → 世界单位：pxToWorld(px, 相机比例) = px / 相机比例   ← 绑在节点上的标记用
```

屏幕尺寸 = 世界尺寸 × 当前相机比例（相机的事，不是规格的事）。

**上次错在哪**：口径①曾经被写成"基准 = 全览（视口）"，于是尺寸乘了取景比例 ——
窗口一变、地图一大，同一个规格就成了不同的世界尺寸（正是用户 ① 指出的问题）。
现在的换算里**没有任何视口/内容/倍率输入**。

## 三、这道数学题与用户的选择

| 量 | 值 |
| --- | --- |
| 线网世界跨度 | **407 × 1623 格** |
| 视口 | 1564 × 814 px |
| 全览时 1 格 = | **0.47 px** |
| 全览要图标 8 px ⇒ 图标得有 | **17 格宽**（比站台还宽） |
| 图标取 2 格（合理）⇒ 全览时 | **0.93 px** |

地图 1623 格长塞进 814 px 视口 ⇒ 任何"一格尺度"的东西都是亚像素。用户的选择是
**保持世界单位，接受"全览只是概览、细节靠放大"** —— 所以格制元素（轨、节点）**本来就是亚像素**，
而绑在节点上的标记（灯、道岔）**固定 8 px、任何倍率都看得见**。

## 四、实测（页面上量）

| 元素 | 口径 | 全览（0.47 px/格） | 6.15×（2.87 px/格） |
| --- | --- | --- | --- |
| 轨道线 | 1 格 | 0.47 px | 2.87 px |
| 节点圆点 | 1 格 | 0.93 px | 5.74 px |
| 信号灯图标 | 8 px 固定 | **8.0 px** | **8.0 px** |
| 道岔菱形 | 8 px 固定 | **8.0 px** | **8.0 px** |
| 方块网格 | 1 格 | 有（pattern） | 有（pattern） |

格制元素随相机缩放、节点标记屏幕上恒定 —— 这正是两种口径该有的行为。

## 五、判据

- `map-elements.test.ts`（7 条）：①格制（`WORLD_UNIT = 1`、轨宽/节点在 1 格量级）、
  ①网格（1×1 格、格线相位为整数格）、②节点标记（屏幕大小恒定、推近时世界尺寸变小）、
  ③屏幕尺寸 = 世界尺寸 × 比例、锚点 = 世界坐标 + 偏移（且灯的偏移为 0）、
  区间状态条比例与用户那三个数同源；
- `signal-overlap.test.ts`：灯头内部几何（空隙按灯点直径的比例判，眼睛够宽）；
- `viewbox.test.ts`：viewBox 与 `worldToScreen` 同一映射、尺寸与世界/视口无关。
