# 389 · 删掉 cab 的 nonstationary（音量起伏）

用户口径（第 43 轮）：

> 「怎么感觉电机音量有起伏呢？是不是后处理不对」
> 「把这个删了」

## 1. 它是什么（先量清楚再删）

`shell.mjs` 的 `nonstationary()` 是一个**纯 AM 乘法器**，三层叠乘：

```js
am   = 1 + 0.30 × sin(2π·0.9·t)        // amDepth / amRateHz
beat = 1 + 0.15 × sin(2π·5.3·t)        // beatDepth / beatHz
tex  = 1 + 0.38 × Σ(4 个 0.11~2.5 Hz)  // textureDepth
y[i] = x[i] × am × beat × tex
```

最坏情况 **1.38 × 1.15 × 1.38 = 2.19 倍（±79%）**。

实测 **0.3~10 Hz 调制深度**（5~50 s，先把 log 包络高通 0.3 Hz 去掉速度斜坡）：

| 变体 | 调制深度 | 调制谱主峰 |
|---|---|---|
| **nonstat 1.0（删之前）** | **12.43%** | **0.90 Hz** ← `amRateHz` |
| nonstat 0.4 | 6.76% | — |
| **nonstat 0（删之后）** | **3.43%** | 0.31 Hz |
| motorD 无壳（干源） | 1.62% | 0.85 Hz |
| 实录 2100 形起步 | 10.54% | 0.39 / 0.95 Hz |

★ 这一级**一个人贡献了 +9 个百分点（3.6 倍）**。干源自己只有 1.62%（来自换档与谐波扫过）。

## 2. 为什么删而不是调小

- 实录的起伏是 **0.39 / 0.95 Hz 混在一起**的统计性起伏；这里是**一个 0.9 Hz 正弦**为主
  ⇒ 听成"规律的音量呼吸"，比"像不像真的"更刺耳。
- 这一级**没有仿真依据** —— 它自己的注释就写着
  「真正的频率抖动要改合成，属于模型层；这里是壳子层，所以用**等效的**幅度起伏来表达」。
  也就是说它是一个**替代品**。
- 删掉之后还剩 1.62% 的**真**非平稳（换档、谐波依次扫过固定频带），那才是模型层的事实。

## 3. 副作用（实测，都是好的）

| | v60（删前） | v63（删后） |
|---|---|---|
| 调制深度 | 12.43% | **3.43%** |
| RMS（5~50 s） | 0.16467 | **0.19000（+1.2 dB）** |
| 峰值 | 0.888 | 0.897 |
| 峰值因数 | 14.6 dB | 13.5 dB |
| 底噪占能量 | **47.6%** | 38.2% |

**电平涨了 1.2 dB 是必然的**：AM 把峰值因数压大了（峰值留在原地、RMS 被起伏拉低），
删掉之后同一峰值下 RMS 更高。方向是好的（录音的峰值因数实测 13.1~15.2 dB，
我们从 14.6 落到 13.5，仍在区间内）。
底噪占比从 47.6% 降到 38.2% —— 因为牵引层 RMS 从 0.1033 涨到 0.1253，底噪没动。

## 4. 落实

- `SHELL_PRESETS.cab.nonstationary`: 对象 → **`null`**（保留键名，不删键：
  `preview.mjs` 的 `--nonstat` 缩放逻辑仍然读它，将来要在**模型层**做真抖动可以再填）。
- `nonstationary()` 补了 **falsy 守卫**（`if (!ns) return Float64Array.from(x)`）——
  没有它会把预设置 null 变成运行时崩溃
  （`TypeError: Cannot read properties of null (reading 'amRateHz')`，selftest 第一遍就撞上）。
  其它级（`artChain` / `smear`）本来就有这个写法，这一级是漏的。

自检 **184 通过 / 0 失败**。`interior` / `exterior` 两个预设**没动**（用户只说了 cab）。

## 5. 这一轮另外两件（都没采纳，留档）

- **档位加密**（`--maxstep 1.15 → 1.04`，27 → 93 档）：最大 `|Δrate|` 从 0.130 降到 0.047
  是硬数字，但用户听**无差异**，且包络跳变统计没改善 ⇒ 不采纳。音频集留
  `sandbox/sound-studio/baked/kei41ms104` / `kei41ms102` 备查。
- **载波簇降幅**（`carrierAmplitude 0.30 → 0.10`）：160~300 Hz 带占比 37.4% → 32.6%、
  500 Hz 以上每带翻倍（它是"闷"的来源：`300~500 Hz` 一带在 f₁≈50 Hz 时占 **57.7%**，
  因为 `6·f₁` 加 9 对边带共 20 根挤在 270 Hz 内）。**待用户裁决**，见
  `preview-kei/AB-carrier.ogg` 与 `v62-carrier10.ogg`。
