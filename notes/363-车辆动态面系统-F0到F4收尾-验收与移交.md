## 3. 账目：欠账在哪（不在这轮做的原因）

三处账目 —— 设计 §11 与 notes/360 的**都还在**；notes/361 那篇整条扩展路径已撤销：

| 出处 | 条目 |
| --- | --- |
| 设计 §11（5 条） | 锚点 JSON 被读四次该合一；`MmtrPidLayout` 只剩对照物身份；facets 曲面仪表盘不支持面文档；元素几何仍只接受数字（"表达式几何"没做）；字段表未含门开合状态（走四步曲）（原第 6 条已随扩展路径撤销） |
| notes/360 §9（6 条） | geometry 向量两端闭环口径；facets 同上；`foreach` 数据源只能是 `vars` 字面量（引擎还没有列表字段）；翻牌机在工作室里只是 2D 示意；`image` 找不到图只画洋红不报错；粒子/几何只接受数字 |
| notes/361 §7（6 条） | （该篇整条扩展路径已撤销，仅存记录） |

**按代价排的下一步候选**（都不是"补漏"，是"要不要继续投入"的取舍，需要拍板）：

1. **给某个车型/资源包加一个内置元素**（新画法）⇒ 引擎侧的新增改动，**改动点清单见作者指南 §10.1**。
   代价：约半天到一天；
2. **`foreach` 接引擎列表字段**（停站表之类）：走"加字段四步曲"（字段表 + 同步键 + 提供者 + 向量）。
   代价：动引擎，且要过同步/权威那两条线；
3. **元素几何可表达式化**（`x`/`y`/`w`/`h` 也吃 JSONLogic）—— 会把"离线出图"与"重画签名"复杂化，
   是设计取舍，不是补丁；
4. facets 支持面文档：等真有人要在曲面仪表盘上画动态内容再说。
