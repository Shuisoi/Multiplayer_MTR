## 3. 账目：欠账在哪（不在这轮做的原因）

三条清单，**都还在，没删**：

| 出处 | 条目 |
| --- | --- |
| 设计 §11（6 条） | 锚点 JSON 被读四次该合一；`MmtrPidLayout` 只剩对照物身份；facets 曲面仪表盘不支持面文档；元素几何仍只接受数字（"表达式几何"没做）；字段表未含门开合状态（走四步曲）；离线自检看不到"装没装那个模组" |
| notes/360 §9（6 条） | geometry 向量两端闭环口径；facets 同上；`foreach` 数据源只能是 `vars` 字面量（引擎还没有列表字段）；翻牌机在工作室里只是 2D 示意；`image` 找不到图只画洋红不报错；粒子/几何只接受数字 |
| notes/361 §7（6 条） | SPI 没有版本号/能力协商；扩展键不进 `schema.json`；扩展画不到 facets；热重载不重扫 `ServiceLoader`；`MmtrFaceElements.Paint` 该独立成 `MmtrFacePaint`；**没打过真的附属模组**（离线判据已闭环，实机没做） |

**按代价排的下一步候选**（都不是"补漏"，是"要不要继续投入"的取舍，需要拍板）：

1. **扩展自己带一份机读清单**（如 `mmtr-face-extension.json`）⇒ 一次性消掉 P3/P4/P7 的全部假警告，
   还能让工作室属性面板显示扩展专属键。代价：定一个小格式 + 模组侧约定；
2. **实机装一个真附属模组**（判据 7 的"进游戏"那一半）：给参考扩展补 `fabric.mod.json`
   丢进 `run\mods\`，面文档写 `{"type":"vendor:bar", …}`。代价：半天，且要重启客户端；
3. **`foreach` 接引擎列表字段**（停站表之类）：走"加字段四步曲"（字段表 + 同步键 + 提供者 + 向量）。
   代价：动引擎，且要过同步/权威那两条线；
4. **元素几何可表达式化**（`x`/`y`/`w`/`h` 也吃 JSONLogic）—— 会把"离线出图"与"重画签名"复杂化，
   是设计取舍，不是补丁；
5. facets 支持面文档：等真有人要在曲面仪表盘上画动态内容再说。
