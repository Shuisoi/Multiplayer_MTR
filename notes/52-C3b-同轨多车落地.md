# 52 - C3b 同轨多车落地：机车 + 挂车车列停在同一股道

> 用户口径：连挂的终点状态是"机车与挂车车列同轨停放"。C3a 给了信号前提（副显示授权），
> 这一片让那个状态**真的存在**：占用树看得见停放车、授权接近有停车点、存档与客户端都按多车处理。

## 三个真缺陷

| # | 现象（旧行为） | 根因 |
| --- | --- | --- |
| 1 | 停放车**不在占用树里** | `writeMmtrMotionVehiclePositions` 有 `getIsOnRoute()` 门（停放车直接跳过）；即使去掉，legacy 走行器还有"跳过第 0 段"门——而停放车的车体恰好**只**在第 0 段上 |
| 2 | 授权接近**没有停车点** | C3a 把被授权轨整段豁免了占用停车，于是机车会直接**穿过**要连挂的车列 |
| 3 | 编组体停放时**占用退化** | 编组体 `distanceM()=0`，镜像腿影以"尾端"锚定，车体落在腿影之前 → 算出的区间为空 |

## 修法

1. `writeMmtrMotionVehiclePositions`：去掉 `getIsOnRoute()` 门与 legacy 第 0 段门，任何"车体真正
   到达的腿"都写占用；再加 `writeMmtrStandingFootprint()`——当车尾在腿影起点之前（编组体停放时
   就是如此），按**轨道自身里程**补写车体区间（与所有读者同一"有序端点距离"坐标系）。
2. `computeMmtrBlockStopM`：授权轨上**保留**占用面停车，间距用新增的
   `MMTR_COUPLER_GAP_M = 0.3 m`（运行跟随仍用 2 m）——机车贴着被挂车列的尾部停下。
3. 存档/渲染无需改代码，但被测试钉住：`Siding.serializeFullData` 逐车写 `vehicles`、
   `init()` 逐车重建；每列车各自一条 `VehicleUpdate`，停放镜像在客户端 tick 中不漂移。

## 回归与证据

新增 `MmtrMultiVehiclePerRailTests` 4 例（合成世界，两条股道 + 真占用树）：

1. `stabledStockIsVisibleInTheOccupancyTree`：停放车写占用；机车从自己股道开过来，**被挡住**（改动前会直接穿过）；
2. `anAuthorizedLocoJoinsTheStabledRakeAndBothSurvive`：授权后机车驶入同一轨，**停在挂车车列尾部 0.3 m**
   （实测：挂车头 7.0 m、机车头 4.70 m = 7.0 − 2.0 − 0.3），60 tick 后两列车都还在、占用树里两段并存；
3. `theSavedWorldCarriesBothTrainsOfTheCouplingPair`：两条股道的 `serializeFullData` → 新 Simulator 重建 →
   两列车都回来；
4. `twoClientMirrorsOnOneRailKeepTheirOwnPositions`：两条客户端镜像各持自己的 `railProgress`，停放镜像 tick 不漂移。
