# 242 · 定速第五处根因：LZB 区段的手动驾驶**根本不走控制器**

日期：2026-09-23 · 现场第五轮，用户先报「还是不行」→ 我看实时状态时抓到铁证：

```
8888 实时：  -3852325235418012157 股道2 onRoute=True moving=True 速度=91.5 km/h
服务端收到：  收到操纵：… 油门=97 制动=0 定速=20 换向=1
```

**定速 20、手柄 97，车在 91.5 km/h 还在涨。** 根因在 `Vehicle.simulateMmtrMotion` 的分支顺序里：

```java
} else if (overridden && !airBrakeConsist && mmtrConsistType != null && getMmtrRegime() == MmtrRegime.LZB) {
    // LZB 连续监督段：手动车走"包线 + 天花板"的**简化模型**（不走控制器）
    speed = Math.min(lzbCeiling, speed + accelPerMs * millisElapsed);   // ← 这里压根没看定速
```

LZB 区段 = 限速 ≥101 km/h 的轨。**在这一段里 `ThreeHandleDriveController`（AFB 那整套）根本不运行**，
速度只受 `min(线路限速, 车底限速)` 约束 —— 所以：

- 车场 / 普通轨：定速能用（走控制器）；
- 一上正线（LZB 段）：定速**完全被绕过**，手柄推多少就跑多少 → 现场口径"定速没用"。

这也解释了前四轮为什么怎么调 AFB 都不对：**那几轮改的代码在 LZB 段根本没被执行。**

## 修法（用户口径：「AFB 速度正常设置，需要 LZB 来进行向下限定」）

```java
final double afbCeiling = 定速 > 0 ? kmhToInternal(clampCruiseKmh(定速)) : Double.MAX_VALUE;
final double ceiling = Math.min(lzbCeiling, afbCeiling);   // LZB 只做**向下**限定
```
LZB 分支里的三处夹紧（包线放行后的加速、超速回收、wantPower 加速）全部改用 `ceiling`：

- 定速 **低于**线路限速 ⇒ 车稳在**定速**（LZB 不干预）；
- 定速 **高于**线路限速 ⇒ 由 **LZB** 压到线路限速（下一段限速更低时，照旧由 LZB 包线提前收）。

## 用例

`MmtrLzbSupervisionTests.theSetSpeedAndTheLzbCeilingAreCoupled`（真实 dev 几何：12 m 车场 → 1400 m/120 LZB 轨 → 200 m/40 AWS 轨）：

```
[AFB+LZB] 定速 60：A 轨最高 60 km/h        ← 定速=天花板，LZB 不插手
[AFB+LZB] 定速 150：A 轨最高 107 km/h      ← 由 LZB 向下限定（功率受限没到 120，但绝不越 120）
```

## 同一轮里顺带修的两处（都是"看不见"的坑）

1. **停在车场、只设了定速的车不会自臂**：`isMmtrRequestingPower()` 只认"油门/手柄 > 0"，
   定速不算"要牵引" ⇒ 司机设了定速、手柄不动，车永远停在原地。现在 `cruiseSpeedKmh > 0` 也算。
2. **手柄在关闭位时 `[MMTR-CONSIST]` 一行都不打**：AFB 自己出力的那几轮现场，日志里没有任何一行能证明
   "定速到底给没给牵引"。现在"手柄 ≠ 0 **或** 定速 > 0"都会打。
