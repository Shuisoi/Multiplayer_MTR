# 254 — "现在有 20%"：先量手柄，再谈力

用户口径（2026-09-23，notes/253 之后）：

> 不对，现在有 20%

## 1. 先把用户那一趟的原始记录摆出来（全部一致，没有互相矛盾的地方）

| 端 | 日志 | 读数 |
| --- | --- | --- |
| 客户端 | `[MMTR-DRV] client sent … 油门=牵引 21% 定速=80` | 客户端认为手柄在 **21%** |
| 服务端 | `[MMTR-DRV] 收到操纵：… 油门=18 定速=80` | 服务端收到 **notch 18**（96 档制 ⇒ 19%） |
| 服务端 | `[MMTR-CONSIST] … 手柄=18 定速=50 牵引比=21% 速度=49.4 电机=49kN` | 实际牵引比 **21%**、力 **63 kN→49 kN** |

⇒ 三处对得上：**游戏把杆读成 19–21%**，所以力就是 `300 kN × 21% ≈ 63 kN`。这不是"读数坏"，
也不是"力算错"；链条是自洽的。

问题因此收敛成一个事实问题：**用户说的"50%"到底是杆的多少行程？**

- 若杆真的在 50% 行程而游戏只认 19% ⇒ **轴映射/校准**问题（`MmtrHidMapping.driveHandleFromAxis` 是线性的：
  `notch = round(|axis| × 97)`，所以轴值只可能是 ≈0.19）；
- 若杆本来就在 19% ⇒ 那"现在有 20%"就是**配置 `afbUsesHandleAsCap=true`（笔记 253）按用户口径在工作**：
  手柄决定力，AFB 只能削不能加。

## 2. 新增：原始轴值日志（notes/254，回答上面那个事实问题）

`MmtrHidInput.poll()` 里加（fabric + forge 两份），只在**真的动了杆**（任一轴出死区）且
`-Dmmtr.trace=true` 时打，1 s 一次：

```
[MMTR-HID] 轴原值：X=0.000 Y=0.190 Z=-1.000 → 定速=0 油门=18 制动=0（死区 0.05）
```

用户把杆推到他心里的"50%"时，这一行会直接给出**轴的真实数值**：

- `Y≈0.19` ⇒ 杆的物理行程只到 19%（或轴的中位/量程不标准）⇒ 我加**按轴校准**（`-Dmmtr.hid.y.min/max`
  把一段子行程映射到 ±97，或给中心偏移），而不是去动力模型；
- `Y≈0.50` 而 `油门=18` ⇒ 映射/轴号错了（例如读错了轴），改 `MmtrHidMapping` / `-Dmmtr.hid.axis.y`。

设备行（已确认用户用的是杆，不是键盘）：

```
[MMTR-HID] 手柄 ShuisoiContorller (GLFW id 0, 轴 4)：X(0)→定速巡航 0..160 步5 · Y(1)→油门手柄 ±97（正=牵引） ·
           Z(2)→制动 运行..EB；死区 0.05；反转 X=false Y=false Z=false
```

## 3. 语义那一半（与校准无关，需要用户一句话定夺）

notes/253 把 `afbUsesHandleAsCap` 改成了 `true`（手柄是上限，AFB 只削）。用户前后两次口径看起来相反：

- 「油门设置在 50% 时也是 300 kN」⇒ 反对"AFB 盖掉手柄"；
- 「现在有 20%」⇒ 若手柄真在 19%，则反对"手柄压住 AFB"（AFB 想拉到设定速度却只有 19% 的力）。

两条只有在"手柄其实一直在 19%"这个前提下才同时成立 —— 所以先把 §1/§2 的事实定下来，再决定开关：

| 选择 | 含义 | 配置 |
| --- | --- | --- |
| A. 手柄是上限 | 手柄 20% ⇒ 力最多 20%，AFB 只削不加（当前） | `afbUsesHandleAsCap=true` |
| B. AFB 可超过手柄 | 定速挂着时 AFB 自己给力，手柄只作司机自己的诉求 | `afbUsesHandleAsCap=false` |
| C. 先修校准 | 杆在 50% 应读 50%，其余照 A | 加轴校准参数 |
