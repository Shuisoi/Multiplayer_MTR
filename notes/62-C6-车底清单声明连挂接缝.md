# 62 - C6 前置：车底清单/作业单可以声明连挂接缝（`mmtrCouplerAfter`）

> 用户方向：机辆模式（机车 + 挂车）刷出来的编组要能解挂；设计文档 §8 **O3**（"挂车 8 条目 → 一条车列"的
> 映射层级：车底清单 / 作业单 / 编组模板谁来声明）本轮定案。
> 引擎侧两处改动 + 3 个用例；无模组侧改动。

## 定案：接缝由 `MmtrCarSpec` 声明（三条路共用）

车底清单（`mmtr-rolling-stock.json`）、作业单（`mmtr-jobs.json`）、编组模板（`mmtr-consist-templates.json`）
**都**经 `MmtrCarSpec` 落到 `VehicleCar`，所以接缝只在这一个地方声明，字段名沿用运行时字段：

```jsonc
{ "vehicleId": "saf101", "length": 16, /* … */ "powered": true, "mmtrCouplerAfter": true }
```

- `mmtrCouplerAfter` = "本节车与**下一节**之间有一个车钩"（即该边界是合法解挂点）；
- 默认 `false` = 整列固定单元（HST8 这类不可解挂的编组保持原样，老作业单/老清单零迁移）；
- 放在**每一组可摘挂车列**的末节上（例如 `机车(true) + 客车(false)`，或 `8 节 EMU(false×7) + (true)` 做重联）。

## 改了什么

| 文件 | 改动 |
| --- | --- |
| `MmtrCarSpec` | 新增 `mmtrCouplerAfter`（读/写 JSON，默认 false）；`toVehicleCar()` 用既有 setter 写到 `VehicleCar` |
| `Siding.mmtrConsistWalkerFromYard` | 生成行走器时把接缝算进去：`MmtrConsistBody.seamArcMsFrom(...)` / `seamCarIndexesFrom(...)` 传给 8 参 `MmtrConsistWalker.place`（原来只传 7 参，接缝被丢掉） |

**为什么第二处是必须的**：`MmtrCoupleSurgery` 连挂/切分时**自己**会算接缝（`seamArcMsFrom`），
但**出生**路径（车场刷车）原来不算 —— 于是清单里写了接缝，车一出来还是"整列固定单元"，
`uncouple` 直接以"该处没有车钩"拒绝。这正是用户看到的现象。

## 用例

| 用例 | 断言 |
| --- | --- |
| `MmtrCarSpecTests.couplerAfterRoundTripsAndReachesTheVehicleCar` | 声明 true → JSON 往返后仍 true → `toVehicleCar().getMmtrCouplerAfter()` 为 true；未声明 → false |
| `MmtrCarSpecTests.legacyPayloadWithoutCouplerAfterStaysAFixedUnit` | 删掉字段的老载荷 → false（零迁移） |
| `MmtrManifestMotionSpawnTests.manifestStockDeclaresItsCouplingSeams` | 两节清单（机车 true + 挂车 false）刷出后：车列 2 节、首节 `mmtrCouplerAfter=true`、`body().seamCount()==1`，且 `MmtrCoupleSurgery.uncouple(sim, id, 0)` **成功**、前段保留 1 节 |

## 验证

- 上述 2 个测试类 8/8 通过；
- 全量引擎套件：本片零新增失败（见提交说明）。
