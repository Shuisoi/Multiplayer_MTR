# 125 - T4（四）：作业单驱动整趟 —— 逐步进路与许可的**口径**

> 对应设计：`docs/01-设计/行车控制-任务联锁与行车许可-设计.md` §6（T4 ④）。
> 前置：notes/121/122/124。触发：用户 2026-09-14「一路把T做完吧」。

## 1. 设计的那句话需要先定口径

设计 ④ 写的是"作业单驱动整趟（MOVE_TO → SERVE → COUPLE）**每步都有进路对象与许可**"。

照字面做会写出一条**错的**断言：**SERVE（开关门）与 COUPLE（连挂手术）本来就不该有进路** ——
它们是动作步/作业步，不是走行。同一份用例末尾那条"手术后不留孤儿进路"
（`no orphan route survives the coupling surgery`，S5 实机 2026-09-09 的回归）
说的**正是这个意思**：连挂做完之后进路就该没了。

所以正确的口径是：**走行类步骤全程都要有进路与许可；动作/作业步不需要，也不能留**。

## 2. 交付

在既有 `MmtrTaskDrivenCouplingTests.runShunt` 的 tick 循环里**逐步采样**（只看驱动步 `stepIndex == 0`）：

```java
while (ticks < 900 && jobScheduler.stateOf("loco") != DONE) {
    n.tick();
    ticks++;
    if (jobScheduler.stepIndexOf("loco") == 0) {
        if (n.sim.mmtrRoutes.route(loco.getId()) != null) driveStepHadRoute = true;
        if (loco.mmtrMovementAuthority() != null)        driveStepHadPermit = true;
    }
}
assertTrue(driveStepHadRoute,  "④ 驱动步（MOVE_TO）全程都要有进路对象");
assertTrue(driveStepHadPermit, "④ 驱动步全程都要有行车许可（与进路同源）");
```

**结果是通过的** —— 也就是说"任务 = 进路意图"这句话从**架构声明**变成了**运行时可观测的事实**：
不是"设计上应该"，而是"每 tick 采样下来确实有"。

## 3. 为什么改既有用例而不是新建一个

这份夹具（车场两股道 + 站立的挂车 + 跨道调车 + 连挂手术）是仓库里唯一一条**真正由作业单驱动整趟**的路径；
另起一套会有两个夹具要同步维护，而且一定会漏掉这条路径上真正的难点（跨道调车授权、手术重建对象、
留孤儿进路）。所以本片**改的是既有用例的采样**，不是新增用例 —— 这也解释了为什么
全量用例数**没有变**（571 → 571），变的只是它检查得更深了。

## 4. 验收

- 全量引擎：**571 通过 / 0 失败 / 4 跳过**（用例数不变；新增的是断言，不是用例）。
- 两条新断言都在驱动步全程采样，比"终态对了就算过"强：它能抓到"中途某一 tick 进路掉了"这一类回归。
