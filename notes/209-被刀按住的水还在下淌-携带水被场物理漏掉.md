# 209 · 「整片玻璃上的部分小水珠跟着走」的真因：被刀按住的水还在自由下淌

> 用户第二轮实测（v36 已装，`span` 已全是非零、回程已不带水、下流正常）：

> （「仅限驾驶室内看」不是线索：`waterOffsetM = -0.05` 把水层放在玻璃**司机侧**，
> 车外本来就被玻璃的深度写入挡掉，见 note 205。）

## 1 真因：`advanceDrops()` 不区分"是否正被刀按住"

每帧的顺序是：

```
advanceWiper()   → 臂动
advanceDrops()   → 全场物理：重力 / 蠕变 / 密度锁下流 / 侧向抖动
applyWipe()      → 刀把水推走、捡起、携带
```

`advanceDrops()` 对所有可见雨滴一视同仁，**包括刚被刀捡起、正被推着走的水**。
于是被携带的雨滴每帧同时吃两个位移：刀给的一个、场物理给的一个。
现实里被刀推着的水是被**按住**的，不会一边被推一边自由下淌。

### 1.1 量它的过程（三次取样，每次都推翻了上一层的猜测）

新增探针 `carrySpreadProbe()`：一趟外行程，逐帧量每颗"被携带"雨滴离刀有多远。
第一版读数：**最远 73 mm**（而拾取时的允许量只有淡出带 30 mm + 合并 12 mm = 42 mm）。

| 猜测 | 量出来的结果 | 结论 |
|---|---|---|
| `carriedM` 的投影钳位让它少走 | 去掉钳位后仍是 73 mm | **否**（钳位确实该去，见 §3，但不是主因） |
| 有东西把雨滴瞬移了 | 每帧"自身位移 vs 刀位移"最大差只有 **24.9 mm** | **否** |
| 拾取那一刻就带这么远 | 拾取时 30 mm，**携带过程自己加了 47 mm** | 携带过程有问题 |
| 偏移相对**刀中点**（刀正是按它的位移搬运珠子）是否守恒 | **长了 258.6 mm** | **是**：842 个携带帧、平均约 0.3 mm/帧、方向一致 |

所以：**被携带的水一边被刀推、一边被场物理往下拽，逐渐从刀前缘线里漏出去**，
散成一片位置各异的雨滴各自跟着刀走。这就是「整片玻璃上的部分小水珠跟着走」。

## 2 修法：被按住的水只跟刀走

```java
for (int index = 0; index < drops.length; index++) {
    final Drop drop = drops[index];
    if (drop.carriedByBlade) {
        continue;   // 刀正按着它：它只随刀移动，既不下淌也不蠕动
    }
    advanceDrop(drop, densityPerM2[index], elapsedSeconds, liftSpeed, lateralAccel, down);
}
```

**实测（同一探针）**：

| | 修复前 | 修复后 |
|---|---|---|
| 刀中点偏移增长 | **258.6 mm** | **0.0 mm** |
| 离刀最远 | 73 mm | **30 mm**（全是拾取时带的淡出带，携带本身只加 1 mm） |
| 被携带帧位移为 0 的 | 0 | 0 |
| 一趟被携带的不同雨滴 | 52 颗 | 49 颗 |

`0.0 mm` 是可证明的：刀中点每帧正好移动 `bladeAdvanceM` 方向 `push`，
而被携带的雨滴每帧正好被移动 `bladeAdvanceM · push`，所以"雨滴 − 刀中点"逐帧严格守恒
（见 §3：这也正是那处投影钳位应当删掉的理由）。

## 3 顺带删掉的投影钳位（note 207 §6 遗留项 1）

```java
// 旧: min(bladeAdvanceM, max(0, progressBladeM - drop.wavePickedProgressM))
final double carriedM = bladeAdvanceM;   // 现在
```

`progressBladeM` 是刀中点在一个**随行程转动**的方向上的投影，而 `wavePickedProgressM`
是拾取时用**当时**的方向算的，两者相减不是坐标系不变量（角原点常量项不抵消）。
它只会**减少**携带，而现在证明了携带本来就只需要刀自己的位移，所以连同
`Drop.wavePickedProgressM` / `progressBladeM` 一起删掉。

## 4 被灌过水的数字要向下修正（第二次）

"被携带的水还额外吃重力"这条，让所有**以位移衡量携带**的数字都偏高。修正后：

| 量（一趟外行程，同一块玻璃） | 修正前 | 修正后 |
|---|---|---|
| 平均携带距离 | 607.4 mm（54%） | **525.1 mm（47%）** |
| 携带分布 min/中位/max | 47 / 585 / 1099 mm | **94 / 515 / 1099 mm** |
| 行程末端水浪规模 | 23 颗 | **32 颗** |
| 三档（刀去的一侧/中段/起始侧） | 51/11/21 | **63/17/36** |
| 折返时释放 | 39 颗 | **54 颗** |

**47% 不是变差，是变诚实**：均匀拾取的犁水，平均携带必然是行程的一半左右
（最早拾取的那颗能走满 1099 mm = 98%），之前多出来的 7 个百分点是重力贡献的、不是刀搬的。

同理，**中雨与满强度的"水收成堆就会流"变强了**（因为水浪不再边推边漏）：

| | 修正前（诚实值） | 修正后 |
|---|---|---|
| 满强度水带 1 s 走 | 214.9 mm（0.160 m/s） | **314.8 mm（0.299 m/s）**，未刮玻璃 84.4 mm → **3.5×** |
| 中雨(0.60) 水带 1 s 走 | 94.5 mm（1.46×） | **270.0 mm**，未刮玻璃 125.7 mm → **2.15×** |

所以 note 208 §5 那次"向下修正"现在被部分收回：中雨的因果不但成立，而且幅度回到 2.15×
（note 206 当年记的 2.2× 竟然接近真相，但它的构成里混着扫掠带的 bug，两件事互相抵消过）。

## 5 断言重定（都是重新推导，不是放水）

| 断言 | 原来 | 现在 | 理由 |
|---|---|---|---|
| 携带 | 平均 ≥ 行程 50% | **最远 ≥ 90%** 且**平均 ≥ 35%** | 均匀拾取的犁水平均必然≈半程；"能带满全程"才是设计主张，用 max 判 |
| 收集区 | 停放数逐趟增长 | **停放的水被再次捡起 = 0 颗** | 落区的水会往下流走、出玻璃变重生，停放数本就不该累积；该守的是"不再被捡起"这条契约 |
| 携带水离刀 | （新） | **相对刀中点偏移增长 < 5 mm** | 修复前 258.6 mm，修复后 0.0 mm |

收集区探针同时修了两处**探针自身**的假阳性：
① `pushedThisStroke` 是整趟累积的，珠子可能在**被停放之前**（作为水浪）就被标记过；
② 落区的珠子流出玻璃重生后会以普通雨水身份被推，这是合法的。
所以这条不变量必须**逐帧**判："仍处于停放状态 且 本帧刚被判为被推"。
最终读数：**0 颗**（第一趟后停放 16 颗）。
