# 102 - ④ 显示层：道岔/岔区未清 → 灯显危险（引擎 + 客户端）

> 承 notes/99（① 区间入口停车）、notes/100（② 岔区清限）、notes/101（③ 占用锁闭收尾）。
> 遗留缺口：①②③ 让引擎把车扣在信号前，但**自由驾驶（无进路）**时那架灯按占用链可能还是绿的。

## 1. 规则（引擎与客户端同一条）

新增 `MmtrJunctionState`：一个**岔节点"未清"** = 下列任一：

1. **岔区被占（②）**：任意车辆的 footprint 落在该节点的清限区内（每根汇于该节点的轨靠近节点的
   `Vehicle.MMTR_JUNCTION_CLEARANCE_M = 10 m`）；
2. **道岔没人定（①/③）**：该节点是岔（≥3 根轨），且**所有进向**都没有人工位、也没有任何授权持有人
   —— 道岔没有位置，任何进路都无法排出来。真实联锁对这种情况就是红灯。

于是链走行里**每一步**（区间 R，从 N0 进入、经 N1 离开）被判定为"受限"，如果：
该区间被占 **或** N0 未清 **或** N1 未清。受限 → 该深度即链深（1=红，2=单黄，3=双黄）。

对照效果：
- ③ 把车扣在保护 R 的那架灯前（R 的远端是未定道岔）→ 该灯 **红**（原来绿）；
- ② 把车扣在岔前（R 的入口节点被占）→ 保护 R 的那架灯 **红**（原来绿）；
- 道岔已定（真实服务端默认把每个岔预置成人工位 0）且清限区干净 → 一切如常（**绿**），自由驾驶不受影响。

## 3. 用例

- 引擎 `MmtrSignalAspectTests.anUndecidedForkAndAFouledJunctionRestrictTheSignal`：未定岔 → 红；预置人工位 → 绿；
  清限区内有 footprint（S 轨 3..5 m）→ 红；道岔已定 + 下一区间被占（权威色通道）→ 单黄。
- 引擎既有 3 例 `MmtrSignalAspectTests` 的合成网络补上"真实服务端默认预置人工位 0"（否则每个岔都未定 → 全红），
  注释写明原因（`Simulator.mmtrDefaultPointsZero`）。
- 客户端 `MmtrSignalChainTests.aRestrictedJunctionCountsAsOccupied`：镜像里 N 未清 → 链深 1（红）；清除后 → 0（绿）。

  `signals` 里该岔的三根轨立刻 `GREEN → RED`（红灯总数 7 → 13）；恢复 `branch=0` 后回到 `GREEN`（10）。
  另：`mmtr-points` 显示 `-212,-60,-159` 这类岔 `manual=-1`（任务跑完后被清空、不会自动恢复）→ 现在显示红灯，
  与引擎行为一致（自由驾驶的车到了这种岔真的会被扣住）。

## 4b. 一处修正（首版过严）

首版把"任何 ≥3 根轨的节点没有人工位/授权"都算未清 → 对**不是真岔的节点**（各进向都只有 1 条前向腿，
例如某根轨在节点处只能 180° 折返）误报红灯。修正：只对**真正需要选择**的进向（`MmtrPoint.computeOrderedLegs`
算出 ≥2 条腿）要求人工位/授权；真实服务端会为每个 (岔, 进向) 预置 branch 0，所以正常世界不触发。
用例里的合成网络也按同样方式补全所有进向的预置。
