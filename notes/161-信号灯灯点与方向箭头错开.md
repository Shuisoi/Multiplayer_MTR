# 161 = 信号灯：画成一个整体再放置（三次要求的收敛）

> 用户 2026-09-15 对同一处连着提了三次：
> ① 「信号灯图标的点和方向指示位置需要**错开一些**」；
> ② 「**现在距离又太大了**」；
> ③ 「**现在箭头又一左一右了**」；
> 最后定调：「**这个还是删了重新画吧，先画成一个整体再放置**」。

## 一、三次都错在同一个地方：两个图形各自算位置

前两版里，灯点与折角是**两个绝对定位的子元素**，各自算各自的位移：

| 版本 | 做法 | 结果 |
| --- | --- | --- |
| 原版 | 两者都画在同一个锚点 | 折角尖的可见外缘离中心 1.68 px，灯点半径 2 px ⇒ **尖戳进灯点**（①） |
| v2 | 沿管辖轴一前一后：箭头进 12、灯点退 8（轴距 20 px） | 折角是**敞开的 V**，灯点落在 V 的开口里 ⇒ 只能继续拉大轴距 ⇒ **距离太大**（②） |
| v3 | 箭头"侧向 14 px" | 侧向**跟着朝向转** ⇒ 南行灯在左、北行灯在右 ⇒ **一左一右**（③） |

三次的根因是同一个：**位移挂在一个会转的坐标系上，而且两个图形分别计算**。

## 二、现行做法：一个整体 + 一次放置

```
一个 <svg viewBox="0 0 20 20.5">          ← 内部几何是常量，只在一处可出错
  <path class="chevron-outline">          ← 折角（黑描边，比本色宽一圈）
  <path class="chevron">                  ← 折角本色（状态色）
  <circle class="lamp">                   ← 灯点（状态色），圆心 = 世界坐标落点
```

放置只做一次：

```
transform: translate(屏幕坐标) rotate(管辖方向) translate(−灯点)
```

- 位移里**没有任何与角度有关的项** ⇒ 不会一左一右（③ 的修法）；
- 灯点与折角的间距是**布局常量** ⇒ 不会"越调越远/越调越粘"（① ② 的修法）；
- 折角画在灯点正上方、与灯点同一条竖线 ⇒ 整组旋转时箭头不会偏到一侧。

## 三、内部几何是搜出来的，不是摆出来的

判据（`scripts/signal-overlap.test.ts`，`npm run test:signal`）：

1. **可见空隙 ≥ 0.6 px 且 ≤ 2.5 px**（一头防"戳在一起"、一头防"距离太大"）；
2. 整体宽 = 图标规格（8 px @6×）、高 ≤ 1.5×图标、灯点直径 = 灯点规格（4 px）；
3. 折角的尖与灯点同一条竖线、两条腿左右对称（防"旋转后换边"）；
4. 尺寸与空隙都按倍率缩放；
5. 灯位偏移不含"沿管辖方向"的分量（那是"一左一右"曾经藏身的地方）。

几何算法：折角按"线心折线 + 半个**可见描边**"算（可见的是那条 5 单位宽的黑色描边，
不是 2.6 单位的本色笔画 —— 算错这一条会把空隙估大），对两条腿的线心密集采样
（步长 0.02 px）求到灯点圆心的最近距离，再减去灯点半径。
**组件与单测共用同一份几何**（`signalUnitChevronPath()`），否则单测量的是"我以为画了什么"。

最终值（`DECAL_KINDS.signalUnit`，viewBox 单位；盒宽 20 单位 = 图标 8 px ⇒ 1 单位 = 0.4 px @6×）：

| 项 | 值 | 换算 @6× |
| --- | --- | --- |
| boxWidth × boxHeight | 20 × 20.5 | 8 × 8.2 px |
| 灯点圆心 | (10, 16) | 世界坐标落点 |
| 灯点半径 | 5 | 直径 4 px |
| 折角尖 | (10, 4) | 在灯点正上方 4.8 px |
| 折角腿下端 | (2, 10.5) / (18, 10.5) | 腿铺开到盒子两侧 |
| 折角本色笔画 | 2.6 | 1.04 px |
| 折角黑描边 | 5 | 2 px |
| **可见空隙** | 1.86 单位 | **0.74 px** |

这一组是**搜出来的**：在参数空间里按"空隙 ≈ 0.8 px / 灯点 4 px / 整体高 ≤ 1.4×图标 /
折角可见高 ≥ 4.6 px"筛，3731 组候选里取分数最高的。

## 四、页面上实测（无头 Edge + CDP，`sandbox/check-web-signal-unit.ps1`）

96 盏灯：

| 倍率 | 整体 | 灯点直径 |
| --- | --- | --- |
| 1.000 | 1.33 × 1.36 px | 0.66 px |
| 1.749 | 2.33 × 2.38 px | 1.16 px |

- **96 盏灯的"灯点相对盒子"极差 = 0.0000 px** ⇒ 整体放置、与朝向无关（③ 的判据）；
- 灯点直径 1.16 px ≈ 4 px × 0.292（误差 0.2%）；
- 整体宽 2.33 px ≈ 8 px × 0.292（误差 0.2%），宽比 1.753 ≈ 倍率比 1.749（误差 0.2%）。

## 五、顺手记下的两个坑

1. **`Measure` 是 PowerShell 内建别名**（`Measure-Object`）。函数取名 `Measure` 时调用会被解析成
   那个 cmdlet —— 现象是"函数里的输出一句都不出现、返回的却是个统计对象"（`GenericMeasureInfo`），
   而真正的报错被 `try/finally` 吞掉。别用 `Measure`/`Select`/`Where`/`Sort` 这类内建别名命名函数。
2. **采集用的那段 JS 要单独放 `.js` 文件**：它含模板字符串与反斜杠，写在 PowerShell 的
   here-string 里被咬坏过两次（症状是脚本静默退出、什么都不输出）。同目录的
   `signal-unit-measure.js` 就是为此存在的。
