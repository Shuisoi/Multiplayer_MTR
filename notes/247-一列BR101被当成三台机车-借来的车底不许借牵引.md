# 247 — 一列 BR101+p1+p1 被当成三台机车（加速度很不正常的真因）

用户口径（2026-09-23）：

> 现在牵引做到什么地步了，现在进游戏加速度很不正常

这一轮把"牵引到底是谁的"钉死：**借来的车底不许借牵引**。

## 1. 现场证据（先量，再改）

| 来源 | 读数 | 说明 |
| --- | --- | --- |
| `[MMTR-CONSIST]` 日志 | 16:29:29 v=0.040241 → 16:29:31 v=0.043216（m/ms） | 2 s 内 Δv = 2.97 m/s ⇒ **a ≈ 1.49 m/s²**，当时 145 km/h、牵引比 100% |
| `mmtr-rolling-stock` API | 三节车都是 `"powered": true`、`"consistTypeId": ""` | p1 客车被当成动力车，而且没声明车底 |
| 现场 `carTypeIds` | 只有 `{"br101": "br101_three_handle"}` | **p1 没有任何映射** |
| `MmtrComposition.fromVehicleCars` | 解析不出车底 ⇒ `type = fallbackType` | 兜底用的正是"说话那节车"的车底 = BR 101 |

⇒ 整列按 **3 台 BR 101** 算：252 t 只是变重，但 **牵引 900 kN / 19.2 MW、常用制动 450 kN 全是三倍**。

模型核算：

| 模型 | 起步 a | 145 km/h 处 a |
| --- | --- | --- |
| 三台机车（错误） | 900 kN / 292 t = **3.08 m/s²** | (19.2 MW/40.3)/292 t = **1.63 m/s²** ← 与实测 1.49 吻合在 5% 内 |
| 一台机车 + 两节客车（正确） | 300 kN / 182 t = **1.63 m/s²** | (6.4 MW/40.3)/182 t = **0.85 m/s²** |

日志反推的 1.49 m/s² 落在错误模型上、离正确模型差 75% —— 这就是"很不正常"。

## 2. 四处改动

### 2.1 代码：借来的车底不给牵引（`MmtrComposition.fromVehicleCars`）

两遍扫描：

1. 车列里**有**任何一节显式解析出车底（车厢声明 / `carTypeIds` 映射）⇒ **所有**借来的车按
   `ConsistType.asHauledTrailer()`：质量 / λ / 制动 / 阻力 / 气路照借，**`F_max = P = 0`**（id 不变，便于认账）。
2. 一节显式的都没有（"整个维度只有一个缺省车底"的老情形）⇒ 只有**第一节**借牵引，其余按拖车。
   —— 这样"整列同型车"的质量照旧进物理，牵引却不会随节数翻倍（老行为是 N 倍功率）。

借了车底就**必须喊**（`[MMTR-CFG]`，按车型只喊一次）：

```
[MMTR-CFG] 车厢 p1 既没声明车底、carTypeIds 里也没有它 —— 按「说话那节车」的质量/制动/阻力兜底，
**不给牵引**。请在 carTypeIds 里给它配一份车底，否则它的牵引/质量都是借来的（notes/247）。
```

### 2.2 代码：说话的车必须真能出力（`MmtrCarTypeResolver`）

优先级改成 ① 动力车 + 车底能出力 → 立刻选；② 能出力但不是动力车；③ 动力车但车底零牵引；④ 随便第一节。
新增判据 `ConsistType.canPull()`（牵引力或功率非零）。

为什么要有 ②：世界数据把挂车的 `powered` 缺省写成 `true` 很常见，若这节挂车排在机车**前面**，
老逻辑会让它当"说话的车"，整列车按零牵引跑 —— 表现是"手柄推到底车不动"，而且看不出是谁的锅。

### 2.3 数据：p1 有了自己的拖车车底

`config-example/consist-types.json` 新增 `p1_trailer`，并在 `carTypeIds` 里加 `"p1": "p1_trailer"`：

| 字段 | 值 | 依据 |
| --- | --- | --- |
| `massKg` | 40 000 | 16 m 客车，与仓内既有客车质量口径一致 |
| `rotatingMassFactor` | 1.06 | 非机车口径 |
| `maxTractiveEffortN` / `maxPowerW` | **0 / 0** | 拖车 |
| `serviceBrakeForceN` | 70 000 | 制动重量 ≈1.4×车重 = 56 t，按 BR 101 同一推导 1.25 kN/t |
| `emergencyBrakeForceN` | 98 000 | ×168/120（notes/246 的 R+E/R） |
| `resistanceAN/BN/CN` | 400 / 11 / 1.3 | 40 t 级客车 |
| `controlMode` | NOTCHED | 它不该当操纵车底 |

`apply-consist-config.ps1 -Force` 已重装 4 份现场配置。

### 2.4 数据：p1 不再声称自己有动力

`run/world/**/mmtr-rolling-stock.json` 里两节 p1 的 `powered` 改成 `false`（br101 仍 `true`）。
以后要摆这种编组，用 `mmtr-vehicle` 命令的 `--unpowered` 挂拖车（`MmtrVehicleCommands` 早就支持，
现场当时是默认给动力摆的）。

## 3. 改完之后这一列车的数（用例钉住）

| 量 | 值 |
| --- | --- |
| 质量 | 84 t + 2×40 t = **164 t**（λ_eq = 1.111 ⇒ 惯性 182 t） |
| 牵引 | **300 kN / 6.4 MW**（只有机车那一份） |
| 常用制动 | 150 + 2×70 = **290 kN** |
| 起步加速度 | **≈1.63 m/s²** |
| 145 km/h 处 | **≈0.85 m/s²** |

`MmtrConsistTractionMappingTests`（新，5 条）钉住：借来的车底不给牵引；整列没配时只有第一节给牵引；
说话的车必须能出力；随包配置里 p1 有自己的拖车车底且零牵引；**BR101+2×p1 的起步加速度落在 1.4–1.8、
145 km/h 落在 0.7–1.0** —— 这一条就是"加速度很不正常"的回归判据。

## 5. 牵引模型现在做到哪一步（回答"牵引做到什么地步了"）

## 7. 这一轮的诊断盲区也一起补了（下次重启生效）

`[MMTR-CONSIST]` 原来只打手柄/牵引比/速度 —— 这次能定位，是靠**速度序列反推加速度**，代价太大。
现在它多打一项"这列车在按什么物理跑"：

```
[MMTR-CONSIST] 车底类型分支：手柄=95 制动=0 换向=1 定速=160 控制器=ThreeHandleDriveController
  牵引比=100%/电阻0% AFB=true 速度=… 本次距离=…m 质量=164.0t λ=1.11 牵引=300.0kN 功率=6.40MW 常用制动=290.0kN 车底=consist:br101_three_handle
```

（该改动只在源码里 —— **不再**在一次运行中重灌 `game/libs` 的 jar：notes/216 记过"运行中换 jar"的三类静默失败。
下次重启时随 `sync-engine.ps1` 生效。）
