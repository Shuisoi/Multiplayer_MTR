# 43 - 换端语义修正：编组体 + 双驾驶室（Motion Core/Vehicle 深度重写立项）

> 用户实机/概念修正（2026-09-08 夜）：notes/42 遗留的"尽头换向"处理**方向错了**——
> 换端不是列车原地掉头 180°，而是"司机走到另一端驾驶室"。这是一次对
> **Motion Core / 道岔 / 信号**三方位的集成修正，并以 **Motion Core + Vehicle 深度重写**立项。
> 设计：docs/01-设计/运动系统-编组体与双驾驶室换端-设计.md。

## 根因（代码事实）

- `MmtrMotionWalker` 只有**单点**状态（rail/enteredFrom/ahead/offset），无车尾、无长度、无姿态；
- `flipDirection()`（walker:359）交换前后节点并**追加反向 PathData 回段**；
- `Vehicle.refreshMmtrMotionLegs()`（1409）把含反向回段的 leg 链直接推给客户端
  `mmtrSetSyncPath`；`MmtrMotionSnapshot.ofWalker()`（110-123）还硬编码 `segmentReversed=false`；
- 结果：换端后**车体位置未变但同步路径方向整体反转** → 客户端重放时车体朝向翻转 180°。
- 结论：这是**数据模型缺陷**（单点表达不了双端编组），不是渲染 bug。

## 用户拍板（定案）

1. **换端 = 司机动作**，序列：列车停稳 → 拔钥匙 → 走到另一端驾驶室 → 插回钥匙。
   因此换端可在任意位置/任意时刻**发起**，但只有满足序列才生效；不涉及运行中反向行驶
   （与红线 748a349「不能倒车」相容）。
2. 驾驶室抽象 = **把司机固定在列车某个点，直接写死**；本轮写死为"编组两端各一驾驶室"，
   动力集中式（双驾驶室同车）为显式已知简化，扩展点预留 `cabAtArcM`。
3. 本轮**只重写 motion 分支**，legacy `immutablePath` 分支不动。
4. **整列占用 `[tail..head]` + 车尾清岔（rear-clear）+ 信号按整列**纳入本轮。
5. **信号新增设计冻结**：S1–S4 只做接线（整列占用、操纵端制式），不再推进 A2/S5 新设计。

## 目标模型（要点）

- 编组体 = 轨道图有向区间 `spine + aEndArcM + lengthM`；车辆中心由 **A 端**度量 →
  **换端不改变任何车辆位置**（数学保证）。
- `activeCab ∈ {NONE, CAB_A, CAB_B}`：行进方向 = activeCab 朝向，前端 = 该方向一侧的编组端；
  `ControlState.reverser` 继续忽略。
- 换端状态机：`insertKey` 需（停稳 ∧ 无他钥匙 ∧ 司机在目标驾驶室）；`removeKey` 任意时刻合法，
  运行时拔钥匙 = 失去牵引 → 服务制动停稳。
- 道岔：hold 归属列车，**车尾出清**才释放（现行"头过即释放"作废）；岔区占用 = 编组区间 ∩ 岔区。
- 信号：占用写整列区间；制式/AWS/LZB 读**操纵端所在轨**。
