# 07 移动世界 e2e 测试基建（M1 探针）— 进展与配方

目标：在引擎单测里重演 MTR 世界生成，让一辆车从 depot 发车并沿线路运行，
用于自动化验证 认领→驾驶→SPAD/保护→镜像→mmtr_couple/uncouple 世界层执行器。

## 探针发现（代码事实）
- Depot extends DepotSchema, schema javaExtends AreaBase<Depot,Siding>：
  - Depot 持 routeIds；writeRouteCache(routeIdMap) -> routes -> platformsInRoute。
  - Depot.tick() 驱动 SidingPathFinder（area 内 rails）并在成功后对每个 siding 调
    siding.generateRoute(platformsInRoute[0], 末位, 数量, cruisingAltitude)；
    siding 完成后 finishGeneratingPath -> generatePlatformDirectionsAndWriteDeparturesToSidings()。
  - siding 在 Siding#simulateVehicles：area != null 且 defaultPathData != null 且 vehicleCars
    非空 且 spawnTrain 时 new Vehicle(...) 放入 vehicleIdMap（发车需 departures/手动）。
- Siding.area 指向所属 Depot(AreaBase<Depot,Siding>)；area/child 接线在 AreaBase 里。
- Rail 工厂签名很长（曲线/超高/样式），轨道连通靠端点；SidingPathFinder 在 depot area rails 上寻路。

## M1 最小网络配方（待实现/验证）
1) 新 Simulator。
2) 建两站两站台 + 直轨平台 rail + 连接 rails；站台 rail 属性 isPlatform。
3) 建 Route（routePlatforms: A→B），加入 simulator.routes & depot.routeIds。
4) depot：setCorners 覆盖 siding/站台、setFrequency 全时段>0、addSiding?（AreaBase 提供）、
   simulator.depots.add(depot)、simulator.sync()。
5) 反复 simulator.tick() 让 Depot.tick 跑 SidingPathFinder 至 finishGeneratingPath；
   断言 depot.getLastGeneratedStatus()==SUCCESSFUL、siding 有 defaultPathData。
6) 断言首个 Vehicle 生成并 railProgress 前进（M2）。

## 第二轮发现（M1 配方收窄）
- **挂接是位置的**：Data#mapAreasAndSavedRails 按 savedRail.midPosition 落在 area 角点内 + 运输模式匹配
  自动设 Siding.area/Depot.savedRails —— 测试里只需 Depot.setCorners 包住 Siding 位置 + simulator.sync()。
- Depot.init()（writePathCache→savedRails Siding::init→写时刻表）；Depot.tick 每 tick 推进
  SidingPathFinder，成功→siding.generateRoute(首站台…)，完成→departures。
- Station(Data)/Platform(pos1,pos2,mode,data)/Route(mode,data)/RoutePlatformData(platformId) 均可直接构造；
  RuntimeTests 演示 station+platform 经 HTTP update 建实体；ArrivalResponseTests 演示 Route+RoutePlatformData 用法。
- 瓶颈收窄到两块：
  1) 真正 rail 网络（含 isPlatform rail、连通、speed/样式参数）+ 轨道位置与 platform/station 对齐；
  2) SidingPathFinder 起点（depot 区域内 siding 的 saved rail）→ 站台 rail 的可寻路路径。
- 下一步（M1 round2）：读 Rail 连通(addConnectedRail/端点匹配)与 Siding.generateRoute/finishGeneratingPath，
  以及 Platform 与对应 rail 的绑定(platform.savedRailId?)；随后在测试里首次组装“站台rail+直轨+折返”试跑。

## 第三轮结论（rails 是前置契约）
- sync() 会 removeIf 无有效 rails 的 platform/siding（isInvalidSavedRail）→ 无 rails 什么都不挂接。
- 已用 MiniWorldWiringTests（org.mtr.core.data）把该契约固化为绿测试（无 rails 不挂接）。
- 下一步 M1 round4：用 Rail 工厂建直轨（platform rail + 连接 rail + siding rail），
  验证 platform 落在 platform rail 上后 station.savedRails 挂接成功（替换本契约测试为正断言）。

## 第四轮结论（rails 正挂接 OK）
- Platform/Siding 合法 = 存在端点完全相同的真实 rail 且带 isPlatform/isSiding flag（SavedRailBase#isInvalidSavedRail）。
- MiniWorldRailsTests（绿）：newPlatformRail/newSidingRail + 同名端点 platform/siding → sync 后
  station/depot.savedRails 正挂接、实体不被剔除。
- 下一轮 M1 round5：把 rails 连成一条线（端点相连），两站两 platform、depot 车场支线 + route，
  跑 depot.init/tick 至 GeneratedStatus.SUCCESSFUL（或记录首个寻路失败原因）。

## 第五轮状态（M1 剩余阻塞点收敛）
- rails 正挂接已绿；剩余：连通线路 + Route(routePlatforms 装配 API 未定位) + depot.generateMainRoute 触发链。
- Depot: init()/sync 后 writeRouteCache(routeIdMap)；generateMainRoute 按 platformsInRoute 相邻对建
  SidingPathFinder；每 sim tick depots tick 推进；GeneratedStatus: NO_SIDINGS/TWO_PLATFORMS_REQUIRED/PATH_NOT_FOUND/SUCCESSFUL。
- 待定位（下轮，一次 grep+read）：Route 平台顺序字段/方法（routePlatforms 或 addRoutePlatformData），
  Platform 与 rail 的方向/停靠位；随后写 MiniWorldLineTests（两站直轨+depot 支线+route），
  以“无异常 + 打印 GeneratedStatus”起步，成功后再收紧断言。

## 第六轮突破：完整装配已跑通（状态 PATH_NOT_FOUND）

## 第七轮突破：真实存档即 e2e fixture（M1/M2 地基到手）
- DevWorldLoadTests（绿，assumeTrue 守卫）：直接用引擎加载开发世界
  run/saves/新的世界/mtr (dimension=minecraft/overworld)：rails/depots/routes>0，且已有 1 辆车在档；
  40 tick 后车辆仍在（加载/模拟健康）。
- 手工单线(A→B)主寻路 PATH_NOT_FOUND 的问题先搁置：真实世界已提供完整可用网络，
  无需再造拓扑。
- M1 验收可改为“DevWorldLoadTests + 现网 fixture”；M2 下一步：无头司机——找到车场里的车，
  加 driver riding entity(同包可调 addRidingEntities) → isManual 车/手动起动 → 驾驶 → 断言 railProgress 前进
  （引擎 Vehicle 公开 API 受限，必要时加只读 getter 如 getRailProgress/getSpeed 以便断言）。

## 第八轮（M2 起步）：Vehicle 只读 getters + 手动发车阻塞记录
- 给引擎 Vehicle 加 public getSpeed()/getRailProgress()（游戏 VehicleExtension.getSpeed 覆盖兼容）。
- 无头司机尝试结论：能注入 driver(riders/drivers=1)、power 升至 7、门开 doorMultiplier=1，
  但车不动(delta=0，1500 tick)。全时刻表扫描亦无自动发车（dev 世界现存 1 辆 manual 车停场）。
- 阻塞点：manual 车在场内/停靠起动语义（门开关边缘、stoppingPoint/blocked、depot 主路有无）未吃透；
  下一轮方向：读 simulateInDepot/simulateStopped 起动分支 + extraData.closeDoors()/门边缘正确化，
  或为自动化加 Vehicle 包级 seam(forceManualStart/forceDeparture) 专供 e2e。

## 第十轮：真正的阻塞定位
- startUp 后车只前进 4e-6 m 即停 → 手动车在车场出口等红信号；dev 沙盒无 AI/信号放行 → 该存档不满足“发车并运行”。
- 无头司机 manCD=0 根因推测与 riding 注册/ride 映射或 isDriver 语义有关（未穷尽）；即使 bypass(直接 startUp) 也因信号不可用而停。
- 结论：做 M2 需要一条“能自动放行”的线路。两条路：
  A) 继续修合成单线的 PATH_NOT_FOUND（rail 角度/方向语义，需再读 Rail.getStartAngle 与角度约定，试双轨/折返）；
  B) 暂停基建投入，转 runClient 验证路线（更快）。

## 第十一轮：合成单线 M1 成功（SUCCESSFUL + 已发车）
- 修复两点：①每条 rail 的 angle2 应为反向(180°)，使 getStartAngle(p2).getOpposite()==续行方向；
  ②车场与站台之间要有一段“引出轨”，避免 siding 与 platformA 共享端点导致单跳退化。
- MiniWorldLineTests（绿，M1 严格）：main A->B OK(n=3)、siding->A OK(n=3)、B->siding OK(n=5)、
  Depot status=SUCCESSFUL、有 1 辆自动车发出。
- M2b 未决：自动车在场内未按时刻离站（timing 细节）；下一步用该合成线手动模式做无头司机
  （干净线路无信号阻塞，应能跑起来）作为 M2 达标路径。
