## 2. 标准（TEST 站台的 as-built 规格）

### 2.1 轴交换映射（TEST 轨沿 z ↔ 那 10 座站轨沿 x）

两站都是 **25 格宽 × 221 格长**，所以映射是一一对应的轴交换：

    along（沿站台）: x_目标 = x1 + (z_TEST - 800)        # TEST +z ↔ 目标 +x
    cross（横向）  : z_目标 = cz + (x_TEST + 40)         # TEST +x ↔ 目标 +z
    y              : y_目标 = y_TEST + (rail_y_目标 - 65) # TEST 轨面 65

轴交换是**镜像**（左右手性互换），所以：

* 带方向的属性值要跟着映射：`facing`/`head` 的 **east↔south、north↔west**；
* **APG 的 `side=left/right` 不能照抄** —— 必须让 `gen_apg_wall.py` 按 `facing` 自己算
  （`left` 的"另一半"在 `rotateYClockwise(facing)`，镜像后互换）；
* `mtr:platform` 的 `door_type/side` **不用手写**：墙铺上去时 MTR 的邻居更新自己算（实测 424 格全变 `door_type=apg`）。

### 2.2 与 TEST 对齐的固定偏移（沿站台方向，从 x1 数）

| 项 | 偏移 | 说明 |
| --- | --- | --- |
| APG 墙 | **4 … 215**（212 列 × 2 层） | 两端各留 4 格给信号灯柱（z 口径就是 TEST 的 804…1015） |
| 门洞起点 z0 | **20**（门洞 20…194，共 30 个） | 门扇占 `z0+1/z0+2` |
| 门洞中心相位 | **x1 + 22 + 6k** | 与停车牌子同一相位（`--apg-phase`） |
| 端头 `apg_glass_end` | 4、5、214、215 | 两端各两块 |
| 停车牌子（10 辆，朝轨端0） | **18** | 吊挂式 `variant=1`，y=轨面+4，facing=east |
| 停车牌子（8 辆，朝轨端0） | **36** | facing=east |
| 停车牌子（8 辆，朝轨端1） | **181** | facing=west |
| 停车牌子（10 辆，朝轨端1） | **199** | facing=west |
| 客流标记 / 海晶灯 / 船体 | 整片 1:1 复制 | TEST 的 `crowd_*`、`sea_lantern(内沿两列)`、`stone_bricks`、`glass` |

> 为什么墙是 **4…215**：TEST 两面不等长（西面 804…1015 = 212 列，东面 806…1015 = 210 列），
> 本工程取**两面一致**的 212 列（对齐 TEST 较长的那面），避免"两面墙不一样长"这种没来由的不对称。

### 2.3 保留原样的东西

`mtr:rail`（绝对不动）、自然方块（草/土/沙/石/矿/树叶/原木）、玩家自己放的方块。
**例外只在**：模板里没有、而目标站有的是"本工程负责的装饰类型"（吊灯笼等）⇒ 删掉并**逐格列在工具输出里**。

## 5. ⚠ 牌子"铺了 ≠ 登记了"（本轮最值得记的一条）

铺完立刻读只读出口只有 **35/88** 条，且分布零散（叶楼村/西段3站/干沙/岩壁 **0 条**）。
根因（读 `MmtrStopMarkerSync`）：游戏端登记走两条路 ——

1. `ServerChunkEvents.CHUNK_LOAD` → 每 tick 只处理 **4 个**待办区块（区块一卸载就丢）；
2. 每 **60 s** 的轮转兜底 `sweepOnePass`，只走**当前已加载**的区块。

批量 `/setblock` 时区块是临时 `forceload` 拉起来的、**铺完立刻卸** ⇒ 相当一部分牌子没赶上登记。
**引擎登记表是落盘的**（`mmtr-stop-markers.json`），所以补法是"让区块再加载一次 + 手动全量扫描"：

```
forceload add <x1-2> <cz-13> <x2+2> <cz+13>
POST /mtr/api/map/mmtr-command {"command":"world scan-stop-markers"}   # → 游戏端 stop-markers scan → scanAll
（读 /mmtr-stop-markers 核对本站两面各 4 条）
forceload remove <同一个盒>
```

补完 **88 条**（TEST 8 + 10 站 × 8），每站两面各 4 ✓。

## 7. 施工中踩到/记住的坑

1. **`block_at` 逐格读太慢**：它每格都把该 section 的 4096 项调色板索引解包一遍 ⇒ 6.6 万格的盒子
   单次读 1 分多钟，10 座站光读十几分钟。`apply_test_platform.read_cells` 已改成"每 section 解一次、
   再逐格查表"（与 `find_blocks.scan` 同写法）。**批量读档一律别用逐格 `block_at`。**
2. **`--glass-end -496,-495,…` 被 argparse 吃掉**（值以 `-` 开头会当成开关）⇒ 写成 `--glass-end=…`。
   本轮第一次下发墙就是这么整条没铺的，日志里只有一行 `expected one argument`。
3. **墙工具不发 `save-all flush`**：铺完立刻读存档 = 读上一次自动保存 ⇒ 会把铺好的墙数成缺失
   （第一次只数到 708/848）。**读档核对前必须自己 flush + 停 3 s。**
4. **`door_type=apg` 是 MTR 自己更新的**（我们只铺了墙，平台方块自己变），所以不要把平台的
   `door_type/side` 写进复制集 —— 手写反而会和邻居更新打架。
5. **`crowd_anchor` 与信号杆只报不删**：实测 下水 `(-497,66,1808)` 出现了一块 `crowd_anchor`，
   查 `[MMTR-CROWD] … 建块 0`（游戏端不建块）+ `[MMTR-LAG]` 显示**用户当时就站在 (-497,1793)** ⇒
   是用户自己按 TEST 的老口径放的"归属锚"。工具因此把 `crowd_anchor`/`mtr:signal_*` 归为
   **"位置由人决定、只报告不删"**（所以 `--check` 允许它存在，差量仍为 0）。
6. **轴交换是镜像**：`facing/head` 要映射，APG 的 `left/right` 要按朝向重算（照抄 TEST 会让门叶左右反）。
7. **10 座站的船体本来就与 TEST 大体相同**（16888 石砖 / 884 玻璃逐块数相等）⇒ 复制是**基本纯增量**：
   2097 格新装饰 + 44~48 盏旧灯笼清理；**唯一的"拆"是内侧两列立柱的上两格**（TEST 没有，见 §4），
   以及 叶楼村 那 22 格外沿海晶灯与用户现场铺的客流标记的"改写"。没有大拆大建。

## 8. 回滚

三层保险（按"代价从低到高"）：

1. **逐格回滚脚本**：`apply_test_platform.py --emit <file>` 会同时写 `<file>.rollback.txt`
   （把每格还原成"改之前读到的原文"，倒序执行）。下水的在 `sandbox/tmp/cmd-xiazui.rollback.txt`。
2. **删除新增物**：牌子 `mark_stop_markers.py --axis x --clear --along-lo … --along-hi …`；
   墙与装饰按 §2.2 的范围 `fill … air`（会连船体一起削，慎用）；正统做法是重跑生成器。
3. **整区备份**：开工前的 16 个 region 文件在 `sandbox/backup/region-20261013-230725/`（128.5 MB，
   已用 `read_block` 校验可读）。整站还原 = 停服 → 覆盖 region → 起服。
