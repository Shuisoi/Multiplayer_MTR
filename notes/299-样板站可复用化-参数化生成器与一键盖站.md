# 299 · 样板站改成可复用：参数化生成器 + 一条命令盖一座站

> 用户口径（2026-09-25）：**「先把样板站弄成可复用的」**。
> 承接 notes/296（车站样板）、297（站台要盖住轨端节点）、298（弧形雨棚）。

## 1. 之前不可复用的原因

三份脚本各自把 `x=-40 / z=800` 写死在常量里，断面偏移也是硬编码的绝对坐标：

| 脚本 | 管什么 |
| --- | --- |
| `gen_station_template.py` | 路基 + 站台 + 站台轨命令 |
| `gen_station_canopy.py` | 雨棚屋面 + 立柱 |
| （施工靠手敲 forceload / rcon_batch / push_rail_commands） | |

换一个站就得改三处常量、还要重新数 forceload 的范围。**现在合成两个工具**：

| 工具 | 干什么 |
| --- | --- |
| `sandbox/gen_station.py` | **只算命令**：给 `--center-x / --z-from / --length / --speed / [--no-canopy]`，出 `<prefix>_fills.txt` + `<prefix>_rails.txt` + `<prefix>_manifest.txt` |
| `sandbox/stamp_station.py` | **一条命令盖起来**：生成 → forceload → **按区块等生成** → 落方块 → 铺站台轨 → 清 forceload |

## 2. 断面全部改成"相对中心线"

只有 `center_x / z_from / length` 三个输入，其余全是偏移：

```
C-12 .. C-5    西站台 8 格      （C-5 是 mtr:platform[facing=east]，其余 7 格石砖）
C-4            空
C-3            ← 站台轨
C-2 .. C+2     空（6 格线间距）
C+3            ← 站台轨
C+4            空
C+5 .. C+12    东站台 8 格      （C+5 是 mtr:platform[facing=west]，其余 7 格石砖）
路基 y=62..64；站台层 y=65；雨棚 70+弧；立柱 66..69，在 C±12 / C±5 列下
```

三条沿用下来的硬口径也都进了生成器的文档，不再靠人记：

1. **站台方块离轨 2 格**（边缘块在 `C±5`，不是 `C±4`）
2. **站台方块与轨节点同层**（`y=65`）
3. **站台方块盖住轨的两个端节点**（轨 L 米 ⇒ 方块 **L+1** 格，别用 `z_from+L-1`）

立柱 z 也从"躲开 z=800/801/1019/1020"泛化成 **"躲开本站两端 4 个信号杆位"**
（`z_from, z_from+1, z_to-1, z_to`），换长度、换位置都不会撞。

## 3. 证据

**① 回归：新生成器能逐字节复现已建好的那座**

```
旧（build_station_template.txt + build_station_canopy.txt）68 条 fill
新（gen_station.py --center-x -40 --z-from 800 --length 220）68 条 fill
→ 逐条完全一致 ✅
```

**② 参数化：三个不同位置 / 长度都对**

| center_x | z_from | 长度 | 西站台 | 轨 | 东站台 | 立柱 |
| --- | --- | --- | --- | --- | --- | --- |
| 120 | 1400 | 220 | 108..115 | 117 / 123 | 125..132 | 11 根 |
| -40 | 1400 | **300** | -52..-45 | -43 / -37 | -35..-28 | **15 根** |
| -200 | **-400** | **180** | -212..-205 | -203 / -197 | -195..-188 | **9 根** |

全部 fill 都在 32768 上限内（生成器自己校验，超了直接中止）。

**③ 编排代码已实跑**（`--stop-after generation`，不落方块）：
在 z=1400 处 `forceload` → **45 个区块的生成等待**（第 1 次缺 45，第 2 次缺 0）→ 清 forceload，
三步都按预期收尾。

## 4. ⚠️ 地形体检当场抓到一个不合适的站址

给生成器加了 `--check-terrain / --check-only`（**按区块**枚举站址，不用正方形扫描器 —— notes/293 §3 那个坑）：

```
z=1400 站址：读到 5525 列，最高 y=93，≥65 的列=1905
  ⚠️ 最高 93 高过清障上限 y=80 —— **这里是真地形**（山/建筑），直接建站会被埋住：
     要么换址，要么把 CLEAR_Y 调到 95 以上
```

**所以 z=1400 不是合格站址**（那一带有座山到 y=93）。而 z=800 已建的那座报的是
"最高 73 落在雨棚带 70..73 —— 若这一带已经建过站，读到的就是已建结构本身"。
两条判据分开（雨棚带内 vs 高过清障上限），就不会把"自己的雨棚"和"真山"混为一谈。

## 5. 还没做的一步（说清楚）

**"一条命令从头盖到尾"我只验证到"生成"这一步**，没有真跑 fills + rails ——
因为那会在世界里留下一座没人要的站（站台轨一旦建起来，清掉要回游戏里敲端节点）。
最后的落方块/铺轨两段复用的是**已经在用的** `rcon_batch.run_with_reconnect` 与
`push_rail_commands.command`（notes/291/294/296 都跑过），只有编排是新的、而编排已经跑通。

⇒ 下一条命令只差一个站址：

```bash
python sandbox/stamp_station.py --center-x <C> --z-from <Z> --length 220
```
