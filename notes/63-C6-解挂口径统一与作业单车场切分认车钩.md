# 63 - C6：解挂口径统一（"切在第几节之后"）+ 作业单车场切分也认车钩

> 前置：notes/62（车底清单/作业单可声明接缝）。本片把"切在哪"的**语义**钉死，并让作业单的车场切分
> 也遵守设计不变量 **U6（切分只认接缝）**。引擎侧三处改动 + 1 个用例。

## 定案：一律用**车厢序号**，不引入"接缝序号"

| 入口 | 值 | 语义 |
| --- | --- | --- |
| `MmtrCoupleSurgery.uncouple(sim, vehicleId, k)` | 车厢序号（0-based） | 在**第 k 节之后**切，尾段从第 k+1 节开始 |
| 指令 `uncouple <id> <k>` | 同上 | 游戏内瞄准某节车厢时也是这个值 |
| 作业单 `UNCOUPLE.targetIndex` | 同上 | 车场切分 |
| `mmtrCouplerAfter` | 布尔 | 该边界是否有车钩；**没有就拒绝** |

为什么不改成设计文档原先写的"接缝序号"：司机/作者瞄准与书写的是**车厢**（"把第 3 节以后留下"），
而"接缝序号"要作者自己数有车钩的边界，既反直觉、又和 `carIndexAfterSeam` 的换算纠缠。
车厢序号 + 车钩闸门等价且更直白，`MmtrCoupleSurgery` 里的换算只有一行。

## 改了什么

| 位置 | 改动 |
| --- | --- |
| `MmtrCoupleSurgery.uncouple` | 参数 `seamIndex` → `cutAfterCarIndex`（**只是改名**：原实现本来就是 `cars.get(k).getMmtrCouplerAfter()` 闸门 + `subList(0, k+1)`），javadoc 写清"车厢序号 + 车钩闸门"；日志改成"在第 k+1 节后切分" |
| `MmtrJobScheduler.executeUncouple` | 原来只查范围，现在过 U6：抽出可单测的 `static uncoupleRefusal(cars, cut)`，无车钩时报"第 k 节之后没有车钩，切分只认接缝" |
| `MmtrJobScheduler` make-up（COUPLE 首步） | 组合 spawn 模板时把**接缝标在发起作业的最后一节**上（`mmtrCouplerAfter = true`）——连挂产生的接缝要在清单里落地，否则连挂后再也切不开 |

## 用例

`MmtrConsistJobTests.yardUncoupleOnlyCutsAtACoupler`：
- `机车(true) + 挂车(false)`：切第 0 节后 = 合法（`null`）；
- 切第 1 节后（最后一节）与 -1：越界拒绝；
- 固定两节单元（两节都 false）：切第 0 节后被拒，理由含"没有车钩"。

## 验证

- `MmtrConsistJobTests` 通过；全量引擎套件零新增失败（见提交说明）。

## 与设计的差异（要回填文档）

`docs/01-设计/编组构建-连挂单元与连挂端点-设计.md` §7 的 C6 行原文是
"`UNCOUPLE.targetIndex` → 接缝序号（含迁移与 web 编辑器）"，按本片结论应改为
"`UNCOUPLE.targetIndex` = **车厢序号**，引擎按 `mmtrCouplerAfter` 闸门映射到接缝（无车钩即拒绝）"。
