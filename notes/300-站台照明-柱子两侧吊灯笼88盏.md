# 300 · 站台照明：每根柱子两侧各吊一盏灯笼（88 盏）

> 用户口径（2026-09-25）：**「给站台加上点照明吧，在柱子左右加灯笼」**。
> 问过一轮并定案：① "左右" = **沿站台方向两侧**（`z-1` / `z+1`）；② 用**普通灯笼**。

## 1. 挂法

每根柱子的 `z-1` 与 `z+1` 各一盏，**吊在雨棚屋面正下方**：

```
y=70  石砖屋面（起拱列，offset=0）
y=69  minecraft:lantern[hanging=true,waterlogged=false]   ← 灯体
y=68  空气
...
y=66  ← 立柱顶（柱子本体在 z 处，灯在 z±1，不打架）
```

| 项 | 数 |
| --- | --- |
| 立柱 | 4 列（`x=-52/-45/-35/-28`）× 11 个 z = **44 根** |
| 灯笼 | 44 × 2 = **88 盏** |
| 间距 | 沿站台**每 10 格一盏**，每口站台两列灯带 |

**为什么是 z±1 而不是 x±1**：4 根柱列里，靠外的两列（`-52` / `-28`）向外那一侧**没有雨棚**
（雨棚只盖 8 格站台），x 向只有内侧一边有屋面可挂；而 `z±1` 对四列都成立、且是左右对称的。
立柱之间相隔 20 格，所以 `z±1` 互不重叠（809/811、829/831…），也都不碰信号杆的 `z=800/801/1019/1020`。

## 2. 做成标准站的一部分

`gen_station.py` 把照明并进了雨棚那一段（`--no-canopy` 时不生成），所以**以后每个站自带 88 盏**：

```
setblock -52 69 809 minecraft:lantern[hanging=true,waterlogged=false]
setblock -52 69 811 minecraft:lantern[hanging=true,waterlogged=false]
…
# 照明 setblock 88 条（每柱 z±1 各一盏，y=69）
```

**回归仍然通过**：加了照明之后，生成器给出的 **68 条 fill 与已建站逐条一致**（照明是 `setblock`，
不动断面）。

## 3. ⚠️ 关键操作纪律：已建好的站**绝不能重跑整份 fills**

`<prefix>_fills.txt` 的第一段是**清障**（`fill … y=65..80 minecraft:air replace`）。
在**已经建好的站**上重跑它，会先铲掉：雨棚（70..73）、立柱（66..69）、站台层（65），
**以及用户放在那里的信号杆（`(-45,66)`）和灯头（`(-45,67)`）**。
虽然后面的 fill 会把雨棚站台重新铺回来，**但信号杆不会自己回来**。

所以给已建站补照明时，只抽 `setblock` 那 88 行单独跑：

```powershell
Get-Content sandbox\station_lanterns_fills.txt | Where-Object { $_ -match '^setblock' } |
  Set-Content sandbox\build_station_lanterns.txt
python sandbox\rcon_batch.py --file sandbox\build_station_lanterns.txt
```

（产物 `sandbox/build_station_lanterns.txt` 就是实际落到那座站上的 88 条。）

## 4. 顺带查清一个"假失败"

大批量 setblock 时日志里出现 `Could not set the block`，一度以为是失败。实测：

```
setblock … minecraft:lantern                     → Changed the block      ✅
setblock … minecraft:lantern[hanging=true]       → Changed the block      ✅
setblock … minecraft:lantern[hanging=true,waterlogged=false]  → Could not set the block
setblock … minecraft:lantern[hanging=true,waterlogged=false]（再来一次）→ Could not set the block
```

`SetBlockCommand` 在 **`world.setBlockState` 返回 false** 时就是这么回话的，而它在
"目标状态与现状**完全相同**"时返回 false ⇒ **这是空操作，不是失败**。
（那批 88 条之所以出现它，是因为 `rcon_batch` 断线重连后**重发同一条命令**，
第一次其实已经写进去了；这批一共重连了 103 次。）

**所以没有把 `could not set the block` 加进 `REJECTED` 词表** —— 它和 `/fill` 的
`No blocks were filled` 一样是"幂等重发的正常现象"，加进去会让每次重跑都刷一屏假警报。
（对比：notes/289 加的 `not loaded` 就是**真失败**，该加。）

## 5. 验收（直读存档，88 盏逐一核对）

| 判据 | 结果 |
| --- | --- |
| 88 个位置的状态 | **全部** `minecraft:lantern[hanging=true,waterlogged=false]` |
| 每盏灯上方 y=70 | 都有方块（屋面）—— 吊得住 |
| 每盏灯下方 y=68 | 全是空气 —— 没被柱子占住 |
| 立柱本身 | `(-52,69,810)=stone_bricks`（柱子还在，灯在它两侧） |
| 用户信号杆灯头 | `(-45,66,800)=mtr:signal_pole`、`(-45,67,800)=mtr:signal_light_4_aspect_1` 完好 |
| `forceload` | 已 `remove all` |

## 6. 回滚

88 盏全清：`fill -52 69 800 -28 69 1020 minecraft:air`（会把 44 根立柱在 y=69 那一格也削掉，
重铺立柱即可；或者逐条把 `build_station_lanterns.txt` 的方块换成空气）。
