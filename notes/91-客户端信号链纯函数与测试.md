# 91 - 客户端信号链抽成纯函数并补测试

> 客户端渲染器（`RenderSignalBase.mmtrChainDepth`）是"信号 = 进路 × 闭塞"的**第二份实现**，
> 此前**零自动化覆盖** —— 而它正是实机目视要看的那个东西。本片把它抽成纯函数并补 5 例测试。

## 1. 抽取

| 件 | 内容 |
| --- | --- |
| `org.mtr.mod.mmtr.MmtrSignalChain`（新，纯） | `depth(startNode, protectedHexes, RailGraph, blocked, lockedNextRails, maxDepth)`：闭塞链为底；分岔默认每支都算；**镜像锁定的径路只跟"接在离开节点上"的那一条**（折返轨因此保留两条候选）；行进方向用点积判断 |
| `RenderSignalBase` | 只留一个 `ClientRailGraph` 适配器（`MinecraftClientData.positionsToRail` → `RailGraph`）+ PENDING 入口压红那 3 行；算法本身委托给纯函数，**行为逐行等价** |

## 2. 测试（`MmtrSignalChainTests`，5 例，无 MC 依赖）

合成网络 `E(-20..0) → N(0) → {S(0..60) | D(0 → 60,+20)} → S2(60..120)`：

| 用例 | 断言 |
| --- | --- |
| `occupancyChainGivesRedSingleAndDoubleYellow` | 0 / 1 / 2 / 3 —— 绿 / 红 / 单黄 / 双黄 |
| `withoutALockedPathEveryForkBranchCounts` | 占用分岔支 → 2（保守规则） |
| `aLockedPathNarrowsTheForkToItsOwnRail` | 镜像锁定直向 → 占用分岔支被忽略（0）；锁定径路自身被占仍算（2） |
| `aDoubledRailKeepsBothCandidatesAndPicksTheRightDirection` | 镜像 `S→[S2,E]`：从 N 走 S 跟 S2、从 M 走 S 跟 E；被保护的 S 被占仍红 |
| `anUnknownRailEndsTheWalk` | 未知轨：未占 → 0、被占 → 1 |

## 3. 验证

- `gradlew :fabric:test --tests org.mtr.mod.mmtr.MmtrSignalChainTests --tests org.mtr.mod.client.MmtrClientRoutesTests`
  → **8/0**（5 + 3）。
- 引擎 Java 未改动（**472/0/2** 不变量）。
- 抽取是**行为等价**重构：循环结构、点积方向判断、候选过滤顺序与抽取前逐行对应；渲染器不再自己实现算法。
