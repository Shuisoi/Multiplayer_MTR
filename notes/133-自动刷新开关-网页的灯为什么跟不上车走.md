# 133 · 「自动刷新」开关：网页的 aspect 为什么跟不上车走

用户 2026-09-14 的现场问题：**"灯 -175,-60,-122 为什么是绿的，我把车开出去了此时应该是红的吧"**。

结论先说：**不是引擎错，是网页那一帧是旧的**。这一轮把根因测清楚，并加了一个默认关的
「自动刷新」开关（用户的决定：`加一个"自动刷新"开关（默认关）`）。

---

## 1. 先证明引擎是对的

对同一时刻、同一盏灯，两条路各读一次：

| 读法 | 结果 |
| --- | --- |
| 引擎 `signal why -175 -60 -122` | 深度 1 → **RED**；本灯区间 `占用=**是**` |
| 网页上那一帧 | **绿** |

引擎给"红"的依据是**占用者**：车 `-1153100900311028339` 的车头 `(-169.5,-198.5)`，
footprint 落在 `(-170,-186)↔(-170,-199)` 的弧 0..13 与 `(-170,-186)↔(-170,-161)` 的弧 0..3 ——
也就是说车**已经压在岔区里**了。而 `-175,-60,-122` 的区间链第一段
（`-175,-60,-122`，13 段 290 m）恰好覆盖这些轨，`depthAt=1` 就是"本段占用"，显示层给红。

`signal why` 的那一行原话可以直接贴给用户看：

```
②[1] 本灯区间 id=-175,-60,-122  段数=13  长=290 m  占用=**是**  出口灯=-168,-60,-222
    span 轨FFFFFFFFFFFF… 弧 0..25 m（长 25 m，方向 0,-1）  ...  [-1153100900311028339] 占弧 [0..3] 与本段重叠=3.0m
④ 结论：深度 1 → RED（红）
```

## 2. 根因：这个页面从来**不轮询**

代码层面就一句话：`TopologyView` 里没有 `setInterval` / SSE / WebSocket，`load()` 只在

- 打开页面（`onMounted`）时，
- 用户按「重新读取」或做完一个动作之后

各跑一次。所以画布上的 aspect 是"**上次读取那一刻**"的快照，引擎早就逐 tick 更新过了。
用户"把车开出去"这件事发生在两次读取之间，页面自然还是绿的——**用户看到的是历史**，
不是判断错。用户自己也读到了同一层：`那就是web刷新问题`。

## 3. 这一轮做了什么

`engine/website/src/views/TopologyView.vue` 加一个开关，四条约定：

1. **默认关**：既有行为不变，也不平白多打接口。开关状态记在
   `localStorage["mmtr.topology.autoRefresh"]`（只认 `"1"` 为开，读不出就当关 ——
   不猜脏值的语义）。
2. **只重读会变的那两份**：拍子上 `Promise.all([fetchSignals(), fetchPoints()])`，
   **不重取 `mmtr-topology`**，所以不重建轨图 → 地图不闪、相机不动、不打断正在看的人。
3. **一拍 3 秒**（`AUTO_REFRESH_MILLIS = 3000`）。一拍失败**不弹错**：轮询本来就会再来一次，
   弹窗只会打扰人（下一拍成功就自己恢复了）。
4. **生命周期要收干净**：`onUnmounted(stopAutoRefresh)`。定时器不属于组件生命周期，
   不显式停就会在离开这个视图之后一直打接口。

HUD 上按钮文字就是状态本身（`自动刷新 开/关`），开着时用道岔那套琥珀色（与"生效中"对上）。

## 4. 怎么验的（`sandbox/check-web-autorefresh.ps1`，13 项全通过）

行为要证的是"**会不会自己重读**"，不是一个数字。做法：在页面里给 `window.fetch` 装个计数器
（只数不改），然后量四件事：

| 检查 | 实测 |
| --- | --- |
| 默认关：静置 7 秒不重读 | 灯 +0 次 / 道岔 +0 次（**默认不轮询**这条被证死了） |
| 点开后 8 秒内按拍重读 | 灯 +2 次 / 道岔 +2 次（3 秒一拍，期望 ≥ 2） |
| 开着的时候**不重取拓扑** | `mmtr-topology` +0 次 → 地图不闪 |
| 关掉后静置 7 秒 | 灯 +0 次（停表） |
| 刷新页面 | 按钮自己回到「开」，且轮询**自己重新起来**（灯 +2 次 / 8 秒） |

验完把偏好复位成"关"，不把"开着"留给下一次调试。

## 5. 这套开关**没有**解决什么（留着，别当成已经解决）

- **它不修"显示层的保守"**：`depthAt` 目前按**全部腿**（含走不到的那些）累加占用，
  所以理论上仍存在"车在不相关的那条腿上、这盏灯却被判红"的保守误红（见 `132` §5）。
  自动刷新只会让这种"保守的红"更快地显示出来，不会让它变少。
- **它不替代服务端版本号**：轮询是"客户端按拍问"，接口再大一点就该由服务端给版本号、
  前端比版本号再决定要不要重取（拓扑文件头里那句老话仍然成立）。这一轮只是把
  "坐在屏幕前看车走"这个**使用场景**先兜住。
- **切回标签页那一瞬间不补读**：只有定时器，没有 `visibilitychange`/focus 补一拍
  （没选这条；真要补，是在 `setAutoRefresh` 之外再加一个监听，与开关无关）。

## 6. 顺带记一笔：现场正锁着的道岔不是这一轮造成的

查 `mmtr-points` 时看到 6 个节点锁着（`locked=true`）：

```
-155,-60,-189  pos=1 manual=1
-170,-60,-137  pos=1 manual=1
-170,-60,-199  pos=0 manual=-1
-170,-60,-161  pos=0 manual=0 / manual=-1（该节点多行）
-67,-60,-139   pos=0 manual=0 / manual=-1（该节点多行）
-154,-60,-139  pos=1 manual=0
```

这是**设计如此**，不是本轮改动：`point set` 对**单开道岔**走
`mmtrOperatorSetTurnoutPosition`，它把三条进向轨全锁上（人工优先，永久生效直到解锁 ——
2026-09-14 用户的决定）。所以"网页点腿按钮 / 世界里人工搬岔"都会留下锁，
`manual=-1` 那几行就是同一次操作**顺带锁上的另外两条进向**。

要清掉它们得逐进向 `point unlock`（`point release` 是释放**车辆申请**，不是解锁）。
这一点写在报告里请用户确认，**没有擅自解锁** —— 锁是真实的操作状态，
到底是"我现场测试留下的"还是"用户自己搬岔留下的"从数据上看不出来。
