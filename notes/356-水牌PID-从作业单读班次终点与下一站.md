# 356 水牌（PID）：班次号 / 本趟终点 / 下一站，从作业单来读

> 用户 2026-10-01 口径：
> 「接下来是水牌逻辑，也就是 PID，我觉得和仪表一个套路就可以了，但是游戏内自动水牌的 API 被我们任务系统拦截了，
> 所以需要重写逻辑，首先需要拿到列车终点站和班次号，还有下一站，这个要从作业单来读取。」
>
> 追问后选定：**班次号 = 作业单号**；**终点 = 本趟最后一个停站的车站名**、**下一站 = 前方下一个开门停站**；
> **走 MMTR 自己的镜像字段**（不复用原版 `thisRoute*`），客户端自己画。

## 1 原版"自动水牌"是怎么断的

断点在引擎侧，一句话：**填那几个字段的那一步被改成了空实现**。

| 环节 | 原版 | 现在 |
| --- | --- | --- |
| 车体上出字的渲染 | `ModelPropertiesPart` 的 `DESTINATION / ROUTE_NUMBER / NEXT_STATION` 显示部件读车体镜像字段 | **没变**（这条链是好的） |
| 字段来源 | `VehicleExtraData.setRoutePlatformInfo()` 按车当前跑的 `Trip`/`Route` 填 | **空实现**，原话："MTR route/timetable info removed with the auto service" |
| 计划来源 | MTR 的 depot 频率/时刻表 | **作业单**（`MmtrConsistJob`） |

所以字段恒为空 ⇒ 车体显示部件没字可画。另外现场**四个资源包一个显示部件都没有**
（`SAF420_v33` / `BR101_v54` / `MMTR_NewStock_v1` / `HST_H_v12` 的 `properties_*.json` 里 `displayType` 出现 0 次），
所以就算把原版字段填上，暂时也没有几何能显示 —— 这正是"水牌贴哪儿、谁画"要单独定的原因。

## 2 三项数据从哪来（唯一真源 = 作业单 + 车跑到第几步）

新增 `org.mtr.core.mmtr.MmtrPid`（`of(simulator, job, stepIndex)`），口径：

| 项 | 口径 | 现场例子（00101） |
| --- | --- | --- |
| **班次号** | 作业单号 `jobId` | `00101` |
| **本趟终点** | **本趟**（从当前位置到**下一次换端**为止）里最后一个"停在站台"的目标的**车站名** | 步 0 出发时 `海山` |
| **下一站** | 当前位置之后第一个"停在站台"的目标的车站名，**允许跨趟** | 步 13 在海山开着门时 `岩壁` |

三条判据（都在代码注释与用例里写死）：

1. **"停在站台"= 目标解析出来是 `MmtrTaskTarget.Kind.PLATFORM`**：`SERVE`（开门乘降）与
   **开往站台**的 `MOVE_TO` 都算。两条规则共用同一个判据 —— 不存在"终点按 SERVE 算、下一站按 MOVE_TO 算"这种两套口径；
   没有 `SERVE` 的回送趟也照样报得出终点。
2. **换端那一步已经算下一趟**（`legIndex` 在换端那一步就 +1）：现场 00101 是 `海山1台 ⇄ 叶楼2台` 来回 13 次换端，
   到海山、换端、再开回叶楼 —— 水牌在**换端那一刻翻面**，与旅客看到的一致。
3. **名字从引擎对象现算**（`MmtrTaskTarget.stationName()`：站台 → 它的车站名），
   **不抄作业单那句 `note`**：note 是作者手写的，可能过时。用例把 note 全改成"胡说八道"再断言三项不变。

> 为什么"下一站"要允许跨趟：在终点站开着门的那几十秒，旅客要看的下一站就是**换端之后那一趟的第一站**。
> 把扫描范围截在"本趟"会得到空 —— 用例 `theNextStationCrossesTheChangeEnds` 专门钉这一条。

## 3 怎么到客户端（"和仪表一个套路"）

三个新镜像字段进 `VehicleSchema`（真源是 `buildSrc/.../schema/data/vehicle.json`）：

```
mmtrPidService   班次号
mmtrPidTerminus  本趟终点（车站名）
mmtrPidNext      下一站（车站名）
```

- **写的人**：`MmtrJobScheduler.tick()` —— 只有调度器知道"本车跑到第几步"。
  *不放在 mission 上*的原因：换端/连挂/解挂这几步按设计**没有 mission**，而换端正是水牌要翻面的时刻
  （挂在 mission 上会让水牌在换端时闪成空白）。
- **不推空补丁**：`Vehicle.setMmtrPid()` 三项与镜像逐字比对，**没变就什么都不做**；
  变了才写镜像 + `mmtrMarkSyncDirty()`。于是"调度器每 tick 都写"不等于"每 tick 都推"。
- **不在跑的作业单要清空**：先让所有在跑的作业单写完，再清"没有任何在跑作业单认领"的车（两遍走，
  否则结果取决于 `instances` 这个 HashMap 的遍历顺序 —— 连挂之后被并进来的那一份仍是 DONE 且记着同一台车）。
- **走稀疏补丁**：`mmtrPid*` 进了 `VehicleSyncPatch.DYNAMIC_KEYS`。过一站就变一次，
  不进白名单的话每次都要发**整份快照**（单节 3.5 KB × 全列）。
- **游戏里能查**：`mmtr vehicle list` 每辆车多一段 `水牌=00101 终点 海山 下一站 岩壁`
  （读的正是客户端那份镜像字段，与客户端同一个数）。

## 5 现场抓到的数据不一致（4 处，用户选定：改作业单 note 去对齐世界站名）

水牌显示的是**世界里的车站名**（从 `Station` 对象现算），而作业单的 note 是作者手写的简称：

| 作业单 note 写的 | 世界里的车站名 | 命中的 note 条数 |
| --- | --- | --- |
| 朗园 | **朗源** | 254 |
| 叶楼 | **叶楼村** | 189 |
| 上水 | **上水村** | 246 |
| 莫氏 | **莫氏岛** | 246 |

用户口径（2026-10-01）：**改作业单 note 去对齐世界站名**（改站名会连带影响站牌/地图）。
工具：`mmtr/scripts/fix-job-notes-station-names.ps1`（默认只报告、`-Apply` 才写盘、`-Strict` 要求改完零残留）。

三条守卫（都实测过）：

| 守卫 | 怎么验的 |
| --- | --- |
| 默认不写盘 | 干跑现场文件，文件 SHA256 前后一致 |
| 幂等 | 连跑两次：第一次 935 条命中，第二次 **0 条**（别名后面已跟全名时不再替换，`叶楼村` 不会变 `叶楼村村`） |
| 只动 note 的**值** | 写盘前自检："字符数变化"必须恰好等于 4 个别名换全名的长度差（实测 +681），否则报错不写 |

**验收判据**（脚本自己报，改前/改后对照；`stations` 读的是世界存档里的车站名）：

```
站名核对：note 里有 10 个不同的站名段（干沙/海山/朗源/莫氏岛/内湾/鸥湾/上水村/下水/岩壁/叶楼村）；世界里 10 个车站
改前：✘ 4 个站名段不是世界车站名 —— 朗园, 莫氏, 上水, 叶楼
改后：✔ 全部是世界车站名 —— 水牌上的字与作业单对得上
```

> 探针里那张别称表（`KNOWN_NOTE_ALIASES`）**不删**：它是"以后谁再写简称就报红"的守卫。
> 作业单改好之后它自然不再命中，但一旦有人改回简称（或改了站名忘了改作业单），那一条用例会红。

**部署顺序**（本次没执行，用户口径：等客户端渲染一起部署）：


## 7 教训

1. **生成文件不是真源**：`engine/src/main/java/org/mtr/core/generated/**` 在 `engine/.gitignore` 里，
   由 `buildSrc` 按 `engine/buildSrc/src/main/resources/schema/data/*.json` **在构建时重写**。
   我第一次直接把字段加进 `VehicleSchema.java`，下一次 `gradlew test` 就被生成器整个覆盖掉，
   报的是"找不到符号 mmtrPidService"（9 个错误）。**加同步字段要改 schema JSON。**
2. **"和仪表一个套路"落到代码上就是三件事**：引擎算原话 → 镜像字段（进动态白名单）→ 变了才标脏。
   第三件最容易被忘：忘了它，水牌会每 tick 推一份补丁；不做第二件，客户端每次都要收整份快照。
3. **别把"每 tick 都算"和"每 tick 都推"混起来**：调度器每 tick 都得算（它才知道跑到第几步），
   但"推不推"的判据只有一处（`setMmtrPid` 的逐字比对），并且这条不变量**有用例直接钉**
   （同名再写一次 ⇒ `checkForUpdate()` 必须为 false）。
4. **先守住夹具再断言反例**：`sync()` 会删掉没有图轨的站台，删掉之后三项全空 ——
   而"终点为空"正是要验的反例之一。夹具守卫（`assertFixtureAlive`）省掉的是"全套用例假通过"。
