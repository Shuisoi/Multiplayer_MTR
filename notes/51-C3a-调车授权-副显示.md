# 51 - C3a 调车授权（副显示）：连挂的信号前提

> 用户口径（2026-09-09 修正）：MTR 一股道只允许一辆停放车**是信号原因**；现实中连挂同样要
> **信号允许越过红灯**（副显示 / 调车授权），所以不能靠"关掉一个数据限制"来实现。
> 本片把这条现实机制落成引擎数据面 + 三处抑制接线，**不做**多车落地（那是 C3b）。

## 为什么不是"放宽限制"

原来的 `Siding.mmtrFormationWindow`（声明于 `:582`、读取于 `:299`、全仓从未赋值）表达的正是
错误模型：一个可以拨动的开关。现实里"一个区段两列车"的合法性来自**许可式工作**：主显示仍红，
副显示（调车/呼唤）授权某**一列车**越过红灯进入被占用区段，低速、随时可停；此时 **AWS 被抑制**、
TPWS 等效保护不判 SPAD。授权到期或撤销，区段立刻回到"一区段一列车"。

## 落成的构件

| 构件 | 位置 |
| --- | --- |
| 授权对象 | `MmtrShuntAuthority`（aspect、车底、起始轨、目标轨、限速、到期） |
| 授权登记表 | `MmtrShuntAuthorityRegistry`（每车至多一条 U8；惰性到期；`allowsCoexistence`） |
| 制式表（UNVERIFIED O6） | `Kind{SUBSIDIARY_SHUNT, CALLING_ON}` → `{抑制 AWS, 施加保护, 限速}`，默认 25 km/h（15 mph 通行做法） |
| S1 例外 | `Vehicle.computeMmtrBlockStopM`：授权覆盖的轨不产生占用停点 |
| S3 抑制 | `Vehicle.tickMmtrAwsWarning`：授权下清警告态并返回（不响、不升级 SPAD） |
| S4 例外 | `Vehicle.evaluateMmtrProtection`：授权下不新判越点/SPAD |
| 调车限速 | `Vehicle.simulateMmtrMotion`：按 LZB 同款"强制上限"衰减，牵引顶不上去 |
| 车场共存 | `Siding.mmtrCoexistenceAuthorized()` 取代 `mmtrFormationWindow` |
| 指令/展示 | `shunt <id> <targetRailHex|off> [minutes] [kmh] [SUBTYPE]`；`mmtr-trains.shuntAuthority`；驾驶室 HUD「副显示」琥珀灯（带限速） |
