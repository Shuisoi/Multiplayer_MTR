# 206 · 雨滴的运动：密度阈值 → 流动，雨刷推水 → 水带下流

> 用户要求（按因果顺序）：
> 1. **雨滴数量达标后需要往下流**（不够多就不动）；
> 2. **雨刷刮过的地方会推雨滴**（不是删掉、不是变淡）；
> 3. **推过去的雨滴因为量大有了流动性所以会往下流**。
>
> 本文记录最终模型、三次失败尝试的实测数字、标定依据、验证方式与遗留项。
> 代码：`mmtr/game/fabric/src/main/java/org/mtr/mod/render/panel/MmtrWindshield.java`
> 离线对照：`mmtr/tools/wiper-preview/DropletFlow.java`（真 BR101 玻璃 + 真打包几何）

## 1 最终模型（三段因果，一段都不能省）

### 1.1 密度场：谁「够多」

`State.measureDensity()` 每帧算一次**每颗雨滴周围的局部密度**（颗/m²）：

```
probe   = 以密度格为单位的 3x3 块（densityCellM = 0.05 m → 15 cm 见方，块面积 0.0225 m²）
count   = 块内可见雨滴数（含自己）
density = count / 0.0225                [颗/m²]
```

所以孤零零一颗 = 44/m²，两颗 = 89/m²，三颗 = 133/m²。
**必须在推进前一次性算完**：如果在 `advanceDrop` 里边走边算，同一块里先走的珠子会被按新位置计入，
一块水会在 1 帧内自己撕开（第一颗在流、最后一颗还钉着）。

### 1.2 起流锁：够多才动

`State.advanceDrop()`：

```
pressure = max(0, density / densityThresholdPerM2 - 1)      // >0 才算达标
running  = pressure > 0 || liftSpeed > 0                    // liftSpeed = 气流爬升（唯一能推动孤珠的力）
mobility = pressure <= 0 ? 0 : min(1, RUNOFF_MARGINAL_FACTOR + pressure)
runoff   = runoffMps * mobility * sizeScale                 // 顺坡向下
```

- **阈值决定「流不流」**，是一个硬闩锁（表面张力本来就是阈值行为）；
- **密度决定「流多快」**：刚从阈值放开时是 `RUNOFF_MARGINAL_FACTOR = 0.4` 倍，密度到阈值的 1.6 倍时饱和到 1.0 倍；
- 珠子自身大小**不再是起流条件**（旧模型 `radiusM > staticThresholdM`），只影响画出来的大小和一点点速度；
- `staticThresholdM` 保留但只用于「新落下的珠子不许一开始就大于它」和 pinch-off 的参考尺寸。

### 1.3 雨刷：把水「收」成一条，而不是平移

`State.applyWipe()`：以刀刃前缘线为界，沿运动方向 `u`（`pushDirectionM`，连杆式取刀刃中点位移，单轴取臂的切向）：

```
ahead > 0（还没碰到，前缘 3 cm 淡出带内）: shove = min(pushM, BOW_WAVE_FRACTION * 刀本帧位移) * wipe
ahead < 0（已经刮过、在带内）           : shove = min(刀本帧位移, -ahead)      // 正好落到前缘线上，不会超到刀前面
```

关键点：**已经刮过的水由雨刷以「自己的速度」带着走**，而刀前方的水被推走的距离**严格小于刀自己的位移**
（`BOW_WAVE_FRACTION = 0.5`）。于是刀会追上前面的水，把它压在自己的前缘上——**所有被碰到的水塌缩成一条线**，
这条线就是水带（windrow）。

被推下玻璃边界（`-0.05..1.05 / -0.10..1.10`）的珠子走 `respawn`，与「从下沿流走」同一条路径。

## 2 三次失败尝试（都是离线实测否掉的）

| 尝试 | 做法 | 实测结果 | 结论 |
|---|---|---|---|
| ① 变淡 | `ink = RE_WET_INK + (1-RE_WET_INK)(1-wipe)` | 下限 0.30 = 绘制 alpha 下限，只是变淡 | 用户当场否掉（"刮水时雨滴应该完全消失"） |
| ② 删除 | `drop.visible = false` | 玻璃立刻干了，但没有"被推走的水"这一物 | 反向过头，堵死第 3 段因果 |
| ③ 刚性平移 | 每颗被刮到的珠子沿运动方向推 `pushM` | 密度 **142 → 146/m²（+3%）**，水带根本没出现 | 刚体平移**严格保距**，任何 `pushM` 都推不出水带 |
| ③′ 速度 ∝ 超出阈值 | `runoff = runoffMps * pressure` | 稳态均值 85/m²（阈值 130），整场速度 **0.026 m/s**（爬） | 场会**自调节**到阈值附近：一块水一旦流就自己排空，超出量永远是 0 附近 |
| ③″ 忘了判号 | `mobility = 0.4 + 0.6*min(1,pressure)` | 孤珠也 0.13 m/s，整块玻璃都在流 | 闩锁形同虚设（离线 harness 的"孤珠不动"断言抓到的） |

第 ③ 条是最有价值的一条：**「水带」不能来自平移，只能来自收拢**。现在的前缘线模型就是这一点。

## 3 标定：数字与依据

| 键 | 值 | 依据 |
|---|---|---|
| `densityCellM` | 0.05 m | 3x3 = 15 cm（约一手宽），是「这里积水」在人眼尺度上成立的最小窗口；0.05 m 时一颗珠 = 44/m²，量化步长 44/m² |
| `densityThresholdPerM2` | 130 /m² | = 15 cm 见方里 3 颗（3/0.0225 = 133）。BR101 玻璃 1.1516 x 1.06 m = 1.2207 m²，140 颗满场均值 115/m² → 暴雨时只有偏密的小块达标，中雨/小雨整块玻璃都在阈值以下 |
| `runoffMps` | 0.45 m/s | 饱和速度。穿过 BR101 的 1.06 m 玻璃约 2.5 s。按密度刚达标时是 0.4 倍 → 0.13~0.18 m/s |
| `pushM` | 0.02 m | 弓形波上限（真正生效值一般是刀的每帧位移的一半，约 11 mm）；约为刀刃触地宽度 0.035 m 的一半 |
| `RUNOFF_MARGINAL_FACTOR` | 0.4 | 见 §2 ③″/③′：让「刚达标」也有可见速度，同时保住闩锁 |
| `BOW_WAVE_FRACTION` | 0.5 | 必须 < 1，否则刀的弓形波追不上，永远不会收拢 |
| `mergeDistanceM` | 0.012 m | 收拢后珠子会重叠，靠合并收敛成更大的珠子；这次补进了 `WINDSHIELD_FIELDS`（一个曾静默丢失的键） |

## 4 离线实测（`DropletFlow`，BR101 真几何 + v34 真配置）

```
probe check        : 均匀 140 颗 → 手算 151/m²，实测 151/m²（探针自证）
intensity 0.30     : alive= 67 mean=  68/m² max=  89/m² flowing=  0 (0.0%)
intensity 0.60     : alive= 98 mean=  73/m² max=  89/m² flowing=  0 (0.0%)
intensity 1.00     : alive=137 mean= 119/m² max= 400/m² flowing= 48 (35.0%) speed(flowing)=0.302 m/s
孤珠（10 s）        : alive=1 movers=0（单珠极限，闩锁有效）
一次行程（0.775 s） : 691 次携带事件 / 75 颗不同珠子，每颗净携带 155.4 mm，0 颗被推出玻璃
                     刮前玻璃均值 119/m² → 刮后 185/m²；水带 mean 222/m²（max 622），0.222 m/s
刀停后 1 s         : 水带 60 颗走了 206.8 mm（0.150 m/s）；没被推到的 32 颗 81.5 mm（0.068 m/s）
中雨(0.6) + 一次行程: 玻璃自身 flowing 0.0%；刀收出来的水 123/m²，0.116 m/s，1 s 走 118.2 mm
单轴(扇形)对照      : 玻璃 flowing 20.7%；一次行程携带 26 颗（每颗 183.4 mm），收成 256/m²（玻璃 84/m²），
                     1 s 走 131.5 mm —— 扇形的"收拢"断言在离线也跑通了
ALL CHECKS PASSED（14 项）
```

读法：
- **小雨/中雨：整块玻璃静止**（max 89/m² 连阈值都够不到）——"不够多就不下"；
- **暴雨：35% 的珠子在流**，0.30 m/s；
- **雨刷在任何雨量下都能造出水带**（中雨时玻璃本身 0%，水带 0.116 m/s、1 s 走 118 mm），这就是第 3 段因果；
- 水带比周围玻璃快 2.2 倍（0.150 vs 0.068）。

### 4.1 扇区路径（单轴雨刷）的一个静默 bug

BR101 是平行连杆，走的是**带式**分支，所以离线对照最初完全没覆盖**扇区**分支——而那正是包里**其他所有车型**走的分支。
它的第一版把「刀的前进量」从**建模刀刃**上读，而扇区路径根本没有建模刀刃 → `bladeAdvanceM = 0` →
每颗珠子的位移 `min(0, ...) = 0`：**单轴雨刷对雨滴完全不作用，而且不报任何错**。
现在扇区路径自己算前缘：前缘前进量 = 臂长 × 本帧转过的角度，并且只对「本帧扫过的弧 + 前方的淡出带」内的珠子作用
（扇形的擦水测试是 park-to-blade，范围远大于"本帧一条带"，不加这个限制会把半程之前的水反复拖着走）。
`DropletFlow` 增加了 `Glass.sector(...)` 对照，断言"单轴雨刷同样推水并收成水带"。

运行方式：
```powershell
& "$env:JAVA_HOME\bin\javac.exe" -d sandbox\dropletflow mmtr\tools\wiper-preview\DropletFlow.java
& "$env:JAVA_HOME\bin\java.exe" -cp sandbox\dropletflow DropletFlow
```

## 5 游戏内诊断行（两行，都在 `LOGGER` 里打）

```
[MMTR-WSHLD] motion <pane> prev= intensity= snow= speedMps= down=(x, y)
             alive= flowing= density=(mean, max, threshold) meanSurfaceSpeed= meanRadiusMm=
             windowMaxStep= travelled= movers= frames= spread= offGlass= pushed= pushedOff= mode= angle=
[MMTR-WSHLD] wipe   <pane> angle= from= span=deg bandWipe= beadsInBand=/ pushed= pushedOff= pushM= advance=
```

要看的三件事：

| 现象 | 看哪两个数 |
|---|---|
| 雨滴到底动没动 | `movers` / `travelled` / `windowMaxStep`（窗口内最大位移，不是单帧） |
| 为什么不动 | `density=(mean, max, threshold)`：`max < threshold` 就是"真的不够多"，是设计而非 bug |
| 雨刷有没有推水 | `wipe` 行的 `beadsInBand` 与 `pushed`；`pushedOff` > 0 表示水被带到玻璃外沿 |

## 7 遗留与风险

1. **雨刷把水带出玻璃后的观感未在游戏内确认**：离线显示 0 颗被推出边界（80° 行程里水带只走到中途），
   但长时间连续刮（快档 + 多个行程）水带会被带到边缘并 `respawn`，需要游戏内看是否"水被甩出去"而不是"消失"。
2. **`fallMps = 0.75` 与客户端注释里的 30 km/h 不一致**：`fallMps` 现在只决定"气流何时压过重力"
   （爬升阈值），0.75 对应的交叉速度约 35~43 km/h，而 `BALANCE_SPEED_MPS = 8.33` 的推导基于 0.55。
   没动它（用户没提），但两处说法应当统一。
3. **`WiperPreview.java` 已经过期**（还在 ink 模型上，且它的 `ALL CHECKS PASSED` 不再代表客户端）。
   已在文件头写明 STALE；其"雨刷几何/扇边/画图"部分仍可读，重写到密度模型是待办。
4. **`wipersweep` 几何仍是 98 点条带**：打包器的扇形拟合读到 `293.764°`，靠机构求解（残差 0.0 mm）才写成 80°。
   把扫掠区收缩成只有两条边界线的结构上不可伪造的形状，是更彻底的修法（未做）。
5. **`panelDown()` 返回单位向量**，所以 `advanceDrops` 里 `slope` 恒为 1；那段注释里"投影 0.646"的说法是错的
   （0.646 是 `|up.z|`，不是投影长度）。数值行为不受影响，注释待改。
6. **密度量化步长 44/m² 是阈值的 34%**：所以"刚达标"和"两倍达标"之间只有 2~3 个量化台阶。
   若想让小雨/中雨也有少量流动，把 `densityCellM` 提到 0.08（24 cm 探针，步长 17/m²）是最省事的旋钮。
