# 47 - 实机缺陷：多节编组在客户端塌成一点（客户端 simulateInDepot 覆盖 railProgress）

> 现象（用户实机）：aassdd 刷出 8 编组 HST 后，**8 节车全挤在一节车的位置**。
> 结论：**不是资源包问题、不是摆位微调**，是客户端每帧的 `Vehicle.simulate()` 把同步来的
> `railProgress` 覆盖成股道默认位置——B 系列"编组体"在实机里只被**单车**验证过。

## 定位链（每步都有证据）

1. **服务端是对的**：`mmtr-motion` 快照 `cars=8 front=(-211.5,-97.5) rear=(-211.5,34.5)`，前后端相距 **132.0 m**。
2. **无头复现客户端重建**：`MmtrConsistMultiCarPlacementTests` 用真实存档把 8 编组放上 186 m 股道，再按
   `VehicleExtension` 的构造方式重建客户端车（`VehicleUpdate` → `DynamicDataResponse` → JSON 往返 →
   `new Vehicle(update.getVehicleExtraData(), null, vehicleJson, ClientData)`）：**逐车铺开 117 m（正确）**，
   路径 `legs=2 start=-159.0 end=27.0` 也正确。
3. **客户端诊断**（临时加在 `MmtrCabInteraction`，重启后拿到）：
   ```
   path(progress=159.0 reversed=false len=132.0 legs=2 start=-159.0 end=27.0 rail=found zs=[62 62 62 62 62 62 62 62])
   ```
   → 路径对、轨道解析对，但 **`progress=159`**（服务端是 `0`）；`159 = (股道长186 + 车长132)/2`，正是
   `VehicleExtraData.getDefaultPosition()`。所有车都从 159 起算 → 越过路径末端 → 夹到股道尽头 `z=62`。

## 根因

`Vehicle.simulate()` 的兜底分支**没有客户端守卫**：

```java
} else {
    currentIndex = 0;
    simulateInDepot();      // ← 客户端每帧也走这里
}
```
```java
private void simulateInDepot() {
    railProgress = vehicleExtraData.getDefaultPosition();   // 覆盖同步值
    reversed = false;                                       // 抹掉同步朝向
    ...
}
```

客户端每帧对所有车辆调用 `simulate()`（`MainRenderer`），于是服务器同步来的 `railProgress=0` 每帧被覆盖成 159。
**单车为什么一直看不出来**：`defaultPosition=(43+15)/2=29` 落在股道中部，视觉上"差不多对"；
8 节编组把它放大成"全挤成一点"。

## 修复

`Vehicle.simulate()`：客户端运动镜像（`mmtrMotionMirror`，已是同步字段）**跳过** `simulateInDepot()`。
只影响客户端镜像；服务端（走 motion 分支）与 legacy 车行为不变。

## 回归（红 → 绿）

`MmtrConsistMultiCarPlacementTests.eightCarConsistSpreadsItsCarsOverTheWholeTrain`：
重建客户端车 → **tick 10 次** → 断言逐车仍铺开且 `railProgress` 不变。

- 修复前：`spread=0.0 m`（8 节全在 z=-124.5，红）
- 修复后：`spread=117.0 m`（绿）

全量 **386/0/2**（385 → +1，零新增失败）。引擎 shadowJar 已同步到 `game/libs`（12:23:43）。

## 环境事实（本轮踩到的坑）

dev 环境里**客户端与服务端是两个进程**：本轮 `runServer` 是 11:55 启动的、`runClient` 是 12:26 启动的。
所以：

- 客户端重启即加载新引擎 jar → **本次修复（客户端侧）当场生效**；
- **服务端仍是 11:55 加载的旧 jar** → C2（非动力车 `mmtrPowered`）**尚未生效**，需要单独重启服务端
  （启动时 manifest reset 会按 `powered:false` 重新刷出 8 编组）。

以后凡是"引擎改动要生效"，必须确认**两个进程都重启**。
