## 1. 地形勘察：z=1800 是**岸线**，不是海面

`scan_surface_area.py --x 0 --z 1800 --size 256`：该 256×256 方块内 **0 个区块未生成**，
高度分布里 y=62 只占 **23.8%**（对照：原点周围 1536² 扫描时 y=62 占 74.1%）。
⇒ **这里已经是陆地**，notes/302 §5 的"环线处处跨海"结论**只对原点附近成立**，不适用于 z=1800。

逐格剖面（`z=1800`，看**真实方块**而不只是高度图）：

| x | 地表 | 方块 |
| --- | --- | --- |
| 0 | 63 | `grass_block`（地面） |
| 10 | 62 | `grass_block` |
| **20** | **65..67** | **`oak_leaves`（一棵树，不是地形）** |
| 30 | 60 | `grass_block`（凹地） |
| **40** | 61..62 | **`water`（岸线从这里开始）** |
| 50 / 100 / 140 | 61..62 | `water`（一片水面） |

沿 `x=0` 往 +Z 则全是陆地森林（树下地表 63..80，树冠到 y=77）。

> 教训：**高度图分不出"树"和"地形"**。z=1800 那个 y=65..67 的"隆起"读起来像小山包，
> 实际是 `oak_leaves`。**清障前必须按真实方块确认一次**，否则会按地形尺寸去估算工程量。

## 4. ★ 纠正 skill 里的一处错误断言

notes/302 写的 skill 里，我把"直轨节点状态"记成了
**「沿 Z 或沿 X 的直轨两端都是 `facing=false,is_22_5=false,is_45=false`」**。
**这一半是错的。** 本轮 L2 实测：

| 轨走向 | 弦向 mod 180 | 节点状态 | `getAngle` |
| --- | --- | --- | --- |
| **东西向（沿 X）** | 0° | **`facing=true`**,is_22_5=false,is_45=false | 0 |
| **南北向（沿 Z）** | 90° | **`facing=false`**,is_22_5=false,is_45=false | 90 |

存档对拍（`sandbox/read_block.py`）：

```
(-107, 65, 542)  mtr:rail[facing=false,…]   ← 既有牵出线，南北向
(-102, 65, 542)  mtr:rail[facing=false,…]
(-107, 65, 292)  mtr:rail[facing=false,…]
( -43, 65, 800)  mtr:rail[facing=false,…]   ← 样板站，南北向
(   0, 65,1800)  mtr:rail[facing=true,…]    ← 本轮新铺，东西向
( 100, 65,1800)  mtr:rail[facing=true,…]
```

**为什么原来会记错**：本工作区**既有的轨（侧线场、牵出线、样板站）全是南北向**，
所以存档里到处是 `facing=false`，很容易当成"直轨都是这个值"。
**新铺第一条东西向轨时，`facing=true` 才是对的** —— 不是把 mod 180 修反了。

已改：`.dsh/skills/mmtr-track-building/SKILL.md` §三 加了走向对照表与本条实测出处，
惯例表里那一行也改成"东西向 / 南北向"两值。

> 这条正好是 skill 自己要求的 L2 判据抓出来的：**L1 全绿（引擎 63 条、160/160、100 m 全对），
> 只有 L2 才看得出朝向。** 若只查引擎，这个错误断言会一直传下去。
