# 358 水牌版式：每个车型（甚至每块牌）自己一套尺寸与排版

> 用户 2026-10-01 追问：「水牌不同尺寸怎么办？」→ 我答"尺寸本来就每块锚点自带" → 用户：
> 「这个问题比较复杂，**不同车型有不同尺寸和排版的水牌，想办法能够独立吧**。」
> 于是这一轮把"排版"也变成**按车型配置**的一件事。

## 1 分工：尺寸来自模型，排版来自配置

| 是什么 | 谁说了算 | 存在哪 |
| --- | --- | --- |
| 牌**多大**、在哪、朝哪 | 模型（那个四边形） | `mmtr_anchors_<车型>.json` 的 `widthM/heightM/x/y/z/normal/up` |
| 牌上**怎么摆字** | 作者配置 | 同一份 JSON 的 `pid` / `next` 段（由车辆配置转发，notes/358 本节） |
| 牌上**写什么字** | 引擎镜像（班次号 / 本趟终点 / 下一站） | 车辆镜像字段 `mmtrPidService/Terminus/Next` |

于是"不同车型不同尺寸与排版"是**天然独立**的：每节车各有各的配置、各有各的锚点、各有各的缓存条目
（客户端的贴图缓存键是 `车辆id:车节:锚点名`）。

## 2 配置写在哪、长什么样

写在**车辆配置**（`consist/saf420.json` 的每节车、或 `example/vehicle.<id>.json`）里，打包器**原样**写进锚点 JSON：

```json
"pid": {
  "background": "#FF101418", "textColor": "#FFF2F4F6", "pxPerMetre": 512,
  "rows": [
    { "field": "service",  "x": 0.03, "y": 0.5, "size": 0.46, "align": "left", "color": "#FF9FB3C8" },
    { "field": "terminus", "x": 0.97, "y": 0.5, "size": 0.62, "align": "right", "prefix": "开往 " }
  ]
},
"next": {
  "rows": [ { "text": "下一站", "x": 0.5, "y": 0.75, "size": 0.22 },
            { "field": "next", "x": 0.5, "y": 0.35, "size": 0.5 } ]
}
```

- `field` ∈ `service` / `terminus` / `next`；或用 `text` 写字面量（"下一站"、"回库"）。
- `x`/`y` = 牌面宽/高的 **0..1**；`size` = **牌高的比例**；`align` = left/center/right；`color`、`prefix`/`suffix` 可选。
- **不写 `pid`/`next` 段 = 默认版式**（班次号在上、站名在下两行）——与 notes/357 那套写死的排版逐字一致，
  老包一个字节都不用改（`MmtrPidLayoutTests#theDefaultLayoutAgreesWithTheUnversionedRules` 钉着这条）。

**为什么全是比例**：同一份版式在任何尺寸的牌上自动等比 —— "按车型独立"与"换尺寸不改版式"两件事同时成立。
某一行超过牌宽 90% 会自动等比缩小（不会被牌边切掉）。

## 3 这一轮实际配了什么（SAF420，v35）

那块牌是 1.24 × 0.22 m 的**扁牌**，两行会挤 ⇒ 配成**一行并排**：班次号靠左（小、偏蓝），
`开往 <终点>` 靠右（大、白）。两端各写一份（版式按**节车**读，所以 B 端想长得不一样就改它自己那份）。

⚠ **并排必须靠边对齐**（`left` + `x:0.03` 与 `right` + `x:0.97`）：两块都 `center` 时，大字号那行的宽度
会压到另一块上 —— 第一版示范就是这样画出一团重叠的字（离线预览一眼就看出来了，这正是预览工具的价值）。

## 4 判据（都在离线）

| 位置 | 判什么 |
| --- | --- |
| `MmtrPidLayoutTests`（8 例） | 解析与取字：没写段 ⇒ 默认且与 `lines()` 逐字一致；两块牌各读各的段；取不到内容的行不画（拼错字段、回库趟、下一站未知）；字面量行**只受"挂牌门"约束**（门在 `MmtrPidBoard`）；数字被钳（size 0.02..1.5、x/y 0..1）；空/坏 JSON 退回默认（渲染路径上抛异常会中断整帧） |
| `MmtrPidTextTests`（6 例） | 内容口径本身（哪些行、主次、签名含尺寸） |
| `tools/anchor-check/verify_pid.js`（P1..P7） | 锚点几何（位置/绕序/朝向/up/端号/尺寸） |
| `sandbox/pid-anchor-probe/check.ps1` | 上面那个 verifier 的故障注入（6 种坏法各自变红） |
| `tools/pid-preview/preview.ps1` | **出图**：跑真的那条链（`MmtrPidLayout.parse` + `MmtrPanelCanvas`）画成 PNG，改版式一秒看一眼 |

## 5 离线出图（新增工具）

```powershell
pwsh -File mmtr\tools\pid-preview\preview.ps1 -Anchor <mmtr_anchors_x.json> `
     [-Board pid|next] [-Service 00101] [-Terminus 海山] [-Next 鸥湾] `
     [-Out <png>] [-WidthM 1.24 -HeightM 0.22 -PxPerMetre 512]
```

- 尺寸默认从锚点读（与游戏完全一致）；给 `-WidthM/-HeightM` 就回答"做成 1.6 × 0.12 m 好不好看"。
- 实测四张图（`sandbox/pid-anchor-probe/preview_*.png`）：默认两行 / 一行并排（扁牌）/ 方牌三行 /
  **同一份方牌版式铺到扁牌上**（比例自动等比）——四种都对。
- 诚实边界：CJK 字形走**系统兜底**（离线预览拿不到资源包里的 HarmonyOS），字面形状与游戏里有细微差别。

## 7 边界与没做的

1. **`next` 还没有任何模型挂**：契约、版式、预览工具都就位，等模型加 `mmtr_next_*`。
2. **每块牌独立于每节车**：同一节车两端、乃至同端两侧的牌目前共用同一段配置（`pid`）；
   要做"左侧一块、右侧另一块"得把段名细化到锚点名（现在没必要，留作将来）。
3. **颜色/字体**：底色、字色、字号可配；字体仍是客户端那两套（西文 DIN 1451 + 中文 HarmonyOS），没做按牌选字体。
4. **引擎 web 口（8888）这一轮没起**：所以我没法用 web OP 查车的位置，只能靠"正线走廊上等车经过"
   来触发绘制（上面就是这么做的）。这是环境现象，与本次改动无关。
