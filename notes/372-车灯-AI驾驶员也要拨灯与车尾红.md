# 372 · 车灯（三）：**无人那趟车由引擎自己拨灯** —— AI 车头白、车尾红

日期：2026-10-03 · 承接：**notes/352**（三档开关 + 端 + 按键解耦）、**notes/345**（锚点 → 逐片元）、**notes/351**（光影包那一侧）
代码：`engine/…/core/mmtr/MmtrLightSwitch.java`、`engine/…/core/data/Vehicle.java`（`mmtrTickAutoLights`）·
客户端**一行没改**（`render/light/MmtrHeadlights.java` 照旧读镜像）

**用户口径（原话）**：「然后是关于车灯的问题，AI驾驶员也需要控制车灯开关，并且尾部车灯需要变红」。

**一句话结论**：灯的**权威在引擎**（每端一个档位 → 镜像 `mmtrLightA/mmtrLightB` → 所有客户端照着画，notes/352），
而**唯一会拨开关的人**是坐在驾驶室里按 L 的司机 —— **无人那趟车没有任何代码写这两个字段**。于是两件事同时成立：
① 车头一路是暗的（两端都停在出厂值尾灯）；② 更要紧的是**车尾那一端**：上一次人工驾驶按过 L 留下的白灯没人收
（`releaseMmtrLightSwitch()` 只在占用锁释放那一刻跑**一次**，漏了就永远漏）。再叠一处**判据级**的坑：
镜像里的换向器 `mmtrReverser` 也只有 `applyMmtrControl` 才写 ⇒ 自动车在客户端**恒读成 N**，
而判据第 2 条是"换向 N ⇒ 固定红" ⇒ 就算把车头拨到夜间，画出来照样是红的。

---

## 1. 三个事实（都是查出来的，不是推断）

| # | 事实 | 证据 |
|---|---|---|
| 1 | 自动运行**从不**调用 `applyMmtrControl`：它在物理那一支里**合成**一个 ControlState（`new ControlState().setThrottleNotch(autoNotch).setReverser(1)`），而灯光唯一入口 `applyMmtrLightSwitch` 只挂在 `applyMmtrControl` 上 ⇒ 对无人车**不可达** | `Vehicle.java:2823`；全仓 `applyMmtrControl(` 的生产调用点只有两处：`MmtrDriveControl.apply`（客户端包，`Vehicle.java:3699` 那条链）与 `Vehicle.java:2413`（司机自臂） |
| 2 | 镜像换向器在无人车上是**陈旧值（出厂 0 = N）**：`mmtrReverser` 只在 `mmtrActiveControl != null` 时写 | `Vehicle.java:5161`；实测客户端行 `[MMTR-LIGHT] 车灯：… 灯光=A端=尾灯 B端=尾灯（换向N：固定红）`（11:46 那场） |
| 3 | 白灯回落**只有一次机会**：占用锁释放时 `releaseMmtrLightSwitch()` 把日/夜落回尾灯；那一次没跑（或跑在别处）就永远留着 | `Vehicle.java:3759`（定义）、`Vehicle.java:3904`（`releaseMmtrManualOverride` 里原有的那一次调用；本轮新增的兜底在 `:3850`） |

> 用户看到的就是 ② 与 ③ 的合成：**"AI 开着车，车尾却是白的"**。车头那一端反而因为出厂值就是尾灯而"安安静静地红着"。

## 2. 判据（四条纯函数 + 一条策略）

四条纯函数加在 `MmtrLightSwitch`（本仓"灯该亮什么"的唯一真源，notes/352 §1.3）：

| 函数 | 语义 | 行 |
|---|---|---|
| `autoHeadlightState(int gameHour)` | **世界时** `[06:00, 18:00)` = 日间档（低亮度），其余 = 夜间档（高亮度）；负值（引擎还不知道世界时）= 夜间档（最亮） | `MmtrLightSwitch.java:156` |
| `autoLeadingEnd(boolean travelsTowardB)` | 自动运行的**车头端** = 走行体的**真实行驶方向**（B 在前 ⇒ B 端） | `:167` |
| `otherEnd(int end)` | 车尾端 = 车头的另一端 | `:172` |
| `autoReverser(boolean travelReversed)` | 镜像换向器**在档**：前进 `+1` / 尾在前 `−1`（**绝不能是 0**，0 会被判成"换向 N ⇒ 固定红"） | `:184` |

策略 `Vehicle.mmtrTickAutoLights()`（`Vehicle.java:3808`，每 tick 在 `simulate()` 的服务端分支里跑一次，`Vehicle.java:2229`）：

1. **"AI 在开"的判据**（四条合取）：车上挂着一个**没结束**的任务（`!isTerminal()`）· 执行者是 `AUTOPILOT`/`AI` ·
   钥匙是引擎那把占位钥匙（`cabs().isSystemKey()`）· 没有人工接管（`!mmtrManualOverride`）。
   **刻意不用 `mmtrMotionAuto`**：它在每次"停车点重规划 / 换向翻转"时都会被清掉再自臂，拿它当判据车头灯每到一站就闪一下。
2. **车头 = 真实行驶方向**（`travelsTowardB()`），不是"被占用驾驶室那一端" —— 自动运行允许**尾在前**跑
   （`mmtrMotionSelfArmMission` 规划不出来时会翻一次换向器，见 `Vehicle.java:931`），灯必须跟着真实方向，否则车尾亮白灯。
3. **两端都写死**：车尾先写 `TAIL`，车头写 `日间/夜间`。**"车尾也写一遍"就是用户那句"尾部车灯需要变红"的本体**：
   不依赖任何人把上一次的白灯收掉。
4. **镜像换向器先写在档**，再写两端开关（顺序有讲究：`setMmtrLightSwitch` 的日志里会印 `describe(...)` 的**生效结果**，
   换向器还是 0 时那行会印出"（换向N：固定红）"这种自相矛盾的读数 —— 12:18:33 那场实测原话就是
   `灯光开关：A端 = 日间（A端=尾灯 B端=尾灯（换向N：固定红））`，12:19:30 重编后改成本顺序）。
5. **司机优先**：有乘务员钥匙（`isCrewKey()`）或人工接管（`mmtrManualOverride`）⇒ 这条规则**一条都不动**。
   注意第二条是必须的：司机在**无人编组**上推手柄时，引擎自己会补一把 SYSTEM 占位钥匙让编组有头
   （`mmtrAdoptUnmannedConsistForDriver`），那种车上他刚按 L 拨的档位就是他要的答案。
6. **交还**：任务收工 / AI 不再持钥匙 ⇒ 白灯落回尾灯；并且**无人照看时每 tick 幂等地收掉陈旧白灯**
   （notes/352 的不变量 2"无人照看的车两端都是红标志灯"的自愈版）——③ 那种"漏一次就永远亮着"的值最多活一 tick。

## 3. 实机证据（2026-10-03 12:18–12:20；`game/libs` 的引擎 jar 12:19:30 构建，服务端 12:20:07 起重启）

* `灯光=A端=夜间 B端=尾灯` 后面**没有**"（换向N：固定红）"那个后缀 ⇒ 客户端手上的镜像换向器**不是 N**（这正是 §1 第 2 条那一坑被填上的直接证据，因为那后缀只在 `mmtrReverser == 0` 时出现）；

## 5. 边界与代价（诚实清单）

| 项 | 现状 / 理由 |
|---|---|
| **停车（站台停留/等信号）时车头仍亮白** | 真车在服务站内也是这样（换向器在档、灯不灭）。**如果用户要的是"停着两端红"，改动是一行**（策略里加"`speed ≈ 0` 且停在停车点 ⇒ 跳过"）。这一条要用户拍板 |
| 车场停放（有 SYSTEM 钥匙、**没有任务**） | **不亮白灯**，两端红标志灯 —— 与 notes/352"无人照看的车两端都是红标志灯"一致 |
| 非编组体的单点走行器（老式车） | 没有驾驶室模型（`MmtrCabState` 不存在）⇒ 这条策略不适用，灯仍是出厂尾灯 |
| 人工接管 | 引擎绝不覆盖（§2.5）；他停手/下车那一刻的回落由 §2.6 的兜底接手 |
| 引擎时钟 | 世界时来自游戏端 `SetTime`（每 25 s 推一次 + 按毫秒外推）。**服务端刚起、还没推到之前读 0 时 ⇒ 夜间档**（最亮，比"看不见的前照灯"安全）。日志每行都带"世界时 N 时"，现场不用猜 |
| 灯光不进运动流 ① | 仍走 ②（整份/稀疏补丁；两端档位在白名单里）。**换向器走 ① 的 CONTROL 帧**，而 ① 首帧不重发控制值（只在变化或每秒边沿补发）⇒ 客户端最迟 1 秒看到"在档"。这 1 秒内客户端会把两端都画成红（旧的 N 值），不是白 |
| 一个 1 秒级的抖动 | 接上一条：AI 刚接管灯光的那 ≤1 s，画面可能还是"两端红"（客户端还没收到 `mmtrReverser`）。要彻底消掉得让 `Slot` 帧也带控制值（改运动流格式），本轮**没做** |
| 距离剔除（既有，本轮没动） | 候选灯的既有闸门是 `cameraDistance > range + 64` ⇒ **车头 104 m、尾灯 76 m** 之外不进候选（尾灯射程 = `headlightRangeM × 0.30`，默认 12 m）。实测那一列 10 节车、车尾在 180 m 外时 `候选=2/锚点=4`：尾灯没上传。那个距离上 0.26 m 的灯罩是**亚像素**，加上去也看不见，所以本轮**不改**；真要"尾灯从很远就看得见"，得动 8 槽位的挑选顺序（让整列两端优先）与着色器数组长度，那是另一件事 |
| 中间车厢 | 现在只有两端驾驶室车有灯锚点（`saf420cab_a/cab_b`），所以"车头白/车尾红"就是整列观感的全部；将来中间车加灯，按"它自己那一端的档位"亮，与 notes/352 §7 同一口径 |

## 6. 实机验收（需要人）

1. 看一列**无人**（AI）在跑的车：**车头白、车尾红**；18:00 那一瞬车头会自己从日间翻到夜间（更亮一档）。
2. 它停在站台时车头仍白（当前口径，见 §5 第一条）。
3. 按 G 接管（或坐进驾驶室）⇒ 灯归你，按 L 循环照旧，引擎不再插手；**下车走开**⇒ 车头重新点亮、车尾红。
4. 特意制造"陈旧白灯"：坐进某端驾驶室按 L 到夜间 → 拔钥匙走开 → 让它变成 AI 在跑 ⇒ 车尾应当是**红**的
   （服务端会打一行 `无人照看：收掉陈旧白灯` 或 `自动运行灯光交还`）。
5. 服务端日志里认这三行：`自动运行灯光：车头=… 尾=… 换向=…`（一次转换一行）、`灯光开关：X端 = …`（真的写了才有一行）、
   `无人照看：收掉陈旧白灯`（兜底干活了）。

## 7. 遗留

| 项 | 说明 |
|---|---|
| 灯光状态没有任何**只读出口** | `/mtr/api/map/mmtr-trains` 与 `query trains` 都读不到两端档位与换向器 ⇒ 只能翻服务端日志/站在车边看。要的话加 `lightA/lightB/reverser` 三个字段（网页与诊断都能直接看） |
| 停车时是否灭白灯 | 见 §5 第一条，等用户拍板 |
| ① 首帧不带控制值 | 见 §5 里"灯光不进运动流 ① / 一个 1 秒级的抖动"两行 |
| 连挂灭尾灯 | 接口仍是 `Vehicle.setMmtrLightSwitch(end, OFF)`（notes/352 §4），本轮没动 |
