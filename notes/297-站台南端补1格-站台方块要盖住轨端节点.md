# 297 · 站台南端补 1 格：站台方块必须盖住轨的两个端节点

> 用户口径（2026-09-25）：**「-44 1020处，轨道伸出站台一格」**。
> 直读存档确认了，属实，而且比看上去更严重一点。

## 1. 用户看到的是什么（存档取证）

```
z=1019  x=-52..-46 石砖 x7 | -45 mtr:platform[east] | … | -35 mtr:platform[west] | -34..-28 石砖 x7
z=1020  -43:mtr:rail  -37:mtr:rail          ← 只有两个轨节点，站台什么都没有
z=1021  (全空)
```

根因是**"220 m" 与 "220 列" 差 1**：`rail add` 的两端节点相距 220 ⇒ 轨长 220 m，
但节点本身**占两列**（z=800 与 z=1020）；而我把站台方块铺成了 `z=800..1019`（220 列），
于是南端那个节点落在站台之外。

**顺带更严重的一点**：路基 `fill -52 62 800 -28 64 1019` 也只到 z=1019，
所以那**两个轨节点其实是悬空的**（y=64 下面没有方块）。用户看到的是"伸出站台一格"，
实际还多了"底下没路基"。

## 2. 定下来的标准化口径

> **站台方块要覆盖轨的两个端节点。**

⇒ 轨长 220 m（节点相距 220）时，**站台方块是 221 格**（`z=800..1020`），
路基也同步到 1020。MTR 眼里的"站台长度"仍然是 **220 m**（Platform 的长度来自站台轨，
不是方块列数），方块多出的那一格只是把端节点包进去、不让它露在外面。

以后按这个模板批量建站，`Z_TO` 一律取 `RAIL_Z_TO`（= 轨南端节点所在的 z），不要用 `Z_FROM + 220 - 1`。

## 3. 补了什么

`gen_station_template.py` 里 `Z_TO` 由 `1019` 改成 **`1020`**（= `RAIL_Z_TO`），重新生成后补铺 z=1020 一整列：

| fill | 量 |
| --- | --- |
| `fill -52 62 1020 -28 64 1020 minecraft:stone_bricks` | 75（路基 25 × 3） |
| `fill -52 65 1020 -46 65 1020 minecraft:stone_bricks` | 7 |
| `fill -45 65 1020 -45 65 1020 mtr:platform[…facing=east…]` | 1 |
| `fill -35 65 1020 -35 65 1020 mtr:platform[…facing=west…]` | 1 |
| `fill -34 65 1020 -28 65 1020 minecraft:stone_bricks` | 7 |

（重新生成的完整文件现在是 8 条 fill / 108,511 格；整份重跑是幂等的。）

## 4. 验收

| 判据 | 结果 |
| --- | --- |
| 站台层 z=800 / 1019 / 1020 逐格（3 × 16 = 48 点） | 全部正确（两个 `mtr:platform` 的 facing 仍是一东一西） |
| 路基 z=1020、y=62..64、x=-52..-28 | 全是石砖 |
| 两个轨节点脚下 `(-43,64,1020)` / `(-37,64,1020)` | 都是 `minecraft:stone_bricks`（不再悬空） |
| z=1021 | 整排空气（没有多铺） |
| `forceload` | 已 `remove all` |

## 5. 回滚

撤这一列：`fill -52 62 1020 -28 65 1020 minecraft:air`。
（但撤了轨节点就又悬空 —— 除非同时把轨南端节点挪回 1019，那样轨长变 219 m。）
