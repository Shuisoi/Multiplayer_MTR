# notes/04-带宽基准（M0b 基线段，2026-09 round3）

环境：本机 loopback；MMTR Engine standalone（Transport-Simulation-Core jar，Jetty 8899）；维度 test（空世界）。

## echo 通道（/mmtr/api/bridge/echo，POST JSON）
- 首请求（JIT/预热）213ms；此后 40 次采样：
- RTT p50 = 15.3 ms，p90 = 16.0 ms，max = 17.8 ms，avg = 15.2 ms
- 平均单请求 请求+响应 ≈ 194 B
- 折算：@20Hz/客户端（单操作通道）≈ 3.8 KB/s —— 与既有 map 接口同量级，无压力

## ping/vehicles（GET）
- ping/vehicles 空世界 200，RTT ~15ms（见 notes/03）

## 结论与缺口
1. 协议层（HTTP+JSON、维度路由、双向 echo 相关）已验证可工作，延迟 ~15ms 可用。
2. 带宽基准的“重头”= 含列车世界下 vehicles 快照（10–20Hz）的真实字节数 → 需先做
   “演示世界生成器”（用引擎 API/测试工具造 depot+siding+列车并落盘），再测。
3. 预留：快照将来切 MessagePack + 增量 + 区域裁剪，目标单客户端下行 < ~50 KB/s@20Hz。

## 补充：vehicles 负载曲线（round4，synthetic 同构快照，整表全量刷新 @20Hz 假设）
- 8 辆   : ~1.0 KB/响应 -> ~20 KB/s
- 40 辆  : ~4.6 KB/响应 -> ~91 KB/s
- 200 辆 : ~22.8 KB/响应 -> ~446 KB/s
- RTT 恒定 ~15ms（与负载无关，本机 Jetty 开销主导）。
解读：naive 全量 20Hz 轮询在 40 辆可见时约 91KB/s/客户端（LAN 可承受，公网偏大）。
后续用：区域/可见性裁剪 + 增量(delta) + 低频 LOD + (可选) MessagePack，目标单客户端 <50KB/s@20Hz。
