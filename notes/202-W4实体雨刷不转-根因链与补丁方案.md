## 2. 已修的实质改动（保留）

`ModelPropertiesPart.renderNormal`：W4 的整段旋转原本被关在
`if (OptimizedRenderer.hasOptimizedRendering()) { … } else { …W4… }` 的 **else** 里，
而优化渲染默认开着 ⇒ **永不执行**。修法：机制部件绕开优化分支。

```java
boolean isWiperPart = false;                       // 提前算（wiper_ / wiperarm_ / wiperrod_）
if (OptimizedRenderer.hasOptimizedRendering() && !isWiperPart) { …门… } else { …W4… }
```

## 3. 为什么还是不动（OBJ 路径的绘制机制）

`ModelPropertiesPart` 有两个 `writeCache` 重载，OBJ 重载里：

```java
optimizedModelDoor = () -> isDoor() ? OptimizedModelWrapper.fromObjModels(objModels) : null;
positionDefinitions.forEach(… -> { if (type == PartType.NORMAL) { iteratePositions(… -> {
    if (!isDoor()) { addObjModelPosition(objModels, objModelsForPartConditionAndRenderStage, …); }   // ← 进主批
    addObjModelPosition(objModels, objModelsForPartConditionAndRenderStageDoorsClosed, …);
    partDetailsList.add(new PartDetails(new ObjectArrayList<>(), optimizedModelDoor.get(), …));      // ← modelParts 恒空
``` 

也就是说 **OBJ 模型下每个部件的 `modelParts` 都是空的**（日志 `modelParts=0` **连门也是**），
可绘制几何全部走 `objModelsForPartConditionAndRenderStage` → 汇成**主优化批**在别处一次性绘制；
`renderNormal` 的 `else` 里那句 `partDetails.modelParts.forEach(render)` 画的是空集。
**唯一能逐部件单独绘制（因而能施加变换）的，是 `optimizedModelDoor`** —— 而它只对门非空，
且它在优化分支里**只在开门时**才被 queue。

## 4. 补丁方案（下一轮机械执行）

目标：让机制部件**像门一样**拥有自己的可绘制 wrapper，并**在 `else` 里被真正画出来**（不是只在开门时）。

1. **`ModelPropertiesPart` 增加机制部件判定**（与 `isDoor()` 并列）：
   部件名以 `wiper` 开头（`wiper_` / `wiperarm_` / `wiperrod_`）即视为机制部件。
2. **OBJ 重载 `writeCache`（约 L187-207）**：
   - `optimizedModelDoor = () -> (isDoor() || isMechanism()) ? OptimizedModelWrapper.fromObjModels(objModels) : null;`
   - **不要把机制部件加进主批**：`if (!isDoor() && !isMechanism()) { addObjModelPosition(objModels, …RenderStage, …); }`
     （否则会同时出现"静止副本 + 旋转副本"）。
3. **Blockbench 重载 `writeCache`（约 L144-160）**同理对称处理（当前不用 BB，但保持两条路径一致）。
4. **`renderNormal` 的 else 分支**：现在那里画的是 `partDetails.modelParts`（OBJ 下恒空）。
   改成：`modelParts` 非空就照旧逐部件画；为空则画 `partDetails.optimizedModelDoor`（若有）。
   ⚠️ 注意：门的 `optimizedModelDoor` 现在只在优化分支、且 `openDoorways` 非空时 queue ——
   改成"else 里也画"时要保证**门不会因此被画两遍**（门的优化分支保留，机制部件不走那条）。
5. 保留 §2 的 `&& !isWiperPart`（机制部件必须走逐部件路径）。
6. **删掉 3 处临时诊断**（`MmtrWindshield` 的节流 `part-entry`、`ModelPropertiesPart` 的 `draw-site`、
   以及残留注释）—— 当前 `draw-site` 已刷到 **52488 行**，必须清掉。
7. 跑 `verify_windshield` + `selftest`（确认雨刷运动学判据没被弄坏）→ 重编译重启 → 实机按 J 验收。

## 6. 实机验收（2026-09-19 23:2x）：**动了，但动得不对**

用户实测："动了，但是动的不对 —— 刀片本身朝下做曲线运动而不是正常向上做扇形；两个连杆有规律地飞到天上。"

**这是坐标系错误，不是运动学错误。** 三点判断：

1. "朝下曲线运动" ⇒ 旋转**轴**不是玻璃面法线（或方向反了）；
2. "连杆飞到天上" ⇒ 连杆支点 `pivot2`（以及 `pinA/pinB`）是**玻璃面局部坐标**（`pivotU×面宽` 这类比例），
   却被施加在**部件的模型坐标系**里 —— 坐标系不一致时位移量级被放大，表现就是"甩出去/飞走"；
3. 这段 W4 代码是早先几轮写好的，**一直被优化分支挡着、从未真正执行过**（notes/187 的 W4"未实现"），
   所以它的坐标系假设从来没被实机校验过 —— 今天第一次跑起来才暴露。

> §2/§3 的修复**是对的、要保留**：几何终于在被旋转的那次绘制里了。要修的是"在哪个坐标系里旋转"。

### 修法：把运动学**共轭**到几何所在的坐标系

运动学本身（面内米制、绕支点转）一字不改，只在外面套一次面的基变换：

    B = [right, up, normal]（锚点在模型空间的三个轴），原点 = 锚点中心
    M_model = B · M_pane · B⁻¹

即：先把矩阵变到面的局部系（`B⁻¹`），在面内做原来的
`translate(pivot) · rotate(angle, 面法线) · translate(−pivot)`，再变回 `B`。

要点：
- `right/up/normal` 必须用**与几何同一套**空间（`MmtrPanelQuad` 的 `toModelSpace` = `(x, −y, −z)`，
  `right = cross(up, normal)`，`facingSide` 选边）—— 复用那套，不要写第二份；
- 支点/销点（`pivotU/V`、`pinAU/AV`、`bladeAU/AV`、`pivot2U/V`）都以**面中心为原点**换算成米再进 `B`；
- 连杆与刀片用同一套变换 ⇒ 连杆不会再飞；
- 方向症状（"朝下"）多半在轴正确后自动消失；若仍在，再查 `sweepSign`
  —— **先修坐标系、再看方向**，两者混查会来回改。
