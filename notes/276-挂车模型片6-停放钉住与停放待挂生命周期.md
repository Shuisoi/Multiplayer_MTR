# 276 — 挂车模型 片 6：停放 = 钉住 + 停放待挂生命周期

日期：2026-09-26 · 设计：`docs/01-设计/非动力挂车-车辆模型与编组对象-设计.md`（片 6）

用户口径（2026-09-26）：停放制动"**简化为不动就行了**"；"对于多人游戏，**不被连上就钉死在地里**就行了"；
坡道力**不接**（决定 1/6）。

## 1. 口径：钉住是**推导**出来的，不是搬来搬去的标志

```
钉住 ⇔ 没有司机（无 override，也没人坐司机位）
     ∧ 没有在跑的任务（任务就是"让它动的理由"）
     ∧ 整列车列没有任何能出力的车底（与准入层同源：anyCarCanPull，含 powered 三态）
```

推导而不是存状态的好处：连挂/解挂改车列、人上车/下车、任务起止，**任何一条变了都自动跟上** ——
不存在"标志忘了搬"。所以它**不进连挂状态串**（设计文档 §3.3 ③ 里那句"进 MmtrComposition 那一层"按实现改了：
推导量不需要载体）。

为什么"位置锁死"必须放在那一串闸门最前面：闭塞停车与保护制动都是"这列车本来能动"的语义，
而钉住是"它根本不该动"。没有这一支，一节**被声明成无动力**的车（单节不走等效车底那条路）会被
**任务**照常开走 —— 准入层只管人（片 2）。

## 3. 顺带修掉的缺陷：`anyCarCanPull` 与物理层不同源

片 2 的 `anyCarCanPull` 原来按"每节车自己的车底，解析不到就用编组缺省"判 `canPull`，
而 `MmtrComposition.fromVehicleCars` 的规则是**只要整列有一节显式解析出车底，借来的车一律按拖车**
（`F_max = P = 0`）。于是"货车车型没配映射"的车列会被判成**能出力**（借了缺省车底的牵引），
准入层放行、钉住层也钉不住它 —— 现场那列车（BR101 + 2×p1，p1 没配映射）正是这个形状。

现在 `anyCarCanPull` 与 `fromVehicleCars` + `toConsistType` **逐条同源**：先算"每节车最后落在哪个车底"
（显式 / 第一节借缺省 / 其余 `asHauledTrailer`），再按"powered 的车 +（整列没声明有动力时）最多一节
没表态的借牵引车"求和。真值表与物理层一一对应，用例（片 2 那 15 条 + 本片 3 条）全部保持绿。

## 4. 判据

**`MmtrHauledRakeLifecycleTests`（新，3 条）**

```
真值表：无人/无任务/拉不动 ⇔ 钉；有司机、有任务、能出力，任一条成立就不钉
停放待挂的车列（两节显式无动力货车）⇒ 钉住；连上机车（整列能出力）⇒ 解钉
单节**被声明成无动力**的车（车底本身能出力）⇒ 不算能出力 ⇒ 钉住（准入层与钉住层各堵一半）
```

**`MmtrCoupleSurgeryTests`（增 1 条，走真 Simulator 与真连挂手术）**

现场日志（同一条用例跑出来的三条状态翻转）：

```
[MMTR-DRV] 车 … 已钉住（停放）：车节数=2 司机=false 任务=false 整列能出力=false
[MMTR-DRV] 车 … 已解钉：车节数=3 司机=true  任务=false 整列能出力=true      ← 连上机车
[MMTR-DRV] 车 … 已钉住（停放）：车节数=2 司机=false 任务=false 整列能出力=false  ← 解挂之后重新钉住
```

**踩到的坑（记一笔）**：本类原有的 `cars("wagon", …, false, "wagon")` 夹具里 **"wagon" 车底是有牵引的**
（`maxTractiveEffortN: 36000`），所以那列车在物理上真能开 —— 用它测"钉住"会得出"钉不住"的假结论。
新用例改用**显式声明无动力**的车列（世界文件/`--unpowered` 那条路写出来的就是它）。

**全量：869 条、失败 3 条、跳过 6 条** —— 三条失败仍是预存在的世界存档漂移。
