# 252 — "牵引力永远是 300 kN"：镜像值不刷新 + 诊断补全

用户口径（2026-09-23，notes/250/251 之后）：

> 我发现问题了，牵引力永远是 300kn

## 1. 这个数意味着什么

`300 kN` 正好是 BR 101 的**起动牵引力上限**（`maxTractiveEffortN`）。按力模型：

```
F(v) = min( F_max · r , P · r / v )          v > 0
F(0) = F_max · r
```

要让它**永远**停在 `F_max · r`，只有两种可能：

1. `v ≈ 0` 或 `P ≈ 0` —— `TractionSpec.effortN` 里那两个短路条件（`maxPowerW <= 0 || v <= 0` ⇒ 直接返回
   `effortLimit`）；
2. **值根本没刷新** —— 快照里那一格停在"某一次推送时的旧值"（那次恰好速度≈0、手柄已推上 ⇒ 300 kN）。

物理层已经排除：`MmtrConsistTractionMappingTests` 里断言过 40.3 m/s 处
`tractionAccelerationMps2(1, 40.3) ≈ 0.85 m/s²`（⇒ 力 ≈ 159 kN，会随速度掉），那条用例是绿的。
所以问题在**读数链路**，不在力模型。

## 2. 本轮改动

### 2.1 值变了就标脏（先修最可疑的那一半）

`Vehicle.updateMmtrSyncFields()`：

```java
final double motorForceN = getMmtrMotorForceN();
if (Math.abs(motorForceN - vehicleExtraData.getMmtrMotorForceN()) > 500) {
    vehicleExtraData.mmtrMarkSyncDirty();   // 不标脏 ⇒ 这一格只在"别的字段顺带推送"时才刷新
}
vehicleExtraData.setMmtrMotorForceN(motorForceN);
```

原来是**只写不标脏**：镜像推送由 `hasRidingEntityUpdate` 决定，只要没有别的状态变化，客户端就
一直拿着上一次推送的旧值 —— 表现就是"数字不动 / 永远是 300 kN"。（`acceleration/deceleration`
两个镜像字段也是这么写的，同样只在顺带推送时更新；它们只用于信号预留与电机音调，所以一直没露馅。）

### 2.2 诊断补全（一次驱动就能定位）

| 端 | 日志行 | 打的东西 |
| --- | --- | --- |
| 服务端 | `[MMTR-CONSIST] …` | 追加 `电机=<活算>kN 镜像=<写进快照的那份>kN`（外加已有的 质量/λ/牵引上限/功率/缸压/管压/LZB 上限/状态） |
| 客户端 | `[MMTR-CL] 电机诊断：…`（2 s 一次，`-Dmmtr.trace=true`） | `速度SI` / `本机活算=kN` / `快照值=kN` / `车底Fmax=kN` / `车底P=MW` / `质量=t` |

四种可能一眼可分：

- **服务端** `电机` 会随速度掉、`镜像` 也是同一个数 ⇒ 服务端没问题，问题在传输/客户端；
- 服务端 `电机` 就不掉（或 `功率上限=0.00MW`）⇒ 车底/活算那条链的问题；
- 客户端 `车底P=0.00MW` ⇒ 镜像车底缺功率上限（那客户端跑的物理也是错的，不只读数）；
- 客户端 `本机活算` 掉而 `快照值` 恒 300 ⇒ 快照没刷新（2.1 就是修这个）。
