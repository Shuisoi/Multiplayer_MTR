# 256 — AFB 只能削减，不能提升功率（第五次也是最后一次口径修订）

用户口径（2026-09-23）：

> AFB 只能限制功率，不能提升功率，为什么现在一上车手柄为 0 就会直接往前开

## 1. 之前错在哪

notes/240/241 为了修"没法定速"，把 `afbUsesHandleAsCap` 设成 `false`，控制器里留了这条分支：

```java
tractionRatio = handleTraction > 0 && cap ? min(handleTraction, afbDemand) : afbDemand;
//                                                 ↑ 手柄在关闭位 ⇒ AFB 自己给满力
```

于是**上车手柄 0、定速还挂着旧值 ⇒ AFB 直接给 300 kN，车自己开走**。这正是用户这次报的现象。

## 2. 新规则（唯一口径）

```java
tractionRatio = cap ? Math.min(handleTraction, afbDemand) : afbDemand;
```

- **手柄关闭 ⇒ 牵引 0**：AFB 不提升功率，车不许自己走；
- 手柄 20% ⇒ 出力 ≤ `300 kN × 20% = 60 kN`（AFB 只能往下削）；
- **超速那一半不变**：AFB 照旧可以自己上电阻制动 + 补气制动（它只让车变慢，不违反"不提升功率"）；
- **定速的作用 = 限速/保速，不是自动驾驶起步**：要起步/加速必须司机推手柄。这是刻意的取舍
  （用户口径优先于"设了就得走"）。
- `afbUsesHandleAsCap=false` 降级为**非符合口径的历史模式**（只为兼容保留），
  缺省改为 **true**（`ThreeHandleSpec.DEFAULT` 与 `fromJson` 缺省都改了）。

## 3. 用例（把口径钉死）

| 用例 | 断言 |
| --- | --- |
| `afbNeverPullsTheTrainWithTheThrottleClosed`（改写自旧的 `afbPullsTheTrain…`） | 手柄关闭 + 定速 100：积分 200 s 后 **v = 0.00 km/h**、牵引比 0 |
| `afbOnlyCutsNeverAdds`（改写自 `afbCanAddTractionBeyondTheHandlePosition`） | 缺省 cap=true；手柄 5% ⇒ 牵引比 = 手柄那份（AFB 不加）；近设定速度 ⇒ 被削到 <0.3 |
