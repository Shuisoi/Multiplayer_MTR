# 217 · 「刚才能动，现在又动不了」= 信号/进路把车按住（司机此前看不见）

日期：2026-09-21 · 车辆：BR101（`7805686184092402671`）· 结论：**不是手柄、不是车底、不是类加载** ——
是**运动/信号层的闭塞停车与进路闸门**在 {@code mmtrBlockedWaiting} 状态下把速度强制为 0，而它**排在司机分支之前**；
理由以前只写在服务端日志里，司机在游戏里看不到任何解释。本轮把理由做成**司机可见**（镜像 + HUD + 动作栏）。

用户原话：「刚才能动了，现在又动不了了，是什么原因」。

## 1. 证据（全部来自日志，不猜）

被当掉的那辆车 `7805686184092402671`（客户端 perf 行同时显示 `本地最大位移=0.000 格 外部最大挪动=0.000 格（0 次）`
—— 真的一格没动），而 `[MMTR-HLTH] … mmtrOverrides=1` **一直有效**：手柄包到了、操纵权也在。

```
[15:49:38] [MMTR-SIG] motion resting at block stop 778.44m (block ahead ends at an unset turnout, waiting)
[15:49:38] [MMTR-SIG] occupancy block cleared - manual control resumes          ← 闸门一开就能走
[15:50:30] [MMTR-SIG] motion resting at block stop 789.37m (block ahead ends at an unset turnout, waiting)
[15:50:57] [MMTR-SIG] motion stopped at block stop 977.13m (block ahead occupied, waiting)
[15:52:14] [MMTR-SIG] motion stopped at block stop 970.07m (block ahead occupied, waiting)
[15:52:14] [MMTR-SIG] occupancy block cleared - auto resumes to stop target 1030.04m
[15:52:33] [MMTR-SIG] motion stopped at block stop 705.74m (进路未设好，停在出发信号前：
           物理道岔 -170,-60,-511 被 v1174309050070027396 按在位置 1（岔股开放），
           本车需要位置 0（正线贯通）—— 两条进路互斥, waiting)
```

**"刚才能动"就是 `occupancy block cleared` 那几拍**；**"现在又不动"就是又撞上新的闭塞停车/进路闸门**。
前面还出现过 `红灯：停在这架信号前`、`敌对进路：与 v… 共用轨 … 且方向相反`（15:48:5x）。

## 2. 代码为什么是这个结果（优先级顺序）

`Vehicle.simulateMoving` 的分支顺序（节选）：

```java
if (mmtrProtection) { … 紧急 … }
else if (mmtrBlockedWaiting) { speed = 0; }        // ← 闭塞停车：**无条件**，包括司机持 override 时
else if (autoBraking) { … 任务制动包络 … }          // ← 任务停点包络也压牵引
else if (autoActive && !airBrakeConsist) { … 自动巡航 … }
else if ((overridden || autoActive) && …) { … 司机控制 … }   // ← 司机在这一支
```

所以：**司机手持操纵权 ≠ 车一定能动**。闭塞停车（前方区间被占 / 道岔未设 / 红灯 / 敌对进路）是设计上的
更高优先级 —— 这与现实一致（信号优先），但它此前**没有任何面向司机的输出**。

## 3. 本轮做的：把"为什么不动"给司机看

| 位置 | 内容 |
|---|---|
| 引擎 `Vehicle.mmtrMotionHoldReason()` | 一句话理由：`紧急保护（超速/闯灯）` / `前方进路未设好（红灯）` / `前方道岔未设好` / `前方区间被占（闭塞停车）` / `已到停车点（站停/等待任务）` / `前方无进路（死端）` / `已到任务目标轨（等待任务）`；空串 = 没被按住 |
| 镜像字段 `mmtrHoldReason` | schema + 同步白名单 + 在 `simulate()` 每 tick 入口重算并**只在变化时标脏**（`mmtrMarkSyncDirty`）——放在入口而不是司机分支里，因为被按住时根本走不到司机分支 |
| 客户端 `MmtrDriverHud` | 理由非空时**顶到 HUD 第一行**（琥珀色）；理由**变化**时给一句动作栏提示「车被扣住：…」（只在变化时，不刷屏） |
| 详细理由 | 仍在 `[MMTR-SIG]` 日志行里（HUD 只放短句，避免长句挤爆一行） |

新用例（红证过）：`MmtrSignalAuthorityStopTests.aTrainWhoseRouteIsNotSetIsHeldAtItsDepartureSignal`
追加断言「扣住时理由必须镜像出来」；新增 `theHoldReasonClearsOnceTheTrainIsLetGo` 钉住
**理由在放行、车真的走起来时必须清空**（否则 HUD 会挂着过期理由）。

> 第一版我把"清空"断言写成"200 拍之后理由必须为空"，实测拿到 `前方道岔未设好` —— 那是在断言
> "后面一路绿灯"，不是断言这条理由会清。改成"逐拍检查必须出现过'在走且没有理由'的时刻"。
