# 113 - S6 水闸区间：两层模型定案 + 区间图层改用引擎的区块（修掉重复 span）

> 承接 notes/104–112。本片回应三件事：用户对**区间划分**的最终定义（"水闸"）、
> notes/112 §3.2 记下的**重复 span** 缺陷、以及 WEB 区间图层此前用的是我自己拍脑袋的"轨切口"划分
> （134 根轨切成 137 片、64 对重叠，已被证伪）。

## 1. 定案：两层模型（用户 2026-09-10 拍板，不再讨论）

> "应该分两层，轨道层本身可以通过节点进行拓扑以展示线路。但是节点不能带到区间层，
> 信号灯就像水闸一样，靠路径搜索对信号灯进行检测拓扑才对……比如某区间闭合是本区间每个出口都有
> 向区间内的信号灯，而向外的信号灯是下个区间的事情，无信号灯的以铁路末尾或其他情况的区间自己成一个区间。"

| 层 | 边界的来源 | 用途 |
| --- | --- | --- |
| **轨道层** | 节点（道岔/轨端） | 显示线路、拓扑（`mmtr-topology`、道岔层） |
| **区间层** | **只有信号灯**（水闸） | 闭塞：一区段一车 |

推论（本片实现所依据的三条）：

1. **节点不切区间**：区间跨轨端，一根 15 m 的轨不因端点是道岔就成为一个区间；
2. **朝内的灯是界，朝外的灯是下一区间的事**：区间闭合 ⟺ 每个出口都有朝内的灯；
3. **没有灯的地段（尽头、站线）自己成一个区间**。

现实对照（`docs/01-设计/参考-英铁AWS与TPWS机制.md` §4）：真实闭塞分区 = 轨道电路区段，
信号机立在**分区入口**，所以分区边界就是信号机位置；"一区段一车"正是这个分区的存在意义。

## 2. 引擎实现：`gateBlocks()`

`MmtrDirectionalBlockService.gateBlocks()`：对每盏灯沿它**面对的方向**走行，
走到节点上**朝内的**灯（`lampAt(node, heading)` 带方向过滤）或走不动为止；
没被任何走行覆盖到的轨（即整根轨上一盏灯都没有）**各自**成一个区间（不与邻居合并 ——
合并需要节点，而节点不属于这一层）。

- 区间身份 = **开它的那盏灯**（无灯区间用序号）；`endsOpen` = 走到尽头而不是停在下一盏灯。
- `nearestLampOnSpan` 同样加了**朝向过滤**：朝外的灯不再截断本次走行 ——
  这是"西向灯在东端只保护到轨中段"这个错的成因（一个 100 m 轨被算成 50 m）。

## 3. 修掉 notes/112 §3.2 的重复 span（这是本片真正的缺陷修复）

实测（dev 世界，修前）：**448 个 span 里 103 个是同一段轨的重复副本**，
单盏灯的区块里最多 37 段有 17 段是第二份（`-167,-60,-289` 等）。

原因：多腿走行（岔口多腿）的每条支路都会把**共享干线的同一段轨**再 push 一次，
而 `addSpan` 之前没有去重。

修法：`addSpan(section, span)` —— 同一根轨、同一走行方向**只记一次**（先到者胜），
反向通行的记录保留（那是同一段轨上的另一次运行，合法）。

修后实测：

| | 修前 | 修后 |
| --- | --- | --- |
| 区块数 | 97 | 97 |
| span 总数 | 448 | **345** |
| 重复 span | 103 | **0** |
| 覆盖轨 | 134 | 134 |

新增回归用例 `aBlockListsEachRailOnlyOnce`（Y 形岔 + 设进路收窄，两个方向都断言无重复）。

## 4. WEB 区间图层改为引擎的区块

- feed `mmtr-sections` 新增 **`blocks[]`**：每个区块带 `id / lamp / open / occupied / aspect /
  length / spans[]`，每个 span 带引擎算好的 **采样点**（9 段）。旧的 `pieces[]`（我的轨切片）删除。
- 前端只做渲染：`MmtrSectionsService.blocks()` → `MapComponent.applySectionLayer()`
  （按区块上色、占用画粗红、无灯区块画淡灰），数量徽标 = 引擎给的区块数 / 占用数。
  **web 不做任何划分判断**（用户要求：以服务端数据为准）。
- 已删除：`partitionViews()` / `PartitionPiece` / `dedupeCuts` / `addLampCuts` /
  `distanceToRailM` / `lampAtArc` 及其三个常量（它们服务的是已被证伪的轨切口划分）。

## 5. 诚实的遗留（都没修）

1. **实测仍重叠 287 处**：车场梯线里，多盏灯各自"面向"共享的梯线轨，它们的区块**天然**互相包含
   （不是重复 span，是"每盏灯的保护区"这一语义本身的交叠）。地图上后画的会盖住先画的。
   要彻底唯一划分，需要"锁定进路后再定区间"（= 联锁语义），**本轮未做**。
2. **97 个区块里 91 个 `open`**：车场尽头多，走行大多走到尽头才停。
3. **世界里有同坐标/同 y 差 1 的重复灯**（notes/112 §3.3），例如 `-157,-59,-189` 与 `-157,-60,-189`、
   `-163,-60,-189`，这些"灯自己重叠"也会让区块重叠；测试世界，用户说不用管。
4. `MMTR_AWS_TRIGGER_LEAD_M = 75.0` 与英铁实测 ≈183 m 的差距（notes 既有项）。
