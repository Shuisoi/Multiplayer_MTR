## 1. 删掉的东西（B1 · 原版走行分支）

`Vehicle.simulate()` 原来的分派是"motion 车 → `simulateMmtrMotion`；在路线上 → `simulateStopped`/`simulateMoving`；
否则 → 车场"。`simulateMoving` 里那一整套 `speedTarget / powerLevel / stoppingPoint` 计算（含"档位 × 固定加减速度"
积分、`stoppingCooldown`、`railBlockedDistance`、`getUpcomingSlowerSpeed`、`deviationSpeedAdjustment`）**整段删除**。

现在 `simulateMoving` 只剩两种身份：

| 身份 | 行为 |
| --- | --- |
| 服务端 · 在路线上但没有走行器 | **不动，并且说话**：`[MMTR-DRV] 车=<id> 在 MTR 遗留路径上、没有走行器 …请重新编组`（只报一次）；HUD 的"状态"行同时给出同一句话（`mmtrMotionHoldReason()` 新增第一条判据） |
| 客户端镜像 | 与服务端**逐点相同**的 `ConsistDynamics` 积分（`mmtrActive` 为假则跟着服务端一起停） |

`simulateStopped()`（原版"停在停车点等发车"）整段删除；`startUp()`（原版发车）整段删除并留注释说明去向。
"到终点就回车场"那一支（`railProgress >= totalDistance ⇒ simulateInDepot()` + 清乘客）也删除 ——
终点行为现在由任务/停车锚点管。

## 2. 车场发车 → **司机自臂**（B2 的替代品，这是本轮唯一的新机制）

删掉发车闸门会撞上用户 2026-09-21 的硬规矩：**"只要司机能上车，那么什么都阻挡不了他开车"**（notes/233）。
所以车场那一支不是"什么都不做"，而是把"起步"换成 Motion-Core 的**就地自臂**（`Vehicle.mmtrSelfArmForDriver()`），
触发条件与原来那条闸门一字不差（有人掌权 + 推了手柄/请求牵引 + 没被保护锁住）：

1. `Siding.mmtrConsistWalkerFromYard()` —— 车列体（双端车体 + 驾驶室，"人开着走"的正路）；
2. `Siding.mmtrMotionWalkerFromYard()` —— 单点走行器（老车列的退化形态）；
3. `Vehicle.mmtrWalkerFromOwnPath()` —— 车场编不出来时（例如**车列比股道还长**）按"车现在压在哪根轨"建走行器。

三条路都编不出来 ⇒ 打一行**指名道姓**的日志然后停住（绝不静默把司机锁在原地）。

两个必须记住的坑（都写进代码注释了）：

- 自臂会走 `engageMmtrMotionPosition()`，那里**会释放司机现有的 override**（"停车状态变了就不留旧操纵"）。
  这一次自臂恰恰是**司机本人**要的起步，所以编完必须把他的 `ControlState` 原样放回去。
- "分支意图"要交给走行体：车列**已经带着的那条进路**就是当时按道岔位置逐段选出来的路线，现在折成
  **操作位**（`mmtrBranchIntentFromOwnPath()`：每一处"上一段腿 → 下一段腿"记下有序续行表下标）交给它。
  不折的话，司机在岔前会被"没人给位"扣住 —— 现场表现就是**"推着油门停在岔前不动"**。道岔的物理位置闸门
  照旧生效：操作位只是"想要哪条腿"，开通与否仍由道岔说了算（`MmtrForkElection`）。
- `Utilities.getElement(path, i)` 对越界下标是**取模回绕**的（`-1` 拿到最后一段腿）：写"上一段腿"之前
  必须先判 `index > 0`。少了这个判断，车头会当场掉头（本轮实测：走行器在 20 m 股道尽头 `endOfLine=true`，
  `railProgress` 却刚好等于股道长度）。

## 3. §4 缺车底类型 ⇒ 响亮失败（不是死车）

- "没有车底类型 ⇒ 退回 MTR 加减速常数"的退路**删除**（`simulateMmtrMotion` 里的 `else if (overridden)` 线性积分那一支）。
- 服务端**永远**有一份可用车底：解析不到就用 `ConsistType.FALLBACK`（`__mmtr_fallback__`，一节通用车
  60 t / λ1.06 / 100 kN / 600 kW / 制动 60–90 kN / 阻力 900+12v+1.8v²），并且**必须说出来**：
  `[MMTR-DRV] 车底解析：车=… → **缺配置**：既没匹配到车型、也没配 defaultConsistTypeId —— 本车用通用车力学…`。
- 真连兜底都拿不到（理论上只有客户端镜像同步坏了才会）⇒ `mmtrLogNoControllerIfNeeded()` 打一行并**钉在 0 速**。
- `MmtrProtection` 的包线判据从"原版常数 `Siding.MAX_ACCELERATION * 2`"改成**本车自己的紧急制动减速度**
  （空车/重车、单机/长大货物列的可用包线本来就不同）。

## 4. AUTO 作业模式与 MANUAL 合并

`Vehicle#startUp` 是 AUTO 模式唯一的发车手段（`startAutoService` / `kickParkedAutoDeparture`），
而且 `advanceAuto` 数的 `thisPlatformId` 在 Motion 时代**已经没人写**（永远 0）。两者一起删除：
`startOutbound()` 现在对两种模式都调 `runManualStep()`，`running()` 尾部统一 `advanceManual()` ——
一步的完成由它自己的任务终态判定（MOVE_TO 到点/贴车钩、SERVE 开关门与停留、COUPLE/UNCOUPLE 手术）。

## 5. 运行时配置迁移（A7 的最后一块）

`pwsh -File mmtr\scripts\apply-consist-config.ps1 -Force` —— 世界里的 4 份 `mmtr-consist-types.json`
（`run\world` 1 份 + `saves\新的世界` 3 个维度）已换成力键版本。**没换之前**每份车底都会命中
`[MMTR-CFG] 车底 … 用了已删除的旧加减速度键…` 并退回通用车力学（= 所有车型手感一样、阻力为 0）。
