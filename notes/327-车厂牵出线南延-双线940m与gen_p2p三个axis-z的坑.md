## 3. 本轮踩到并修掉的四个坑（**都是"回话 ok 但世界是错的"**）

### 3.1 ★ `gen_p2p.route_fills` 在 `axis="z"` 上把路基铺到原点去了（已修）

```python
sweep = ai if plan.frame_axis == "x" else ci   # ✗ 对 axis="z" 把**横断坐标**当纵向
```

东段（源轴 = x）走 `if` 分支，所以一直没暴露。对 axis="z"：`fill` 的 z 范围变成 `ci-5..ci+5`
= x 范围 ⇒ 每个采样点都在 **(x=c, z=c) 的对角线**上铺 11×11 石砖，而且**整条 940 m 走廊一根路基都没铺**。

* **第一次真跑就中招**：日志里 `fill -26 62 -26 -16 64 -16 … -> Successfully filled 63 block(s)`
  一路刷过去，指令全 OK、引擎全受理。
* **判据**：不看回话，看**产物坐标范围** —— `x -109..109  z 777..1723`（修好后）vs 修前 z 全在 -109..109。
* **处理**：`world-backup.ps1 -Action restore -Label 20260926-220738-depot-south-depot_south`
  （施工前刚取的还原点，停服整目录回滚；复原前又自动存了一份 `…-221057-pre-restore`）。
  回滚后逐格核对：`(-26,63,-26)=air`、`(-26,62,-26)=water` ✓ 原样。
* **修法**：`sweep = ai`（两种轴都取沿线路那一轴）。对 `axis="x"` 行为**完全不变**。

### 3.2 清障会把邻段刚铺好的路基顶挖掉（已修）

`route_fills` 是**逐段「清障+路基」交替**输出的，而清障是 `fill … minecraft:air replace`，
**从该段低端轨面往上**挖。本线第 8 段起轨面降到 64（清障从 y=64 起），
于是把第 7 段平顶 64 的那一层**挖掉**，z=1595..1605 出现 10 m 的"轨下露缝"。

* **判据**：存档直读该处 `(100..108, 64, 1597) = minecraft:air`（本该是 smooth_stone）。
* **修法**：`reorder_fills()` —— **先全部清障、再全部铺路基**（重叠处取高的那个）。
* ⚠ 反过来重放清障会**删掉已铺的节点方块与灯**（它们都在轨面那一层），所以补铺时**只能重放路基**。

### 3.3 检查器的两个假警报（已修，不然会误判成"施工失败"）

| 假警报 | 真因 | 修法 |
| --- | --- | --- |
| 节点方块 40 个里 38 个"不是 mtr:rail" | 读存档时**世界还在内存里没落盘** | 核对前 `save-all flush` + 停 2 s |
| 19 处"路基顶高过轨面" | 检查器沿**两节点连成的弦**取点，而引擎画的是**弧**（22.5°/R=355 弦中部离弧 6.8 m） | 改沿**中心线采样点**（理想弧）横向 ±2.5 取点 |
| 坡段高端的 5 m 被判"高 1 格" | 判据用了**整段低端轨面**，可那段轨还高着 | 判据改成**该点轨的真实高度**（QUADRATIC ⇒ `y(t)=y0+Δy·t²`）：`路基顶 <= ceil(y)-1` |

### 3.4 灯朝向"交替"在节点间距不均匀时会跳号（已修）

`line_signals` 用 `k = round(acc/200)` 的奇偶定朝向。本线 acc = 18/217/494/771/970
⇒ k = **0,1,2,4,5** —— 连续两处同向，于是某个方向的闭塞被拉成 **757 m**。

* **修法**：朝向按"第几处灯"**严格交替**（`ordinal`）。源轴 = x 的东段两种算法结果一致。
* **实测**：修后每方向闭塞 365..557 m（最长 757 → **557**）；`mmtr-total-sections` 110 → **121 组**。
