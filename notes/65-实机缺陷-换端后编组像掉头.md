# 65 - 实机缺陷：换到另一端往前开，整个编组像掉头（镜像车列方向没跟着走）

> 用户实机反馈（2026-09-09）："从 A 端开出去之后，刹车下车进另一端，切到 RF，往前开，会导致车类似掉头
> 一样完全反过来，相对在后面挂着的货车跑前面去了。"
> 结论：**用户描述准确，是引擎的镜像方向没跟着走**。一处修复 + 3 个用例。

## 根因

编组体车的"车列摆放方向"由 `Vehicle.reversed` 决定（`getVehicleCarsAndPositions`：`reversed=false`
时第 1 节车摆在 `railProgress` 端、逐节向后铺；`true` 时从 `railProgress - 总长` 逐节向前铺）。
它必须与**镜像腿的方向**一致——而镜像腿（`mmtrMotionLegs`）是**每个行驶 tick** 重建的：

```java
if (integratedDistance > 0) { … if (mmtrMotionWalker instanceof MmtrConsistWalker) refreshMmtrMotionLegs(); }
```

但 `reversed` 只在 `syncMmtrConsistMirror()` 里刷新，而那条路只在 **换端指令 / 换向器 / 出场**时走：

| 路径 | 会刷新 `reversed`？ |
| --- | --- |
| `changeEndsMmtrMotion()`（换端指令） | ✅ |
| `applyMmtrTravelReversed()`（换向器） | ✅ |
| `engageMmtrMotionPosition()`（出场/编组） | ✅ |
| **`enterMmtrCab` / `enterMmtrCabAtCar`（走过去按 G）** | ❌ 只 `updateMmtrCabSyncFields()` |

于是"走过去进另一端"之后：镜像腿已按新方向重建，`reversed` 还是旧值 → 车列被铺在**错误的一端**
（第 1 节机车被摆到货车那一头），整列看起来像掉头，货车"跑到了前面"。

> 为什么现在才发现：notes/61 修好"端 2 没法开车"之前，端 2 根本开不动，这条路没人走到。

## 修复

`refreshMmtrMotionLegs()` 里一并重新推导车列方向 —— 它是唯一重建镜像腿的地方，方向一变就同步：

```java
if (mmtrMotionWalker instanceof final MmtrConsistWalker consistWalker) {
    reversed = consistWalker.mirrorReversed();
    mmtrMotionLegs.addAll(consistWalker.buildMirrorLegs());
}
```

`syncMmtrConsistMirror()` 里的同一行保留（换端/换向/出场时立即刷新，不用等下一个行驶 tick）。

## 用例（`MmtrConsistVehicleMotionTests`，2 节机辆探针：机车(带车钩) + 货车）

| 用例 | 断言 |
| --- | --- |
| `drivingFromTheOtherCabKeepsTheCarOrder` | **用户原场景**：A 端开出去→停稳→走到同节车另一端→**再往前开 2 tick**：车列顺序不变，且机车相对货车的位置向量不翻（容差 5 cm；车列铺错端会翻整整一节车长 2.2 m） |
| `changingToTheOtherCabDoesNotMoveOrReorderTheCars` | 换驾驶室本身零位移（I1）+ 顺序不变 |
| `pullingTheReverserDoesNotMoveOrReorderTheCars` | 拉换向器同样零位移 + 顺序不变 |

**反向验证**：把 `reversed = consistWalker.mirrorReversed();` 两处都注掉后，`drivingFromTheOtherCabKeepsTheCarOrder`
**失败**（第 189 行相对位置断言）；恢复后通过 —— 用例确实咬住这个 bug。
