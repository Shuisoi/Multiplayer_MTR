# 286 · 区间带"有些颜色不显示"：岔区里同向的带共面打架

> 用户实机反馈（2026-09-25）：**「有些颜色是透明的不显示」**，紧接着追问：**「是因为道岔干扰么？」**
> 结论：**是岔区，但不是道岔"位置/状态"在干扰** —— 是岔区那根轨上**同一行车方向的几条带叠在同一处**，
> 而它们被画成了**完全共面**的四边形。数据与修法如下。

---

## 1. 先回答"是不是道岔干扰"（实测，不是推断）

`sandbox/_band_probe/BandOverlayProbe.java`（只读打开真实存档）加了"叠带发生在哪类轨上"的判据 ——
**端点度 ≥ 3 = 岔区（咽喉）**，度 = 2 = 普通区间：

```
同向叠带（共面打架）：16 / 46 根轨上有，最多叠 2 层
岔区轨（端点度>=3）= 30 / 46；其中出现同向叠带的 = 16 / 16
（叠带轨里落在岔区的比例：100%）
```

- 用户的直觉**对了一半**：出问题的地方**100% 在岔区轨上**，普通区间一根都没有；
- 但不是"道岔位置在干扰显示"：道岔位置只影响**哪些区间存在**（它进的是引擎的区间重建签名），
  与"画出来的四边形谁盖住谁"没有关系。真正的机制见下。

## 2. 机制：同向 → 同侧 → 同位置 → 完全共面

区间带画在 `RenderLayer.getEntityCutout`（`MoreRenderLayers.getExterior`）那一层：**alpha-test、写深度**。
而"让开哪一侧"由**行车方向**定（`(-dz, dx)`，与网页 `bandOffsetDirection` 同一公式）：

- 相对的两个方向 ⇒ 让到两侧 ⇒ 横向范围 0.1..0.9 与 −0.9..−0.1，**根本不重叠**；
- **同一个方向**（岔区里一个咽喉常被同向的两条区间各覆盖一次）⇒ 让到**同一侧**、同一高度
  ⇒ 两个四边形**完全共面** ⇒ 深度测试谁赢按像素随机 ⇒ 现场就是"色带缺一块 / 透掉了 / 看着是透明"。

这也解释了为什么只在**岔区**看得见：那里一根轨上最多叠 5 条带（notes/283 的实测），
而同向的两条才有这个机会。

## 3. 修法：把被盖住的弧窗**剪掉**（后写的盖住先写的）

`render/MmtrSectionBands` 新增两个纯函数：

| 函数 | 作用 |
| --- | --- |
| `sideOf(rail, band)` | 这条带让到哪一侧：`sign(点积(弧增方向, 行车方向))` ⇒ ±1。**与渲染时算让开方向的判据同一个**（异侧横向就分开，只有同侧才可能共面） |
| `visibleWindows(arcFrom[], arcTo[], sides[])` | 从**后往前**：后面的先占位，前面的撞上占位就被剪（`subtract` 做区间减法）。返回"每条带实际要画的弧窗"：空 = 整条被盖住，多段 = 中间被切掉 |

剪完以后同一根轨上任意两段弧窗都不再相交（同侧已剪开、异侧本来就分开）⇒ **谁在上谁在下不再重要**，
也不需要靠"抬高几毫米"去躲深度冲突（那在远处根本不够）。口径与网页一致：**后写的盖住先写的**。

顺带一处同类隐患：三角形的抬升从 3 毫米（`IGui.SMALL_OFFSET`）改成 **10 毫米**（`TRIANGLE_Y_LIFT`）——
3 毫米在 50 米外就与深度精度同量级，白色箭头会和它下面的色带打架。

## 4. 取舍（写下来，免得以后当成 bug）

重叠段现在**只显示后写的那一种颜色**。网页那边是 SVG 半透明描边，重叠会**混色**（"叠色"，notes/158）；
而游戏里这一层是 alpha-test 不透明层，混不了色。要让"重叠"本身看得见，是另一件事
（例如给后写的那条加描边、或斜纹），**不要在深度上做文章** —— 共面打架只会变成闪烁。

### 5.1 一条被用例抓到的自摆乌龙

`theLastBandWinsNoMatterHowManyOverlap` 第一版的期望值我手算错了：三条同侧 `[0,20] / [2,18] / [5,12]`，
最外层被剪成的是 **[0,2] ∪ [18,20]**，不是 [0,5] ∪ [12,20] —— 因为中间那条**整段** [2,18] 都会挡住它，
**即使中间那条自己有一段被最后一条盖住**（那一段露出来的颜色属于最后一条，但不属于最外层）。
用例红了一次，值了。

## 6. 还没做

- 若实机发现"叠带处颜色跳来跳去"仍有残留，先量 `visibleWindows` 的输入（打印每条带的 arcFrom/arcTo 与 side），
  别再靠肉眼猜 —— 这一条已经吃过一次"按精确朝向分组把打架数成 0"的亏（见探针里的注释）。
- 岔区"一轨 5 条带"能不能看得更清楚（例如把同向的几条并排细分成更细的带），是**显示设计**问题，
  要用户先裁定，不在本轮。
