# 322 - 施工前还原点：世界备份与复原（`world-backup.ps1`）

> 用户口径（2026-09-26）：「下一站建在 4031, 71, 2312，**但是先想办法做备份复原**」，
> 并补充「车站走向为 ±X」。
>
> 本篇只记**备份/复原**这一半；建站那一半（含轨面 75→71 的坡度段）另起一篇。

---

## 1. 为什么非要有它：`/setblock … air` 清不干净

"指哪打哪"一次施工会**永久**改世界：几百条 `/fill`、几十条 `rail`、一堆 `setblock`。
出错时最贵的**不是重做，是清不干净**：

* `/setblock … air` **不触发** `BlockNode.onBreak2` ⇒ 方块没了、引擎里的轨还在（幽灵轨，铁律 6）；
* 反过来 `/fill … air replace` 连节点方块一起删掉、**引擎却不知道**（notes/304）；
* 引擎侧没有"按区域撤销"这回事，`rail remove` 只能一个节点一个节点敲。

所以规矩改成：**动手前先取还原点，出事就整目录回滚**。这比任何"手工清理脚本"都可靠。

## 2. 工具：`mmtr/scripts/world-backup.ps1`

```powershell
pwsh -File mmtr\scripts\world-backup.ps1                                    # 备份（默认）
pwsh -File mmtr\scripts\world-backup.ps1 -Label before-p2p-4031
pwsh -File mmtr\scripts\world-backup.ps1 -Action list
pwsh -File mmtr\scripts\world-backup.ps1 -Action verify -Label before-p2p-4031
pwsh -File mmtr\scripts\world-backup.ps1 -Action restore -Label before-p2p-4031
```

存放位置：`mmtr/game/fabric/run/world-backups/<时间戳>[-标签]/`，里面是
`world/`（整目录快照）+ `manifest.json`（逐文件 sha256 + 引擎状态）+ `engine-state.json`。

### 2.1 备份**不用停服**（实测）

```
save-off → save-all flush → 等 3 s 落盘 → robocopy → save-on
```

`save-off` 之后区块只在内存里，磁盘上的 region 文件是冻结的 —— 这是 Minecraft 的标准备份法。
一次 219.5 MB / 360 文件，**0.7 s** 复制完，不用停服。

### 2.2 ★ 必须排除 `session.lock`

第一次实现用 `Copy-Item -Recurse`，**当场失败**：

```
另一个程序已锁定文件的一部分，进程无法访问。 : '...\world\session.lock'
```

服务端进程一直持着它的句柄，**连读都不行**。它只是"这个世界正在被谁用"的标记文件，
服务端启动时会重建，不属于要备份的数据 ⇒ 换成 `robocopy /E /XF session.lock`。

### 2.3 复原**必须停服**，而且复原本身可回滚

进程持有 region 句柄，而且内存里的世界会覆盖回磁盘 ⇒ 先 `save-off` + `stop`，
**等到 loom 进程退出且端口关闭**（最多等 120 s，超时就中止、世界不动）。
然后：

1. 先把**当前**世界存成 `<时间戳>-pre-restore` 这一份还原点；
2. 再用目标快照覆盖 `world/`。

⇒ 复原错了还能再复原回去。**不留这一手的话，"复原"本身就成了不可逆操作。**

复原后脚本**不会替你起服务端**（避免与 IDEA 抢启动权）：自己跑
`pwsh -File mmtr\scripts\dev-server.ps1`，客户端要重进（区块已换）。

### 2.4 抄下**引擎权威状态**，复原后拿它对账

`manifest.json` 里除了文件哈希，还有备份瞬间的
`railCount / railHexes / lampCount / platforms`。

理由：**"方块回滚对了、引擎没回滚"是最难查的一种"看起来好了"**。有了这份对账，
复原后一条命令就能确认两边都回来了。

## 3. 实测闭环（不是"跑通了"，是"验过了"）

| 步骤 | 动作 | 判据 |
| --- | --- | --- |
| ① 取还原点 | `-Label baseline` | 360 文件 / 219.5 MB / 0.7 s；引擎 rail 116、灯 112、平台 8 |
| ② 校验 | `-Action verify` | 逐文件 sha256 一致 ✔ |
| ③ **故意破坏** | `setblock 3005 100 1905 diamond_block` + `rail add 3000 65 1900 → 3100 65 1900` | rail **117** 条；存档直读 = `minecraft:diamond_block` |
| ④ 复原 | `-Action restore -Label baseline` | 校验通过 → 停服 → 存 pre-restore → 覆盖 |
| ⑤ **验收** | 重启服务端后读数 | rail **116**（测试轨没了）；存档直读 = **`minecraft:air`**；灯 112；平台 8 |

第 ⑤ 步是**两层都对**的证据：引擎层的轨条数回去了，方块层的钻石块也没了
（`read_block.py` 直读存档，不听 RCON 的）。

## 4. 已接进工作流

`sandbox/gen_p2p.py` 现在**默认先取还原点**（`--no-backup` 可关）：

```
④ 取还原点（世界备份；出事就整目录回滚）
   还原点 20260926-190536-p2p-xxx
...
完成。核对：…
  · 回滚：pwsh -File mmtr\scripts\world-backup.ps1 -Action restore -Label 20260926-190536-p2p-xxx
```

备份失败就直接中止（不落任何方块）—— 宁可不干，也不留一个没法回滚的现场。

## 5. 坑与边界

| 现象 | 真因 | 处理 |
| --- | --- | --- |
| `session.lock` 锁死、复制失败 | 服务端进程持句柄 | 排除该文件（2.2） |
| manifest 里 `totalBytes` 是空的 | `[ordered]@{}` 上 `Measure-Object -Property bytes` 数不出来 | 改成 `[pscustomobject]` |
| 复原起不来/世界被覆盖回来 | 没停服就复制 | 脚本会等 loom 进程退出，超时中止 |
| 备份里没有 `session.lock` | 刻意排除 | 服务端启动时自建，无影响 |

**边界**：备份是**整目录**快照（219 MB / 0.7 s），不做增量、不做定时。够用是因为
本工作区的改动都是"一轮一批"，一轮一个还原点即可；真要省空间再考虑只存 region 文件。
