# 225 三角型斜边上的方形的凸起 —— 20%/30° 的楔形装不下读数，我加了底板，形状就破了

承接 notes/224。用户看出图后一句 **「三角型斜边怎么有个方形的凸起」**。

## 1. 形状为什么破了

上一版把背景画成 **楔形 ∪ 读数底板** 的并集。动机是正当的：30° 的浅斜边装不下当时
208×104 的横长条读数，白字会压在白底上被"切"掉（notes/224 的缺陷 B）。
补法是给读数垫一块矩形底板，并把并集算成一个多边形一次填充。

但**形状是用户的**：他要的是"直角在屏幕右下角、底边 20% 屏宽、斜边与底边 30°"的三角。
垫出来的底板在斜边上多了一段**水平台阶** —— 一眼就看出来了。

回头看，真正的问题是：**我为了迁就版式去改了形状**。正确的做法是反过来。

## 2. 改法：形状保持纯三角，读数按斜边约束自动定字号

- **画布 = 楔形自己的外接矩形**（宽 = 底边 171、高 = 底边 × tan30° = 99 @854 宽）。
- **背景只画那一个三角形**：`fillPolygon({0, W, W}, {0, 0, H})`，不再有并集、不再有底板。
- **读数从右下角往左上排**，字号由斜边反推（`digitInkHeight`）：

  ```
  约束只有一个 —— 数字块的左上角必须在斜边内侧：
      EDGE_PADDING + d + margin  ≤  (块左边界) × tan30°
  块左边界 = W − PAD − km/h宽 − GAP − 3×格宽，而格宽与 km/h 宽都正比于 d
  ⇒ 先线性反解初值，再用**真实宽度**迭代收敛（同限速牌那套 fittedInkHeight）
  ```
- **装不下的东西就不画**：854 宽窗口下 "AWS" 字样放不进去（行顶 66、行左 96，斜边在 y=66 处只到
  x=114），那就不画文字，只留灯 —— 灯本身就是用户要的"AWS 图标指示"。
  1280 宽（画布 256×148）时余量够，字样自动回来。

实测（离线探针打印的版面）：

```
屏宽  854：画布 171x 99  数字墨迹高 28.83  块左边 70.28 / 斜边在同高处 60.32（余 +9.96）  AWS 字样 不画
屏宽 1280：画布 256x148  数字墨迹高 36.00  块左边 132.94 / 斜边在同高处 72.75（余 +60.19） AWS 字样 画
屏宽  640：画布 150x 87  数字墨迹高 25.45  块左边 59.00 / 斜边在同高处 54.48（余 +4.52）  AWS 字样 不画
```

顺带：窄窗口下 20% 只有几十个单位（320 宽 → 64），连三个数字都放不下，所以给了底边下限
`MIN_WEDGE_LEG = 150`（只影响窄窗口；854 起走的仍是用户口径的 20%）。

## 3. 判据升级成"像素级形状检查"

这一轮把两次反馈都变成**在真实出图上数像素**的断言（`SpeedHudPaintProbe.checkShapeAndContent`）：

| 判据 | 含义 | 结果 |
| --- | --- | --- |
| 深色像素**出斜边 = 0** | 背景正好是那个三角形（多出去就是"方形的凸起"） | 854：0（最多超 0.00）、1280：0 |
| 亮色像素**出斜边 = 0** | 读数全在斜边里（多出去就是"数字被斜边切掉"） | 854：0、1280：0 |

分类方式很土但可靠：`alpha ≥ 40` 的像素里，RGB 之和 ≤ 120 算背景（`0xB8101418` = 17+19+24 = 60），
> 120 算内容（白字、红圈、白面、琥珀灯、灰蓝 km/h 都远高于它）。抗锯齿边允许超出 1.5 单位。

**踩到的坑**：`insideWedge(x, y, margin)` 的 margin 语义是"再往里收"（`y + margin ≤ x·tan30`），
所以验抗锯齿时得传**负**容差才表示"允许超出去一点"。第一版传了正的 1.5，于是三角形自己的
抗锯齿边被当成"出界 2650 像素"，而打印出来的最大超出量只有 0.36 —— 数字和判据矛盾时就该怀疑判据。

## 5. 这一版付的代价（如果用户不认，就改回去）

**底边 20% + 30° 在 854 宽下把数字字号压到 28.8（原 36），并且放不下 "AWS" 字样。**
两条路：

1. **保持现在的形状**（用户口径的 20%/30°，纯三角）⇒ 代价就是上面的字号与标签。
2. **保住 36 号字与 "AWS" 字样** ⇒ 楔形必须变大：读数左上角要在斜边里，底边得约 270 单位
   （≈ 854 屏宽的 32%）。改的是一处常量/规则，形状仍是纯三角。

这一轮选了 1，因为"形状是用户指定的"，而字号与标签是版式细节。
