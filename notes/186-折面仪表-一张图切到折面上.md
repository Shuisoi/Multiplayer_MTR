# 186 - 折面仪表：一张图切到折面上（atlas + 每面 UV）

## 起因

用户问："现在有些车辆的仪表是折面，我们可以显示吗"

## 结论

分两种情况，答案完全不同：

| 情况 | 现状 |
|---|---|
| **单折面**（一块倾斜的平面，如 SAF101 / HST_H 的 45° 上仰仪表面） | **早就能显示**。锚点自带 `normal/up/right` 三个轴，客户端用它们解欧拉角把 quad 贴上去，面是斜的完全不影响 |
| **真折面**（一个 `mmtr_hud*` 组里有多个不同角度的子面） | **原先不行**，本次实现 |

## 原先为什么不行

`pack_vehicle.js` 的 `buildAnchors()` 把**一整个 `mmtr_hud*` 组压成一个锚点**：

1. 中心 = 组内**所有**顶点的平均 → 折面的质心掉在折角外的空气里
2. 法线 / up / right 只取**面积最大的那个面**，但宽高用**全部顶点**在该坐标系上的投影 → 面板被撑成"包住整个折面"的大平板
3. 客户端只画**一个** quad、贴**整张**图

叠加 `MmtrPanelQuad.SURFACE_OFFSET_M = 0.03`，可见偏差 ≈ 非共面度 + 0.03 格。不是"不显示"，是"显示成一块错位的平板"。

副产品：若最大那块面法线接近水平（仪表顶面），客户端 `facingSide()` 水平分量≈0 →
判不出朝向 → **正反各画一遍**。

## 实测：仓库里原有 7 个 `mmtr_hud*` 全是单面

用新建的 `mmtr/tools/anchor-check/anchor_faces.js` 跑遍所有车辆 OBJ：

```
汇总: 7 个 mmtr_hud* 锚点，其中 0 个是折面
saf101 / SAF101v2  hud_1 hud_2   面=1  折角=0.00°  非共面度=0.0000
HST_H\hst_h        hud         面=1  折角=0.00°  非共面度=0.0000
其余 6 个（br101 / p1 / cargootest / HST_B …）无 hud 锚点
```

即"折面"要么是尚未导出的模型，要么指**可见仪表壳体是折面、而锚点只贴在其中一个子面上**。

## 方案对比

- **路线 1（零代码）**：拆成 `mmtr_hud_<cab>_1` / `_2` 两个锚点，各画**完整**一张图。
  适用"主屏 + 复示屏"这种**本来就是两块独立屏幕**的情况；**不适用真折面**（一张图跨折角切开）。
  命名正则 `^(hud|seat|cabdoor|ack)(?:_(\d+))?(?:_(\d+))?$` 和 `findHuds()` **本来就已经支持**多锚点。
- **路线 2（本次实现）**：一张图 + 每面 UV 子矩形，把折面**展开**成一张画布。
- 不用考虑：MTR 自带的 `display`/PIDS-on-model（`ModelDisplayPart` + 模型 UV）对 OBJ 车**不可用** ——
  `DynamicVehicleModel` 里 `nameToDisplayParts` **只在 Blockbench 构造函数里填**，OBJ 构造函数根本不建它。
  （且它的 display 元素也是每块贴整图 `0,0,1,1`，同样切不开。）

用户选定**路线 2**。

## 实现（路线 2）

### 数据流

```
Blender: mmtr_hud_1 是 N 个共边四边形的**一个 Object**
   ↓ 打包器 buildFacets()
锚点 JSON: 组级字段全部不变 + 新增 canvasWidthM / canvasHeightM / faces[]
   ↓ 客户端 MmtrVehicleAnchors.getFacets()
MmtrCabDashboard: 画布尺寸 = canvas W×H，layout.paint() 只画**一次**
   ↓ 逐 facet
MmtrPanelQuad.drawFacet(): 每面用自己的 frame + 自己的 UV 子矩形
```

### 展开算法（"沿折痕累积"）

关键几何事实：**折痕垂直于折叠轴**，所以一个 facet 沿折叠轴的局部坐标 `L(f,x) = dot(x - f.pos, axis_f)`
在整条折痕上是**常数**。于是两邻面在折痕处连续，只需让那个常数相等：

```
off_j = off_i + L_i(X) - L_j(X)      X = 折痕上任意一点（用共享边顶点平均）
```

以参考面（面积最大）为基准 off=0，沿**共享边**（= 共享的两个顶点索引）BFS 传播。
这就是"展开成平面后沿弧长量距离"，所以图像跨折痕连续且**在每个斜面上都不被压缩**。

- 共享轴（不变的那个）：`right` 或 `up`，取**一个**仿射函数 → 天然连续
- 折叠轴：上式累积
- 折角 > 89° / 链断掉 / 两轴同时转（扭曲面）→ **放弃 facet，退回原来的单 quad** 并 warn

### 两个实测踩到的坑

1. **组级法线在折面上是歪的。** 组级 `n` 用"三个顶点 × 组内全部顶点的平均"求得，
   折面上那个平均值不在参考面平面上 → 实测 45° 折面时法线偏离 **2.7°**。
   这对旧的单 quad 无害，但会让"所有 facet 是否共享一个轴"的 0.999 判据**假失败**。
   → facet 数学一律用**参考面自己**的 frame。
2. **v 轴要翻转。** 画布第 0 行是**图像顶部**，客户端把 texture v=0 放在 quad 的 +up 边；
   而 `L` 沿各面自己的 `up` 增长。不翻 → 仪表**上下颠倒**。
   → 发出 `v0 = (foldMax - sMax)/foldSpan`（顶边）、`v1 = (foldMax - sMin)/foldSpan`（底边）。

### JSON 形态

```json
{"name":"hud_1","kind":"hud","cab":1,
 "x":0.0707,"y":0.90403,"z":0,                       // 全部老字段语义不变
 "normal":[...],"up":[...],"right":[...],
 "widthM":3.0067,"heightM":0.7121,                   // 仍是"投影"尺寸（= 旧 quad 的尺寸）
 "canvasWidthM":3,"canvasHeightM":0.8,               // 展开后的画布（0.5 + 0.3）
 "faces":[
   {"x":0,"y":0.75,"z":0,"normal":[-1,0,0],"up":[0,1,0],"right":[0,0,1],
    "widthM":3,"heightM":0.5,"u0":0,"v0":0.375,"u1":1,"v1":1},
   {"x":0.10605,"y":1.10605,"z":0,"normal":[-0.707107,0.707107,0],"up":[0.707107,0.707107,0],"right":[0,0,1],
    "widthM":3,"heightM":0.3,"u0":0,"v0":0,"u1":1,"v1":0.375}]}
```

单面模型**完全不写** `faces`/`canvas*` → 客户端走原路径，**老资源包不用重打**。

## 验证（离线，三层）

1. **合成 fixture** `mmtr/tools/anchor-check/fixture/foldfix.obj`
   —— 竖直下折面 + 45° 上折面共一条折痕，加车身盒子和座位点。
   实测输出与手算**逐位一致**：`fold=45.0deg about right canvas=3.000 x 0.800m`，
   两面的 v 在 **0.375** 处精确相接，而老字段 `heightM=0.7121 = 0.5 + 0.3·cos45`。
2. **`verify_facets.js`** —— 从源 OBJ 与锚点 JSON 重新推导，八项判据：
   G1 面数一致 / G2 顶点在 facet 平面上且在矩形内 / G3 矩形面积=面面积 / G4 法线与绕序一致 /
   **G5 UV 连续性**（共享顶点从两个 facet 算出的 uv 必须相同 —— 这是展开的全部意义，也是截图**测不出来**的东西）/
   G6 各面铺满画布且沿折叠轴无缝无叠 / G7 图像朝向（v=0 必须落在面板**顶边**）/ G8 单面锚点不得带 facet 数据。
3. **`selftest.js`** —— 往刚生成的数据里注入 6 种故障（v 不翻转 / uv 错位 / 面离平面 / 面缩小 /
   删掉 facets / 删掉 canvas 尺寸），断言 `verify_facets.js` **全部抓到且理由正确**。
   → `PASS: verify_facets.js caught all 6 injected faults`
   （不这么做的后果：验证器把猜测洗成"已验证"。第 6 个最初是"崩了"而非"报告了"，
   已修成显式失败。）

## 建模侧约定（补充）

- **仪表是折面 → 把 N 个四边形放进同一个 `mmtr_hud_<cab>` Object**，共边即可（顶点要**焊接**，
  折痕 = 共享的顶点索引；没焊接就"没有折痕"，会退回单 quad 并 warn）。
- **每个面必须是四边形**（非四边形只在日志里 warn：客户端画的矩形盖不住它）。
- **折角 ≤ 89°**；接近 90°（折成 L 形）请改用路线 1 当两块独立屏。
- 想让**两块屏各显示完整仪表** → 用 `mmtr_hud_<cab>_1` / `_2` 两个独立 Object（路线 1）。
