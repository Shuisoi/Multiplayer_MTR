# 48 - 实机缺陷二则：门开不了 / 开车必须手持钥匙

> 用户实机反馈（8 编组 HST 正常显示之后）：① 门不开；② 手里不拿钥匙就开不动车。
> 两处都是引擎/客户端上报语义的缺陷，与资源包无关。

## ① 门开不了

**现象**：网页指令 `doors <id> open` 返回 `[doors] ... 开门`（执行成功），但 `mmtr-motion` 的
`doorsOpen` 始终 `false`，客户端门也不动。

**根因**：`Vehicle.simulateMmtrMotion()` 每 tick **无条件**关门：

```java
vehicleExtraData.closeDoors();     // 本意：MTR 的"动车即关门"安全规则
```

于是船员的开门命令在**下一个 tick 就被回滚**——站着不动的车也永远开不了门。

**修复**：只在真正移动时自动关门。

```java
if (speed != 0) {
    vehicleExtraData.closeDoors();
}
```

停稳时门保持开/关状态；"从停点发车"和"新控制到达"本来就有显式关门，语义不受影响。

**回归**：`MmtrConsistMultiCarPlacementTests.aStandingMotionTrainKeepsTheCrewsDoorsOpen`
（`mmtrSetDoors("open")` → `simulate` 20 次 → 门仍为开）。

## ② 开车必须手持钥匙

**现象**：用 F 键进了驾驶室、仪表也亮，但手里不拿司机钥匙推油门没反应。

**根因链**（三层）：

| 层 | 事实 |
| --- | --- |
| 引擎占用锁 | `MmtrDriveAccess.canControl(senderIsRidingDriver, ...)`：**只承认"坐在司机席"的乘客**，否则直接丢弃控制 |
| 引擎判定 | `Vehicle.hasMmtrDriverRiding(uuid)` 读 riding entity 的 `isDriver` |
| 客户端上报 | `VehicleRidingMovement.tick()`：`isHoldingDriverKey = driverKey != null`——**"司机"被等同于"手持钥匙"** |

而 F 键进驾驶室走的是 MMTR 权限缝（`MmtrCabPermissions.canBoard/canDrive`，默认全开），**不设置**这个标志
→ 引擎认为"你不是司机" → 油门指令被丢。钥匙在手里时走的是 MTR 老路径，所以只有那种情况能开。

**修复**（客户端上报语义）：坐在 MMTR 驾驶室（`mmtrCabLocked`）且权限允许驾驶时，同样上报
`isDriver = true`：

```java
final boolean mmtrCabDriver = mmtrCabLocked && ridingVehicleId != 0 && MmtrCabPermissions.canDrive(permissionPlayer, ridingVehicleId);
final boolean isHoldingDriverKeyNew = driverKey != null || mmtrCabDriver;
```

钥匙仍然有效（原路径保留）；引擎侧规则**未改**——它依旧只信 `isDriver`，只是现在这个标志的语义
从"手持钥匙"变成"坐在司机席"。
