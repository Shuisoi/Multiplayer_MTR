# 132 - 链不许沿"走不到的腿"接：灯的黄/红要对准这条进路真正的前方

> 触发：用户 2026-09-14 追 `-152,-60,-122` 那盏单黄，并纠正 notes/131 之后我的解释：
> 「不对，这个区间向上在 -170,-60,-222 和 -176,-60,-222 就结束了」。
> 前置：notes/130（浅岔口有了物理模型）、notes/131（走不到的腿不再把整段判断路）。

## 1. 用户指出的到底是什么

`signal why -152 -60 -122` 当时的输出自相矛盾：

```
②[1] 本灯区间 id=-152,-60,-122  段数=13  长=290 m  占用=否  出口灯=-172,-60,-122
      结束原因：停在面向本区间的灯 -164,-60,-122 …
      本段起点节点=（未知）  结束节点=-162,-60,-122  下一段=-172,-60,-122
②[2] 第 2 段 id=-172,-60,-122  43 m  占用=**是**（车 -1344699863109040279 停在 (-169.5,-108)）
③ 深度 2 → SINGLE_YELLOW
```

区间 **13 段 span 确实止于 `(-170,-60,-222)` 与 `(-176,-60,-222)`**（用户说得对），
可它的**出口灯/结束节点**却是往北那一支走出来的（`-164,-60,-122`、`-162,-60,-122`）——
链于是接到了 100 m 外**另一条线**上那段 43 m 的股道，那上面停着车 ⇒ 显示单黄。

**为什么那支会被走**：`-170,-60,-161` 现在在**位置 1（岔股开放）**，它的正线远端那一侧是**切断的**；
但区间（用户 2026-09-10 的"一盏灯守整个咽喉"）在每个岔口沿**每一条腿**都走，
于是它仍然折上了那条走不到的腿，并把那条腿的入口灯当成了自己的出口灯。

## 2. 两层问题

| 层 | 症状 | 状态 |
| --- | --- | --- |
| span 覆盖 | 走不到的腿被收进区间 → 它撞禁行侧把整盏灯判红 | notes/131 已修（只守、不判断路） |
| **出口灯/链** | 走不到的腿的**入口灯**仍被收成出口灯 → 链接到别的线上，黄/双黄对准了走不到的地方 | **本笔记修掉** |

顺带说明链本身是按 `exitSignalKeys` 里的**全部**出口灯接的（`rebuild`，注释写得很清楚：
"岔口每个分叉各一架，全部都要接上"，notes/107 的 depot 咽喉就是这么来的）——所以问题不在"只接了一架"，
而在**那几架里混进了走不到的腿的入口灯**。另外 `endNodeKey` / `endReason` 是"最后走到的分支获胜"，
在岔口上本来就是多值的，这次一并按"只有走得到的腿才写"处理。

## 3. 修法

`walk()` 里已经有 notes/131 加的 `reachableRoute`（这条分支是不是这次运行走得出去的），
再加一个 `reachable = reachableRoute && reachableLeg`，用它把三件事挡住：

- **出口灯**（`addExitLamp`）：走不到的腿的入口灯不收 —— 链只沿这条进路真正能开的腿接；
- **结束原因**：同理，不许覆盖真正的出口那支写下的原因；
- **结束节点**（`endNodeKey`）：只有走得到的腿才写。

**span 照旧收全部腿**（保住"一盏灯守整个咽喉"：岔股上可能停着扳岔之前就进来的车）。
老式无模型咽喉完全不受影响：那里 `allowedNextHex == null` ⇒ 每条腿 `reachable` 都是 true
（实测那批用例全绿）。

顺带记一条写测试时才踩清的约定：**灯面方向 = 它守的走行方向**（`guardedHeadings`）。
所以"某条腿的入口灯"要**朝着腿的远端**（不加 180°），而"本区间的起始灯"是**朝着节点**的
（区间从它那里往节点方向走）。

## 4. 验收

- 新增用例 `anUnreachableLegDoesNotContributeAnExitLamp`：位置 0（岔股禁行）时，
  区间收**走得到**那条腿（正线侧）的入口灯，**不收**走不到的岔股那条腿的入口灯。
- 全量引擎：**591 通过 / 0 失败 / 4 跳过**。
- 现场（部署后）：`(-152,-60,-122)` **单黄 → 绿**，链变成
  `(-152,-122) → (-168,-222) → (-168,-253) → (-167,-289) → (-168,-306)`，深度 0 ⇒ 绿；
  全图逐灯比对（`logs/2026-09/lamp-aspects-before-chainfix-154451.txt`）：**只有 2 盏变了**，
  都是"黄 → 绿"：

  ```
  -174,-222 : DOUBLE_YELLOW → GREEN
  -152,-122 : SINGLE_YELLOW → GREEN
  ```

  其余 70 盏不动（16 盏红仍旧是那几段停着车的股道，抽查 `占用=**是**`，是对的）。

## 5. 还留着的一条保守项（未改）

区间的 **span 仍覆盖走不到的腿**，而占用判定是"本段任意 span 有车"（`isOccupied`）——
所以"某列车在道岔扳动之前就进了岔股、之后一直停在那条走不到的腿上"仍会让这盏灯显示红。
这是**保守**方向（宁可红），而且需要"车先进岔股、再把道岔扳走"这种少见次序才会出现，
所以本次不动；要在意的话，下一步可以把占用判定也收紧到"走得到的 span"。
