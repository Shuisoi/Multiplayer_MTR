## 1. 用户说了什么

> "继续对 BR101 的车辆模型进行细节上的处理，首先铁轨轨距在游戏中和咱们使用的真车口径不同，
> 游戏内轨距为 3 格方块"

我先做了**测量**（没有直接改），把两边都量出来摆在用户面前：

| 参照物 | 实测（格） | 出处 |
|---|---|---|
| MTR 默认轨距（两钢轨**中心线**间距） | **1.5625** | `models/rail/rail.obj`：轨头竖面 x=±0.7175、**轨腰中心 x=±0.75** |
| MTR 默认转向架 `bogie_1` 轮心距 | **1.5625** | `models/vehicle/bogie_1.bbmodel`：轮心 x=±12.5 px ÷ 16 = ±0.78125 |
| BR101 模型现状（真车 1435 mm × 1.6949） | **2.4321** | 老锚 |

因为"3 格"与我量到的 1.5625 差近一倍，我**问了用户口径**（量的是中心距/外缘/轮缘总宽），
并问了改动范围。用户选了"**两条钢轨中心线间距**"+"**整车等比缩放**"。

> 随后用户更正：**"数错了，的确是 1.5"**。

**结论**：目标轨距 **1.5 格**，与 MTR 自带车的 1.5625 只差 **4.0%**。
反过来说明老锚（真实 1435 mm = 2.4321 格）确实偏宽 56% —— 这次是往 MTR 口径上**收**。

> ★ 如果我没先量、直接按"3 格"做，整车会从 5 格宽放大到 6.17 格宽、39.9 格长，
> 而用户实际要的是**缩小**。两个方向完全相反。

## 2. 换锚是什么

```
老锚：车体外宽 2,950 mm  ->  5.0 格      SCALE = 1.694915 格/m
新锚：轨距     1,435 mm  ->  1.5 格      SCALE = 1.045296 格/m
统一比例 F = 1.045296 / 1.694915 = 0.6167247
```

**整车每个「格」值一律 × 0.6167247**。实测逐项对照（车宽 / LüP / 车高 / 轮距 / 销位 /
门 / 风挡 / 壳厚 / 倒角 / 驾驶室 / 缓冲器…）**比值全部 = 0.6167，无一例外**。

| 量 | 老锚 | 新锚 |
|---|---|---|
| 车宽 | 5.0 | **3.083624** |
| LüP 整车长 | 32.372881 | **19.965157** |
| 车高 Y1 | 7.220339 | **4.452962** |
| **轮距** | 2.4321 | **1.500000** |
| 车轮半径 | 1.0593 | **0.653310** |
| 销位 / 轴位 | 9.2797 / 2.2458 | **5.722997 / 1.385017** |
| 倒角 | 0.5（8 体素） | **0.308362** |
| 壳厚 / 门开口深 | 0.10 / 0.20 | **0.061672 / 0.123345** |

## 3. 两条**不能照抄**的例外

### 3.1 `EDGE_CHAMFER` 也必须 × F（一开始我把它当"游戏体素栅格"留成 0.5）

正脸【纯平段】半宽 = `HALF_W − EDGE_CHAMFER`。凹龛（1.9）与风挡（1.9188）都卡在它以内；
用户当年就因为"凹龛没有包在倒角内"退过一次（台账 §5.10）。

若倒角留 0.5：新锚正脸纯平段只剩 `1.5418 − 0.5 = 1.0418`，比风挡（1.1833）和凹龛（1.1718）
都窄 → 两个开口一起啃进 45° 倒角带；凹龛刀体侧面还会与"正脸/倒角"那条棱**近相切**，
布尔造零面积面（老锚上为此实测到 **6 条非流形 + 4 条边界**）。

取 **0.308362** 后，风挡唇边 0.0501、凹龛唇边 0.0617 —— 与已定稿模型**逐点相似**。

### 3.2 `GLASS_MARGIN` **不 × F**，保持绝对 0.002

它本来就是"留一点点防共面"的**数值容差**而不是尺寸。按 F 缩到 0.0012 后，
"玻璃到车体最小距离"从 0.010 掉到 **0.000968**，逼近 `r29` 的 1e-3 验收门限。

## 5. ★★★ 两个一直存在、这次才量出来的**真 bug**

### 5.1 `mmtr_cabdoor` 的"翻绕序"分支是**空操作**

`r33` 原文：

```python
nf = [tuple(reversed(f)) for f in chk_f]     # 把所有面都翻了
nf = [nf[0]] + nf[1:]                        # 再把第 0 个放到最前 —— 净效果 = 什么都没改
```

而且同文件的 `face_normal` 公式也是错的：
`(b - c).cross(cc - c)`，其中 `c` 是顶点**中心** —— 那不是面法线，只是"从中心指向某条边"
的方向。老锚上门叶够厚（0.10 vs 半宽 0.684）才碰巧能用。

两处都改成标准公式（`(v1−v0)×(v2−v0)`）+ **只翻第一个面**，并如实记录
`first_face_is_outer`（原来写死 `True`）。

### 5.2 ★★ 车轮被放在**端面**位置 —— 实际轨距 1.6463（目标 1.5，差 9.8%）

`r34` 原文：

```python
cx = sx * (HALF_GAUGE + WHEEL_T / 2)      # 把【端面】怼到了轨距线上
cyl_x(cx, WHEEL_R, az, WHEEL_R, WHEEL_T / 2, 28)
```

轮心因此在 **±0.8232**（= 0.75 + 0.0732），**轮子整体往车外偏了一个轮厚**。

**为什么一直"绿"**：自检写的是

```python
R["gauge_from_wheel"] = round(2 * HALF_GAUGE, 6)
R["gauge_err"] = round(abs(2 * HALF_GAUGE - GAUGE_BLOCKS), 9)   # ≡ 0，恒真
```

—— **拿输入当输出自证**。无论轮子摆在哪，`gauge_err` 永远是 0。

**修法**：`cx = sx * HALF_GAUGE`（轮心落在钢轨中心线上）；
判据移到独立脚本 `sandbox/r56_verify_gauge.py`：

```
轮圈识别 = 到某根轴心的圆半径 = 轮半径（几何身份，不用 |x| 阈值）
轮心 x   = 该轮【两个端面】x 的中点
轨距     = 右轮心 − 左轮心

实测：轮心 −0.750000 / +0.750000  →  轨距 = 1.500000000（误差 0）
      轮底 y = 0.000000000        轮心高误差 1.5e-8        轮外沿 0.823171 < 1.541812 ✓
```

> **通用教训**：自检里凡是 `期望值 = 某个常量` 的，先问一句
> **"这个常量本身就是被验证的输入吗"**。是的话这条检查恒真，等于没有。
> 同理，`r34` 里那句注释"判据不能取 x 极值就完事"我也写进去了。

## 6. 全链顺序（`sandbox/r56_build.py`）

**顺序 = 依赖顺序，不是编号顺序**。真实依赖三条：

1. `r29`（玻璃）必须在 `r18`/`r19`（掏窗）**之后** —— 玻璃是嵌进洞口的；
   顺序错 → `side` 窗射线全部 `first=body`（我第一版就把 r29 放早了）。
2. `r30`（仪表台）必须在 `r29` 之后 —— 它要朝风挡打射线验"玻璃挡在车体前面"，
   但它只**读** `interior_glass`，不创建。
3. `r37`（HUD）必须在 `r33` 之后、在 `r35`（材质）**之前** —— 它从 `interior` 里挑仪表板面，
   而材质要给 `mmtr_hud_*` 分配贴图。

> 顺序错的那两轮，下游 6~7 个步骤全红，而真正的原因只有一个。
> 这也是写驱动脚本（而不是手敲十几条命令）的理由。
