# 54 - C4b 解挂切分：只认接缝

> 设计 §5.4：解挂只在接缝处切；切分后两段各自停稳、各自占用、各自车底条目；挂车侧保留原空管状态。
> 不变量 U6「切分只认接缝」是本片的核心。

## 接缝从哪来

`vehicleCar.json` 新增 **`mmtrCouplerAfter`**（默认 false）：连挂手术在**接缝那节车厢**上置真
（即两车对接处），随车列持久化。于是：

- EMU 8 节内部无接缝 → 不可切（对应用户口径"这 8 节无需动态连挂"）；
- 机车单车无接缝 → 不可切；
- 机车 + 挂车车列连挂后，**恰好一个接缝** → 只能在那儿切。

## 切分手术（`MmtrCoupleSurgery.uncouple`）

| 项 | 做法 |
| --- | --- |
| 闸门 | 车辆存在、Motion 模式、**停稳**（U5）、`0 ≤ 接缝 < 节数-1`、该处确有车钩（U6）、切点在轨内 |
| 前段 | 车列 `0..k`，新的末节清掉车钩标记；**沿用原 id 与位置**（客户端镜像连续） |
| 后段 | 车列 `k+1..n-1`，新车 id；`MmtrMotionWalker.startAtOffset` 放在同一轨、同一方向、`cutOffset = 头端里程 − 前段长度` 处；登记到同一股道 |
| 乘员 | 按车厢归属分两侧，后段车厢序号重编号 |
| 空管 | 按 `encodeAirStates` 的逐单元串在接缝处切开，两段各自 `applyAirStateString` |
| 拒绝 | 非接缝 / 越界 / 未停稳 / 跨轨切分（待 C5） |

## 车场规则的修正

原来 `Siding.simulateVehicles` 的"一股道最多一辆停放车"会把解挂产物当重复车剔除。改成
**同一轨同一位置才剔除**（`Vehicle.mmtrRailSpan()` 比区间）：首尾相接的两段是合法车场状态
——这正是解挂的产物；几何未知的 legacy 车仍按老规则。有调车授权时两者都保留（连挂窗口）。

## 回归与证据

`MmtrCoupleSurgeryTests` 增至 **6 例**（+3）：

1. `uncouplingCutsTheFormationAtTheSeam`：连挂 3 节后在接缝 1 切分 → 前段 2 节（不位移、沿用原 id）
   + 后段 1 节机车（同轨、位于前段之后、新车 id）；末节车钩标记清除；两段 60 tick 后都存活；
2. `cuttingAnywhereElseIsRefused`：非接缝（0）→"没有车钩"；越界（2）→"至少一节"；从未连挂的固定编组 →"没有车钩"；
3. `theCrewStaysWithItsOwnCar`：司机在合并车里是 car 2 → 切分后回到后段（机车）car 0。

- 引擎全量 **416/0/2**（413 → +3，零新增失败）；引擎 jar 已重建同步；`:fabric:compileJava` 通过。

## 实机用法

```
couple <机车id> <挂车id>        # 连挂
uncouple <合并车id> <接缝序号>   # 例如 3 节车列在 1 号接缝切分（前 2 节 + 后 1 节）
```
