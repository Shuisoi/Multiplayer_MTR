## 1. 用户的问题：任务只有"半条命"

全库搜下来的事实（不是印象）：

| 环节 | 有没有 |
| --- | --- |
| 把这一步挂到车上（`dispatchTask` → `MmtrMission.attachTask`） | ✅ |
| 任务数据被使用 | ✅ 三处：**进路类型**（T4 ③）、**冲突裁决优先级**（`Vehicle.mmtrPlannedMillis`）、**认领去重**（`isVehicleRunningTask`） |
| 真的让车动起来 | ✅ 动车子系统自臂：目标 → 轨 → 规划 → 申请道岔 → 上电自动 → **开到目标停住** |
| 任务完成 | ✅ 靠观察推进（动了→DISPATCHED、停稳到点→AT_TARGET、停够→COMPLETE） |
| **按任务类型执行动作** | ❌ **没有**。`task.kind()` 在计划包之外只被用来判"是不是站台目标"（`Simulator.dispatchTask`） |
| **换端能不能派出去** | ❌ **派不出去**：`ChangeEndsTask` 按设计没有目标（`targetRef=0`），而 `dispatchTask` 遇到 0 直接 `return false` |

也就是说：**"一站一站开会"是通的；"到终点换端"既派不出去、也没人执行。** 这两条合起来就是
"交路一到终点就停住"——现场那台自臂后又停下的车正是撞在这上面（它到了目标、任务却推进不下去）。

对照物：**作业单那条路是有执行者的**（`MmtrJobScheduler.completeChangeEndsStep` →
`vehicle.changeEndsMmtrMotion()`），计划层缺的正是这一小段。

## 2. 修法（三处，各自带红证）

1. **原地动作也能派**：`MmtrTask.inPlace()`（默认 false）+ `ChangeEndsTask.inPlace() = true`，
   派发判据由"有目标"改成 `dispatchable() = targetRef != 0 || inPlace()`。
   连带把"原地动作的目的轨"记下来（`MmtrMission.setInPlaceTargetRailHex`：**车此刻所在的那根轨**），
   于是任务生命周期照常走（已派 → 到点 → 完成），而真正动手的是执行器。
   *红证：把 `dispatchable()` 改回 `targetRef != 0` ⇒ 两条新用例红。*
2. **执行器**：`Vehicle.mmtrRunInPlaceTaskAction()` —— 任务到点、车**停稳**之后，按类型动手：
   `CHANGE_ENDS` → `changeEndsMmtrMotion()`（与作业单同一条原语：翻司机台、丢掉为旧方向算的进路/道岔申请，
   让任务从新的一端重新自臂）。一次任务只动手一次（`mmtrTaskActionDone` 闩，换任务时清）。
3. **"当前版本"的另一半**：换代交接原来只按任务 id 比对。现在**目的地（目标类型 + id + 任务种类）变了就不交接** ——
   收回重派，不让车继续开向新计划已经不要的地方；**时刻变了不算**（车已在路上，"过去不可改"）。
   *红证：把目标比对短路 ⇒ 这条用例红。*

现场读数（部署后）：交路 C1 的 78 步里终点三步现在是 `STATION_SERVICE → CHANGE_ENDS → DRIVE_TO_SIDING`，
四个换端步骤（`L1/C1/020` @00:14:44、`039` @00:23:28、`058` @00:32:44、`077` @00:41:28）都在清单里；
服务端无异常。

**还没验的（如实记）**：换端**真的翻过去**那一下没有现场证据 —— 要看到它，车得先能跑到终点，
而现在车还出不了库（下一条）。这条只能在联锁修好之后补现场读数。

## 3. 还挡在"车能跑"前面的那件事（下一轮的活）

现场仍然是：一台车自臂后挪 14 m 停住、其余五台在库里等；引擎原话：

```
道岔位置给不了（物理层/净空闸）：point -170,-60,-186 wantLeg=0 needPos=0 
  ｜lock=false holder=- queue=… phys=<另一台车> 现位=1
```

即"一台**停着不动**的车按着某处道岔的位置，另一台要互斥位置的车永远等不到"。本轮已经加了
"等太久/停太久就让位"（两条路都加了、有测试与红证、已部署，现场日志能看到 26 条让位），
但**没能解开这次的具体僵局**：让位之后那台车又自臂、又把位置拿回去（20 秒的窗口对它俩不够）。

下一步的候选（按代价排序）：
1. **让位的判据别只看时间**：停着不动 + 自己这一轮没有再往前挪过（位置/里程没变）才是真僵局；
   让位窗口里连"重新自臂"都不做，改成"等对方真的动了再申请"（对方动一次就够）。
2. **环路检测**：请求集是原子的，但物理位置跨 tick 存活 ⇒ 环可以从"我按着 A 等 B、你按着 B 等 A"形成。
   在权限层做一次环检测（谁在等我、我在等谁），环上按计划时刻最晚的那台先退（T5 的优先级已经在了）。
3. **计划层少抢**：出库那一步提前 5 分钟派出去、且一次把整条进路的道岔都申请下来 ⇒ 库里六台车
   同时握着咽喉的不同道岔。把"申请窗口"收紧到"眼前这一处岔"，或让出库按次序排队（一次只放一台进咽喉）。
