# 75 - C10 调车进路增强（二）：调车授权覆盖整条进路

> 实机（2026-09-09 19:18）：987654 车场给 L1 的机车排了 `[MOVE_TO L2, COUPLE]` 作业单。进路规划成功、机车也
> 开出了 L1，但在**中途**被占用树拦住：`[MMTR-SIG] motion resting at occupancy block … (rail ahead occupied, waiting)`。
> 原因是任务授的调车授权只覆盖"起始轨 + 目标轨"，而这条进路要路过别的停放车占用的轨。

## 语义

调车授权（副显示）在真实规则里授的是一**段**进路，不是两个端点：`SUBSIDIARY_SHUNT` 允许列车驶过危险信号进入
被占用的区段，沿途可能连着好几个被占用的轨。所以授权对象应该是"这次移动的整条进路"。

## 实现

| 件 | 内容 |
| --- | --- |
| `MmtrRunPlanner.Plan` | 新增 `routeRailHexes`：本次进路经过的**全部轨**（当前轨在最前），三种规划器（前进 / 尽头换向 / 牵出—推进）都填充 |
| `MmtrShuntAuthority` | 新增 `routeRailHexes` 集合；`covers(railHex)` = 起始轨 ∪ 目标轨 ∪ 进路轨；`getRouteRailHexes()` 供地图/控制台显示 |
| `MmtrShuntAuthorityRegistry` | 新增 `grantRoute(vehicleId, grantRail, targetRail, routeRails, kind, speed, validity)`（旧 `grant` 语义不变） |
| `MmtrMission` | 新增 `needsShuntAuthority` 标记：调度器在创建 MANEUVER mission 时打标（目标股道有车或下一步是 COUPLE） |
| `Vehicle.mmtrMotionSelfArmMission` | 规划成功且 mission 带该标记时，按 `plan.routeRailHexes` 授**整条进路**的授权（15 分钟），然后才 arm 进路 |

日志：`[MMTR-MSG] 调车进路授权覆盖 6 条轨（<目标轨> 为目标）`（进路不变时不重复打印）。

## 用例

`MmtrShuntAuthorityTests.aRouteWideAuthorityCoversEveryRailOfTheMovement`：
起始轨/中间轨/目标轨都 covered，进路外的轨不 covered，`allowsCoexistence` 对中间轨同样成立。

## 实机验证

- **aassdd 回归**：`调车进路授权覆盖 6 条轨` → 作业单 `loco` DONE（step 2/2），3 节编组挂上；
- **987654 L1→L2**（当初被中途占用拦住的场景）：`MOVE_TO` 步骤**这次走通了**（机车从 L1 开到 L2 停稳），
  失败点变成了 `COUPLE refused: 两列车必须同向（A↔B 对接）` —— 这是我摆位的语义错误（两列车同向本来就挂不上），
  不是进路问题。
