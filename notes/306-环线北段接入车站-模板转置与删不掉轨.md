# 306 · 环线北段接一座车站（东西向）—— 模板转置 + 发现"删不掉轨"

> 用户口径（2026-09-26）：**「在这里接上一个车站」**。
> 选择：站位 **A 西端 x=-500..-280**；站台轨限速 **80（与样板站一致）**。

## 1. 结构性难点：`gen_station.py` 是**南北向**的，这条线是**东西向**

既有模板（`sandbox/gen_station.py`，notes/296–300）整套几何写死在
「**横断面 = x、纵向 = z**」上：站台在 `x=C±5..C±12`、方块 `facing=east|west`、轨沿 z 跑。

而环线北段沿 **X** 跑，两轨在 `z=1800 / z=1806`。
好消息：**现有两轨正好就是 `z=1803±3`** —— 模板的 `C±3` 天然对上，中心线取 `C=1803` 即可。

### 1.1 做法：给生成器加 `--axis x`（**不 fork**）

在 `gen_station.py` 里加一层**输出时的坐标对调**：

```python
_FACING_ROTATE = {"east": "south", "south": "west", "west": "north", "north": "east"}

def _swap_command(line):     # fill / setblock / rail add 三条命令都拆开、把 x 与 z 对调
    ...
```

- `axis="z"`（默认）**根本不调用它** ⇒ 既有南北向站的产物**逐字不变**（已回归确认）。
- `axis="x"` 时：局部「横断面 +x」映射到世界「+z」，所以 `facing=east` → `facing=south`、
  `facing=west` → `facing=north`（**90° 旋转，四个方向都要转**，别只转用得到的两个）。
- 同时新增 `Station.world_box()` 让 `--check-terrain` 用世界坐标取包围盒。

调用：

```powershell
python sandbox/gen_station.py --center-x 1803 --z-from -500 --length 220 --speed 80 --axis x --prefix station_ring_nw --check-terrain
```

（`axis=x` 时 `--center-x` 是**世界 z**，`--z-from` 是**世界 x 起点**。）

## 2. ★ 发现：**mod 里没有删轨命令，`/setblock` 也删不掉轨**

原计划是把车站段改成 `--platform`，为此想把 `-300..-200` 那段**切开**成 `-300..-280` + `-280..-200`
（因为站台只到 `x=-280`）。于是先查怎么删轨：

| 查了什么 | 结果 |
| --- | --- |
| 命令面 | `rail` 命名空间**只有 `add` 和 `list`**，没有 remove |
| `MmtrCommandExecutor` / mmtr 游戏端类 | 只有 `MmtrSignalSync`（信号），**没有任何 rail 删除/同步通路** |
| `BlockNode.onBreak2` | 参数带 `PlayerEntity` ⇒ 是**玩家破坏方块**的钩子；`/setblock … air` 不触发 |
| **实测** | `setblock -300 65 1800 air` 前后 `rail list` **都是 74 条** —— **确实删不掉** |

### 2.1 结论与绕法

**删不掉，所以切不开。** 既有的 100 m 节点分段在车站段**保持原样**。
好在 `rail add` 的 hex **只由两个端点决定**（`hex = f(p1) + f(p2)`，与限速/类型无关），
所以「同一对端点重推」= **引擎原地替换**，可以**改类型而不删轨**（notes/304 已证）。

据此把车站段重推成：

```
rail add -500 65 1800  -400 65 1800  --platform --speed=80     ← 站台轨
rail add -400 65 1800  -300 65 1800  --platform --speed=80     ← 站台轨
rail add -300 65 1800  -200 65 1800  --speed=160               ← 保持普通（且在站外 80 m）
（z=1806 同样三条）
```

**代价（如实记）**：站台轨是 **200 m**（`-500..-300`），车站最后 **20 m（`-300..-280`）压在普通 160 轨上**。
要修得先给 mod 加 `rail remove`（本轮**没做**，不是本轮范围）。

### 2.2 顺带一个必须记住的顺序结论

车站 fills 的第①步是 `fill -500 65 1791 -280 80 1815 air replace` ——
**y 范围含 y=65，正好把 `-500 / -400 / -300` 三处节点方块删掉**（这是设计使然，不是意外）。
所以流程必须是：**先 fills，再重推 rail**（`sandbox/station_ring_nw_relay.txt` 就是为此写的）。
这与 notes/304 的教训同源：**节点方块就在 y=65，`/fill` 不认识轨道。**
