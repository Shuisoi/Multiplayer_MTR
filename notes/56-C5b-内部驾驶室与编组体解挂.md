# 56 - C5b 内部驾驶室 + 编组体解挂

> C5 之后编组体（双驾驶室模型）能连挂了，但 C4 的取舍还在：合并后机车驾驶室落在**车厢内部**，
> 两驾驶室模型表达不了，于是"连挂后无人持钥匙、船员要走到前车驾驶室重新插钥匙"。这一片把它修掉，
> 并让编组体也能解挂。

## 内部驾驶室 `cabAtArcM`

`MmtrCabState` 新增：

| 字段/方法 | 语义 |
| --- | --- |
| `cabArcM` | 驾驶室在编组内的里程（从 A 端量起）；**`NaN` = 具名端**（CAB_A=0 / CAB_B=车长），数值 = 内部驾驶室 |
| `insertKeyAtArc(arc, towardA, stopped, atCab, crew)` | 在内部里程插钥匙；方向仍由 facing（`activeCab()` 标签）决定 |
| `isInteriorCab()` | 钥匙是否在编组内部（供 HUD/运维显示） |
| `changeEnds` | 换端 = 走到另一端 → 清掉内部里程 |

**连挂后钥匙不再被拔**：手术把后车（机车）的钥匙按里程搬进合并编组——
`jointArc + 后车驾驶室里程`（`jointArc` 取合并编组体自身的接缝里程，不能用两段车长相加：
MTR 的长度约定在接缝处算上了车钩 padding）。于是司机连挂后**原地继续开**。
**解挂后**钥匙跟着含它驾驶室的那一半走（`cabArc ≥ seamArc` → 后段，里程减 seamArc）。

## 编组体解挂

`uncouple` 对编组体按**接缝里程**切分：前段 A 端不变、后段 A 端 = 接缝，两半各自 `place` 新走行器；
跨轨切分仍拒绝（前段/后段必须落在一条轨内）。

## 又挖出两个真 bug

| # | 现象 | 根因 |
| --- | --- | --- |
| 1 | 解挂后后段被车场当重复车剔除 | `Vehicle.mmtrRailSpan()` 用 `offsetM()` 推车体区间，而**无人**编组体的 `offsetM()` 恒为 0、`currentRail()` 返回 null → 区间未知 → 按老规则剔除。修法：新增 `MmtrConsistWalker.referenceRail()/referenceArcM()/referenceOffsetM()`（在岗=驾驶室朝向端，无人=**A 端**），占用/S1/区间判定全改用它 |
| 2 | 重建后的 VED 车长/默认位错 | `totalVehicleLength`/`defaultPosition` 是 **final** 派生字段，随 JSON 从原编组带过来；手术重建时补 `patchGeometry` 按新车列重算（否则车场规则、占用区间、`getIsOnRoute()` 全错） |

## 回归与证据

`MmtrConsistBodyCouplingTests` 增至 **2 例**（+1）：

1. 连挂后：**钥匙仍在**（crew key）、`isInteriorCab()`、里程 8.2 m（= 接缝）、朝向 A —— 司机不用走动就能开；
