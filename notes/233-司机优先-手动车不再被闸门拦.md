# 233 · 司机优先：手动车不再被闸门拦（闯信号 = 紧急制动、可按响应键解除）

日期：2026-09-21 · 规则裁定人：用户 · 视图：手动开车（自动/无人那条支一字未改）

用户口径（本轮）：

> 「主要是针对手动开车这件事情，**只要司机能上车，那么什么都也阻挡不了他开车**。」
> 「过信号闯区间等问题，**触发紧急制动**就行了，紧急制动也是**可按响应键解除**的，这才是正常逻辑，
> 而不是给车直接速度归 0。**只有在道岔没设置对会发生脱轨时才直接按到 0**。」
> 「（AWS）保留 SPAD，只把确认键补回客户端。」「（道岔）跟随道岔当前物理位置。」

这一条**推翻了 notes/217 §4 的取舍**（当时明确记着"手动司机不能越过闭塞停车 …要改成'手动可以冲进占用区间'
是一个规则决定（危险），本轮没动"）。现在这个决定做了。

---

## 1. 修前的实际行为（为什么"司机上车了也开不动"）

`Vehicle.simulateMmtrMotion` 的分支顺序里，**闸门全排在司机控制之前**：

```java
if (mmtrProtection) { … 紧急 … }
else if (mmtrBlockedWaiting) { speed = 0; }   // ← 闭塞/许可/岔区：**无条件**把速度钉成 0
else if (autoBraking) { … 任务制动包线 … }
else if (autoActive && !airBrakeConsist) { … 自动巡航 … }
else if ((overridden || autoActive) && …) { … 司机控制 … }   // ← 司机在这一支
```

此外还有三处**同样"按了没反应"**的旁路：

| # | 位置 | 现象 |
| --- | --- | --- |
| 1 | 停车点**夹紧**（`brakeTargetM` 那段）对手动司机也生效 | 车头被截在停车点上，再怎么推手柄都过不去（判据永远差一点点） |
| 2 | AWS 报警 2.5 s 未确认 → SPAD 紧急制动（`tickMmtrAwsWarning`） | 而客户端**根本没有确认键**（notes/185 删旧驾驶键位时一起删了，报文里 `acknowledge` 恒为 false）⇒ 过了任何非绿灯信号就必然被刹停、且无从解除 |
| 3 | 岔口没有人工位/授权/目标时 `MmtrForkElection.elect` 返回 null | 手动车停在岔前等一个"没人会来设"的岔位 |

## 2. 现在的行为（规则落地）

### 2.1 未授权界限 = 紧急制动，不是速度归 0

`Vehicle.mmtrTickDriverAuthorityTrip()`：手动车进入**紧急制动包线**（按紧急减速度算，即"车已经停不住"的那一刻）
才动手，施加 `mmtrProtection` —— 车是被**刹车停住**的，不是被钉住的；界限前最后那一小段仍由既有夹紧收口
（否则 1 s 积分步会把车带到界限之外，实测冲过 1.5 m）。

- **解除**：司机按**响应键 R**（`ControlState.acknowledge`）⇒ 释放紧急制动，并把**这一处**界限记为已放行
  （`mmtrAuthorityReleased`）：此后同一处不再触发、也不再夹紧 —— 司机可以照他的意思开过去（闯区间）。
- **不自动解锁**：`mmtrAuthorityTripped` 为真时跳过"10 s 自动解锁"（那是 AWS SPAD 的既有行为）。
  真车 SCR 的口径：司机不按键就一直施加着。少了这一条，按住油门等 10 秒就能无视红灯开过去。
- **自动解除**（不需要按键）：① 界限本身消失（区间空了 / 灯绿了 / 岔设好了）；② 授权到手（调车授权 / 副显示放行）。
- **停着不动不算越界**：在红灯前规规矩矩停住的司机不会看到"闯信号"，也不吃紧急制动。
- **HUD 必须说清**：`mmtrMotionHoldReason()` 对该状态返回
  「紧急制动（越界/闯灯）—— 按响应键 R 解除」（自动车仍是「紧急保护（超速/闯灯）」）。

### 2.2 被授权的接近照旧（连挂要靠它）

`driverAuthorisedApproach = overridden && getMmtrShuntAuthority() != null`：有调车授权时**保留**原来的
服务包线 + 夹紧 —— 那条界限就是**车钩间隙**，连挂必须在那里停稳（`MmtrAutoCoupler` / `MmtrCoupleSurgery`
的判据）。这一支一个字没改（15 条连挂/调车用例在改到一半时红过，正是少了这条区分）。

### 2.3 道岔：手动跟随物理位置（唯一还硬停 0 的地方）

`MmtrForkElection.elect(..., boolean manualDrive)`：前四条（人工位 → 授权 → 任务目标 → 唯一续行）都选不出腿时，
手动车**读道岔当前开通的那条腿**（`turnout.continuationFrom(viaHex, position)`）；没有物理道岔模型的节点
（度 4 交叉 / 三岔口）走最直的一条腿。**绝不替司机扳岔**（扳岔仍是联锁/操作员的事）。

物理位置不允许他要走的那条（会脱轨，例如从岔股往正线远端而道岔在位置 0）⇒ 仍然返回 null ⇒ 走行器拒绝推进
⇒ `speed = 0`（唯一保留的硬停）。这正是用户口径里的那一条例外。

### 2.4 无人编组的司机：先给编组一个"头"

`Vehicle.mmtrAdoptUnmannedConsistForDriver()`：司机在**无人编组**上动车时补一把引擎占位钥匙（CAB_A）。
修前编组体走行器的一切都挂在"哪个驾驶室被占用"上（`currentRail()`/`railHex()`/`advance()` 都要求有人持钥匙），
无人时车**在物理上一动不动**，且全链路没有任何解释。方向不会因此改变：无人时 `travelsToward(B)` 与
CAB_A 在岗时同为 false ⇒ `towardB = !travelReversed` 两边一致。

### 2.5 AWS 确认键补回客户端（用户选的第二项）

- `KeyBindings.MMTR_AWS_ACK` = **R**（`key.mmtr.aws.ack`，en_us 已补名）。
- `MmtrDriveInput` 读上升沿 → **立刻单独发一包** `acknowledge = true`（不参与"只在变化时发"），
  其余时刻恒为 false（`notes/94` 的坑：常亮就等于每拍都在确认）。
- `MmtrDriverHud.notifyAwsWarning`：报警出现时往动作栏播一句「AWS 报警：按响应键 R 确认（约 2.5 秒内，
  否则紧急制动）」—— "有键"不等于"人知道要按"。
- 引擎侧 `applyMmtrControl` 的 acknowledge 现在**同时**干两件事：报警确认（既有）+ 解除紧急制动（新）。

### 2.6 顺手修的两个真缺陷

| 缺陷 | 现象 | 修法 |
| --- | --- | --- |
| AWS 窗口**按 tick 无条件累加**，只靠 `liveManual` 拦 SPAD | 在红灯前停过一会儿再起步 ⇒ **起步第一拍**直接 SPAD（累加值早就超窗）。与这段代码自己的文档"停在安全的地方不再计时"相反 | 只在 `liveManual`（真的在动）时累加 |
| `mmtrCurrentRailLimitPerMs()` 在"没有当前轨"时返回 0，被自动巡航当成"限速 0" | 无人/未插钥匙的编组体：`cruiseCap = 0` ⇒ 永远不加速 | 本轮只记录（见 §遗留）；手动那一支已由 2.4 的补钥匙绕开 |
| `isMmtrRequestingPower()` / 仪表功率只看 `throttleNotch` | 三手柄车底**恒发 0** ⇒ 起步闸门与仪表里永远"没要牵引" | 两处都加上 `driveHandle > 0`；`displayPower` 改用既有的 `mmtrLegacyPowerLevelFromControl` |

## 5. 遗留（明确记下来，免得下次当成新 bug）

1. **客户端每秒补发会顶开"到点闩"**：手柄停在牵引位时，到站 1 秒后车会自己起步
   （`applyMmtrControl` 每包都推进 `mmtrControlApplySeq`）。本轮**没改**（那是既有契约，
   多条用例依赖"再应用一次 = 再动一次手柄"）。要修得让序号只在**手柄值真的变了**时推进。
2. `mmtrCurrentRailLimitPerMs()` 的"没有当前轨 ⇒ 0"仍会被自动巡航读成"限速 0"
   （无人/未插钥匙的编组体）。手动那一支已绕开（补占位钥匙），自动那一支要单独决定"没有轨 ⇒ 不限速"的语义。
3. 手动车可以开进被占用的区间（撞上停着的车也不会停）—— 这是用户明确要的规则（"闯区间触发紧急制动就行"），
   不是缺陷；但它意味着**车厢穿模**在手动模式下是允许的。
4. `DevYardMotionE2ETests` 与两个 placement 用例依赖真实 dev 世界；世界的股道一旦变动它们就红
   （§4 的 3 个失败）。这类用例应改成按"世界里有这条股道吗"跳过，而不是断言它一定在。
