# 176 = 右侧动作按钮条：先做「解锁所有人工锁岔」

> 触发（2026-09-16，用户原话）：**「UI右侧设计按钮，先设计一个解锁所有人工锁岔吧」**
>
> 状态：**已实施、已在活页面上验过**（新组件 `MapActions.vue` + 新数据层 `api/command.ts` + 用例 3 条 +
> 探针 `map-actions-probe.mjs` **4/4**（真鼠标点击 + 回读引擎清零 + 复原锁））。
> **纯前端**：引擎已经有 `point unlock --all` 这条指令（`MmtrPointCommands`），所以不需要打 jar、不需要重启服务端。

## 1. 这一条为什么值得单独做

**人工锁是"界面上看不全"的状态**，这一点是实测出来的，不是推测：

```
$ curl -s -X POST http://127.0.0.1:8888/mtr/api/map/mmtr-command -d '{"command":"point locks"}'
人工锁 3 把（锁着的道岔不许自动扳，自动进路排队等 point unlock）
  -170,-60,-511  via FFFFFFFFFFFF…
  -170,-60,-511  via FFFFFFFFFFFF…
  -170,-60,-511  via FFFFFFFFFFFF…

$ curl -s http://127.0.0.1:8888/mtr/api/map/mmtr-points | …  # 56 行里 locked=true 的
locked=true 的行 = 1
```

**引擎手里 3 把锁、接口里只有 1 行报 `locked`。** 原因在引擎自己的注释里写着：人工扳一次岔
（`mmtrSetPoint`）会把那处道岔的**三条进向一起锁上**（用户 2026-09-14 的裁定："人工搬岔同时把道岔锁住，
永久生效直到解锁"），而 `/mmtr-points` 只列得出"够得上是一个岔口"的进向 —— 另外两条进向在界面上
**根本没有行**。于是：

- 现场症状（用户 2026-09-14 报过）：**网页上锁闭显示 0，重启后锁全回来**；
- 所以引擎专门留了 `point unlock --all`（按它自己持有的键全清），**界面就照它调**。

## 2. 界面这一侧做了什么

### 2.1 `layers/MapActions.vue`：右侧的按钮条

- 位置：**右侧竖排、垂直居中**（`right: 12px; top: 50%`）。右上角留给消息提示、左上角留给
  选中列车的任务卡片，所以动作条占右侧中段；地图的拖拽/缩放在它之外照常
  （浮层容器整体 `pointer-events: none`，按钮条自己 `auto`）。
- 样式：与节点菜单/任务卡片同一种"假玻璃"（深色实底 + 1px 发丝线 + 小圆角 + 同一种雾面渐变）。
- 它只放"按一下要对世界做一件事"的按钮，**不放读数**（读数在悬浮提示与卡片里）——
  用户要的是"按钮"。

### 2.2 按钮：解锁所有人工锁岔

点一下 → `POST /mtr/api/map/mmtr-command {"command":"point unlock --all"}` → **把引擎的 `lines[0]` 原样弹出来**：

```
已解锁全部人工锁：清掉 3 把（含界面上没有对应进向的那些）
```

为什么显示引擎原话而不是界面自己拼一句：同一件事两边各写一遍说法，迟早会说岔（这个项目里
"显示与游戏不同源"被咬过多次，notes/79/114/167）。

### 2.3 **按钮一直可点**，不按 `locked` 灰掉

看起来能做的优化（用 `mmtr-points` 里的 `locked` 决定灰不灰）**是错的**：那份数据只报得出 1/3 的锁
（见 §1）。按它灰掉，就会在"锁还在、界面上看不出来"的时候把**唯一的解药**关掉 ——
而那恰恰是这条指令存在的理由。N = 0 时引擎会如实说"清掉 0 把"，所以"白点一下"的代价只是提示条上一句话。

### 2.4 数据层放进了 `api/command.ts`（而不是 `api/topology.ts`）

- 指令通道是"按一下做一件事"的通用入口，以后每加一个按钮都走它（`runMmtrCommand`），
  每个动作就是一行包装（`unlockAllPoints`）。
- 单独一个文件还带来一件事：它**只依赖 `./client`**（不引 `@/…` 别名、不引领域模型），
  所以可以用假 fetch 直接测（`scripts/map-actions.test.ts`）—— 而 `api/topology.ts` 引了 `@/domain/*`
  与无扩展名的 `./client`，在 `node --test` 下根本加载不起来（实测 `ERR_MODULE_NOT_FOUND`）。
  指令字符串写歪一个词的坏法是**静默的**：引擎只会回一句 usage，界面却会把它当成成功提示。

## 4. 这一轮踩到的两件小事（都是"看起来能用、其实是错的"）

1. **不能把 `runMmtrCommand` 放在 `api/topology.ts` 里**：那个文件在 `node --test` 下加载不起来
   （`@/domain/*` 别名 + 无扩展名的相对导入），用例根本跑不到。所以数据层单开一个只依赖 `./client.ts`
   的小文件 —— **能被测到**这件事本身就是设计约束（见 §2.4）。
2. **`locked` 那份数据不能用来做按钮的使能条件**（见 §2.3）。顺带记一笔：这也意味着**节点卡片上的
   「已锁闭」只对"有行的那条进向"成立**，另外两条进向的锁在界面上是看不见的 ——
   如果以后要让用户"看见全部人工锁"，得让引擎把 `point locks` 的结果也发进某份 feed
   （本轮没做：那要动引擎 + 重新部署，而用户只要一个按钮）。
