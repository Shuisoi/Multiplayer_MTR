## 1. 先量，再定判据（不猜阈值）

那个巨块的成因在 notes/155 §15 已经查明方向：区间从一条走廊走到底，在尽头的 **U 弯**处
**跟着钢轨的物理连接转了过去**，于是沿对面走廊往回走，把对手方向的整条走廊收进了自己的区间。

问题是判据怎么定。所以我先把**真实世界量了一遍**：把每个区间的所有 span 采样点按走行顺序拼成折线，
逐点算"当前走向"相对**区间起点方向**的**带符号投影**（+1 = 一直朝前，−1 = 完全掉头）。

**为什么用带符号投影，而不是"最大转角"**：180° 的累计转角有两种完全不同的成因 ——
① 真掉头（U 弯）：一路拐过去，终点方向与起点相反；② **尖角/折返股道**：某一步方向突变 180°，
但走行并没有沿着反方向继续走。判据要抓的是 ①，只有带符号的投影能分开这两者。

量出来的分布（当时 101 个区间）：

| 带符号投影 | 区间数 | 说明 |
| --- | --- | --- |
| 从未低于 **+1.0** | **88** | 一直朝前 —— 正常区间 |
| **−1.0** | **9** | 一路掉到相反方向 —— **真掉头** |
| +0.15 | 2 | 尖角股道：拐得急，但**没有走回头** |

**中间是空的。** 所以"投影是否明显为负"就把 ① 和 ② 干净地分开了，**不需要调参**。

## 2. 判据（三条约束，缺一不可）

```java
final double walkForward = sectionHeadingX * spanHeadingX + sectionHeadingZ * spanHeadingZ;
if (walkForward < MMTR_REVERSAL_DOT && legs.size() <= 1) { ... 结束本区间 ... }
```

**① 为什么与"本区间基准方向"比，而不是与"当前走向"比**：
U 弯不是一步转过来的 —— 它由好几根缓弯轨拼成，每一步相对**当前**走向都只是小转角（点积仍为正）。
只有每一步都拿来跟**区间出发时的方向**比，掉头才显形。（这也是批次 2 里 `directionOf` 取"第一段朝向"
的原因：区间内所有 span 必须同向。）

**② 为什么只对"唯一续段"生效**（`legs.size() <= 1`）：
岔口是**多腿**，那里的走向可以合法地拐回来（尖角/渡线/岔股），而用户 2026-09-10 的裁定是
"**一盏灯守整个咽喉**"—— 那几条腿的轨**必须留在本区间里**（岔股上可能停着扳岔之前就进来的车）。
实测把这层豁免去掉，`theBranchOfAShallowCrossoverIsGuardedWithoutTurningTheLampRed` 立刻红。
所以：节点只有一条可续轨时才是"沿线继续走"，这时才谈得上掉头；多腿一律照旧全走。

**③ 为什么门槛取一个"明显为负"的值（−0.5）而不是 0**：**直角转弯必须放行**。
判据是"续段在基准方向上的投影"，而直角转弯（岔线向南出、过节点后转上向东的主线）的投影
**正好是浮点意义上的 0**（探针实测 `4.4e-16`）。拿 0 当门槛会把这条正常行车判成掉头 ——
实测它让 `aNodeLampGuardsTheLegThatLeavesTheNodeItsOwnWay` 的区间长度从 150 m 缩回 50 m
（那条用例钉的正是"岔线走到节点后继续走主线"）。
−0.5 落在实测空档里（正常最低 +0.15，掉头 −1.0），两边都留足余量。

## 4. 测试（一条新用例，**红证过**）

`theWalkNeverTurnsBackDownTheLine`：夹具是一个"发夹" ——
南行段 `(0,0,0)→(0,0,100)`、10 m 连接段横过去、回程段 `(10,0,100)→(10,0,0)` **朝北**；
灯站在南行段北端朝南。判据：

| 断言 | 含义 |
| --- | --- |
| 段数 = **2** | 南行段 + 那 10 m 连接段（垂直，属正常行车） |
| 长度 ≈ **110 m** | 到此为止，不是 210 m |
| `endsAtDeadEnd` = true | 结束原因是"走到尽头（方向反了）"，不是撞上另一盏灯 |
| 回程段**不在**本区间里 | 逐段点名 |
| `sectionAt(南行段, 50, 朝南)` = 本区间；`sectionAt(回程段, 50, 朝北)` = null | 带方向地问，答案自洽 |

**红证**：把门槛改成永不触发（−2.0）⇒

```
MmtrDirectionalBlockServiceTests > theWalkNeverTurnsBackDownTheLine() FAILED
  ==> expected: <2> but was: <3>
```

也就是"回程段被吃进来了"—— 正是巨块的成因。
