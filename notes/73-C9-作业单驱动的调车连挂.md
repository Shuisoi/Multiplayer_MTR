# 73 - C9 作业单驱动的调车连挂（跨道走行 + 到达即挂）

> 用户需求（2026-09-09）："在两条道上生成两列列车，给其中一列设置连挂任务" —— 也就是让作业单自己把车开到另一条道，
> 把停在那里的车列挂上，不需要人开。

## 现状与缺口

引擎里跨道能力其实齐了：`MmtrRunPlanner.planToRail` 做轨道图搜索、算沿途道岔操作、含尽头换向；
`Vehicle.mmtrMotionSelfArmMission` 每 tick 自己规划并 arm（`setMmtrMotionAuto` + 停车距离）；
mission 的状态机也在跑。**卡住的是三处：**

1. `MmtrJobScheduler` 里还留着 Motion Core 重写时代的临时闸门
   `cross-track auto-move is offline (step … targets another siding …)` —— MOVE_TO 另一条道直接失败；
2. 进被占用的股道需要**活调车授权**（S1 许可 + 连挂闸门都查），当时只有人工/网页授；
3. COUPLE 只支持"首步 make-up"（两作业单的车辆清单在生成前合并），不支持"开到位再真连挂"。

## 实现

| 件 | 内容 |
| --- | --- |
| 放行跨道 | 删掉那条闸门；MOVE_TO 另一条道走既有 mission 路径（`MANEUVER` mission → 自 arm 跑过去）。到不了的进路由 mission 报原因，不再由调度器一刀切拒绝 |
| 任务即授权 | `grantShuntForStep`：目标股道有车（或下一步是 COUPLE）时，给该车授 15 分钟的 `SUBSIDIARY_SHUNT`（grant rail = 当前轨，target = 目标股道的图轨）。空股道不授，普通调车不受影响 |
| 到达判定 | 跨道进路的停车点是股道**远端**，实际停在车列前：`arrivedAtTargetConsist`（车钩间距 ≤ 0.75 m）与 `targetConsistAbsorbed`（自动车钩把对方并进来了）都算到达 → 结束 mission、清 auto 与停车点 |
| COUPLE 动作 | `executeCoupleAtStand`：停稳后对"目标作业单的车列"（`targetJobId`）或本道另一列车调 `MmtrCoupleSurgery.couple`；成功则把 `instance.vehicleId` 换成合并后存活那列、刷新 `fleetCars`、把目标作业单标 consumed。目标已被自动车钩吸收时按完成处理 |
| UNCOUPLE 动作 | `executeUncoupleAtStand`：不在自己车场股道时（跨道之后）用真手术就地切，而不是车场模板重建 |
| 任务实例化 | `MmtrTaskKind` 增 `COUPLE`/`UNCOUPLE`，新 `CoupleTask`/`UncoupleTask`，`MmtrTaskFactory` 不再返回 null（C6 遗留项） |
| mission 继承 | 连挂手术会**新建 Vehicle 对象**，运行期挂在其上的 mission（作业单正在执行的步骤、task、executor）会丢。手术现在把 mission 交给合并后的车，并且当合并体已经站在 mission 的目标轨上时直接判定到达（避免合并瞬间 walker 还没解析出轨道就自 arm 失败） |
| "已经在目标轨"语义 | `mmtrMotionSelfArmMission` 从"失败"改为"到达"：目标轨就是当前轨 = 这段移动已经完成。旧用例 `selfArmFailsMissionWhenTargetIsTheCurrentRail` 相应改成 `selfArmCompletesMissionWhenTargetIsTheCurrentRail` |

## 用例

`MmtrTaskDrivenCouplingTests`（两条股道 + 中间联络轨的小世界，机车停在一条道、2 节挂车停在另一条道）：

- `aJobDrivesAcrossTheYardAndCouplesTheStandingRake`：作业单 `[MOVE_TO 目标股道, COUPLE targetJobId=rake]`，
  机车自己开过去贴到挂车、自动车钩挂上（3 节），作业单两步走完 → DONE；
- `aJobCouplesAManualCouplerRakeBySurgery`：挂车声明人工车钩时不会自己挂，COUPLE 步骤执行真手术，同样 DONE。

`MmtrTaskFactoryTests.coupleAndUncoupleMapToTheirActionTasks`：COUPLE/UNCOUPLE 现在有任务实例。

## 验证

- 全量引擎套件 **439/0/2**（上一轮 437/0/2）；
- 实机布置：滚动清单把 aassdd 的两条道留给作业单（不再预置 HST8），`mmtr-jobs.json` 里
  `rake`（新长道 `-3054567530540565369`，2×p1，无步骤）+ `loco`（`-5385228036078397`，1×saf101，
  步骤 `[MOVE_TO 新长道, COUPLE rake]`）。开世界后机车应自己开到长道、贴住客车、自动挂上 3 节。

## 后续

- COUPLE 的 `targetJobId` 目前要求目标作业单已被调度器认识（它自己的 stock）；对"世界里本来就有的车列"用本道另一列车兜底。
- 进路被别的车占用/道岔被别人锁住时，mission 会等（日志 `motion mission … waiting for turnout authority`），调度器有 step 截止时间兜底。
