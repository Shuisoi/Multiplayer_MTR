## 1. 实测到底差在哪（r53~r59）

r50 当初为了满足"客户端每个折面画一个**矩形**"这条约束，把两翼**绕折痕转了 4.3°**，
从 85.7° 的平行四边形变成 90° 的刚性矩形 —— 台面（`interior`）没跟着改，于是翼板外缘比台面高：

| | 相邻边夹角 | 外缘 Y |
| --- | --- | --- |
| `interior` 台面四边形 | **85.696°**（流动） | 4.0900 / 4.5400 |
| `mmtr_hud_*` 翼板（r50 后） | **90.0°**（刚性） | 4.1877 / 4.6377（**高 97.7 mm**） |

四张台面四边形与六张仪表面一一对应；中屏那张**四角差 1.0 mm**（既有容差），两翼外缘差 **97.7 / 57.0 mm**
（正好等于 r50 报告里的 "+97/+57 mm"）。
`+0.0977 = 1.2987 × sin(4.3°)` —— 就是那 4.3° 的转动量。

## 4. 同一轮的第二件事：司机眼位抬高 4.75 → 5.12（并解开它的上限）

用户："把玩家视角提高一点 / 再高些"。**Blender 里的"玩家视角"就是 `SeatCam_1` / `SeatCam_2`**
（父级挂在 `mmtr_seat_1/2` 物体上，`SeatCam_1` 还是场景相机）。

关系（已实测确认，两端同一个数）：

```
合成地板 y = 1 + legacyRiderOffset
legacyRiderOffset = mmtr_seat 眼位 y − 1.62(MC 眼高) − 1
相机 y = 合成地板 + 1.62 ≡ mmtr_seat 眼位 y
```

- `br101_r61`：把眼位**网格**从 4.75 抬到 4.92 —— 注意锚点 `cabView` 上车时**丢弃座位 Y**（只取门坎），
  所以上车点不受影响，只有打包器算出的 offset 跟着变。
- `br101_r63/r64/r65`：把它换算成**移动物体**（`ob.location.y += d` 同时把顶点 −d 补偿回来），
  这样父级在物体上的**相机跟着走**；最后 `r65` 把网格也定到目标高度（打包器读的是网格世界坐标）。
  最终：**网格 5.12 / `SeatCam_1` 5.12 / `SeatCam_2` 5.12**。

### 上限在哪，怎么解开的

上车时的入场 Y 原本取**门坎+0.05 = 2.3203**，而 `VehicleRidingMovement` 的兜底判据是
`|合成地板 − 入场Y| ≤ 1 m` ⇒ **眼位最高只能到 4.94**。眼位 5.12 ⇒ 合成地板 3.50 ⇒ 差 1.18 m ⇒ **会被踢下车**。

修法（本轮已改、已过编译）：

| 位置 | 改动 |
| --- | --- |
| **打包器** | 锚点 JSON 新增顶层 `rider: {feetY: 1 + legacyRiderOffset}` |
| **`MmtrVehicleAnchors`** | 解析 `root.rider.feetY`（与 `hud` 同级），`riderFeetY(vehicleId)` 暴露；`clearCache()` 一并清 |
| **`MmtrCabInteraction`** | 上车 Y 优先用 `riderFeetY`，没有才退回门坎 —— **入场点正好落在合成地板上**，余量恢复完整的 1 m，眼位想多高都行 |

`check-java-compile` OK（432 文件）；打包器语法 OK。

**唯一待办**：`verify_facets` 的四边形路径我改到一半，卡在**自己引入的 bug**上 ——
"choose the best face" 那段把 undefined 传给了 `L.sub`（`TypeError: Cannot read properties of undefined`），
所以这条判据目前是**报错退出**而不是通过。**已经定位为 verifier 自己的问题，不是包的问题**：
`sandbox/hud_corner_diag.js` 独立证明**打包器写出的四角与模型那一面的顶点逐点吻合**
（误差 2e-5），且 `verify_panel_frame` 已经从另一侧验证了同一批数据。

修法（下一步，小改）：把"选面"改回**用四角点集与面顶点点集直接配对**（最大点距最小者），
不要在配对阶段投影 (a,b)；或者干脆回到按 index 配对、但先把 verifier 的
`group.faces` 按折痕链排序。修完跑绿即可收尾。

> 另一个结论：**`verify_facets` 之前那些"rectangle"报错里混着 index 错配**（重新导出后面序变了），
> 所以"判据报错"当时被我误读成"判据还假设矩形"。两件事都真实存在，现在分开处理了。


现在仪表面是**平行四边形**，而客户端/打包器仍然假设"折面 = 矩形"：

- 打包器把每个折面的 `widthM/heightM` 取成**面自身两个轴的包围盒**：
  平行四边形 → `1.295 × 0.5563`（`0.5563 = 0.4589 + 0.0974`，就是 r49 报的 0.556）；
- 客户端按 `widthM × heightM` 画矩形 → **比面板高 9.7 cm，会探出台面**（正是 r50 当初要解决的问题）；
- `canvasHeightM` 取的是折面在共用轴上的跨度（`sharedSpan`）→ 会变成 **0.5563** 而不是 0.4589，
  画布宽高比就错了，画面会被**纵向压扁 ~17%**。

所以需要（按依赖顺序）：

1. **打包器**：每个折面额外输出**自己的四个角**（在面内 `right/up` 坐标下的 `[[a,b]×4]`，顺序 BL/BR/TR/TL）；
   并把"共用轴跨度"改成由**真实的折痕边**决定（而不是所有角点投影的包围盒），
   使 `canvasHeightM = 折痕长 0.4589`、`widthM = 垂直于折痕的跨度 1.295`。
2. **客户端** `MmtrPanelQuad.drawFacet`：有 `corners` 就按四角画（UV 仍按既有的
   BL→(u0,v1) / BR→(u1,v1) / TR→(u1,v0) / TL→(u0,v0)），没有就退回矩形路径（兼容旧包）。
3. **判据**：`verify_facets.js` 的"矩形/面积"检查改成"四角与模型面四角一致"；
   `verify_panel_frame.js` 的 P5（展开比例）改用四角算边长。

**在 1~3 完成之前不要重打包 BR101**（否则翼板会探出台面 9.8 cm —— 比修改前更糟）。
