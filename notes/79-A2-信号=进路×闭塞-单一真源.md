### 显示规则（本片定案）

1. **闭塞链是底**：深度 1 = 被保护轨自身被占 → 红；2 = 行进方向后一轨被占 → 单黄；3 = 再后一轨 → 双黄；0 → 绿。
2. **进路 SET 收窄分岔**：被走行的轨上有 SET 的 **MAIN** 进路时，链只沿该进路的下一轨走（联锁已锁死一条径路），
   不再"每个分支都算" —— 这正是旧保守规则下"信号比它保护的进路还差"的问题。
3. **进路 PENDING 把起点信号压红**：某轨是某条未设好进路的**入口轨**时该轨显示红（车停在信号外等联锁），
   进路中段的轨不受影响。
4. **调车（SHUNT）进路不清主灯**：调车授权是副显示（主灯仍红，C3a），因此不收窄、不给绿。
5. **无进路 = 自由驾驶**：维持原闭塞链显示（红/黄/绿），行为与 A2 之前完全一致。

方向判定不新增字段：进路的 `railHexes` 是有序的，`routeNextRail` 用"下一轨是否与当前轨共用远端节点"判断该进路
是否就是本方向；不匹配则退回保守链。

## 3. 用例与验证（引擎）

`MmtrSignalAspectTests`（6 例，合成 4 轨网络 entry→fork→{straight→beyond | diverge}）：

- 占用链：被保护轨被占→红；后一轨→单黄；再后一轨→双黄；
- 无进路时占用分岔支→单黄（保守规则仍在）；
- **SET MAIN 进路收窄**：占用分岔支但进路走直向 → 绿；再占用进路上的轨 → 单黄（进路自身仍受保护）；
- **PENDING 进路** → 入口轨红（即使线路全空）；
- **SHUNT 进路** → 仍单黄（主灯不因调车放行）；
- 未知/空 hex 安全返回绿，`aspectsForAllRails` 每轨一条。

全量引擎套件 **460/0/2**（上一轮 454/0/2，+6 例，零新增失败）。
