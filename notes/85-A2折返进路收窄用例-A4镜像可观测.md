# 85 - A2 折返进路收窄用例 + A4 客户端镜像可观测

> 承接 notes/84（主动派车实机验收）。本片补两处收尾：一个真实场景的边界用例，一个运营可观测口。

## 1. A2 边界：进路把同一轨走了两次（折返 / 牵出—推进）

实机 aassdd 调车用的正是**牵出—推进**（notes/74/75），进路的轨序里会出现**同一条轨两次**
（去一程、回一程）。`MmtrSignalAspect.routeNextRail` 必须挑**与当前行进方向一致**的那一次出现，
否则信号会跟着列车**已经走过的**径路走。

用例 `MmtrSignalAspectTests.aRouteThatRunsOverARailTwiceNarrowsPerDirection`：

- 网络：`E(-20..0) → N(0) → S(0..60) → M(60) → {S2(60..120) | D(60 → 120,+20)}`；
- 进路：`E, S, S2, S, E`（S 出现两次），无道岔 → SET；
- 同时占用**分岔支 D** 与**回程目标 E**；
- 断言：无进路时 `aspectFrom(S, N)` = 单黄（保守看到 D）；有进路时 = **绿**
  （锁定径路是 S2，D 与 E 都不在径路上）。

结论：现实现按"下一轨是否接在本次行进方向的远端节点"逐次匹配，折返进路两个方向都能挑对，无需改动。

## 2. A4：把客户端镜像暴露到运营 feed

客户端镜像（`MmtrRouteRegistry.setMainRouteNextRails()` / `pendingEntryRails()` →
`PacketMmtrRoutes` → `MmtrClientRoutes` → `RenderSignalBase`）此前只存在于推送链路里，运营端看不到。
现在 `mmtr-trains` feed 顶层多一个 `routeMirror`：

```json
"routeMirror": { "nextRails": { "<railHex>": "<下一轨 hex>", … }, "pendingEntries": ["<未设进路入口轨>", …] }
```

这样实机目视时可以**对照**：feed 里 `nextRails` 说明引擎告诉客户端"这条轨之后只走哪条"，
`pendingEntries` 说明哪些轨的主灯被压红。

用例 `SystemMapRouteMirrorTests`（2 例）：SET 进路的锁定径路出现在 `nextRails`、
PENDING 进路入口出现在 `pendingEntries`；空闲网络两个视图都为空。
