## 3. 新 skill 的定位（**刻意与旧 skill 分工，不重复**）

| skill | 管什么 |
| --- | --- |
| `mmtr-track-building` | **约束与故障**：铁律、轨道几何公式、四层验证、症状谱系 |
| **`mmtr-line-construction`（新）** | **施工手册**：`用哪个生成器 → 什么顺序 → 敲什么命令` |

`SKILL.md` 内容：

1. 两份 skill 的分工 + 台账指针
2. **三条口径**（双线 z=1800/1806、节点每 100 m、断面与材料、限速、灯高公式）
3. **端到端七步**（勘察 → forceload+等生成 → 土方 → 路基 → 铺轨 → 信号 → 验收），
   并写清**为什么 ③ 必须在 ⑤ 之前**
4. **生成器清单**（10 个脚本 + 各自关键参数 + `axis`/`rail-y` 的坐标语义）
5. **三个现成配方**：从零铺一段 / 改既有线段 / 接一座车站
6. **改 mod 代码怎么部署**（引擎 shadowJar → 游戏 compileJava → 停 loom → sync → 拉起）
7. **验收清单**（L1/L1'/L1''/L2/L3/L4 + "RCON 掉线的 ✘ 不算结论"）
8. 坑的指针（细节回 `mmtr-track-building`）

`reference/cookbook.md`：**10 组复制即用的命令序列**，每组都注明当时跑出来的结果
（`14/14 被拒 0`、`112 → 88` 等），并收录了本次反复用到的验收 Python 片段
（全链找断口、存档直读、灯的绑定、锚定到本次查询的 `signal why`）。
