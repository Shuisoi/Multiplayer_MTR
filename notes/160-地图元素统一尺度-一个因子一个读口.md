# 160 = 地图元素统一尺度：一个因子，一个读口（含一处静默降级缺陷）

> 用户 2026-09-15 的要求：「这个是需要**所有**地图元素都有类似效果的，不是单单几个图标」，
> 以及此前的口径：「所谓的 8px 是缩放为 6x 的时候大小是 8px，这个应该跟随缩放变换大小，
> 你可以理解成是**摄像机在移动，地图大小和位置关系不动**」。

## 一、规格：只有一条规则

`domain/mapElements.ts#DECAL_KINDS` 是**唯一真源**，所有像素量都在表里，不许散回组件写死：

| 元素 | 规格（6× 下） | 备注 |
| --- | --- | --- |
| 图标（信号灯、道岔菱形） | 8 px | 用户规格 |
| 灯点 | 4 px | 必须小于图标，否则盖住方向箭头 |
| 区间端点圆点 | 5 px | 比图标小，免得盖住线心 |
| 节点圆点（半径） | 3.6 px | |
| 灯相对节点的横向偏移 | 10 px | 用户规格 |
| 道岔偏移 / 引线 | 16 / 16 px | 偏移是**算出来的下限**（菱形外接框半宽 + 灯命中半径 + 余量） |
| 区间线心 / 状态条 | 6 / 2 px | 用户规格；条距线心中心 ±2 / ±5 px |
| 轨道线 / 护套 / 命中区 | 4 / 7.2 / 12 px | 本轮新增到表里 |

换算只有一个函数：`mapScale(zoomRatio) = zoomRatio / REFERENCE_ZOOM`（`REFERENCE_ZOOM = 6`）。
元素屏幕尺寸 = 规格 × 该因子；**位置偏移也乘同一个因子**（否则缩放时元素会相对锚点滑走）。

## 二、本轮真正确认的缺陷：`inject` 被塞进 computed，静默降级成 1

五处（轨道层、区间层、节点、灯、道岔）原先都是这一行：

```ts
const zoomRatio = computed(() => inject(ZOOM_RATIO, undefined)?.value ?? 1);
```

看着无害，实际是**分时正确**的：

- `inject()` 靠「当前组件实例」找提供者，而组件实例**只在 `setup()` 期间**是确定的；
- 这些 `zoomRatio` 被 `v-bind` 的样式副作用在 **setup 之外**首次求值 ⇒ `inject` 找不到提供者
  ⇒ **静默**返回缺省 `1`；
- 同一个 computed 在**渲染时**求值又能拿到真值 —— 所以 JS 里量到的数是对的，
  只有**样式里的宽度永远停在全览倍率**。

实测（修复前，`data-zoom-ratio = 6.1528`）：

| 元素 | 修复前 | 应为 |
| --- | --- | --- |
| 轨道线 `stroke-width` | **0.667 px** | 4.10 px |
| 区间线心 | **1 px** | 6.15 px |
| 区间状态条 | **0.333 px** | 2.05 px |
| 灯图标 | 8.20 px（对） | 8.20 px |
| 道岔菱形 | 11.60 px（对） | 11.60 px |

也就是说：**图标在长、线不动** —— 这正是用户说的"脱层"观感的来源，而不是四个图标各自的问题。

### 为什么会「灯对、线不对」

灯与菱形的尺寸来自**模板表达式**（渲染期求值 ⇒ 拿得到真值）；
线与条来自 **`v-bind` 进 CSS**（样式副作用里求值 ⇒ 拿到缺省 1）。
同一个 bug，两条路径两种结果 —— 所以只看 JS 侧数值是查不出来的，**必须量样式**。

## 三、修法：读口只留一个，且必须在 setup 里调

`views/mapContext.ts` 重写为「两个读口 + 一个写口，注入键**模块私有**」：

- `provideMapContext(camera, zoomRatio)`：画布 `setup()` 里调一次；
- `useCamera()` / `useZoomRatio()`：**在 setup 里**调用，函数体内就是 `inject` + 拿不到就**抛错**
  （不再静默降级）；
- 注入键 `CAMERA` / `ZOOM_RATIO` **不再导出** ⇒ 「把 inject 塞进 computed」这种写法在类型上就写不出来。

五处调用点全部改成 `const zoomRatio = useZoomRatio();`（一行），
轨道层、区间层、节点、灯、道岔**不再各写一套**。

## 四、验收（无头 Edge + CDP，量真渲染值）

两条检查脚本，口径都是「**尺寸比 == 倍率比**」（不依赖倍率恰好落在某个值）：

- `sandbox/check-web-element-scaling.ps1`：一张图内 1× → 6.15×，量
  轨道线 / 节点点 / 灯图标 / 灯点 / 菱形（路线图）与 线心 / 状态条 / 端点圆点（区间图）；
  并验「基准倍率下灯图标 ≈ 8 px」「区间线心 / 状态条 = 3」（规格 6/2）。
- `sandbox/check-web-cross-view-scaling.ps1`：**分两轮装页面**（第①轮装载后立刻切区间图、
  第②轮留路线图），各自从 1× 推到 6.15×，最后**跨图对照**：
  6× 下「区间线心 / 轨道线 = 1.5」（规格 6/4）、「状态条 / 轨道线 = 0.5」（规格 2/4）——
  即两张图确实乘的是**同一个因子**。
  （跨图对照是必要的：区间图是异步取数据后挂载的，装载后再推近的话它一开始就已经在 6×，
  量不出「有没有跟着变」。）

结果：两条**全部通过**，各元素尺寸比与倍率比误差 ≤ 1.4%（节点点 0.9%、灯点 1.4%，
其余 0.0～0.4%）。另验：区间图下 `轨道/节点` 元素数 = `0/0`（两张图是切换，不是叠加）。

## 五、留下的口子（知情未做）

- `REFERENCE_ZOOM = 6` ⇒ 全览（1×）时图标只有 1.33 px。用户口径是「6× 时 8 px」，
  所以这是规格的直接推论；若希望全览也看得清，改这一个常量即可（全局一致）。
- 命中区口径**不统一，是有意的两套**：轨道线的可点区（`railHitWidth` 12 px）在 `DECAL_KINDS` 表里、
  跟着倍率缩（它只在"选灯改绑"时出现，那时人会先推近）；而节点圆点的 24 px 靶
  （`NodeMarker` 的 `.node::before`）是**固定屏幕像素**，因为缩到 1× 就完全点不中了。
  两处都写了理由；要改成一套的话，节点靶应当进表、并且明说"接受全览时点不中"。
