# 116 - T1：道岔物理唯一持有者 + 进路 SET 判据纳入物理位置

> 对应设计：`docs/01-设计/行车控制-任务联锁与行车许可-设计.md` §A-1 / §A-2 / §6（T1）。
> 前置：notes/115（一处道岔一个位置 —— **几何模型**）；本篇是它的**权限层**。
> 触发：用户 2026-09-14「开始 T1 吧」。

## 1. 这一片修的是什么

notes/115 把道岔的**几何**唯一化了（`MmtrTurnout`：一个位置、两根互斥进路），但**权限层没跟上**。
后果是两件事，实测都能触发：

1. **物理上互斥的两份许可可以同时成立。** `MmtrPointAuthority` 的键是 `(节点, 进向轨)`，
   两列车从不同进向申请同一处道岔 → 两个键 → **都 GRANTED**；
   `MmtrRouteRegistry.refresh` 判 SET 只看 `isGrantedTo(...)` → **两条互斥进路都报 SET**。
2. **位置由数组下标仲裁。** `Simulator.mmtrSyncTurnoutPositionToGrant` 按
   `{stem, far, branch}` 的固定顺序取第一个"有授权能翻译成位置"的进向 —— 于是**谁赢取决于
   数组下标**，而不是请求顺序、更不是计划。

走行侧的禁行闸门（notes/115 §3）把**安全**兜住了（车停在岔前，不会脱轨），所以症状不是碰撞，
而是**进路状态说谎 + 咽喉僵持**。

## 2. 交付

| 件 | 内容 |
| --- | --- |
| `MmtrPointAuthority.Result` | 新增 **`REJECTED`**：这个 (进向, 腿号) 要求的组合物理上不存在（背向穿过尖轨）。**不给许可、也不排队** —— 排队等于承认它将来可能成立 |
| `MmtrPointAuthority.TurnoutLookup` + `withTurnoutLookup` | 物理层的几何来源，由 `Simulator` 注入（`new MmtrPointAuthority(...).withTurnoutLookup(this::mmtrTurnout)`）。**不注入 = 整层不生效**，逐进向语义逐位不变（引擎单测里的合成 authority 就是这种，所以基线不受影响） |
| 节点级持有者/队列 | `physicalHolders`（`节点 → {owner, position}`）+ `physicalQueued`（互斥需求在**道岔上**排队，而不是各进向各排一队） |
| `request(...)` | 先走**原有**逐进向仲裁，再加一道物理闸门（见 §3 的顺序） |
| `passed / releaseAll` | 越岔或终态时让出位置并推进道岔队列；递补者**同一步**拿到逐进向授权（走行读的是那一份） |
| 查询 | `physicalPosition` / `physicalHolder` / `hasTurnout` / `turnoutDemand` / `physicalQueueSnapshot` |
| `Simulator` | `mmtrSyncTurnoutPositionToGrant` 与 `mmtrSyncTurnoutPositionsToGrants`：**物理持有者优先**，没有持有者才退回逐进向老路；`mmtrTurnoutPosition` 在持有者存在时**不被"行视图折进位置"改掉** |
| `MmtrRouteRegistry.refresh` | SET 追加第二个条件：**每个未越过的岔，其物理位置必须就是本条腿要的那一位**（先判物理互斥、再判授权，理由点名道岔+持有者+两位） |

## 3. 关键设计决定：顺序

**逐进向机器先跑，物理闸门只加一道，而且同一次调用内完成撤回。**

```
request(node, via, owner, leg)
  ├─ 不是道岔 → 原样走逐进向（与修前逐位一致）
  ├─ positionForLeg(via, leg) == MIN_VALUE → REJECTED（不进任何队列）
  ├─ 逐进向仲裁 → 非 GRANTED 就原样返回（**同一进向的 FIFO 语义一字未改**）
  └─ 逐进向 GRANTED 了，再加物理闸门：
       无持有者 或 持有者是我      → 我定位置
       持有者位置 == 我的需求      → 相容，放行（道岔不是我们之间的争用点）
       否则                        → **收回刚发出的逐进向授权**，改为在道岔上排队
```

为什么是这个顺序：
- 先跑逐进向 ⇒ "同一条进向上的两列车 FIFO"保持不变，这是既有测试与既有玩法的基础；
- **撤回必须在同一次调用内**（不能跨 tick）—— 半个持有正是 T1b 要根治的 hold-and-wait 的起点。

为什么"位置相容就放行"：两列车要的是**同一位**时，道岔不是它们之间的争用点；
它们之间真正的冲突是共用轨段/对向，那由闭塞（S1）与 T1b 的**敌对进路表**负责，不归道岔这一层。

## 4. 唯一一处期望值改动（不是措辞，是阻挡点换了）

`MmtrRouteConflictTests.conflictingRoutesQueueAtTheThroatAndTheSecondSetsAfterTheFirstClears`
（咽喉双车）改了口径。**原因不是打印格式变了，而是后车被挡在了更前面：**

- 夹具的闸口 `N=(-20,0,0)` 是一处**单开道岔**（`y1`/`throat` 是直股对、`y2` 是岔股）：
  train 1 走 `y1→throat` 要**位置 0**，train 2 走 `y2→throat` 要**位置 1**，两者物理互斥。
- **修前**：两列车各自拿"自己那一行"的授权，直到 `M=(0,0,0)` 的岔口才排队 —— 也就是说
  **两列车同时"持有"一处物理上不可能同时成立的道岔**。
- **修后**：物理层在 `N` 就把它们分开，后车停在**咽喉口**（还在自己的股道上）等。

所以断言从「点名 `holder=vN@leg`」改成「点名**前车**」+「点名道岔坐标」+「点名互斥的位置」
（`本车需要位置 1` / `岔股开放`）。判据本身没有放松 —— 该用例仍然断言
"互斥进路不能同时 SET、后车不 arm、前车越岔后后车自动 SET 并跑完"。

实测侧写（探针打印，已删）：train 1 先 `demand=0` 成为持有者 → train 2 `demand=1` 被 QUEUED
且位置**纹丝不动** → train 1 越岔 → train 2 接手、位置翻到 1。

## 6. 边界与未结

1. **"同位相容"不做仲裁** —— 同一位的两列车都由闭塞/敌对进路表（T1b）约束，本片不越界。
2. **递补者跨 tick 的一致性靠两道网兜住**：递补/`promote` 安装的逐进向授权没有再过一遍物理检查，
   但（a）走行侧的**禁行闸门**（notes/115）挡住物理上不该走的腿，（b）**进路 SET 的第二条件**
   会把位置不符的进路立刻降为 PENDING。下一 tick 的重申请会把状态彻底对齐。
3. **顺带发现、未修**：`releaseAll` 里的
   `queued.entrySet().removeIf(e -> e.getValue().removeIf(...))` 只要删掉一个元素就把**整个队列条目**
   丢掉，会连带丢掉别人的排队项（新写的物理队列没沿用这个写法）。因为每列车每 tick 都会重申请，
   现象会自愈，所以**没有在这次一并改**（保持 T1 的 diff 聚焦）。
4. **T1b 才是死锁的解**：本片只是让"一处道岔一个位置"在权限层成立；
   逐岔申请 + 部分持有（`requestForkOps` 失败不回滚）导致的 **hold-and-wait / 循环等待**
   仍要靠 T1b 的**咽喉原子获取 + 敌对进路表**根治。
5. **T3 才让信号真正控车**：本片之后，被物理挡死的进路会诚实地报 PENDING，
   但"车停在进路入口的信号外"这条停车规则属于 T3。
