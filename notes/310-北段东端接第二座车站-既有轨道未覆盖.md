# 310 · 北段东端"接"一座车站（x=800..1020）—— 既有轨道一条没动

> 用户口径（2026-09-26）：**「在这边轨道后面接一个车站，不要覆盖原有轨道」**。
> 「这边」= 刚铺完的 +X 段；「后面」= 东端 `x=800` 之外。
> 关键约束是**不要覆盖原有轨道** —— 这一条决定了做法。

## 1. 与上一个车站的**做法差异**（这是本次的重点）

| | 车站一（notes/306–307） | **车站二（本次）** |
| --- | --- | --- |
| 位置 | **骑在既有线上**（x=-500..-280） | **接在线的东端之后**（x=800..1020） |
| 站台轨 | **就地重铺**：把站内既有 100 m 分段改成 `--platform --speed=80`（改类型，hex 不变） | **新增** `rail add 800→1020`，与既有轨无关 |
| 既有轨道 | 站内那几段被改成了站台轨 | **一条都没动** |
| 为什么要拆/重铺 | 既有分段切不开，只能改类型 | 不需要 —— 站台轨是长在新位置上的 |

**实测对拍证明"没覆盖"**：

```
施工前:  (700,65,1800)→(800,65,1800)  普通  限速 160/160  长 100 m
施工后:  (700,65,1800)→(800,65,1800)  普通  限速 160/160  长 100 m   ← 逐字未变
         新增 (800,65,1800)→(1020,65,1800)  站台  限速 80/80  长 220 m
```

引擎条数 **86 → 88**（只多出 2 条站台轨，没有任何一条被替换或删除）。

## 4. ★ 一个必须知道的细节：清障会删掉接缝处的节点方块

站址 fills 第①步是 `fill 800 65 1791 … 80 1815 minecraft:air replace`，
**y 范围含 y=65 ⇒ 会删掉 `(800,65,1800)` 与 `(800,65,1806)` 两个节点方块**（既有 700→800 轨的东端节点）。

这不是事故，是**流程的一环**：紧接的第 3 步 `rail add 800 … 1020 …` 会把这两个节点**按同一朝向重新放回**
（hex 只由端点决定 ⇒ 既有 700→800 轨本身不受影响，只是它的端点方块被"重写"了一次，状态相同）。

所以顺序**必须是 fills → rails**，中途节点缺失是正常的。这与 notes/304/306 的教训同源。
