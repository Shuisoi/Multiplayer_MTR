## 1. 操作

```
POST /mtr/api/map/mmtr-dispatch?dimension=0
{ "vehicleId":"7115558568630424271", "kind":"MANEUVER",
  "targetSidingId":"1607594720369027237", "executor":"AUTOPILOT", "startNow":true }
→ ok:true（987654 车场一列停放车，目标同车场另一条股道）
```

随后每 3 秒采样 `mmtr-trains`（列车状态 + 该车进路覆盖轨的 `signals[]` 显示）。

## 3. 结论（真实存档、真实网络）

1. **进路对象在活体任务上成立**：派车即出现 `route{kind:MAIN,state:SET,rails:6}`，一路保持 SET
   （分段释放：越过的道岔不再要求持有）。
2. **信号显示 = 进路 × 闭塞 在真实网络上随车推进而变化**：车所在轨转 **红**，前方按闭塞链给
   **单黄/双黄**，车过后回 **绿**；两条红轨即线上另有停放车占用。
3. **S1 在真实网络上生效**：列车在 `[MMTR-SIG] motion stopped at occupancy block 112.17m (rail ahead occupied, waiting)`
   处停稳等待，mission 保持 DISPATCHED、进路保持 SET（联锁未释放，正是"停在信号外等闭塞"的形态）。
4. 服务端日志无新代码异常。

## 4. 遗留的世界状态（供用户处理）

- 那列车（`vehicleId=7115558568630424271`，987654 车场）现在停在网络轨上等闭塞，其进路为 SET。
  它等待的是被其他停放车占用的轨，若不去动它不会自行结束。

  以免误删你的车底。
