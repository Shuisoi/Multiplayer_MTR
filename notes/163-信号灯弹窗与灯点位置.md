# 163 = 信号灯：弹窗被倒过来 + 灯点位置不准（都是"旋转中心的坐标"算错）

> 用户 2026-09-15：「为什么向下的信号灯鼠标移上去**弹窗也是反的**……**信号灯位置也不准确**。
> 都是相同的坐标系不是吗」

两件事，两个不同的原因 —— 第二件我在排查中途**量错了一次**并把对的改错，也记在下面。

## 一、弹窗是反的：信息卡是**旋转元素的后代**

整盏灯当时是一个 `<div>` 带 `transform: rotate(...)`，信息卡是它的子元素 ⇒ 朝下的灯（180°）
把卡片里的字一起倒过来。

**修法**：拆成两层 —— 外面 `.signal` **只有位移**（不转），里面 `span.rot` 只装图形并承担旋转。
卡片挂在外层，于是永远正、永远在锚点右下方。

## 二、灯点位置不准：盒偏移写成了两个不同的量

`boxOffsetPx` 当时是"灯点在盒子里的位置"（`lampX/boxWidth × 宽`），
而它是**唯一**该写的那处偏移 —— 但我在中途把变换写成 `translate(中心) rotate translate(−中心)`，
再加上 `left/top: −boxOffset`，等效于用了**两次**偏移，灯点被平移到 `R(θ)·(中心 − 灯点)`：
偏差 ≈ 1.7 px 而且**随朝向变**（这正是"位置也不准确"的样子）。

**定值方式换了**：不再推导（推导过两轮，都差一个"盒子尺寸"的常数项 —— 旋转中心是
`left/top` 之后那个盒子的中心，而绝对定位的 SVG 还在零尺寸的 `.rot` 里，常数项在中间被抵消）。
改成**在页面上试**：`sandbox/signal-offset-trial.js` 把 `.unit` 的 `left/top` 换成几组候选、
各量 24 盏灯，谁让"灯点在锚点上"就用谁。

| `left/top` 取值 | 偏离锚点（均值 / 最坏，px） |
| --- | --- |
| **灯点在盒子里的位置（取反）** | **(0, −0.004) / 0.013** |
| 半个盒子 | (0, 0.86) / 2.06 |
| 中心 − 灯点 | (1.48, 3.23) / 8.53 |
| 0, 0 | (1.48, 2.37) / 6.72 |

## 三、中途量错一次、把对的改错了（记下来免得再来）

我一度量出"折角的尖**永远指向管辖方向的反面**"（四个朝向 `dotWithProduct = −1`），
于是把旋转符号翻成 `−arrowRotation`。**那是量错了**：我量的是"尖相对**灯点**"的方向，
而灯点画在盒子的 78% 高处、尖在上方 —— 同一条竖直轴上，两个图形本来就朝相反两头。

用**引擎的真值**核对才定案：角 0 的灯管南，引擎 `headingOf(0) = (0, +1)` 指屏幕下方；
配 `rotate(0)`（= `arrowRotation = 角 + 180`）时，折角相对**旋转中心**的方向是 `(0, +1)` ✔。
正确的符号是**正**的，已经改回。

## 四、判据（`sandbox/check-web-signal-unit.ps1`）

96 盏灯，四条判据：

| 判据 | 结果 |
| --- | --- |
| 灯点在锚点上 | 均值偏差 (0.001, 0.010) px，96 盏极差 **0.0164 px**（与朝向无关） |
| 折角指向管辖方向 | 与 `headingOf(角)` 的最小一致度 **1.000** |
| 弹窗不带旋转 | 外层带 rotate 的 0 盏、把卡片放进旋转层的 0 盏 |
| 尺寸随倍率 | 整体宽比 1.747 ≈ 倍率比 1.749 |

### 量法上的三个坑（都写进脚本注释了）

1. **`getScreenCTM` 的 e/f 不是文档坐标**：对 SVG 子元素它是**相对 SVG 视口**的
   （曾经据此报"某些朝向差 1.77 px"，而渲染其实是对的）。
2. **量圆的外接框前要临时关掉 `drop-shadow`**：1 px 的点会被滤镜撑成 3.5 px 的框，圆心歪 1.7 px。
   关掉之后均值偏差从 1.5 px 掉到 0.004 px —— 这才是"位置准不准"能测得准的前提。
3. **"箭头指哪边"要比相对旋转中心的方向**，不是相对灯点（见第三节）。

## 五、顺带修的一处检查口径

"跨图缩放"检查里的端点圆点改按**规格**量而不是外接框：它只有 1 px（6× 时）、
1× 时 0.17 px，光栅化会把它抬到设备像素 —— 量外接框会得出"没跟着缩放"的错误结论。
