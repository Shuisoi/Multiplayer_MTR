# 227 收窄成"只收物品栏那一簇"，聊天保留 —— 并把"别碰聊天"变成判据

上一轮（notes/226）做的是"物品栏 + 第一人称的手"。用户随即把口径收窄：

> **「只把物品栏，物品栏上的信息，隐藏，聊天一定要保留」**

（中间问过一次"要不要整条 HUD 一起收（等同 F1）"，用户选了整条，但紧接着就用上面这句否掉了 ——
所以最终口径以"只"和"聊天保留"为准，**没有**动 `GameOptions.hudHidden`。）

## 1. 现在收起的是哪四样

`InGameHudMixin` 从 1 个注入点扩到 4 个，正好是原版里挨着物品栏的那一簇：

| 注入点 | 它负责画的东西 |
| --- | --- |
| `renderHotbar(FLnet/minecraft/client/gui/DrawContext;)V` | 物品栏九格 + 副手格 + 选中框 |
| `renderStatusBars(Lnet/minecraft/client/gui/DrawContext;)V` | 血量 / 饥饿 / 护甲 / 氧气泡 |
| `renderExperienceBar(Lnet/minecraft/client/gui/DrawContext;I)V` | 经验条 + 等级数字 |
| `renderHeldItemTooltip(Lnet/minecraft/client/gui/DrawContext;)V` | 切换物品时弹在物品栏上方的物品名 |

加上 `HeldItemRendererMixin` 的第一人称手，一共 5 个"上车后消失"的东西。

**没碰**：聊天（`ChatHud`）、准星、状态效果图标（右上角那排药水）、计分板、F3、字幕。
坐骑的 `renderMountHealth` / `renderMountJumpBar` 也没碰 —— 那是骑马时才有，在列车上不可达。

## 2. 把"聊天一定要保留"变成判据

用户点名"一定"，那就不能只靠"我记得没碰"。`run-mixin-probe.ps1` 在核对完注入目标之后，
再扫一遍所有 mixin 源码里 `method = "…"` 的名字：

- 任何注入点名字含 `chat`（不分大小写）⇒ **FAIL**；
- 否则打印出"聊天未被触碰"，并**列出全部注入点**，方便改口径时一眼看出有没有收多。

顺带，名字后面的括号只取到 `(` 为止（描述符里面有 `;` 和 `/`，正则不能贪），
输出的注入点清单就是可以直接对照的"我们到底干涉了原版哪些方法"：

```
聊天未被触碰（没有任何注入点的名字含 chat）
全部注入点（7 个）：
  ClientWorldRenderingMixin.java: getEntities
  HeldItemRendererMixin.java: renderItem
  InGameHudMixin.java: renderHotbar, renderStatusBars, renderExperienceBar, renderHeldItemTooltip
  PlayerRendererOffsetMixin.java: getPositionOffset
核对 7 个注入目标，失败 0 个
```

4 个新注入点全部通过描述符精确匹配 —— 上一轮建的守卫这一轮立刻就用上了（4 个新描述符要是我手写错一个，
离线就会红，而不是等进游戏炸 `InjectionError`）。

## 3. 验收

- 我改的三个文件 `javac` 通过（`MmtrVanillaHud` / `InGameHudMixin` / `HeldItemRendererMixin`）；
- mixin 守卫：**7/7** 目标存在（含描述符精确匹配）、聊天未被触碰；
- 判据方法从 `hideHotbarAndHand()` 改名成 `hideWhileRiding()`（名字要跟"实际收什么"对齐，
  收的东西变了、名字不变就会误导下一个读代码的人）。

**进游戏要验的**（离线验不了，列清楚免得漏）：
① 上车后物品栏、血量/饥饿/护甲/氧气、经验条、切换物品的名称都消失，下车全部回来；
② **聊天仍在**（这是用户点名的那条），准星、右上角药水图标、计分板也仍在；
③ 第一人称的手消失，但**别的玩家**手里的物品还在。
