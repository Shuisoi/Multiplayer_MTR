# 273 — 挂车模型 片 3：逐车气路口径 + 按车长的管容积当量 + P1 自己的 bar 键

日期：2026-09-26 · 设计：`docs/01-设计/非动力挂车-车辆模型与编组对象-设计.md`（片 3）

用户口径（2026-09-26）：**管容积当量用车长**；**P1 可以给**（自己的 bar 键）。

## 1. 修前是什么样

`BrakeSystem.step` 里"气压沿车列往后传"这件事**只有说话那节车的口径**：

```
① 车头：pipeBar[0] ← spec.stepPipe(…)          ← 编组级 spec（= 说话那节车）
② 传播：pipeBar[i] ← pipeBar[i] + gap × spec.getPipePropagationPerSecond() × dt
                                               ← 同样读编组级 spec
③④⑤ 逐车缸压：specOf(i)                        ← 这几步本来就是逐车的
```

后果：**挂车自己的充排气速率与传播率从来不参与** —— "这列车的管子多快"完全由机车决定
（notes/270 §6 自认这条）。另外 `p1_trailer` 一个 bar 键都没有，于是客车的分配阀/缸压上限
也是借说话那节车的（notes/270 的用例里那条"客车按自己的 2.0 bar 封顶"只存在于夹具里）。

| `brake/BrakeCar.java` | 新增第 5 个分量 `lengthM`（**管容积当量的唯一输入**）+ 4 参便捷构造（`lengthM = 0`）。老调用点（`NotchedDriveController`/`SteplessDriveController`/`equivalentBrakeCar`/老用例）逐字不动 |

## 3. 判据（`MmtrPneumaticBrakeTests` 新增 3 条，全过）

```
尾车建满：编组口径（5.0/s）3.55 s / 挂车自己的慢气路（1.0/s）10.20 s   ← 逐车口径真的生效
尾车建满：20 m 车 3.55 s / 40 m 车 4.75 s                            ← 管容积当量按车长
pipeVolumeScale：20 m⇒1.0、0⇒1.0（未知不修正）、40 m⇒0.5
随包配置：p1_trailer 有自己的 bar 键（缸压上限 2.0、充风 5.2、传播 4.0、无电制动、仍零牵引）
```

**零回归**：`MmtrPneumaticBrakeTests` 里既有的逐车管压用例读数一位没变
（车头 3.15 s / 尾车 3.70 s、滞后 0.55 s、现场场景 44.6 kN、制动距离 439 m vs 427 m）——
因为那些夹具的车长正好是 **20 m**（= 基准车长 ⇒ 缩放 1.0），而 `MmtrBrakeModelReuseTests`
直接构造 `BrakeCar`（`lengthM = 0` ⇒ 同样不缩放）。**基准选 20 m 就是为了不做无谓的手感改动**。

**全量：855 条、失败 3 条、跳过 6 条** —— 三条失败仍是预存在的世界存档漂移。

## 4. 已知取舍

* **管容积当量仍然是个替身**：没有建 250–300 m/s 的压力波（20 m 车长上只有 0.07 s，真正拖慢长编组的是
  容积与充排气时间）。片 3 给的是"逐车口径 × 按车长缩放"，可标定、可解释，但不是波速模型。
* `p1_trailer` 的**分配阀倍率/充排气/传播**是**估算**（配置注释里点明了）：只有"缸压上限 2.0 bar"是用户给的。
  等真车数据替换时只改这几个键。
* `lengthM` 只进了 `BrakeCar`（制动系统）；`MmtrUnitCar`（编组几何）本来就有长度，两条路暂时各走各的。
