# 268 — 制动 P5：逐车列车管传播（尾车滞后）

用户口径（2026-09-25）：**「把 P5 做完之后停双端重启吧」**。本轮做完 P5，然后停服务端/客户端换 jar 重启。

## 1. 为什么 P5 是最后一块

前四片（P1 气压语义 + UIC 标定、P2 闸片/电制动曲线、P3 电空混合、P4 黏着截断）都建立在
**"整列车一个管压"**上：司机阀一动，全列同一时刻建压。真车的列车管是一根**长管** ——
阀只作用在车头，压力沿车列往后传（规格 §5：压力波 250–300 m/s，但真正拖慢长编组的是**长管容积的
充排气**），于是**尾车的闸比车头晚**。这正是"长编组制动距离更长"里我们一直缺的那一半
（用户 2026-09-25 专门问过这件事，当时的回答是"同 λ 的车挂多少节都一样 + 这一半还没建模"）。

## 2. 模型（`BrakePipeNetwork`）

```
管压[0] ← 司机阀目标（stepPipe；紧急走 stepPipeEmergency）
管压[i] ← 向管压[i−1] 一阶松弛：gap × 传播速率 × dt        （缺省 5.0/s，notes/266 的替身）
缸压[i] ← max(分配阀(管压[i]), AFB 补气下限)，再按建/缓解速率追
力[i]   = 该车**自己的制动力锚** × f(缸压[i]) × κ(v)
总力    = Σ 力[i]                    （稳态与"整列一个锚"**逐位相同**）
```

- **电空混合只削动力车**：电制动是机车自己的 ⇒ 它替掉的是机车自己那份机械制动，拖车缸压不动
  （P3 的"总力 = 司机诉求"在逐车口径下依然成立）；
- **紧急同样逐车**：排风/建压逐车走 ⇒ 尾车的紧急制动也滞后（长编组的紧急距离同样更长）；
- **牵引联锁看全列最大缸压**（notes/238/248 的纪律：任何一节还压着闸就不许牵引）；
- **镜像仍是车头读数**：驾驶室的表看的就是司机那一节 ⇒ `mmtrPipePressure`/`mmtrBrakeCylinderPressure`
  报车头值（客户端 HUD 读它，不需要知道逐车细节，与 notes/259 的口径一致）；
- **传播速率**是配置键 `airPipePropagationPerSecond`（缺省 5.0/s）：3 节车尾车滞后约 0.3–0.4 s、
  8 节约 1 s、50 节货车约 10 s（真车量级）。

## 3. 实测（`MmtrPneumaticBrakeTests`，5 节编组：BR101 + 4×p1）

```
[TEST] 逐车管压：车头缸压到位 3.15 s、尾车 3.70 s（滞后 0.55 s）
[TEST] 1 s 时制动力：逐车 34.6 kN / 整列 55.9 kN；12 s 时：逐车 276.9 kN / 整列 276.9 kN
[TEST] 100 km/h 全常用：逐车管压 439 m / 整列一个管压 427 m
```

三条判据都钉住了：
1. **尾车滞后 ≥0.3 s**（实测 0.55 s）；
2. **过渡过程更弱**（1 s 时只有整列模型的 62%）—— 这就是"长编组更长"的来源；
3. **稳态逐位一致**（12 s 时 276.9 = 276.9 kN）⇒ **P5 只改过渡、不改稳态手感**；
4. 100 km/h 停车距离 **+12 m（+2.8%）**（5 节车；编组越长差距越大）。

补上用户那个问题的完整答案（100 km/h 全常用，含建压过渡与阻力）：

| 编组 | 整列一个管压 | 逐车管压（本轮） |
| --- | --- | --- |
| BR101 + 4×p1（5 节） | 427 m | **439 m** |
| 越长 | 同（力与惯性同比例） | **越长**（尾车滞后累积） |

## 4. 改了什么

| 文件 | 改动 |
| --- | --- |
| `mmtr/BrakePipeNetwork.java`（新） | 逐车管压网络：传播、逐车分配阀/缸压、逐车力、只削动力车的混合、紧急逐车 |
| `physics/PneumaticBrakeSpec.java` | 新增 `airPipePropagationPerSecond`（缺省 5.0/s）：JSON + `PB` 镜像串 |
| `ThreeHandleDriveController.java` | `setConsistBrakeCars(...)` 挂上逐车网络；服务/紧急两条支路都走逐车；联锁看最大缸压；镜像报车头读数；新增 `isPerCarBrakePipe()` / `getCylinderBar(i)` / `getPipeBar(i)` |
| `MmtrComposition.java` | 新增 `carServiceBrakeForceN()` / `carEmergencyBrakeForceN()` / `carPowered()` |
| `Vehicle.java` | 服务端多节编组时把逐车锚交给三手柄控制器（**客户端不设**：镜像没有注册表，逐车锚会算错） |
| 测试 | `MmtrPneumaticBrakeTests` 新增 3 条（尾车滞后 + 过渡/稳态 + 停车距离 + 单车零回归） |

**零回归**：单车编组、客户端镜像、legacy 车底（没有 bar 键）都逐位走原来的单车等效模型
（`setConsistBrakeCars(null)` / 只传一节车 ⇒ `isPerCarBrakePipe() == false`）。
