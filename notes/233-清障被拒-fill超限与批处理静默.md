# 233 · 「末端轨道被地形截断」的真因：清障命令被 /fill 上限拒了，而批处理把它当成成功

> 用户口径（2026-09-24）：「末端 4000 那边后延的轨道被地形截断了，应用和其他轨道一样的上方方块去除」。

## 1. 现场

新世界往 +Z 的延伸段实际造到 **z=4222**（两台 160 限速直轨 x=0/x=5 + 4142..4182 一组剪刀渡线），
但用户看到末端那段**被地形埋住**。

已有的施工命令文件里，`z_extend_crossover_fills.txt`（清障）只写到 z=4182，
而且它的每一条都是这样：

```
fill -5 64 4082 10 96 4181 minecraft:air replace      ← 要求清 52800 格
```

服务端的回答是：

```
Too many blocks in the specified area (maximum 32768, specified 52800)
```

**这条命令没有生效**。断面是 x=−5..10（16 格）× y=64..96（33 层）× z 100 格 = 52800 格，
超了原版 `/fill` 的 32768 上限。主干道那批（`build_z_clearance_full.txt`）用的是 x 0..5（6 格宽）
⇒ 6×33×150 = 29700 刚好过关，**只有渡线这一段被拒** —— 于是那一段的地形从来没被清过。

## 2. 为什么没人发现（真正的坑在工具里）

`sandbox/rcon_batch.py` 的设计是"**只打印有回应的命令**"（理由：这台 dev 服务端对条件为假的
`execute if block` 是静默的，静默本身就是信号）。但被**拒绝**的命令**是有回应的** ——
一句错误人话，于是它被原样打成 `OK ... -> Too many blocks ...`，
在几十条 fill 的输出里与"执行成功"长得一模一样。

## 3. 处置（已生效）

1. 按体积重切分段：16 格 × 33 层 ⇒ 一段最多 62 格 z（16×33×60 = 31680 ✓）。新文件
   `sandbox/z_extend_clear_4082_4222.txt`；
2. 执行结果（这一段的真实地形量）：

   | 段 | 结果 |
   | --- | --- |
   | z 4082..4141 | **Successfully filled 10317** |
   | z 4142..4201 | **Successfully filled 4553** |
   | z 4202..4222 | No blocks were filled（先前已清掉 2 格） |
   | 路基 y=62..63 | No blocks were filled（已在） |

   合计清掉 **14876 格**地形；
3. **补回轨道节点方块**：清障把 y=64 的节点方块一起带走了（这是这套流程的已知后果，
   `gen_z_extension.py` 的 `relic_commands()` 注释里写着"节点方块由 rail add 重放时重放"），
   所以按**引擎里的实际轨**（`mmtr-topology`：x=0/x=5 的 6 段直轨 + 4142..4182 两条斜轨）
   重放了 8 条 `rail add`。复查：清障框里现在只剩 2/4/2 个方块 = 刚补回的节点方块 ✓。

## 4. 两处工具修复（防复发）

1. **`rcon_batch.py`**：新增 `REJECTED` 正则识别"我拒绝了这条命令"的措辞
   （`Too many blocks` / `unknown` / `invalid` / `cannot` / `无法` …），命中就打 `FAIL`、
   计入"被拒 N 条"，并以**退出码 1** 结束。用当天那条被拒的原命令验证：
   `FAIL fill -5 64 4082 10 96 4181 …` + `exit=1` ✓。
   批处理"静默即成功"的老规矩对**条件为假**仍然成立，但对**被拒**必须响铃。
2. **`gen_z_extend_crossover.py`**：`fill_commands()` 不再按 z=100 拍，
   改为按体积算 `max_z_span(x, y)`（`FILL_BLOCK_CAP // (x_span × y_span)`），
   重新生成的 fills 每段 ≤62 格 z ✓。

## 5. 顺带发现（**没动**，但要记一笔）

生成器里的渡线中点是 **z=4132**，而世界里实际造出来的是 **z=4142**（引擎 `mmtr-topology` 的读数）。
所以 `z_extend_crossover_rails.txt` 现在与现场**不一致**：谁要重放那个文件，
会在 4132 多出一组不存在的轨、并把渡线拉歪。我这次**没有**重放它，
而是照引擎里的实际轨逐条重放 ✓。要么把生成器的 Z1 改成 4142，要么把世界改回 4132 ——
两者选一，别让两个真源并存。
