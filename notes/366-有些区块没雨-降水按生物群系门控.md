# 366 · 「有些区块下雨、有些没有」不是缺陷：降水是按生物群系门控的

2026-10-03。用户口径：「第一个 bug 是下雨，有些区块没音效没下雨粒子效果，有些区块有」，
随后自查确认：「大部分地方都没有，我现在位置就没有」→「我今天才知道草原不下雨，那就没事了」。

结论：**这不是 MMTR 的渲染缺陷，一滴雨都不该修**。原版对**雨粒子**和**雨声**用的是同一条门：
`Biome.hasPrecipitation()`。所以"隔一块有一块"的边界不落在区块上、落在**群系边界**上，
而那些边界在这个世界里恰好与区块对齐（见 §3 的实测）。

这一篇的作用只有一个：**下次再有人（包括我）报"这里没下雨"，先读这一篇，别再去查渲染**。

---

## 1. 那一行门（Yarn 1.20.4，`javap -c` 实证）

```
// net.minecraft.client.render.WorldRenderer.renderWeather(...) 字节码
 225: invokevirtual  World.getBiome:(BlockPos)RegistryEntry
 240: invokevirtual  Biome.hasPrecipitation:()Z
 243: ifne  249          // 有降水 → 继续，画雨/雪
 246: goto  1470         // 没有降水 → 跳过这一格（continue）
```

```
// net.minecraft.world.biome.Biome.getPrecipitation
   0: aload_0
   1: invokevirtual  hasPrecipitation:()Z
   4: ifne  11
   7: getstatic      Biome$Precipitation.NONE
  10: areturn              // ← savanna / desert 永远走这一支
```

**雨声走的是同一格**：`WorldRenderer.tickRainSplashing(camera)` 在外层循环里
`aload 6  ifnull 566` —— 那个 `astore 6` 只在"这一格真的落下雨"时才被赋值，
没落到就 `ifnull` 跳过整段播声（`SoundEvents.WEATHER_RAIN` / `WEATHER_RAIN_ABOVE`）。
⇒ **粒子与音效不会分家**，用户看到的两个症状是同一个原因。

### 群系自己的声明（原版 jar 里的数据文件，不是我的记忆）

从 `sandbox/gradle-home/caches/fabric-loom/1.20.4/minecraft-extracted_server.jar` 解出：

| 群系 | `has_precipitation` | `temperature` | `downfall` |
| --- | --- | --- | --- |
| `savanna` | **false** | 2.0 | 0.0 |
| `desert` | **false** | 2.0 | 0.0 |
| `plains` | true | 0.8 | 0.4 |

> **修正一个常见误记**：不是"只有沙漠不下雨"。1.20.4 这一版里 **savanna 与 desert 一样是 `false`**
> （"热带草原会下雨"是更早/更晚的版本行为）。
>
> 另外：**原版 1.20.4 没有"让沙漠下雨"的那个开关**（`hasPrecipitation` 是硬门，没有 `temperatureModifier` 旁路）。

## 2. 已排除的两条（别再往这两个方向查）

| 猜法 | 判据 | 结论 |
| --- | --- | --- |
| MMTR 的 mixin 拦掉了天气渲染 | 全库搜 `hasPrecipitation` / `Precipitation`：游戏侧只有挡风玻璃自己读 `clientWorld.isRaining()` 判雨量（`MmtrWindshield.java:481`），没有任何 mixin 碰原版天气 | **无关** |
| 光影包把雨吃掉了 | `run/config/iris.properties` 里 `enableShaders=false`（包没开） | **无关**（但开着时要另判一次，见 §5） |

## 4. 现场自查（不需要问我）

1. 按 **F3**，左上角读**所在区块的群系名**。是 `savanna` / `desert` / `badlands`（或任何 `_ocean` 水面）→ 本来就不该有雨。
2. 想强制看雨：`/weather rain`，然后**往里走 200 格**到 `forest` / `plains` 那种群系再看。
3. 万一是"该下的群系也不下"，那要查的三件事按顺序是：`ran` 世界降雨梯度是否 >0 → F3 里的群系名 →
   §2 那两条排除。

## 5. 如果哪天真的要"到处都下雨"

两条路，代价完全不同：

| 路 | 做法 | 代价 / 风险 |
| --- | --- | --- |
| **改世界数据**（推荐） | 用 WorldEdit 把线路走廊刷成会下雨的群系（`plains` / `forest`） | 只动存档 `biomes` 数据；不动代码；对已建成区可框选刷 |
| **改 mod** | mixin 进 `WorldRenderer.renderWeather` 的 `hasPrecipitation` 判定，做成客户端开关 | 新建 mixin + 验一次；只影响画面与雨声，不写存档；**会让"沙漠出雨"这种反直觉画面出现** |

2026-10-03 用户口径：**两条都不做**（"那就没事了"）。
