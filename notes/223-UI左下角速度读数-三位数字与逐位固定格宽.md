# 223 · UI 构建第一件：大号速度读数（三位数字 / DIN / 右斜体 / 逐位固定格宽）—— **右下角**

日期：2026-09-21 · 结论：新增 `MmtrSpeedHud`（屏幕**右下角**，三位数字，DIN 1451 + 右斜体，
**每一位在自己的固定格子里居中**）。客户端 437 源 / 642 类编译通过；排版与版位不变量由离线探针
对着**真方法**跑了 **99 + 120 项检查 / 0 违规**。

> 版位变更：最初按用户口径做在**左下角**，同日用户改为**右下角**（`blockLeft(...)` 一行：
> 右边缘钉在 `屏宽 - EDGE_PADDING`）。逐位居中的排版逻辑与判据不受影响。

用户口径：「显示速度，一个大号的三位数字，字体用 DIN，**右斜体**，三个数字**单独排版**，
**位置中点固定**，防止字宽不同导致整体伸缩」（首版在左下角，随后改为右下角）。

## 1. 逐位排版（这是本条要求的核心）

比例字体里 `1` 比 `8` 窄：整串画一次，读数会随数字内容左右抖（199 → 100 时整块缩一截），
而当读数是唯一信息时这非常刺眼。做法：

```
格宽 = max(量出 '0'..'9' 的宽度) + DIGIT_GAP      // 只算一次，缓存
第 i 位的绘制 x = i * 格宽 + (格宽 - 该位实际宽度) / 2
```

于是**格子中心 = i*格宽 + 格宽/2，与"这一位是谁"无关** ⇒ 整块宽度恒定、数字在原地变化。

**★ 一处我自己读错要求的地方（值得记下来）**：第一版判据我写的是"窄数字与宽数字的**左边缘**差 ≤ 1 px"，
离线探针当场 FAIL（`1→3` vs `8→1`，差 2 px）。那 2 px 不是抖动，**正是居中的结果** ——
用户要的是"**中点**固定"，不是"等宽网格"。判据改成中点一致（≤1 px 取整误差）后 99/99 通过。
探针与 JUnit 用例都按这个口径改对了。

## 2. 斜体

用 MC 自己的斜体：`Style.withFont(mtr:ui).withItalic(TRUE)` —— MC 把字形**向右剪切**，正是"右斜体"；
DIN 1451 本身没有斜体字重，这样也省掉再找一套字体。倾斜量由 MC 实现固定（想更斜得上自定义变换，
本轮不做，记在遗留里）。

## 3. 显示条件与版位

- **只在坐在司机位上时画**：判据与"能不能操作手柄"同源（`MmtrDriverSeat.isAtControls()`），
  所以不会出现"有读数却按不动"的组合；乘客与站台上的人看不到。
- 位置：**右下角**，距右边与下边各 8 px；**右对齐**——`blockLeft = 屏宽 - 留白 - 三位格宽*缩放`
  ⇒ 右边缘固定，读数不会随数字宽度左右移动（缩放前对齐 ⇒ 缩放后仍对齐）。
  字号 = 4 倍（MC 行高 9 px ⇒ 约 36 px 高）；数字纯白、带阴影。
- 前导零：`String.format("%03d")` —— 固定三位版位（`087`）。想"空着前导位"就把那行换成右对齐拼接。
- 格宽缓存 + `reset()`：按字体量出来的常量，**资源重载（换字体）后必须重新量**，
  已接进 `CustomResourceLoader.reload()`（与 `MmtrPanelFont.reset()` 同一处）。

## 3.1 背景楔形（用户口径 2026-09-21）

「直角边靠在屏幕右下角、与屏幕底部夹角 30°、底部边长为屏幕宽度 20%」⇒ 直角顶点在屏幕右下角，
底边沿屏幕底边（长 `0.20·屏宽`），斜边自左下顶点起 **30°** 上升，竖边高 = `底边 × tan30° ≈ 0.1155·屏宽`
（854×480 下：底边 171 px、竖边 99 px）。

- **画法**：逐列 1 px 竖条，列高按列位置线性涨到竖边高（`wedgeColumnHeight`）。
  逐列而非逐行，是因为 30° 是缓坡 —— 列高变化平缓，上沿不会有阶梯洞。
  MC 的 2D 矩形没有抗锯齿，斜边是像素台阶（用户说"简易绘制"，接受）。
- 颜色 `0xA8101418`（半透明深蓝黑，压在读数下面保证白字可读）；一个常量，实机可调。
- 几何做成**纯函数**（`wedgeBottomLeg` / `wedgeHeight` / `wedgeColumnHeight`）以便被单测与探针钉住。

## 3.2 单位、限速牌与 AWS 灯（用户口径 2026-09-21）

「在速度右加个 km/h 用于指示，三个数字的间距缩小点，在加的 km/h 上面绘制限速图标，再加入 AWS 的图标指示」。

| 元素 | 做法 | 数据来源 |
|---|---|---|
| `km/h` | 数字右侧、**底部对齐**（按自己的 1.5 倍字号单独摆一次，不是把 y 相加）；不斜体 | — |
| 数字间距 | `DIGIT_GAP` 2 → **1**（格宽本身取最宽的那位，所以实际观感间距就是这个数） | — |
| 限速牌 | 红圈 + 白面 + 黑字（与资源包 BR101 仪表盘里的限速控件同色 `C8322B/F2F4F6/101418`）；**限速 0 就不画**（没有监督就没有牌子） | `getMmtrSpeedLimitKmhFromSync()` |
| AWS 灯 | 圆灯 + 左侧 `AWS` 标签；**灭** / **已确认（绿）** / **未确认告警（琥珀，1 Hz 闪烁）** | `isMmtrAwsWarningPendingFromSync()` / `…AcknowledgedFromSync()` |

- **图标是画出来的，不是贴图**：圆 = 逐行水平条（`circleHalfWidth(r, dy) = round(sqrt(r²−dy²))`），
  圆环 = 大红盘 + 小白盘。好处是随分辨率自适应、不引入新资源；代价是无抗锯齿（"简易绘制"）。
- 图标行整行**右对齐**：限速牌右边缘 = `屏宽 − 留白`，AWS 灯与标签依次往左。数字块的右边缘让出
  单位所占的宽度（`digitsLeft(..., trailingWidth)`）。
- **值得实机看一眼的几何**：楔形在右边只有 `0.2W·tan30° ≈ 0.1155W` 高（854 宽下 99 px），
  而"数字行 + 图标行"叠起来约 36 + 4 + 26 ≈ 66 px，加上下留白已接近楔形的坡顶；
  数字块左端（更靠楔形薄的一侧）会探出坡边。要全塞进楔形里，就把楔形加宽/加陡（两个常量）。
- `AWS_BLINK_PERIOD_MILLIS` 与两个半径、`ICON_ROW_GAP`、`UNIT_SCALE/GAP` 都是常量，实机可调。

## 5. 遗留

1. **与右上角 HUD 的"速度"行重复**：`MmtrDriverHud` 里还有一行小号速度。要不要去掉那一行（把速度只留左下）
   等你一句话；
2. 字号/位置/前导零都是常量（`SCALE` / `EDGE_PADDING` / `%03d`），实机看后调；
3. 斜体量不可调（MC 固定剪切）；要更斜得自己上变换矩阵；
4. 今天的读数还是"瞬时速度"（镜像速度取整）。真车速度表常有阻尼/指针滞后 —— 要不要加个平滑，
   也等你定（`hud` 侧一行低通即可）。
