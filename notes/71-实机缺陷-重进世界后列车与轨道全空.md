# 71 - 实机缺陷：离开世界再进来，列车与轨道全空

> 实机（2026-09-09 18:07:32 / 18:07:38）：用户离开世界又回到同一世界两次，客户端 `client vehicles=0`，
> 轨道也不显示；日志里服务端一直在推车（`[MMTR-SYNC] push vehicle … dirty=false client=bd11acc2-…`），
> 客户端却一辆车都没有。

## 根因：引擎的"客户端记录"跨会话残留

引擎为每个 UUID 保存一份 `Client` 记录，记录**已经发过什么**（`existingVehicleIds` 等）：

```java
public void update(Vehicle vehicle, boolean needsUpdate, int pathUpdateIndex) {
	if (needsUpdate || !existingVehicleIds.contains(vehicleId)) { vehicleUpdates.put(...); }   // 全量
	else if (!vehicleUpdates.containsKey(vehicleId)) { keepVehicleIds.add(vehicleId); }        // 只"保活"
}
```

玩家重进世界时，客户端 `MinecraftClientData.reset()` 清空了自己知道的一切，但**服务端那条记录还在**，
仍然认为"这辆车早发过了" → 只发 keep、不发 update → 客户端把 keep 当作"保留我有的"（它什么都没有）→ 全空。
只有某辆车真的动起来（dirty）时才会被重新发出去。

记录唯一的清退点是 `PlayerPresentResponse.verify`（**维度不一致**时），所以同一维度内重进 = 永远空。

## 修法

1. 引擎：`Simulator.removeClient(UUID)`（`PlayerPresentResponse` 改用同一方法），语义 = 玩家已离开本维度/服务器，
   丢掉这条记录；下次进世界 `DataRequest` 会重新建一条空记录 → 全量重发。
2. 游戏侧：`MmtrPlayerSessions` 注册 `ServerPlayConnectionEvents.DISCONNECT` → 找到该玩家所在维度的 `Simulator` →
   `simulator.run(() -> simulator.removeClient(uuid))`（切到模拟线程，与 HTTP/游戏线程隔离）。
3. `MTR.onInitialize()` 里注册（与 `MmtrChunkTracker`/`MmtrCommandExecutor` 同一处）。

## 用例

`ClientTests.testRemovedClientResendsEverythingOnRejoin`：
- 新记录 + `update(passenger, true)` → 发 1 个 `vehicles_lifts` 包（全量）；
- `update(passenger, false)` → 发 0 个（只保活）；
- `simulator.removeClient(uuid)` 后按"重进"重建记录，再 `update(passenger, false)` → **又发 1 个全量包**。

修复前这条断言会失败（重建前记录被复用，重进后依然是 0 个包）。

## 验证

- 引擎全量套件 **433/0/2**；
- 实机：待用户"退出世界 → 再进"确认列车与轨道都在。
