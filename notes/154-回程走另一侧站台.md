## 1. 问题：一条线原来只有"一份站序、两个方向共用一个站台"

现场每个站都有**两个站台**（站 1~10 各两个），去程该走一侧、回程走另一侧。
而线路模型里 `MmtrLine.stops` 只有一份：`{stationId, platformId, dwellMillis}`，
返程趟次只是把这份站序**反过来走**，于是回程会开去**同一个站台**（对向台）——这在双线路上是错的。

不拆成两条线的理由：拆了就没有"套班/周转/往返配对"了（P3 的整套算法都建立在"一条线、一趟去一趟回"上）。

## 2. 修法：每个站多一个"回程站台"

```
MmtrLine.Stop:
  stationId          站
  platformId         去程（1→10）用的台
  returnPlatformId   回程（10→1）用的台   ← 新增；0/空 = 与去程同一个台（旧配置行为不变）
  dwellMillis        停站
```

- `MmtrServicePlan.buildTrip`：**只有返程趟次**用它取台
  （`direction == BACK && stop.returnPlatformId != 0 ? returnPlatformId : platformId`）；
  站序、停站、ring、套班、配对算法**一个字都不用改**；
- 落盘/接口：十进制字符串（与其它 id 同一条口径，见 `MmtrPlanIds`），空/0 不写这一项；
- 控制台：线路页的每一站多一列下拉"**回程站台**"（第一项"回程：同去程站台"）；
  选项构造写在脚本里而不是模板里 —— 模板内联数组带引号嵌套会让 `vue-tsc` 直接报语法错（踩过一次）。

测试（两条，都红证过）：`theReturnTripUsesTheOtherPlatformOfEachStation`
（去程三站走 2000/2001/2002，回程三站走 3002/3001/3000）、`withoutAReturnPlatformTheOldBehaviourStands`。
