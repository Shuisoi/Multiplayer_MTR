# 403 车音效：**坐在驾驶位上就忽略距离衰减**，以及把混音表摊平（2026-10-08）

## 0 用户口径

> 音效的声音不够大，但是游戏内的确是有根据距离削减声音的效果。我们需要提供一个**判定玩家是否在驾驶位上**，
> 若在驾驶位上，则**播放完整音量的音频忽略距离影响**；此外需要将**音频混合算法明朗**一下，
> 因为目前游戏内听到的音频声音偏低。

然后（第二轮现场）：**"没有电机励磁音"**。

两件事：① 驾驶位 ⇒ 忽略距离、满音量；② 把"音量从哪来"摊平成一张可核对的表，并回答"为什么偏低"。

**结论先放这里**：

| 症状 | 真因 | 状态 |
|---|---|---|
| **没有电机励磁音** | 司机坐的是 **Tc 控制拖车**（`saf420cab_a`，世界清单 `powered:false`），被"挂车一律静音"那条判据**静音**了；真正响的 6 节动车在 20–125 m 外、再被距离衰减削掉 | ✅ 已修（§2.5 操控位豁免） |
| **两种音效配比不一样** | 交付音频里牵引层峰值 **−25.47 dBFS**、走行层 −11.19 / −10.00 dBFS（差 14–15 dB）。**上一版这里判断错了**：当时以为"播放端只能衰减、补不了"，实测**能**放大（§3.4）⇒ 一个层基线就抬起来了 | ✅ 已修（`TRACTION = 2.2` = +6.8 dB） |
| **励磁音没有按"速度定段 × 牵引力定音量"组合播放** | 旧"负载轴"把速度**混进了音量**（功率项带 v、级位项被 `exp(−v/8)` 削），低速还被门限**按速度把音量压成 0** | ✅ 已修（§2.6 两个轴正交） |
| 偏低（总响度） | 总出手量写死 `0.45` = 白丢 −6.9 dB | ✅ 已顶到 1.0 |

## 0.1 ★ 第二轮现场："没有电机励磁音"——真因是**操控位豁免**（§2.5）

先把不可能的都排掉（都有据可查，不是猜）：

| 嫌疑 | 排掉它的证据 |
|---|---|
| 资源包没接上 | 解 `SAF420_v42.zip`：三节车 `bveSoundBaseResource = kei2100` ✓；`sounds.json` **69 条事件**齐全，`kei2100_motor01 → mtr:kei2100/motor01` ✓ |
| 事件名落空（多一个 `sounds/`） | 上面那条 `name` 逐条查过 ✓（这正是 v41 的坑） |
| 走行层响、牵引层不响 ⇒ 引擎根本没接管 | 走行层与牵引层**在同一个 `MmtrVehicleSound` 实例里**，同一个 `playMotorSound` 里更新 ⇒ 走行层响就说明引擎接管了 |
| 被"挂车静音"判据静音 | **这一条**没排掉 —— 见下 |
| 电机出力镜像为 0 | 未排除，但优先级降到第二（若镜像为 0，新加的日志会直说） |

**世界清单里的编组**（`mmtr/game/fabric/run/world/mtr/minecraft/overworld/mmtr-rolling-stock.json`）：

```
0: saf420cab_a  powered=false  type=saf420_trailer   ← ★ 司机坐的就是这一节
1..6: saf420car powered=true   type=saf420_motor     ← 真正有电机、真正会响的 6 节
7,8: saf420car  powered=false  type=saf420_trailer
9: saf420cab_b  powered=false  type=saf420_trailer
```

⇒ 判据链是：

```
VehicleExtension.playMotorSound(carNumber)               mmtr/game/fabric/.../data/VehicleExtension.java
    powered  = cars[0].getMmtrPowered()                  = false   （清单 powered:false）
    declared = cars[0].isMmtrPoweredDeclared()           = true    （清单那条路会显式标声明）
    mute     = shouldMuteMotorSound(true, false)         = TRUE    ⇒ 出力被喂成 0
    ⇒ feedDemand(..., 0) ⇒ isExcited(0, 0) = false ⇒ selectFor 返回 null ⇒ 牵引层一声不响
```

而"挂车静音"这条判据本身**没有错**：被牵着走的货车确实没有电机。
错的是**它在动车组上也会打到司机**——SAF420 是 `Tc–M×6–T×2–Tc`，**控制车就是拖车**。

**修法（口径）**：**谁在操纵，谁就听得到。**
`mute = 是挂车 && 听者不在这一节的操纵位上`。依据不是"多算一台电机"：
喂给音效的出力本来就是**整列口径**（`Vehicle.getMmtrMotorForceN()` 是列车级读数，
每节车喂的是同一个数）——所以让司机这一节响，是把这条**列车级**读数还给唯一在听它的人。
与"驾驶位忽略距离衰减"是同一条口径的两半。

新增纯函数 + 用例（含阳性对照，见 §4）：

```java
MmtrTractionSoundModel.muteTractionSound(hauledWagon, listenerAtControls)
```

## 1 距离衰减：机制是**从字节码读出来的**，不是猜的

先把它钉死，否则"忽略距离"就是在一个不知道形状的东西上做手脚。MC 1.20.4（yarn 映射的 merged jar）
里这条链只有三处：

```
SoundSystem.play(SoundInstance)                 ← 距离衰减**只在这里**写给 OpenAL
    float v = instance.getVolume();
    float maxDistance = Math.max(v, 1.0f) * sound.getAttenuation();      // getAttenuation() = sounds.json 的 attenuation_distance
    ...
    sourceManager.run(source -> {
        source.setVolume(adjustedVolume);
        if (instance.getAttenuationType() == LINEAR) source.setAttenuation(maxDistance);
        else                                         source.disableAttenuation();
        source.setPosition(...); source.setRelative(instance.isRelative());
    });

Source.setAttenuation(float v)                  ← 衰减参数就是这四个
    alSourcei(AL_DISTANCE_MODEL       = 0xD000, AL_INVERSE_DISTANCE_CLAMPED = 0xD003);
    alSourcef(AL_MAX_DISTANCE         = 0x1023, v);
    alSourcef(AL_ROLLOFF_FACTOR       = 0x1021, 1.0f);
    alSourcef(AL_REFERENCE_DISTANCE   = 0x1020, 0.0f);

Source.disableAttenuation()
    alSourcei(AL_DISTANCE_MODEL = AL_NONE);
```

复现命令（不需要游戏、不需要反编译）：

```powershell
$jar = Get-ChildItem -Recurse -File -Path sandbox\gradle-home\caches\fabric-loom\minecraftMaven `
       -Filter "minecraft-merged-1.20.4-net.fabricmc.yarn*.jar" | Select-Object -First 1 -ExpandProperty FullName
& env\jdk-21\bin\javap.exe -p -c -classpath $jar net.minecraft.client.sound.SoundSystem | Select-String 'Attenuation' -Context 4,8
& env\jdk-21\bin\javap.exe -p -c -classpath $jar net.minecraft.client.sound.Source     | Select-String 'setAttenuation|disableAttenuation' -Context 0,14
```

**两个必须记住的后果：**

1. **`AL_REFERENCE_DISTANCE = 0` 时逆距离式退化**（`ref/(ref+rolloff·(d−ref))` 在 `ref=0` 上分子分母同时为 0），
   曲线由 **OpenAL 实现**决定，不是 MC 规定的。所以本项**不去凑那条曲线**（凑也凑不准，而且换台机器就变）。
2. **衰减只在 `play()` 那一刻写下去**；之后每 tick（`SoundSystem.tick` → `Channel$SourceManager`）
   只更新 volume / pitch / position。⇒ **口径一变必须重新起播**，否则"人从车厢走进驾驶室"那一刻
   听到的还是老口径 —— 而这正是本项要改的那一件。

## 2 做法：换驾驶位就把整级关掉（规范保证，不依赖上面那条曲线）

`AttenuationType.NONE` ⇒ MC 调 `Source.disableAttenuation()` ⇒ `AL_DISTANCE_MODEL = AL_NONE`
⇒ **增益恒为 1**，任何 OpenAL 实现都一样（这是 1.1 规范里 `AL_NONE` 的定义）。
位置照常 `setPosition`，所以**左右/前后的声像保留**，丢掉的只有距离滚降。

| 文件 | 改了什么 |
|---|---|
| [`VehicleLoopingSoundInstance`](../../mmtr/game/fabric/src/main/java/org/mtr/mod/sound/VehicleLoopingSoundInstance.java) | 新增 `noAttenuation`；`getAttenuationType()` 在 true 时报 `NONE`；`setData` 里**口径变了先 stop 再起播**（记 `appliedNoAttenuation`） |
| [`MmtrVehicleSound`](../../mmtr/game/fabric/src/main/java/org/mtr/mod/sound/MmtrVehicleSound.java) | 新增 `setListenerAtControls(boolean)`，把口径推给**已经建出来的每一条**循环（牵引档 / 齿轮 / 两条走行层的每一档）；新建的走 `newLoop()` 统一带上口径 |
| [`VehicleSoundBase`](../../mmtr/game/fabric/src/main/java/org/mtr/mod/sound/VehicleSoundBase.java) | 新增 `setListenerAtControls(boolean)`，**默认空实现** ⇒ 对 BVE / legacy 无影响 |
| [`PersistentVehicleData`](../../mmtr/game/fabric/src/main/java/org/mtr/mod/data/PersistentVehicleData.java) | 新增 `setListenerAtControls(vehicleResource, carNumber, …)`（与 `feedDemand` 同一形状） |
| [`VehicleExtension`](../../mmtr/game/fabric/src/main/java/org/mtr/mod/data/VehicleExtension.java) | 在 `playMotorSound` 里判定并喂下去 |

### 判据只有一份

用的是**既有的** [`MmtrDriverSeat`](../../mmtr/game/fabric/src/main/java/org/mtr/mod/client/MmtrDriverSeat.java)
—— 它已经在回答"坐在操纵位上吗"（同时决定：能不能操作手柄、要不要向引擎报"我是司机"、
要不要把撞键的原版操作摘下来）。本项只多做**一次比较**：

```java
final MmtrDriverSeat.Seat seat = MmtrDriverSeat.current();
persistentVehicleData.setListenerAtControls(vehicleResource, carNumber,
        seat != null && seat.vehicleId() == getId() && seat.carNumber() == carNumber);
```

**没有新增第二套"我是司机"的判据**；`CONTROLS_RADIUS_M = 2.0 m` 那条门槛（notes/215）也照旧生效 ——
所以"站在车厢里"不会误判成司机，那节车照样按距离衰减。

### 范围：**只覆盖"我在操纵的那一节车"**（刻意）

不是整个编组、也不是"我所在的那节车"：
- 用户口径说的是**驾驶位**，而 `MmtrDriverSeat` 正好是它唯一已存在的判据；
- 别的车节（以及别人的车、站台上的车）保持距离衰减 —— 对他们是**对的**；
- 想放宽（例如"坐在哪节车就哪节车满音量"或"司机所在的整列都满"）只改上面那一行比较，其余不动。

### 成本

`MmtrDriverSeat.current()` 每个车节每帧一次（10 节车 = 10 次/帧）。它是 O(车数 + 锚点数) 的查表，
不载入任何资源；**没有为它加缓存**是刻意的 —— 缓存一旦与"人是否还在车上"错拍，症状是"下车后声音还是满的"，
那种 bug 比这点 CPU 贵得多。

### 2.5 ★ 同一条判据的第二半：**操控位豁免"挂车静音"**

"驾驶位 ⇒ 忽略距离"只解决了距离；现场第二轮报的 **"没有电机励磁音"** 是另一条路吃掉的，
而它用的**是同一条判据**（`MmtrDriverSeat`），所以两件事必须一起说清：

```
atControls = 听者就在这一节的操纵位上          ← 判据只有这一份
listenerAtControls(atControls)                ← 半一：这一节忽略距离衰减
mute = 是挂车 && !atControls                   ← 半二：这一节免掉"挂车静音"
```

半二的推导、证据与世界清单读数见 **§0.1**。三处实现：

| 位置 | 改动 |
|---|---|
| [`MmtrTractionSoundModel.muteTractionSound`](../../mmtr/game/fabric/src/main/java/org/mtr/mod/sound/MmtrTractionSoundModel.java) | **新增纯函数**（原来这条规则是调用点上的一个 `&&`，没法被用例钉住） |
| [`VehicleExtension.playMotorSound`](../../mmtr/game/fabric/src/main/java/org/mtr/mod/data/VehicleExtension.java) | **把算 `atControls` 提到算 `mute` 之前**（原来顺序反着，`mute` 根本看不到它） |
| 同上 | `reportHauledCarOnce`：这一节被判成挂车、以及**这次有没有被豁免**，各留一行痕（每辆车每一节一次） |

### 2.6 ★ 两个轴**正交**：速度定段、牵引力定音量

用户口径（第三轮）：

> 逻辑上励磁音并没有根据**当前速度（决定音频播放那一段）**以及**电机牵引力（决定播放大小）**做组合播放。

**说得对。**旧口径那条"负载轴"把速度混进了音量，一共三处：

| # | 旧代码 | 速度是怎么漏进音量的 |
|---|---|---|
| 1 | `byPower = |P| / P_max`，而 `P = F·v` | **同一个牵引力、速度不同音量就不同** |
| 2 | `byEffort = ratio · exp(−v / vBlend)` | 速度越高，牵引力对音量的影响被削得越小 |
| 3 | `motorAudible(v, 5)` 直接把音量压成 0 | 音阶门限本是"**段**合不合法"，却当成了音量开关 |

**改法**（两个方向都收窄到单一来源）：

```
选段：  selectFor(kmh, …)                       ← 只由速度（f₁ = v·转子系数 + 滑差）
         └ 门限挪进来：v < gate.vSmokeKmh ⇒ 没有合法的段（而不是"音量 0"）
音量：  MmtrSoundMix.tractionVolume(力轴)        ← 只由牵引力，入参里**没有速度**
         └ 力轴 = |F| / maxTractiveEffortN（沿用已有的 [官方] 额定位，不新增参数）
```

`loadAxis(...)`（三参、带速度）**已删除**；新增 `forceAxis(motorForceN, spec)` 与
`isExcited(forceAxis)`。旧代码里那个 `effortRatio` 现在就是力轴，两处同源。

**两处刻意的例外**（都是物理，不是混音串门）：

1. **力的符号仍参与选段**：带滑差的音效集里 `f₁ = 转频 ± 滑差`（力行加、回生减），
   符号会挪动频线 ⇒ 可能落到不同的段。本音效集 `slipHz = 0` ⇒ 选段**严格**只由速度定。
   用例里对这一点有专门一条（`assertNotEquals` 那段）。
2. **力为 0 = 惰行 ⇒ 根本没有段**（没有励磁就没有定子基波），这不是"按速度关音量"。

**顺带一处实打实的收益**：低速段音量回到满值（旧律的 `exp(−v/8)` 那一刀没了）——
满级位时 20 km/h 旧律 **0.55** ⇒ 新律 **1.0（+5.2 dB）**、10 km/h 旧律 **0.29** ⇒ 新律 **1.0（+10.9 dB）**。
"起步/低速听不到励磁音"最刺眼的就是这里。

**行为上也更干净**：松手柄不再让段被淡出（只是音量落到 0），再给力从**同一段**接着响，
不会"松一下、再给力就重新起播一次"。

## 3 混音表：[`MmtrSoundMix`](../../mmtr/game/fabric/src/main/java/org/mtr/mod/sound/MmtrSoundMix.java)

### 3.1 为什么要有这个类

在这之前音量散在三处各写一半：`MmtrVehicleSound.MASTER_VOLUME`、`GEAR_VOLUME`、
清单里的 `running.layers[].masterVolume`。而**"这几级乘起来是多少 dBFS"没有任何一处写下来** ——
于是"声音偏低"变成一个**没法回答**的问题：不知道是哪一级吃掉的，也不知道还有没有余量。

### 3.2 增益分级（从样本到耳朵）

| # | 级 | 谁决定 | 范围 |
|---|---|---|---|
| 1 | **ogg 样本峰值** | 烘焙链（`artifacts/kei2100-av417534959`） | 实测见 §3.3 |
| 2 | 层内律 | `MmtrTractionSoundModel`（负载轴 / 速度律 / 门限） | 0..1（负载轴可到 1.5） |
| 3 | **层基线 × 总出手量** | **`MmtrSoundMix`** | 0..1 |
| 4 | 换档淡化 | `MmtrVehicleSound` | 0..1 |
| 5 | 分类音量 × 主音量 | 玩家设置（Blocks / Master 滑杆） | 0..1 |
| 6 | 距离衰减 | MC → OpenAL（§1） | 0..1；**坐操纵位时整级旁路**（§2） |

`MmtrTractionSoundModel.volume(...)`（"负载轴 × 总音量"）**已删除**：层内律(2)归模型、
出手量(3)归混音台，**一个量只在一个地方乘**。调用点现在写
`MmtrSoundMix.tractionVolume(loadAxis(...))`。

### 3.3 实测的交付电平（写进代码，并由用例对着磁盘核）

| 层 | 最响那一档的峰值 | 出处 |
|---|---|---|
| 牵引 motor | **−25.47 dBFS** | `game/kei2100-upd-step01..23.wav` |
| 走行 roll | **−11.19 dBFS** | `game/run/roll-step01..23.wav` |
| 走行 aero | **−10.00 dBFS** | `game/run/aero-step01..23.wav` |

（ogg 与源 WAV 同电平 —— 编码不改幅度。三条由 `MmtrSoundMixTests` 逐条重量一遍；
`AUDIO-GEN-REPORT.md` §6 第 10 条也记着同一组数，并指出**走行层是被 −10 dBFS 的上限顶着的**。）

### 3.4 ★ 上一版这里**推理错了**：播放端**能**放大（`sandbox/openal-gain-probe/`）

> **错的版本**（保留下来是因为"错在哪"本身值得记）：我原来写"两条硬性质 ——
> ① 播放端只能衰减不能放大；② 绝对响度只由烘焙电平决定"。
> 依据是从 MC 字节码读到 `Source.setAttenuation` → `alSourcef(AL_MAX_DISTANCE, max(音量,1)×衰减距离)`、
> `alSourcef(AL_ROLLOFF_FACTOR, 1)`、`alSourcef(AL_REFERENCE_DISTANCE, 0)`，
> 又查到 OpenAL 1.1 规范里 `AL_MAX_GAIN` 默认 1.0，就**推论**出 `AL_GAIN` 被夹在 1。
> 推论的前半段都对，**结论是错的** —— 我把"规范允许什么"当成了"这个实现干什么"。

不猜了，直接量。用 **LWJGL 打包的那个 OpenAL Soft 1.21.1**（就是游戏实际用的那一个）：

```
PROBE: 渲染器 = OpenAL Soft          OpenAL 版本 = 1.1 ALSOFT 1.21.1
PROBE: 新建 source 的 AL_GAIN 默认 = 1.0
PROBE: 写入 AL_GAIN=0.45 ⇒ 读回 0.4500  ✅ 未被夹
PROBE: 写入 AL_GAIN=1.00 ⇒ 读回 1.0000  ✅ 未被夹
PROBE: 写入 AL_GAIN=2.00 ⇒ 读回 2.0000  ✅ 未被夹
PROBE: 写入 AL_GAIN=3.16 ⇒ 读回 3.1600  ✅ 未被夹
PROBE: 写入 AL_GAIN=8.00 ⇒ 读回 8.0000  ✅ 未被夹
```

⇒ **层增益可以大于 1**，"播放端补不了那一截"不成立，**不需要回烘焙侧重编码**。

**诚实边界**：读回值证明它**存**得下；规范把 `AL_MAX_GAIN` 默认定在 1.0，所以"最终会不会真的放大"
严格说是**实现相关**的（我把渲染结果落到 WAV 再量峰值的第二步探针没跑通 —— wave 后端在这台机器上开不起来）。
但至少这个实现不夹，而这正是游戏用的那一个。

**于是口径改成对两种情况都安全**：允许层增益超过 1（`MAX_LAYER_GAIN = 4.0` 只是防手滑的护栏），
**削顶由余量核算守**。若某个实现真的夹在 1，结果只是回到"用满烘焙电平"的响度，不会更差。

### 3.5 改了什么

| 项 | 前 | 后 | 依据 |
|---|---|---|---|
| `MASTER` | 0.45 | **1.0** | 它不承担平衡作用（三层同乘）⇒ 白丢 6.9 dB。这一截直接拿回来 |
| **`TRACTION`（新增）** | — | **2.2（+6.8 dB）** | ★「两种音效配比不一样」的旋钮：牵引层交付峰值比走行层低 14–15 dB（§3.3）。抬完 **−25.47 ⇒ −18.62 dBFS** |
| `RUNNING` | 1.0 | **0.9（−0.9 dB）** | 给上面那 +6.8 dB 让出余量；走行层本来就顶着链上那个**任意的 −10 dBFS 上限**，这一档很小 |
| 层增益的夹子 | `clamp01`（≤1） | **`clampLayer`（≤`MAX_LAYER_GAIN`=4.0）** | 承 §3.4：1.0 不是天花板 |
| 换档淡出的起点 | 写死 1.0 | **上一帧真正的音量** | 力轴 < 1 时从 1.0 开始淡出，换档那一瞬间会有一次**音量凸起**；被 0.45 压住过，顶到 1.0 就露出来了 |
| 层峰值常数 | （不存在） | **三个实测常数** | 让"混音表"与磁盘上的音频**可对账**（§4） |
| 接管日志标签 | "事件前缀 ← 资源目录" | 两个都打、各自标清 | 原来那个标签正好是 `SAF420_v41` 整套静音那个坑的形状（notes/402 §5） |
| 新增日志行 | — | `[MMTR-SND] 混音：…` | 让"声音多大"进日志，可核对而不是印象 |

**余量核算**（`worstCaseKeepsHeadroom()`）：三层同时到顶
= `1.0 × (2.2×0.0533 + 0.9×0.2757 + 0.9×0.3162) = 0.650` ⇒ **−3.74 dBFS，余量 3.7 dB**。

进游戏时日志里那一行长这样（实测跑出来的）：

```
[MMTR-SND] 混音：总出手量 1.00（+0.0 dB）· 层基线 牵引 ×2.20（+6.8 dB）/ 走行 ×0.90（-0.9 dB）
 · 交付峰值 dBFS 牵引 -25.47 / 轮轨 -11.19 / 风噪 -10.00（实测）
 · 三层同时到顶 -3.74 dBFS（余量 3.7 dB） · ★ 牵引层满力输出 -18.62 dBFS（= 烘焙峰值 +6.8 dB）
```

**单旋钮，两种听感各一条路**：

| 听下来 | 调哪 |
|---|---|
| 励磁音还是压不住走行 | 抬 `TRACTION`（每 +3 dB 约 ×1.41），抬完**必须**看余量 |
| 走行（轮轨/风噪）太吵、盖住别的 | 降 `RUNNING` |
| 整体还是小 | 先看玩家设置里的 Blocks / Master 滑杆；`MASTER` 已经是 1.0，再要更响只能抬各层基线 |

### 3.6 已不做的一件事（原计划，现在**不需要**）

原来是"回烘焙侧把牵引层那 14–15 dB 补回来、重编码 69 条 ogg、重打 `SAF420_v43.zip`"。
§3.4 的实测把这个方案**降级为可选**：播放端一个层基线就够，不用动资产、不用改任何 sha1。
留着的理由只有一条：如果哪天要**统一音频资产的绝对电平**（例如给别的车复用这套音效），
那时才值得回烘焙侧做一次口径统一的归一化。

### 4.1 新增的"为什么没声音"取证

在 §0.1 之前，"没有电机励磁音"在日志里**一个字都没有** —— 几种完全不同的来源长得一模一样。
现在有三个新读数，**一句话点出是哪一种**（都是"原因变了才说一次"，上限几条，不会刷屏）：

| 日志 | 说明什么 |
|---|---|
| `[MMTR-SND] 第 N 节被判成无动力挂车（显式声明 powered=false）⇒ 牵引音静音/不静音` | **§0.1 这一条**。被豁免时写「**不静音**：听者就在这一节的操纵位上」 |
| `[MMTR-SND] {base} 牵引层没在出声：…` | 选段那一支两种：① **在音阶门限以下**（`v < gate.vSmokeKmh = 5 km/h`，这一段不合法）；② 基波是 0。音量那一支一种：**未被励磁**（牵引力 0，**或本节被判成挂车、出力被主动喂成 0**） |
| `[MMTR-SND] {base} 距离衰减：听者在操纵位上 ⇒ 整级旁路（满音量）/ 回到常规距离衰减` | §2 那一半到底有没有生效 |

### 上车验收（要看的三处）

1. **人坐在驾驶位上**：自己的车声**不再随走位变轻**（走进车厢中部也不掉），
   且**控制车（Tc）也会出牵引音** —— 不再"一片安静"。
   坐在车厢里 / 站台上 / 别的车上时，衰减照旧。
2. **励磁音要"跟着手柄走"**：同一个速度下给力/收力，音量应当明显跟着变；
   同样的力、不同速度，音量应当**几乎不变**（这才是 §2.6 那条正交性的听感判据）。
   低速（10–20 km/h）满级位应当**明显比上一版响**（+5…+11 dB）。
3. **日志里三行**：接管行、`混音：… 牵引层满力输出 -18.62 dBFS（= 烘焙峰值 +6.8 dB）`、
   以及进/出驾驶室时的 `距离衰减：…` 那一行。
4. **若还是没声**：看 §4.1 那几行 —— 它会把原因指名（挂车静音 / 未被励磁 / 门限），不必再猜。
