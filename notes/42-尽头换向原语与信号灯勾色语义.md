# 42 - 尽头换向原语 + 信号灯勾色语义（实机问题两则）

> 用户实机报告两件事：① brush 勾选颜色后信号灯不再按占用变化；② 道岔 (-147,-169)
> 处列车"掉头"直接在岔心右拐约 158°，人字道岔不应允许该走法——正常应"开到前面
> （死岔尽头）换端再开回"（火车两头都能开）。

## ② 根因与修复：尽头换向（换端 flip）

- 现象成因：mmtr-junction-legs.json 残留进向表条目 (-147,-169)|via #9（80 限速对角轨），
  legs 声明含 x=-147 北段（相对 #9 来向约 158°，cos≈-0.93）。进向表语义=完全取代几何，
  于是引擎按表让车在岔心完成真实铁路不可能的发夹拐（人字道岔从一支只能去 stem/直臂）。
- 现实基准：真实人字岔上想掉头只能**开进直臂尽头的死岔（headshunt），停稳、换端、
  反向驶出**。MMTR 此前无换端能力（"引擎没有倒挡，掉头只能靠走轨形"）。
- 新增（engine）：
  - `MmtrMotionWalker.flipDirection()`：换端原语。前提=车头已停到当前轨 far 端（≤1 mm）；
    翻转 enteredFrom/ahead、offset=0、追加反向 PathData 回段，distanceM 单调累计。只认
    "死端"，不依赖 endOfLine 旗标。
  - `MmtrRunPlanner`：直行计划失败时自动尝试 `planToRailViaDeadEndFlip`——探测前方
    单续接走廊（几何/进向表有序 legs 恰 1 条），其 far 端必须真死端（仅此一轨）；计划 =
    开到死端（flipCumulativeM/flipRailHex）→ flip → 沿死岔轨反向回岔心 → 按有序 legs
    择路继续到目标（forkOps/forkMeters 照常产出，approach 节点按死端方向传入）。
    走廊有 ≥2 续接 / 死端不干净 → 拒绝并保留原 reason。
  - `Vehicle`：flip 待执行期间死端也是刹车目标（到缓冲前减速停稳）；停稳后执行 flip、
    重建 leg shadow（refreshMmtrMotionLegs）、清 blockedWaiting，自动运行继续驶向最终
    stop target（stop target 只在 flip 后生效）。
- 实机动作：删除 (-147,-169)|via#9 进向表条目（web upsert legs=[]，已持久化）。
- 测试：`MmtrDeadEndFlipTests`（合成人字：斜入 C / 死岔 D / 回程 U）：到死端 flip 合法、
    换端后沿 D 回岔心经 operator branch 0 直行上 U、距离单调、legs=3 段。
- 引擎全量测试绿（含新测试）。
- 待实机目视：TT 车到换向区改为"直进死岔尽头 → 停 → 换端 → 反向出岔上行"，
  观察渲染端车头在死端换向的视觉表现（180° 瞬时转向如不理想后续做平滑）。

## ① 根因与修复：brush 勾色后灯失灵

- 现象成因：MMTR 每轨注入独立唯一信号色（笔记 35，服务器权威占用通道）。d99a715 起
  渲染逻辑只在"未勾选任何颜色"（filterColors 空）时走 MMTR 占用链；一旦在
  SignalColorScreen 勾了 16 色板中的任一颜色，就退回 MTR 原版"颜色匹配"分支——而
  MMTR 唯一轨色永远不会等于用户勾的色板颜色 → 灯不再随占用变化（看起来"设置无效"）。
- 修复（fabric，RenderSignalBase）：灯显示恒走 MMTR 占用链（红=保护轨占用，单黄/双黄=
  前方 1/2 轨占用，绿=clear）；勾选颜色只保留影响调试色条的显示宽度（持轨道工具可见），
  不再影响灯头占用显示。注释说明 MMTR 唯一轨色与 legacy 色板不兼容的来龙去脉。
- 后续：如果用户目标是"这盏灯显示某条指定轨道的信号"（2 格外/读另一侧），那是
  mmtr-signals 的 BOUND 覆盖绑定 → 渲染接入（A2 联锁显示片），与颜色勾选无关。
