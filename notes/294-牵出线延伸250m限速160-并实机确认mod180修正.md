# 294 · 牵出线往 +Z 延伸 250 m / 限速 160 —— 顺带第一次实机验证 mod 180 修正

> 用户口径（2026-09-25）：**「z=292 往+z继续铺限速160的轨道距离250m」**。
> 承接 notes/293（地基已铺到 z=640），这一轮把**轨**补上。

## 1. 铺了什么

`sandbox/build_lead_extension_rails.txt`（2 条 `rail add`，走 `push_rail_commands.py`）：

```
rail add -107 65 292 -107 65 542 --speed=160
rail add -102 65 292 -102 65 542 --speed=160
```

| 项 | 值 |
| --- | --- |
| 起止 | `z=292 → z=542`，**250 m**（542 − 292） |
| 类型 | **普通轨**（没加 `--siding`），所以 `--speed=160` 生效 |
| 引擎回报 | `(-107,65,292)→(-107,65,542)  普通  限速 160/160  长 250 m`（-102 同理） |
| 起点 | z=292 是 notes/289 留在牵出线南端的**出口节点**，本来就在 |
| 终点 | z=542 由 `rail add` 自己放节点方块 |

## 2. ✅ 第一次实机确认：mod 180 修正真的生效了

notes/288 §5 改的 `MmtrCommandExecutor.resolveNodeState`（方位按 **mod 180** 比较），
上一轮没重启所以一直"未生效"。而 16:27 那次重启**把它编译进去了**：

```
源码     MmtrCommandExecutor.java   2026/09/25 15:50:47
class    MmtrCommandExecutor.class  2026/09/25 16:27:00   ← 比源码新
日志     > Task :fabric:compileJava   （不是 UP-TO-DATE）
```

**实机判据**：沿 Z 的直轨两端，四个节点全部

```
mtr:rail[facing=false,is_22_5=false,is_45=false,is_connected=true,waterlogged=false]
```

包括新放的远端 `(-107,65,542)` 与 `(-102,65,542)`。
按**旧代码**（0..360 比 0..157.5），远端方位 270° 会落到 0° ⇒ `facing=true`、横 90° ——
也就是 notes/288 §5 用户当场指出的那个毛病。**这次没有了。**

## 3. 出口信号灯自动"接上"了新轨（notes/292 §2 的预言兑现）

notes/292 §2 记过：两条牵出线在 z=292 是死头，朝南那盏出口灯"面朝方向上没有腿"、
退回全部腿、和朝北那盏挤在同一段 50 m 上。**铺完新轨后自动分开了**：

| 灯 | 朝向 | 现在守的轨 |
| --- | --- | --- |
| `(-109,67,291)` | 朝南 0° | **`(-107,292)→(-107,542)`，250 m，从弧 0 起** ← 新接上的 |
| `(-109,67,293)` | 朝北 180° | `(-107,242)→(-107,292)`，50 m |

`-100` 那两盏（牵出线 B）同理。四盏状态全 GREEN。

**没有任何手工绑定** —— 全是引擎按几何重算的（`模式=AUTO`）。
