## 1. B2：按 G 进驾驶室

### 1.1 三条设计原则（都是 notes/184 §6 里被删掉那一层踩出来的）

**① 谁写"骑乘坐标"只有一个答案：`VehicleRidingMovement`。**
`MmtrCabInteraction` 只管三件事：**瞄的是哪个驾驶室**、**给引擎发请求**、**给玩家反馈**。
它**不碰**玩家的位置 —— 位置由 `VehicleRidingMovement.mmtrEnterCab(...)` 写。
旧版本是自己写骑乘字段的，这正是那层代码没法推理的一半原因（184 §6 #2/#3）。

**② "是哪个驾驶室"只能有一个搜索。**
`MmtrInteractPrompt.findCabTarget(player)` 就是画 `[G] 进入驾驶室1` 那个提示用的同一次搜索。
两边各算一次，结果就是**玩家按下去拿到的是标签旁边那个驾驶室**。所以现在提示层和交互层**共用同一个函数**，
`Candidate`/`CabTarget` 里带上 `vehicleId / carNumber / cab / carTransform`。

**③ 判不判定由引擎说了算，客户端不复制规则。**
请求走 `PacketMmtrCabOp` → 引擎命令 `cab <vehicleId> <car><A|B> <crew>`。
物理闸门是引擎的：**必须是 MMTR 编组体车**、**必须停稳（speed == 0）**、**驾驶室必须空闲**
（引擎的**系统钥匙**会被顶掉，**别的乘务员的钥匙不会被顶掉**）。
客户端**不重写**这些规则 —— 复制一份必然和引擎漂移，然后在玩家面前当场对不上。
拒绝怎么告诉玩家？**看镜像状态**：`getMmtrActiveCabFromSync()` / `getMmtrCabKeyHolderFromSync()`，
`CONFIRM_MILLIS = 1500` 之后判定"钥匙持有人是不是乘务员钥匙"，是就报"完成"，否则报
"需停稳 / 驾驶室空闲 / 编组体车"。这个判据就是**后面驾驶闸门要用的同一个判据**。

### 1.2 键位与朝向

- 键位：`MMTR_CAB_INTERACT = GLFW_KEY_G`（`key.mmtr.cab`）。同键再按一次 = **拔钥匙**（
  发 `LEAVE` + `VehicleRidingMovement.mmtrLeaveCab()`），这也是"司机的拔钥匙"动作。
- **上车朝向**：`mmtr_seat` 锚点的法线是**行车方向**，所以世界朝向 = 这个**车体局部**向量过**车自己的变换**：
  `carTransform.transformForwards(...)`，再按 MC 的实体 yaw 约定 `look = (-sin(yaw), 0, cos(yaw))` 反解 yaw。
- **位置**：`MmtrVehicleAnchors.cabView(anchors, cab)`（车体局部的地板点 + 朝向）交给 `mmtrEnterCab`。
- 进驾驶室后 `movePlayer` 的 `speedMultiplier = 0`（在车上不能自己走），`leaveRide()` 是**唯一**清理
  驾驶室状态 + `isHoldingDriverKey` 的地方。

## 2. BR101 仪表

### 2.1 新增 `gauge`：会动的指针表

原来的控件里只有 `speed`（一个数字）和静态的 `rect/circle/arc/line/text` ——
**静态图形拼不出会动的指针**，而机车台面没有指针就不是仪表。所以 `MmtrHudLayout` 加了 `gauge`：

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| `x`,`y` | — | 表盘圆心（面板比例，原点左下） |
| `radius` | — | 表盘半径（相对面板**高**） |
| `start`,`end` | `0`,`360` | 指针在 **0 与满量程**时的角度（逆时针从 +X 起算的度）。`end < start` = 顺时针扫 |
| `max` | **160** | 满量程 km/h（忘写也仍有可用指针，不是死的） |
| `ticks` | 0 | 主刻度段数；`> 12` 时每 5 格画长刻度，否则全按主刻度 |
| `tickLength` | 0.12 | 刻度长（相对高） |
| `labelEvery` | 0 | 每几格标一次数字（0 = 不标） |
| `labelSize`,`labelColor` | 0.13, `color` | 数字大小/颜色 |
| `lineWidth`,`color` | 0, 默认文字色 | 表盘弧 |
| `needleColor` | `#FFFF3B30` | 指针（默认红） |
| `needleWidth`,`needleLength` | 0.05, 0.94 | 指针宽（相对高）/长（相对半径） |

指针角 = `start + (end - start) * 速度 / max`，**两端都钳位** → 超速**顶在满量程**，不会绕一圈回到低速。

### 2.4 真正的发现：折面仪表要**按客户端的取景数学**再验一遍

`verify_facets.js` 验的是**打包器自己的展开坐标系**（沿折痕展开、累加偏移，数字自洽）。
**客户端不用这套坐标系。** 它对每个 facet 重算：

```
right = cross(up, normal)                    // 注意：锚点 JSON 里的 right 被忽略
side  = facingSide(position, normal)          // 车以原点为中心 → 法线指向原点的那一侧
局部 +X = side * right,  u0 在 −X, u1 在 +X   // 再沿局部 +Z 抬离锚面 3 cm
```

两套坐标系之间可以**连续地错开**，于是出现了两个"打包成功但游戏里不对"的形态：

1. **仪表台是剪切的平行四边形**（85.70°/94.31°，不是 90°）→ 已在 notes/193 修直；
2. 修直之后，**画布在两道折痕上不连续** —— 跨共边 u 从 `1` 跳到 `0.412`（图像被撕开/错一格）。
   真因是 Blender 里 `mmtr_hud` 面的**绕序**方向不一致；把绕序重做后
   `sandbox/panel_crease_check.js` 从 `*** DISCONTINUOUS *** @x=0.432, 1.532` 变成
   `CONTINUOUS`（canvas u[0,0.412] = 左翼、[0.412,0.760] = 中屏、[0.760,1] = 右翼，**u 朝司机右手增大**）。

**这两个症状在打包器自己的数字里全都看不出来，截图也只能说"看着不对"。** 所以加了
`tools/anchor-check/verify_panel_frame.js`：按客户端的方式摆**四个角**，落在同一点（≤ 2 cm）的两个角
必须拿到**同一个 (u,v)**；再按 **u 必须朝司机的右手方向增大** 判镜像。六项判据：

| | 判据 |
| --- | --- |
| P1 | facet 的 position/normal/up 有限、宽高 > 0、`u0 ≤ u1`、`v0 ≤ v1` |
| P2 | **折痕连续**：共点的两个角必须同 (u,v) |
| P3 | **u 方向不翻**：facet 各自的局部 +X 会随法线旋转（45° 折面就差 45°），所以**不要求平行**，但**不许反向**（点积 ≤ 0 即镜像） |
| P4 | **不镜像**：沿局部 +X（= 司机右手）排序，u 必须同序 |
| P5 | **展开比例**：折叠轴方向每个 facet 铺满 0..1；另一轴 `\|du\| × canvasWidthM == widthM`（v/heightM 同理），并且**不许有缝/重叠** |
| P6 | 一个锚点只能选出一侧（`facingSide` 一致且非 0，否则客户端画正反两份） |

**P4 是唯一有牙的那条**：全局镜像（`u → 1-u` 且保持 `u0 < u1`）**既连续、又正好铺满画布、也满足展开比例**，
P2/P3/P5 全绿，只有 P4 能发现。故障注入里专门放了这一例。

fixture 说明：老的 `fixture/foldfix.json` **不能**当这个用例的底料 —— 它是一段以原点为中心的 4 m 桩，
面板正好落在**车体中心面**上，`facingSide()` 根本选不出边（返回 0）。所以
`fixture/make_panelfix.js` 从**真实 BR101 包**里抽出两个 `mmtr_hud` 锚点写成
`fixture/stage-panelfix/`（纯 JSON、不带 OBJ，因为这几项判据是纯锚点算术）。`stage-panelfix/` **故意不被
.gitignore 忽略**（生成物 `stage/`、`stage-wipefix/` 才是）。

`selftest.js` 新增第三个 suite（5 例注入，全中）：
镜像整张画布 → `reads BACKWARDS`；单个 facet 的 uv 矩形沿折痕平移 → `TEARS at the crease`；
`canvasWidthM` 虚报 → `not proportional to the unfolded length`；单个 facet 法线反向 → `different sides`；
删掉 `canvasHeightM` → `canvasWidthM/canvasHeightM`。
