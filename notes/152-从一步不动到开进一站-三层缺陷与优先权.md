# 152 · 车从"一步不动"到"开进 1 站"：三层真实缺陷 + 优先权

> 用户的问题一路收窄："现在车停着不动的原因是什么" → "是不是根本没做让 AI 运行当前版本任务的逻辑"
> → "这就要谈优先级问题（00:05 那台优先）" → "车还卡在 -170,-60,-199"。
> 本轮把**从车场到 1 站站台这条路上挡着的每一层**都追到并修掉，最终现场读数是：
> **第一台车开出 207 m、车头到达 (-169.5,-305.5)（1 站站台前）**，第二台紧跟其后在咽喉按闭塞等待。
> 引擎 **676 通过 / 0 失败 / 4 跳过**；每一条修复都带红证；已停机部署。

---

## 1. 现场因果链（逐层剥开）

### 第 1 层：进路永远 SET 不了（"先有鸡还是先有蛋"）

```
[interlock] route=MAIN/PENDING rails=10 forks=5
  turnouts: (-170,-137)(-170,-161)(-170,-186)(-170,-199) holder=自己 ✓   (-170,-289) holder=-
  pendingRequests: 只有 4 处 —— **少了 -170,-289**
授权：RED mustStop=True  理由=进路未设好，停在出发信号前
```

申请侧是**接近锁闭**（只收眼前 `MMTR_APPROACH_LOCK_METERS=120 m` 内的道岔，后车因此不会抢前车还没用到的道岔），
而 SET 判定要求**整条进路的道岔全都持有** ⇒ 只要有一处在 120 m 外，进路永远 SET 不了；车不动，
窗口就永远推不过去。

**修**：`MmtrRouteRegistry.refresh(vehicleId, authority, pendingOps)` —— SET 只判**本车当前申请集**
（= 车正在接近的那一段），远端的道岔等车开近再进窗口、再申请、再验。
车辆两处调用点都把 `mmtrPendingPointOps` 传进去；旧的两参重载保留（其它调用方/用例行为逐位不变）。

**结果**：进路从"永远 PENDING"变成 **SET**，两处道岔都拿到。

### 第 2 层：通行优先权（用户裁定：00:05 那台先走）

逐进向的队列**早就有**计划时刻优先权（`Req.priorityMillis` → `pickNext`/`better`），
但**物理位置那一层没有**：它按到达先后，而且"位置归持有者"不许别人改 ⇒ 晚班车一旦按上位置，
早班车只能干等；几台车于是轮流按位置、轮流让位（现场实测的 ping-pong）。

**修**：
- `Physical` / `PhysicalReq` 都带上 `priorityMillis`；物理队列用 `pickNextPhysical`（计划时刻 → 到达序 →
  防饿死那一档，与逐进向**同一条口径**）；
- **早班车可以收回晚班车按着的位置**：`priorityMillis < holder.priorityMillis` 且**净空闸允许**（晚班车没压在岔区里）时，
  位置改判给早班车；晚班车排队等，不许抢回去。

**红证**：去掉优先权比较 ⇒ 新用例红。

### 第 3 层：车被"自己的影子"扣住（真正的死结）

进路 SET、道岔全拿到之后，读数变成：

```
车： 进路=SET  车速 0  授权=RED mustStop=True  理由=红灯：停在这架信号前（0 m）
下一区间 -172,-60,-222： 别人占=**False**  总占=True  占用者=**[它自己]**
全世界 95 个区间只有 6 个被占 = 5 台停在库里的 + 它自己
```

**没有任何别的车挡它**，扣住它的是它自己：车体压在岔区里/站在该区间内，而信号层问"前方占用"时
**没有把自己排除掉**：

- v2 区间占用那一层**有**排除（`isOccupied(..., excludeVehicleId)`）✓；
- v2 的**受限节点**那一档（`restrictedNodes`：净空被占 / 道岔未定）用的是**全局缓存、不排除任何车** ✗；
- v1 逐轨回退链里 `junctionRestricted(...)` 同样是全局那份 ✗。

**修**（收窄到只排除"足迹"这一条理由 —— 这是被 4 条既有用例逼出来的收窄）：
- `MmtrJunctionState.reasonExcept(...)` / `unclearedNodeKeys(..., excludeVehicleId)`：只把**自己的足迹**
  从"净空被占"里排除；"岔口没人决定"这类与足迹无关的理由照旧（否则红灯就不红了）；
- `MmtrSignalAspect.restrictedNodeKeysExcluding(vehicleId)`（缓存按"树签名 + 车 id"认），
  v2 走查与 v1 走查都改用它；
- v1 的**预留颜色通道保留不动**（`aReservedColourOnlyHoldStillShowsDangerOnAV2Rail` 这条用例明确要求
  它在 v2 轨道上继续说话 —— 我第一版把它一起跳掉了，红了 4 条，已收回）。

### 第 4 层：两台车同时出库，互相锁在净空区里

```
point -170,-60,-186 wantLeg=0 needPos=0 | lock=false holder=- phys=- 现位=无主
净空闸=岔区净空被占：轨 … 靠这个节点的 10.0 m 内有车足迹 —— 不许把道岔从车下抽走
queue=v-55427…@0 v12003…@0        ← 两台车各自排在对方后面
```

每台车的停车位都落在**别人要过的那处道岔的净空区**里（净空闸"不许从车下抽道岔"完全正确）。
而计划把出库那一步一律"发车前 5 分钟"派出去 ⇒ 咽喉里必然同时有两台。

**修**：`MmtrPlanDispatcher.YARD_DEPARTURE_GAP_MILLIS = 4 分钟` + 纯判据
`yardDepartureAllowed(now, lastYardDeparture)`：两次"出库那一步"之间至少隔这么久。
与优先权互补：一条排次序，一条隔时间。**红证**：把判据改成恒真 ⇒ 新用例红。

## 2. 现在为什么又停住（下一轮的活，本轮新发现）

第一台车开到 **207 m / (-169.5,-305.5)**（1 站站台前）后停住，理由是：
它要进的区间 `-145,-60,-169#2` 里**有两台车**：它自己 + `-6716286574583169110`。
后者是**被我上一轮的"收回任务"扫尾收掉活的那台车** —— 日志：

```
[MMTR-PLAN] 交路 L1：N=6 … 6 辆车 24 趟      ← 计划重算（我在观察脚本里重贴了密度表）
[MMTR-PLAN] 收回任务：这一版计划没有认领它（L1 已不在/已重排）→ 车 -6716286574583169110（L1/C1/001）
```

也就是说：**计划一变，正在咽喉里开的那台车的任务被收回，它就停在咽喉里，把后面的车挡住。**
"收回"这条规矩本身没错（那一步在新计划里确实没了/换了目标），错的是**时机**：
车正处在"停在哪儿都会挡路"的位置时不许撤它的活。

**下一步的修法**：收回任务前先看车——**在途/握着道岔申请的车不撤**，让它把这一步走完、停稳再收
（`World` 侧加一句"这台车现在是不是在动/还持有道岔"，`Simulator.mmtrReleaseUnclaimedPlanTasks`
与 `adoptFrom` 的孤儿分支都要过这一问）—— 与现场实测的口径一致："任务终态才收回"本来就是这个引擎的既有原则。

## 3. 本轮新增的只读出口（"看不见的状态修不好"）

1. `mmtr-trains` 每台车多四项：`currentRail` / `nextSection` / `nextSectionOccupiedByOthers` /
   `nextSectionOccupiedAtAll` / `nextSectionOccupants`（**占用者是谁**）。
   现场正是靠"别人占=False、占用者=[它自己]"这一句把"自己的影子"钉死的；
2. `MmtrDirectionalBlockService.occupantsOf(section, trees, excludeVehicleId)` —— 占用者 id 列表；
3. 等道岔的日志早已带 `net=`/`净空闸=`（notes/149/151）。
