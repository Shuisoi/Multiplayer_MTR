# 86 - 实机缺陷：连挂后的合并车无人持钥匙 → 永远无法再派车

> 承接 notes/83–85（实机验收）。本片是 notes/84 那趟派车失败（`ok:false`）的根因修复。

## 1. 实机证据

notes/84 里对**连挂后的合并车**派任务，`mmtr-dispatch` 返回 `ok:false`，服务端日志给出：

```
[MMTR-RUN] no plan for …: forward=walker has no current rail / ahead node |
            flip=flip: current rail not found | setback=setback: walker or target rail unavailable
```

而同一存档里其它停放车（987654 车场）派车是成功的。查 `mmtr-motion` 快照：

```
merged: activeCab=NONE, cabManned=false, cabKeyHolder=NONE      ← 合并车无人持钥匙
其它车: activeCab=CAB_A, cabManned=true,  cabKeyHolder=SYSTEM    ← 引擎占位钥匙
```

## 2. 根因

- `MmtrConsistWalker.railHex()` / `offsetM()` / `currentRail()` 在**无人持钥匙**时返回 `null` / `0`
  （设计如此：只有有人驾驶时"车头在哪儿"才有意义）；
- `MmtrRunPlanner` 恰恰要读 `walker.railHex()` 与 `aheadNode()` 才能规划 → 无钥匙 = 规划必失败；
- `MmtrCoupleSurgery` 合并时**只转移 CREW 钥匙**（`leadingHasCrewKey` / `trailingHasCrewKey`），
  而任务驱动调车的两列车通常都只有**引擎占位钥匙**（`KeyHolder.SYSTEM`，车场放置时就带）
  → 合并后 `isManned()==false` → 这列车**从此再也接不到任务**（对后续作业单是硬伤）。

同一类问题在**解挂**上也存在：切出的两半只有"含驾驶室那一半"拿到 CREW 钥匙，另一半无人。

## 3. 修复

| 位置 | 改动 |
| --- | --- |
| 合并（`MmtrCoupleSurgery`） | 合并后若 `!cabs().isManned()`，在**领车原来驾驶的那一端**插入引擎占位钥匙（`insertSystemKey`），与车场放置的惯例一致；方向不理想时由 C10「不可规划则反向一次」兜底 |
| 解挂 | 每一半若无人持钥匙，各自在 A 端插入引擎占位钥匙（驾驶室所在那一半仍保留 CREW 钥匙，不受影响） |

## 4. 用例与验证

- `MmtrTaskDrivenCouplingTests`：连挂完成后合并车 `isSystemKey()`、`railHex()` 非空，
  且**再规划一趟新任务可行**（`planToRail(...).feasible`）——正是实机失败的那一步。
- `MmtrConsistBodyCouplingTests.uncouplingConsistBodiesCutsAtTheSeam`：原断言"rake 半无人"改为
  "rake 半保留引擎占位钥匙、无 CREW 钥匙"（新语义）。
- 全量引擎套件 **470/0/2**（零新增失败）。

## 5. 端到端复验（真实存档）

同步新 jar（21:52）并重启 dev 服务端，开机重放连挂：

```
[MMTR-COUP] 连挂后合并车获得系统钥匙（CAB_B），保持可派车
[MMTR-COUP] 连挂完成: -3324537797497337662 + 796232162201679298 -> -3324537797497337662（3 节，48.0 m）
```

`mmtr-trains` feed：合并车 `cabKeyHolder=SYSTEM, cabManned=true, activeCab=CAB_B`（修复前是 `NONE/false`）。
对其派任务：规划器**已经能正常规划**，给出的拒绝理由变成了真正的几何原因

```
no plan for …: forward=target rail … is not reachable from the vehicle
             | flip=… | setback=… is not reachable with one reversal
```

（修复前是同一条命令直接报 `walker has no current rail / ahead node`。）目标股道本身是 46 m 死端支线、
与合并车所在的 187 m 长轨不相通，属**车场几何**而非缺陷；把目标换成可达股道即可派车。

> 结论：`SYSTEM` 钥匙 + 规划器可读 = 合并车重新回到任务层可调度状态。
