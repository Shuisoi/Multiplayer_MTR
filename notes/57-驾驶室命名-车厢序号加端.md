# 57 - 驾驶室命名：`<车厢序号><端>`（双端机车怎么办）

> 用户提问：双端机车（同一节车两个驾驶室）在建模软件里的 HUD / seat 面怎么命名？HUD 又该怎么显示？

## 建模侧：打包器约定已经支持

`pack_vehicle.js` 的锚点名规则是 **`<kind>[_<cab>][_<index>]`**：

| 锚点 | 含义 |
| --- | --- |
| `mmtr_hud[_<cab>]` | 仪表面（法线指向该驾驶室的司机） |
| `mmtr_seat_<cab>` | 座位点（走 sidecar JSON，Blender empty 不进 OBJ） |
| `mmtr_cabdoor_<cab>_<n>` | 驾驶室 `<cab>` 的第 n 扇司机门 |

`cab 1 = A 端，cab 2 = B 端；不写 cab = 单驾驶室模型（默认 1）`。

**双端机车就是同一节车里写两套**：`mmtr_hud_1`/`mmtr_hud_2`、`mmtr_seat_1`/`mmtr_seat_2`、
`mmtr_cabdoor_1_1`/`mmtr_cabdoor_2_1`，两套锚点 `carIndex` 相同、靠 `<cab>` 区分；
各自法线朝自己那头的司机（打包器可用 `flipAnchorNormalByGroup` 逐个翻）。

**客户端缺口**（本次修掉）：`MmtrVehicleAnchors.findHud(anchors, car)` 只按车厢找，
双端机车的第二个驾驶室会拿到第一个 HUD——视角与仪表面都落错位置。现在按 `(car, cab)` 查，
`cabView` 的 HUD 与 seat 都用**有效 cab 号**（镜像单驾驶室模型时用 cab 1 的锚点）。

## 显示侧：`<车厢序号><端>`

| 场景 | 名字 |
| --- | --- |
| 编组 A 端驾驶室 | `1A`（旧 `CAB_A`） |
| 编组 B 端驾驶室 | `8B`（8 节时，旧 `CAB_B`） |
| **双端机车**（第 3 节两个驾驶室） | `3A` / `3B` |
| 连挂后机车的内部驾驶室 | 机车在合并编组里的车厢序号 + 端 |

- 车厢序号 = MTR `vehicleCars` 顺序（1 = 车头方向第一节）；端 = A（朝车头）/ B（朝车尾），都是车体固定坐标；
- 驾驶室落在车厢边界时归属它**所在的那一端**的那节车（A 端驾驶室属于从这里开始的那节，B 端属于到这里结束的那节）；
- 不用"前/后"（随行进方向翻转）、不用"1 号/2 号"（编组里驾驶室数量不固定）。

## 落地

| 层 | 改动 |
| --- | --- |
| 引擎 | `Vehicle.enterMmtrCabAtCar(carIndex, towardA, crew)`（由编组体算弧长）；镜像新增 `mmtrCabCarIndex`/`mmtrCabEnd`/`mmtrCabArcM` 与 `getMmtrCabNameFromSync()` |
| 指令 | `cab <id> 3A` / `3B`（旧 `A`/`B`/`out` 不变） |
| 客户端 | `validCab` 不再只认编组两端：**任何载有该锚点的车厢**都是有效驾驶室（双端机车的第二个驾驶室、连挂后的内部驾驶室都能进）；提示语"按 G 进入 第3节 A 端驾驶室"；认领核对同时比对车厢序号 |
| HUD | 新增「驾驶室 3A」芯片（`NEON_BLUE`） |
