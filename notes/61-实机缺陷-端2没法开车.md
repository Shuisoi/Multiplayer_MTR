# 61 - 实机缺陷：端2 没法开车（方向相关的停车标志没随驾驶室切换清掉）

> 用户实机反馈（2026-09-09）：在端 1 开过车、走到端 2 后按油门车不动（"现在没法在端2开车"）。
> 引擎侧一处修复 + 一个回归用例；无模组侧改动。

## 根因

编组体行走器有两个**方向相关**的停车标志：

| 标志 | 含义 | 设置点 |
| --- | --- | --- |
| `endOfLine` | 前端撞到**死端**（前方无轨、也无可选的岔） | `advance()` → `extendSpine()`（`MmtrConsistWalker:567`） |
| `atTarget` | 前端已上任务目标轨，就地停 | `advance()` / `extendSpine()` |

两者都是"**以当前行进方向看**前端如何"的结论。行进方向由驾驶室决定（`cabs.travelsToward(End.B)`），
所以换到另一端后它们全部失效。原来只有**换端指令**（`changeEnds`，`MmtrConsistWalker:280-281`）会清掉它们，
而"人走到另一个驾驶室按 G"走的是 `Vehicle.enterMmtrCabAtCar` → `cabs.insertKeyAtArc`，
**不经过** `changeEnds` —— 标志留着。

实机日志完全对得上：

```
[16:22:49] [MMTR-DRV] motion authority halt on FFFF…FF57 at 0.0m (awaiting operator/task)   ← 端1 开到死端
[16:29:26] [MMTR] cab 2 of car 1 (vehicle -341542099384…, model saf101): seat car-local (-1.0, 0.9802, 5.04948)
[16:29:28] [MMTR-DRV] driver=… engaged override T1 B8 R0                                    ← 端2 给油门，车不动
```

`advance()` 开头就是 `if (… || atTarget) return false;`，循环里又 `while (… && !endOfLine && …)`，
于是端 2 的每一次推进都被拒绝 —— 车不动，不是钥匙问题，也不是驾驶室不认。

## 修复

`MmtrConsistWalker` 记住标志是给哪个驾驶室算的，驾驶室一换就作废：

```java
private MmtrCabState.Cab flagsCab = MmtrCabState.Cab.NONE;

private void syncDirectionFlags() {
    final MmtrCabState.Cab active = cabs.activeCab();
    if (active != flagsCab) {
        flagsCab = active;
        endOfLine = false;
        atTarget = false;
    }
}
```

调用点：`advance()` 开头 + `endOfLine()` / `atTarget()` 两个读取器。这样**任何**换驾驶室的路径都覆盖到：
走过去按 G（`enterMmtrCabAtCar`）、OP `cab` 指令（`enterMmtrCab`）、`cabs.insertKey*` 直接插钥匙、
以及原来的 `changeEnds`（它自己的清理保留，成了冗余但无害）。

## 回归用例

`MmtrConsistVehicleMotionTests.takingTheOtherCabAtTheDeadEndLetsTheConsistDriveBack`：

1. 把 1 节编组体放到末轨 r2 靠近死端处，端 2 上钥匙，油门 → 车头撞死端停住，断言 `walker.endOfLine()`；
2. 同一乘务员用 `enterMmtrCabAtCar(0, true, crew)` 走到**同一节车的另一端** → 断言 `activeCab = CAB_A`
   且 `walker.endOfLine()` 已清；
3. 再给油门 → 断言 `walker.distanceM()` 前进 > 0.5 m（修复前恒为 0）。

日志证据（修复后）：`motion seg=…0014 offset=20.0m → authority halt`，随后
`offset=17.87 → 0.84 →` 换到前一条轨 `offset=16.34 …`，即车确实倒着退出了死端。

## 同批反馈的另外两件事（未在本片处理）

1. **倒挡**：现在是**红线**（commit `748a349`「火车不能倒车」）—— `Vehicle.applyMmtrControl` 把
   `reverser < 1` 强行改回 1（`Vehicle.java:1310-1314`），行进方向只由 `activeCab` 决定，
   设计文档也写明 `ControlState.reverser` 对 motion 车**继续忽略**（运动系统设计 §62、§323，不变量 I3「距离单调/无倒挡」）。
   要"端一端二都有倒挡"就得改这条红线：建议的最小语义 = **换向器只在停稳时可动**（与换端同门），
   `-1` 表示车尾在前（不换驾驶室），`0` 中立，`1` 车头在前；实现上给行走器加一个"行进方向翻转"位
   （`travelReversed`），并保持"同一方向内距离单调"。
2. **驾驶室钥匙开关**：用户口径"端 1 开着时跑到端 2 再开，端 1 自动关"。
   `Vehicle.enterMmtrCabAtCar` 已经支持同一乘务员换到另一驾驶室（只拒绝**他人**持钥匙，
   `Vehicle.java:1504`），而游戏内按 G 走的正是这条路；`enterMmtrCab(A/B)`（OP 指令）仍拒绝已有钥匙。
   待办：把 OP 那条路也对齐（同一乘务员可自动关掉旧端），并在换驾驶室时一并同步镜像/HUD。
