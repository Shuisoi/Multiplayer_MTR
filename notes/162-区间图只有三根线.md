# 162 = 区间图只有三根线（重复绘制 + 条位置偏了半像素）

> 用户 2026-09-15：「区间图是一根 6px 的线，1-2、4-5 是用于显示轨道区间的，
> 也就是说**绘图只有三根线**，现在有 5 根」。

## 一、为什么会有 5 根

上一版 `SectionLayer` 给**每个方向的每个 span** 画了**两条**状态条：

```ts
// 远心那条（|5 px|）
result.push({side: offsetSvgPath(path, offset)});
// 近心那条（|2 px|）—— 注释写的理由是"两根轨并排时两侧都看得出状态"
result.push({side: offsetSvgPath(path, nearOffset)});
```

规格是"**线心的两侧各一个方向**"，而不是"每个方向两侧各画一条"。于是双向轨上出现：
线心 + 方向 A 的两条 + 方向 B 的两条 = **5 根**，一眼就能看出来。

**修法**：每个方向的区间只画**一条**，写在线心的哪一侧由方向决定
（`sideOfDirection` 按法向符号分侧）⇒ 线心 + 两侧各一条 = **三根**。

## 二、顺带查出：条的位置偏了半个像素

规格里的"1-2、4-5"说的是条**占**第 1–2 px 与第 4–5 px，所以**条中心**在 **1.5 与 4.5**
（条宽 2 ⇒ 覆盖 0.5–2.5 与 3.5–5.5）。而规格表里写的是 2 / 5（覆盖 1–3 与 4–6）：

- 外侧那条的外缘正好到 6 px —— **压在线心边缘上，没有余量**；
- 内侧那条与线心的白边叠了 2 px。

改成 1.5 / 4.5 之后：两条都落在线心内（4.5 + 1 = 5.5 ≤ 6）、两缝之间留 1 px，
线心两侧各一条。

## 三、验收（`sandbox/check-web-section-three-lines.ps1`）

状态条是**线心按法向平移**出来的，所以判据可以直接量几何：条上每个点到它那根线心的距离
必须**恒定**、且等于规格值。匹配"条 ↔ 线心"用"到哪个线心折线的距离恰好等于那个偏移"来判。

5.35× 下实测：

| 判据 | 结果 |
| --- | --- |
| 线心 | 96 条（每根被区间覆盖的轨一条），宽 5.350 px = 规格 6 × 倍率 0.892 |
| 状态条 | **173 条 = span 数**（每个方向的区间一条；上一版是 2× span） |
| 条到线心的偏移 | 139 条全部匹配上，偏移**极差 0.000000 px**，= 规格 1.5 × 0.892 = 1.338 px |
| 条宽 | 1.783 px = 规格 2 × 0.892 |
| 两侧分布 | 正向 74 条 / 负向 65 条 ⇒ 线心两侧各一条 = 三根线 |

规格值由组件挂到图层上（`data-core-width` / `data-stripe-width` / `data-stripe-near` /
`data-stripe-far`），检查脚本**直接读它们**，不把"规格是多少"再抄一遍 ——
抄一遍就会出现"规格改了、检查还在按旧值判"（这次就发生过一次：改 2 → 1.5 后检查立刻报
"与规格差 25%"）。

## 四、留着的那个数

`stripeFar = 4.5` 现在没有被绘制用到（两侧的条用的是同一个 `stripeNear`，
因为 `stripeNear`/`stripeFar` 与线心中心对称，两侧用哪个偏移结果一样）。
留着它是为了：① 规格表把"第 1–2 px 与第 4–5 px"两个位置都写清楚；
② 单测用它证明"取 5 会压在线心边缘上"这个反例。

## 五、端点圆点（同一轮的后续要求）

> 用户 2026-09-15：「端点无需颜色，因为双向的区间不同，点需要落在区间线细线上不是基础线上」。

两条都改了：

1. **不带颜色**：原来端点用"该区间入口灯的颜色"（红/黄/绿/双黄），而双向的两个区间颜色本来就不同，
   一个节点上两个端点并排会看着像第三个东西。现在统一**白色**（`--fg`），
   它只表示"区间到这里为止"；属于哪个方向由它落在**哪一侧的状态条上**表达。
2. **落在状态条上，不是线心上**：端点是"这条区间的端点"，而区间画在法向偏移 1.5 px 的那条细线上。
   坐标改为**直接从那条已经偏移好的条上取**（`offsetSvgPath(...)` 结果的首/末点），
   而不是"从线心取再自己加偏移"—— 自己加偏移会在弯道处与条的真实端点错开
   （条的偏移是逐段算法向的）。

实测（5.35×，`check-web-section-three-lines.ps1`）：

| 判据 | 结果 |
| --- | --- |
| 端点颜色 | 202 个端点只有一种填充色 `rgb(255,255,255)`，不含任一 aspect 色 |
| 位置 | **202/202 落在状态条的端点上**，到条端点的最大距离 **0 px** |
| 对照 | 到**线心**的距离是 2.23 px（= 线心半宽 2.675 − 条中心偏移 1.338 的量级）⇒ 确实不在线心上 |
## 六、端点大小改为 1 px（同一轮第三次要求）

> 用户 2026-09-15：「点的大小也改为 1px」。

`DECAL_KINDS.endpointDot` 从 5 改成 **0.5（半径，画布坐标单位）** ⇒ 6× 时**屏幕上直径 1 px**
（线心 6 px、状态条 2 px 做参照：它只有线心的 1/6）。

### 单位这一步又踩了一次

`r` 与 `cx/cy` 必须是**同一套单位**（都是画布坐标），而这一层"画布坐标 × 倍率 = 屏幕像素"
（6× 时正好相等）。第一版我按"直径 ÷ 2 × 6 ÷ 倍率"再换了一次，量出来屏幕上直径是 **6 px**
（差了 6.7 倍）—— `check-web-section-three-lines.ps1` 的"屏幕直径 = 规格 × 倍率"这条判据当场抓住。

顺带把描边从写死的 `1` 改成"半径的 0.4 倍"：写死像素时，1 px 的点加 1 px 描边就只剩描边了。

实测（5.35×）：端点屏幕直径 0.892 px = 规格 1 px × 倍率 0.892（误差 0.0%）。
