# 81 - A3 AWS 绑定信号显示

> 承接 notes/79–80（A2 信号 = 进路 × 闭塞，引擎与游戏内同一规则）。设计：
> `docs/01-设计/行车控制-低速区信号道岔任务集成-设计.md` §2 A3「AWS 挂点（低速区）」：
> 触发条件从"固定距离"改为与**信号显示/限速对象**绑定；本信号非绿（红/黄）→ 进警示，绿 → 复位；
> 未确认窗口按现实对齐（2~2.5 s）。

## 1. 改之前

`Vehicle.tickMmtrAwsWarning` 的触发条件是**距离启发式**：在 75 m 触发带内存在"受限边界"（S1 占用停车点
或前方更慢的轨）就响。它看不见**黄灯**——占用在两轨之外（双黄）时 `mmtrBlockStopM` 还是 MAX，不会响；
也看不见"信号本身"是什么显示。

## 2. 本片交付

| 件 | 内容 |
| --- | --- |
| `MmtrSignalAspect.aspectFrom(railHex, entryNode)` | **方向敏感**的显示查询（"我这头看这架信号机是什么显示"），含 PENDING 进路压红规则；`aspectOf` 重构为它的两端取最严 |
| `Simulator.mmtrSignalAspectView()` | 缓存信号视图（rails-signature 门控，与信号颜色同一套）；`mmtrRefreshSignalAspectView()` 每 tick 在 rail tick 之后刷新一次 |
| `Vehicle.tickMmtrAwsWarning` | 触发 = **即将通过的那架信号机**：取 `peekNextRail()` 的显示（无下一轨则取当前轨），**非绿且在本车行进方向的距离空间里进入触发带** → WARN；绿 → 清除。更慢的下一轨（限速起点）与 S1 占用停车点仍保留为触发源 |
| `MmtrRunPlanner.remainingToAheadNodeM` | 提升为 public（A3 需要"到信号机的方向感知距离"，与规划器同一套折返语义） |
| `MMTR_AWS_ACK_WINDOW_MILLIS` | 3000 → **2500 ms**（A3 按现实 2.5 s 对齐） |

### 语义（本片定案）

1. **信号机是挂点**：AWS 警示属于"正在接近的那架信号机"，不属于某个抽象距离；显示用 A2 的
   `aspectFrom`，因此天然带上"进路收窄分岔"与"PENDING 压红"两条 A2 规则。
2. **黄灯也会响**：单黄/双黄都是"本信号非绿"，占用在两轨之外时照样响（旧规则漏掉的情形）。
3. **绿灯复位**：显示回到绿即清除警示与已确认指示。
4. **在信号机之间行驶不重复响**：离开上一架信号机的触发带后警示清除；进入下一架信号机的触发带（又是非绿）
   重新响 —— 与"司机在每个 AWS 磁钢处按一次"的现实节奏一致（用例里模拟了这段"清—再响"）。
5. **调车抑制、TPWS 兜底、窗口到期制动**三条既有语义不变。

## 3. 用例与验证（引擎）

`MmtrAwsWarningTests` 5 例（3 旧 + 2 新）：

- 旧三例（占用告警 → 未确认 SPAD；确认后停在边界不 SPAD；自动运行无司机告警）**未改动即通过** ——
  占用停车点仍是触发源，行为不回退。
- 新 `cautionTwoBlocksAheadWarnsAtTheSignal`：占用在第三轨（B 干净、C 被占）时，列车**仍在 A 轨**、
  在信号触发带内即告警 —— 这正是旧规则看不见的单黄情形（此时占用停车点远在触发带之外）。
- 新 `greenSignalClearsTheAcknowledgedWarning`：车在 C 前的占用停车点停稳、指示已确认；C 清空后
  信号转绿 → 警示与已确认指示同时清除。
- 测试同时把"占用"写进**两个通道**（共享占用树 + 该轨的信号色 hold），因为真实列车两条都会写。

全量引擎套件 **464/0/2**（本轮 +2 例；另有并行会话 +1 例，零新增失败）。
