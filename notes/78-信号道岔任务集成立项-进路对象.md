## 1. 为什么先做进路对象

设计文档 §1 把缺口写得最清楚的一行是：

| 现实角色 | MMTR 组件 | 现状 | 缺口 |
|---|---|---|---|
| 进路意图（车要去哪） | `MmtrTask` / mission 计划 | 已有（每车现算路线） | **无"进路"状态对象，信号读不到** |

A2「信号 = 进路 × 闭塞」与 S5「进路原子锁」都要求同一个前提：**"这条进路是否已经为这列车设好"必须是一个可查询的对象**。
现在这些信息散在 `MmtrRunPlanner.Plan`（`routeRailHexes`/`forkOps`）、`Vehicle.mmtrPendingPointOps`、
`MmtrPointAuthority`（holder/queue/lock）三处，信号层无法读，也没有"SET / PENDING"这个二值状态。

于是本片（R1）只做一件事：把"进路"变成一等对象，且**状态永远由道岔权威派生**（不复制状态机）。

## 2. 本片交付

| 件 | 内容 |
| --- | --- |
| `mmtr/route/MmtrRoute` | 进路描述：`vehicleId`/`owner`/`kind(MAIN\|SHUNT)`/有序 `railHexes`/`forks{node,via,leg}`/`targetRailHex`/`requestedMillis`；派生状态 `established` + `stateReason`；`coversRail`、`getEntryRailHex`、`sameMovement`（重试不churn 身份） |
| `mmtr/route/MmtrRouteRegistry` | 每车一条进路；`request`（同一 movement 保留原对象）/`refresh(vehicleId, authority)`（由道岔权威重算 SET/PENDING，理由复用 `MmtrRunPlanner.describeForkWait`）/`release`/`routesOverRail`（只返回 SET 的，按 vehicleId 定序）/`snapshot` |
| `Simulator.mmtrRoutes` | 进程内登记表；`deleteMmtrVehicle` 连带清进路 + 道岔持有 + 调车授权（原先只删车） |
| `Vehicle` | 武装时 `request` 进路（先发布再申请道岔 → 申请期间是 PENDING）、**每 tick** `refresh`（不只在武装后：等锁期间道岔被人工锁上也要立刻回到 PENDING）、终态 `release`；新增 `getMmtrRoute()` |
| `SystemMapServlet` | 每列车带 `route{state,kind,entryRail,targetRail,railCount,forkCount,rails[],stateReason}`；顶层新增 `routes[]`（SET 与 PENDING 全给，供运营台/联锁视图） |

### 语义（本片定案）

1. **SET = 这条进路需要的每一个道岔现在都握在本车 owner 手里**；空道岔的进路（直线）请求即 SET。
2. **PENDING 不进 `routesOverRail`** —— 未设好的进路不给任何"允许信号"。
3. 人工锁定/他人持有时理由点名道岔与原因（`lock=true` / `holder=v2@1`），与 notes/76 的等待诊断同源。
4. 进路状态**只读派生**，`MmtrPointAuthority` 仍是唯一权威；两边不可能不一致。

## 3. 用例与验证（引擎）

- `MmtrRouteRegistryTests`（8 例）：空道岔进路即 SET；缺一个道岔保持 PENDING 且点名 wantLeg；
  人工锁定 → PENDING（含 `lock=true`）→ 解锁 SET；他人抢占 → PENDING（含 `holder=v2@1`）；
  `routesOverRail` 只列 SET 且按 vehicleId 定序；同 movement 重试保持同一对象、改 kind 则替换；release 清干净。
- `MmtrRouteVehicleTests`（4 例，真实 `Siding`/`Platform`/道岔网络）：任务武装即发布进路（MAIN、入口=停放轨、
  目标=站台轨、覆盖 3 条轨、2 个道岔、SET）；道岔被人工锁定 → 进路 PENDING 且不武装，解锁后 SET；
  有调车授权时 kind=SHUNT；删车连带清进路与道岔持有。
- 全量引擎套件 **454/0/2**（87 类；上一轮 442/0/2，+12 例，零新增失败）。
