## 1. 诊断：现在到底哪一块不是物理

| 环节 | 状态 | 位置 |
| --- | --- | --- |
| 牵引曲线 | **已物理**：恒力矩到折点 → 恒功率 `a₀·v_bp/v`，再减阻力 | `MmtrPhysics.tractionAcceleration` |
| 运行阻力 | Davis 形态 `A+Bv+Cv²`，但量纲是 m/s²（不是牛顿，也没有质量） | `MmtrPhysics.resistance` |
| 服务/紧急制动 | **常数**：`serviceBrakeDecelerationMps2 × 缸压`，与速度无关 | `ThreeHandle/Notch/Stepless` 三个控制器 |
| 无人自动巡航 | **常数加减速**（用户看到的就是这一支） | `Vehicle.simulateMmtrMotion` 的 `autoActive` 分支 |
| 多车节 | 把各车 m/s² **当力**加权求和 ⇒ 说明代码本来就想做"力" | `MmtrComposition` |
| 坡度 / 曲线 / 黏着 | **完全没有**（轨道有 Y/倾角/曲率数据，纵向模型没读） | `Rail` / `RailMath` |
| 积分器 | **已正确**：10 ms 定步长 + 梯形距离，不用动 | `ConsistDynamics.advance` |

结论：缺的是"**力这一层**"（质量、功率/牵引力上限、制动力–速度、黏着、坡道、曲线），
以及**正向/反向两套接口共用同一个模型**。

## 2. 阶段 1 做了什么（本轮，行为不变）

### 2.1 新模块 `org.mtr.core.mmtr.physics.DynamicsEnvelope`（纯函数）

**反向半**：由"还剩多少米"反解"现在需要多大减速度 / 最多能进多快"。

```java
brakingDistance(v1, v2, decel)          // v1 → v2 需要多少米
requiredDecel(v1, v2, distance)         // 这些米里减到 v2 需要多大减速度
maxEntrySpeed(distance, vTarget, decel) // 反解：这段路最多能进多快（规划器要的那个口）
requiresBraking(v, vTarget, distance, decel, margin)   // 现在就该动手了吗
usableDecel(v, vTarget, distance, decel)               // min(所需, 可用)，直接喂积分器
isPast(v, distance)                                    // 已经越过且还有速度
```

**余量的方向**（很容易记反，已在 javadoc 与用例里钉死）：

- `margin < 1` ⇒ **更早**动手（留余量）→ 自动巡航 / LZB 用 **0.98**；
- `margin > 1` ⇒ **更晚 / 更宽容** → 保护层（SCR/TPWS）用 **1.05**。

**退化输入不产生垃圾**：不需要减速 → 0；没有制动能力 / 距离已用光 → `NEVER`（`+∞`），
它参与 `min` 会被可用减速度截断，所以速度不会被算成 `Inf/NaN`。

### 2.2 收敛掉的重复点（原来 `0.5·v²/a` 各写一遍）

| # | 位置 | 原来 |
| --- | --- | --- |
| 1 | `MmtrProtection.requiresProtection` | `0.5v²/d > a·1.05` |
| 2 | `Vehicle.simulateMmtrMotion` 自动包线判据（`autoBraking`） | `remaining < 0.5v²/a` |
| 3 | 同上：自动停点每拍减速度 | `min(0.5v²/max(r,1e-3), a)·dt` |
| 4 | 同上：前方更慢轨的提前量（自动巡航） | `0.5(v²−vT²)/max(d−v·dt, 1e-3)` |
| 5 | 同上：LZB 的提前量 | 同 4 |
| 6 | `Vehicle.mmtrTickDriverAuthorityTrip`（司机越界紧急制动包线） | `0.5v²/remaining > a` |
| 7 | `Vehicle.simulateMoving`（遗留分支）安全/硬停车距离与减速步 | `0.5v²/a` ×3 |

现在这七处全部走 `DynamicsEnvelope`。**观测不到的行为差异只有一处**：
第 3 处在 `remaining ∈ (0, 1e-3)` 且速度极低时，旧代码用 1e-3 兜底、新代码用真实余量
（差 ≤ 1 mm，方向上更早停一点点）。

未动：`Lift`（电梯/缆车的交通数学，另一域，`Siding.ACCELERATION_DEFAULT` 语义不同）——
留作下次顺手收。

### 2.3 用例（`DynamicsEnvelopeTests`，5 条）

1. **互为逆运算**：`requiredDecel(brakingDistance(...)) == a`、`maxEntrySpeed(brakingDistance(...)) == v`
   （多组速度 × 减速度 × 目标速度）—— 这是"规划器算出的刹车点"与"车真在那里停住"不分家的根据；
2. 物理量级与缩放：80 km/h / 0.8 m/s² ≈ 308.6 m；速度翻倍 ⇒ 距离四倍；
3. 退化输入：0 / `NEVER` / `isPast`；
4. **余量方向**：0.98 更早、1.05 更晚（就是上面那条容易记反的语义）；
5. **包线闭环**：用同一组函数跑"恒减速律停车 + 距离收口"，必须**正好**停在目标上（≤1e-9）。
