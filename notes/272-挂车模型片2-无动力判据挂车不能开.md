# 272 — 挂车模型 片 2：无动力判据（挂车不能开）

日期：2026-09-26 · 设计：`docs/01-设计/非动力挂车-车辆模型与编组对象-设计.md`（片 2）

片 1（notes/271）把"显式无动力"这件事**带进了数据**；片 2 让它在**物理与准入**上生效。

## 1. 三处判据（一处改规则、两处加闸门）

| 处 | 改前 | 改后 |
| --- | --- | --- |
| `MmtrComposition.toConsistType`（物理） | `anyPowered = 整列有没有 powered`；没有 ⇒ **第一节**借牵引 | 三态逐车判据：**显式无动力永不贡献牵引**；"没表态"的老兜底照旧，但整列最多一节，且那一节的车底得真能出力（`type.canPull()`） |
| `MmtrCarTypeResolver.resolve`（谁说话） | ② "能出力但不是动力车"这一档会把一节**被声明成无动力**的机车选成说话的车 ⇒ 整列按它的满牵引跑 | 该档加一条判据 `declaredUnpowered`（显式无动力）跳过；三态进 `keyOf`，改声明会触发重解 |
| `Vehicle.mmtrControlRefusalReason`（准入） | 只看"是不是司机位 / 有没有任务 / 别人在开" | 新增第一条：**整列车列没有任何能出力的车底 ⇒ 拒绝掌权**（理由点名"挂车不能开"）。判据与物理层**同源**（`MmtrCarTypeResolver.anyCarCanPull`） |

为什么准入层必须有这一条：**单节车不走"按车求和"的等效车底**（`tryInitMmtrController` 只在节数 >1 时折等效车底），
所以一节被声明成无动力的车仍会按它自己的车底跑 —— 只靠物理层拦不住。准入层是"挂车不能开"的真正落点。

## 2. 三态规则（实现就是这么写的）

```
一节车贡献牵引 ⇔
  ① 它 powered = true（不论声明与否）且 它自己的车底 canPull()      ← 正常动力车
  ② 或者：整列**没有任何**"声明有动力"的车，且它是**没表态**的车，且它的车底 canPull()
     —— 老兜底，整列最多一节（"一台车底一份牵引"，与 notes/247 同口径）
显式无动力（powered:false 写在数据里 / --unpowered）：① ② 都不适用 ⇒ 一分牵引都没有
```

## 3. 行为变化（写在明处）

* **`vehicle spawn … --unpowered` 收紧**：老行为是"一节都没声明动力 ⇒ 第一节借牵引"，所以
  `vehicle spawn saf101 saf101 --unpowered` 过去是**能开的**（第一节当机车）；现在**不能开**。
  这正是用户口径"挂车不能开"。要摆"一列能开的同型车"就直接写 `vehicle spawn saf101 saf101`（不写 `--unpowered`）。
* **单节显式无动力不再可掌权**：一节 `powered:false` 的车（例如单摆一台挂车）现在连司机都拿不到操纵权，
  日志会点名理由（`[MMTR-DRV] 操纵被拒：… 挂车不能开`）。
* 老夹具/老作业单（**不写** `powered` 的车列）**一位也没变** —— 这是三条用例分别钉住的。

## 4. 判据与证据（`MmtrConsistTractionMappingTests` 11 → 15 条，全过）

```
显式无动力 ×2（车型映射到能出力的车底）⇒ 牵引 0 kW/N、canPull()=false、质量照旧 168 t
单节显式无动力 ⇒ anyCarCanPull=false（准入拒绝）；单节没表态 ⇒ true（老行为）
没表态 ×2（powered=false）⇒ 仍只有一份 300 kN（老兜底）
说话的车：显式无动力的机车 + 后面的挂车 ⇒ 解析出 trailer（不让无动力机车说话）；
          没表态时仍解析出 loco（老数据零回归）
```
