# 192 · BR101 游戏里看不见的真因：**模型朝向**（Y 不是"上"）

## 症状

车辆刷出来、模型也**成功加载**（`obj=1006426 chars`、`groups` 里 `body` 只出现一次 ✓、properties 组名吻合 ✓），
但游戏里**看不见车**。

## 实测（打包后 OBJ 的包围盒）

| 模型 | X（宽） | **Y** | **Z** |
|---|---|---|---|
| saf101（正常显示 ✓） | ±2.50 | **1.00..6.00 = 高** ✓ | ±8.0 = **长** ✓ |
| br101（看不见 ✗） | ±2.50 | **±16.19 = 长（32 m）** ✗ | **−7.22..0 = 高（7 m）** ✗ |

10482 个顶点里 **10202 个 |Y| > 8**，极值属于 `car_body` / `interior` / `bogies` / `wiper_*`
（即**整个模型**）；锚点也一致 —— 挡风玻璃在 riding space 里 `y = ±15`（正是车长两端）。
⇒ 模型是"**长度沿 Y、高度沿 Z**"，相对 MTR 的约定**绕 X 转了 90°**（在 Blender 里它是立着的）。
结果：车被立起来，大半在地下/天上 → 看着就是"不显示"。

## 约定与判据

MTR：**Y 朝上、长度沿 Z**。导出用 `up_axis="Y"` + `forward_axis="NEGATIVE_Z"` 是对的
（`sandbox/br101_r48_export_obj.py:23`），所以问题在**模型在 Blender 里的摆放**，不在导出参数。

导出后自检（应当约等于）：

```
X = ±宽/2      ≈ ±2.5
Y = 1..6       坐在轨面上（客室地板约 1 m 高）
Z = ±车长/2    ≈ ±15.5（居中）
```

## 排查中已排除

- `[br101] No floors or doorways found in vehicle models` —— **saf101 也报同一句** ✓，不是原因。
- 孤立顶点：0 个（10482 个顶点全部被面引用 ✓）。
- 打包器的同名组覆盖：**已修**（`body` 从 ×5 → ×1 ✓，notes/191）。
- 服务端运行时会锁住 `run/resourcepacks/*.zip`，打包器 `EBUSY` 写不进去 → **必须先停服再打包**（notes/191）。

## 修法（2026-09-19）：改导出脚本的轴向声明，**不动模型**

用户在 Blender 里就是按 **MC/MTR 口径（Y 向上、Z 向前）** 建模的 ✓，所以不该转模型，
该改的是**导出参数**：Blender 场景自身的口径是"Z 向上、−Y 向前"，导出器会**按你声明的目标口径转换**。

```python
# sandbox/br101_r48_export_obj.py
- forward_axis="NEGATIVE_Z", up_axis="Y"     # ✗ Blender 认为"文件要 Y 朝上" -> 额外转 90°
+ forward_axis="Y",           up_axis="Z"     # ✓ = Blender 自身口径 -> 恒等转换，坐标原样导出
```

同一个脚本的**兜底分支**也要保住这两个参数：它原来在 `TypeError` 时把
`forward_axis` / `up_axis` 一起 `pop` 掉 ✗ → 退回 Blender 默认值（`NEGATIVE_Z` / `Y`）→
**又一次静默把车转歪** ✓ 已同时修正（只丢可能不存在的可选参数）。

判据：重新导出后 OBJ 的包围盒应为 **Y ≈ 1..6（高）、Z ≈ ±15.5（长）、X ≈ ±2.5（宽）**。

## 另一处（待确认）：导出帧

`br101_r48_export_obj.py:14` 是 `FRAME = 37`，而它自己的注释写
"`13` = 行程端点（phi = ∓46 度）；**`1` = 停放位**"。
按建模契约（docs §1.4）雨刷应**建在停放位**导出；实测 frame 37 时刀片确实贴在作用面端盖上
（离端盖 ~0.06 m ✓）所以能用，但若那个端不是"停放"那一端，车上的静止位置会反 ✗。建议导出用 `FRAME = 1`。
