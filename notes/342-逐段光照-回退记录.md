## 3. 顺带记录：一次**没走成优雅停机**的事故

回退前需要停服务端重编译，用项目自带的 `mmtr\game\mc-server.ps1 -Action stop`（走 RCON 25575，
配置里 `enable-rcon=true`、密码 `mmtr-dev-rcon`、端口在听）。结果：

```
rcon stop failed (调用“Write”…“Unable to write data to the transport connection: 你的主机中的软件中止了一个已建立的连接。”); forcing kill of pid 15472
```

服务端日志（`run/logs/latest.log`）末尾只有：

```
[12:53:10] [RCON Listener #1/INFO] Thread RCON Client /127.0.0.1 started
[12:53:10] [RCON Client /127.0.0.1 #2/INFO] Thread RCON Client /127.0.0.1 shutting down
```

**没有 `Stopping the server` / `Saving the world`** ⇒ `stop` 根本没送达，服务端是**被硬杀**的。

- **后果评估**：引擎数据（`world/mtr/...`）在被杀前 7 秒刚落盘（`12:53:03`），最多丢 ≤30 s 的引擎状态；
  重启后服务端**干净起来**（`Done (3.360s)`），`latest.log` 里 **没有任何** `corrupt` / `Chunk file` / `region file` 记录，
  引擎也报回 `vehicles=10` ⇒ **没有观察到损坏**。
  （附：我曾用一个"region 文件长度必须是 4096 倍数"的判据判"可疑 41/113"，**那是错判** ——
  09/25、09/26 的老文件同样不满足，说明本机这个判据不成立；真正的判据是**启动日志里有没有区块损坏记录**。）
- **待办**：`mc-server.ps1 -Action stop` 的 RCON 握手在本服上**不工作**（连上就断）。
  下次要优雅停机，得先修 RCON 或改用引擎自己的停机通道（`mmtr-stop.request` / 引擎控制台）。
  **不要**把它当成"能优雅停"就用第二次。
