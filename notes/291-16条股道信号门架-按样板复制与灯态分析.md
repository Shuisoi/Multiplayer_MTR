# 291 · 16 条股道各一套信号门架：按用户样板复制，4 灯位，双向

> 用户口径（2026-09-25）：**「X-142 Z67处，我放了一些栅栏和在节点正上方的信号灯，按这个给所有股道都配置信号灯」**
> + 灯位数选 **4 灯位**。
>
> 承接 notes/290（放灯的三段链路：方块 → 扫描登记 → 绑定）。那一轮只放了一盏验证通路的样本，
> 这一轮按用户样板铺满 16 条。

## 1. 用户的样板（从存档逐格还原出来的）

```
(-144, 65..69, 67)  nether_brick_fence                        ← 立柱，立在地基 y=64 上
(-144, 70, 67)      fence[east=true]                          ┐
(-143, 70, 67)      fence[east=true,west=true]                │ 横臂 y=70、z=67，跨 x=-144..-141
(-142, 70, 67)      fence[east=true,west=true]                │ （正好跨过轨顶）
(-141, 70, 67)      fence[west=true]                          ┘
(-142, 70, 66)      mtr:signal_light_4_aspect_1[facing=south] ← 北侧灯头，朝南
(-142, 70, 68)      mtr:signal_light_4_aspect_1[facing=north] ← 南侧灯头，朝北
```

规律：**立柱在轨西 2 格**（x-2），横臂从 x-2 伸到 x+1，两个灯头挂在**轨正上方** y=70、
z 各偏 1 格（66=北侧、68=南侧）。用户原话"在节点正上方"指的就是这一对灯头 ——
节点在 y=65，灯头在 y=70，确实在正上方。

## 2. 复制的产物

`sandbox/gen_yard_signals.py` → `sandbox/build_yard_signals.txt`：

| 项 | 数 |
| --- | --- |
| setblock 总数 | **176** |
| 栅栏 | 144（16 套 × 9 格：立柱 5 + 横臂 4） |
| 信号灯 | 32（16 条 × 2 个灯头，`mtr:signal_light_4_aspect_1`） |

**为什么相邻门架不打架**：第 k 条横臂占 `[x-2, x+1]`，下一条在 `x+5`、横臂占 `[x+3, x+6]`，
中间空一列 `x+2`。16 条 x∈[-142,-67] ⇒ 横臂最西 **-144**（平台西缘）、最东 **-66**（平台到 -65），都在平台上。

**逐格核对**：16 套 × (立柱 5 格 + 横臂 4 格 + 灯头 2 格) 全部与样板逐字节一致（含 fence 的
`east/west` 连接位与 `waterlogged=false`）。

## 3. 登记与绑定：这轮**不用**手工绑

`/setblock` 不触发 `BlockSignalBase.onPlaced2`，所以照 notes/290 §3 跑一次 `world scan-signals`
（先 `forceload` 住 z=67 那一片，扫完已 `forceload remove all`）。**绑定全部交给引擎的 AUTO 推断**，
而且它判对了 —— 例如第 1 条：

| 灯头 | 引擎判它守的轨 | 结论 |
| --- | --- | --- |
| `(-142,70,66)` 朝南 | `(-142,67)→(-107,242)`（咽喉 S 弯，180 m） | 出库进路 |
| `(-142,70,68)` 朝北 | 1 m 咽喉 + 220 m 股道 = **221 m**（进路两段） | 入库进路 |

即"北侧朝南守咽喉、南侧朝北守股道"，与用户搭这一对朝向相反的灯头意图一致。
`signal why` 里有逐腿的选择过程，可随时复核。

## 4. 灯态：16 盏绿、14 盏红 —— 这是对的，不是 bug

```
z=68 朝北（守本股道）   16 盏 全 GREEN
z=66 朝南（守咽喉）     -107 / -102 两盏 GREEN（两条牵出线的直通进路）
                        其余 14 盏 RED   ← 正好是 14 条要"并进牵出线"的股道
```

红的原因是**进路走不出去**，引擎在 `signal why` 里原话：

```
结束原因：撞在道岔 -107,65,92 的**禁行侧**（道岔位置 0：这条轨禁止通行）→ 这条进路走不出去，按红显示
```

即：14 个汇入点都成了道岔（`point list` 里 14+ 条，全部 `→ 腿 0`），默认位禁止从**岔股**
（那条 S 弯）通过。所以任何一条侧线的**出库信号机默认在红灯位**——这恰恰是铁路该有的样子：
**不扳道岔，车出不去**。

要让某条侧线出车，把对应的汇入道岔扳到岔股那一位：

```
point set <x> 65 <z> --via=<牵出线轨hex> --branch=<汇入段轨hex>
```

（14 个汇入点分别是 `(-107,65,{92,117,142,167,192,217,242})` 与
`(-102,65,{92,117,142,167,192,217,242})`，对应 14 条 S 弯轨。）

另有一处观察：`signal list` 的统计里"区间 33 段，连成链 31 条"——
**链条数远小于段数**，因为这是个终端车场，绝大多数灯前方没有下一段，
所以**单黄/双黄（预告）到不了**，只有红/绿两态。要看到多显示，得在咽喉以南继续铺轨与灯。
