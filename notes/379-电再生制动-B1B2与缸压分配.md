# 379 — 电再生制动：B1/B2 与"缸压分不明白"

> 用户 2026-10-03：「这个车还有一个 B1,B2 是电再生制动逻辑呢，这样缸压就能分明白了吧」

## 1. 他说得对，而且这正是"缸压分不明白"的根

`availableElectricN`（共用制动系统做电空混合的输入）当初**只有三手柄那条路在传**
（`ThreeHandleDriveController` 传 `spec.rheostaticEffortN(v)`），**有级/无级一律传 0** ——
于是 SAF420（`NOTCHED`，6 动 4 拖）在模型里**根本没有电制动**：B1/B2 必然是"纯空气闸"，
缸压从第一档就按分配阀建起来（实测 B1 = 0.638 bar，动力车与拖车一模一样），
与真车"低档先吃回生"不符，HUD 上的"缸压 vs 司机诉求"自然对不上。

（另一半原因在 notes/376 §7 之前的那份实测里：编组等效车底的 bar 口径整套来自**说话那节车**，
而 SAF420 的头车是**无动力的控制拖车**、`blendingEnabled:false` —— 就算控制器传了电制动，
编组级开关也会把它关掉。）

## 2. 改了什么

| 位置 | 改动 |
|---|---|
| 新 `physics/ElectricBrakeSpec.java` | 三段式（低速切除 → 淡入 → 恒力 → 恒功率）+ **`regenCutoffKmh`**（notes/378 点名"模型缺的那个物理量"）；`plus()` 编组求和；`encode/decode` 供镜像 |
| `ThreeHandleSpec` | `rheostaticEffortN` / `rheostaticFade` / `rheostaticBreakpointMetersPerSecond` **改为委托**同一份口径（默认"切除 = 满力速度的一半"，老配置逐位不变）；新增 `getElectricBrake()` |
| `ConsistType` | **任何操纵方式**都读 `rheostaticBrakeForceN` / `rheostaticMaxPowerW` / `rheostaticFadeKmh` / `regenCutoffKmh`；**有牵引却没写电制动 ⇒ 点名**（那意味着它的 B1/B2 全是空气闸）；`asHauledTrailer()` 不借电制动（与"不借牵引"同一条纪律） |
| `MmtrComposition` | 整列电制动 = 各**动力车**之和（`ElectricBrakeSpec.plus`，切除/满力速度取最保守）；**编组级 `blendingEnabled` = "有没有动力车能混合"** —— 不能照抄说话那节车 |
| `Notched`/`Stepless` 控制器 | 把整列可用电制动力交给共用制动系统；**把被电替掉的那一份加回合力**（EP 只削不加 ⇒ 总制动力不变，变的是气/电分配） |
| `ThreeHandle` 控制器 | 电制动口径改取**车底**那份（它带自定义 `regenCutoffKmh`），三手柄规格里那份作后备 |
| `Vehicle` | "电机"行与"制动力（电）"改由控制器报的 **牵引力 / 电制动力** 两个数合成（以前拿"净加速度 × 质量"当电机出力，会把气制动也算成电，两行重复计） |
| 镜像 | 新增 `mmtrElectricSpec`（schema + 稀疏补丁白名单），客户端跑同一份物理 |
| 配置 | `saf420_motor` 补四个键 + `_regenNote` |
| 用例 | 新增 `MmtrBrakeModelReuseTests.regenerativeBrakingCoversTheMotorCarAndLeavesTheTrailerOnAir`（电削动力车 / 拖车留气 / 总力不变 / 切除点以下退回纯气）；`loco(...)` 夹具加 `regen` 开关，**量气路本身**的那条（缸压顶到上限 + 牵引联锁）改用无电制动版本 |

**配置数值是假设（写在 `_regenNote` 里）**：`rheostaticBrakeForceN = 60800` / `rheostaticMaxPowerW = 676000`
取**牵引机包线**（回生通常与牵引同机，网侧接受容量不足时才降额）；`rheostaticFadeKmh = 15` 与 BR101 同口径；
`regenCutoffKmh = 5` 按**全電気ブレーキ**（E235 有）取 —— 注意 notes/378 从 BVE 声学数据取的 **27 km/h**
是"听得到回生"的门限，不是物理切除点。**等用户给真车口径再改。**

## 3. 实测（SAF420 6M4T，60 km/h，3 s 稳态；探针 `sandbox/saf420_param_probe`）

| 档 | 电 kN | 气 kN | 合计 kN | 缸压 车头(Tc) | 缸压 动车 | 缸压 尾车(Tc) |
|---|---|---|---|---|---|---|
| B1 | 52.05 | 31.92 | 83.98 | 0.64 | **0.00** | 0.59 |
| B2 | 103.96 | 63.33 | 167.29 | 0.97 | **0.00** | 0.88 |
| B4 | 189.07 | 110.21 | 299.28 | 1.54 | **0.00** | 1.26 |
| B6 | 243.04 | 135.10 | 378.14 | 1.91 | **0.00** | 1.42 |
| B8 | 243.36 | 151.72 | 395.08 | 2.00 | **0.00** | 1.48 |
| B2 @ 3 km/h（< 切断点） | 0 | 83.98 | 83.98 | 0.97 | 0.97 | 0.88 |

**读法**：动力车那 6 节的缸压**整档都是 0**（回生覆盖得住）；拖车那 4 节照旧建气（它们没有电机）。
电制动在 60 km/h 被恒功率段卡在 `6 × 676 kW / 16.67 m/s = 243 kN`，所以高档电不再涨、气接着补。
B7/B8 的"合计"比无回生时低约 11 kN 是 3 s 那一刻**尾车还在建压**的暂态，不是丢力
（2 节车的稳态用例断言 `气 + 电` 与纯气逐位相等，1 N 容差通过）。

用例打印的原话（`MmtrBrakeModelReuseTests`）：

```
[TEST] 回生混合（60 km/h、4 档）：电 57.2 kN / 气 57.2 kN；缸压 动力车 0.00 bar、拖车 2.41 bar
```

## 4. 还没做的 / 待定

- **车头是控制拖车** ⇒ HUD 的"缸压"那行读的是**拖车**那份空气压力（B1 就在 0.64 bar）。真车同形
  （拖车没有电机，它那份只能走空气），但"缸压 0 = 纯回生"只在动力车上成立 ——
  要不要在 HUD 上把"动力车缸压 / 拖车缸压"分开显示，是另一个决定。
- `emu_8_notched` / `lr_stepless` / `freight_air` 三份**占位车底**现在每次加载都会点名
  "有牵引没写电制动"（它们确实没有真数据）；`p1_trailer` / `freight_wagon` 没有牵引，不点名。
- 电制动的**网侧接受容量**（多列车同时回生时降额）没建 —— 现在按单车能力给。
