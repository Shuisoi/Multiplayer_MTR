用户口径（2026-09-25）：

> 初级制动停留在 4.6 bar，然后根据档位逐级递减至 3.5 bar。
> 制动力计算可以参考以下（五个模块的完整链路），但**要做简化**，先拿个方案出来吧。

本轮实施其中的 **P1（气压语义 + UIC 标定）** 与 **P2（闸片衰减 + 电制动恒功率）**；P3 电空混合、

## 1. 落地口径（一页）

```
档位 ──级位表──▶ 列车管目标(bar) ──充/排气速率──▶ 管压 P_pipe
                                                   │分配阀：P_bc = 2.533×(5.2 − P_pipe − 0.2)，上限 3.8
                                                   ▼ 缸压 P_bc（EB 4.2）
        力 F = F_UIC · max(0, P_bc − 0.3)/(3.8 − 0.3) · κ(v)        κ(v) = μ_b(v)/0.39
        F_UIC = m_equiv · (0.0065·λ + 0.12)        λ = 制动重量 / 车底质量 × 100%
```

| 量 | 值 |
| --- | --- |
| 列车管 | 定压 5.0 / 运行位 5.2 / 初制动(1A) 4.6 / … / 8 档 3.5 / EB 3.0 bar |
| 级位表（11 位） | `5.2,4.6,4.4,4.2,4.05,3.9,3.8,3.7,3.6,3.5,3.0` |
| 分配阀 | 倍率 2.5333、灵敏限 0.2 bar、缸压上限 3.8 bar（EB 4.2） |
| 缸簧 | 0.30 bar（低于它不出力，**算力时扣**） |
| 充/排气 | 0.35 / 0.85 bar/s；缸压建/缓 1.30 / 0.95 bar/s；EB 排风 ×3、缸压 2.0 bar/s |
| 闸片 | μ_b = 0.39 − 0.00045·v_kmh（下限 0.28）⇒ 100 km/h 0.345、200 km/h 0.30 |
| 力的锚 | BR101：λ=142.9% ⇒ **102.2 kN**；R+E 168 t ⇒ λ=200% ⇒ **138.4 kN**（旧铭牌 150/210 kN） |
| 电制动 | 150 kN 到 153.6 km/h，之上按 6.4 MW/v（200 km/h ⇒ 115 kN）；低速淡出带保留 |

**零回归机制**：气压口径是**随包配置**的开关（一个 bar 键都不写 ⇒ `PneumaticBrakeSpec` 为 null ⇒
控制器逐位走旧的归一化模型）。所以全量 826 条既有用例里只有两处**故意**重锚（制动力锚与制动重量表），
其余一条没动。

## 3. 实施中抓到的两个缺陷（都写进用例了）

1. **分配阀倍率四舍五入 ⇒ 满缸压永远差一点**：配置写 `2.5333`，`2.5333 × 1.5 = 3.79995 < 3.8`，
   于是"8 档 = 满缸压"永远差 5e-5 bar，缸压/联锁/断言全跟着抖。修法：分配阀输出在
   `≥ 上限 − 1e-3` 时**吸附到上限**（限压阀本来就是这个行为）。
2. **AFB 补气诉求 0 被折成 0.3 bar（缸簧）⇒ 车永远不动**：`缸压目标 = 弹簧 + 比例 × (上限 − 弹簧)`，
   比例 0 时得到 0.3 bar ⇒ 缸压停在 0.3 bar ⇒ **牵引联锁（>1% 常用力）永远松不开**。
   这正是本仓最怕的一类"看起来能开、其实不动"的现场，被
   `applicationAndReleaseFollowTheConfiguredRates`（末段断言"完全缓解：缸压归零"）当场抓住。
   修法：比例为 0 ⇒ 目标 0。

## 4. 验证（数字即判据）

`MmtrPneumaticBrakeTests`（11 条）：

```
[TEST] 初制动（1A）：缸压 1.013 bar，轮周力 20.8 kN
[TEST] 全常用建压 3.1 s（管压 3.5 bar）
[TEST] 松闸到联锁放开（缸压 ≤0.35 bar）3.9 s
```

- UIC 锚：`0.0065×142.86+0.12 = 1.0486` ⇒ 102.2 kN；λ=200% ⇒ 138.4 kN（E/S = 1.354）；
- 分配阀逐档稳态缸压与设计文 §2.2 的表逐行对上（含灵敏限 0.2 bar 与限压）；
- 缸簧死区（0.3 bar 以下 0 力）、常用侧饱和；1A ≈ 20.8 kN（旧表 1A 只有 7.5 kN —— **bar 语义下没有 5% 弱档**）；
- 闸片：μ(0/100/200 km/h) = 0.390/0.345/0.300 ⇒ 8 档在 200 km/h 只剩 78.6 kN；
- 电制动：折点 42.67 m/s（153.6 km/h）满力、200 km/h ⇒ 115.2 kN、10 km/h 落在淡出带给一半、5 km/h 以下为 0；
- 镜像串往返（级位表/分配阀/闸片/功率），**旧串与旧配置解回 `null` 气压规格** ⇒ 旧模型逐位回归。

全量：**827 条，失败 3 条** —— 仍是那 3 条世界存档漂移（`the long (aassdd) siding must exist`），
本轮新引入的失败为 0。

## 5. 实机影响（已生效）

本轮末尾按用户要求**先加 HUD、再换 jar 重启**（用户口径 2026-09-25：「拉之前在屏幕 UI 右上角添加
制动压力以及制动力显示」）：

- 右上角 HUD 新增三行（notes/266 的 HUD 部分）：`管压 x.xx bar`、`缸压 x.xx bar`、
  `制动力 xx kN（气 · 电）`；数据源是 `Vehicle.getMmtrPipeBar() / getMmtrCylinderBar() / getMmtrBrakeForceN()`，
  在**服务端与客户端读同一份镜像字段**（客户端的气压规格来自镜像串的 `PB` 段，不会各说各话）；
- 换 jar 流程：`server stop`（引擎自己写的停机标记 ⇒ 启动器不当成失败）→ `sync-engine.ps1` →
  `check-java-compile.ps1`（448 个源文件、0 错误）→ 重启 `dev-server.ps1` + `dev-client.ps1`；
- **实机对账**（新 jar 起来后用户当场拉 1B）：

  ```
  [MMTR-CONSIST] 手柄=0 制动=2 缸压=0.400 管压=0.846 常用制动=189.5kN 质量=164.0t
  ```

  缸压 0.400 × 3.8 = **1.52 bar**、管压 0.846 × 5.2 = **4.40 bar** —— 与设计文 §2.2 表的 1B 行
  （管压 4.4 / 缸压 1.52）**逐位一致**；`常用制动=189.5kN` 是 UIC 逐车求和的结果
  （102.2 + 2×43.7，旧铭牌口径是 290 kN）。旧模型同档位会给缸压 0.12 ⇒ 三处数字互相印证新模型在跑。

生效后的手感变化（按设计文 §7 的评估表）：

- **全常用软 32%**：单车 150 → 102.2 kN（1.54 → 1.05 m/s²）；BR101+2×p1 290 → 189.5 kN（1.67 → 1.09 m/s²）
  ⇒ 100 km/h 纯制动距离 243 → 371 m；包线/保护读同一份物理会自动提前，但**线路上按旧口径布的信号与
  停车点要重新目视**；
- **初制动变利**：1A 从 7.5 kN 变成 20.8 kN（0.21 m/s²）；
- **管压是真 bar 了**：运行 5.2、1A 4.6、8 档 3.5；建压 ~3 s、松闸到牵引回来 ~3.9 s、完全缓解 ~7 s；
- 电制动在 153.6 km/h 之上开始掉力（200 km/h 只剩 115 kN），高速阻力段会更依赖机械制动。
