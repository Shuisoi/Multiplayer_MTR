# 80 - A2 游戏内信号灯读进路（镜像通道）

> 承接 notes/79（引擎侧 `MmtrSignalAspect` 单一真源）。本片把"进路已设"这一维送到**客户端渲染器**，
> 让游戏内信号灯与 WEB 信号层用同一条规则——此前 `RenderSignalBase.mmtrChainDepth` 是第二份实现，
> 且注释里写着"route-locked aspect needs the S5 interlocking"。

## 1. 通道设计：引擎算，客户端只显示

不在客户端复刻联锁逻辑，而是把**派生视图**推给客户端（两个视图就把 A2 的全部新规则讲清楚了）：

| 视图 | 内容 | 渲染器用途 |
| --- | --- | --- |
| `nextRails` | railHex → SET 的 **MAIN** 进路在该轨之后的下一轨 | 分岔处只沿被锁定的径路走（不再"每个分支都算"） |
| `pendingEntries` | 未设好（PENDING）进路的**入口轨** | 该轨显示红灯（车停在信号外等联锁） |

引擎侧新增两个只读派生方法（`MmtrRouteRegistry.setMainRouteNextRails()` / `pendingEntryRails()`）——
它们本身就是 A2 规则的可传输形式，调车（SHUNT）进路与 PENDING 进路天然被排除。

## 2. 本片交付

| 件 | 内容 |
| --- | --- |
| 引擎 `MmtrRouteRegistry` | `setMainRouteNextRails()`（SET+MAIN 才进表，按轨序压平）+ `pendingEntryRails()`；单测覆盖 |
| `PacketMmtrRoutes`（fabric） | 服务端→客户端推送；线格式 = 压平对数组 + 入口轨数组（`iterateStringArray`，无需动态键解析） |
| `MmtrClientRoutes`（fabric） | 客户端静态镜像：`nextRail(hex)` / `isPendingEntry(hex)`；空 = 无进路（= A2 之前的自由驾驶行为） |
| `MmtrRouteMirror`（fabric） | `END_SERVER_TICK` 每 tick 比对签名，**只在变化时**广播（空闲世界零流量；多世界按 worldId 分别记签名） |
| `RenderSignalBase.mmtrChainDepth` | 入口轨 PENDING → 深度 1（红）；否则分岔优先跟随 `nextRail`（且校验该轨确实接在远端节点上，方向不符则退回保守链） |
| `Init` / `MTR` | 注册包 + 注册 pusher |
