# 218 · HID 接入：DirectInput 的 X = AFB、Y = 油门、Z = 制动

日期：2026-09-21 · 车辆：BR101 · 结论：三根手柄接上**手柄/摇杆**（GLFW 轮询，直读 DirectInput 轴序），
换算数学放引擎并**单测钉住**；键盘与 HID 并存（轴是绝对量，压在键盘之后）。引擎 **759 通过 / 0 失败 / 5 跳过**。

用户口径（原话）：「把操作在客户端接入到 HID，DirectInput 中 **X 轴 AFB、Y 轴油门、Z 轴刹车**」。
（顺带一句："车内信号系统还没完善，目前能开了就好" —— 所以本轮不碰信号层。）

## 1. 接线（只读）

| 轴 | 手柄 | −1 端 | +1 端 |
| --- | --- | --- | --- |
| X | 定速巡航 AFB | 0（关闭） | 车型上限（BR101 = 160，步长 5 km/h） |
| Y | 油门手柄（双向） | 满电阻制动 | 满牵引（**中位 = 关闭**） |
| Z | 气制动手柄 | 运行（缓解） | EB |

为什么中位 = 关闭正好：油门手柄本来就是**双向**的（中央关闭、两侧最小 → 5…100%），
一根回中杆天然对上它；制动手柄是**单向**的（运行 → EB），一根拉到头的杆天然对上它。

## 2. 换算放引擎、轮询放客户端（这是一个"为了能测"的分工）

| 位置 | 类 | 职责 |
|---|---|---|
| 引擎 | `MmtrHidMapping`（新） | 轴值 → 档位的**纯函数**：死区、量化、两端吸附、逐轴反转、镜像对称 |
| 引擎测试 | `MmtrHidMappingTests`（新，5 例） | 真值表 |
| 客户端 | `MmtrHidInput`（新） | 找设备（GLFW）、读轴、按启动参数校准、换设备/掉线打日志 |
| 客户端 | `MmtrDriveInput.applyHidAxes()` | 把绝对杆位压到三根手柄上（键盘之后） |

放引擎的理由很实际：**客户端的测试集要把整个客户端源码树编出来（需要引擎 jar），引擎的不需要** ——
而这张表值得有真值表。客户端只留下"环境相关、无法离线验证"的那一小块（GLFW 调用）。

## 3. 三处被真值表逼出来的细节

1. **油门映射必须严格镜像对称**：`Math.round(-48.5)` 是 −48（半数向上），直接 `round(a * 97)`
   会让 +0.5 → +49、−0.5 → −48，两侧差一格。改成"按绝对值取整再补符号"，
   用例 `assertEquals(-49, driveHandleFromAxis(-0.5, …))` 钉住。
2. **模拟轴上"最小"档（位置 ±1，2%）不可达**：它落在死区里，一出死区就是 5%。
   有意如此（电噪声要有地方消化）；要 2% 就用键盘单击 ↑/↓。已写进类注释与用例注释。
3. **死区只做吸附，不做量程缩放**：油门只在**中央**吸附（回到关闭），制动只在**两端**吸附
   （拉到底稳稳是"运行"、推到顶稳稳是 EB）。若把死区拿来缩放量程，"最小档"会被吃掉一整段。

## 4. 校准不改代码

实物千差万别（DirectInput 的"往前推"是负值、各家杆不同），所以方向/轴号/死区都走启动参数：

```
-Dmmtr.hid.joystick=0          选 GLFW 手柄号（0 = GLFW_JOYSTICK_1）；默认第一个连着的手柄
-Dmmtr.hid.axis.x/y/z=0,1,2    轴号（DirectInput 惯例 X/Y/Z）
-Dmmtr.hid.invert.x/y/z=true   逐轴反转
-Dmmtr.hid.deadzone=0.05       死区
```

选中/换设备/掉线各打一行 `[MMTR-HID]`，写明**生效的映射**（设备名、轴号、方向、死区）——
"手柄没反应"不该再是一种只能靠猜的现场（这是这四轮反复出现的教训）。

## 5. 验证

| 项 | 结果 |
|---|---|
| 引擎 JUnit 全量 | **759 通过 / 0 失败 / 5 跳过**（新增 `MmtrHidMappingTests` 5 例） |
| 客户端 javac | **436 源 / 641 类 OK** —— 用**新构建的 shadowJar** 顶在 classpath 最前做的检查，**没碰 `game/libs`**（游戏还开着；notes/216 的护栏要求停服才同步） |

> 那个"不碰 game/libs 也能验客户端"的手法值得记下：`gradlew shadowJar` 只写
> `engine/build/libs/`，把它作为 classpath 第一项跑 `check-java-compile` 的 javac 调用即可。
> （不能用 `engine/build/classes` —— 那是**未着色**的类，和 jar 里着色过的 gson 会打架：
> 实测报 `找不到 JsonReader(JsonObject)`。）

## 6. 遗留

1. HID 的**按键/帽子开关**没接（手柄按钮当 AWS 确认、门键等）；本轮只接了三根轴；
2. 手柄上"回中弹簧"的杆（普通摇杆）松开就回关闭 —— 这是**杆的物理性质**，不是软件取舍；
   真要"定住"得用不带弹簧的推杆（或把 AFB 当速度保持用）；
3. 车内信号层仍不完善（用户明确说先放着）：`mmtrBlockedWaiting` 之类的扣车照旧，
   但**理由已经能在 HUD 上看到**（notes/217）。
