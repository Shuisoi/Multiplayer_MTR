# 164 = 坐标系重构（一）：viewBox 当相机

> 起因：用户 2026-09-15「现在的绘图系统就是一坨。有没有什么框架可用？」
> 结论：**不引框架，改坐标系。** 框架换不掉病根 —— 病根是"世界坐标被蒸发掉了"。

## 一、病根

三个，都在坐标系上：

1. **没有任何地方保存"世界"**。`Rail.planeX/planeY` 这些是世界坐标，但**画出来的路径是屏幕像素**：
   渲染时调 `worldToScreen(camera, …)` 投影一次。于是相机一动，所有图层全部重算 ——
   这是 54 处 `zoomRatio / mapScale / REFERENCE_ZOOM` 的来历。
2. **`REFERENCE_ZOOM` 这个模型把两件事混成一件**。用户口径是"摄像机在移动，地图大小和位置关系不动"，
   而我实现成"每个元素一个 6× 下的规格值 + 乘倍率"，再额外给固定屏幕尺寸的东西加 `1/倍率` 反向补偿。
3. **旋转中心与锚点各算各的**。信号灯那一串缺陷（弹窗倒过来、灯点偏 1.7 px、箭头符号翻错）
   全部出在"绕哪个点转"上 —— 因为坐标是屏幕像素，旋转中心只能手算。

## 二、这一阶段做了什么

**SVG 自己就是相机**：一个 `viewBox` 替代所有手写投影。

| 之前 | 现在 |
| --- | --- |
| `worldToScreen()` 逐点投影，一层一套 | `camera.ts#viewBoxOf(camera, host)` 出一个 `viewBox` 字符串 |
| 每层自己把世界坐标算成屏幕坐标 | **坐标直接写世界坐标**（`railPath.ts` 的路径点就是世界坐标） |
| 线宽 = 规格 × 倍率（每层自己算） | 线宽 = `specPxToWorld(规格, 倍率, 相机比例)`（**一处换算**） |

关键的一步其实很小：`railPath.ts` 里的几何**本来就全在世界坐标里算**，只在最后投影
（`curvePath` 的 `project` 回调）。把那个回调从 `worldToScreen` 换成**恒等**
（`railWorldPath` / `railSpanWorldPath`），再由 `viewBox` 承担相机 —— 就这样。

## 三、尺寸口径：这次重构**不换口径**

这是最容易搞错的一点，来回错了两次（先多乘了 6，又少乘了 6，两次都是实测抓出来的）。
正确的一条：

```
屏幕像素 = 规格 × 倍率 / REFERENCE_ZOOM        （6× 时等于规格值 —— 用户 2026-09-15 定的）
世界单位 = 屏幕像素 / 相机比例                  （相机比例 = Camera.scale）
```

代入 SVG 的映射（一个世界单位 = 相机比例个视口像素）后，屏幕宽度**正好回到**旧口径的值。
逐值对账（页面上实测，`near` = 1×，`far` = 5.35×）：

| 元素 | 规格 | 1× 实测 | 5.35× 实测 | 旧口径期望 |
| --- | --- | --- | --- | --- |
| 轨道线宽 | 4 | 0.667 px | 3.567 px | 4×倍率/6 |
| 区间线心 | 6 | 1.000 px | 5.350 px | 6×倍率/6 |
| 状态条 | 2 | 0.333 px | 1.783 px | 2×倍率/6 |
| 端点直径 | 1 | 0.167 px | 0.892 px | 1×倍率/6 |

## 四、判据

### 单测（`npm run test:viewbox`，6 条）

1. **`viewBoxOf` 与 `worldToScreen` 是同一个映射** —— 抽三个世界点逐点比。
   这一条最重要：一个是"给 SVG 的声明式说法"、一个是"视图层算指针用的"，
   两者不一致就是"画出来的"与"点得到的"错位。
2. 两个方向的比例必须相同（否则图会被拉伸）。
3. 退化输入（容器没量出尺寸、比例 0/负）不产生空串或 NaN —— 空 `viewBox` 会让 SVG
   退回"用户单位 = 像素"，画面会突然跳到 1:1（实测过）。
4. `worldToScreen` 与 `screenToWorld` 互为反函数。
5. **`specPxToWorld × 相机比例 == screenPxOfSpec`**（左边是写进 SVG 的世界单位、右边是应当看到的
   屏幕像素）—— 差一点就说明线宽与坐标用了两套尺度，那正是"线与图标脱层"的成因。
6. 换算的退化输入不产生 NaN 或负值。

### 页面实测

- **viewBox 映射与 `worldToScreen` 一致**：预测的屏幕位置与 `getBoundingClientRect` 差 **2×10⁻⁶ px**；
- `kx == ky`（0.46675 / 0.46675）⇒ 不被拉伸；
- 上表四类尺寸在 1× 与 5.35× 下**逐值**与旧口径相同；
- `sandbox/check-web-section-three-lines.ps1` 7 条全通过（被量的量现在以世界单位给出，
  脚本用页面自报的 `data-world-px-scale` 换算成屏幕像素再断言 —— 不再自己拿 viewBox 猜比例）。

## 五、还没做的（下一阶段）

**HTML 标记层**（节点、信号灯、道岔）仍然用 `decalPlacement`（世界→屏幕 + 像素偏移）定位。
它们与 SVG 层现在**共用同一台相机**，所以两者是一致的（这正是"同一坐标系"的落点），
但"手写投影"这条路还没拆完：

- 标记层的位置可以改为注入 `1/相机比例`（CSS 变量），让**位置也只有一处换算**；
- 固定屏幕尺寸的标注（1 px 端点已随本阶段解决、命中区仍写死像素）统一到一处；
- `mapElements.ts` 的 `decalPlacement / decalTransform / pixelOffset` 在标记层改造后大部分可以删掉。
