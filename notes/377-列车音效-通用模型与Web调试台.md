## 2. 模型定义：两个输入轴 + **一个必须补的第三输入**

### 2.1 两个轴
**速度 v（km/h）× 牵引功率 P（W，带符号）** —— 就是用户定的那两个。
行业共识也正好是这一对（只是他们叫"转速 × 负载"）：

| 系统 | 控制模型 |
|---|---|
| Open Rails（`.sms`） | `SpeedControlled` + `CurveForceControlled` 两条曲线 |
| Zusi 3 | 转速 → 播放速率；负载 → 音量（作者亲述，两个发动机声槽位） |
| 赛车（Project CARS 2 / AudioMotors） | RPM × 负载；分档 loop 与粒子合成两条路混用 |
| BVE5 | 表内只有速度；功率是**表外的**增益乘数 |

差别在于：BVE 的"功率"只是个 0..1 的抽象档位乘数，而 MMTR 手里那份 `P` 是**真实瓦特数**，
所以我们的模型可以比它们更物理。

### 2.2 ★ 为什么必须补"级位"
**静止时 P = F·v ≡ 0**，可起步时逆变器明明在工作 —— 只认功率的话，
**"起动音"永远发不出来**，而那恰恰是 VVVF 最有辨识度的部分。

所以模型接受第三个输入 `ratio`（手柄比例 / 级位）：给了就用它，没给才由功率反推。
它同时充当"有没有励磁"的判据（`excited`）。这是自检抓出来的（`selftest.mjs` [5]），
不是先验设计 —— 早期版本在静止工况下算出来是**完全静音**。

## 3. 频率口径（最容易错的地方，先钉死）

| 量 | 定义 | 出处 |
|---|---|---|
| 转频 f_rotor | `k·v`，`k = 极数·齿轮比/(22.62·动轮径 m)` | 西门子「電車制御時の発生騒音」騒音制御 29(4) 2005 式(1) 整理 |
| 基波 f₁ | `f_rotor ± 滑差`（**牵引加、再生减**） | 日立評論 61(5) 1979「力行時には加算し、回生制動時には減算する」 |
| 滑差 | 恒力矩区 ≈ 4.5 Hz | 同上（实车示波图） |
| 载波 f_c | 异步：独立指定；同步：`= 分周数 × f₁` | 见 §4 |
| 分周数 | **每个基波周期的载波周期数** | ⚠️ 日/中圈另有一套"每**半**周期脉冲数 N ⇒ f_c = 2N·f₁"，**差 2 倍**；抄参数表前先对齐 |
| 磁歪声基音 | **2f₁**（磁致伸缩每半周期达峰） | ja.wikipedia 磁励音：变压器磁歪音基频 = 电源频率 2 倍 |
| 齿轮啮合 | `齿数 × 转频/(极数/2)` | VVVF-Simulator `SetCalculatedGearHarmonic`（注意其源码用 `2^Np` 是 bug，我们按 `2·Np`） |

**对表验证**（`selftest.mjs` [3]，两条独立出处）：
- 西门子原例 G=5.93 / D=0.82 m / P=4 ⇒ k = 1.2788 Hz/(km/h)，**80 km/h = 102.3 Hz**（论文写 ≈102 Hz）✅
- E531 实测异步→同步切换在 31 km/h、机械转速 19.3 Hz ⇒ 我们算出 **38.64 Hz = 19.3 × 2（极对数）** ✅

## 4. 调制状态机：切换点必须**算出来**，不能写阈值表

```
异步段：f_c = clamp(k·f₁, f_cmin, f_cmax)          ← 载波独立于基波
切换点：f₁_sync = f_cmax / P_max                    ← 异步载波刚好爬到上限的那一点
同步段：f_c = P·f₁，P 取满足 P·f₁ ≤ f_cmax 的最大阶梯值；阶梯用尽 → 1 分周（方波）
```

两个**踩过的坑**（都写进代码注释了）：

1. **判据必须只依赖 f₁（无状态）**。早先写成"在异步与同步里挑载波更高的那个"，
   结果 f₁ 略高于切换点时会算出 `P·f₁ < f_cmax`，于是**又从同步翻回异步**，
   表现为音色在切换点附近来回跳。真机的模式切换是**单调**的。
2. **"最大可行分周数"是启发式，与真车对不上**。为省开关损耗，实际控制器会**提前降档**
   —— 209 系三菱 GTO 的真实表是 `0–9 Hz→57 分周、9–19→33、19–29→21、29–45→9、45–53→3、≥53→1`，
   而"最大可行"规则到 45 Hz 还算得出 21。所以要保真就得**能吃表**（`spec.modeTable`）。

### 四种真实载波形态都实现了（都有实车出处）
| 形态 | 出处 | 我们的预设 |
|---|---|---|
| `fixed` 恒定 | E231 日立制 **1045 Hz** | `SPEC_E231_IGBT` |
| `ramp` 斜坡到封顶 | BART 250→500、TGV 150→300→600 | `SPEC_SAF420` |
| `table` 查表（**ドレミファ**） | 西门子 SIBAS32：175–400 Hz **九个音阶** | `SPEC_N1000_SIEMENS` |
| 全程同步、**无异步区** | 209 系三菱 GTO 3 电平，57→1 六段 | `SPEC_209_MITSUBISHI_GTO` |

> 「ドレミファ」有**两个不同成因**，别混：**(A)** 同步分周换档的台阶感（几乎所有 GTO 车都有）；
> **(B)** 真把载波排成音阶（只有西门子系少数车）。我们两种都能表达。

## 5. 为什么可以只用正弦分音、不用 PWM 比较器

真实声源是开关纹波电流经电机铁心磁致伸缩振动的辐射，听感上是**载波 + 边带**的窄带簇。
用若干正弦分音叠加：

- **按构造就带限，零混叠** ⇒ 不需要 PolyBLEP / 过采样 / 波表 mipmap 那一整套抗混叠工程；
- 相位由累加器维护，**频率连续变化时不重置相位** ⇒ 换档、扫频天然不爆音。

这也正是业界成熟折中（把 PWM 频谱离线算好成谐波幅度表，运行时加法合成）。

**1 分周要特殊处理**：那时已无所谓"载波"，输出就是方波，频谱是 **f₁ 的奇次谐波（1/n 衰减）**。
当成载波簇算会得到 `(1±n)·f₁` 这串**含偶次**的分音，音色偏软、不像方波。
实测（`sweep.mjs` 209 系 100 km/h）：157 / 471 / 785 / 1099 … = 1×/3×/5×/7× ✅

## 6. 顺带把 BVE 兼容层做对了（现存 27 套素材要用）

深挖 OpenBVE 源码后发现 **MTR 的实现与官方行为有 9 处偏差**，接线时要用对的那个：

| # | 偏差 | MTR | OpenBVE 官方 |
|---|---|---|---|
| 1 | **功率语义** | 线性 `× |power|` | `pow(加速度比, 0.25)`（四次方根） |
| 2 | BVE4 音量 | `volume/128` 直接用 | `pow(volume/128, 0.25)`，**MTR 少了四次方根** |
| 3 | BVE4 下标 | `(int)(v/0.2)` 截断 | `round(\|v\|×18)` 四舍五入（1 m/s 边界差 1 项） |
| 4 | **BVE5 空单元格** | 跳过、靠相邻行插值 | **空 = 1.0（unity）**；而"该行列数不足"= **0（静音）** |
| 5 | 过零（惰行） | `power==0 → 音量 0`，靠自造的 `MotorOutputAtCoast` | `ndir==0` **不动声源** |
| 6 | P/B 表选择 | `sign(power)` | `sign(CurrentAcceleration)` |

表头 `BveTs Motor Noise Table 0.01` 里那个 `0.01`：**OpenBVE 只校验前缀字符串，这个数被完全忽略**，
也不是格式版本号（BVE5 官方规范页甚至没记载这套 CSV）。我们记下来备查但代码里不用它。

这两条换算律（`bve4VolumeGain` / `bveAccelerationGain`）已实现并有对表用例。

## 7. 实测：现有素材能不能用、能不能被合成复刻

写了两个探针（`sandbox/sound-probe/`）：

**循环接缝**（`loop_seam.py`，判据 = 接缝跳变 / 正常逐样本步进）：
- 除 `run.ogg`（**9.7**）与 `motor1.ogg`（**4.7**）外，其余 14 个全部 ≤ 3 ⇒ **可直接整段循环**
- 全部单声道 ✅；但采样率不齐：`doorcls.ogg` 是 48 kHz，其余 44.1 kHz

**频谱**（`spectrum_probe.py`）：
| 文件 | 谱平坦度 | 最大峰占比 | 结论 |
|---|---|---|---|
| `motor1.ogg` | 0.0000 | **66.4%**（1070 Hz 一个峰） | 近乎纯音 —— 本来就是合成出来的 |
| `rub.ogg` | 0.0000 | 44.1%（3868 Hz） | 同上 |
| `motor2.ogg` | 0.0002 | 31.5%（665 Hz） | 同上 |
| `motor0.ogg` | 0.0347 | 2.7% | **宽频噪声型**（风机/走行） |

⇒ **音调层可以参数化合成复刻同一族音色；宽频层（`motor0`/`run`）留采样。这就是混合路线的依据。**

**行业硬约束**：变调预算 **±5%~15%**，超出要"换素材"而不是继续变调 ——
这解释了 BVE 为什么 5 档 motor 就够用。已实现为 `clampPitch()`。

## 9. 已知不足（下一轮要处理的）

1. **游戏端一行未改** —— SAF420 仍然是哑的。接线方案见 §1，但那需要把模型移植到 Java

3. **事件层没做**：轨缝/道岔/喇叭/压缩机都是 one-shot，与牵引模型解耦。
   其中**喇叭在全仓库没有任何音频**（d78/1995/1996 的 `[Horn]` 三行全是注释）。
4. **音源池与 LOD 没做**：全局音源约 247（streamed 仅 8），MTR 是**每节车**一套环路
   （`PersistentVehicleData:161` 按 `carNumber`），一节车最多约 12 环 ⇒ 8 节编组约 96 个，
   同屏两列车就爆池。调研给的一条省算力办法值得抄：**同一分周档内 f_c 与 f₁ 严格成正比，
   所以"预烘焙每档一条循环 + 按 speed 变调播放"恰好是正确的**。
5. 三条线索里那条"三菱 GTO-VVVF 调制办法"（0–4/4–34.5/34.5–38/38–160 km/h 断点、"
   注入频率"）**查不到任何出处**，同文原样出现在一个 CSDN 的 AI 回答页上，判定为 LLM 产物；
   我们改用有出处的 209 真实分周表与 E231 定载波。
6. `SPEC_SAF420` 的电气四数（极数 4 / 齿轮比 5.93 / 轮径 0.82 / 载波 1045）取自**通勤型典型值**
   （西门子论文原例 + E231 实测载波），**不是 SAF420 的真实参数** —— 我们手上没有这台车的电气数据。
   页面左侧的常量输入框就是为"拿到真参数后改这几个数"准备的。
