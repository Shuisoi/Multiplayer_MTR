# 402 车资源包的音效：是**一个 SAF420 包**，不是"saf420 + 京急2100"两个（2026-10-08，口径）

## 0 这一枪打的是什么

用户口径（原话）：

> 车资源包的音效，目前两个资源包 `saf420` 和京急2100 是**分开发**的，这是一个**命名混淆** ——
> 其实 SAF420 的声音**就是**模仿京急2100 的，需要把这个音效包**做进 saf420 包里面作为同一个包**。

也就是说：**"京急2100 音效包"不是一个与 SAF420 并列的交付物**，它是 SAF420 这套牵引/走行音的**音色出处**。
问题不在音频，在**名字与交付形态**。

★ **本轮只改文档口径，不重建任何包、不动 `run/`**（用户："那就把文档改好就行了，等待我下一步"）。
下面 §4 把"要真改名字得动哪一处"写清楚，等下一步。

## 1 现场：三件事都是可复核的

| 事实 | 读数 | 怎么自己看一眼 |
| --- | --- | --- |
| `run/resourcepacks/` 里两个包并存 | `SAF420_v42.zip` **2,816,711 B** / `Kei2100_v1.zip` **1,363,825 B** | `Get-ChildItem mmtr\game\fabric\run\resourcepacks` |
| 游戏里**两个都启用着** | `resourcePacks` 数组最后两项就是 `file/SAF420_v42.zip`,`file/Kei2100_v1.zip` | `mmtr\game\fabric\run\options.txt:47` |
| **v42 里已经带了整套音效** | 69 条 ogg 在 `assets/mtr/sounds/kei2100/` + 69 条事件登记 + `mmtr_traction.json`（引擎清单） | 解 zip 看条目 |

第三行是这件事的关键：**车包和音效包在 v42 里已经是同一个包了**。
之所以现场看起来还是"两个包"，是因为那个**独立音效包 `Kei2100_v1.zip` 还留在 resourcepacks 里、还开着**。

## 2 硬证据：`Kei2100_v1.zip` 是 `SAF420_v42.zip` 的真子集

把两个 zip 逐条目做 sha256 对拍（`System.IO.Compression` + `SHA256`，逐字节）：

| 判据 | 结果 |
| --- | --- |
| 条目数 | `Kei2100_v1.zip` **74** / `SAF420_v42.zip` **98** |
| **kei 里 v42 没有的条目** | **0 条** |
| 69 条 ogg（同一个路径 `assets/mtr/sounds/kei2100/`） | **69/69 逐字节相同** |
| `assets/mtr/sounds.json`（69 条事件登记） | 两边 sha256 **都是 `E0AA2E10 8BC5F026 …`**，同一份 |
| 两边**同内容不同**的条目 | **只有 `pack.mcmeta`**（只差 `description` 文案；`pack_format` 两边都是 22） |
| v42 独有的 24 条 | 三节车的 `definition_/properties_/mmtr_anchors_/*.obj/*.mtl/*.png` + `mtr_custom_resources.json` |

即：**`Kei2100_v1.zip` 的 74 个条目里有 73 个在 v42 里逐字节存在，第 74 个（`pack.mcmeta`）只是描述不同。**
装 v42 已经有车 + 音效；再装 kei 那一个包，**一个字节的新东西都不会带来**，
只会多占 1.3 MB、并让"这到底是哪台车的音效"重新变成一个要问的问题 —— 这就是那个**命名混淆**的真身。

## 3 裁定（写进文档的三条口径）

1. **音效集归属 SAF420。** 它不叫"京急2100 音效集"，它是 **SAF420 的牵引音（23 档）+ 走行音（轮轨/风噪各 23 档）**。
   音色来源是**京急2100 形（更新車）**的实录（`Av417534959` 的 16–70 s），
   出处与整套生成链留在 `artifacts/kei2100-av417534959/`（**素材出处 ≠ 交付物的名字**）。
2. **对外只有一个包：`SAF420_v<NN>.zip`。** `Kei2100_v1.zip` **不是**并列的第二个交付物，
   是同一批文件的独立副本 ⇒ 归为**冗余交付件**（保留在 `artifacts/…/pack/` 里当链的产物没问题，
   但**不该同时出现在 `run/resourcepacks/` 并且开着**）。
3. **游戏里只启用最新的 `SAF420_v<NN>`**，`Kei2100_v1.zip` **不要启用**。
   三个资源包同时开着（`BR101` / `SAF420` / `Kei2100`）时，69 条同名 ogg 与同一份 `sounds.json`
   被两个包各带一遍，**没有任何正面作用**。

## 4 还没做的：包内的名字仍是 `kei2100`（等下一步）

口径改了，但**包里的字符串还是 `kei2100`**：

| 位置 | 现值 |
| --- | --- |
| 事件 id | `kei2100_motor01` / `kei2100_roll01` / `kei2100_aero01`（69 条） |
| 包内目录 | `assets/mtr/sounds/**kei2100**/` |
| 车辆 → 音效集 | `consist/kei2100_saf420.json` 三节车 `soundBase = "kei2100"` |
| 清单里的 name | `mtr:kei2100/motor01`（`soundNamePrefix` 由 `BASE` 拼出） |

要连名字也并进 SAF420，**改动面很小**（`artifacts/kei2100-av417534959/pack_kei2100.py` 的 `BASE = "kei2100"` 一处）：

1. `BASE = "saf420"` ⇒ 重跑 `pack_kei2100.py`（⇒ `pack/stage/…/assets/mtr/sounds/saf420/` + 事件改前缀）
   ⇒ 重跑 `check_pack_kei2100.py`（12 项）；
2. `consist/kei2100_saf420.json` 的 `soundBase`/`soundDir` 跟着改 ⇒ `pack_consist.js` ⇒ **`SAF420_v43.zip`**；
3. 从 `run/resourcepacks/` 删掉 `Kei2100_v1.zip`，并从 `options.txt:47` 的 `resourcePacks` 里去掉它。

**判据**（重建后必须全绿）：

- `check_pack_kei2100.py --names <zip>`：`name` 落空 **0 条**（这正是 v41 整套静音的那个坑）；
- `check_pack_kei2100.py --vehicle <zip>`：未登记事件 **0 条**；
- 包里**只能有一个音效集目录名**（不许出现"车包指 `kei2100`、目录叫 `saf420`"这种半改状态）。

> ⚠ 改 `BASE` 会**同时**改掉事件 id 与 `name` 前缀 —— 这两处必须一起动。
> 反过来，只把 `name` 写成 `mtr:sounds/saf420/…`（多一个 `sounds/`）就是
> `SAF420_v41.zip` 那 28 条事件**全部静音**的原因（见 `AUDIO-GEN-REPORT.md` §4 末）。

## 5 顺带记下的一处（与本次无关；**已在 notes/403 修掉**）

引擎接管成功时打的那条日志，标签写的是"事件前缀"，打出来的却是**资源目录**：

```
MmtrTractionSoundSet.java:122   Init.LOGGER.info("… 事件前缀 {}:{}", …, parsed.namespace(), parsed.baseDir());
```

`baseDir` 来自清单的 `"baseDir": "sounds/kei2100"` ⇒ 现场看到的是
`事件前缀 mtr:sounds/kei2100`，而**真正的事件前缀是 `mtr:kei2100/`**（差一个 `sounds/`）。

**它不影响播放**（播放走的是 `sounds.json` 里的 `name`，不是这条日志），
但它**长得正是 v41 整套静音那个坑的形状**，排障时会把下一个人带进沟里。

⇒ 本条在 **notes/403** 里已经修掉（两个都打、各自标清），并顺手加了一行混音表读数。
