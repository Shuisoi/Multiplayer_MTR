# 190 · BR101 雨刷：必须建在**停放位**（含本轮工具口径修正）

## 1. 结论：模型把雨刷建在了摆动中点，契约要求建在停放位

实测（刀片中点到作用面两个端盖的距离）：

```
wipersweep_1_1: 到端盖A = 0.8899 m, 到端盖B = 0.9421 m
wipersweep_2_1: 到端盖A = 0.9518 m, 到端盖B = 0.8781 m
```

**两个端盖都在 ~0.9 m 外 ⇒ 刀片在摆动的正中间。** 而用户的原话就是答案：
"这个车的雨刷初始是**居中**的……左右摆幅度为 47 度……**静止位置应该在 +46 度处**"。
建模契约（docs §1.4）要求"**雨刷建在停放位**"，因为停放位只能由"模型当前所在位置"来定义。

后果（全部实测到）：
- 对称 ⇒ **两个端盖的残差都 ~0** ⇒ 打包器与校验器**各挑一边** ⇒ `sweepSign` 分歧
  （1_1 / 2_1 / 2_2 三块，一边 +1 一边 −1）；
- 客户端会把"中点"当成 park，雨刷会**以中间为基准对称地扫**，而不是"停在 +46° 再扫到 −47°"。

**修法**：把**刀片 + 臂 + 拉杆整套建在停放位（+46°）**；`mmtr_wipersweep_*`（扇形作用面）
**不用动** —— 它本来就覆盖整个行程 ✓。

## 2. 本轮修掉的**工具侧**问题（都不是模型的问题）

1. **"销必须贴在刀片上"原本按刀片【中心线】判** —— 真车的刀片带**三角板**（属于同一个
   `wiper_` 网格），外侧连杆接的正是"三角板顶点销"（`TRI_OUT_OFF`，与条子中线差 `DX/2`）。
   实测：臂销离中心线 63 mm、拉杆销 124 mm，但**两者离刀片几何都只有 28 mm**。
   改为按**几何**判（`BLADE_BODY_TOL_M = 0.15`）；打包器那两条
   `reaches to … off the blade` / `does not reach the blade` 警告同样改为量几何。
2. **容差低于两个实现自身的离散度**：`ARM_TOL_M` 1 mm → 10 mm、`ANGLE_TOL_DEG` 0.05 → 0.5、
   `FRACTION_TOL` 1e-3 → 5e-3（BR101 刀片两端在两实现间差 27 mm）、写出的销点对比放宽到
   `2×ARM_TOL_M`、`solveStrokeFromFan` 的"刀片落在这条轮廓边上"5 mm → 30 mm。
   每条都写明理由，且 selftest 的注入位移是 50 mm/100 mm/10° 量级（5~50 倍余量）。
3. **打包器解行程由"第一条匹配的边就 break"改为"取全局最小残差"** —— 扫过的曲带轮廓有
   ~100 条弦（圆弧是分段 tessellate 的），某条弦的最近 φ 可能落在停放位**另一侧**，于是写出
   相反的 `sweepSign`（真车 4 块玻璃里错了 3 块 → 游戏里会朝反方向扫）。校验器一直是全局最小。
4. **判据顺序**：把"销必须贴在刀片上"移到那条带 `continue` 的
   `blade ends were written as …` **之前** —— 否则只要刀片两端稍有偏差，真缺陷（销离刀片 10 cm）
   就完全不会被报出来。`continue` 本身保留（去掉它会让空字段模型抛异常、累积失败不打印，
   反而丢掉一条注入用例）。
