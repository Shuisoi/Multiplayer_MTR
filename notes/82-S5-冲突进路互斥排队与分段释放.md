## 1. 本片发现并修掉的语义缺口：进路要"分段释放"

R1 的进路 SET 判定是"**全部**道岔现在都握在本车手里"。真跑起来（本片咽喉用例）暴露了它的错误：
列车一跨过第一个道岔，该道岔的持有就被消费（`passed`），进路立刻掉回 PENDING —— 对一条**多道岔进路**来说，
列车刚走完第一岔，后面那段进路就"没设好"，A2 的收窄也随之失效（信号退回保守最坏分支）。

真实联锁是**分段释放**（route locking releases sectionally）：列车越过一段就解锁一段，进路在列车前方仍然保持。
本片据此修正：

| 件 | 内容 |
| --- | --- |
| `MmtrRoute.crossedForkKeys` + `markForkCrossed` / `isForkCrossed` / `allForksCrossed` | 记录已越过的道岔（键 `x,y,z\|viaHex`，与道岔权威同格式） |
| `Vehicle.drainMmtrCrossedPoints` | 越岔时把该道岔标进进路（与既有的"从待请求集里摘掉"同一处） |
| `MmtrRouteRegistry.refresh` | 判定只要求**尚未越过的**道岔被持有；全部越过 → 保持 SET，理由 `all turnouts crossed` |

## 2. 咽喉用例（S5 验收，引擎侧）

`MmtrRouteConflictTests`（2 例，双车、双停场线汇入一条咽喉）：

布局：Y1(-40,0,0) 与 Y2(-40,0,10) 汇到咽喉入口 N(-20,0,0)，咽喉 N→M(0,0,0)，M 处岔分两条站台轨
P1(→100,0,0) 与 P2(→100,0,20)。两列车都需要**同一个岔 (M, 咽喉轨)**，但一条走直向（P1）、一条走岔向（P2）。

| 用例 | 断言 |
| --- | --- |
| `conflictingRoutesQueueAtTheThroatAndTheSecondSetsAfterTheFirstClears` | 1 号任务武装、进路 SET、握住 (M,咽喉)；2 号任务发布后进路 **PENDING**，理由点名道岔与持有人 `holder=v1@0`，**不武装**、车留在自己股道；在 1 号越过岔之前，2 号**一步都没动**；1 号越岔后 2 号才武装，随后抵达 P2；两车都过岔后岔无人持有 |
| `aFollowingMovementOnTheSameLegIsNotAHostileRoute` | 两车目标同一站台（同一条腿）不算敌对进路：2 号只是排在同一点后面；1 号越岔后 2 号立即武装跟进，随后被 **S1 占用停在咽喉末端**（一节闭塞）——不闯进 1 号所在的站台轨 |
