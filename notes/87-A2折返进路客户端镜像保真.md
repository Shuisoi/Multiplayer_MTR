# 87 - A2 保真度：折返进路的客户端镜像不再丢回程

> 承接 notes/85（镜像可观测）。实机 aassdd 那条牵出—推进进路的 `rails` 里，同一条轨出现两次：
> `[…3D, …61, …4E, …4E, …61, …3E]` —— 而客户端镜像此前是 **rail → 单条下一轨** 的 map，
> `putIfAbsent` 只会留下**去程**那一支，回程方向的收窄在客户端直接失效。

## 1. 影响

- 引擎侧（`MmtrSignalAspect.routeNextRail`）按"下一轨是否接在本次行进方向的远端节点"逐次匹配，
  折返两个方向都对（notes/85 的用例）；
- 客户端（`MmtrClientRoutes.nextRail`）只有一条候选 → 回程时那条候选不接在远端节点上 →
  渲染器退回"每个分支都算"的保守链 → **同一架灯，feed 显示绿、游戏里可能显黄**。
  这正是实机目视对照时最容易让人误判为 bug 的差异。

## 2. 修复

| 件 | 改动 |
| --- | --- |
| `MmtrRouteRegistry.setMainRouteNextRails()` | 值改为**有序列表**（每轨可有多条下一轨，按进路轨序），仍只收 SET 的 MAIN 进路 |
| `PacketMmtrRoutes` | 线格式仍为压平对数组，**允许同一轨重复出现**；客户端按轨聚合为列表 |
| `MmtrClientRoutes` | `nextRails(railHex)` 返回列表（不可变）；`isPendingEntry` 不变 |
| `RenderSignalBase.mmtrChainDepth` | 在候选里挑**接在本次远端节点上**的那一条；都不匹配才退回保守链 —— 与引擎同规则 |
| `mmtr-trains` feed `routeMirror.nextRails` | 值改为数组（运营端一眼看出折返轨的两条去向） |

## 3. 用例与验证

- `MmtrRouteRegistryTests.clientMirrorCarriesTheLockedPathAndThePendingEntries`：新增折返进路断言 ——
  `nextRails[中间轨] == [去程下一轨, 回程下一轨]`（顺序即进路轨序）；
- `SystemMapRouteMirrorTests`：feed 形状改为数组后仍断言 SET 径路与 PENDING 入口；
- 全量引擎套件 **470/0/2**；`:fabric:compileJava` **SUCCESS**（包/客户端/渲染器三处签名同步更新）。

## 4. 目标剩余

仍是游戏内目视（分岔按进路放行 / PENDING 压红 / AWS 黄灯响与绿灯复位 / 未确认 SPAD）。
本片把"引擎与客户端规则一致"这一条从**分岔**补到**折返**，让实机对照不再有假差异。
