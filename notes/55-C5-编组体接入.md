# 55 - C5 编组体接入：接缝、占用、S1 间距

> 用户口径：机辆模式机车要能和挂车车列连挂。实机里这些车都是**编组体**（双驾驶室模型），
> 而 C4 的连挂只重建了车列，没重建编组体——这一片补上，并顺带挖出两个坐标系的真 bug。

## 三个真缺陷（都被 C5 的测试逼出来）

| # | 现象 | 根因 |
| --- | --- | --- |
| 1 | 授权下机车**冲过**挂车车列 | 编组体的占用写在**腿影空间**（`buildMirrorLegs` 以尾端锚定），而所有读者按**轨道里程**比 → S1 的精确间距算错 |
| 2 | 机车停在挂车后 **2.5 m** 而不是 0.3 m | 连挂闸门用 `offsetM() - 车长` 算前车尾部；编组体的 `offsetM()` 是**前缘**、车体在**其后**（与 legacy 相反） |
| 3 | 方向判断错 | 想用 `aheadNode()` 判行进方向——它只是 spine 的 B 侧节点；正确来源是**在岗驾驶室** `cabs().travelsToward(End.B)` |

## 落成的构件

| 项 | 做法 |
| --- | --- |
| 接缝 | `MmtrConsistBody` 新增 `seamArcMs` / `seamCarIndexes`（与 `aEndArcM` 同一 spine 坐标系）+ `seamArcMsFrom(aEndArcM, carLengthsM, couplerAfter)`（由每节车的 `mmtrCouplerAfter` 直接算） |
| 放置 | `MmtrConsistWalker.place(...)` 新增接缝参数重载 |
| 连挂重建 | `placeMergedConsistWalker`：从前车 A 端重新 `place`，车列 = 合并车列，spine 自动延伸到后车所在轨——**A 端零位移** |
| 占用 | 编组体逐腿按 `body().occupancy()` 写轨道里程（含 `VehiclePosition.segmentsExcluding` 供精确间距使用） |
| S1 间距 | 新增 `mmtrConsistBodyBlockStop`：在轨道里程里找行进方向上最近的占用面；授权 → 0.3 m、运行 → 2 m |
| 前后判定 | 新增 `Vehicle.mmtrTravelFrame()` = `[行进方向里程, 车长]`，连挂闸门用它判前后与车钩间隙 |

## 回归与证据

新增 `MmtrConsistBodyCouplingTests` 1 例（两台真编组体：2 节挂车 + 1 节机车）：

- 机车在授权下**精确停在挂车尾部 0.3 m**（实测前缘 8.4 m vs 挂车尾 8.1 m）；
- 连挂后：车列 3 节 `[wagon, wagon, loco]`、**接缝 1 处**（`seamArcM(0) − aEndArcM = 4.3 m`，即挂车两节长度）、
  `carIndexAfterSeam(0) = 1`、A 端 arc/轨道/里程**逐项不变**、占用段覆盖两车旧位置、合并后无人持钥匙。

- 引擎全量 **417/0/2**（416 → +1，**零新增失败**——换端/占用/信号/连挂既有测试全绿）；
- 引擎 jar 已重建同步；`:fabric:compileJava` 通过。
