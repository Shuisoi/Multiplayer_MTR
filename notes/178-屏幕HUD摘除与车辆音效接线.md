## 2. 音效接线（复用 BVE 音效包）

### 2.1 先把契约钉死（这三点错了就静默无声）

从 `mmtr/game/fabric/.../sound/BveVehicleSoundConfig.java:18-30` 与 `BveConfigFile.java:86-98` 反推：

```
bveSoundBaseResource = "saf101_snd"        (不带冒号 → 命名空间 mtr)
  配置读取：  configBaseName = "mtr:sounds/saf101_snd"  → assets/mtr/sounds/saf101_snd/sound.cfg
  事件 id：   audioBaseName  = "mtr:saf101_snd_" + cfg 的值（去扩展名/去路径）
              [Motor] 0 = motor0.wav  →  事件 mtr:saf101_snd_motor0
  音频文件：  assets/mtr/sounds/saf101_snd/motor0.ogg        ← 注意是"子目录"，不是 `<base>_<key>.ogg`
  sounds.json:{ "saf101_snd_motor0": { "sounds": [ { "name": "mtr:saf101_snd/motor0",
                                                     "attenuation_distance": 32 } ] } }
```

**关键**：新音效包**必须自带 `sounds.json`**。`SoundHelper.createSoundEvent(id)` 编译成 `SoundEvent.of(Identifier)`
（`javap -c` 证），而 MC 的 `SoundSystem.play` 在 id 未注册时打 `Unable to play unknown soundEvent` 并直接 return。
现有 1719 条 `assets/mtr/sounds.json` 就是这么来的（例：`"a_train_run" -> mtr:a_train/run`）。
只替换已有音效包的 .ogg 才不需要 sounds.json；**新增音效集必须注册**。

另两个坑：
- `.cfg` 里的值**必须**是 `.wav` 结尾（解析器 `BveConfigFile.java:93` 会 strip `.wav`），但**磁盘上必须是 `.ogg`**——仓库里 1701 个音源**零个 .wav**。
- `.cfg` 的值会被 `replaceAll("\\.wav|\\s|.+/","")` 处理，路径前缀会被吃掉。

### 2.2 打包器改动

| 文件 | 改动 |
|---|---|
| `pack_vehicle.js` | 新增 `soundBase` / `soundDir` 两个参数；`soundDir` 加入 `${MC_ROOT}` 占位符解析白名单（第 9 行那个 for 循环，顺带补上原本漏掉的 `hudLayout`） |
| `pack_vehicle.js` | 复制 `soundDir/*` → `assets/mtr/sounds/<soundBase>/`；**只把真实存在的 `.ogg` 登记成事件** |
| `pack_vehicle.js` | 写出 `assets/mtr/sounds.json`；`mtr_custom_resources.json` 增 `bveSoundBaseResource` |
| `pack_consist.js` | `sounds.json` 从"逐车覆盖"改成**跨车合并**（否则后一节车会把前一节的注册冲掉） |

**"只登记真实存在的 .ogg"这条是必须的**，不是优化：`sound.cfg` 里 `[MTR] DoorCloseSoundLength = 1`、
`RegenerationLimit = 7.5`、`[Motor] 0 = motor0.wav` 的键 `0` 都是**纯数字**，按"值当文件名"解析会产出
`saf101_snd_1` / `saf101_snd_7.5` / `saf101_snd_0` 这种垃圾事件（第一次跑就撞上了）。用"文件存在性"过滤后干净落到 16 条。

## 3. 顺带发现的既有缺陷（本轮**未修**，仅登记）

均来自 BVE 音效层深挖，按"会不会白干"排序：

| # | 缺陷 | 位置 | 影响 |
|---|---|---|---|
| 1 | **法兰音硬编码音量为 0** | `BveVehicleSound.java:118-122`（`// TODO play flange sounds` + `setData(0, 1, pos)`） | 过弯尖啸**永远不响**。自己合成法兰音之前必须先补这段 |
| 2 | **轨缝音 `[Joint]` 解析了但零引用** | `BveConfigFile.java:141-147` 写进 `joint[0]`，全仓库无读取者 | 过岔"咔哒"不响，尽管每个音效包都带了 `point.ogg` |
| 3 | **压缩机永远充不上气** | `BveVehicleSound.java:99` `mrPress += (int)(secondsElapsed*5)`，20 fps 下 `(int)(0.05*5)=0` | 一旦制动把压力打到 ≤700，`isCompressorActive` 永久锁 true，环路常鸣 |
| 4 | `[Door]` case 缺 `break`（掉进 `[BrakeHandle]`）；`[Compressor]` 同理掉进 `[Others]` | `BveConfigFile.java:164-176`、`:187-198` | 当前**无害**（键集不相交），但 `[Door] apply = x` 会错绑 |
| 5 | **MMTR 手动门丢掉关门音** | `RenderVehicles.java:245-247` 只在 `openDoorways` 非空时调 `playDoorSound`，而手动门那一支（`:150-173`）关门帧列表为空 | 关门那一下没声音 |
| 6 | `[Run] 1..7` 被静默丢弃 | `run` 数组长度固定 1（`BveConfigFile.java:12`），但 `:122-134` 接受索引 < length | 1995/1996/d78/light_rail_1..4 的 run1..N 白写，sounds.json 却还注册着 |
| 7 | `ScheduledSound` 一次性音 N 次排队的 N² 播放 | `ScheduledSound.java:24-29` | 同 tick 3 个事件 → 每个放 3 遍、3 倍响 |
| 8 | `[Horn]` / `[Buzzer]` / `[Suspension]` 等节解析后丢弃 | 三个 stock cfg 里 `[Horn]` 已写好但无效 | 喇叭根本不存在（无按键、无代码） |

**硬上限（`javap -c` 证，绕不过去）**，直接影响"自合成音效"的做法：

- **pitch 被钳到 `[0.5, 2.0]`**（`SoundSystem.getAdjustedPitch`）→ 合成时基准音高要落在这个区间，否则被压平
- **volume 钳到 `[0,1]`**，且 BVE4 的 unity 是 128、表里写到 255 → BVE4 音量曲线上半段全部塌到 1.0
- **无实时滤波**：只有 `alSourcef` 的 pitch/gain，没有 EQ/带通 → 法兰尖啸、压缩机音色、轨缝频谱**必须烘进采样**
- pitch/volume 每 **20 Hz** 刷新一次（渲染帧调、音频 tick 生效）→ 会有 20 Hz 阶梯
- 全局音源池约 247（streamed 只有 8）；一节车最多 run+flange+noise+shoe+compressor+7×motor ≈ 12 个环路，8 节编组约 96 个
