# 255 — "杆在 20、显示 20，力不是 300×0.2=60 kN"：那是 AFB 把它削掉了

用户口径（2026-09-23，notes/254 的追问回答）：

> 杆在 20，游戏里显示 20，牵引力不是 300*0.2=60kn

## 1. 现场日志（用户那一趟，服务端）

```
17:56:47 手柄=  18 定速=  80 牵引比=   0% 速度=  80.0km/h 电机=    0kN
17:56:49 手柄=  18 定速=  80 牵引比=   1% 速度=  79.8km/h 电机=    3kN
17:57:05 手柄=  18 定速=  80 牵引比=   3% 速度=  79.8km/h 电机=   10kN
```

三件事同时成立：

1. **手柄诉求确实是 60 kN**：notch 18 / 96 = 19% ⇒ `tractionRatio ≈ 0.21` ⇒ `0.21 × 300 kN ≈ 63 kN`；
2. **实际出力被削到 ~0–10 kN**：因为车**已经在设定速度上**（80.0 km/h，定速 80），
   AFB 只要贴住运行阻力（80 km/h 处 ≈ 4 kN）就够 ⇒ 牵引比 0–3%；
3. 这正是用户自己的口径："**动力手柄决定当前输出的力，AFB 根据速度来削减**" —— AFB 在削，没坏。

⇒ "力不等于 60 kN"是**对的**：60 kN 是手柄诉求，不是实际出力。想在游戏里看到 60 kN：
**把定速清掉（AFB 关闭）**，手柄放 20%，那时出力就是 `300 × 0.2 = 60 kN`。

## 2. 顺手把 HUD 改成"自己会解释"

`MmtrDriverHud` 的「电机」那行：当**手柄诉求与实际出力差 > 5 kN** 时，把手柄诉求也标出来：

```
电机   0 kN · 0.00 MW（手柄 63 kN）      ← 定速 80、车已在 80：AFB 把 63 削到 0
电机  63 kN · 0.79 MW                    ← 定速清掉、手柄 20%：要多少出多少
```

引擎侧加只读接口 `Vehicle.getMmtrHandleDemandForceN(int driveHandle)`
（`手柄比例 × 牵引曲线`，含黏着上限，**不含** AFB 削减），HUD 传**本地**手柄值（司机刚推那一下立刻可见，
不等包）。fabric / forge 两份 HUD 同步改。
