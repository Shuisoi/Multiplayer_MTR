# 191 · 打包器：同名组必须合并（否则车体静默不显示）

## 症状

BR101（以及任何 config 把多个源组映射到同一角色的模型）刷出来之后**游戏里看不见**：
车辆实体、锚点、properties 全在，OBJ 也在，就是渲染不出车体。

## 根因

MTR 按**组名**给部件建表（`nameToObjModels.put(name, model)`）——**同名互相覆盖，只剩最后一个**。
而 `groupMap` 是**故意**把多个源组映射到同一角色的：

```
BR101 的 body = car_body + buffer_beam + buffers + bogies + wiper_motors   （5 个源组）
```

打包器只**改名**、没有**合并**，于是打包后的 OBJ 里出现 5 个 `g body`
→ MTR 只留最后一个（`wiper_motors`，一小块）→ 车体等于消失。

## 实测

| | 修复前 | 修复后 |
|---|---|---|
| zip 里的组 | `body x5`、`interior x3` | `body x1` |
| 组数 / 面数 | 29 / 9154 | 23 / 9154（面数不变 ✓） |

## 修法

打包时做一次**同名合并**（`mergeSameNamedGroups`）：顶点行全部提前（面索引是绝对的，保持有效），
然后每个名字**只输出一次**，面按原顺序、并把它当时的 `usemtl` 随面重放。

## 附带发现（同样重要）：服务端会锁住 zip

- 服务端运行时**占着 `run/resourcepacks/*.zip`** → 打包器 `unlink` 报
  `EBUSY: resource busy or locked` ✗ → **zip 还是旧的** ✗。
  前几轮"明明重新打包了、游戏里却没变化"就是这个：打包器报错退出，包没写进去。
  **以后改包必须：先停服 → 打包 → 再起服。**
- `server stop` 之后 JVM **可能没退干净**（孤儿进程仍占文件 ✗），需要确认/手动结束再打包。
