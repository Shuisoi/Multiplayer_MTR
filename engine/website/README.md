# engine/website — MMTR 控制台（Vite + Vue 3 + Naive UI）

> 2026-09-11：原 Angular 脚手架（连同 MTR 官网整套前端）已整体删除，改为 **Vite 7 + Vue 3 + TypeScript + Naive UI**，
> 从零重建。本文件记录**接线与硬约定**，避免再踩已经踩过的坑。

## 〇、前后端分离（最重要的一条）

**Java 侧只做两件事：把静态文件发出去、把标准 HTTP 接口暴露出来。** 网页是**独立构建、独立部署**的前端应用。

- **dev（默认）**：`scripts/dev-server.ps1` 会设 `MMTR_WEB_ROOT=engine\website\dist\website\browser`，
  引擎（`Main.resolveWebContentProvider`）于是**直接从磁盘读**这个目录。改前端只要：

  ```powershell
  cd engine\website; npm run build      # 然后刷新浏览器
  ```

  **不需要**重打 jar、**不需要**重启服务端。（早期把前端焊进 jar，改一行 CSS 都要重启 40 秒的服务端，
  这是调试慢的根结构原因。）
- **前端热重载**：`npm run dev`（5173），`vite.config.ts` 已把 `/mtr/api` 代理到 `127.0.0.1:8888`。
- **发布**：Gradle 的 `setupWebserver` 仍会把 `dist/website/browser` 嵌进 jar（`WebserverResources`），
  没有 `MMTR_WEB_ROOT` 时引擎就用内嵌那份。发布包因此仍然是自包含的单 jar。
- **接口即契约**：前端的唯一数据来源是 `/mtr/api/map/*`（清单见第四节）。Java 改接口要当成契约变更：
  要么加字段、要么开新版本路径，别让网页跟着一起炸。

## 一、构建与部署（三个硬约定）

1. **`base: "/"`** —— 引擎静态服务把 index.html 挂在 `/`，资源必须从根路径解析。
   用 `base: "a"`（Angular 时代遗留的 `--base-href a`）会让 `/a/*.js` 落到 index 回退，**页面永远白屏**。
2. **`build.outDir = "dist/website/browser"`** —— 这个目录既是 dev 的 `MMTR_WEB_ROOT`，
   也是 Gradle 任务 `WebserverSetup` 嵌 jar 的来源。改了它，两边都断。
3. **不要开 CSP 自动注入**（Angular 的 `security.autoCsp` 那类）——它会用 CSP 把样式表锁成 `media="print"`，
   再靠一个内联脚本放行；脚本一旦被 CSP 自己挡住，页面就变成"无样式 + 无框架"的裸 HTML。

构建：

```powershell
cd engine\website
npm run build                     # vue-tsc 类型检查 + vite build → dist/website/browser
```

验证：`http://127.0.0.1:8888/index.html`（`/` 同页），静态资源在 `/assets/*.js|css`、字体在 `/media/*.woff2`。

## 五、地图页的两层：框架 + 图层（2026-09-15 定）

旧的绘图那一摊（画布 + 自写相机 + 六个图层/标记 + 尺度表，4796 行）已按用户要求整块删除
（"太混乱了"、"都搞干净然后重新构建"）。根因是三套坐标/尺寸口径（屏幕像素 / 取景基准 / 世界格）
互相打架，每层各自乘倍率。现在的分法是**两层，互不干涉**，而且落成了文件结构：

```text
views/
├── MapView.vue               ← 「地图」= 框架 + 图层清单 + 浮层（加图层/浮层都在这里加一行）
├── SectionMapView.vue        ← 「区间地图」= 框架 + 区间图层清单（轨 → 带 → 端点 → 灯 → 站台）
└── map/
    ├── mapContext.ts         ← 框架↔图层的唯一契约：常量 + 锚点 + project() + toCanvas()（provide/inject）
    ├── MapFrame.vue          ← 框架：舞台 + SVG + 相机（svg-pan-zoom）+ HTML 浮层插槽（#overlay）
    ├── layers/
        ├── RailNodesLayer.vue    ← 地图页基础图层：轨道线 + 铁路节点（它把世界范围报给框架当锚点）
        ├── SignalLayer.vue       ← 信号灯图层（节点旁的状态图标 + `^` 管辖方向）；**两页共用**，
        │                            区间地图传 `anchor-frame="rail-sample"`（见 §六）
        ├── SectionTrackLayer.vue ← 区间地图基础图层：轨道线（**引擎原始形状**，道岔淡一半，报锚点）
        ├── TotalSectionsLayer.vue ← 区间地图：**总区间的带**（1 格、一处一条、按最不利上色）
        ├── SectionCutPointsLayer.vue ← 区间地图：**区间端点**（2 格、样式同地图页节点）
        ├── PlatformsLayer.vue    ← 区间地图：**站台**（白色方括号 + 站名/站台号沿轨书写）
        ├── VehiclesLayer.vue     ← 地图页：**车辆**（**一节车一个记号**：圆角箭头 / 矩形 / 中空四边形；

        ├── TrainRouteLayer.vue   ← 地图页：**进路叠加层**（点中一列车之后，它 `route.rails[]` 的轨用强调色压上去）
        ├── vehicleMarkerShapes.ts ← 共用：记号的**三种形状**与判定（纯函数 + `vehicle-shapes.test.ts`）
        ├── vehicleHit.ts         ← 共用：**点得动**的命中判定（旋转矩形 + 屏幕余量，纯函数 + `vehicle-hit.test.ts`）
        ├── railAlignment.ts      ← 共用：轨的采样形状**对齐到端点**的规则 + 按弧长在折线上取点
        ├── BlockSectionsLayer.vue ← 区间地图：L2 方向带 —— **已从页面撤下**（见 §六），文件与用例留着

        ├── TrainCard.vue         ← 浮层：**选中那列车的任务卡片**（任务 / **目标** / 起点 / 进路）
        ├── MapActions.vue        ← 浮层：**右侧动作按钮条**（按一下对世界做一件事，走 `api/command.ts`）
        ├── nodeInteraction.ts    ← 节点浮层与图层共享的状态（命中判定在图层、显示与动作在浮层）
        └── trainSelection.ts     ← 车辆那套的同一件事：选中/悬停 + "车压在节点上时点谁"的仲裁
```

> 两张地图（`MapView` / `SectionMapView`）**共用同一套框架**（`map/`）：切换条上的三个页签是
> 区间地图（默认）/ 地图 / 时刻表。`domain/SignalPlacement.ts`（灯的方位槽）、
> `domain/TrackSection.ts`（L1 区间解析 + 区间端点）都是纯函数 + 用例。

| 层 | 是什么 | 谁定 |
| --- | --- | --- |
| **图像坐标系** | 一套自己的单位：取景窗 `MAP_VIEW = 1000`（`viewBox="0 0 1000 1000"`），**距离比例** `UNITS_PER_BLOCK = 2`（1 格 = 2 画布单位），锚点 = 世界里的哪一点落在画布中心。常量在 `mapContext.ts` | 框架 |
| **相机** | 现成控件 `svg-pan-zoom`（3.6.2，零依赖、自带类型）：只往那个唯一的 `<g>` 上写 `transform="matrix(a,0,0,a,e,f)"`。滚轮/拖拽只改矩阵，**一个画布坐标都不动** | 库 |
| **图层** | 各自取数、各自用 `ctx.project()` 把自己的世界坐标落进画布；尺寸也写画布单位（自己的常量）。层与层不互相依赖，也不碰相机 | 各图层 |

- **锚点"报到一次后冻结"**：基础图层拿到世界范围后 `ctx.setAnchor(中心)`，只有第一次生效 ——
  否则每加一个图层画面就跳一下。锚点是响应式的（`ctx.anchor`），所以先画好的图层会**一起重算**，
  不会一半旧锚点一半新锚点。图层算布局时要**先读一次 `ctx.anchor.value`**，否则它不会跟着重算。
- **加一个图层**：在 `layers/` 新建组件 → `const ctx = useMapContext()` → 在 `MapView.vue` 的
  `<MapFrame>` 里加一行。只需要守两条：尺寸写画布单位；自带 `<defs>` 时 id 取不重名的
  （整个 SVG 共享一个 id 空间）。
- **节点状态怎么拿（2026-09-16）**：`api/topology.ts` 的 `fetchMapNodes()` 一次取齐三份数据
  （拓扑 / 道岔 / 信号灯）交给 `domain/MapNode.ts` 的 `deriveMapNodes()`，拼成 `MapNode`
  = 原始节点 + `turnouts[]` + `signals[]`。**两样都可能没有**，界面必须能表示"什么都没有"：
  实测这张 dev 世界 155 个节点里 **30 个有道岔、63 个有灯、7 个两样都有、69 个两样都没有**。
  两条匹配规则：
  1. **道岔按节点键精确匹配**（实测 56/56 命中，key 就是节点键）。注意单开道岔是**每个进向一行**
     （实测 18 个节点 1 行、10 个 3 行、2 个 4 行），`MapNode.turnoutState` 给的是**根部那一行**——
     只有它的 `via === stem`，也只有它能表达位置 0/1，随手取第一行会把位置说反。
  2. **信号灯按水平面最近节点 + 5 格容差**。灯立在轨旁而不是轨上，坐标本来就不重合：实测最近节点
     偏移 **dx=±2 共 85 盏、±3 共 9 盏**，再往外是 11.4 / 21.1 格那 2 盏 —— 它们进 `orphanSignals`
     而**不是**硬塞给最近的节点（硬塞会让一盏远处的灯长在错的节点上，比不显示更难查）。
     y 不参与比较（灯比节点高 0～1 格是常态，这张图是平面视图）。
  - 用例：`scripts/map-nodes.test.ts`（8 条，`npm test` 里一起跑）。它当场抓到一个真陷阱：
    `Node` 的平面纵坐标叫 `planeZ`、`Signal` 的叫 `planeY`（同义不同名）——写错不会报"拼错了"，
    只会让距离变 NaN、**整层灯静默消失**。
  - 测试要直接用 node 跑源码，域模块的相对导入得带 `.ts`（`tsconfig.json` 的
    `allowImportingTsExtensions`，理由写在那里）。
- **节点交互（2026-09-16）：悬停显示坐标 + 左键菜单**。设计文档里的 P2 就是这件事
  （`docs/01-设计/道岔系统-方向感知与多级控制-设计.md`："点击岔口 → 显示分支 → 点 0/1/leg 即搬"）。
  - 普通节点 → 菜单只有「复制坐标」（写 `x, y, z` 到剪贴板）；道岔节点 → 菜单是**扳岔动作在前、
    「复制坐标」在后**（用一条发丝线隔开：上面是"改动世界"的操作，下面是"只是复制"）。
    **每个节点都能复制坐标**（道岔节点也一样）。扳岔动作由 `domain/MapNode.ts` 的 `turnoutActions()` 算
    （纯函数、有用例）：单开道岔（实测 28/30 个节点）给「位置 0（正线贯通）/ 位置 1（岔股开放）」，
    当前位禁用并标出；没有物理模型的岔口（实测 2/30，都是地图画法遗留的度4节点）逐行逐腿列。
    **位置↔腿的换算在那里做完** —— 腿序是"直通→左→右→其它"，位置与腿号没有固定对应，
    直接发 0/1 有时候会把位置说反。
  - **扳岔后必须回读**：`mmtr-point-op` 只要 `via` 非空就回 `ok:true`，**不带拒绝原因**
    （"车压在岔上不许扳"、腿与位置互斥都在引擎里判）。所以"受理了"≠"扳到位了"：下发完重新取
    `mmtr-points`，看那个动作是不是变成了"当前位"，才算数（不是就提示"位置没有变 + 当前状态"）。
  - **三个坑（都实测踩过，改这块之前先看）**：
    1. **浮层不能从图层里渲染**。图层的模板在 SVG 的 `<g>` 里：写 `<div>` 会被当成未知 SVG 元素
       （不渲染），`<Teleport to="body">` 也**救不了**（Teleport 把 SVG 命名空间一起带过去，
       落地仍是 SVG 元素：实测 `namespaceURI` 是 svg、`getBoundingClientRect()` 是 0×0、
       `button.disabled` 是 undefined）。→ 浮层由框架的 `#overlay` 插槽渲染（在 SVG 外面的真 HTML）。
       **判断"画出来了没有"要看命名空间与尺寸，只看 textContent 会被骗**（探针里就是这么被骗过一次）。
    2. **指针 → 画布坐标要用"带相机矩阵的那个 `<g>`"的 CTM**，不能用手写 `viewBox` 的 `<svg>` 根
       元素的 CTM（那里没有相机）——用错了命中判定永远找不到节点，而且缩放越大错得越离谱。
       这件事收在框架的 `ctx.toCanvas()` 里（相机是框架的东西）。
    3. **菜单的点击不能被当成"点了地图空白"**。菜单在舞台里，点击会冒泡到舞台元素上的
       `pointerdown`；照单全收就会先把菜单关掉，于是 `pointerup` 落到别的元素上、`click` 永不触发 ——
       **菜单看得见、就是点不动**。所以舞台的 `pointerdown` 只处理 target 是 SVG 元素的事件。
  - 命中判定按**屏幕像素**（12 px）而不是画布单位：点只有 1 格大（默认取景下 1.25 px），
    按元素监听等于拿鼠标去戳亚像素的点；`ctx.toCanvas()` 同时给出当前比例，半径随缩放换算。
  - 浏览器实测（`sandbox/node-ui-probe.mjs`，13/13 通过）：悬停浮层坐标正确且**是真 HTML、有尺寸**；
    普通节点菜单只有「复制坐标」、道岔节点菜单是"两个位置 + 复制坐标"且点下去都确实把坐标交给了
    `writeText`（无头环境读不回剪贴板，核对的是实参）；点另一位后**回读 `mmtr-points` 位置真的 0 → 1**，
    提示条"已扳到…"；图层随之重画（被淡出的出口线 27 → 28 根，与引擎新的 `prohibited` 去重根数一致）；
    探针最后扳回原位。
- **信号灯图层（2026-09-16）**：灯**不画在它的世界坐标上**，而是按其与节点的相对位置挂到节点的
  **正上 / 正下 / 正左 / 正右**（规则在 `domain/SignalPlacement.ts`，纯函数 + 5 条用例）：
  取主轴（`|dx| ≥ |dz|` → 左右，否则上下），正好落在节点上时给确定的"上"。
  - 为什么按方位槽而不是真实坐标：**灯立在轨旁不在轨上**（实测 85/96 盏正好偏 dx=±2、dz=0，其余 ±3），
    真按坐标画缩放一小就糊在一起。**以后改成人工用工具绑定远端灯**（不再靠引擎按最近节点识别）也照样成立 ——
    那时"相对位置"就是"节点指向那盏灯的方向"，主轴量化同样得到四个槽；这一层只依赖 `(节点, 灯)` 配对，
    不依赖配对是自动还是人工来的。
  - 图标 = **一个整体图形**，在**局部坐标**里画好（灯点在原点、`^` 在它**正上方**），整组只用一个
    `translate(槽位) rotate(管辖方向)` 摆出去 —— 图形长什么样只定义一次，四个方向（以及以后任意角度）
    都只是同一个图形转过去，**不是逐元素按方向算位置**（用户 2026-09-16 的要求）。灯点仍与节点**等大**
    （`SIGNAL_LAMP_RADIUS = (UNITS_PER_BLOCK − 描边)/2`，连描边一起 1 格 —— 只把半径写成一样会差一圈描边）；
    离节点的距离是 **2 格**（用户要求从 4 格缩一半）。
  - `^` 是**画出来的折线**（3 点，不是文字符号），无填充、用同一个状态色。
    形状由两个常数一起定：高 **0.6 格**、半宽 **0.6 格** ⇒ **张角 = 2 × atan(半宽/高) = 90°**、描边 0.15 格
    （= 高度的 25%，与箭头同比例）。历史：48°（高 2 格）→ 70°（高 1 格）→ 90°（半宽加到与高相等）
    → **等比缩到 0.6 格、张角仍是 90°**（用户 2026-09-16 的四次要求）。
    离灯点的竖直净空 = `SIGNAL_ARROW_GAP − 半个灯描边` = **0.20 格**。
    这里踩过三个坑：① 原来让它跟灯图标共用 0.1 格的描边 —— 折线配 0.125 px 的线，默认取景下
    **细到等于没画**，看起来像"一个没渲染出来的符号"；② 描边必须**跟着箭头一起缩**，不然小箭头上
    糊一根粗线就是一坨；③ 量"离点远近"要量**竖直净空**，不能量"折线到灯心的最近距离" ——
    张角一开大两条腿往两侧伸，那个斜向最近距离反而变大（第一次就是这么量错、被探针的 FAIL 抓住的）。
    同一槽多盏灯的外排间距也按**整个图标朝外的跨度**重算过（见 `SIGNAL_SLOT_SPREAD`）。
  - 状态色：红 `#ef4444` / 单黄 `#c8920c` / 双黄 `#ffd400` / 绿 `#22c55e` / 未给出 `#5f5f5f`。
    颜色只做"一眼看出通不通"，精确说法在节点菜单的状态行（`MapNode.stateText`）。
  - 尺寸都在画布单位里（图层顶部常量）⇒ 默认取景（1 格 = 0.625 px）下：灯直径 1.13 px、离节点 2.50 px、
    `^` 高 0.75 px / 宽 1.50 px、线宽 0.19 px、张角 90°、`^` 尖离灯心 1.63 px。同一槽里多盏灯沿同方向依次外排
    （当前世界不会撞：实测组合只有 右+左、上+下、单个）。
  - 浏览器实测（`sandbox/signal-layer-probe.mjs`，14/14 通过；探针**直接引同一份 `signalSlot()`**，不是复刻）：

    **每盏灯到最近节点的距离都是 2.000 格**；局部坐标里 `^` 的尖与两腿都在 y<0（正上方）；
