| # | 怎么做 | 通过标准 |

## §5 回退与边界（判据 §7-2 / §7-4）

| # | 怎么做 | 通过标准 |
| --- | --- | --- |
| 5.1 | 给一个**没铺牌子**的站台派自动车 | 行为与今天完全一致：车头停在站台轨远端端点（日志里还是 `stopFraction = 1.0` 那条路） |
| 5.2 | 把一块牌子的辆数改成 0（`/data merge block … {cars:0}`）后再扫 | 该条不进登记表（"辆数未设定，暂不计入停车基准"），**方块不删** |
| 5.3 | 同一 (站台, 辆数, 方向) 摆两块牌子 | 只认离站台中点最近的一块；只读出口里另一块 `conflict: true`；自动车不会两边都试 |
| 5.4 | 牌子摆在两条股道之间（贴中线） | 就近解析取最近那条；歧义时用刷子显式绑定（先把待绑站台点好再右键牌子） |
| 5.5 | 牌子摆在站台外（水平 >6 格 或 垂直 >4 格） | 不登记（日志无"登记"行）—— 这是刻意的：算不出归属就不该当基准 |

## §6 回滚

* 拆牌子 ⇒ 下一次扫描即从登记表移除（或 `stop-marker remove <x> <y> <z>`）；
* 清掉一片：`python mmtr\tools\stop-mark\mark_stop_markers.py --x -45 --y 68 --clear --apply`；
* 完全回退：删 `world/mtr/minecraft/overworld/mmtr-stop-markers.json`（引擎回退到"没有牌子"的世界，行为与今天一致）。

## §7 出问题怎么报

拿这四样：① `logs/<yyyy-MM>/` 里服务端/客户端日志（搜 `[MMTR-STOP]`）；②
`GET /mtr/api/map/mmtr-stop-markers` 的原文；③ `stop-marker list` 的回话；④ 停车后 F3 的坐标。
有这四样，"牌子算出来的点"与"车实际停的点"就能对上账。
