> **要动地图（铺轨 / 盖站 / 摆灯 / 挖填）就先读这篇。** 这里是**唯一入口**：
> 从"动手前先干什么"到"铺完怎么验"，以及各类构件（直线、曲线、车站、信号）的具体做法。
>
> 分工：

> | **本手册** | `docs/02-运行与作业/` | **怎么做**：顺序、参数、命令、验收清单 |
> | `mmtr-track-building` skill | `.dsh/skills/` | **哪里会静默出错**：铁律、几何公式、故障谱系、四层验证 |

## 0. 三条保命的事（每次动手前）

### 0.1 先取还原点

```powershell
pwsh -File mmtr\scripts\world-backup.ps1 -Label before-<干什么>
```

* 备份**不用停服**（`save-off` → `save-all flush` → robocopy，219 MB / **0.7 s**）；
* 复原**必须停服**，而且复原前会自动把当前世界另存一份 ⇒ **复原本身也能撤销**；
* **为什么必须**：施工会永久改世界，而 `/setblock … air` **不触发** `BlockNode.onBreak2`
  ⇒ 手工回滚必留幽灵轨。出处：notes/322。

```powershell
pwsh -File mmtr\scripts\world-backup.ps1 -Action list                       # 有哪些还原点
pwsh -File mmtr\scripts\world-backup.ps1 -Action restore -Label <名字>        # 回滚（会停服）
```

`sandbox/gen_p2p.py` 会**自动**先取还原点（`--no-backup` 可关）。

### 0.2 RCON 已经是一条命令读一个包

`rcon.py` / `rcon_batch.py` 现在是 **2 ms/条、不掉线**（旧实现在每条命令后发 `help` 哨兵 +
sleep 0.35 s，既慢 175 倍又是"几百次重连"的**根因**）。一次完整施工 ≈ **30 秒**。出处：notes/326。

### 0.3 判据纪律

**指令回 `ok` ≠ 东西对了。** 必须分层验（见 §10）。
凡"引擎不报错但结果不对"的，都要有独立检查器——例如
`sandbox/check_rail_above_deck.py`（专治"轨道沉进地基"）。

## 2. 施工总顺序（不能换）

```
⓪ 还原点        world-backup.ps1
① 勘察          scan_surface_area.py（地形高度 / 水陆 / 找平地）
② 加载 + 生成    forceload add（**一次 ≤256 区块**，超了静默不生效）→ 等到存档里读得到
③ 土方          清障 / 挖方 / 隧道（gen_ring_north_east.py、gen_line_climb.py）
④ 路基          smooth_stone / stone_bricks（含在 ③ 的产物里）
⑤ 铺轨          rail add（**必须在 ③④ 之后**）
⑥ 信号          setblock 摆灯 → **world scan-signals**（不扫 = 有灯无登记）
⑦ 验收          四层 + 专项（§10）
```

**为什么 ⑤ 必须在 ③④ 之后**：清障的 `/fill … air replace` 会把 `y ≥ 轨面` 的
**节点方块删掉但不通知引擎**（引擎里还留着那条轨）。反过来，铺轨之后要动 `y=轨面`
就必须先 `rail remove`。

## 3. 铺轨的基本单位：节点 + 轨

* **节点方块** `mtr:rail`：带朝向（§4.1），角点落在整数坐标上；
* **轨**（`rail add <x1 y1 z1> <x2 y2 z2> [--speed=] [--platform] [--siding] [--angle1= --angle2=]`）：
  一条命令一根，**形状完全由两端位置 + 两端朝向决定**，与命令里的其它参数无关；
* `rail add` 是**运行时**的（方块与引擎数据同时产生，不用重启）；同端点重推 = **原地替换**；
* 删轨用 `rail remove <x> <y> <z>`（= 玩家敲掉该节点方块）；**`/setblock … air` 不能删轨**。

**直线段**：节点每 **100 m** 一个（起点不在 100 整数倍上时首段可以短），两端朝向给同一个值。

## 4. 曲线

### 4.1 节点朝向空间：只有 8 个值，而且 mod 180

`getAngle` 由三个布尔算出，穷举只有 8 个：

| `facing` | `is_22_5` | `is_45` | `getAngle` | | `facing` | `is_22_5` | `is_45` | `getAngle` |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| true | false | false | **0** | | false | false | false | **90** |
| true | true | false | **22.5** | | false | true | false | **112.5** |
| true | false | true | **45** | | false | false | true | **135** |
| true | true | true | **67.5** | | false | true | true | **157.5** |

* **口径** `atan2(dz, dx)` 的度数：**0=东(+x)、90=南(+z)、180=西、270=北**（别和 MC 的 yaw 混，两者镜像）；
* **mod 180** ⇒ 一根直轨的两端本来就该是同一个值；
* ⇒ **每步 22.5° 是能切到的最细粒度**。想要更细的转向，物理上做不到。

### 4.2 三种摆法的引擎实测（`sandbox/probe_corner_angles.py`）

| 摆法 | 结果 | 能不能用 |
| --- | --- | --- |
| **终点摆在"理想弧终点"** `R·(sinφ, 1−cosφ)`，两端朝向差 φ | **✔ 79.00 m**（R=200、φ=22.5° 的理想弧长 78.5） | **能用，这就是真弧** |
| **折角**：弦沿起点方向、终点另给一个角 | ✘ **轨整条消失**（引擎给零长） | **不能用** |
| 两端同角、弦不沿该角 | ✔ 103 m（弦长 100）= S 弯 | 形状不是你要的 |
| 45° 转角（同"理想弧终点"摆法） | ✔ 157.00 m（理想 157.1） | 能用 |

**三条推论**：

1. **弧是可以切段的**（节点摆在圆弧上即可）——这点曾被判错，代价是返工三轮；
2. 一段轨的**弦必须与两端朝向一致**，否则整条被引擎丢掉（"两段直线硬接转角"做不到）；
3. 相邻两段共享一个节点，而节点只有一个朝向 ⇒ 要让**前一段的终点朝向 = 后一段的起点朝向**。

### 4.3 标准做法：**22.5° 弧段链**

方向**一步步**转过去，每段一根轨、段段相切：

```
0 → 22.5 → 45 → … → m·22.5 → … → 45 → 22.5 → 0        （上行 m 段、下行 m 段）
```

**参数关系**（选型的全部数学）：

```
横向平移量  o = 2R · (1 − cos(mφ))            φ = 22.5°
纵向占用    L = 2R · sin(mφ)
每段弧长    s = R · φ      （也就是曲线上的节点间距）
```

**"尽可能平滑" = 半径尽量大 = 总转角 mφ 尽量小** ⇒ 取**满足长度的最小 m**（`--curve-steps 0` 自动）。

**现场实例（莫氏岛东段：横向 509 m、可用纵向 1401 m）**

| `--curve-steps` | 转向到 | **R** | 每段弧长 | 曲线节点 | 前后直线 |
| --- | --- | --- | --- | --- | --- |
| **2（自动选到）** | **45°** | **869 m** | 341 m | 5 | 各 86 m |
| 3 | 67.5° | 412 m | 162 m | 7 | 各 320 m |
| 4 | 90° | 255 m | 100 m | 9 | 各 446 m |

> 不切节点的"理想 S 弯"是 R=1091 m；自动档的 4 段 22.5°、R=869 m 已经很接近，
> **而且节点一个不少** —— 这是"平滑"与"带节点"能同时拿到的最优解。

### 4.4 90° 转弯（`--mode=turn`）

同样用 4 段 22.5° 弧接出 90°（0→22.5→45→67.5→90），两端直线各带 100 m 节点。

### 4.5 双线：沿**法线**各偏 ±3

一根轨的两个端点各沿**该点法线**偏 ±3 ⇒ 弧上自然是**同心弧**，**轴距恒为 6**。
（"两条一样的弧错开"会让双线在弯里分叉。）

### 4.6 铁律：坡度**每根轨 Δy ≤ 1 格**

`rail add` 建的轨固定是 `Shape.QUADRATIC`，而 `RailMath.getPositionY` 的默认分支是**二次式**：

```java
// RailMath.java:537
return yChange * offsetValue * offsetValue / (intercept * intercept) + yInitial;
```

⇒ 两端不同高时纵向剖面**是抛物线不是直线坡**，最大偏差 **`|Δy| / 8`**。
Δy = 4 格 = ±0.5 格 ⇒ **路基按直线算就会被顶穿，轨道看着沉进地基**（notes/324 实机）。

| 规则 | 理由 |
| --- | --- |
| **每根轨 Δy ≤ 1 格** | 偏差 ≤ 0.125 格，肉眼不可见（既有爬坡段就是这么做的） |
| 落差**按弧长摊到全部轨段** | 只摊在短直线上会变成每段 2 格，又踩坑 |
| 每段**路基平顶** = `min(该段两端轨面) − 1` | 台阶落在节点上，不让路基跟着轨斜 |

## 5. 路基与清障

* **线路路基** `minecraft:smooth_stone`，顶 = 该段**低端轨面 − 1**；**车站路基** `stone_bricks`；
* **斜段 / 弧段的路基只能逐米铺轴对齐方块**（一条 `/fill` 表达不了斜条带）：
  每个采样点一个 1 米长、横向 `2×5+1` 宽的方块，**只在它自己那一米上取值**——
  **不要向两端外撑**（外撑会让斜段边缘离轨最多 4 米，而且后一段的清障会把前一段的平顶削掉）；
* **清障**从该段低端轨面往上；地形本来就在那之下的方块**直接跳过**（省一半命令）；
* 隧道判据（`gen_ring_north_east.py`）：脚下 11 列里 ≥60% 高过"轨面+7" ⇒ 只掏到那里，留洞顶。

## 6. 车站

```powershell
python sandbox/stamp_station.py --center-x <断面中心> --z-from <起点> [--axis x|z] [--rail-y 65]
```

* `gen_station.py` 只算命令，`stamp_station.py` 一次跑完（forceload → 等生成 → fills → 轨 → 灯 + 扫描）；
* **整套断面的 Y 都相对轨面**（`--rail-y`）⇒ 爬坡后的线路照样用同一套模板；
* 坐标轴：`axis=z` 时 `--center-x` 是世界 x；**`axis=x`（东西向站）时 `--center-x` 是世界 z**；
* 站台方块盖住轨的两个端节点（轨 L 米 ⇒ 站台 L+1 格）；
* **别对已建好的站重跑整个 fills**（里面的清障会把雨棚/立柱/站台一起删掉）。

## 8. 指哪打哪（一条命令从既有站接到目标坐标）

```powershell
python sandbox/gen_p2p.py --from <既有站名> --to <X> <Z> [--rail-y 71] [--mode shift|turn|straight|auto]
python sandbox/gen_p2p.py … --dry-run        # 只看计划，不动世界
```

* **目标坐标 = 新站站台中心**；新站轴向由 `--mode` 决定（`auto`：Δcross=0 → 直连，
  ≤半个站长 → 平移，再大 → 90° 转弯）；
* **源站必须是该方向的自由端**（中间站两边都有轨，v1 直接报错并列出自由端）；
* 全程自动取还原点、自动 forceload 走廊（不是包围盒）、等地形生成、按地形分路堑/隧道；
* 一次约 **30 秒**。

**源不是车站、终点也不盖站**（例：车厂牵出线往外续建）⇒ 用 `gen_depot_south.py` 那一路做法：

```powershell
python sandbox/gen_depot_south.py --dry-run --profile   # 几何表 + 沿线地形剖面
python sandbox/gen_depot_south.py                       # 真干（同一个还原点保护）
python sandbox/gen_depot_south.py --check --step 8      # 存档直读三条硬检查
python sandbox/verify_depot_south.py                    # 引擎侧 L1/L1''/L3/L4
```

要点（照抄它的 `make_source()` + `fix_grade()`）：

1. 用 `route_geom.Source(axis=…, center=…, along_lo=along_hi=自由端)` **把自由端伪装成源站**
   （`length=0` ⇒ 不盖站）；双线偏置靠 `route_geom.RAIL_DX`（牵出线间距 5 ⇒ 2.5）；
2. `build_plan` 的坡度默认摊到所有段（会落在弧上）⇒ 必须自己重排，**落差只放直线腿、弧水平**；
3. 路基/清障/灯仍用 `gen_p2p.route_fills` / `gen_p2p.line_signals`，
   但**清障要全部排在路基之前**（否则后段的清障会挖掉前段刚铺的路基顶）。

## 10. 验收清单（收工前逐条看）

| 层 | 判据 |
| --- | --- |
| L1 引擎 | `rail list` 条数增减对得上；每段长度/限速/类型对 |
| **L1′ 贯通** | 相邻段**首尾相接**；接头节点上同时挂着该有的两条轨（断口 0） |
| L2 方块 | **存档直读**：节点是 `mtr:rail` 且朝向对；结构层（路基/站台/雨棚）对 |
| L3 区间 | `mmtr-total-sections` / `signal why`：段数合理、切分到位 |
| L4 灯 | `mmtr-lamps`：每盏 `unbound=false`、位置在节点旁 |
| 专项 | 弯道另跑 `check_rail_above_deck.py`（引擎不会报这类错） |

## 11. 已知边界与取舍

| 项 | 说明 |
| --- | --- |
| **每步最小 22.5°** | 节点朝向只有 8 个值 ⇒ 曲线再平滑也只能 22.5° 一段；"更平滑"只能靠**加大半径** |
| **节点间距 = R × 22.5°** | 单段轨 = 两个节点 ⇒ 节点密度与每步转角绑死：想要 100 m 节点，半径就被压到 ~255 m |
| **弦必须与两端朝向一致** | 一段轨画不出"从 A 朝向拐到 B 朝向"的自由形状，转向只能靠**多段拼接** |
| **弧段路基按米铺** | 曲线处命令数 ≈ 弧长（米）× 2，地基是阶梯不是真曲线 |
| **坡度的抛物线** | 每根轨 Δy > 1 格就开始看得出来（`\|Δy\|/8`） |
| **`--rail-y` 必须与源站一致或按弧长摊** | 起点若另起一个不同高度的节点，会**静默断线** |
| **线路 `smooth_stone` / 车站 `stone_bricks`** | 当前是刻意的不一致，统一要两边都动 |
