> ### ★★★ 换锚还挖出两个**真 bug**（老锚上一直存在，只是没人量）
>
> **① `mmtr_cabdoor` 的"翻绕序"分支是空操作。** `r33` 里写的是
> `nf = [tuple(reversed(f)) for f in chk_f]; nf = [nf[0]] + nf[1:]`
> —— 把**所有**面翻了一遍再取 `nf[0]`，净效果是"什么都没改"，
> 而 `first_face_is_outer` 字段被写成了**恒真的假话**。同一个文件里的
> `face_normal()` 公式也是错的（`(b-c)×(cc-c)`，其中 c 是顶点**中心**，
> 那不是面法线，只是"从中心指向某条边"的方向），老锚上门叶够厚才碰巧能用。
> 两处都已改成标准公式 + **只翻第一个面**，并如实记录 `first_face_is_outer`。
>
> **② ★ 车轮被放在 `±(HALF_GAUGE + WHEEL_T/2)` —— 端面怼在轨距线上，轮心偏出一个轮厚。**
> 实测轮心在 ±0.8232、**实际轨距 1.6463**（目标 1.5，差 9.8%）。
> 之所以一直"绿"，是因为 `r34` 的自检写的是
> `gauge_from_wheel = 2 * HALF_GAUGE`、`gauge_err = |2*HALF_GAUGE − GAUGE_BLOCKS| ≡ 0`
> —— **拿输入当输出自证**，无论轮子摆在哪都通过。
> 改成"从网格量轮心（两个端面的中点）再比对"之后立刻暴露。
> 新判据落在 `sandbox/r56_verify_gauge.py`（独立脚本），实测 **轨距 = 1.500000000**。
>
> > **教训**：自检里凡是 `期望值 = 某个常量` 的，都要问一句"这个常量本身就是被验证的输入吗"。
> > 是的话，这条检查恒真，等于没有。

### 2.1 ★★ 车体比 LüP 短：整个模型的关键一条

**LüP（Länge über Puffer）= 量到【缓冲器面】的长度**，不是车体长度。所以：

```
BUF_PROJ_MM = 250.0                        # 用户视觉定（参考图量到 ~370，用户觉得伸出太多）
BUF_PROJ    = 250 × SCALE / 1000           = 0.261324...  格     (老锚 0.423728813559322)
BODY_HALF   = HALF_L − BUF_PROJ            = 9.721254...  格     (老锚 15.7627118644068) ★ 车体半长
BODY_LEN    = 2 × BODY_HALF                = 19.442508... 格 = 18,600 mm  (老锚 31.5254237288136)
```

**实测依据**（`assets/models/blender/br101/OIP.jpg` 侧视图逐像素扫描）：
车顶线 y=126、轨面 y=223 → 43.9 mm/px；整车含缓冲器 **464 px**；
车体本体约 **446 px ≈ 18,357 mm** → 每端突出 ≈ **370 mm**。
`18,360 mm` 与 `18,357 mm` 吻合 ✓

**★ 推论：控制点空间 → 格的【纵向】系数 `SX` 必须由 `BODY_HALF` 定，不是 `HALF_L`。**

```
SX_旧 = HALF_L / 8.169    = 1.9814470165217406
SX_新 = BODY_HALF / 8.169 = 1.9295766757751     （−2.62%）
SY                            不变
```

于是**所有由控制点空间纵向导出的格值整体缩 3.87%**（形状与相对比例不变）：

| 量 | 旧 | 新 |
|---|---|---|
| 车头最外点 P2.x | 16.186441 | **15.762712**（= `BODY_HALF`，钉住） |
| 车门宽 | 1.1401994 | **1.1103512** |
| 车门中心 \|z\| | 12.1601403 | **11.8418121** |
| 侧窗中心 \|z\| | 13.3625 | **13.029288** |

**不缩的**（这些不是纵向控制点量）：
车宽/前脸宽（x 向）、车高（y 向）、前风挡（宽按前脸 4.0 定）、
侧窗边长、凹龛 x/y、缓冲器全部 UIC 绝对值、`BODY_H` / `Y0` / `Y1`。

> **一句话**：**"整车长 = LüP" 和 "缓冲器伸出车身" 是同一个量，只能二选一** ——
> 选了后者（B 案），车体就得短一圈，`SX` 跟着缩。

## 3. 车头曲线（控制点空间）

用户在 `sandbox/profile.json` 里手调过 4 个控制点。**x = 距车体中心，y = 距车底，y 最大 = 车顶。**

| 控制点 | 控制点空间 | 缩放后（格） |
|---|---|---|
| P1 | (7.950, 0.000) | (**15.752504**, 1.046544) |
| P2 | (8.169, 0.485) | (**16.186441**, 2.030213) ← 最外点 = `HALF_L`，精确钉住 |
| P3 | (6.925, 2.847) | (**13.721521**, 6.820787) |
| P4 | (5.312, 3.044) | (**10.525447**, 7.220339) ← = `Y1` |

```
SX = HALF_L / 8.169 = 1.9814470165217406
SY = BODY_H / 3.044 = 2.0281851075985524
```

- 曲线用 **PCHIP（Fritsch–Carlson）**，不用 Catmull-Rom（后者过冲 0.092 格）。
- 车头剖面**凸**：从水平量起的段角 **58.8° → 54.8° → 5.2°**，单调递减。

### 3.1 曲线柔化（消除控制点处的"折"）

**根因**：PCHIP 是**保单调**插值，代价是**二阶导在控制点处跳变** → 视觉上是一段段折。

```
1) 按【弧长】均匀重采样（步长 0.05 格）
2) 拉普拉斯平滑 5 遍： nz[i] = (z[i-1] + 2·z[i] + z[i+1]) / 4
3) 控制点处按 0.6 强度回拉： nz[j] = 0.6·cv + 0.4·nz[j]
4) 两端点（车底/车顶交点）钉死；最后整体缩放到 max 精确 = HALF_L
```

实测控制点位移：**P1 +0.4 / P2 −0.1 / P3 −8.5 / P4 +0.3 mm**（最大 0.23 体素），
`normalize_scale` = 1.000042。

| 旋钮 | 当前 | 含义 |
|---|---|---|
| `SMOOTH_PASSES` | 5 | 调大更柔，**0 = 回到原始 PCHIP** |
| `SMOOTH_STEP` | 0.05 | 弧长重采样步长 |
| `SMOOTH_KEEP_CTRL` | 0.6 | **1.0 = 控制点完全不动**，0 = 不管 |

### 3.2 规格里"迎风面后倾"的算法（踩过的坑）

规格的 27° 是**从铅垂线量起**，所以 `run = 高差 / tan(角度)`。
曾把整个车高都拿去算 run，得出 12.5 格（77% 半长）—— 那是**长楔子，不是车头**。
正确做法：**迎风面下部近乎垂直，只有风挡下沿以上才后倾**（本车取 y = 4.20 为分界，高差 2.17 格 → 跨 4.26 格）。

## 4. 车体构造（第 12 步换的方法，第 13 步柔化）

### 4.1 为什么不用"环放样拼面"

前 11 步把倒角手写进环公式（用 `t_top`/`t_bot` 描述三条棱），每碰一个新角就翻一次车：
台阶 → 竖直带 → 尖点收口 → 面被收窄 → 车顶切八边形 → 选错边集 → 倒角带在角上被切断。

根因两条：
1. **倒角是三维操作**，写进二维截面公式就必然要手推每个角；
2. 环放样让"车顶周长边"在侧壁上的邻边只有 **0.006** 长 → bevel 要沿它挪 0.5，
   要么被 `clamp_overlap` 掐到 0.006，要么关掉钳制后**自交 434 对**。

### 4.2 现在的方法：实体 + 倒角

```
剖面（Y-Z 平面闭合折线）= 车头曲线 + 车顶 + 车尾曲线 + 车底
沿 X 挤出到 ±HALF_W  →  一个真正的闭合实体
只把【侧面那一圈边界】整条链拿去 bevel（跳过车底收口那条 31.8 格长边）
```

自动满足：车头面剖面形状不变（只在 X 上两侧各让 0.5）· 车顶板宽 4.0 全长不退 ·
侧壁上缘降到 `Y1 − 0.5` · **倒角带宽度恒 0.5、转角斜接、一体弯过去** · 整车长/高不受影响。

> ⚠️ **`recalc_face_normals` 必须在 bevel 之前跑。** 原始实体的绕序是**朝内**的，
> 不修就倒角偏错方向（实测宽度 5.0 → 6.0）。

### 4.3 采样与倒角参数

| 参数 | 值 | 说明 |
|---|---|---|
| `LAYER_STEP` | 0.125 | 基础高度分层 |
| `RUN_MAX_U` | 1.0 体素 | 前端进给量上限（二分加密，跑不出 1 体素） |
| `MIN_DY` | 0.015 | 剖面最小点距 |
| `ARC_STEP` | 0.06 | 剖面按弧长重采样（**太短的段会让 bevel 自交**） |
| `EDGE_CHAMFER` | 0.5 | 8 体素 |
| `clamp_overlap` | **False** | 见下表 |

**倒角参数是量出来的，不是拍的**（`sandbox/bevel_tune.py` 实测）：

| 配置 | 自交 | 车顶宽 |
|---|---|---|
| `clamp=True` | 0 | **4.569** ✗ 被短剖面段掐到 0.2156 |
| `clamp=False`，原剖面 | 22 | 4.0 |
| `clamp=False`，弧长 0.06 重采样 | 10 | — |
| **`clamp=False` + 弧长 0.06 + 退化清理** | **0** | **4.0** ✓ |
| ↑ 再去掉车底那条边 | **0** | **4.0** ✓✓ 最终配置 |

**车底不倒角**（用户明确要求）—— 车底倒角曾产生 2 处自交 + 4 个反向面，全在
`(±2.25, y≈1.30, z≈0)` 的车底倒角带上；去掉后两项归零。

### 5.3 布尔之后修掉的两个真问题（**都不是门洞本身**）

**① 车肩处倒角几乎自己收拢。**
布尔后有 2 个顶点只差 **0.00458**；第 12 步的 `dissolve_degenerate(0.004)` 恰好差一点点没抓到
（0.00458 > 0.004），于是薄片留了下来。
→ 按 **0.006** 合并，最小边长 0.00458 → **0.01582**，薄片消失。

**② 侧壁成了 226 顶点的非凸 n 边形。**
布尔为了在实心侧壁上开矩形洞，用**"窄 V 型开槽"**分解：沿一条斜边切进去 → 绕门洞一圈 →
再沿另一条斜边切出来。两个斜槽末端只差 **0.079**。
**Blender 显示没问题，但导出 OBJ 后被扇形三角化会直接翻车**（三角形跑到多边形外面）。
→ 用 `bmesh.ops.triangulate(ngon_method="BEAUTY")` 把**仅有的 2 个非凸面**三角化
（共面 → 视觉零变化，已重新出图逐像素确认）。凸的车顶 8 边形保留不动。

### 5.6 车窗（第 18–19 步）

**每端 3 个 × 2 端 = 6 个。**

| 窗 | 尺寸（格） | 位置 | 深 | 数量 |
|---|---|---|---|---|
| **前风挡** | 宽 **3.583125** × 高 **1.75** | x ∈ **±1.7915625**，y ∈ [**4.30**, **6.05**] | 0.125 | 2（每端 1） |
| **侧观察窗** | 1.125 × 1.125 | \|z\| 中心 **13.029288**，y 中心 5.3125 | 0.125 | 4（每端左右各 1） |

折合实车：前风挡 **2.114 × 1.033 m**，侧窗 0.66 × 0.66 m。

**前风挡的两次调整（用户）**：① 原本 3.25 × 2.25，太高 → **底边不动、顶边降 0.5 格** → 高 1.75；
② 再**加宽 5% 两次** → 3.25 → 3.4125 → **3.583125**。
正对前方的平面部分宽 4.0（x ∈ ±2.0），所以风挡两侧**各剩 0.208438 格（123 mm）车身**，再宽就该碰 45° 倒角了。

**前风挡在【柱面】上 —— 平面槽底是不可能的。**
前脸是剖面曲线沿 X 挤出的柱面，后倾角从 y=4.30 的 **21°** 变到 y=6.55 的 **48°**。
`z = 常数` 的平面槽底在窗顶那端会整个跑到车身外面（挖不到），在窗底那端只挖出一小条。
**正确刀体 = 剖面曲线沿【法线】内外偏出的"曲面薄片"**：

```
外边界 = 曲线向外偏 0.25   （布尔最怕共面，必须让刀体穿出车身）
内边界 = 曲线向内偏 0.125  （= 槽深）
两条边界在 y 方向两端收口成闭合多边形，再沿 X 挤出到 ±1.625
```

曲线与法线**从现有网格切片反推**（三角形-平面求交取 `min z` → 中心差分求斜率），
不重新推导公式 —— 保证刀体与模型里真实的面对齐。

**"等法线深度"实测成立**：沿 z 的退让量随高度从 **0.137 → 0.184** 单调增大，
正是 `0.125 / cos(后倾角)`（21° → 0.134，48° → 0.187）。
**若槽底是平面，这个数会是常数，或出现负值。**

**槽底范围**：`x = ±1.625` 平面；开孔下沿正好落在 **y = 4.30**；
顶端实测 **6.52**（比目标 6.55 少 **0.03 格 = 半个体素** —— 收口边是沿法线的斜线，可忽略）。

### 5.7 布尔开口的通用坑

前两条见 §5.3/§5.4（非凸 n 边形、倒角收拢薄片）。车窗新增四条：

**① 曲面上的孔：平坦槽底必然失败。** 见 §5.6。
判据：同一高度上【窗内】与【窗外】的前脸 z 相减 —— 为 0 就是没挖到；
随高度单调增大且量级 ≈ `深度 / cos(后倾角)` 才对。

**② ★ 量"孔"时取 `min z` 会把孔壁算进去 —— 我因此连续误判两次。**
车窗是**开在面中央的凹槽**，两侧的车身仍在原位，所以
"该高度上所有交点的最小 z" **永远等于原表面，无论挖没挖**。
正确做法：切片后**排除孔壁所在的那条边界**（`abs(x) < 半宽 − 1e-3`），
否则孔的侧壁（它本来就一直连到原表面）会把结论拉回 0。

**③ ★ `bm.free()` 之前必须 `bm.to_mesh()`，否则清理全部静默丢弃。**
第 18 步结尾写了 `bm.free()` 却没写回，于是 `remove_doubles` / `dissolve_degenerate` /
`join_triangles` / 非凸三角化**全部白做**，盘上存的是布尔的原始输出。
**症状：渲染脚本读到 1441 面，而生成脚本自己报告 1642 面。**
→ **两个脚本对同一个物体报出不同面数，就是"没写回"的铁证**，以后每次交叉核对。

**④ 布尔的"快照取整"会留下亚体素薄片。**
实测侧窗后沿 `(±2.5, 5.875, ∓12.80087)` 处有 **0.0008736** 的边，同处还有 **0.0014267** 的边
—— `dissolve_degenerate(1e-5)` **完全管不到**。
→ 阈值取 **0.003**（远小于当时的最小合法边 0.0158，安全）：最小边 0.00087 → **0.00312**。
**这和第 12 步那个 0.00458 的收拢薄片是两回事**：那个在倒角带上，这个在布尔切边上。

### 5.9 ★ 三个"检查说通过，但检查的不是要保存的那份网格"的陷阱

同一个病在这一轮**发作了三次**，每次症状不同。共同点：**报出来的数不是盘上的数**。

**① 下游脚本里写死的常量 → L4 检查静默返回 `null`。**
`WIND_HALF_X` 同时出现在 r18 和 r19 里，只改了 r18 → r19 按旧值 1.625 去筛顶点，
**筛不到任何东西 → 返回 `null` / `[]`**。而 `all_checks_pass` 仍是 `true`，
因为那个判据只看非流形/边界/连通分量/非凸/自交，**不包含尺寸字段**。
→ **凡 L4 尺寸检查必须同时判断"量到了没有"**（个数 0 直接 FAIL）。
→ 共享常量要么抽成单一模块，要么两边都写 `# ← 与 br101_r18_windows.py 保持一致`。

**② `bm.free()` 之前没 `bm.to_mesh()` → 全部清理静默丢弃。**
（r18 第一版）`bm` 是独立副本，不写回就 free，前面每一步都白做。

**③ `fm.validate()` 放在测量**之后**、保存**之前** → 验证的是一个已被改掉的网格。**
（r19 第一版）`validate()` 会**删掉**它认为退化的几何：脚本自己报 1522 顶点 / 1620 面，
而渲染脚本读到 **1498 / 1588**（validate 删了 32 面 24 点）。
→ **`validate()` 必须紧跟 `to_mesh()`，在所有测量之前**；测量要重新 `from_mesh` 读一遍。

**★ 唯一可靠的信号：两个脚本对同一个物体报出不同的顶点数/面数。**
所以每次生成脚本跑完，**必须用另一个脚本（渲染/探针）重新读一遍数**。
r19 现在内置了 `counts_match`（量完的数 vs `len(body.data.*)`），不匹配就拒绝保存。

### 5.9b ★ **抽壳**（用户提议，第 25 步）—— 内壁倒角的正解

用户："有没有一种办法我们可以抽壳，反正车内的东西还可以再建" —— **对，而且是唯一对的路子。**

之前我一直往【刀体】里塞倒角，三轮全部把布尔搞崩（12 条棱 / 4 条长棱 / 只倒顶棚 2 条，
见下表）。**抽壳把这个问题整个绕开了**：内壁就是外表面的**等距偏移**，
所以外表面上的车肩 45° 倒角带、车头曲线、车尾曲线，**全部原样出现在内壁** —— 不需要任何刀体技巧。

| 做法 | 结果 |
|---|---|
| 刀体倒角 12 条棱 | 非流形 126 / 边界 111 ✗ |
| 刀体倒角 4 条长棱 | 非流形 100 / 边界 11 ✗ |
| 刀体只倒顶棚 2 条 | 网格切空 ✗ |
| **抽壳（SOLIDIFY，offset=−1）** | **非流形 0 / 边界 0 / 外表面 dims 一点没变** ✓ |

**★ 关键顺序：先抽壳，再开洞。**
Solidify 在闭合体上生成的是**两片互不相连的壳**（components = 2），
门洞只通到两壳之间的夹层 ⇒ 进不去内腔。
所以洞必须在抽壳之后切 —— 刀一次切穿两片壳，两壳就**被洞口缝合**：

| 步骤 | components |
|---|---|
| 抽壳后 | **2** |
| 切完门洞后 | **1** ✓ 内腔真的通了 |

参数：`SHELL_T = 0.10`（必须 < 风挡切口，否则风挡封死；风挡切口已从 0.125 提到 **0.20**）。
抽壳前后：体积 913.03 → **67.47**（= 壳体材料），顶点 844 → 1688，dims **不变** ✓

**链的顺序（用户定）**：`r13 → r15 → r17 → r25(抽壳) → r26(地板) → r14(门) → r18(窗) → r19 → r21 → r27(缓冲梁) → r24(锚点)`

> ✅ **遗留缺陷已修**（同一轮内解决）。切穿两片壳之后一度留下 **6 条非流形边 + 4 条边界边**，
> 全部聚集在**车肩倒角带**（y 6.4–6.8、|z| 13.1–13.4）。自适应薄片清理压不掉 —— 因为它不是薄片。
>
> **真正的根因**：车体在抽壳前就已经有一条 **0.02745 的收拢边**（就在 `(±2.5, 6.396, ∓13.096)`）——
> 倒角的内缩边界在车肩处自己折回来（0.5 的倒角压在 ARC_STEP=0.06 的剖面上）。
> 它**在抽壳前是"干净但近退化"的**（非流形 0，所以查不出来），
> **Solidify 沿顶点法线偏移时在那里产出翻面/破洞**。
>
> **修法**：把 r15 的 `PINCH_DIST` 从 `0.006` 提到 **`0.035`** ——
> 盖住 0.02745，离最小合法边（~0.06，弧长重采样步长）还有富余。
> 修后最小边 **0.0275 → 0.0380**，整条链恢复全绿：

| 步骤 | 非流形 | 边界 | 部件 |
|---|---|---|---|
| r13 车体 | 0 | 0 | 1 |
| r15 清理（PINCH 0.035） | 0 | 0 | 1 |
| r17 守卫 | 0 | 0 | 1 |
| **r25 抽壳** | **0** | **0** | 2 |
| r14 开门（切穿两壳） | **0** | **0** | **1** ✓ |
| r18 开窗 | **0** | **0** | 1 |
| **r19 收尾** | **0** | **0** | 1 · `all_checks_pass: true` ✓ |

> **教训**：`非流形边 = 0` **不等于**网格健康。近退化特征（0.027 的边）能骗过所有拓扑检查，
> 却会在下一步沿法线偏移/细分时炸开。**每次都要把最小边长也一起报出来**，
> 并对它设一个下限（本项目：≥ 0.03）。

**过程中的两个真 bug**：
1. `verts, faces = [], []` 忘了重置 → 刀体 B 混进刀体 A 的几何 → 自重叠刀体（非流形 106 / 部件 **2**）。
   这让两轮"倒角失败"的结论作废、得重测（数值错了，结论没变）。
2. r15/r17/r18/r19 的报告代码假定门/窗是**有底的凹槽**；抽壳后它们是**通透开口**，
   筛不到槽底就直接 `ZeroDivisionError` / `max() empty` 崩掉。已全部加守卫，
   改成"筛不到就按侧壁上的开口边界量"。

### 5.9c 地板（第 26 步）—— 两件**不同**的事，别混

规范（`notes/181` 命名表 + 标准化工作流 §"车内可站立地面"）把它们分得很清楚：

| | 谁做 | 说明 |
|---|---|---|
| **可走地板 `floor`** | **打包器自动生成** | `type: FLOOR`，可站可走、**不渲染**。**不要建模**。无客车门叶可依据时用配置强制：`"floor": true` + `"floorHeightBlocks"` |
| **看得见的地板** | **我们自己建** | 属于 `interior`（内装，走 INTERIOR_TRANSLUCENT） |

**本步两件都做了**：
- 建了对象 **`interior`**（最终分组名），内容是车内地板
- `vehicle.br101.json` 加了 **`"floor": true` + `"floorHeightBlocks": 2.2602378`**（= 门坎高度），
  并在 `groupMap` 里补了 `"interior": ["interior"]`

**★★ 流水线顺序（用户定的）：先抽壳 → 再填地板 → 后挖洞。**
原来的顺序是"先挖洞再铺地板"，地板得去躲已经存在的凹龛，被卡成一堆妥协。
换成这个顺序之后，**铺地板时壳上还没有洞**，一切从简：

| | 旧顺序（先挖洞） | **新顺序（先填地板）** |
|---|---|---|
| 地板厚度 | 0.045238（被凹龛顶 2.21 卡住，再往下就从前脸开口探出车外） | **0.10**（用满壳厚） |
| 前后长度 | 30.433 | **30.436** |
| 量内壁 | 要在有洞的壳上探 | 在**干净壳**上探 |
| 与车体最近距离 | 0.002065 | 0.00066（留 0.001 缝） |

**尺寸**：顶面 = 门坎 `CAB_FLOOR = 2.2602378`；宽 ±2.399；厚 0.10；长 **30.436 格**；8 顶点 / 6 面。

**★ 两个把地板做对的关键（都是实测撞出来的）**：

**① 厚度被缓冲器凹龛卡死 → FLOOR_T = 0.045238，不是壳厚 0.10。**
凹龛顶 `BAY_Y_TOP = 2.21` 已经把那一带的前壁**连同壳一起切掉**（前后都是开口）。
地板只要往下越过 2.21，前缘就从凹龛口**探出车外**（实测与车体 64 对面重叠）。
所以厚度取 `min(SHELL_T, CAB_FLOOR − BAY_Y_TOP − 0.005)`。

**② 前后长度必须在【地板外缘那个 x】上量内壁，不能取切片的最小 z。**
车肩 45° 倒角带的内表面是**往里退**的：在中心处内壁在 `|z| = 15.761`，
但在 `|x| = 2.398`（地板外缘）处只有 **15.219**。用中心值会让地板的**两个前角扎进倒角带** ——
实测最近距离 0.28，那正是扎进去的量。改用外缘处的值后：长度 30.433，
**最近距离 0.002065**（= 我留的 0.002 缝），**均匀贴壁不穿模** ✓

> **另一个坑**：`BVHTree.overlap` 是**按包围盒**判的。地板是横跨整节车的大盒子，
> 包围盒和一大堆车身面重叠，全是误报（64 → 40，怎么调间隙都不归零）。
> **要判穿模得用 `BVHTree.find_nearest` 的距离**，别用 `overlap`。

### 5.9e 驾驶室隔墙（第 28 步）

用户："把驾驶室隔出来吧"

抽壳之后整节车是**一个连通空腔**，驾驶室没被隔开。做法：两端各加一道**后隔壁**。

| 项 | 值 |
|---|---|
| 位置 | **\|z\| = CAB_REAR = 11.0**（在车门后沿 11.2866 之后 —— 车门开在驾驶室这一侧 ✓） |
| 厚度 | **0.10**（= 壳厚），向车中方向 |
| 高度 | 地板顶 `CAB_FLOOR = 2.2602378` -> **内腔顶棚** |
| 几何 | 直接**追加进 `interior`** 物体（最终分组就是它），336 顶点 / 330 面 |

**★ 又用上了同一条教训（§8.21）：内腔不是矩形，隔墙轮廓不能是矩形。**
逐格打射线量内腔顶棚，实测：

| 位置 | 内腔顶棚 y |
|---|---|
| 车中（x = 0） | **7.0283** |
| 边缘（\|x\| = 2.398） | **6.58657** |

**★ 验收判据**：从**驾驶室里**朝车尾打射线，必须被隔墙挡住，
且命中点必须落在隔墙的 z 区间内（证明是隔墙挡的，不是别的面）。

> 踩到的两个小坑：① 射线起点一开始放在 `−(CAB_REAR − 0.5)` —— 那是**机器间**不是驾驶室 ✗，
> 全部打空。驾驶室在 `|z| > CAB_REAR` 一侧。② 广角机位朝向写反，拍到了车外。

**待办**：隔墙目前是**实心**的，没有司机室通门。真车隔墙上有门；
如果需要，在同一位置留一个洞即可。

### 5.9f 玻璃（第 29 步）

用户："把玻璃嵌进去吧"

**★ 归组：规范里【没有单独的 glass 角色】。** 角色表只有
`body` / `interior` / `door_l|r_<n>` / `doorway_*`+`floor`(自动) / `mmtr_*`。
工作流 §3.1：

- L206 `interior` = 内装，走 **INTERIOR_TRANSLUCENT（可透视）**
- L227 "玻璃不透 → 透明 PNG 的部件层设 INTERIOR_TRANSLUCENT；**外壁玻璃需独立 part**"
- L250 "translucent 面性能贵，只给玻璃/车窗用"

→ 玻璃做成**独立物体 `interior_glass`**，`groupMap` 里归 **`interior`** 角色。
  **不能并进 `body`**（车体是不透明的），也不能并进 `interior` 的实体件（地板/隔墙）。
  配置已改为：`"interior": ["interior", "interior_glass"]`

**★ 前风挡中间有一根【竖梁】，把风挡一分为二**（用户指出的实车特征）。

**梁必须是实体** —— 不能只把玻璃切开留条缝，否则从缝里能看穿到驾驶室。
所以做法是：**在车体上把风挡开成两个洞，中间留出梁**（那一条就是壳体本身的材料），
玻璃也相应分成两块。

| 参数 | 值 | 备注 |
|---|---|---|
| 风挡全宽 | **3.837527**（`WIND_HALF_X = 1.9187634`） | 1.7915625 × 1.05 × 1.02 = **+7.1%**（用户两次加宽） |
| 风挡高 | **1.3125**（y **4.30 -> 5.6125**） | 1.75 × 0.75 = **−25%**（用户："再扁25%"）<br>**下沿（窗台线）不动，只压上沿** —— 沿用之前"位置不变，顶部向下一点"的说法 |
| **竖梁宽** | **0.09**（`WIND_MULLION_W`） | 0.25 -> 0.12 -> **0.09**（用户两次："太粗了"、"再细25%"） |
| 侧窗纵向 | **1.204875**（`SIDE_WZ`） | 侧窗是正方形，**"加宽"只能动沿车长那一维**，高度仍是 1.125 |

**★ 位置**（洞口深 0.20）：

```
外表面 -> 玻璃外面 0.06 -> 玻璃厚 0.03 -> 内面      （沿【法线】往里量；洞口 0.20 富余很大）
四周比洞口再缩 0.002，贴住框（只留一点点防共面）
```

**★★ 两个方向别搞混（各踩过一次）**：

| 参数 | 管什么 | 用户反馈 | 现值 |
|---|---|---|---|
| `GLASS_MARGIN` | 四周的**缝** | "贴靠挡风玻璃框一点，现在是**悬浮**的" | 0.01 -> **0.002** |
| `GLASS_RECESS` | 往车里的**进深** | "像是**附在前脸上**一样，需要 **y 减小 z 增大**" | 0.03 -> **0.06** |

**★★★ 最后真正的病根是【符号写反了】，不是数值。**
用户第二轮纠正："你应该是看反了……你刚刚的操作在我看来是**需要 y 增大 z 减小**" —— 完全正确。

r29 里玻璃的偏移量原本写的是 **`zs + RECESS * nrm`**，而 `nrm` 是**朝外**的法线
（r18 的刀体正是用 `+CUT_OUT * nrm` 往车外伸）。所以那不是往里压，而是**往车外推** ——
把 `RECESS` 从 0.02 加到 0.06 只是把它推得更出去，当然还是"浮着"。

改成 **`zs − RECESS * nrm`** 才朝内：

```
−nrm = (−dz/L, +dy/L) = (y 减小, z 增大)      <- 正是用户描述的方向
```

**★ 关键几何**：前脸是**后倾**的（越往上越往后退），所以"往车里进去"这个方向
**不是纯 +z**，而是 **(y 减小, z 增大)** —— 就是曲面法线的朝内方向。
所以用户说"y 减小 z 增大"和"沿法线加大进深"是**同一件事**；
反过来，如果看到的是"y 增大 z 减小"，那一定是符号错了。

**★ 新增自检（防复发）**：`glass_behind_profile` —— 逐点算 `out_z − zs`（玻璃外面相对车头剖面），
**必须全为正**（表示在皮后面）。实测两端都是 **+0.04722 ~ +0.05525** ✓（= 0.06 × 法线 z 分量）。
写成 `+RECESS*nrm` 时这里是负的 —— 有了这条，下次一眼就能看出来。

**前风挡是曲面**：前脸是柱面，玻璃也必须是**沿剖面法线偏出的曲面薄片**，
用平面会在两端捅进车头（这条 r18 已经栽过一次）。

| | |
|---|---|
| 玻璃块数 | **8**（每端风挡左右各 1 + 侧窗左右各 1） |
| 顶点 / 面 | **560 / 544**，全是四边形 |
| 非流形 / 边界 / 零长边 | 0 / 0 / 0 ✓ |
| 到车体最小距离 | **0.009999** ✓ |

**★ 验收判据**：从**车外正对每块玻璃的中心**打射线 ——
**必须先撞到玻璃**，而且玻璃之前不能有车体面（否则说明玻璃缩进车体里了 / 没盖住）。
实测 16 条（风挡左右各 2 × 2 端 + 侧窗 1 × 4）**全部 `first: "glass"`** ✓

> 踩到的坑：风挡射线的起点写成 `sz * (zc − 1)` —— `zc` 本身是负的，再乘 `sz` 就跑到
> **另一端**去了，10 条里 6 条全打空（`first: null`）。判定"车外"要按端分别算。

> **另一个坑（值得记）**：渲染脚本会把不需要显示的物体设成 `hide_viewport = True`，
> 而**渲完不还原** —— 用户因此在 Blender 里**看不到刚建好的玻璃**，问"玻璃在哪"。
> 两个渲染脚本现在都改成：进来先 `_HIDE0` 存下所有可见性，**退出前逐条还原**。

**待办**：① 现在**没有材质**，渲染里玻璃是不透明的（上材质后才会透）
② **司机门玻璃没做** —— 4 个门洞现在只是开口，门叶（`door_l_*`/`door_r_*`）还没建，
   门叶要独立 Object 且带自己的玻璃。

### 5.10 前脸下部镂空（缓冲器凹龛）

用户："从控制点1到控制点2整个面切掉" —— 就是前脸最下那块**凸起**。

| 项 | 值 |
|---|---|
| x 范围 | **±1.9**（正脸是 ±2.0 —— **留在正脸内，不碰 45° 倒角**） |
| y 范围 | **Y0 → 2.030213**（= P1 的 y → P2 的 y） |
| 底面 | **z = −15.686354 的平面**（平底） |
| 深度 | **顶部（P2 处）0.498236 → 底部（P1 处）0.067809**，线性渐变 |
| 剖面峰值 | z = **−16.186354**（在 y = 2.046544，**不是** P2 的 2.030213） |

**★ 这个凹龛不能用"曲面薄片"（车窗那套）。** 第一版照车窗沿法线内偏 0.5，结果在**凸起峰值**附近翻车：
峰值处剖面法线方向会**翻转** → 内偏曲线自己折回来 → **自交 25 处**，
清理后还在顶棱上留下 **4 个面的非流形边**。先扫出真峰值再退 0.002 也没用 —— 那一段本来就相切退化。

**→ 改用平底盒**：底面是一个 `z = 常数` 的平面，放到**峰值再往后 0.5**。
这个高度段上的整个凸起都落在平面之前 → 整块被切掉（正是用户要的效果），
而且底面是平的，**没有任何相切退化**。
代价是深度沿高度渐变（0.498 → 0.068）：底部只切掉薄薄一层，顶部切掉半格。
视觉上就是一个从下往上加深的凹口 —— 浅处 0.068 格 ≈ 2 体积素，仍看得出来。

**为什么 x 用 1.9 而不是 2.0：** 正脸的边界正好在 |x| = 2.0（外面就是 45° 倒角带）。
刀体的侧面如果正好落在 x = ±2.0，就**和"正脸/倒角"那条棱共面**了 —— 布尔最怕这个。
取**正好 2.0 时刀体侧面与那条棱【正相切】**，布尔造出零面积面 -> 实测 6 条非流形边 + 4 条边界边。\n退到 **1.9**：留 0.1 格（1.6 体素）正面唇边，既不碰倒角、也不与棱相切 -> 全清。\n（历史：更早用过 2.2，会啃进倒角 0.2 格，用户指出"没有包在倒角内"。）

**★ 凹龛顶边是 2.21，不是 P2 的 y（2.030213）。**
用户原话"从控制点1到控制点2整个面切掉"，P2 的 y = 2.030213。但缓冲头 Ø450 mm 中心在 1060 mm
（y = 1.7966）高处 → **顶边到 y = 2.1780**，比 P2 高 **0.148 格（87 mm）**。
只切到 P2 的话，头的最上面 87 mm 会**埋进车身里看不见**。
所以顶边抬到 **2.21**（头顶 2.1780 + 0.032 余量）。P2 的值仍记在脚本的 `bay_y_top_ctrl_p2` 里备查。

**★ 两端各一个。** 第一版只建了一个盒（`z ∈ [−20, −15.686]`，只有 −Z 端），
忘了像风挡/侧窗那样循环镜像 —— **靠体积对账抓出来的**：
单端实测挖掉 1.2310，而按"面积 × 全宽 4.4"算是 1.2214，正好是**单端**的量。
（教训：只要模型的体积变化和"面积 × 宽度"对不上，先怀疑**少做了一端**。）

### 8.1 桥接协议备忘

- 请求 = `json.dumps({"type":"execute","code":<python>,"strict_json":<bool>}).encode() + b"\0"`
- 响应 = JSON + `b"\0"`；**插件读命名空间变量 `result`，且必须是 dict**
- `strict_json=False` 允许 repr 非序列化值；exec 行号比文件行号 **+2**
- Blender 顶点坐标是 **float32** → 比较容差 ≥ 1e-5
- **保存策略：每完成一步就写盘**（用户会重载 Blender，没存的轮次全丢）
- 写回顺序：先删旧的 `car_body` 物体与网格，**再** `bpy.data.meshes.new(NAME)`，
  否则新网格拿到 `.001` 会被清理循环误删
