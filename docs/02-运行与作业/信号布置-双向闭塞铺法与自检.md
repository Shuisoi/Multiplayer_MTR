# 信号布置：双向闭塞铺法与自检

> 状态：**有效（2026-09-25）**。起因：用户实机反馈「铁轨建好后信号很麻烦，不知道怎么铺双向的信号」。
> 适用：**单线双向**（一根轨、两个方向都要跑车）。双线（两条独立轨各跑一个方向）不适用，见 §6。
> 机制依据：`01-设计/闭塞区间-两层模型-设计.md`（当前唯一有效的区间模型）；工具依据：notes/283（区间叠加层）、notes/284（放灯即登记）；坑的现场依据：notes/103 §4、notes/114。

## 1. 一句话

**MTR 的灯没有"双向"这个属性：一盏灯只有一个朝向，只开一个方向的行车区间。**
所以"双向信号"不是一盏灯的事，而是**每个分界处背靠背放一对灯**（现实里也是这样：分界点两架灯，各管一个方向）。
只放单侧的后果就是 dev 世界 `x=−170` 走廊那个病：灯全朝一边 ⇒ 另一个方向没有灯可读 ⇒ **那个方向整条走廊是"一个无灯大区间"**，一列车进去就锁整条。

## 2. 两个术语先钉死（否则"朝南"会歧义）

| 术语 | 是什么 | 在哪读 |
| --- | --- | --- |
| **发光面** | 玩家肉眼看得到的那一面 | 应**朝来车**（司机迎着它开过来） |
| **FACING / 朝向角** | 这盏灯**管的那一侧**，与发光面**相反** | `signal why` 的 `朝向=`、网页 `/mmtr-lamps` 的 `angle` |

- 代码依据：选腿规则是「灯守它 FACING 那一侧的腿」（点积 > 0.1，`MmtrSectionService.resolveLegByPointState`）；渲染把模型绕 Y 转 `-angle`，**灯面在 FACING 的反面**。
- 口语换算：**肉眼看灯面朝北 ⇒ 它管南边那段**（车从北边迎着灯面来，过灯之后进入南段）。
- **别自己心算角度**：`signal why` 已经把结论打出来了 —— `区间从弧 N 开始，<方向>（走到哪一端由几何定，不看灯的朝向）`。

## 3. 铺法（六步）

1. **定分界**：站台两端、咽喉/岔前、长区间按制动距离再补切。
   两个方向的分界**不要求对齐**（错开是允许的，网页会标 `staggered`），但**成对**最省事。
2. **每个分界放两盏，背靠背**：
   - 一盏**发光面朝南** → 给**北行车**读，管**北边**那段；
   - 一盏**发光面朝北** → 给**南行车**读，管**南边**那段。
   规则：**灯立在它所管区间的入口；发光面朝来车**。
3. **放上去就登记**（notes/284）：`BlockSignalBase.onPlaced2` → 服务端日志 `[MMTR-SIG] 放灯即登记 x,y,z`，区间**同一 tick** 就切好。
   看不到这行 = 这盏灯走的是轮转扫描（≤60 s）或没有钩子的路径（`/setblock`、结构生成）；先等一轮再看。
4. **手持信号灯看叠加层**（notes/283）：手里拿着 MTR 信号灯（2/3/4 显示灯或臂板）时，轨面不再刷"轨道类型"颜色，改成**按区间上色**：
   - **跳色处 = 区间边界**（边界看不见就是没切对）；
   - **白色三角 = 该段的行车方向**；
   - 沿轨法向**两侧各一条带 = 上下行各一个方向**。
   - 判据：某方向**只有一整条长带、一路不跳色** ⇒ 那个方向缺灯。
5. **逐盏核对**：`signal why <x> <y> <z>`
   - ① 它保护的轨、起点弧、"区间从弧 N 开始，<方向>"——方向反了就是灯放反了（notes/114 那个"选腿方向搞反"的现场表现是"游戏红、网页绿"）；
   - `[选腿]` 段逐条列出该节点上每条腿的**指向 / 远端 / 与朝向点积**与结论；打印 **"无腿（判定不参与闭塞）"** = 这盏灯的位置或朝向要改（不是代码问题）；
   - `lamps`（游戏端）看每盏的 `aspect / occupied / unbound`。
6. **覆盖核对**（这才是"双向铺完了"的判据）：
   - 游戏端：`totals`（总区间，看 `directions`）、`blocks-v2 <轨>`、`tracks`、`occ`；
   - 网页：`/mtr/api/map/mmtr-lamps`（每盏应 `unbound=false`）、`/mtr/api/map/mmtr-total-sections`（看 `directions` / `staggered` / `covers[].uncovered`）；
     地图上 `uncovered` 已画成「**无灯区段**」，不是绿灯。
   - **通过判据**：① 走廊里不再有很长的 `uncovered=true`；② 每盏灯 `unbound=false`；③ 每个分界处 `directions=2`。

### 3.1 一页速查：现象 → 先看哪一条

| 你看到的 | 一眼定性 | 先敲什么 | 判据 |
| --- | --- | --- | --- |
| 某个方向整条走廊一个大区间 | 那个方向**没灯** | `totals` → `directions`、`covers[].uncovered` | 该方向应被切成多段；`uncovered` 段长度应降下来 |
| 放了灯但区间**不刷新** | 登记没跟上 | 服务端日志找 `[MMTR-SIG] 放灯即登记` | 有 → 镜像问题另查；无 → 走了轮转/无钩子路径，等一轮 |
| 灯色"游戏红、网页绿"（或反过来） | **灯放反**或选腿选错腿 | `signal why` 的 ① 与 `[选腿]` | ① 的"行进方向"应等于你打算放行的方向 |
| 某盏灯永远绿、还说不出守哪条轨 | **守不到轨**（哑绑定） | `lamps` / 网页 `unbound` | `unbound=true`、`aspect` 空（**不会给你假绿**）→ 用 §4.3 人工绑定 |
| 车到红灯前不减速/照闯 | 该方向无灯可读（不是代码 bug） | 该走廊 `direction` 上的灯数 | 补朝该方向的灯（notes/103 §4 就是这个结论） |

## 4. 四个坑（都踩过）

1. **单侧无灯** ⇒ 那个方向一个大区间：一列车在里面，同方向后车只能停在块外；`x=−170` 走廊是现成例子（notes/103 §4）。
2. **灯面放反** ⇒ 管错方向；症状是灯色与网页 / `signal why` 不一致（notes/114）。
3. **守不到轨** ⇒ `unbound=true`、`aspect` 空。灯离轨 2 格以上（门架、悬挑）或密集布置时用**人工绑定**：
   `/give @s mtr:signal_binder` → **先右击灯、再右击轨道节点**（BOUND，人工绑定优先于自动选腿）。
4. **岔口别每腿放一盏**：一盏灯守**整个咽喉**的多条腿（每腿各建一段区间，显示取**最不利**的那条）。道岔当前禁行的那条腿**也照样守**（标 `reachable=false`，"守着但不判断路"），但走行**撞在禁行侧 ⇒ 红**。

## 5. 为什么必须成对（机制，一句话版）

| 层 | 方向性 | 由什么切 |
| --- | --- | --- |
| **L1 轨道区间** | **无方向**，双向共用；**占用判定只在它上面做** | 切点**只由灯**产生（哪边朝向的灯都算） |
| **L2 行车区间** | **有方向**，灯到灯、跨轨 | 从"一架朝方向 D 的灯"起，沿 D 走到**下一架同向灯**为止 |

推论：**方向 D 的分界只能由朝 D 的灯给出**。某个方向没有灯 ⇒ 该方向只剩**无灯大区间**（每块两段，id `无灯#<L1 id>` / `无灯#<L1 id>·逆`，`entrySignal` 空）。
附带好处：补上的一对灯也**顺带把占用粒度切细了**（L1 切点只由灯产生）。

## 6. 边界（不适用 / 刻意不做）

- **双线**（两条独立轨各跑一个方向）：各自按单向铺即可，**不需要**成对。
- **不做"某方向无灯就自动补一盏"**：这属**布置**，不做代码（旧设计文档 §S5 同一口径）——本文就是它的替代品。
- 分界别贴着站台门、道岔尖（清限区 10 m）放；长区间要留够制动距离余量（现实里的提前量：英铁 AWS 磁铁在信号机外方 ≈183 m（200 yd），中国预告信号机距主体 ≥800 m，见 §7）。

### 7.1 四条依据（互不替代，取交集）

| # | 依据 | 决定什么 | 现实里的硬约束例子 |
| --- | --- | --- | --- |
| ① | **它所防护的险阻点**（前方信号机 / 道岔 / 站台 / 道口 / 尽头线）+ **制动距离** | 灯离险阻点多远；灯立在它所防护区段的**入口**，**外方**才是来车方向 | 进站信号机距进站遇到的**第一个道岔尖轨 ≥50 m**（因调车与制动距离一般 ≤400 m）；预告信号机距主体 **≥800 m**，主体显示距离不足 400 m 时 **≥1000 m** |
| ② | **检测区段的物理边界**（钢轨绝缘节 / 计轴点） | 灯与**区段边界同坐标**（现实里"灯摆哪"和"绝缘节在哪"是同一件事的两面） | 装轨道电路的车站：**钢轨绝缘距警冲标 3.5–4 m**；信号机与绝缘**原则上同一坐标**（允许绝缘在信号机前方 1 m、后方 6.5 m 内）；划不出 ≥25 m 无岔区段时，两架**背向**调车信号机**并置在同一绝缘点两侧**（这就是"背靠背一对"的现实原型） |
| ③ | **瞭望 / 显示距离（sighting）** | 灯能不能在制动距离起点被看清；看不清就挪位置或加预告 | 中国：**左侧行车制 ⇒ 信号机设在列车运行方向线路的左侧**（司机位在左）；不得侵入建筑接近限界（高柱信号机突出边缘距正线中心 **≥2440 mm**、到发线 **≥2150 mm**，曲线另加宽），间距不足用信号桥/托架；不能连续显示 1000 m、常有降雾暴风雪时须设预告信号机 |
| ④ | **机位与作业细则** | 具体坐标的取舍 | 出站信号机在**警冲标内方**线间距足够处（尽量不影响股道有效长）；站内上水处信号机距水鹤 ≥50 m；道岔区段、道口、桥隧各自收口 |

### 7.2 双向这块：现实靠"制度 + 方向控制"，不靠"反向也摆一排灯"

- 双线区间正常只按**规定方向**行车，反方向要办手续：**《铁路技术管理规程》**把"**无双向闭塞设备的双线区间反方向发车或改按单线行车**"列为须按特定办法办理的情形（[原文](https://www.nra.gov.cn/xxgk/gkml/ztjg/gfzd/bmgz/202206/t20220624_327439.shtml)）；
- 单线双向 / 装设双向闭塞设备的区间，靠**闭塞制度与方向控制**（方向电路/改变运行方向、区间空闲确认、联锁进路）保证"同一时间只有一个方向有权占用"，而不是靠"两个方向都摆满通过信号机"；
- 所以现实里"反方向没有通过信号机"**不等于**不安全：安全由闭塞制度承担。**游戏里没有这层制度**，于是"该方向没灯"就直接退化成"整条一个大区间"（§1 的 `x=−170` 走廊）——这就是我们**必须成对补灯**的原因。

### 7.3 搬到游戏里：哪些照搬、哪些不存在

| 现实依据 | 在 MMTR 里 |
| --- | --- |
| ① 制动距离 / 险阻点 | **照搬**：分界位置按你线路的限速与制动模型（`01-设计/制动系统-气压与制动力模型-设计.md`）留够距离，**不要等距摆**；岔前、站台端按现实留 ≥50 m 级余量也比贴脸放稳 |
| ② 绝缘节 / 计轴点 | **不存在**：切点**只由灯**产生。等价的次序是反过来 —— 现实"先定区段边界再立灯"，游戏里"**你放灯 = 同时定了区段边界**"，所以 §3 第 1 步"定分界"就是现实里的"定绝缘节坐标" |
| ③ 瞭望 / 限界 / 左侧行车 | **不存在**：MTR 灯只能贴在轨旁/节点，左侧行车、限界、曲线加宽都无意义；保留的只有"**朝向要对**"（= 现实里"显示面朝来车"） |
| ④ 并置（背向两架在同一绝缘点两侧） | **就是本清单的"背靠背一对"**（§3 第 2 步）；游戏里可以放在同一节点、也可以错开（错开 = 现实里两方向分界不重合，网页标 `staggered`） |
| AWS 183 m / 预告 ≥800 m | **可照搬**当提前量：他们实现的 AWS 触发带就挂在灯上（`notes/103` 实测 26.9 m 触发，属游戏尺度） |
