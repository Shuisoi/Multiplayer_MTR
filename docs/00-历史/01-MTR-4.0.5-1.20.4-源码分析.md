# 01 MTR 4.0.5（MC 1.20.4）源码分析

分析对象：`sources/Minecraft-Transit-Railway-master`（GitHub `Minecraft-Transit-Railway/Minecraft-Transit-Railway` @ master，`gradle.properties` = `version 4.0.5 / minecraftVersion 1.20.4`）。许可证 MIT。以下结论均来自本仓库源码的直接阅读。

## 1. 仓库与构建系统

- Gradle 多模块：`settings.gradle` include `fabric` 与 `forge`；`gradle.properties` 直接定义 `version` 与 `minecraftVersion`（当前 4.0.5 / 1.20.4）。
- 平台代码生成：仓库内**真正的 Java 实现只存在于 `fabric/src/main/java/org/mtr/mod`（约 360+ 文件）**；`forge` 模块只有少量入口/模板（`org/mtr/init/MTR.java`、`mods.template.toml`、mixins json），构建期由 `buildSrc` 的 BuildTools 把实现代码与模板（`*Template.java`、`*.template.json`）渲染成 Forge 源码/元数据——README 中的构建命令即：
  ```
  gradlew setupFiles -PminecraftVersion="<mc>"
  gradlew build     -PminecraftVersion="<mc>"
  # 产物: build/release/MTR-<fabric|forge>-<版本>+<mc版本>.jar
  ```
- 本地预编译依赖（`libs/`，随仓库分发、会打进 jar）：
  - `Transport-Simulation-Core-0.0.1.jar`（TSC 交通模拟引擎，MTR4 的“后台”）
  - `Minecraft-Mappings-*-1.20.4-0.0.1.jar`（org.mtr.mapping，跨 Fabric/Forge 的 MC 抽象 API）
  - `Minecraft-Mod-API-Tools-0.0.1.jar`（org.mtr.mapping.registry：Registry/RegistryClient/事件）
  - `Shadow-Libraries-*.jar`（Gson、Jetty、fastutil 等，打包时 relocate 到 `org.mtr.libraries`）
- JSON Schema → Java 代码生成：`buildSrc/src/main/resources/schema/` 下的 `resource/*.json`（新格式）与 `legacy/*.json`（旧格式）由构建工具生成 `org.mtr.mod.generated.*` 类（如 `CustomResourcesSchema`，源码仓库中不存在、构建期生成）。**Schema 就是权威的数据契约**，已全部复制到 `docs/reference/`。

## 2. 发布 jar 内部结构与依赖面

以 `mods/MTR-fabric-4.0.5+1.20.4.jar` 实测：
- 一级：`assets/ data/ org/ fabric.mod.json mtr.mixins.json mtr.accesswidener minecraft-mappings.accesswidener mtr.refmap.json 1.20.4-mapping-refmap.json jetty-dir.css ...`
- `org/`：`org/mtr/core`（TSC 引擎）、`org/mtr/mapping`（映射抽象）、`org/mtr/libraries`（重定位三方库 + `org/eclipse/jetty` 内嵌 Web 服务器）、`org/mtr/mod|legacy|mixin|init`。
- `fabric.mod.json`：id `mtr`，入口 `org.mtr.init.MTR`(main)/`MTRClient`(client)/ModMenu/Jade；声明依赖仅 `fabric` loader + `minecraft 1.20.4`。
- 自带的默认内容就在 jar 的 `assets/mtr/mtr_custom_resources.json`（默认列车/轨道/站牌/电梯等）+ `mtr_custom_resources_pending_migration.json`。

## 3. 运行时架构（源码实证）

- 入口：Fabric `MTR.onInitialize → org.mtr.mod.Init.init()`；Forge 同理。`InitClient.init()` 为客户端侧。
- 服务端启动（`Init`）：世界就绪后
  `main = new Main(<world>/mtr, serverPort, threadedSimulation, threadedFileLoading, webserverSetup, worldIds)`
  即在本进程内启动 **TSC 引擎实例**（数据存 `<世界目录>/mtr`），每 tick `main.manualTick()`、每 30s 自动存档、每世界 `RailActionModule` 处理 TSC→MC 消息（`MinecraftOperationProcessor`）；游戏时间与 TSC 同步（50 秒/游戏小时）。可以单线程（与主线程同步）或线程化仿真。
- 客户端（`InitClient`）：启动本机 Web 服务器（Jetty），日志可见：
  `Open the Transport System Map at http://localhost:<port>`
  `Open the Resource Pack Creator at http://localhost:<port>/creator/`
  servlet 集合 `org.mtr.mod.servlet.*`：`ClientServlet`、`ResourcePackCreatorOperation/UploadServlet`、`MinecraftOperationProcessor`。客户端在本地 Web 上提供**在线系统图**与**资源包创作器**（生成/上传/热重载车辆资源）。
- 数据流：`CustomResourceLoader.reload()`（客户端）用 `ResourceManagerHelper.readAllResources(identifier mtr:mtr_custom_resources.json)` **跨所有资源包**读取同名 JSON 并叠加；每条解析为 `CustomResources`（继承生成的 Schema 类），缓存在 `VehicleResourceCache/VEHICLES/...`；旧格式经 `org.mtr.legacy.resource.CustomResourcesConverter` 自动转换（读 `Config.readResource` 的 JsonObject，同时尝试 legacy 与新 schema）。

## 4. 资源格式（扩展/建模最相关，MTR4 现状）

主文件（任意资源包，可叠加）：`assets/mtr/mtr_custom_resources.json`，顶层：
```json
{ "vehicles": [], "signs": [], "rails": [], "objects": [], "lifts": [] }
```
引用模型/贴图的标识符用 `namespace:path`（如 `mtr:models/vehicle/bogie_1.bbmodel`）。

### vehicle（车辆/列车等）要点（`vehicleResource.schema.json`）
- 顶层车辆定义：`id/name/color(6位hex)/transportMode(TRAIN|BOAT|CABLE_CAR|AIRPLANE)/length/width/bogie1Position/bogie2Position/couplingPadding1/2/hasGangway1/2/hasBarrier1/2/description/wikipediaArticle/tags`，以及 `models[]/bogie1Models[]/bogie2Models[]`。
- 每个 model 条目（`vehicleModel.schema.json`）：`modelResource(.bbmodel|.obj|.json) + textureResource + modelPropertiesResource + positionDefinitionsResource + flipTextureV`。
- `modelProperties`：`modelYOffset`、车厢间贯通道 gangway 与隔档 barrier 的 6 面贴图/宽高/偏移、`parts[]`。
- `modelPropertiesPart`（每“部件”）：`names[]`（对应 .bbmodel 中的分组名）+`positionDefinitions[]`+`condition`（NORMAL/AT_DEPOT/DOORS_OPENED/…圣诞灯等）+`renderStage`（LIGHT/ALWAYS_ON_LIGHT/INTERIOR/INTERIOR_TRANSLUCENT/EXTERIOR）+`type`（NORMAL/DISPLAY/FLOOR/DOORWAY/SEAT）+`display*`（目的地/线路号/下一站等 LED 屏配置）+`door*`（开关门动画：STANDARD/PLUG/BOUNCY/MLR/R179/R211 等）。
- 支持模型文件：**Blockbench .bbmodel**（标准：根元素名 = 部件，分组=parts names）、OBJ（MTR4 新支持，源自 NTE）、Minecraft block model .json、以及 MQO（`MqoModelConverter`）。内置 `BlockbenchModelValidator` 会在加载时校验 .bbmodel 合规性。
- 自带车辆数据即真实范例（`assets/mtr/mtr_custom_resources.json`，伦敦地下铁 D78/1995/1996/S7/S8、MLR、C114 等几十款），字段结构可直接照抄改造；官方另有更小的示例包 `examples/MTR Custom Resources.zip`（已复制到 `docs/reference/`）。

### 其他资源
- `signResource`（铁路标牌贴图，支持多语言/小尺寸/镜像），`railResource`（自定义轨道类型，含轨道模型/底座），`objectResource`（装饰物，可含动画部件），`liftResource`（电梯贴图变体）；详情见 `docs/reference/*.json`。
- 资源热重载：游戏内改动后执行资源重载即可看到新内容（客户端 `ReloadCustomResourcesScreen`，配合 Creator 网页端更顺手）。

## 5. 注册体系与包地图（Java 侧）

`org.mtr.mod` 根：`Blocks/Items/BlockEntityTypes/EntityTypes/CreativeModeTabs/SoundEvents.init()` 注册全部内容，统一走 `org.mtr.mapping.registry.Registry(REGISTRY)`（`Init.REGISTRY` 静态公开）；客户端 `REGISTRY_CLIENT` 注册渲染类型/实体渲染/按键等。Packet 在 `Init.init()` 用 `REGISTRY.registerPacket(...)`（约 30 个 `Packet*`）。
- `block/`（107）：站台/轨道节点/信号/PIDS/电梯/门/楼梯扶梯/车站设施等方块（如 `BlockSignalBase`、`BlockLift*`、`BlockAPG*`、`BlockCeiling*`…）。
- `item/`、`entity/`、`render/`、`screen/`（GUI）、`packet/`、`sound/`、`model/`、`client/`、`data/`（含 `RailActionModule`、`ArrivalsCacheServer`）、`config/`、`servlet/`、`resource/`（上文）、`legacy/resource/`（转换器）。
- TSC 世界数据模型（`org.mtr.core.data`）：Station/Platform/Route/Depot/Vehicle/… 在引擎内维护，Minecraft 侧经消息与事件消费。

## 6. 衍生模组/Addon 的可行扩展点

MTR 4 **没有官方 Addon API/事件总线**；社区 Addon 的普遍做法（仓库实证：`DistrictOfJoban/Joban-Client-Mod`、`jonafanho/MTR-Station-Decoration-Addon`、`jonafanho/MTR-Russian-Metro-Addon`、`WerySkok/MTR-Russian-Metro-Addon`、the-tube/London Underground 等）分两类：

1. **纯资源包（数据层，零 Java，推荐先做）**
   - 新车辆/船/飞机：Blockbench 建 .bbmodel（Modded Entity），按第 4 节 schema 写 vehicle 定义到 `assets/mtr/mtr_custom_resources.json`，模型/贴图/属性 JSON 放进同包 `assets/mtr/models|textures|properties|...`。无需编译，跨版本兼容好，玩家当作资源包启用即可；衍生模组也能把这份 JSON 打进自身 jar 的 `assets/` 自动供给。
2. **Java 衍生模组（需要代码逻辑时）**
   - 以 MTR jar 作为 `compileOnly/depend`（fabric.mod.json `depends: mtr`）后，可直接引用 `org.mtr.mod.*`/映射 API 注册自定义方块/物品/实体、复用站台/轨道/信号基类；参考 JCM：自定义方块 + mixin + 数据驱动贴图/模型。
   - 更深度的改造（想改核心渲染/信号/仿真）则应 fork MTR 仓库按第 1 节命令自编译（输出与官方同名的 `MTR-fabric-4.0.5+1.20.4.jar`）。
   - 注意点：版本锁死 1.20.4 + MTR 4.0.5；与 NTE（mtrsteamloco）互斥；资源命名用小写/无空格。
