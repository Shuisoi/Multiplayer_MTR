     游戏里的车正常"→ 当场"就现在，我卡死了"。先排掉服务端拽人（全窗口 `外部挪动=0`、全 mod 没有一处
     服务端 teleport）、tick 被卡（稳定 20 TPS）、渲染线程死掉（每 2 秒一条心跳不断档）——
     **真相是"tick 还在跑、画面不出帧"**。jstack 连续两次停在同一样东西上：
     `Arrays.fill ← ArrayOcclusionCache.resetCache ← WorkerThread.runTick`，5.15 秒里烧掉 3.77 秒 CPU
     （**73% 的一个核**）。根因是缓存大小是 reach 的**立方**：渲染距离 32 区块 ⇒ reach=512 ⇒
     `new byte[(2*512)³/4]` = **256 MB**，清一次 ~7 ms；而 `runTick` 是"睡 10 ms → 队列非空就 reset 一次
     + 每队列只跑一个任务"，消费上限 100 个/秒 < 每帧产出 ⇒ 队列长期满 ⇒ **每秒清约 100 次**
     （≈700 ms/秒、≈25 GB/s 纯内存写），并且任务被调度方丢掉（花了 CPU 却没做剔除）。
     修法两处：①新增 `MmtrSparseOcclusionCache`（库允许注入缓存），只清"本帧碰过的字节"，
     与库实现逐位一致（2 万步对照用例）；②`runTick` 改成"有活一口气干完、没活才睡"。
     顺带装上三行默认开的取证：`[MMTR-PERF]`（**帧率与 tick 率分开量**）、`[MMTR-LAG]`、`[MMTR-CL]`。用例 4/4。
