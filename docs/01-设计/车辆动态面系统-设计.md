# 车辆动态面系统 · 设计（MMTR Dynamic Vehicle Faces）

> 状态：**F0 地基 / F1 作者可用 / F2 工作室 / F3 复杂业务 / F4 代码面 已落地**（见 notes/359、notes/360 与 notes/361）；
> 面文档格式的权威表在 [`车辆动态面-面文档格式.md`](车辆动态面-面文档格式.md)。
> 口径来源：用户 2026-10-02「动态的东西会很多，需要构建一个子系统专门处理这些动态面的显示以及绘制器，
> 否则其他构建者或者车体作者难以制作车辆资源包」；方案选定为**方案 A**。

## 1. 这个子系统解决什么

一块"动态面"= 车体上的一块平面 + 上面**随车状态变化**的内容（水牌、下一站牌、车厢 PIS 内屏、
司机台综合屏、灯箱、故障提示……）。在它之前，这类东西每来一个需求就得改一次客户端 Java：
版式写死、条件只能"有值就画"、动画没有、第三方想加一块屏无从下手。

这个系统要把四件事分开，且**每一件都有稳定的接口**：

| 谁 | 只负责 | 产物 | 需要会什么 |
| --- | --- | --- | --- |
| 车体作者 | 牌**多大、在哪、朝哪** | Blender 里的 `mmtr_*` 锚点 | Blender |
| 资源包作者 | 牌上**画什么、什么时候画** | 锚点 JSON 里的 `faces` 段 | JSON（逻辑用 JSONLogic） |
| 附属模组开发者 | 缺的字段 / 公式 / 画法 | Java SPI | Java |
| 引擎维护者 | 数据**镜像**出来 | 字段 + 稀疏补丁 | 引擎 |

## 2. 信任边界（★ 方案 A 的核心决定）

**资源包是不可信内容**：它会从服务器、从别人的整合包进到玩家客户端。所以：

- 资源包里**只有声明式数据**，由本系统的求值器解释：没有反射、没有 I/O、没有类加载、有预算上限
  （≤512 节点 / ≤24 层）。恶意资源包能做到的最坏情况是"这块牌画歪了"；
- 想要**代码级**能力，走 **Java SPI**（元素画法 / 自定义算子 / 模板过滤器 / 客户端算的扩展字段 ——
  四样都在 `MmtrFaceRegistrar` 上，见 §8）：那已经是"装了一个模组"，信任级别与其它模组相同，
  不由资源包触发；
- 明确**不做**：在资源包里执行 JS/脚本（那是把资源包变成任意代码执行通道）。

## 4. L0 · 数据接口

字段登记表就是**给外人看的接口**，一行一个量：名字 / 类型 / 单位 / 来自哪个镜像字段 / 更新节拍 / 说明。
导出的 `tools/face-studio/fields.json` 供 web 工作室做自动补全，并由用例**逐字**比对（防漂移）。

**四方核对**（`MmtrFaceFieldsTests`）：登记表 ↔ 取值口 `case` ↔ 引擎 `DYNAMIC_KEYS`（节拍）↔ 导出文件。

**加一个新量 = 四步曲**：
1. 引擎侧算出来并进镜像（`schema/data/vehicle.json` 加字段；写的地方标脏；每 tick 变的量必须进
   `VehicleSyncPatch.DYNAMIC_KEYS`，否则客户端只在整份快照时更新 —— notes/257 的"读数不实时"）；
2. `MmtrVehicleFaceSource` 加一个 `case`；
3. `MmtrFaceFields` 加一行；
4. 重生成 `fields.json`（用例不一致时会写出 `fields.json.actual`）。

**两条口径**：取不到 = 不放进去；空串也算没有。于是 `var`／`missing`／模板三个用法对"没有这个量"的理解一致。

## 5. L1 · 面文档（作者写的东西）

```json
"faces": {
  "<锚点名>": {
    "background": "#FF101418",      // 缺省透明（牌底交给模型）
    "textColor":  "#FFF2F4F6",      // 文本元素没写 color 时用它
    "pxPerMetre": 512,              // 缺省 512
    "side":       "normal",         // normal（朝读它的人，默认）/ driver（仪表面板）/ both
    "require":    {"!!": [{"var": "pid.service"}]},   // 整块面画不画
    "vars":       {"arriving": {"<": [{"var": "lzb.targetM"}, 200]}},
    "elements":   [ … ]
  }
}
```

**★ 面名 = 锚点名**：模型里那个锚点叫什么，文档就写在 `faces.<锚点名>` 下。由此：

- 再加一块牌**不用改客户端**（打包器给锚点 + JSON 写文档）；
- "哪块牌归谁画"有唯一答案：**有文档的锚点归面系统，没文档的仍归老渲染器**
  （`MmtrPidBoard` 会跳过有文档的锚点）⇒ 把水牌切到面文档是**纯资源包动作**。

### 5.1 元素（9 种；键与缺省的权威表见 `车辆动态面-面文档格式.md` §5）

| type | 键 | 说明 |
| --- | --- | --- |
| `text` | `text`（模板）、`x,y,size`、`align`、`color`、`shrinkToFit`（默认 0.9）、`when` | 取不到内容 ⇒ 不画（不是画空位） |
| `rect` | `x,y,w,h,color` | 实心矩形 |
| `roundRect` | 同上 + `radius` | 圆角矩形 |
| `line` | `x,y,x2,y2,width` | 直线（圆头） |
| `circle` | `x,y,radius` | 实心圆 |
| `arc` | `x,y,radius,start,end,width` | 圆弧（角度逆时针从 +X 起） |
| `gauge` | `x,y,radius,start,end,max,ticks,labelEvery,lineWidth,needle,needleColor,needleWidth,needleLength` | 表盘 + 指针；指针值来自 `needle` 表达式（默认车速） |

几何一律**比例**：`x/w` 乘牌宽，`y/h/size/radius` 乘牌高 ⇒ 同一份文档贴到任何尺寸的牌上都等比。

### 5.2 模板与过滤器

`"开往 {pid.terminus}"`；过滤器：`upper / lower / trim / int / num:N / pad:N / len / default:文本`。
`{{` `}}` 是花括号转义。数字默认不写小数点后缀（`1.0` 写成 `1`）。

## 6. L2 · 逻辑层：JSONLogic 子集

- 算子：`var`（点号路径 / 数组下标 / 缺省值）、`if`、`and`、`or`、`!`、`!!`、`==`、`!=`、`===`、`!==`、
  `<`、`<=`、`>`、`>=`、`+`、`-`、`*`、`/`、`%`、`min`、`max`、`cat`、`substr`、`in`、`missing`、
  `missing_some`、`?:`、`some`、`all`、`none`、`filter`、`map`，以及自定义 `fn:*`（SPI）。
- 口径：真值 = `null`/false/0/空串/空数组为假（`"0"`、`"false"` 是**真**）；两边可数字化按数字比；
  **有一边 null ⇒ 比较一律假**（不把缺数据当 0）；类型不匹配的算术 ⇒ null。
- 预算：≤512 节点、≤24 层（超了抛，调用方跳过那一个元素）。
- **共享测试向量** `tools/face-studio/conformance/logic.json`（68 条）：Java 端两种数据形态各跑一遍，
  web 工作室的 JS 端跑同一份文件 —— "浏览器里试出来的条件进游戏还是那个结果"因此可证伪。

## 7. L3 · 绘制器

- **节拍**：数据每帧每车一份（同一帧十几块面读同一份）；贴图只在"文档身份 + 数据 + 牌面尺寸 + 像素密度"
  签名变化时重画；四边形每帧照画。
- **画在哪一侧**由文档的 `side` 说（`MmtrPanelQuad.drawSide`）——notes/357 那个"背面剔除让整块牌看不见"
  的坑从此是数据可配的。
- **错一处不毁一块面**：条件求值抛异常 / 类型不认识 / 模板写坏 ⇒ 跳过那一个元素 + 记一次日志。
- 元素注册表就是"缺画法"的落点：`MmtrFaceElements.register(type, painter)` 已经是代码级入口（附属模组不用改引擎）——
  F4 把它连同另外三个 SPI（算子 / 过滤器 / 字段）一起做成了**对外契约**
  （`MmtrFaceRegistrar` 的四个 sink），并加了"工作室导出 Java 骨架"（见 §8）。

## 8. 升级阶梯（"复杂 UI"卡住时走哪条）

**前四级的现状**（F4 已落地，所以"要一个现成元素画不出的东西"不再是"等引擎支持"）：

| 级 | 卡在哪 | 做法 | 现状 | 判据 |
| --- | --- | --- | --- | --- |
| 1 | 能用现成元素/条件表达 | 写 JSON | 已可用 | 面文档用例 + 自检 P1..P9 |
| 2 | 缺**算子/过滤器** | `registrar.function("厂家:名字", (arguments, data) -> …)` / `registrar.filter("厂家:名字", (value, parameter) -> …)`；提成内置则要同时改 Java、工作室与共享向量 | **已可用** | 向量**含负例** |
| 3 | 缺**画法** | `registrar.element("厂家:名字", (canvas, document, element, paint) -> …, "它认的键"…)` | **已可用** | 元素用例 + 出图 + 骨架真的编译过 |
| 4 | 缺**取值** | ① **客户端算**：`registrar.field(new MmtrFaceField(){…})` —— 拿已收集好的快照算一个新量；② **让引擎多一个权威量**：加字段四步曲（引擎 → 取值口 → 登记表 → 重生成 `fields.json`） | ① **已可用**；② 属引擎改动、**不是 SPI 的活** | ① 扩展字段用例；② 四方核对用例绿 |
| 5 | 跨面协同（整列车同步翻页等） | 需要面级 state + 数据提供者 | **还没有这条路** | —— |

每一级都**不改资源包格式**：作者侧永远只是 JSON 里多一个字段名、一个算子名或一个 `type`。

**三条边界**（都在格式文档 §12.1 里写死了）：

1. 扩展注册的名字**必须带命名空间**（`厂家:名字`），不带的一律被拒绝并记一条账（`MmtrFaceExtension.isNamespaced`）；
2. 扩展的键**不进** `schema.json`，扩展字段**不进** `fields.json`，扩展算子/过滤器**不进**
   `operators()`（32 个）/ `filters()`（8 个）—— 那三份是"随包发行"的最小集，工具一致性用例逐项钉着；
   要问"这个客户端现在认得哪些"用 `MmtrFaceLogic.allOperators()` / `MmtrFaceText.allFilters()` / `MmtrFaceElements.types()`；
3. 装了扩展的客户端才认得那些 `type` ⇒ 离线自检会给扩展作者刷 P4/P3/P7 三条**假警告**，
   用 `--allow-type` / `--extra-fields` / `--allow-filter` 显式放行（报告里逐条写明放宽了什么）。

**作者侧的入口**：工作室顶部「导出 Java 骨架」按当前这块面生成一份能直接编译的 `MmtrFaceExtension`
（四类各留一个带 TODO 的桩 + ServiceLoader 声明的内容与放置目录）；装法就是标准 `ServiceLoader`
（`META-INF/services/org.mtr.mod.mmtr.face.MmtrFaceExtension` 一行全限定名）。

## 10. 明确不做

1. 资源包里的可执行代码（见 §2）；
2. 为一块牌新增第三方依赖；
3. 运行期编译 Java；
4. 破坏现有资源包：没有 `faces` 段时行为与今天**逐字相同**（有水牌等价性用例钉着）。

## 11. 已知欠账（诚实清单）

1. 锚点 JSON 被读**四次**（anchors / hud / pid / faces），各读各的缓存 —— 该合成一次；
2. `MmtrPidLayout` 现在只剩"等价性用例的对照物"这一个身份，等 F1 的 golden 图入库后删；
3. 折叠面（facets，曲面仪表盘）不支持面文档（运行时跳过并记一次日志）；
4. ~~`elements` 里的几何只接受数字~~（F3 已补：`anim`/`rotate`/`opacity` 是逐帧量，几何仍要求数字 ——
   想按数据算坐标得等"表达式几何"，**F4 没做这一条**：F4 做的是四类扩展 SPI，不是几何可表达式化）；
5. F0 的"字段表"只登记了 52 行（够水牌 / PIS / 仪表盘用），门的开合状态在 `VehicleExtraData` 里，
   还没进字段表 —— 按四步曲补（注意：**F4 的扩展字段不走这条**，它是客户端从快照算的，
   不等于"引擎里多了一个权威量"）；
6. 离线自检看不到"装没装那个模组"：扩展用的类型/字段/过滤器会被报成 P4/P3/P7 假警告，
   现在靠三个显式开关放行（§8 边界 3）。要根治得让扩展自己声明一份机读清单（例如随模组附一个
   `mmtr-face-extension.json`），目前**没做**。
