# 车辆动态面 · 面文档格式（v2）

这一份是**面文档（face document）的权威格式表**：作者写它，引擎读它，工作室画它。
三类读者要的东西不一样，所以本文按"键"组织，每条键都给**类型 / 缺省 / 单位 / 一句话含义**，
几何一律**比例**（见 §3），逻辑一律 **JSONLogic 子集**（见 §6）。

| 谁 | 从哪读到同一份事实 |
|---|---|
| 人（作者） | 本文 + [`MMTR-车辆动态面-作者指南.md`](../02-运行与作业/MMTR-车辆动态面-作者指南.md)（上手流程、症状表） |
| 引擎（权威实现） | `mmtr/game/fabric/src/main/java/org/mtr/mod/mmtr/face/MmtrFaceDocument.java`、`MmtrFaceAnim.java`、`MmtrFaceLogic.java`、`MmtrFaceText.java` |
| 工作室（绘制器 / 校验） | `mmtr/tools/face-studio/`（`schema.json` 由 Java 导出，页面按它生成属性面板） |
| 打包校验 | `mmtr/tools/anchor-check/verify_face.js`（P1–P9） |

> **漂移怎么防**：`MmtrFaceSchema`（Java）导出 `mmtr/tools/face-studio/schema.json`；
> 用例 `MmtrFaceSchemaTests` 三方对照（Java 键表 ↔ schema.json ↔ JS `schema.mjs`/`painter.mjs`），
> 少一条键就红。运行时还有一层：**画的时候遇到不认识的键会提示一次**（拼错键不再静默）。

## 1. 文档住在哪

面文档写在**锚点 JSON** 的 `faces` 段里，键 = **锚点名**：

```json
{
  "anchors": [
    { "name": "mmtr_pid_1", "widthM": 1.24, "heightM": 0.22, "position": [0, 0, 0], "normal": [0, 0, 1] }
  ],
  "faces": {
    "mmtr_pid_1": { "textColor": "#FFF2F4F6", "elements": [ … ] }
  }
}
```

**一条契约**：`faces` 里出现了哪个锚点名，**那个锚点就归面系统画**（老渲染器会让位）。
于是"把一块牌换成面文档"是**纯资源包动作** —— 客户端一行不用改，换车型也只是换一份锚点 JSON。

## 2. 文档键表

| 键 | 类型 | 缺省 | 含义 |
|---|---|---|---|
| `background` | 颜色 | `0`（透明） | 整面底色。**`0` = 不铺底**（让模型材质透出来）；要铺底就写 `#AARRGGBB` |
| `textColor` | 颜色 | `#FFF2F4F6` | 文本/gauge 的缺省颜色（元素自己写了 `color` 就用元素的） |
| `pxPerMetre` | 整数 | `0` → 512 | 想要的像素密度。牌小的时候调大能让字更清楚 |
| `side` | `driver`/`normal`/`both` | `normal` | 画在锚点**法线那一侧**（水牌就是这条）／司机那一侧／两侧 |
| `require` | 逻辑 | 无 | 整块面的门：不成立就一块都不画（"不在作业单上不挂牌"） |
| `vars` | 对象 | `{}` | 给条件起名字，值是一条逻辑表达式（见 §6.4） |
| `fps` | 整数 1..30 | `8` | **动画重画节拍**（见 §10）。没有动画的文档用不到它 |
| `elements` | 数组 | — | 元素表。**没写 `pages` 时它就是第 0 页**（v1 文档的唯一形态） |
| `pages` | 数组 | — | 多页（见 §4）。写了 `pages` 就忽略 `elements`（工作室会提示） |
| `pageSeconds` | 数 ≥ 0 | `6` | 自动轮转周期（秒）；`0` = 不自动转 |
| `pageExpr` | 逻辑 | 无 | 指定当前页：数 = 下标（**回绕**），字 = 页名；写了它就压过 `pageSeconds` |
| `roll` | 度 | `0` | 整面绕**自身法线**滚转（面内转角度） |
| `tilt` | 度 | `0` | 整面绕**自身水平轴**抬起（安装仰角） |
| `drum` | 对象 | 无 | 翻牌机（见 §9）：把各页贴到一个 N 面棱柱上转过去 |

## 3. 坐标是比例（这一条决定了"不同尺寸怎么办"）

`x`/`w`/`size`/`radius`(表盘) 乘**牌宽**，`y`/`h`/`size`/`radius` 乘**牌高**。
`y = 0` 是**牌底**，`y = 1` 是牌顶（MTR 的锚点坐标系 y 朝上）。同一份文档贴到 1.24 m 和 2.4 m 的牌上都等比。

**各类元素的"锚点"不一样**（画的时候容易错，工作室的拖拽按这条实现）：

| 元素 | `x`,`y` 是哪个点 |
|---|---|
| `text` | 文本的锚点（`align` 决定左右，竖直永远居中） |
| `rect` / `roundrect` / `image` | **左下角**（`w`,`h` 向右上长） |
| `line` | 起点（终点是 `x2`,`y2`） |
| `circle` / `arc` / `gauge` | 圆心 |

### 3.1 颜色怎么写（一条容易踩的）

颜色一律是 `#RRGGBB` / `#AARRGGBB` / `0xRRGGBB`。**`0` 是哨兵值**，不是"不透明黑"：
它表示"按这个键的本意取缺省" —— 底色 ⇒ 不铺底、`text`/`gauge` 的 `color` ⇒ 用 `textColor`、形状的 `color` ⇒ 全透明。

要**不透明黑**请写 `#FF000000` 或 `000000`（六位全零仍然是黑）。
这条是 F3 收尾时工作室的绘制器抓出来的：它一度只能靠"把键删掉"才能拿到文档里写的那个缺省语义
（`parseColor("0")` 曾经按十六进制算成 `0xFF000000`）。判据在 `MmtrFaceDocumentV2Tests#zeroIsASentinelNotOpaqueBlack`。

## 4. 页（`pages`）

```json
"pages": [
  { "name": "去程", "require": { "==": [ { "var": "handle.reverser" }, 1 ] }, "elements": [ … ] },
  { "name": "回程", "elements": [ … ] }
]
```

* 页键：`name`（可选，给 `pageExpr` 用字名）、`require`（可选门）、`elements`（必填）。
* **选哪一页**，按优先级：`pageExpr` 有值 → 用它；否则 `pageSeconds > 0` → 自动轮转
  `floor(秒数 / pageSeconds) % 页数`；否则第 0 页。
* 页的 `require` 不成立 ⇒ **这一页不画**（不自动跳到下一页 —— 跳到哪一页是作者的语义，引擎不替他决定）。
* `pageExpr` 求值失败 / 下标越界 / 页名找不到 ⇒ 第 0 页（不报错，记一次）。

## 5. 元素

**公共键**（哪种类型都认）：

| 键 | 类型 | 缺省 | 含义 |
|---|---|---|---|
| `type` | 字 | — | 元素类型（下表） |
| `when` | 逻辑 | 无 = 总是画 | 这个元素的显示条件 |
| `x`,`y` | 0..1 | `0.5`,`0.5` | 见 §3 |
| `w`,`h` | 0..1 | `0` | 图形元素的宽高（文本用不到，除了 `marquee` 当视口） |
| `size` | 0.02..1.5 | `0.4` | 字高（牌高比例） |
| `color` | 颜色 | `0` | **`0` = 用文档 `textColor`**（只对 `text`/`gauge`；形状写 `0` = 全透明） |
| `align` | `left`/`center`/`right` | `center` | 文本水平对齐 |
| `text` | 模板 | `""` | 见 §7 |
| `rotate` | 度 | `0` | 绕**这个元素自己的锚点**在面内转（顺时针为正） |
| `opacity` | 0..1 | `1` | 整元素透明度（乘到颜色 alpha 上） |
| `anim` | 对象 | 无 | 逐帧动画（见 §8） |

**类型表**（`type` 之外的键）：

| type | 专属键（缺省） |
|---|---|
| `text` | `shrinkToFit`（0.9；超宽等比缩小，写 0 = 不缩） |
| `rect` | — |
| `roundrect` | `radius`（0.08，牌高比例；钳到短边一半） |
| `line` | `x2`,`y2`（= `x`,`y`）、`width`（0.03） |
| `circle` | `radius`（0.1） |
| `arc` | `radius`（0.4）、`start`（0）、`end`（360）、`width`（0.01） |
| `gauge` | `radius`（0.44）、`start`（225）、`end`（-45）、`width`（0；**别名**：没写 `lineWidth` 时它就是线宽）、`lineWidth`（0.004）、`max`（160）、`ticks`（0）、`tickLength`（0.12）、`labelEvery`（0）、`labelSize`（0.13）、`labelColor`（0 = 用表盘色）、`needle`（逻辑，缺省 `{"var":"speedKmh"}`）、`needleColor`（`#FFFF3B30`）、`needleWidth`（0.05）、`needleLength`（0.94） |
| `image` | `src`（必填，形如 `命名空间:路径`，例如 `mmtr:vehicle/face/logo.png`；**漏了命名空间会当成 `minecraft:`**，那就找不到）、`fit`（`stretch`/`contain`/`cover`）、`alpha`（1）、`tint`（`#FFFFFF`） |
| `foreach` | `var` 或 `of`、`as`（`item`）、`index`（`index`）、`limit`（32）、`elements`（必填）。**规范拼写是小写 `foreach`**（键表、校验脚本、工作室都用这个；引擎对大小写不敏感，写 `forEach` 也认） |

角度都是**度**，逆时针为正（`gauge` 的 `start`/`end` 沿用 MTR 仪表盘那套：从 +X 起算）。

## 6. 逻辑（JSONLogic 子集）

### 6.1 方言

与 `json-logic-js` 一致的**子集**，**以下 32 个**（清单以 `MmtrFaceLogic.operators()` 为准）：

| 类 | 算子 |
|---|---|
| 取值 | `var` `missing` `missing_some` |
| 分支 | `if` `?:` |
| 比较 | `==` `===` `!=` `!==` `<` `<=` `>` `>=` |
| 逻辑 | `!` `!!` `and` `or` |
| 算术 | `+` `-` `*` `/` `%` `min` `max` |
| 文本 | `cat` `substr` `in` |
| 集合 | `some` `all` `none` `filter` `map` |

★ **没有** `merge` / `reduce` / `log`（这三个在完整的 JSONLogic 里有，本子集刻意没实现）。
想要新算子/新过滤器有两条路（§12.1 第 2 级）：**自己加一个**（附属模组
`registrar.function("厂家:名字", …)` / `registrar.filter("厂家:名字", …)`，随模组发行、不改引擎），
或者**提成内置**（那是方言改动，要**同时**改 Java、工作室与共享向量 `conformance/logic.json`——
不是在一份资源包里能解决的事）。多键对象 = `and`，**短路**求值。

### 6.2 四条必须记住的语义

1. **真值**：`null`/`false`/`0`/`""`/`[]` 为假；`"0"`、`"false"`、非空数组为真。
2. **比较**：带 `null` 的比较一律**假**（不抛）。
3. **算术**：类型不匹配（`"abc" * 2`）→ `null`；`/` `%` 除零 → `null`。**`null` 会画出"空"**，不会画成 0。
4. **"没有值"是"键不在"**：快照里取不到的字段**不放进去**（不是放 `null`），空串也算没有。
   所以"这个字段有值吗"要写 `{"!!":[{"var":"pid.service"}]}`，
   **不能**写 `{"!=":[{"var":"pid.service"},""]}`（后者在字段缺失时是**真**，F0 第一版就这么错过）。

### 6.3 预算

不可信内容：求值节点上限 512、深度上限 24，超了抛异常（元素被跳过并记一次）。

### 6.4 `vars` 与数组

```json
"vars": {
  "arriving": { "and": [ { ">": [ {"var":"lzb.targetM"}, 0 ] }, { "<": [ {"var":"lzb.targetM"}, 200 ] } ] },
  "calls": [ "海山", "鸥湾", "榕屿" ]
}
```

`vars` 的值是**一条表达式**。数组在 JSONLogic 里就是"逐项求值后得到列表"，
所以 `calls` 直接是一个列表 —— `foreach` 可以拿它当数据（这也是引擎将来暴露"停站表"之类列表字段的落点）。

## 7. 文本模板

`{路径}` 取字段，`{路径|过滤器}` 加工，`{{`/`}}` 是转义的字面花括号。过滤器（8 个，以 `MmtrFaceText.filters()` 为准）：

| 过滤器 | 效果 |
|---|---|
| `upper` / `lower` | 大小写 |
| `trim` | 去首尾空白 |
| `int` | 取整（`num:0` 同义） |
| `num:N` | N 位小数，N 钳到 0..4；**`num:0` = 取整**（`12.345 → 12`） |
| `pad:N` | 左侧补零到 N 位，N 钳到 0..16（`{pid.service\|pad:7}` → `0000101`） |
| `len` | 字符数 |
| `default:X` | 空值/取不到时用 `X` |

## 8. 动画（`anim`）

```json
{ "type": "text", "text": "列车进站", "x": 0.5, "y": 0.5, "anim": { "kind": "blink", "onMs": 600, "offMs": 600 } }
```

| `kind` | 键（缺省） | 效果 |
|---|---|---|
| `blink` | `onMs`（600）、`offMs`（600） | 亮 `onMs`、灭 `offMs` 交替 |
| `marquee` | `spanMs`（4000）、`direction`（`left`）、`gap`（0.3） | 文本横向走马灯：视口 = 元素的 `w`（0 = 从 `x` 到牌右缘），`gap` 是牌高比例的接缝。**只有明确写 `right` 才反过来**（拼错的方向按向左走） |
| `fade` | `spanMs`（1500）、`min`（0.25） | 透明度在 `min`..1 之间来回（三角波） |
| `spin` | `spanMs`（2000） | `rotate` 在 `spanMs` 里转一圈（叠在元素自己的 `rotate` 上） |

* 时间轴 = 客户端时钟（`MmtrFaceRuntime` 每帧给一次），**与游戏 tick 无关**，所以掉帧不会让动画变慢。
* 不认识的 `kind` ⇒ 当没有动画（记一次）。
* 动画是**逐帧**的显示属性，不参与"数据变了吗"的判断（见 §10）。

## 9. 整面姿态（`roll`/`tilt`/`drum`）

* `roll`/`tilt` 把整块四边形绕自己的法线/水平轴转，用来贴斜装的牌子。
* `drum` = **翻牌机水牌**（一个 N 面棱柱，每一面贴一页）：

```json
"pages": [ { "name": "上行", "elements": [ … ] }, { "name": "下行", "elements": [ … ] } ],
"drum": { "count": 2, "turnFraction": 0.25, "radiusM": 0 }
```

| 键 | 缺省 | 含义 |
|---|---|---|
| `count` | `2`（钳 2..8） | 棱柱面数；第 i 面贴第 i 页（页不够就回绕） |
| `turnFraction` | `0.25` | 一个换页周期里**用来翻**的比例：前 25% 转过去，其余停住 |
| `radiusM` | `0` → 正棱柱 `w / (2·tan(π/N))` | 棱柱外接半径（米）；写小一点 = 薄牌。**`count: 2` 时正棱柱算出来是 0**（两面共面 = 一块翻来翻去的平板），想要厚度就写 `radiusM`（例如 `0.02`） |

换页节奏仍由 `pageSeconds`/`pageExpr` 给。语义要说清：一个周期里**前 `1 - turnFraction` 停在第 k 页**（正面就是 `pageIndex` 那一面，与"不用翻牌机的多页"换页时刻一致），**最后 `turnFraction`** 翻到第 k+1 页（缓入缓出），落地那一刻正好是 `pageIndex` 前进的时刻；`pageExpr` 指定页时**不翻滚**（指定的那一面就是正面）。

## 10. 节拍与代价（为什么动画不会把 CPU 吃光）

| 层 | 什么时候动 |
|---|---|
| 数据快照 | 每帧一份，同一帧里这节车的所有面共用（不会一块写"海山"一块写"鸥湾"） |
| 贴图重画 | **只在签名变化时**。签名 = 文档 id + 数据摘要 + 牌面尺寸 + 像素密度 + 姿态 |
| 动画 | 文档里有动画时，签名里才带 `bucket = floor(t / (1000/fps))`；`fps` 默认 8、钳 1..30 |

于是：**没有动画的牌一个字都不多画**（回到 F0 的"数据不变就不重画"）；
有动画的牌按 8 fps 重画（不是 60 fps）—— 走马灯/闪烁这种效果 8 fps 已经够顺，代价是原来的 1/7。

## 11. 出错怎么办（资源包是不可信内容）

| 情况 | 行为 |
|---|---|
| 不认识的 `type` | 跳过这一个元素，记一次（列出认得的类型） |
| 不认识的键 | **照画**，但记一次（防拼错：`colour`/`siz` 这种） |
| `when`/`require` 求值抛异常、超预算 | 不画这一个元素（或整块面），记一次 |
| 模板路径取不到 | 当空串（`text` 空 ⇒ 这一行不画，不是画个空位） |
| 页下标越界 / 页名找不到 | 回落到第 0 页 |
| 一个元素画的时候抛异常 | 跳过它，其余照画（一块牌里坏一行不该让整列车水牌全黑） |

每条"记一次"的账在资源重载时清空（`MmtrFaceRuntime.clearCache()`）。

## 12. 版本与兼容

| 版本 | 形态 | 兼容性 |
|---|---|---|
| v1 | `elements` + `require` + `vars` + 每元素 `when` | v2 实现读它**逐字不变**（`MmtrFaceDocumentTests` 钉着） |

### 12.1 升级阶梯（缺东西时按这条走，别改引擎）

每一级都**不用改资源包格式**：作者侧永远只是 JSON 里多一个字段名、一个算子名或一个 `type`。

| 级 | 缺什么 | 现状 | 走哪条 | 作者交付 |
| --- | --- | --- | --- | --- |
| 1 | 能用现成元素/条件表达 | 已可用 | 写 JSON | 一份面文档 |
| 2 | 差一个**算子/过滤器** | **已可用**（F4） | 附属模组 `registrar.function("厂家:名字", …)` / `registrar.filter("厂家:名字", …)`；用内置的 32 / 8 个就写 JSON | 一个 Java 类 |
| 3 | 差一个**画法**（新的图形/图像处理） | **已可用**（F4） | 附属模组 `registrar.element("厂家:名字", renderer, 它认的键…)`，文档里写 `{"type": "厂家:名字"}` | 一个渲染器类 + 一句话注册 |
| 4 | 差一个**取值** | 分两条 | ① **客户端算**：附属模组 `registrar.field(new MmtrFaceField(){…})` —— 拿已收集好的快照算一个新量（**已可用**，F4）；② **引擎里多一个权威量**：加字段四步曲（`MmtrFaceFields` + 取值口 + 镜像 + 重生成 `fields.json`），**属引擎改动，不是 SPI 的活** | 一个字段类 / 一份字段申请 |
| 5 | 跨面协同（整列车同步翻页等） | 还没有 | 提需求（要面级 state，目前只有"文档级 `vars` + 数据字段"这两样） | 一份需求 |

**三条口径**（写错就会被判红）：

1. **扩展注册的名字必须带命名空间**：`厂家:名字`（如 `vendor:bar`）。不带冒号的一律被引擎**拒绝**并记一条账
   （`MmtrFaceExtension.isNamespaced`），理由见那个接口的类注释（不撞内置 / 能解释"我为什么没有它"）。
2. **扩展的键不在 `schema.json` 里**：`schema.json.elementTypes` 与各 `element:<type>` 段是**随包发行的最小集**。
   扩展在 `registrar.element(type, renderer, declaredKeys…)` 里报的键只影响**拼写守卫**（未知键提示），
   不进 `schema.json`。同理：`MmtrFaceLogic.operators()`（32 个）与 `MmtrFaceText.filters()`（8 个）
   也只列内置；要问"这个客户端现在认得哪些"用 `MmtrFaceLogic.allOperators()` /
   `MmtrFaceText.allFilters()` / `MmtrFaceElements.types()`。
3. **装了扩展的客户端才认得那些 `type`**：没装的客户端里，那块面照旧解析，只是那个元素被跳过并记一条账。
   离线自检（`verify_face.js`）因此会把它们报成 P4/P3/P7 三条**假警告** —— 用
   `--allow-type` / `--extra-fields` / `--allow-filter` 显式放行（见作者指南 §10.1）。
