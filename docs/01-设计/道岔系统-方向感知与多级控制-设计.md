## 1. 目标与范围

把一个岔口（junction/turnout）建成完整的受控对象：

1. **正确的抽象**：岔口的识别与决策必须**方向感知**——候选续轨只包含该进向下列车实际能走的轨
   （含单向连接、直角/丁字汇入、交叉通过、多分支等拓扑），不能再"把所有邻轨按 cos 取前二"。
2. **自动控制接口**：岔口能接入自动逻辑（任务/AI/进路/联锁），自动设置、按车申请、过岔释放。
3. **人工控制接口（保留）**：operator 随时可人工搬岔并覆盖自动（人工优先级最高），现有
   `mmtr-point-op`/`mmtr-points` 语义不回退。

范围红线：不做"轨道铺设/信号机实体外观"；道岔=轨道图上的受控连接点（(节点, 进向轨) 视角）。

## 2. 现状盘点（代码事实，2026-09）

| 件 | 位置 | 说明 |
|---|---|---|

| 进路预置 | `MmtrRunPlanner.applyForkOps` | 任务/MOVE_TO 规划时把沿途岔口预置写 store（一次性） |
| 任务运行 | MmtrMissionControl / Vehicle mission 自武装（notes/20/23） | 目标轨停靠闭环 |

已知局限（本文件要解决）：
- 发现/决策把**节点上除来轨外的所有轨**都当候选：交叉(X)路口会产出假的"分叉"；"来轨背后回头轨"
  可能被计入；等角/直角场景 branch0/1 的几何意义可能不符直觉。
- 单向连接（若有方向约束的区段/股道/咽喉）未被显式建模。
- 只有"人工 operator 0/1 + 规划预置"，没有"自动逻辑申请-授权-释放"接口；多车同时接近同一岔口
  没有裁决/排队语义。

## 3. 需求细化（用户确认的三点）

### R1 方向感知的岔口抽象（拓扑正确性）
- 进向相关：岔口决策输入 = (节点, 进向轨, 车头朝向)，输出 = 该进向下**可达续轨的有序集合**。
- 候选过滤（按序）：
  a. 方向可达：单向连接/禁入侧剔除（MTR 图暂无显式方向位时，先由"轨端连接约定+股道作业方向"
     推导；若未来引入方向属性则直接读）；
  b. 回头排除：排除与来轨同一几何、仅反向可达的续轨（防"走回去"候选）；
  c. 几何连续：按 cos 扇区聚类为 直行(±θ₁)/左/右 档；
- 岔口形态分类（合成网测试矩阵用）：
  1. **通过节点**：单续向 → 不设权直接过（现状保持）；
  2. **标准分叉**：2 续向（直+岔 / 左+右 T 型 / 任意 2 支）→ branch0/branch1；
  3. **丁字 T**：进向与主线垂直，左/右两支均为合法续向 → branch0/1 = 左/右（依方向扇区）；
  4. **交叉 X**：直通主向 + 垂直另一直通 → 只把"主向直通"作为可选续向时非岔；若两条直通都是合法
     续向（菱形交叉/道岔交叉）→ 2 支分叉；
  5. **3 路及以上**（三开/多支）：控制层仍用 branch 0/1 不方便 → 引入 `leg`（有序候选列表）语义：
     操作/自动接口可指定 legIndex；兼容层把 b0/b1 = leg0/leg1 映射（现有 walker 逐节点二选一裁决
     先保持 2-leg 上限，3+ leg 由自动/人工预置选定后走单一续向进入，避免改变 walker 热路径）。
- 附带：端点/缓冲区/断轨 = 无续向（endOfLine）；回库股道入口语义属 M2 路由。

### R2 自动控制接口
- 岔口是"受控资源"，提供：
  - `request(node, via, owner, desiredLeg, untilMillis)`：自动逻辑（任务/进路/AI）申请；
  - `grant`/`deny`（冲突则入队/拒绝带原因）；
  - `release`（列车越过该岔口后自动释放；或超时释放）；
  - `autoPolicy`：默认策略（任务目标命中优先 —— 现状 elect 的 task 语义升级为显式申请）。
- 自动逻辑接入点（后续片）：
  - Motion 任务（MmtrMission AUTOPILOT）进路：MmtrRunPlanner 的预置改为"经 authority 逐岔申请"
    （申请成功才放行，失败重试/等待），替代一次性 applyForkOps；
  - 信号联锁（后续）：按进路一次性锁定一组岔口（route locking），与信号机状态联动；
  - 多车并发：同一 (node,via) 上多个申请按 owner 优先级+到达序裁决；车未到岔口前的预申请窗口
    防止临近岔口被抢占（"接近锁定"）。
- 裁决顺序（统一）：**人工 operator > 显式任务/进路申请 > 默认策略（直通优先）> 绝不 auto**。
  （与现状 elect 兼容：operator 0/1 仍最高；无 operator 时任务申请生效；都没有 → null 等待。）

### R3 人工接口保留
- `mmtr-point-op` 0/1（及未来 legIndex）保持为"人工搬岔"，可随时覆盖自动设置并**锁定**
  （锁定期间自动申请被拒/排队；可加 `mmtr-point-unlock` 释放回自动）；
- `mmtr-points` 查询扩展输出：形态类型、各 leg 轨 hex、当前状态来源（manual/task/auto/none）、
  申请队列（owner/desiredLeg）、过岔计数；
- Web 地图（8888）增加点选搬岔 UI（第一片交付物）：点击岔口 → 显示分支 → 点 0/1/leg 即搬；
  与游戏内驾驶并存（实机验收路径不变）。

## 9. 交付补记（2026-09-14，notes/130）：判据必须由几何决定，不能由遍历顺序决定

现场实测暴露了 P1 形态分类的一个硬缺陷：**浅岔口（两条平行正线之间的渡线/汇入，岔股只偏 9.5°~21.8°）
认不出来**。原因是"直股对"的选法 —— 老实现取"遍历腿表时**最后**遇到的一对互为直股的轨"，
而 `COS_STRAIGHT = 0.9`（≈25.8°）让浅岔股自己也够"直"，于是三根轨里有三对够格，
谁最后被遍历到谁赢（外层是哈希表，顺序与几何无关）。后果两种，都严重：

1. **模型倒置**：把岔股当正线、正线一端当岔股（实测 `-147,-60,-169`）；
2. **返回 null**：胜出的那一对恰好"看不见第三根" ⇒ 找不到根部 ⇒ 整个节点没有物理模型
   —— 网页退化成 legacy 卡片，**T1 的物理互斥在这一处完全不生效**（实测 `-155,-60,-189`，
   与上一个几何完全镜像却一认一不认）。

已修正（notes/130）：

- **直股对 = 互直度（两个方向 cos 的较小者）最大的那一对**，要求 ≥ `COS_STRAIGHT`；
  并列按轨 hex 定序 ⇒ 结果只由几何决定。实测世界 22 个度3节点：**8 → 预期 21** 个有模型
  （剩下的那个三向互成 66°/150°/143°，没有任何一对互为直股 = 真三岔口，本来就不该建模）。
- **根部判定看两个正线进向**：浅岔口上另一个进向会因为岔股几乎在正后方（cos ≈ −0.99）而看不见它。
- **直角三岔口仍然拒绝**（现实里是两组道岔背靠背）。
- **判据 = 岔尖测试**（第二轮，用户指出对称人字岔）：「存在一对近乎共线的直股」只是**单开道岔的样子**，
  对称人字岔（正人字形）两根进路一样斜，会被它整处误判成"不是道岔"。物理事实只有一条：
  **一个可动件 + 两根互斥进路 + 一个岔尖** —— 所以判据是"存在一根轨，从它开进去另外两根都在前方"
  （cos > 0.1）。再保留 45° 门槛（岔尖那两根里更直的一根 cos ≥ 0.707）：三条线在一个点上交汇
  （三开道岔 / 三角线）现实里要两组可动件，本模型一个节点只有一个，不建模。
  实测世界 22 个度3节点**全部**有模型（改前 8 个）；只剩两个度4 节点（一个节点需要两个可动件）。
- **诊断入口 `point why <x> <y> <z>`**：把判定过程本身写成人读的（与 `resolve` 同一段代码），
  轨用远端坐标而不是 hex（负坐标的 hex 全是 `FFFFFFFFFFFFFF…`，等于没写）。

随之落地的两条现场规则（用户 2026-09-14 当场定，详见 notes/130 §5）：

- **R3 的"人工搬岔可覆盖自动并锁定"现在是真的事实**：`point set`/网页搬岔 = 设位置 +
  锁定三个进向；锁随 `mmtr-points.json` 的 `locks` 段落盘（重启不静默解锁），
  `point unlock` 释放。清掉人工位（`branch < 0`）不锁。
- **人工扳岔多了一道安全闸**：岔区净空被占（车压在岔上）时**拒绝扳岔**并给出可读原因 ——
  判定与灯显示"岔区净空被占"读同一段代码（`MmtrJunctionState.blockedThrowReason`），
  否则会出现"灯说岔区被占、道岔却照样能扳"的自相矛盾。同一条闸也加在意图扳岔那条路上。
- **裁决顺序里"显式任务/进路申请"真的会扳岔**：人工位 / 授权 / 任务目标这条意图与道岔位置不一致时，
  联锁把道岔扳过去（`MmtrForkElection` → `Simulator.mmtrThrowTurnoutForIntent`），
  三道闸门：人工锁着不扳、有人物理持有不扳（T1：不许把道岔从列车脚下抽走）、车压在岔上不扳。
