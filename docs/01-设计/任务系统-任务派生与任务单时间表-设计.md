# 任务系统：任务派生体系 + 任务单时间表（设计）

> 状态：设计定稿前评审版（2026-09-08）
> 用户拍板：
> 1. 连挂需要派生 Vehicle 类（动力车 / 非动力车），**该派生本轮之后再做**，但任务接口预留；
> 2. 有专门地方**生成派生非动力车**（停放待挂），玩家开动力车去执行连挂——作为目标场景先立；
> 3. 作业单（ConsistJob）步骤**直接实例化任务**；作业单上的时间要求就是任务的时刻；要把**任务单抽象成时间表**同时给玩家与 OP 看。

## 1. 任务 = 某时 × 某地 × 某操作

任务不是"单车跑一段"，而是可陈述的作业语句：

> "**车次 X** 于 **07:03** 从 **3 站台上行** 发车，**07:05** 到 **5 站台上行**，开门停站 30s"
> "**调机 1** 于 **08:40** 到 **车场 3 道**，连挂 **非动力车 U-02**，**09:00** 前拉到 4 道"

形式化：

```
MmtrTask
 ├─ when   : 计划时刻窗口（start / due / latest）/ 相对时刻
 ├─ where  : 目标对象 id（平台 / 股道 / 非动力车 / 折返轨）+ 到位语义
 └─ what   : 派生类型定义的操作（驱动 + 动作 + 完成条件）
```

### 抽象基类职责（三问）

- **驱动（drive）**：任务如何让执行车移动（目标 rail、停车点、速度限制语义）；
- **动作（act）**：到位后做什么（门循环 / 连挂对接 / 停留作业）；
- **完成（done）**：何时算完成（停稳 / 门关 / 钩挂好 / 停留时间到）→ 供时刻表记录"实际完成"。

通用属性：`taskId`、执行车（consist/vehicle）、`earliest / due / latest`、可重复、可取消；
失败必须带原因（时刻表/OP 直接可见）。

## 2. 派生类型（首批，按运营域）

### 走行类（只开车，动作为空）
| 类型 | 目标 | 完成 | 说明 |
|---|---|---|---|
| `DriveToSiding` | 股道 | 停稳 | 调车转线 / 回库 / 出库，目标即现有 siding 目标语义 |
| `DriveToPlatform` | 平台 | 到站停稳（不开门） | 与 StationService 分离：可表达"通过不停 / 只停不开门" |
| `DriveToConsist` | 目标车列（**预留：派生非动力车对象 id**） | 到达连挂区停车点（低速对位完成） | 连挂走行任务；"挂上"本身属 Couple（Vehicle 派生后） |
| `DriveTurnback` | 折返轨/另一向股道 | 停稳 | 掉头=走行任务（经进向表），引擎无倒退 |

### 动作/作业类（到达后做）
| 类型 | 前置 | 完成 | 说明 |
|---|---|---|---|
| `StationService` | 停在平台 | 门开→停站→门关 | 开门时刻 = 到站时刻；完成 = 门关（=发车时刻） |
| `Couple`（接口预留） | 停在目标车列连挂区 | 钩已挂（后续由派生 Vehicle 体系实现） | 本轮只定义契约与状态位 |
| `Uncouple`（沿用） | 停稳 | 摘解完成 | 与现有车库 UNCOUPLE 语义统一（单 Vehicle=编组的列表切分） |
| `FreightWork`（占位） | 货位/停留点 | 装卸停留完成 | 待货运场地形态确认后细化 |

### 不做成独立任务的（属性/编排）
- 折返"换端"若未来支持倒退 → 加动作；当前折返 = `DriveTurnback` 走行。
- 联挂后的牵引 = 走行类任务挂到"合并后编组"上，不需要新类型。

## 3. 与作业单的关系：步骤 → 任务实例

- `MmtrConsistJob.steps[]`（MOVE_TO / SERVE / COUPLE / UNCOUPLE + due）在调度执行时**直接实例化为对应任务**：
  `MOVE_TO 平台` → `DriveToPlatform`；`SERVE` → `StationService`；`COUPLE/UNCOUPLE` → 对应类型（实现随 Vehicle 派生）。
- 现有 `MmtrMission` 保留为**运行时任务实例容器**（state/executor/failure/车辆归属），重构为携带 `task` 引用；`kind`（PASSENGER/MANEUVER）由任务类型的用途推导，保留兼容。
- 玩家执行：任务 executor 可为 PLAYER——玩家开车执行任务（如"开去连挂"），任务/时刻表只观测行为（位置、门、停车点、连挂状态），不强制 AUTOPILOT；AI/自动驾驶 = 现有 motion 自臂路径。

## 4. 任务单 → 时间表（Schedule 视图）

目标：把"车底作业单"渲染成 **玩家与 OP 都看得懂的时间表**。

### 引擎侧数据（TaskSchedule 摘要）
每个作业单 → 行集合，每行 = 一个任务条目：

```
jobId | 车(车次) | 序 | 任务类型 | 地点(平台/股道/连挂对象) | 计划到 | 计划发(due) | 实际到 | 实际发 | 状态 | 失败原因
```

- 时间基准 = 引擎作业钟（同 scheduler 的 dayTime），同时给"距下一任务倒计时"；
- 状态 = 任务执行状态（PENDING/RUNNING/DONE/FAILED）→ 直接来自任务实例。

### 出口与展示
1. **OP（WEB 8888）**：`mmtr-schedule` feed（jobId 维度，含每个任务条目的上述字段）→ 控制台"时间表"面板：每车一行、任务列、计划/实际时刻、状态着色；复用现有 mmtr-ops-panel 区域扩展；
2. **玩家（游戏内）**：驾驶台/时刻面板显示本车任务序列（下一任务 + 倒计时 + 目标地点）；依赖 HUD 渲染层，HUD-2 后接入；
3. 时刻表数据与信号/岔权显示一致：任务=该车当前"进路意图"，供 Step-2 英铁式联锁引用。

## 5. 边界与顺序（Roadmap）

- **本片（建议）**：MmtrTask 抽象 + 首批类型（走行类 + StationService + Couple 契约占位）+ 序列化 + 单元测试；scheduler 步骤→任务实例映射；`mmtr-schedule` feed + OP 时间表面板 v1。
- **后片 A**：Vehicle 派生（动力车/非动力车）→ 激活 `DriveToConsist`/`Couple` 与"专门地点生成非动力车"；
- **后片 B**：任务驱动的英铁式进路/岔权/信号联锁（任务=进路意图的来源）。
- **后片 C**：玩家时间表面板（HUD-2 内）；FreightWork 场地细化。
