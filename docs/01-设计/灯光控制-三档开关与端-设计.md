# 灯光控制 · 三档开关、端与按键（notes/352 的设计面）

> 用户口径 2026-09-29（原文要点）：
>
> - 灯光控制分 **日间 / 夜间 / 尾灯** 三档；**每个驾驶室各一个开关**，"在哪个驾驶室驾驶，设置的就是
>   当前驾驶室前的灯光"；
> - **默认 = 尾灯红色暗光，无需灯光射线**；进入驾驶室设为日间 = 较低亮度、夜间 = 较高亮度；
> - **换向器为 N 时固定红色**，其余遵循灯光设置；
> - **机车**多一档"关闭"（留好"连挂时尾灯灭掉"的接口，那套逻辑以后再谈）；
> - 驾驶室里的按键要与游戏内操作**解耦**，键位：A/D 油门、`;` `'` 刹车、R/F 定速、Q 响应、J 雨刷、L 灯光。

---

## 1. 概念模型

### 1.1 端（A / B）是几何事实，不是编号

车体局部的 **+Z 由 bogie1→bogie2 定义**，而 MTR 把 bogie1 放在编组脊柱的 A 端 ⇒ **+Z = 引擎的 B 端**。
这条换算只有一处：`MmtrVehicleAnchors.engineEndOfSeat(z)`（`z > 0 ⇒ 2 (B)`）。
灯锚点 `mmtr_light_<cab>_<n>` 的 `position` 就在同一个车体局部空间里，所以"这一盏灯属于哪一端"
是**查符号**，与"锚点里写的 cab 编号是几"无关（那是模型自己的约定，2026-09-21 实机踩过）。

### 1.2 每端一份开关（不是全列一份）

| 状态 | 值 | 灯（那一端） |
| --- | --- | --- |
| 关闭 OFF | 0 | 不亮（**只有机车能选到**） |
| 尾灯 TAIL | 1 | 红、暗、短射程（标志灯） |
| 日间 DAY | 2 | 白、**低**亮度 |
| 夜间 NIGHT | 3 | 白、**高**亮度 |

- 出厂默认 = `TAIL`：**无人照看的车两端都是红标志灯**（用户口径"默认为尾灯红色暗光"）。
- 引擎侧镜像两个整数：`mmtrLightA` / `mmtrLightB`（+ `mmtrLightLoco` = 本车底有没有关闭档）。
- 客户端**只报自己这一端的档位**；"我这一端是哪一端"由**引擎的占用状态**决定
  （`mmtrActiveCab`）⇒ 协议上不存在"改别人那一端的灯"。

### 1.3 判据顺序（`MmtrLightSwitch.lampState`，自上而下第一条命中）

1. 本端开关在**关闭** ⇒ 灭。**它压过换向器 N** —— 否则"机车挂车时尾灯灭掉"这条永远做不到
   （挂车时换向器多半就是 N）。动车组没有关闭档，这条对它不可达；
2. 换向器 **N** ⇒ 固定红尾灯（无视档位）；
3. 否则按本端档位（尾灯 / 日间 / 夜间）。

> 为什么这三条必须写成**纯函数**：它是唯一真源 —— 引擎写镜像、客户端画灯、HUD 显示"本端/对端"、
> 未来的连挂逻辑，全都调它。真值表直接测（`MmtrLightSwitchTests`，9 个用例含反例）。

### 1.4 循环顺序

- 动车组：尾灯 → 日间 → 夜间 → 尾灯（三档闭环）；
- 机车：关闭 → 尾灯 → 日间 → 夜间 → 关闭（四档闭环）。

档数来自**车底配置** `consist-types.json` 的 `lightSwitch: "LOCO" | "MU"`（缺省 `MU`）。
客户端没有这份配置，所以引擎把答案镜像成 `mmtrLightLoco` —— 否则 HUD 的档位循环会与引擎的判据打架。
写错的值**点名**（`[MMTR-CFG]`），不静默按 MU 走。

## 2. 数据流（谁权威）

```
L 键（MmtrDriveInput，坐在司机位上）
   └─ PacketDriveControl.lightSwitch ─→ MmtrDriveControl.lightSwitch
         └─ ControlState.lightSwitch ─→ Vehicle.applyMmtrLightSwitch
               · 端 = getMmtrActiveCab()（A/B）        ← 客户端说了不算
               · 档位 = MmtrLightSwitch.sanitize(收到值, 车底有没有关闭档)
               · 写 mmtrLightA 或 mmtrLightB（另一端不动）+ 标脏
                     └─ 稀疏补丁（VehicleSyncPatch 白名单里有那三个字段）
                           └─ 所有客户端的 VehicleExtension 镜像
                                 └─ MmtrHeadlights.requestCar：端(几何) + 档位 + 换向器 ⇒ 每盏灯亮什么
```

三条不变量：

| 不变量 | 为什么 |
| --- | --- |
| 旧客户端（不带 `lightSwitch`）**零回归** | 读取缺省 `-1` = "这一包没带" ⇒ `apply` 不动开关；旧客户端看到的仍是"两端尾灯" |
| 无人照看的车不亮白灯 | 占用锁释放时（`releaseMmtrManualOverride`）把两端**日/夜**落回尾灯；`尾灯`/`关闭`原样保留（换端走路那一段也正好把对面那端的白灯清掉） |
| 车灯是**所有人的画面** | 开关状态走引擎权威 + 镜像；不是"谁开车谁自己看"的本地效果 |

## 3. 渲染（`MmtrHeadlights`）

- 判据从"**按逐帧位置增量猜行进方向**（停着不动只能含糊）"换成"**端 + 档位 + 换向器**"：
  车停着、无人、等信号，灯的答案都不再依赖"车有没有在动"。
  随之作废的配置项：`headlightAmbiguous`（写了会点名一次）。
- **日 / 夜亮度**：绝对量仍是 `headlightLux`（= 夜间那档），日间 = `headlightLux × headlightDayRatio`
  （默认 0.45）。一个调"有多亮"、一个调"日/夜差多少"。
- **尾灯不照世界**（用户口径"无需灯光射线"）：地形那一侧（Sodium 的地形 program / 光影包注入的
  地形与实体程序）上传灯表时**跳过尾灯候选**（靠 `mmtrTerrainLuxScale` 这一族 uniform 认程序），
  尾灯只在车厢/实体那一侧留一圈很近的红晕。
- 强度仍按**灯罩面积**缩放（不必在命名里暗号化"主/副灯"）。

## 4. 与连挂的接口（本轮只留口，不实现）

用户口径："机车灯光多一档默认的关闭，以连挂时尾灯灭掉。但这个逻辑我们到时候再说。留好接口。"

接口就是 **`Vehicle.setMmtrLightSwitch(end, MmtrLightSwitch.OFF)`**：
将来连挂逻辑只要把**被挂那一端**的开关写成 `OFF`，那一端的尾灯就真的灭了 —— 不必再动判据、
不必再动渲染、也不必再动协议（引擎内部调用，连打包都省了）。
"关闭压过 N"这一条就是为它准备的（见 §1.3 判据顺序的说明）。
