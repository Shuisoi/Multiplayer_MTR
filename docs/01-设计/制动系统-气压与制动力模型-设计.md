## 0. TL;DR

1. **压力语义换成真 bar**：列车管 `5.2`（运行）→ `4.6`（1A 初制动）→ 逐级 → `3.5`（8 档全常用）→ `3.0`（EB 快排）；
   制动缸由分配阀导出 `P_bc = clamp(2.533 × (5.2 − 管压 − 0.2 灵敏限), 0, 3.8 bar)`。
2. **力的标定源是 UIC 制动重率**（Q3）：`a = 0.0065λ + 0.12`、`B = m_equiv·a` ⇒ BR101 全常用
   **102.2 kN**（λ=142.9%）、紧急 **138.4 kN**（λ=200%），比今天的铭牌值 150/210 kN **软 32%/34%**。
3. **闸片摩擦随速衰减**（0.39 → 0.30 @200 km/h）叠在 UIC 之上 ⇒ 8 档在 0/100/200 km/h = **102/90/79 kN**
   （1.05 / 0.93 / 0.81 m/s²）。
4. **电空混合**：诉求由**管压**表达，电制动先吃饱、机械补缺口，**EP 阀只削不加**（机械绝不超过管压那份）。
5. **黏着截断**用 Curtius-Kniffler `μ(v)=7.5/(v_kmh+44)+0.161`，与天气/撒砂取小；WSP 恒开。

**三条要先说清楚的影响**（详细数字见附录 C）：

- **制动距离 +50%**：BR101+2×p1 全常用从 1.67 → **1.09 m/s²**；100 km/h 纯制动距离 243 → **371 m**。
  引擎的包线/保护读的是同一份物理（`serviceBrakeDecelerationMps2`），所以会自动提前刹车；
  但**线路上按旧口径布的信号与停车点要重新目视**（可能"来不及停"）。
- **"5% 制动力"这种弱档不存在了**：灵敏限 0.2 + 缸簧 0.3 ⇒ 最小有效减压 ≈0.32 bar ⇒ 最小可施力 ≈20.8 kN
  （旧表 1A 只有 7.5 kN）。低档整体抬强 2–3 倍。
- **UIC 经验式本身是"含衰减的整段平均"**，再乘一遍 κ(v) 会多保守约 11%（0→200 km/h 平均 κ=0.885）。
  留了开关 `padFadeEnabled`（默认 true）；若觉得整体偏软，先关它、再考虑把 `brakeWeightTonnes` 调大。

| 层 | 今天 | 差距 |
| --- | --- | --- |
| 司机指令 | `ThreeHandleSpec.brakeRatios[]` = 每个档位的**制动缸比例** | ❌ 无 bar 语义；档位 = 力的百分比 |

## 3. 简化后的模型（五层）

```
手柄档位 ─①级位表─▶ 列车管目标(bar) ─②充排气速率─▶ 管压
                                                    │③分配阀（倍率/灵敏限/限压）
                                                    ▼ 缸压
   ④力 = F_UIC(制动重率) × f(缸压) × κ(闸片, v) ◀────┘
   ⑤总力 = min( 机械 + 电制动 , μ_黏着(v)·m·g )   ← 黏着截断 / WSP
```

### ① 级位表（司机指令层）
`airPipeTargetsBar[notch]`（§2.2 的表）。这是唯一"数据"，其余全是公式。
旧 `brakeRatios` 保留可读（legacy 路径），新配置以 bar 表为准。

### ② 充排气速率（bar/s，**Q2 已确认**：保持今天的时间手感）
| 动作 | 新（bar/s） | 旧（归一化/s） | 等效时间（实测） |
| --- | --- | --- | --- |
| 列车管充风 | 0.35 | 0.15 | 全减压后充回 ≈ 4 s |
| 列车管排风 | 0.85 | 0.5 | 全常用减压 1.7 bar ≈ 2.0 s |
| 缸压建立 | 1.30 | 0.35 | 8 档从运行位建到 3.8 bar ≈ **3.1 s**（实测） |
| 缸压缓解 | 0.95 | 0.25 | 3.8 → 0 ≈ 4 s |
| 紧急排风 | 0.85×3 | 5.0 | ≈ 0.7 s；缸压到 4.2 bar ≈ 2 s |
| 逐车传播（P5） | 5.0 /s | `PIPE_EQUALIZATION_PER_SECOND` | 保留 |

> 充风取 0.35 而不是更慢的值，是因为**松闸后牵引回来的时间**由它决定：实测从满缸压松闸、
> 到牵引联锁放开（缸压 ≤1% 常用力）**3.9 s**（旧口径 4 s 量级，notes/248 的现场"二十秒没牵引"
> 不会被重新引入）。

### ③ 分配阀（管压 → 缸压）
```
P_bc = clamp( k_bc · (5.2 − P_pipe − 0.2) , 0 , 3.8 )     k_bc = 3.8 / (5.2−3.5−0.2) = 2.533
```
紧急：管压目标 3.0；缸压不再走 `k_bc` 而是直接 4.2 bar（紧急限压）。
**不做**：分配阀两段先导/主阀动作、空重车自动调整。

### ④ 力（缸压 → 轮周力）——**标定源已按 Q3 改为 UIC**

```
F_UIC  = m_equiv · (0.0065·λ + 0.12)          λ = brakeWeightTonnes / massTonnes × 100
F_mech = F_UIC · max(0, P_bc − 0.30) / (3.8 − 0.30) · κ(v)
κ(v)   = μ_b(v)/μ_b(0) ,  μ_b(v) = clip(0.39 − 0.00045·v_kmh , 0.28 , 0.39)
```
- BR101：`brakeWeightTonnes = 120` ⇒ λ=142.9% ⇒ a=1.0486 ⇒ **F_UIC = 102.2 kN**；
  紧急 `emergencyBrakeWeightTonnes = 168` ⇒ λ=200% ⇒ **138.4 kN**（E/S = 1.354，与旧 1.399 同量级）。
- P1 客车：`brakeWeightTonnes = 56` ⇒ λ=140% ⇒ **43.7 kN**（旧 70 kN）；紧急按 R+E≈1.4R ⇒ 59.1 kN。
- κ(v)：0 / 100 / 200 km/h = 1.000 / 0.885 / 0.769。
- **配置优先级**：显式 `serviceBrakeForceN` / `emergencyBrakeForceN` **优先于** UIC 反推（用于特例与既有用例），
  两者同时出现时按显式力走并在日志点名（沿用 notes/235 的"不静默"纪律）。

### ⑤ 电制动（三段式，补上高速恒功率）
```
B_ed(v) = B_max·(v/v_fade)     v < v_fade        （低速切除淡出，v_fade = 15 km/h）
        = B_max                 v_fade ≤ v ≤ v_base
        = min(B_max, P_regen/v) v > v_base        ← 新增
```
BR101：`B_max = 150 kN`、`P_regen = 6.4 MW` ⇒ `v_base = 153.6 km/h`；200 km/h 时 = **115 kN**。
`TractionSpec` 不动，只在 `ThreeHandleSpec` 加 `rheostaticMaxPowerW` 与纯函数 `rheostaticEffortN(v)`。

### ⑥ 电空混合（**已实施，默认开**）
```
B_demand      = F_mech(P_bc_分配阀, v)           ← 司机诉求 = 管压那份（不另算比例）
B_ed_actual   = min(B_demand, B_ed(v))           ← 电先吃饱，且不超过诉求
B_mech_demand = B_demand − B_ed_actual           ← 机械补缺
P_bc_final    = min( 反解(B_mech_demand) , P_bc_分配阀 )   ← **EP 阀只削不加**
```
- 总力 = 司机诉求；关掉（`blendingEnabled=false`）= 今天的行为（两者相加）。
- 司机**电阻制动手柄**仍是手动干预，与自动电制动**取大不相加**。
- 只在动力车做混合。
- 实测：200 km/h 8 档 ⇒ 缸压被削到 0（电制动全吃 78.6 kN）；静止 ⇒ 电制动为 0、缸压 3.80 bar；
  双手柄 ⇒ 150 kN（取大）而不是 282 kN（相加）。

### ⑦ 黏着截断与 WSP（**已实施，WSP 默认恒开**）
```
μ_adh(v) = min( 7.5/(v_kmh+44) + 0.161 , AdhesionSpec.usableMuMax() )
B_actual = min( B_mech + B_ed , μ_adh(v)·m·g )
```
- **实测结论**：新标定下**干轨/湿轨都吃不穿**（C-K 上限 = 0.19g–0.33g 的减速度，而常用制动只有 0.11g）
  ⇒ P4 实际是一条**天气特性**：只有**落叶/油污（μ≈0.07 ⇒ 单车 57.7 kN）**才真的截。
- `wspEnabled=false`（默认关）：超限按动摩擦断崖 `wheelSlipMu ≈ 0.12` 掉力（力反而更小）并打一条自白日志。
  轮对角速度/滑差率状态仍不做（牵引侧 S3 的活）。
- 现在用**整列** `m·g` 算上限；逐车版随 P5。

### ⑧ 与铭牌/制动重量表的对账（不再作为标定源）
铭牌口径（制动重量表 R=143% ⇒ 1.25 kN/t ⇒ 150 kN）与 UIC 经验式（1.05 m/s² ⇒ 102 kN）差 **1.47 倍**。
Q3 已定：**以 UIC 为准**，铭牌表只留作 `brakeWeightTonnes` 的来源（120 t / 168 t / 56 t）与实机对账参考。
另外模块一的几何链条算出来是 **211 kN**（附录 A），三种口径的关系是
`铭牌 150 : UIC 102 : 几何 211`，所以几何链条同样只作新车的力初值与对账。

**编组长度 vs 制动距离**（用户 2026-09-25 提问「挂车变多，制动距离会相应变长么？」）：
UIC 是**按每节车自己的制动重量**折算力的（`F_i = m_equiv_i·(0.0065λ_i+0.12)`），力与惯性**同比例**随车数涨
⇒ **同 λ 的车挂多少节，制动距离几乎不变**（实测 100 km/h 全常用：1 / 2 / 4 节 P1 = **370 / 371 / 372 m**，
制动力 146 / 190 / 277 kN 对惯性 140 / 182 / 267 t）。真正拉长距离的是 **λ 更低的车**：

| 编组 | λ | 100 km/h 全常用距离 |
| --- | --- | --- |
| BR101 + 2×p1（现场） | 141.5% | 371 m |
| 2×BR101 重联 + 2×p1 | 141.9% | 370 m |
| BR101 + 4×W50（25 t/50 t） | 77.5% | **608 m** |
| BR101 + 4×无闸货车 | 42%（只有机车在刹） | **1168 m** |

用例：`MmtrConsistTractionMappingTests.addingEquallyBrakedCoachesDoesNotLengthenTheBrakingDistance` /
`lowerBrakedWeightCarsLengthenTheBrakingDistance`。
**逐车管压（P5，已实施）**给这一栏补上另一半：尾车滞后 ⇒ 长编组的**过渡过程**更弱、停车距离更长
（5 节编组 100 km/h：427 → 439 m；编组越长差距越大），但**稳态逐位一致**（力与惯性同比例）。
另注：经验式的 **+0.12 常数落在"每节车"**（有闸车与"整列一次"的读法差 <2%；无闸车我们的实现更物理：
一分力都不出，而"整列一次"会白送它 0.12 m/s²）。

## 8. 实施记录（P1+P2，2026-09-25）

代码：`PneumaticBrakeSpec`（新）、`BrakeSpec`（UIC + 缸压→力 + κ(v)）、`TrainPhysics`（减速度走带衰减入口）、
`ConsistType`（制动重量解析 + 显式牛顿优先点名）、`ThreeHandleSpec`（`rheostaticMaxPowerW` +
`rheostaticEffortN(v)` + 气压规格 + 镜像串尾段）、`ThreeHandleDriveController`（bar 路径）。
细节与逐条证据见 `notes/266`。

**零回归机制**：气压口径是随包配置的开关 —— 一个 bar 键都不写 ⇒ `PneumaticBrakeSpec` 为 `null` ⇒
控制器逐位走旧的归一化模型。全量 826 条既有用例里只有两处**故意**重锚（`MmtrBrakeWeightTableTests`
的力锚、`MmtrConsistTractionMappingTests` 的编组制动力 290 → 189.5 kN）。

**实施中抓到的两个缺陷**（都已进用例）：

1. 配置里分配阀倍率写 `2.5333`（四舍五入）⇒ `2.5333 × 1.5 = 3.79995 < 3.8`，"8 档 = 满缸压"永远差
   5e-5 bar ⇒ 缸压/联锁/断言一起抖。**修法**：分配阀输出在 `≥ 上限 − 1e-3` 时吸附到上限（限压阀行为）。
2. **AFB 补气诉求为 0 时被折成缸簧 0.3 bar** ⇒ 缸压停在 0.3 bar ⇒ **牵引联锁（>1% 常用力）永远松不开 ⇒
   车不动**。这是本仓最怕的"看起来能开、其实不动"型现场，被"完全缓解 ⇒ 缸压归零"的断言当场抓住。
   **修法**：比例为 0 ⇒ 目标 0。

**实测**（`MmtrPneumaticBrakeTests`，dt = 50 ms）：

```
初制动（1A）：缸压 1.013 bar，轮周力 20.8 kN
全常用建压 3.1 s（管压 3.5 bar）
松闸到联锁放开（缸压 ≤0.35 bar）3.9 s
```

全量：**827 条，失败 3 条**（全部是预先存在的世界存档漂移，与本轮无关）。

**生效前提**：跑着的服务端/客户端还是旧 jar —— 红线是运行中不许覆盖 `game/libs`
（notes/216/77）。要生效：停服 → `scripts/sync-engine.ps1` → 重启。

## 9. 可复用性（P6，2026-09-26 用户口径）

> 「尽量使其更加可复用，因为不同列车逻辑不同，操作也不同，手柄档位也不同，车体连挂形式也不同
> （需要留连挂接口）」

四个"不同"各有一个落点，**模型本身只有一份**：

| 不同 | 落点 | 加一台新车要做什么 |
| --- | --- | --- |
| 列车逻辑（分配阀/闸片/缸压口径/黏着） | `PneumaticBrakeSpec` + `AdhesionSpec` + `BrakeSpec` | 写配置键（同一族车 ≈25 行），**零代码** |
| 操纵方式（三手柄 / 有级 / 无级 / 将来的 ATO） | `DriveController` + `BrakeCommand` | 新控制器只做"手柄 → 三个数"，制动逻辑不重写 |
| 手柄档位（几档、哪一档是全常用、紧急位在哪） | `ThreeHandleSpec`（三手柄）/ `ConsistType.brakeNotches`（有级）/ `airPipeTargetsBar` 级位表 | 改档数/级位表，模型一行不改 |
| 车体连挂形式（单机 / 机车+客车 / 双机重联 / 货车） | `List<BrakeCar>` + 连挂状态串 | 换一份列表（`MmtrComposition.brakeCars()`） |

### 9.1 分层与"谁持有状态"

```
  操纵方式层        ThreeHandleDriveController │ Notched │ Stepless │ (ATO)
                            └── 只做一件事：把手柄折成 BrakeCommand(demandRatio, assistRatio, emergency)
                                                    │
  制动模型层（唯一）        BrakeModel ◀── 每个控制器挂一件（BrakeCarrier.getBrakeModel()）
                            └── BrakeSystem：管压(逐车) → 分配阀 → 缸压(逐车) → 电空混合 → 逐车力 → 黏着
                                                    │
  数据/口径层        PneumaticBrakeSpec · BrakeCar(每节车的锚/动力/自己的口径) · 级位表
                                                    │
  连挂接口           encodeState() / applyState(String) / seedAfterCoupling(i)   ← 格式与 MmtrComposition 同
```

`BrakeModel` 就是"这套制动模型能被任何操纵方式挂上"的那件东西：归一化管压/缸压读数（镜像种子、
HUD、日志）、整列气制动力（`getPneumaticForceN()`）、牵引联锁（`isPneumaticHolding()`）、
逐车 bar 读数（`getPipeBar(i)`/`getCylinderBar(i)`）都从它出。控制器自己的 `AirBrakeStateful`
（客户端镜像种子）也转发到它 —— 于是 HUD/镜像那一侧同样不必知道是哪种操纵方式。

### 9.2 诉求口径（P6 新增的一条约定）

级位表的**表尾是紧急/快排级**（默认表 `5.2…3.6,3.5` 之后还有 `3.0`）。它不该被"0…1 的连续制动诉求"
够到 —— **无级手柄推到底、货车最后一档都必须是全常用（3.5 bar）**，紧急由保护层显式给
（`BrakeCommand.emergency()`；三手柄的紧急位仍由它自己的规格判定）。所以：

* 三手柄：`demandRatio = 档位/(档位数−1)`（级位表逐位，含紧急位，与 P1 起逐位一致）；
* 有级：`demandRatio = 档/档数 × getServiceDemandLimit()`（最后一位 = 全常用）；
* 无级：`demandRatio = 制动轴 × getServiceDemandLimit()`；
* `getServiceDemandLimit()` = 表中"全常用"那一档的位置比例（默认表 `9/10 = 0.9`）。

### 9.3 连挂接口

* `Vehicle.mmtrAirStateSnapshot()` / `mmtrApplyAirStateString()` / `mmtrSeedAirStateAfterCoupling()`
  按 **`BrakeCarrier` + 车底有没有 bar 键** 分派：有模型 ⇒ 走模型的逐车状态串；没有 ⇒ 走
  `MmtrComposition` 的旧归一化气路（老车底逐位不变）。判据用**车底**而不是"模型里有没有系统"，
  因为连挂手术常常发生在"新车还没人开"的那一拍（此时状态串先存进 `BrakeModel.pendingState`，
  第一拍建系统时灌进去）。
* 解挂切分：`MmtrCoupleSurgery` 把状态串按车序切开，各自 `applyState` 那一半；
* 连挂合并：先 `applyState`（保住已有的气压）再 `seedAfterCoupling(n)`（新挂上来的无动力车从
  管压 0/缸压 0 起，自己充风；动力车自带风源）。

### 9.4 验收判据（`MmtrBrakeModelReuseTests`，dt = 50 ms）

```
诉求 0.1…0.9：三手柄 = 有级 = 无级（20.8 / 35.6 / 50.4 / 61.5 / 72.6 / 80.0 / 87.4 / 94.8 / 102.2 kN）
全常用位：机车第 9 位 = 3.50 bar，常用诉求上限 0.90
逐车口径：机车缸压 3.80 bar、客车 2.00 bar（客车自己的上限 2.0）
迟到的状态串：建系统后管压 2.098 bar、缸压 1.965 bar（按切分时那一份，而不是满管）
```

**零回归**：没配 bar 键的车底三种操纵方式都不接管（`isPneumatic()` 假、bar 读数 0），
逐位回到旧归一化模型 —— 有级那一支的减速度逐位等于 `serviceBrakeDecelerationMps2(档/档数, v)`。

**P6 抓到的缺陷**（已进用例）：整列气制动力（notes/269 那条镜像）在**常用制动**支路上忘了赋值
⇒ 服务端镜像给客户端的"气"那份恒为 0，HUD 会在司机拉闸时只显示电制动 —— 正是 notes/269 现场
那个症状的另一个入口。修法：服务支路把逐车求和的结果写进 `lastPneumaticBrakeForceN`，
`getMmtrPneumaticBrakeForceN()` 同时按 `BrakeCarrier` 分派（有级/无级也有这一份读数）。
