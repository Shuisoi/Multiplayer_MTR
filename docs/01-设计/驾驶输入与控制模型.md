# 07 驾驶输入与列车控制模型（三手柄规格 v2）

> 状态：**规格定稿（2026-09-19）**，本轮落地"输入侧 + 引擎控制模型"，客户端键位已接、HUD/面板仍留 B6。
> 上一版（v1，单手柄 notch + HID 轴）见文末 §12 附录；本版是 BR101 这类**三手柄机车**的语义真源。
>
> 用户口径（本轮逐项确认）：
> ① 原逻辑是 legacy 单手柄 **P7 B8**（7 牵引档 / 8 制动档，见 `MmtrSupport.controlFromLegacyPowerLevel`）；
> ② 新列车**三根手柄**＝定速巡航 + 油门（牵引与电阻制动集成、双向）+ 气制动；
> ③ 定速巡航：**步长 5 km/h、量程 0–160**（33 个定位），AFB 式自动保速，油门手柄降为"牵引上限"；
> ④ 油门：**1% 一档**，中央"关闭"、两侧各有独立"最小"档、其后 5%…100%（两侧镜像：牵引 / 电阻制动）；
> ⑤ 制动：**运行 / 1A / 1B / 2 / 3 / 4 / 5 / 6 / 7 / 8 / EB**（1A、1B 是弱档，力按档位查表）；
> ⑥ 换向仍是独立换向器，沿用引擎红线"只在停稳时可动"；三手柄不含它。

---

## 1. 三根手柄总览

| # | 手柄 | 取值 | 定位 | 谁说了算 |
| --- | --- | --- | --- | --- |
| H1 | 定速巡航（AFB） | `cruiseSpeedKmh` 0…160，**步长 5** | 33 位：0 = 关闭 | 设定值＝目标速度；牵引/电阻制动由引擎自动调节 |
| H2 | 油门（Fahrschalter，牵引＋电阻制动） | `driveHandle` **−97…+97** | 中央 0 = 关闭；±1 = 最小；±2…±97 = 5%…100% | 牵引侧＝牵引力；制动侧＝电阻制动力；AFB 生效时牵引侧降为**上限** |
| H3 | 制动（气制动） | `brakeNotch` 0…10（＝位置下标） | 0 运行 / 1 = 1A / 2 = 1B / 3…9 = 2…8 / 10 = EB | 气制动缸压力，按查表比例 + 建/缓解速率 |
| — | 换向器（独立小杆） | `reverser` −1/0/+1 | 后退 / 中立 / 前进 | 只在停稳时可动（引擎红线，`applyMmtrTravelReversed`） |

三根手柄互不排斥但在引擎里按**固定优先权**合成，见 §5。

## 2. H1 定速巡航（AFB）

- 量程 0…160 km/h，**每档 5 km/h**；`0` = 关闭（不干预）。客户端键位：**数字键 9 = −5、0 = +5**（暂定）。
- 生效条件（全部满足）：`cruiseSpeedKmh > 0` ∧ 非紧急 ∧ **气制动手柄在"运行"位** ∧ 不在超速/SPAD 保护中。
  - 司机一碰气制动，AFB 立即**让位**（设定值保留，回到"运行"位后自动恢复）；
  - 保护/紧急由既有监督层（`evaluateMmtrProtection`、LZB 天花板）在控制器**之上**执行，AFB 不复制这套判断。
- 调节律（`ThreeHandleDriveController`，纯比例）：
  - `error = target − v`（m/s）；
  - `error > 0` → 牵引比例 `= min(cap, gain × error)`，`cap` = 油门手柄牵引侧比例（**关闭位 cap = 0**，见下）；
  - `error < −0.2 m/s` → 电阻制动比例 `= max(手柄电阻侧比例, min(1, gain × |error|))`；
  - 其余（|error| ≤ 0.2 m/s）→ 惰行（只受运行阻力）。
  - `gain`（默认 0.15 /(m/s)）可配；比例控制天然有静差，换来的好处是**不会在目标速度上来回抖**（无死区跳变）。
- **"牵引上限"的确切含义**：AFB 生效时油门手柄不设定速度，只限制引擎能用多少牵引力 —— 手柄在"关闭"位则 cap = 0，AFB 这一侧只能保速/电阻制动（下坡），想加速必须把油门推上去。
  - 若日后判定这不合手，改 `consist-types.json` 的 `afbUsesHandleAsCap: false` 即可（AFB 不再看手柄）。**这是本规格里唯一需要实机确认的语义**。
- AFB **不使用气制动**：电阻制动不够时由司机自己拉制动手柄（与真车一致：AFB 只动电力/液力制动）。

## 3. H2 油门手柄（牵引＋电阻制动，双向）

位置 p ∈ [−97, +97]，1% 一档：

| p | 位置 | 牵引比例 | 电阻制动比例 |
| --- | --- | --- | --- |
| 0 | **关闭** | 0 | 0 |
| +1 | **最小** | `driveMinRatio`（默认 0.02） | 0 |
| +2 … +97 | 5% … 100% | `(p + 3) / 100` | 0 |
| −1 | **最小** | 0 | `driveMinRatio` |
| −2 … −97 | 5% … 100% | 0 | `(|p| + 3) / 100` |

- 校验：`p = +2 → 5%`，`p = +97 → 100%`；`+1` 的 2% 低于 5%，这就是"最小"独立成一档的原因。
- 牵引：`MmtrPhysics.tractionAcceleration(type, ratio, v)`（恒力矩到折点、其后恒功率 1/v、再减运行阻力）。
- 电阻制动：`a = rheostaticBrakeDecelerationMps2 × ratio × fade(v)`，
  `fade(v)` 在 `rheostaticFadeKmh`（默认 10 km/h）及以上为 1，往下降到**其一半**（5 km/h）线性归零，
  再低**完全失效**。
  **低速失效是刻意的**：真车电阻制动在低转速下建立不了力矩，想停住必须用气制动 ——
  这也是"两根手柄要配合"的根据。若把衰减写成 `a ∝ v`，列车会以指数律渐近停住，这条就成了一句空话。
- 电阻制动与气制动**叠加**，但**没有自动补气**（电阻制动衰减时不会自动代以气制动）——那是司机的活。

## 4. H3 制动手柄（气制动）

位置表（下标即 `brakeNotch`，比例可配 `brakeRatios`）：

| 下标 | 位置 | 制动缸目标比例 | 备注 |
| --- | --- | --- | --- |
| 0 | 运行 | 0.00 | 缓解：管压回充、缸压排空 |
| 1 | 1A | 0.05 | 弱档（低速微调） |
| 2 | 1B | 0.12 | 弱档 |
| 3 | 2 | 0.20 | |
| 4 | 3 | 0.32 | |
| 5 | 4 | 0.44 | |
| 6 | 5 | 0.56 | |
| 7 | 6 | 0.68 | |
| 8 | 7 | 0.80 | |
| 9 | 8 | 1.00 | 全常用制动 |
| 10 | **EB** | 紧急 | 忽略速率直接按 `emergencyDecelerationMps2`，并置 `emergency` 标志 |

- **建压/缓解不是瞬时的**：缸压按 `airBrakeApplyRatePerSecond` / `airBrakeReleaseRatePerSecond` 追目标值，
  管压同步镜像（供 HUD 与镜像种子）；这与既有 `AirBrakeController` 的"降保升"同一套参数、同一套口径。
- 制动减速度 = `serviceBrakeDecelerationMps2 × 缸压 + 运行阻力`。
- 手柄到 EB 位与"外部紧急"（保护层）**同一个出口**：两者都走紧急减速度，`DriveOutput.emergencyBrake = true`。

## 5. 合成优先权（每 tick，从上到下第一条命中即生效）

| 序 | 条件 | 结果 |
| --- | --- | --- |
| 1 | 紧急（EB 位 / 保护层） | 紧急减速度，牵引与电阻制动全部封锁 |
| 2 | 气制动 > 运行 位 | 气制动生效；AFB **暂停**（设定值保留）；电阻制动仍可叠加（司机手柄） |
| 3 | AFB 生效（§2） | AFB 调牵引/电阻制动；牵引受油门手柄上限约束 |
| 4 | 加油门（p > 0） | 纯牵引（含"最小"） |
| 5 | 拉电阻制动（p < 0） | 纯电阻制动，**低速衰减**（§3） |
| 6 | 都没有 | 惰行（只减运行阻力） |

### 6.1 `ControlState`（引擎侧统一输入状态）

| 字段 | 含义 | 备注 |
| --- | --- | --- |
| `driveHandle` | H2 位置 −97…+97 | **新增** |
| `cruiseSpeedKmh` | H1 设定值 0…160（步长 5） | **新增** |
| `brakeNotch` | H3 位置下标 0…10 | 复用：THREE_HANDLE 按查表解释，NOTCHED 仍按 `notch/brakeNotches` |

| `throttleAxis`/`brakeAxis` | HID 连续轴 | 保留（STEPLESS 用） |
| `emergency` / `acknowledge` | 紧急 / AWS 确认 | 不变 |

### 6.2 `ConsistType`（服务端 JSON，新增 `THREE_HANDLE` 控制模式）

**车底是按车选的，不是按维度**（`MmtrCarTypeResolver`）。两条来源，按优先级：

1. 车厢**声明的**车底 id（资源包的 `mmtrConsistTypeId`，随 OBJ 车列元数据进来）；
2. 注册表里的**车型映射** `carTypeIds`：`{"br101": "br101_three_handle"}` —— 不必重打包就能把已有车型接到新车底上；
3. 都解析不出来 → 维度缺省 `defaultConsistTypeId`（**零回归**：没配过的车一个字节不变）。

一列车是一个刚体、纵向动力学只有一套参数，所以**第一节能解析出车底的动力车说话**（机车/动车组），
没有动力车才取第一节能解析出的车厢；连挂/解挂换了说话的车，控制器与气制动状态会重解一次
（判据是"决定车底的那节车的型号|车底|动力位"）。

```json
{
  "defaultConsistTypeId": "emu_8_notched",
  "carTypeIds": { "br101": "br101_three_handle" },
  "consistTypes": [
    {
  "id": "br101_three_handle",
  "controlMode": "THREE_HANDLE",
  "powerNotches": 97, "brakeNotches": 11,
  "maxSpeedKmh": 160, "manualMaxSpeedKmh": 160,
  "tractionAccelerationMps2": 0.55, "tractionBreakpointKmh": 80,
  "serviceBrakeDecelerationMps2": 1.0, "emergencyDecelerationMps2": 1.8,
  "rheostaticBrakeDecelerationMps2": 0.9, "rheostaticFadeKmh": 10,
  "driveMinRatio": 0.02, "drivePercentSteps": 96,
  "cruiseMaxKmh": 160, "cruiseStepKmh": 5, "afbGainPerMps": 0.15, "afbUsesHandleAsCap": true,
  "brakeRatios": "0,0.05,0.12,0.20,0.32,0.44,0.56,0.68,0.80,1.00,1.00",
  "airPipeChargeRatePerSecond": 0.15, "airPipeDischargeRatePerSecond": 0.5,
      "airBrakeApplyRatePerSecond": 0.35, "airBrakeReleaseRatePerSecond": 0.25
    }
  ]
}
```

- 缺省值保证"不填也能跑"：`rheostaticBrakeDecelerationMps2` 缺省跟随 `serviceBrakeDecelerationMps2`，
  `brakeRatios` 缺省即上表，`drivePercentSteps`/`cruiseStepKmh` 缺省 96 / 5。
- 老模式（`DEFAULT`/`NOTCHED`/`STEPLESS`/`AIR_BRAKE`）**一个字节不改**：三手柄是新模式，不是替换。

### 6.3 谁能操纵（准入判据，2026-09-19 放宽）

| 判据 | 内容 |
| --- | --- |
| 引擎权威 | `Vehicle.canTakeMmtrControl(uuid)`：**骑在这辆车上、并且是司机位**（ride 包的 `isDriver`） |
| ~~钥匙~~ | **不再是前提**：`holdsMmtrCabKey` 从操纵判据里去掉（用户口径「操作手柄不需要手里握着钥匙」）。它保留下来只回答"钥匙在谁手里"（system 钥匙 / 乘务员钥匙的区分） |
| 占用锁 | 一列车上同时只有一个司机：没人持有 override 时谁先动手谁拿到；持有者**还在司机位上**时别人抢不走 |
| 交还判据 | **司机位空了才交还**（人走开 / 下车 / 断线）。拔钥匙**不再**断牵引 —— 否则站在司机位上、车正在走的人会因为"钥匙被人拔了"而突然失去制动 |
| 任务闸门 | 无任务不得操纵（T4 策略开关，默认关） |
| 客户端上报 | `isDriver = mmtrCabConfirmed \|\| MmtrDriverSeat.isAtControls()`，**只在变化时**发包 |

- 客户端的"我在司机位"判据与雨刷的 `driverOnBoard` 共用 `MmtrVehicleAnchors.nearestCab`（**唯一一份**），
  所以"雨刷会动的地方"和"能操作手柄的地方"永远指同一个驾驶室。

## 7. 键位（本轮；可在控制菜单改）

| 键 | 动作 |
| --- | --- |
| ↑ | 油门手柄往**牵引**侧一步（+1%，长按 >0.25 s 后按 20 步/秒扫） |
| ↓ | 油门手柄往**电阻制动**侧一步（−1%，同样长按扫） |
| ; | 气制动 **+1 档**（施加；一直按到 10 = EB） |
| ' | 气制动 **−1 档**（缓解，最低回"运行"） |
| 9 | 定速巡航 **−5 km/h**（到 0 = 关闭） |
| 0 | 定速巡航 **+5 km/h**（上限 160） |
| → / ← | 换向器 前进 / 后退（±1，停稳才生效） |
| G | 进/出驾驶室（既有，B2） |
| J | 雨刷（既有，W4） |
| K | 连挂/解挂（既有，C7） |

- "1% 一档 + 96 档"必须能长按扫，否则推满要按 96 次 —— 单击 1 档、长按 0.25 s 后 20 档/秒。
- **操作不需要钥匙**（用户口径 2026-09-19）：键位在**坐在司机位上**时即产生控制意图，
  判据是 `MmtrDriverSeat`（沿车长的位置离哪个驾驶室的玻璃最近，与雨刷 `driverOnBoard` 同一条规则），
  **不要求按 G 申领驾驶室、也不要求手里握着钥匙**；引擎侧对应地不再要求 `holdsMmtrCabKey`（见 §6.3）。
- 坐在司机位上**第一次动手柄**时会自动把该驾驶室接管过来（`MmtrCabInteraction.claimSeatWhenDriving`，
  就是 G 键那条命令）—— 因为"哪一端在前"由被占用的驾驶室决定，不接管的话坐在 A 端的人会倒着开。
  刻意不在"坐下"时就接管：那会让"坐到 AI 车的驾驶室里看看"把自动运行停掉。
- 离开司机位时客户端把三手柄归到 **关闭 / 运行 / 定速 0** 并发最后一次状态，避免"人走了车还带着旧手柄"；
  **换向器不动**（真车手柄停在哪就在哪，方向本来就由引擎在停稳时才认）。

## 7.1 右上角简略 HUD（`MmtrDriverHud`）

```
┌───────────────┐
│ 速度   87 km/h │
│ 油门 牵引 45%  │   ← 牵引蓝 / 电阻制动橙 / 关闭灰
│ 制动        2  │   ← 非运行位橙、EB 红
```

## 7.2 HID（手柄 / 摇杆）：DirectInput 的 X / Y / Z

| 轴 | 手柄 | −1 端 | +1 端 |
| --- | --- | --- | --- |
| **X** | 定速巡航 AFB | 0（关闭） | 车型上限（BR101 = 160，步长 5 km/h） |
| **Y** | 油门手柄（双向） | 满电阻制动 | 满牵引（**中位 = 关闭**，含死区） |
| **Z** | 气制动手柄 | 运行（缓解，含死区） | EB（末尾吸附） |

- 换算全在引擎的 `MmtrHidMapping`（纯函数 + 真值表单测：中央关闭 / 两端吸附 / 逐轴可反转 / 镜像对称）；
  客户端 `MmtrHidInput` 只做"找设备、读 GLFW 轴、按启动参数校准"三件事。
- **键盘与 HID 并存**：轴是绝对量，所以它**压在键盘之后**（有真杆时以杆位为准）。没插手柄时 `poll` 返回
  `null`，纯键盘照常 —— 零回归。
- 开机（或换设备/重连）打一行 `[MMTR-HID]`，写明设备名、轴号、生效方向与死区 —— "手柄没反应"
  不该再是一种只能靠猜的现场。
- **校准不改代码**（实物千差万别）：

  ```
  -Dmmtr.hid.joystick=0          选 GLFW 手柄号（0 = GLFW_JOYSTICK_1）；默认第一个连着的手柄
  -Dmmtr.hid.axis.x/y/z=0,1,2    轴号（DirectInput 惯例 X/Y/Z）
  -Dmmtr.hid.invert.x/y/z=true   逐轴反转（推杆方向与预期相反时）
  -Dmmtr.hid.deadzone=0.05       死区
  ```

- **两处有意的不对称**（写下来，免得当成 bug 查）：
  1. 模拟轴上**"最小"档（位置 ±1，2%）不可达** —— 它落在死区里，一出死区就是 5%。要 2% 就用键盘单击 ↑/↓；
  2. 死区只做**中央吸附**（油门）与**两端吸附**（制动），不做量程缩放 —— 否则"最小档"会被死区吃掉一整段。

## 8. 客户端输入链

```
KeyBindings (键盘) ─┐
                    ├─ MmtrDriveInput.tick()   每客户端 tick：MmtrDriverSeat 判定 + 状态机 + 长按扫描 + HID 绝对量
MmtrHidInput (GLFW) ┘        ├─ MmtrCabInteraction.claimSeatWhenDriving(seat)   第一次动手柄 ⇒ 自动接管该驾驶室（定方向）
                             └─ PacketDriveControl (C2S)   仅在值变化时发；坐着期间每秒补发一次（自愈）
                                  └─ MmtrDriveControl (op) 引擎权威入口（occupation lock：只有坐在司机位的玩家算数）
                                       └─ Vehicle.applyMmtrControl → MmtrDriveAccess.sanitize（钳位）
                                            └─ ThreeHandleDriveController.compute（每 tick / 每子步）
```

- **只在变化时上报**：手柄状态是"保持型"，不按不耗流量；每秒补发一次是为了引擎侧 override 被自动释放后能自愈。
- 引擎钳位是**外部守卫**（`driveHandle` ±100、`cruise` 0…320），按车型的精确范围由 spec 再钳一次 —— 恶意/有 bug 的客户端推不出物理范围外的值。

## 9. 镜像（客户端同物理）

- 客户端没有 `consist-types.json`：车型参数与手柄规格通过车辆快照镜像。
- 新增镜像字段：`mmtrDriveHandle`（整数）、`mmtrCruiseKmh`（整数）、`mmtrHandleSpec`（**紧凑字符串**，如
  `TH;0.02;96;0.9;10;160;5;1;0,0.05,…`；只有车型变化时才变，不必每帧传数组）。

  于是客户端与服务端跑的是同一个控制器、同一个手柄值 —— 与既有 AIR_BRAKE 的 `mmtrAirState` 种子同一套路。
- 增量同步白名单（`VehicleSyncPatch`）必须带上这三个字段，否则"改了手柄客户端不同步"（历史坑）。
