# 停车对标：牌子方块与站台停车基准（设计）

> 状态：**设计稿已拍板 · P0/P1/P2 已装机验收 · P3（批量铺站）已于 2026-10-13 完成**（TEST 站台整套
> 铺到台账里另外 10 座标准站，轨道除外；见 §12.8 与 `notes/424`） ｜ 日期：2026-10-13
> ⚠ 落地实况与本文的差异（字段名、坐标口径、两套 fraction 的换算）见 **§12**，实现以 §12 为准。
> 触发（用户口径）：「现在需要界定列车的停站位置，因为加入了屏蔽门所以需要给予一个点让玩家对标」
> →「牌子我们可以立在任意位置，但是牌子的属性有 ID（设立在站台股道下的），以及停车点（车头计算）」
> →「一块牌子 = 一个辆数（每面 9 块）」＋「多种样式」＋「引擎加站台停车基准字段（选项 C）」
> 关联：`mmtr/notes/417`（TEST 铺 APG 墙）、`420`（对标表 + 引擎现状逐条调查）、`421`（门栅格复核）
> 工具：`mmtr/tools/stop-mark/stop_table.py`（算各辆数的车头停点）

## 0. 一句话

给每条站台股道挂一组「停车牌子」，每块牌子记 **归属股道（ID）+ 一个辆数 + 车头停点**；
引擎据此得到「站台停车基准」（自动车按它停、司机 HUD 显示到对标点距离），
而牌子的**型号/样式**只是渲染，**位置**只用来反解"车头要停在哪个里程"。

## 1. 现状核对（引擎侧，逐条已核对）

| 事实 | 出处 |
| --- | --- |
| 自动车到站：`stopFraction = 1.0` ⇒ **车头停在站台图轨在行进方向上的远端端点**（TEST 南行 = z1020、北行 = z800） | `data/Vehicle.java:988-999`、`mmtr/MmtrRunPlanner.java:833-836` |
| 被对到锚点的是**车头（leading 端面）**，不是列车中心 | `Vehicle.java:4640-4681`、`MmtrConsistMotionTests`（"车头恰好停在锚点的深度上"） |
| 引擎**完全没有**"车门 ↔ PSD/APG"概念 | 全库 `PSD|APG` 零命中；`data/Platform.java` 只有 `dwellTime/crowdLevel/routes` |
| 门与屏蔽门是**接近即联动**（±1 格扫描 + 未锁门推 `doorValue`），不含对位基准 | `game/.../render/RenderVehicleHelper.java:15-59` |
| **玩家任务没有停车点**，`mmtrDistanceToStopTargetM`/`mmtrRunStopTarget` 恒 −1 ⇒ 司机今天没有任何"到点距离"读数 | `Vehicle.java:1126-1147`（PLAYER 分支）、`VehicleExtension.java:651`、`MmtrTaskHud.java:616`、`PdaScreen.java:356,374` |
| 没有"停车标 / 对标"概念（`stopMark` 是停机请求文件，同名不同义） | 全仓搜索 |

⇒ 结论：**这是一个从零定义的新概念**，不是修 bug。

## 2. 几何地基（实测，notes/420 §1 + 421）

| 量 | 值 |
| --- | --- |
| 每节车门洞数 | 每侧 3 个（`door_l_N`/`door_r_N` 是**同一门洞的左右两片**），每个门洞宽 2 m |
| 车内门距 / 跨车缝门距 | **都是 6.000 m**（头车 19.5+1.05、拖车 16.95+1.05 配门位恰好补平） |
| **车头端面 → 第 1 个门洞中心** | **5.0245 m**（打包后 `cab_a` 的驾驶室在 +Z，`9.750 − 4.7255`） |
| ⇒ 整列 30 个门洞 | `u = 5.0245 + 6.000k`（k=0…29），**与编组辆数 2…10 无关，两个方向同相** |
| TEST 的 APG 门洞中心 | `z0 + 2`，`z0 = 821 + 6k` ⇒ **822 + 6k** |
| ⇒ 车头必须满足 | `车头 z ≡ 822 − 5.0245 = 816.9755 (mod 6)` |

**这两条推论是本设计成立的前提**：
1. **一块牌子只需要一个数**（车头停点）——因为门栅格与辆数无关、两方向同相；
2. 不同辆数之所以要不同牌子，只是"让列车在站台上居中"这一条**人为选择**（表见 §11）。

## 3. 口径（已定）

| 项 | 口径 |
| --- | --- |
| 牌子粒度 | **一块牌子 = 一个辆数 + 一个方向**（2…10 × 上/下行）⇒ **单方向站台面 = 9 块**，双向面 = 18 块 |

> ⚠ **方向不能省**（写设计时纠正）：门栅格两个方向**同相**（同一辆数的**车身停点区间**相同），
> 但**牌子位置分方向** —— 因为**驾驶室在列车前端**：南行车头在北端（牌子 = 车头 + 1.25 m），
> 北行车头在南端（牌子 = 车头 − 1.25 m）。§11 表里两列分别对应两个方向。
| 牌子位置 | **任意**（用户口径）；它只用来反解"车头停点" |
| 牌子属性 | **ID**（归属站台股道，可在站台股道下设立/绑定）＋ **停车点**（按车头计算）＋ 辆数 |
| 样式 | **多种**（立杆 / 吊挂 / 贴墙；牌面默认写"N 辆"） |
| 对标参照点 | **驾驶室侧窗**（车头端面后 **1.25 m**；备选：司机座 1.55 / 驾驶室侧门 2.25 / 挡风 0.025） |
| 自动停车 | **改**：新增"站台停车基准"，自动车按牌子停（用户选 C） |
| 玩家 | 同一个基准作为**只读参考**下发给司机（HUD/PDA 读数），**不夹刹车**（notes/229 口径不变） |

## 4. 数据模型

### 4.1 方块 `mmtr:stop_marker`

* `BlockState`：`facing`（朝向，决定牌面朝哪）、`variant`（**样式**，0..N）、`waterlogged`（可选）
* `BlockEntity`：
  | 字段 | 含义 |
  | --- | --- |
  | `cars` | 本牌对应的编组辆数 `2..10`（0 = 通用） |
  | `direction` | 本牌对应的行车方向（NORTH / SOUTH；站台面只走一个方向时可省略） |
  | `platformId` | **ID**：归属站台（引擎 `Platform.id` / hex）；0 = 未绑定 |
  | `headStopFraction` | 车头停点在这条股道上的比例（0..1，投影得到） |
  | `datumM` | 参照点相对车头的偏移（默认 1.25 = 驾驶室侧窗；牌子位置 → 车头停点 = 牌子位置 − datumM） |
  | `label` | 牌面文字（默认 `"N辆"`；可空） |
* 交互：持 **刷子** 右键 = 绑定归属（先右键站台/股道方块记 id，再右键牌子写入）；右键 = 就地改辆数（`2→3→…→10→2`）；**潜行+右键 = 改样式**。

### 4.2 归属解析（顺序）

1. **显式绑定**：block entity 的 `platformId ≠ 0`；
2. **位置解析**：把牌子的世界坐标投影到最近的**站台股道**（判据与 `MmtrCrowdPlatformLevels.platformAt` 同源：水平 ≤ N 格、垂直 ≤ 4 格；曲线站台用弧长按 §10 处理）；
3. 都失败 ⇒ **未登记**：牌子渲染成"未绑定"外观（红叉），不参与注册，日志一行。

### 4.3 冲突与边界

* 同一 (平台, 辆数) 出现多块牌 ⇒ **取离该平台中心最近的一块**，其余报冲突（日志 + 只读出口里标 `conflict`）；
* `cars` 超出 2..10 ⇒ 拒收；
* 车头停点落在股道之外 ⇒ 拒收（`headStopFraction ∉ [0,1]`）。

## 5. 引擎侧

### 5.1 落点选择：**独立注册表**（推荐）而不是塞进 `Platform`

| 方案 | 说明 | 取舍 |
| --- | --- | --- |
| A 塞进 `Platform`（`buildSrc/.../schema/data/platform.json` 现有 2 字段） | 加 `stopMarkers[{cars, railHex, fraction}]` | 改动小；但牌子是**自由摆放**的方块，塞进"由站台方块决定"的对象会破坏语义、且牌子拆掉后要脏回平台 |
| **B 独立注册表（推荐）** | 新增 `StopMarkers` 数据集（按 `platformId` 索引），生命周期与信号灯/灯位同构 | 与"牌子可以立在任意位置"一致；拆装只动注册表；HTTP 出口、扫描命令都能照抄现成套路 |

### 5.2 停车基准接入点（自动车）

`Vehicle#mmtrMotionSelfArmMission` 的目标解析（`Vehicle.java:988-999`）：

```
现在：  stopFraction = 1.0                              // 站台轨远端端点
改成：  marker = stopMarkers.find(platformId, 本车编组辆数, 本车行进方向)
        stopFraction = marker != null ? marker.fraction : 1.0     // 查不到 = 行为不变
```

* `railHex` = 牌子归属股道（`marker.railHex`），`fraction` 由牌子位置投影得到；
* `planToRailForward` 与"按锚点校正"（`Vehicle.java:4665-4681`）**不动**：它们是把估算里程改精确的既有机制；
* 编组辆数：`vehicleExtraData.immutableVehicleCars.size()`（同源已在用）。

### 5.3 玩家参考字段（只读，不夹刹车）

最小改动路径（notes/420 §6.2 的调查结论）：

1. `Vehicle.java:1126-1147`（PLAYER 分支，唯一业务改动点）：把 `plan.stopCumulativeM/stopRailHex/stopFraction`
   写进**两个新字段**（如 `mmtrDriverStopTargetM` / `mmtrDriverStopRailHex`）——**不要**调 `setMmtrMotionStopTarget(...)`（那会顺带成为刹车目标，违反 notes/229）；
2. `buildSrc/.../schema/data/vehicle.json`（+2 字段）→ `operation/VehicleSyncPatch.java:47 DYNAMIC_KEYS` → `Vehicle#updateMmtrSyncFields`；
3. 客户端：`data/VehicleExtension.java`（getter，照 `:651` 的既有先例）+ `render/MmtrTaskHud.java:616`（该行 `<0` 不画，可直接复用）+ `screen/PdaScreen.java:356,374`。

### 5.4 任务系统

* **到站判据不动**（notes/229：玩家任务走宽松观测，`mmtrArrivalIsLoose`）；
* 停车基准只服务两件事：**自动车的精确停车**、**给司机的读数**；
* 站停子任务可在提示文本里带"对标点还有 X m"（走 `mmtrSubTaskHint`，不新增状态）。

### 5.5 登记与只读出口

| 通道 | 形式 | 作用 |
| --- | --- | --- |
| 游戏端扫描 | `world scan-stop-markers`（与 `world scan-signals` 同构） | 扫已加载区块里的 `mmtr:stop_marker`，解析归属 → `mmtrPushCommand("stop-markers register …")` |

## 10. 待定与风险

1. **0.275 m 的端面归属**（notes/421 §2 保留项）：建议实机在某 220 格站台停车后用 F3 量一次"第一个门洞 vs 屏蔽门洞"的 z 差，把 5.0245 这个基准钉死；牌子侧用 `datumM` 可以整体平移，所以不阻塞实施。
2. **曲线站台的投影**：`MmtrPlatformCommands.java:344` 已记录"曲线站台真实弧长 > 弦长"，牌子投影要用弧长参数化，不能用直线弦。
3. **牌子的位置歧义**：立在两条股道之间时按"最近股道 + 显式绑定优先"处理，未绑定即红叉。
4. **容差**：APG 门洞 2 m 宽、车厢门洞 1.095 m 宽 ⇒ 停车偏差 ≤ ±0.45 m 时门完全落在洞内；±1 m 时仍可上下客（半格错位）。牌子本身不解决司机手感，只给基准。
5. **多辆数并存时的"停哪一段"**：本设计取"居中"（§11 表）；若要改成"靠北端对齐"，改 `stop_table.py` 的选 j 规则即可，牌子位置随之重铺。

## 12. 落地实况（as-built，2026-10-13）

> 这一节是**实现完成后回填的**：与 §4/§5 的设计稿有出入的地方，以本节为准；差异逐条写了原因。

### 12.1 方块与方块实体（实况）

| 项 | 实况 |
| --- | --- |
| 方块 id | `mtr:stop_marker`（**一个**方块，三个样式是同一方块的 `variant` 属性 0..2 = 立杆/吊挂/贴墙） |
| 方块属性 | `facing`（水平四向）、`variant`（0..2） |
| 方块实体字段 | `cars`(int, 2..10, 0=未设定)、`platformId`(long, 0=按位置解析)、`platformHex`、`datumM`(double, 默认 1.25)、`label` |
| 交互（刷子 `mtr:brush`，全部服务端判定） | 普通右键 = 辆数 `未设定→2→…→10→未设定`；**潜行**右键 = 换样式；先拿刷子点**站台方块**（Fabric `UseBlockCallback`，只认"手持刷子 + 点到 `BlockPlatform`"）记下归属，再右键牌子 = 写入归属 |
| 放置朝向 | `facing = 玩家朝向的反方向` —— 牌面朝 `facing`，所以放完正面朝自己（与 MTR 那些牌子在游戏里的观感一致） |

**与设计稿的差异（3 条，都必须知道）**

1. **`headStopFraction` 不进方块实体**：车头停点要沿站台股道的**弧长**投影才算得出来，而股道是引擎的数据
   （游戏侧只有镜像）。方块实体只记"牌子在哪、归谁、认几辆、参照点偏多少"，投影由引擎在登记时做
   （`MmtrStopMarkerGeometry.project`）。好处是"同一块牌子在两端算出来的停点是同一个值"，不会出现
   两套实现各算一个数。
2. **`direction` 不进方块实体**：方向由**牌子位置**反推（见 §12.3），玩家不需要为"方向"多学一个交互。
   设计稿 §3 那张"每面 9 块"的账因此更简单：一块牌子 = 一个辆数，方向自己带着。
3. **牌子坐标按方块中心解释**：`x,y,z` 是方块坐标，投影时用 `x+0.5, z+0.5`（牌面就画在方块中心那一竖列）。

### 12.2 坐标口径与精度下限（**两条必须记住的量**）

| 量 | 值 | 出处 |
| --- | --- | --- |
| 轨中心线相对节点方块坐标的平移 | **+0.5**（x 与 z） | `RailMath.getPosition` 的既有口径；所以"牌子 z − 站台端 z"**不等于**弧长 |
| 牌子弧长 | `closestArc(折线, x+0.5, z+0.5)`，不是直线弦 | `MmtrStopMarkerGeometry`（曲线站台按折线弧长） |
| 方块栅格决定的停车精度下限 | **±0.275 m** | 理想牌位落在 `*.225/*.775`，方块中心栅格是 `*.5` ⇒ 最近一格差 0.275 |

0.275 m < 屏蔽门对位容差 ±0.45 m（§10.4）⇒ 可用，且这是"牌子摆在整格方块上"这条约束的必然结果，
不是实现误差。真要更准只能让引擎按方块**角点**解释（残差变成 −0.2255，反而更小但语义更绕），本设计不取。

### 12.3 方向由位置反推（实况）

牌子记的是"车头后方 1.25 m 的驾驶室侧窗"，车头在列车前端 ⇒ **牌子落在站台轨前半段**就是
"车朝另一端开"（`deriveTowardEnd0`：弧长 ≤ 全长一半 ⇒ `towardEnd0 = true`）。
于是同一辆数的两块牌子天然对称落在站台两端附近（§11 表的两列）。

查询键因此是 **(站台, 辆数, 方向)** 三键 —— 正好是自动车要用到的三个量。

### 12.4 引擎侧实况

| 层 | 实况 |
| --- | --- |
| 登记表 | `org.mtr.core.mmtr.stopmark.MmtrStopMarkerRegistry`（`TreeMap`，落盘 `mmtr-stop-markers.json`；冲突**不落盘**，读的时候现算） |
| 几何 | `MmtrStopMarkerGeometry`（`project` / `deriveTowardEnd0` / `nearbyPlatform` / `headFractionAlong`） |
| 停车换算 | `MmtrStopMarkerStops.stopFractionFor(...)`（见下） |
| Simulator | `mmtrStopMarkers`、`mmtrStopMarkerRegister(x,y,z,cars,platformIdHint,label,datumM)`、`mmtrStopMarkerRemove(x,y,z)` |
| 游戏端 | `MmtrStopMarkerSync`（放/拆即登记 + 一圈一分钟的轮转兜底 + 刷子取归属 + `stop-markers scan`）、`BlockStopMarker`、`RenderStopMarker` |
| 指令 | `world scan-stop-markers`（转交游戏端 `stop-markers scan`）、`stop-marker list`、`stop-marker remove <x> <y> <z>` |
| 只读出口 | HTTP `mmtr-stop-markers`（含 `conflict` 标记） |

#### ⚠ 两套 `fraction` 口径不同 —— 这是 P2 最容易写错的一处

| 口径 | 起点 | 谁用 |
| --- | --- | --- |
| **牌子**的 fraction | `rail.mmtrOrderedPositions()[0]` 那一端 | 登记表 / 只读出口 |
| **计划**的 `stopFraction` | **进站端**（车会从哪一头进来），1.0 = 远端 | `MmtrRunPlanner.planToRail` / `mission.setTargetRail` / 锚点判据 `fraction × 本轨长` |

换算：车从 `ends[0]` 进站 ⇒ 直接取牌子 fraction；车从 `ends[1]` 进站 ⇒ 取 `1 − fraction`。
**这一步错了的症状是"停车点被镜像到站台另一头"**，而它不会报任何错。

方向从哪来：先用**既有口径 1.0**（远端端点）探一次路，探路结果的最后一个节点就是列车要开向的那一端；
登记表里没有这个 (站台, 辆数) 的牌子时**连探路都不做**，老线路行为逐位不变（§9）。

### 12.5 与设计稿的其它差异

* §4.3 的"冲突取离站台中心最近"落成 `nearestToPlatformMid`（比**头点**的水平距离，不比牌子方块本身 ——
  那样还夹着 datumM 那一小段偏移）。
* §5.5 的引擎指令名最终是 `stop-marker`（单数），游戏端转交的字符串是 `stop-markers scan`。
* §6 的样式资源由 `mmtr/tools/stop-mark/gen_stop_marker_assets.py` 生成（`--check` 可校验），
  牌面文字由方块实体渲染器画（`RenderStopMarker`），贴图里**不写死数字**。
* §4.1 里"右键就地改辆数"就是刷子普通右键；"潜行+右键改样式"实况一致。

### 12.6 铺牌子的工具与精度

> **牌面最终长什么样（实机多轮定稿，2026-10-13）**：牌面**上面一个数字**（2…10；辆数没设写 `?`）、
> **下面一行小号 `CARS`**，两行都按字宽**居中**；**未绑定红色、已绑定白色**（不再写站台 hex）。
> 字体用**原版像素字体**（直接调 `GraphicsHolder.drawText`，不走会切平滑字体的
> `IDrawing.drawStringWithFont`）。正反**两面**都画（哪侧看都读得到），文字平面离牌面 **9 mm**。
> 朝向三条口径（面 / 平移 / 正倒左右）都是实机踩出来的，见 `RenderStopMarker` 类注释与 notes/422。

`mmtr/tools/stop-mark/mark_stop_markers.py`：按 §11 的表算牌位 → 取最近方块 → `setblock` + `data merge block`，
并且**每一步都读档验收**（目标格必须原本是空气，否则拒绝 —— 牌子常摆在站台边缘那一列，
直接 `setblock` 会把屏蔽门/玻璃顶掉）。同目录 `stop_table.py` 出表。

实测（TEST 站台 x=−45 那一列）：`y=66` 那一列整列是 APG 墙、`x=−46` 那一列是客流标记格，
两者都会被工具拦住 —— 牌位列要在铺之前先探（`sandbox/tmp/probe_marker_columns.py` 那种探针一次就够）。

### 12.7 P1（司机只读对标读数）实况

设计 §5.3 要的"同一个基准作为只读参考下发给司机"，落成**两个同步字段 + 两处显示**：

| 层 | 实况 |
| --- | --- |
| 同步字段 | `mmtrStopMarkerTargetM`（牌子说的车头停点，与 `mmtrRunStopTarget` **同一条距离坐标**；<0 = 这趟没有牌子）、`mmtrStopMarkerCars`（牌子认几辆；0 = 没有） |
| 引擎写入 | `Vehicle.mmtrMotionSelfArmMission`：用到牌子的那一刻记下辆数；计划通过后把 `plan.stopCumulativeM` 记进 target（**同一个 plan**，所以两条读数口径一致） |
| 引擎清理 | `updateMmtrSyncFields`：`mmtrMission == null || isTerminal()` 时两字段清掉（否则 HUD 会挂一个陈旧数字） |
| 客户端 | `VehicleExtension.getMmtrStopMarkerDistanceM()`（`target − railProgress`，与既有的 `getMmtrDistanceToStopTargetM` 逐字同构）＋ `MmtrTaskHud` 一行"对标点 X m（N 辆）"＋ `PdaScreen` 驾驶页一行 |
| 刹车 | **一个字都没动**：不调 `setMmtrMotionStopTarget`（notes/229 的"玩家停车不许干预"原样保留） |

没铺牌子的线路这两个字段恒为 `-1/0` ⇒ HUD/PDA **不多画一行**，老线路读数一字不变。

### 12.8 P3（批量铺站）实况：TEST 站台整套铺到 10 座标准站（2026-10-13）

**验收**（`sandbox/tmp/verify_station_standard.py`，10 座站 6 条判据一起过）**10/10 全绿**：

* 与 TEST 模板**逐格对账差量 0**（`apply_test_platform.py --check`）；

* `mtr:rail` 节点方块每站 **4 格未动**（用户口径"除了轨道外"）；
* 墙的逐列类型与 TEST 西面**逐偏移一致**（`sandbox/tmp/compare_wall.py`，0 处不符）。

**两条新纪律（都写进工具注释与 notes/424）**：

1. **牌子"铺了 ≠ 登记了"**：登记触发是"区块加载事件（每 tick 4 个待办）+ 每 60 s 的已加载区块轮转"，
   批量铺时 `forceload` 一卸就可能漏（实测只进 **35/88**）。登记表是**落盘**的 ⇒ 补法 =
   `forceload add` 本站盒 → `{"command":"world scan-stop-markers"}` → 读出口核对 → `forceload remove`。
2. **墙工具不发 `save-all flush`**：铺完立刻读存档会读上一次自动保存的状态，把铺好的墙数成缺失
   （实测把 848 数成 708）。**任何"读档核对"前都要自己 flush + 停 3 s。**

**与 TEST 的两处刻意不同**：① 两面墙**等长**（212×2；TEST 是 212/210，东面短 2 列）；
② 归属锚（`crowd_anchor`）不进复制集 —— 它是"位置由人决定"的声明块，用户现场在自己放
（下水 `(-497,66,1808)`、上水村 `(1018,66,1798/1808)`），工具只报告不删。

② 牌子可 `--clear`，墙/装饰按上述范围重铺；③ 开工前 **16 个 region 备份**在
