# 闭塞区间模型 v2：灯到灯的**跨轨有向**区间（设计 · 待实施）

> 触发（2026-09-10，用户）：「区间还是没有正确的划分出来」。
> 现状一句话：**代码按"一根轨"切区间，和实际摆灯方式（灯贴在节点上）不相容 —— 灯一个都没参与划分。**
> 本文是 v2 模型的设计与实施计划；拍板后按 §7 分片实施。
> 取代 `闭塞区间细化-灯与虚拟边界-设计.md`（v1）里"区间 = 一根轨内的弧长区间 + 节点必分"的隐含前提。

## 1. 证据（真实 dev 世界 + 代码）

`POST /mtr/api/map/mmtr-command {"command":"blocks all"}` 原文：

```
[blocks] 轨道 134 根 / 区间 134 个 / 被灯切分的轨 0 根（灯都贴在节点旁：每根轨 = 一个区间）
[blocks] 灯 -152,-60,-122 AUTO → 轨 FFFFFFB1 长=43.0 弧=0.0 贴节点（不切分）
[blocks] 灯 -168,-60,-122 AUTO → 轨 FFFFFFB1 长=43.0 弧=0.0 贴节点（不切分）
...
[blocks] 灯共 8 架：贴节点 7 / 切分轨 0 / 未生效 1
```

代码 `MmtrBlockService.buildFrom`（126–148）：

```java
final Double arc = projectArc(rail, entry.x + 0.5, entry.y + 0.5, entry.z + 0.5);
if (arc <= NODE_SNAP_M || arc >= length - NODE_SNAP_M) {
    continue; // sitting at an end node: the node is already a boundary
}
```

- `NODE_SNAP_M = 2.0 m`。
- 本世界 **8 盏灯的投影弧长全是 0.0** → **全部命中这个 `continue`** → `signalBoundaries` 是空的。
- 于是边界只剩 `buildRail` 无条件加的两个 `NODE`（轨两端）→ **134 轨 = 134 个区间，每区间就是一根 15–43 m 的轨段**，和灯无关。

**结论：不是"划得不好"，是灯一盏都没参与划分；落在地图上的结果是"按轨道段切"。**

## 2. 为什么"删掉那行 continue"也修不好

v1 的模型是「一根轨 = 一个区间，灯落在轨中段把它切成两段」：`Block` 的字段是
`railHex + arcFromM + arcToM` —— **单轨内的弧长区间**，且 `buildRail` **无条件**把两端节点当边界。

- 灯贴在**节点**上时，它在**自己那根轨**上的投影弧长必然是 0 或全长 → 在那根轨内**切不出任何东西**；
- 即使强制插进去，也只会得到一个与 NODE 重合的边界（零长度区间）；
- 而"节点必分"这条规则会**永久**把长走廊/长咽喉钉死在"轨段级"。

所以要做成「两盏灯之间 = 一个区间」，区间必须**跨越多根轨**，并且**带方向**（同一段轨在两个方向上属于不同的区间）。
这与数据结构冲突，必须改数据模型 —— 不是打补丁。

## 3. v2 模型

### 3.1 定义

> **一个有向闭塞区间 = 从某盏灯 L（含其投影点）出发，沿 L 保护的行进方向走，直到遇到同方向的下一盏灯 L'（不含），
> 或走到"走不下去"（尽头轨 / 选不出腿的道岔）为止，所经过的弧长序列。**

- 区间是**方向性**的：轨道图上的同一段弧属于"某灯 → 下一灯"和"反向的那一对灯"两个不同区间；
- **区间边界只由灯产生**（外加"走不下去"这个自然端）；**轨端节点不再是边界**；
- 一个区间 = **有序的 (railHex, arcFrom, arcTo) 列表**（跨轨），不再是单轨弧长。

### 3.2 灯 → (保护轨, 方向)

`SignalEntry` 已有 `angle`（MTR facing degrees，注释：`0 = east, clockwise`）。

1. **`target` 非空（BOUND）**：优先。取该轨为保护轨，方向由"灯相对该轨的哪一端更近/`angle`"定。
2. **`target` 空（AUTO，`signals scan` 登记）**：**必须按 `angle` 在朝向上找轨**，不能像现在这样只取最近轨
   （现在是纯距离最近，方向完全不参与 —— 面向 A 却可能绑到背后的 B）。
3. 找不到 → 该灯不产生区间（如实报告"未生效"），现状的"投影超差"就是这个情形。

> ⚠ **需要实测确认一次角的约定**：MTR 的 `angle` 与"灯看着哪个方向"的换算（`RenderSignalBase` 用
> `angle + 90` 作为走行起点方向）与 `SignalEntry.angle` 的注释（`0 = east`，顺时针）需要一次现场对齐：
> 站在某盏灯前确认它照的方向，再和 `mmtr-signals` 的 `angle` 对照一次即可定死。

### 3.3 沿方向找"下一盏灯"的走行

**复用已有的正确走行**：`MmtrSignalChain.depth`（客户端侧）已经在做"沿行进方向跨轨走"，
带 `dot > 0` 方向过滤、道岔分支、进路收窄。把同一套走行抽成引擎侧可用的纯函数即可：

- 起点 `(railHex, arc, heading)`；每步：沿当前轨走到远端节点 → 在节点处按方向挑续轨（`dot > 0`）→ 继续；
- 每进入一根轨/一个弧长点，检查**该处是否有灯的投影点**：有 → 本区间在此结束（下一区间从这盏灯开始）；
- 终止条件：无续轨（尽头）/ 所有续轨都不合方向（死端）/ 距离或轨数上限（防环，需给上限并记录）。

### 3.4 数据结构（引擎）

```
MmtrBlockService
  ├─ Section { id, direction, railSpans[(railHex, arcFrom, arcTo)], entrySignalKey, exitSignalKey }
  ├─ 查询
  │    sectionAt(railHex, arcM, heading)                  → 该点在该方向上属于哪个区间
  │    sectionAhead(railHex, arcM, heading)               → 前方第一个区间的边界距离（S1 停车用）
  │    isOccupied(section)                                → 占用（见 3.5）
  └─ 缓存：rails-signature + signals-signature 双签名门控（沿用）
```

键索引：`railHex → List<Section>`（同一根轨可能属于多个方向的多个区间）+ `sectionId → Section`。

### 3.5 占用投影

区间 = 有序弧长集合。占用投影 = 遍历区间内每个 railSpan，与共享占用树求交；任一段命中 → 区间被占。
沿用现有"写入端零改动、只换读取端粒度"的原则。

### 3.6 下游接线

| 消费方 | 现状 | v2 |
| --- | --- | --- |
| S1 停车 `Vehicle.computeMmtrBlockStopM` / `nextSectionStopM` | 本轨区间尾 / 下一区间被占 → 停边界前 | **下一（有向）区间**被占 → 停在该区间入口（= 保护它的那盏灯前） |
| 信号显示 `MmtrSignalAspect` | 按轨数闭塞链 | 链**按有向区间**走（深度 1/2/3 = 前方第 1/2/3 个区间） |
| 客户端 `MmtrSignalChain` + 镜像 | 镜像 per-rail sections | 镜像改为**有向区间**（含 railSpans 或等价的可走行表示） |
| 每区间一个保留色（B3b） | 按轨+序号 | 按 **sectionId**（更自然：一个区间一个色） |
| `MmtrBlockReport` / `blocks` 指令 | 逐灯报告 | 改为**逐区间**报告（起止灯、跨哪几根轨、总长） |
| AWS / LZB 边界 | 消费 `mmtrBlockStopM` | 自动跟随 S1（B5 的传递关系不变） |

## 4. 非目标（本轮不做）

- 不改道岔权威 / 进路锁 / 调车授权的**单位**（仍是"轨 + 节点"）；
- 不改 MTR 的轨/方块数据，不动存档格式；
- 不做"同一轨道图上双向都无灯"的补灯（属布置，不做代码）。

## 5. 验收（用真实世界数据）

1. `blocks all` 在 dev 世界：`被灯切分的轨` 不再是 0；x=−170 走廊上，`(-170,-122)→(-170,-79)` 方向
   的区间**跨越**沿线多根轨段，而不是 43 m 一根。
2. 边界点 = 灯的投影点（`弧=0.0 贴节点` 变成该灯的区间起点，而不是"不切分"）。
3. **`-170` 走廊那个现象消失**：一列车停在走廊中段时，朝南方向的灯（若有）能把它隔成一个区间；
   反向同理 —— 即"每个方向各自成链"。
4. 引擎既有用例零新增失败（现基线 **495/0/2**）；期望值变化必须逐条在 notes 里说明原因。
5. 真实世界 S1：后车停在该区间**入口（灯前）**，不再贴前车尾。

## 6. 风险与回滚

| 风险 | 缓解 |
| --- | --- |
| 走行在复杂咽喉/渡线上叉开或打环 | 距离 + 轨数上限；单测覆盖"同一轨走两次""回头腿""多分支咽喉" |
| 有向区间使区间数翻倍 | 可接受（每方向一链）；缓存按双签名失效 |
| 客户端镜像体积变化 | 未切分轨零发送的优化（B3b）保留 |
| 一次性改动面大 | 按 §7 分片，每片全量零新增失败 + notes；v1 的 `MmtrBlockService` 保留到 S3 再删 |
