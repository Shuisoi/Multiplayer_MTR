## 1. 用户口径（定案）

1. **连解挂的粒度是 Unit（连挂单元），不是车厢。**
2. **高铁动车组 8 节 = 1 个 Unit**，内部永不连解挂；两端各一个 Coupler → 支持 **8+8 重联**。
3. **机车 1 节 = 1 个 Unit**，两端各一个 Coupler。
4. **无动力挂车 = 逻辑独立、物理合并**：车底清单里是 8 个独立条目（可单独引用/派车），
   引擎里落地为**一条 8 节车列**，**每节之间都是 Coupler**（可任意切出 1..7 节）。
5. **连挂后的运动表示照 MTR 自身实现**：一个 `Vehicle` + 单 `railProgress` + 每节车自带转向架
   —— 现实列车表现，**不做多体耦合**。
6. **非动力车在物理层落地**：`MmtrCarSpec` 增 `powered` / `consistTypeId`，`Vehicle` 不再硬编码 `powered = true`。
7. **解挂只在 Coupler 处切**：作业单 `UNCOUPLE.targetIndex` 语义由"车厢序号"改为"**接缝序号**"。

## 2. 依据：MTR 的多节列车实现（代码锚点）

| 环节 | 实现 | 锚点 |
| --- | --- | --- |
| 整列车 | 一个 `Vehicle` + 单一 `railProgress`（沿 path 的累计标量） | `Vehicle.java` |
| 车厢 | `immutableVehicleCars`；每节 `length/width/capacity/bogie1Position/bogie2Position/couplingPadding1/couplingPadding2`；`hasOneBogie = (bogie1 == bogie2)` | `VehicleCar.java:8-14,39-56` |
| 转向架摆位 | 逐节累加"耦合余量 + 车长"，每节算 1~2 个转向架在 path 上的位置 | `Vehicle.getVehicleCarsAndPositions():791-810` |
| 车体姿态 | 两转向架中点作车体位置、连线定 yaw、`pivotOffset1/2` 沿车体轴修正 → 过弯折角 | `PositionAndRotation.java:28-52` |
| 渲染 | 逐车渲染车体 + **逐转向架单独渲染** + 贯通道 | `RenderVehicles.java:70-234`、`GangwayMovementPositions` |
| 长度 | `Siding.getTotalVehicleLength(cars)`（含 `couplingPadding`，首尾不加） | `Siding.java:1012`、`VehicleCar.java:52,56` |

**结论**：连挂 = 在接缝处拼接车厢列表 + 重建 `VehicleExtraData`。转向架摆位、过弯折角、贯通道、
乘客位置**零改动**——这是"符合现实列车表现"的最小代价路径，也是用户拍板选定的路线。

## 3. 概念模型

### 3.1 关键洞察：Coupler 是**语义接缝**，不是几何边界

几何上，MTR 的车厢列表在任何车厢边界都能切；本设计要表达的是**哪些边界允许切**：

```
动车组 8 节 ： [1 2 3 4 5 6 7 8]        内部无接缝；两端各一个 Coupler
              ▲                                     ▲

机车        ： [机车]                     两端各一个 Coupler
              ▲      ▲

挂车        ： [挂1]|[挂2]|[挂3]|...      每节之间都是 Coupler（可任意切）
```

于是"Unit 内部不可分"这条业务规则，落在实现上就是**那些边界没有 Coupler 对象**。
连挂/解挂的一切校验与几何，都以 Coupler 为唯一定位点。

### 3.2 MmtrUnit（连挂单元）

| 字段 | 含义 |
| --- | --- |
| `unitId` | 稳定字符串 id（清单/作业单/端点引用它） |
| `unitClass` | `EMU`（多节固定）/ `LOCO`（1 节动力）/ `WAGON`（1 节非动力） |
| `cars` | `MmtrUnitCar[]`，1..N 节；**顺序即车列顺序，Unit 内永不改变** |
| `lengthM` | Σ(车长 + 车间 couplingPadding)（首尾不加 padding） |
| `couplerA` / `couplerB` | 两端连挂端点（A = cars[0] 外端，B = cars[N-1] 外端） |

- 每节 `MmtrUnitCar` 自带 `powered` / `consistTypeId` → Unit 内可混合（本轮先同质）。
- Unit 是**编组构建的最小不可分单位**；作业单、车底清单、OP 指令都引用 `unitId`。
- `MmtrUnitCar` 是**编组核心自己的车厢类型**（不直接复用 `job` 层的 `MmtrCarSpec`），
  依赖方向固定为 **job → consist**，避免核心反向依赖 Web 编排 DTO；C2 补 `MmtrCarSpec → MmtrUnitCar` 适配。

### 3.3 MmtrCoupler（连挂端点）

| 字段 | 含义 |
| --- | --- |
| `unitId` + `end` | 所属 Unit 与端别（`A` / `B`）——**端点的身份只由这两项决定** |
| `type` | `POWERED_CONSIST`（重联：牵引并联 + 制动/控制贯通）/ `HAULED`（牵引：无牵引，仅空管贯通） |
| `airCharged` | 连挂瞬间的管压初值（`HAULED` 挂车通常 `false` → pipe = 0，随后充风） |

- **连接状态是派生的，不存储**：`MmtrFormation` 的链序**就是**连接状态——Coupler 已连 ⟺
  它不是编组的两个自由端之一。因此"一个 Coupler 最多连一个对端"（U3）是**结构性保证**，
  不可能漂移；`isCouplerFree(coupler)` 是唯一查询入口。
- **朝向**：本轮只支持 `A↔B` 同向对接（见 §8 O1）。
- **Unit id 唯一**：同一编组内 `unitId` 不得重复（否则端点身份会撞车）。

### 3.4 MmtrFormation（编组）

| 组成 | 含义 |
| --- | --- |
| `units` | 有序 `MmtrUnit` 链（相邻两 Unit 由一对 Coupler 连接） |
| `seams` | 接缝表：第 k 个接缝 = 第 k 与 k+1 个 Unit 之间（**解挂切分的唯一定位点**） |

派生（全部是纯函数，可无头测试）：

1. `carLengthsM[]` → 喂 `MmtrConsistBody`（几何/占用/信号）；
2. `MmtrComposition` → 物理层（per-Unit `powered`、空管、`stepAir`）；
3. `VehicleCar[]` → 喂 `VehicleExtraData`（MTR 运行/渲染）；
4. `seamArcM[]` → 每个接缝在编组体弧长空间的位置（用于切分与"车尾清岔"边界）。

### 3.5 三种车底的车列形态（对齐用户口径）

| 车底 | Unit 数 | 每 Unit 车数 | 接缝 | 可切位置 |
| --- | --- | --- | --- | --- |
| 动车组 8 节 | 1 | 8 | 0 | 无（仅能整列 8+8 重联） |
| 机车 | 1 | 1 | 0 | 无 |
| 挂车 8 节 | **8** | 1 | **7** | 任意 1..7 节处 |

> 挂车"逻辑独立、物理合并"：车底清单保留 8 个条目（每个 = 1 个 `WAGON` Unit），
> 引擎侧落地为**一条 8 节车列**（一个 Vehicle），节间 7 个接缝全部可切。

## 5. 连挂/解挂运行语义

### 5.1 前置闸门（引擎强制）

- 两车均**停稳**（`speed ≈ 0`，与 B 系列 I6 同源）；
- 两端 Coupler 均 `FREE`，且朝向兼容（`A↔B`）；
- 同一条轨、首尾相接（几何距离 ≤ 车钩间隙）；
- **调车授权已授**（§5.2）——越红灯进入被占用轨的许可；
- 合并后：车数 ≤ `TransportMode.maxLength`、总长 ≤ 股道 `railLength`；
- `HAULED` 连挂时挂车 `airCharged = false`（空管，随后按 `airPipeChargeRatePerSecond` 充风）。

### 5.2 连挂进路 = **调车授权（副显示）**，不是"停放窗口"

> 用户修正（2026-09-09）：MTR 每股道只允许一辆停场车**是信号原因**；现实中连挂同样要
> **信号允许越过红灯**。所以这不该靠关掉一个数据限制来做——现实里它是**副显示授权**。
> 现实基准见 `参考-英铁AWS与TPWS机制.md` §7。

连挂必须让机车**越过红灯、进入被挂车列所在的占用区段**。对应关系：

| 现实机制 | MMTR 对应 |
| --- | --- |
| 调车信号 / 呼唤显示（副显示） | 信号层新增 aspect `SUBSIDIARY_SHUNT` / `CALLING_ON`：**主显示仍红** + 副显示 |
| 授权进入占用区段 | **S1 占用加"许可式占用"例外**：授权期内该区段允许"授权列车 + 被挂车列"共存 |
| 低速、准备随时停车 | 授权移动限速（调车限速，取值见 §8 O6）+ 制动包络按"随时可停" |
| **AWS 被抑制** | **S3 在副显示授权下不触发 warning**（不响喇叭/不亮向日葵）——这是正确的现实语义，不是漏做 |
| TPWS 等效保护不施加 | **S4 保护在授权期内不判 SPAD**（否则合法连挂会被拦停） |
| 许可式工作（GKRT0044） | "一个区段多列车"的合法性来源 |

- **授权对象**：`(进路, 目标轨, 授权列车, 到期时间)`；一次授权只对**一列车**有效（不变量 U8）。
- **闸门**：车场/低速区、被挂车列已停稳、端点朝向兼容、调车进路的岔权已授。
- **撤销**：连挂完成、超时、或司机取消即撤销；撤销后占用恢复"一区段一车"。
- **落地**：`Siding.mmtrFormationWindow`（声明于 `:582`、读取于 `:299`，全仓从未赋值）
  表达的是**错误模型**，应**删除**，由信号层授权对象取代；`Siding.simulateVehicles:300`
  的单停场判定改为"无调车授权时一区段一车"。

#### 5.2.1 C3a 实现（2026-09-09 落地）

| 构件 | 位置 | 说明 |
| --- | --- | --- |
| 授权对象 | `mmtr/signal/MmtrShuntAuthority` | `Kind{SUBSIDIARY_SHUNT, CALLING_ON}` + 车底/起始轨/目标轨/限速/到期；`covers(railHex)` 判该轨是否在本次调车范围内 |

| 制式表（UNVERIFIED, O6） | `MmtrShuntAuthority.Kind` | `{抑制 AWS, 施加保护, 限速}`：副显示/呼唤均**抑制 AWS**、**不判 SPAD**、默认 **25 km/h**（15 mph 通行做法） |

| 调车限速 | `Vehicle.simulateMmtrMotion` | 授权期内按 LZB 同款"强制上限"衰减：牵引不得把速度顶在限速之上 |

#### 5.2.3 C4 连挂真手术（2026-09-09 落地）

`MmtrCoupleSurgery.couple(simulator, initiatorId, targetId)`：initiator = 顶着调车授权开上来的那列车
（它可能在前也可能在后）。闸门按序：两车都在 Motion 模式 → **都停稳** → **同一条轨** →
**同向**（`enteredFromPosition` 相同，A↔B）→ **调车授权有效且覆盖该轨** → **车钩接触**
（间隙 ≤ `COUPLER_CONTACT_M = 0.75 m`，重叠 ≤ 0.05 m 拒绝）→ 合并后节数 ≤ 模式上限、总长 ≤ 股道长。

手术本身：

| 步骤 | 做法 |
| --- | --- |
| 判定前后 | 用两车在**共享轨上的里程偏移**比较，里程大者为物理前车 |
| 合并车列 | `前车.cars + 后车.cars`（MTR car 0 = 车头，故列表即"从前到后"） |
| 保留谁 | **前车**（位置/走行器/身份参数全不动，列车不发生位移） |
| 重建数据 | 取前车 VED 的 JSON，替换 `vehicleCars` 与 `ridingEntities`（后车乘员的 `ridingCar` 加前车节数），再 `new VehicleExtraData(JsonReader)` |
| 走行器 | 编组体：`engageMmtrConsistMotion(walker, NONE)` 后 `removeKey()`——合并后司机的驾驶室变成**车厢内部**驾驶室，现两驾驶室模型表达不了，故合并后无人持钥匙、船员走到前车驾驶室重新插钥匙；legacy 走行器：`engageMmtrMotion(walker)` |
| 空管 | `mmtrSeedAirStateAfterCoupling(前车节数)`：新接入的**无动力**车 pipe=0/cylinder=0，随后按 `airPipeChargeRatePerSecond` 充风；有动力车自带压缩机保持充风 |
| 收尾 | 两辆车注销（`Siding.unregisterVehicle`，**不**清空股道模板）、合并车登记到前车股道（`adoptVehicle`）、撤销授权 |
| 身份 | 合并车沿用**前车**的 id（客户端镜像连续，只看到编组变长）；解挂时前段沿用原 id、后段是新车 |

#### 5.2.4 C4b 解挂切分（2026-09-09 落地）

| 项 | 做法 |
| --- | --- |
| 接缝（U6） | `vehicleCar.json` 新增 `mmtrCouplerAfter`：连挂手术在**接缝那节**置真（即两车对接处），随车列持久化；EMU 内部与单车机车没有接缝 → 拒绝切分 |
| 闸门 | 车辆存在、Motion 模式、**停稳**（U5）、`0 ≤ 接缝 < 节数-1`、该处确有车钩、切点在轨内（跨轨切分待 C5） |
| 切分 | 前段 = 车列 `0..k`（新的末节清掉车钩标记），后段 = `k+1..n-1`；前段沿用原 id 与位置；后段用 `MmtrMotionWalker.startAtOffset` 放在同一轨、同一方向的 `cutOffset = 头端里程 − 前段长度` 处，登记到同一股道 |
| 乘员 | 按车厢归属分到两侧，后段车厢序号重编号 |
| 空管 | 切分后两段各自保留原气压：按 `encodeAirStates` 的逐单元串在接缝处切开，分别 `applyAirStateString` |
| 车场规则 | `Siding` 的重复停放判定从"一股道一列车"改为"**同一轨同一位置**才剔除"——首尾相接的两段是合法车场状态（这正是解挂产物）；有调车授权时仍然都保留 |

#### 5.2.5 C5 编组体接入（2026-09-09 落地）

`MmtrConsistBody` 现在自带接缝：

| 项 | 做法 |
| --- | --- |
| 接缝 | `seamArcMs` / `seamCarIndexes`（与 `aEndArcM` 同一 spine 坐标系）；`seamArcMsFrom(aEndArcM, carLengthsM, couplerAfter)` 由每节车的 `mmtrCouplerAfter` 直接算出 |
| 放置 | `MmtrConsistWalker.place(...)` 新增接缝参数重载 |
| 连挂重建 | `MmtrCoupleSurgery.placeMergedConsistWalker`：从**前车 A 端**（`body().legAtArcM(aEndArcM)` + `legOffsetM`）重新 `place` 一个走行器，车列 = 合并车列、spine 自动延伸到后车所在轨——A 端零位移 |
| 占用 | 编组体改按 `body().occupancy()` 逐腿写**轨道里程**（此前写的是腿影空间，与所有读者的坐标不一致） |
| S1 间距 | 编组体新增 `mmtrConsistBodyBlockStop`：在轨道里程里算"行进方向上最近的占用面"，间距取 `MMTR_COUPLER_GAP_M`（授权）或 `MMTR_BLOCK_TAIL_GAP_M`（运行）；行进方向由**在岗驾驶室**决定（`cabs().travelsToward(End.B)`），不能用 `aheadNode()` |
| 前后判定 | `Vehicle.mmtrTravelFrame()` 返回 `[行进方向里程, 车长]`，连挂闸门用它判前后与车钩间隙（编组体的 `offsetM()` 是**前缘**，车体在其后，与 legacy 的算术相反） |

#### 5.2.6 C5b 内部驾驶室与编组体解挂（2026-09-09 落地）

| 项 | 做法 |
| --- | --- |
| 内部驾驶室 `cabAtArcM` | `MmtrCabState` 新增 `cabArcM`（从 A 端量起；`NaN` = 具名端 CAB_A/CAB_B，数值 = 编组内里程）+ `insertKeyAtArc(arc, towardA, ...)`、`isInteriorCab()`。方向仍由 facing（`activeCab()` 标签）决定，`换端` 清掉内部里程（走到另一端） |
| 连挂后钥匙 | 连挂不再拔钥匙：把机车（后车）的钥匙**按里程搬进合并编组**——`jointArc + 后车驾驶室里程`，朝向不变。于是司机连挂后**不用走动就能继续开**（这是 C4 那处取舍的修复） |
| 解挂后钥匙 | 钥匙跟着含它驾驶室的那一半走：`cabArc ≥ seamArc` → 后段（里程减 seamArc），否则前段 |
| 编组体解挂 | `uncouple` 对编组体按**接缝里程**切分：两半各自 `place` 一个新走行器（前段 A 端不变、后段 A 端 = 接缝）；跨轨切分仍拒绝 |
| 无人编组体的参考面 | `MmtrConsistWalker.referenceRail()/referenceArcM()/referenceOffsetM()`：在岗时是驾驶室朝向的那一端，无人时是 **A 端**（`currentRail()` 在无人时返回 null，但停放的编组体依然占轨） |
| 几何字段 | 手术重建 VED 时补 `patchGeometry`：`totalVehicleLength`/`defaultPosition` 是 final 的派生字段，会随 JSON 从原编组带过来，必须按新车列重算（否则车场规则、占用区间与 `getIsOnRoute()` 全错） |


### 5.3 重联 8+8

- 两 Unit 同向，`A₁` 与 `B₂` 对接，`type = POWERED_CONSIST`；
- 合并后 = 一条 16 节车列；两 Unit 牵引并联、制动贯通（`MmtrComposition` 已有 `powered` + `stepAir`）。

### 5.4 解挂切分

- 只在 `seams[k]` 处切；切分后两段**各自停稳、各自占用、各自车底条目**；
- 挂车侧保留原空管状态（`MmtrComposition.splitAfter` 已保证各侧独立气压）；
- 切分后不再出库的限制（notes/10 round16）在 **C3 调车授权**落地后**解除**。

## 6. 不变量（验收硬判据）

| # | 不变量 | 判据 |
| --- | --- | --- |
| U1 | **Unit 内部不可分** | 任何连挂/解挂都不得改变 Unit 内车厢数量与顺序 |
| U2 | **接缝守恒** | `Σ Unit.lengthM + Σ 接缝 padding = 编组总长`；合并→切分往返逐项相等 |
| U3 | **端点互斥** | 一个 Coupler 同时最多连一个对端；连挂要求两端 `FREE` 且朝向兼容 |
| U4 | **物理贯通正确** | `HAULED` 挂车 `powered=false` 且只参与空管均衡；`POWERED_CONSIST` 两 Unit 牵引并联 |
| U5 | **停稳连挂** | 连挂/解挂在 `speed ≈ 0` 才成功；解挂后两段各自停稳、各自占用 |
| U6 | **切分只认接缝** | 任何切分点必须命中 `seams[k]`；EMU 内部与机车单车无接缝可切 |
| U7 | **零回归** | 单 Unit 编组（现有全部车辆）行为与既有测试完全不变；全量 367/0/2 起每片零新增失败 |
| U8 | **调车授权互斥** | 一个区段的调车授权同时只对一列车有效；未授权列车不得进入被占用区段 |

## 8. 风险与开放问题

- **O1 重联朝向**：本轮只支持 `A↔B` 同向对接；"B 端接 B 端"（反向重联）不做。
- **O2 Coupler 类型**：先两类（`POWERED_CONSIST` / `HAULED`）；推挽（机车+控制车）暂按 `HAULED` 处理。
- **O3 挂车"8 条目 → 一条车列"的映射层级**：车底清单 / 作业单 / 编组模板三者谁来声明，C6 定。
- **O4 连挂地点**：先限定车场/低速区（`MmtrCoupling.canCoupleAtDepot` 现还要求双方 manual 股道，C4 需放宽）。
- **O5 空管初值**：`HAULED` 连挂瞬间 pipe = 0，充风速率沿用 `airPipeChargeRatePerSecond`（已实现）。
- **O6 调车授权限速与标准核对（已决策：不阻塞）**：权威条款（GERT8075《AWS and TPWS Interface
  Requirements》）为**收费标准**且本机外网不可达，无法引用条款号。因此实现为**可配置表**
  `aspect → {抑制 AWS, 施加 TPWS 等效保护, 限速}`，默认取通行做法（调车/呼唤常见 15 mph ≈ 25 km/h）
  并在代码/文档标注 `UNVERIFIED`；将来取得正文只改表、不动架构。玩法规则偏差不阻塞开发，
  但必须在文档与代码注释中显式标注（见 `参考-英铁AWS与TPWS机制.md` §7.2）。
- **O7 许可式工作的范围**：仅"授权期临时多车"（本设计），还是也支持"长期许可式区段"
  （如站台分段，GKRT0044 语义）？本轮只做前者。
- **R1 多车同轨的占用/存档面**：C3b 是唯一有系统性风险的片，须先合成世界确定性测试再上真实存档；
  C3a（授权数据面 + 抑制接线）无多车落地，可独立验证。
- **R2 legacy 车互操作**：legacy 分支（无 Unit 概念）按"单 Unit 编组"处理，行为不变。
