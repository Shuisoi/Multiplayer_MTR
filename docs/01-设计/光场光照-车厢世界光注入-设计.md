# 车厢光场光照 —— 世界光注入（设计）

> 起因（用户口径，2026-09-28）：**车厢各部分的光照要随它在世界里的真实位置变化** —— 车头在雨棚下、
> 车身在站台灯边、车尾在隧道口，各段的明暗就该各不一样。MTR 优化渲染器给整车的是**每 draw 一个光照常量**
> （按车辆位置采一次光），所以整列车一个明暗；要按世界位置取光，就得把"这个 draw 在世界哪里"的信息
> 送进着色器。
> 三条硬约束（都是用户当场拍的）：**① 光属于世界、不属于 draw**（Flywheel 的语义）；
> **② 不增加 draw call、不改批次划分**；**③ 只在 mod 自己内部改**（不动任何光影包的文件，无光影时也要对）。
>
> 本篇是**定稿后的口径真源**。逐轮的证伪、踩坑与日志原文在
> [`notes/344-MMTR光场-实现记录.md`](../../notes/344-MMTR光场-实现记录.md)（§15–§17.24），
> 那里也是"为什么不能那样做"的证据库；本篇不重复证据，只写**现在是什么、怎么用、怎么验**。

---

## 1. 一句话

每一帧把**相机周围 25×8×25 个 section** 的世界光照（方块光 + 天空光 + 实心位图）采到三张纹理里上传；
车厢的**片元着色器按自己的世界坐标**去查这三张纹理，于是同一个 draw 里每个像素各自有自己的光照 ——
**draw call 数不变**（只是每帧多两张小纹理的 `glTexSubImage2D`）。

## 2. 两条路径（同一套数学，两个消费者）

光影包开着时 MTR 的车厢由**包自己的程序**画，我们只能注入；没开时车厢走 MTR 的 core shader，我们自己说了算。
两条路共用**同一个数学实现**（`mmtr_lightfield.glsl`），只在"世界坐标从哪来"和"采样器挂哪个单元"上分叉。

| | **无光影包** | **有光影包**（Iris） |
| --- | --- | --- |
| 画车厢的程序 | MTR 自己的 core shader `mtr:core/mmtr_vehicle_light` | 包自己的 `gbuffers_entities*`（MTR 的 RenderType 被 Iris 映到它） |
| 我们怎么进去 | 直接就是 shader 主人 | **文本注入**（顶点段 + 片元段），见 §5 |
| 取光在哪个阶段 | 片元（`mmtr_vehicle_light.fsh`） | 片元（改写包 main() 里的 `lmCoordM`） |
| 世界坐标从哪来 | 顶点段算 `mmtrRelWorld = IViewRotMat * (ModelViewMat * ModelMat * Position)`，插值给片元 | **包自己算的** `playerPos = ViewToPlayer(ScreenToView(gl_FragCoord))` |
| 采样器单元 | 固定的 `Sampler3/4/5`（MTR 的 `ShaderManager` 从 `RenderSystem` 取） | 程序里**空闲**的单元（≥8，运行时枚举出来的） |
| 世界 AO | **有**（27 次实心取位 + 三线性角插值） | **暂时没有**（见 §9） |
| MTR 强制点亮的部件 | `mmtrForcedBrightUv2` 判据（车灯/显示屏/车内照明） | 同左（判据在共享核心里，两条路口径一致） |
| 光照值的落点 | 世界光照贴图色（`texture(Sampler2, light/16)`）**× AO** | 直接写回包的 `lmCoord`，由包的方块光曲线/阴影/环境接管 |

**为什么包那条路要写回 `lmCoord` 而不是"另算一个亮度加进去"**：包的下游（`lightmapXM` 方块光曲线、
天空光、阴影 `GetShadow`、环境光、漫反射）全都从 `lmCoord` 出发。另加一项会绕开这些曲线，
颜色和阴影都会和地形对不上；写回 `lmCoord` 则**下游一个字都不用改**。

## 3. 数据：光场长什么样

三张纹理，都由 `MmtrLightField` 每帧在 CPU 侧准备好、按需增量上传。**所有常量在两个语言里必须逐字一致**
（Java 侧 `MmtrLightField` 的常量 ↔ GLSL 侧 `mmtr_lightfield.glsl` 顶部的 `MMTR_*`）。

### 3.1 网格（覆盖范围）

| 项 | 值 | 说明 |
| --- | --- | --- |
| 网格 | `25 × 8 × 25` 个 section | XZ ±12（±192 格）、Y ±4（±64 格） |
| 锚点 | **相机所在的绝对 section**（`gridOrigin = (floor(camPos) >> 4) − OFFSET`） | 格点必须是**绝对**坐标；用"相机相对"会让 CPU 与 GPU 各自取整、差出相机位置的小数部分 |
| 为什么这么大 | 编组列车在站里能横跨十几个 section（实测一列车登记过 79 个） | 网格太小 ⇒ 大部分 section 落在网格外、LUT 全零 ⇒ 整车退回 per-draw 光 |

⚠️ **只有被登记的 section 才有数据**：登记来自 MTR 渲染循环里"这一帧这辆车存在"（`requestCar`，
按车辆包围盒 + 只在网格内的登记）。**相机附近的天空/地形不会自动进光场** —— 不需要，光场只为车厢服务。

### 3.2 光图集（世界光照）

- `R8UI`，1024×1024，**256 个槽位**，每槽 64×64 纹素 = 一个 section 的 16³ 个方块。
- 字节编码：**低 4 位 = 方块光，高 4 位 = 天空光**（`(block & 15) | ((sky & 15) << 4)`）。
- 槽内布局（CPU 写与 GLSL 读必须逐字一致）：

```text
u = x + (z & 3) * 16        // x∈[0,15]，z 的低 2 位选"哪一列"
v = y + (z >> 2) * 16       // y∈[0,15]，z 的高 2 位选"哪四行"
```

- 槽位 → 图集位置：`tile = (slotIndex % 16, slotIndex / 16) * 64`，其中 `slotIndex = slot − 1`（slot 从 1 起，**0 = 这个 section 没数据**）。

### 3.3 LUT（格号 → 槽位 + 元数据）

- `R32UI`，宽 `26 × 高 200`：`x ∈ [0,25)` 是格号，`x = 25`（最后一列）是**元数据**。
- 格 → 纹素：`(cellX, cellZ * 8 + cellY)`（`8 = GRID_Y`；Java 侧按同样的行主序写）。
- 元数据的第 0..6 行（`texelFetch(LUT, ivec2(25, row), 0).r`）：

| row | 内容 | 口径 |
| --- | --- | --- |
| 0/1/2 | 相机所在**方块**坐标（整数） | `floor(camera)` |
| 3/4/5 | 相机位置的小数部分 | **定点 × 65536**（GLSL 1.50 没有 `floatBitsToUint`，只能定点） |
| 6 | AO 强度 | × 1000（0 = 关掉 AO，连那 27 次取位都不做） |

**为什么相机位置必须精确到小数**：着色器只有"相机相对坐标"，要折回绝对方块只能靠这个精确值；
只给整数会让格点差出 `frac(camera)`，症状是"走动时车身光照图案在滑动、走一格重置一次"（§17 记录里的实测）。

### 3.4 实心位图（AO 用）

- `R8UI`，512×256，**一行一个 section**（行号 = 槽位 − 1），**1 bit / 方块**，一个 section 512 字节。
- 位序：`bit = x + (z << 4) + (y << 8)`；`0 = 不实心`。
- 判据用原版 AO 同一个：`BlockState.isOpaqueFullCube(...)` ⇒ 我们算出来的遮蔽与地形自己烘的遮蔽同口径。
- 槽位复用时**必须清行**：旧数据会凭空产生遮蔽（"车开到某处突然整片发暗"）。

### 3.5 采集：什么时候采、谁来采

- **登记**：MTR 渲染循环每帧对每辆车调 `requestCar(中心, yaw, 半长, 半宽)` → 把包围盒覆盖到的、
  **在网格内**的 section 记进 `requested`。
- **分配槽位**：`ensureSlot`（256 个槽位；用尽时挤掉最久没被请求的那个）。
- **采集**：每帧采**一整个 section**（`COLLECT_LAYERS_PER_FRAME = 16`，4096 次 `getLightLevel`，实测可忽略）；
  优先采**离相机最近**的（否则"玩家正看着的那节车"可能排在几十个 section 后面、一直停在"槽位已分配、图块还是零"）。
- **刷新**：收到 `LightUpdateS2CPacket` ⇒ `markChunkDirty` 把该区块列里跟踪中的 section 重新入队（放火把/拆灯）。
- **回收**：连续 `EXPIRE_FRAMES = 240` 帧没被请求 ⇒ 释放槽位。

### 3.6 采样：一个世界坐标怎么变成 (方块光, 天空光)

```glsl
ivec3 gridOrigin = (ivec3(floor(camPos)) >> 4) - MMTR_GRID_OFFSET;
vec3  exact      = relativeWorld + camPos - 0.5;    // relativeWorld = 世界 − 相机
ivec3 base       = ivec3(floor(exact));             // 最近邻方块中心
vec3  interpolant = fract(exact);
// 8 个 tap 三线性混合（与 Flywheel 的 TRI_LINEAR 同构）：
//   · 自己那一格没数据（槽位 0）⇒ 整个判无效，调用方退回自己原来的光照
//   · 网格边缘缺 tap ⇒ 退回最近邻（可预测的旧行为），AO 不参与
```

**`−0.5` 的含义**：光照值住在**方块中心**；`floor(world − 0.5)` 取的就是"离这个点最近的方块中心"。
⚠️ 车体顶点/片元常常正好落在**方块边界**上 ⇒ 单点诊断（只取一格）会读到"隔壁那格"（常见是地板/道床内部，
那里天空光本来就是 0）。**读日志时务必注意这一点**（§9）。

## 4. 无光影包路径（MTR core shader）

文件：`assets/mtr/shaders/core/mmtr_vehicle_light.vsh|fsh`（`.fsh` 里 `#moj_import <mmtr_lightfield_mtr.glsl>`，
后者 `#moj_import <mmtr_lightfield.glsl>` 拿数学）。三条口径全部是实测钉下来的，**别按直觉改**：

| 口径 | 正确写法 | 改错的症状 |
| --- | --- | --- |
| 视空间坐标 | `viewSpace = ModelViewMat * ModelMat * Position` | 少乘 `ModelMat` ⇒ 世界坐标退化 |
| 相机相对世界坐标 | `relWorld = IViewRotMat * viewSpace.xyz`（**必须再乘一次** `IViewRotMat`） | 少乘 ⇒ 光照跟着视角旋转 |
| 漫反射法线 | **视空间**：`mat3(ModelViewMat * ModelMat) * Normal`（`Light0/1_Direction` 本来就是视空间的） | 用世界法线 ⇒ 镜头一转整车亮度变 |
| AO 法线 | **世界空间**：`IViewRotMat * relativeNormal` | 用视空间 ⇒ 镜头一转遮蔽变 |

实测前提：那个 draw 时刻 `mat3(ModelViewMat)` **是单位矩阵**，**相机旋转在 `ModelMat` 里**
（MTR 的 `StoredMatrixTransformations` 是在已经压入视图矩阵的 pose 上做 translate 的）。

光照属性口径：vanilla 的 `(block*16, sky*16)`。
⚠️ **不要照抄 MTR `VertexAttributeState` 的 `exchangeLightmapUVBits`**：构造函数确实交换了两个半字，
但 `apply()` 里 `glVertexAttribI2i(loc, lightmapUV >>> 16, (short) lightmapUV)` **又反序取出**，
两次交换抵消 ⇒ 最终喂进去的正是 vanilla 口径。只看构造函数会得出"喂的是 (sky, block)"的错结论，
于是多做一次交换 ⇒ 白天整列车被"火把光"灌满、与阴影无关（= "整车亮度统一、没有暗处"）。

## 5. 有光影包路径（注入）

### 5.1 为什么必须"改写 token"，不能"用宏影子属性名"

Iris 1.7.2 的流水线是 **先完整预处理**（所有 `#define`/`#ifdef`/`#include` 求值拍平）**再 AST 改写**
（`gl_MultiTexCoord1` 是这一步才被换成 `vec4(iris_UV2, …)`）。所以我方插入的 `#define vaUV2 …`
在最终源码里**已经没有预处理器可用**，结构性无效，而且会让函数变死代码 ⇒ 连它用的 uniform 一起被删
（实测 `glGetUniformLocation` 拿到 −1）。**唯一可行的是把"引用表达式"本身包一层**
（`gl_MultiTexCoord1` → `mmtrLightFromPack(gl_MultiTexCoord1)`），Iris 随后仍会替换**内层** token。

### 5.2 顶点段注入（piece 1 + piece V）

- **piece 1**（三条原型）插在 `#version` 之后：包在文件很前面就调用这些函数。
- **piece V**（`mmtr_lightfield_pack.glsl`）插在**顶点阶段**的 `void main()` 之前
  （用条件编译栈找到它：`#ifdef VERTEX_SHADER` 内、且不在 `#ifdef FRAGMENT_SHADER` 内。
  直接取"第一个 void main"会命中**片元** main ⇒ 顶点专属代码进片元 ⇒ 编译失败、车辆全黑）。
- token 改写三处：`gl_MultiTexCoord1`/`vaUV2` → 恒等包装；`gl_Normal`/`vaNormal` → **法线包装**。
- **法线包装是这一段的实质内容**：MTR 的 `Normal` 是**模型局部空间**，而包按 vanilla 口径期待**视空间**
  ⇒ 不做转换，包的方向光照/阴影用的是"模型朝向"，症状是"车辆建模的不同面对光的反射不同"。
  运行时开关 `normalFix=`（默认 0，实测看不出差别，谁好谁坏留给眼睛）。

### 5.3 片元段注入（piece F + 锚点改写）—— 取光的正解

**根因**：用户实测"手持光源完全正常、固定光源不对"。包的手持光是**逐片元按世界距离**算的
（`lib/lighting/heldLighting.glsl`），而"改写光照属性"只能到**顶点**阶段 —— MTR 车体是大面片低模，
几个角各采一次光、中间线性插值 ⇒ **取到的光是对的，落在面上是错的**。
（§17.22 的"采样点外移"与"逐 draw 一致性"双双无效，正好排除落点与来源混用，剩下的就是粒度。）

**做法**：包在片元 main() 里**自己已经算好了逐像素世界坐标**，白送：

```glsl
vec3 screenPos = vec3(gl_FragCoord.xy / vec2(viewWidth, viewHeight), gl_FragCoord.z);
vec3 viewPos   = ScreenToView(screenPos);     // 只用 gbufferProjectionInverse 反投影，**不读深度纹理**
vec3 playerPos = ViewToPlayer(viewPos);       // = 世界 − 相机（与 held light 同一个量）
…
vec2 lmCoordM  = lmCoord;                     // ← 我们只改这一行
```

锚点改写（一行，文本替换）：

```glsl
vec2 lmCoordM = lmCoord;  →  vec2 lmCoordM = mmtrFragmentLmCoord(lmCoord, playerPos);
```

`mmtrFragmentLmCoord`（在 `mmtr_lightfield_pack_frag.glsl`）做四件事：
哨兵判定（不是 MTR 的 draw 就原样）→ 逐片元三线性取光（**不算 AO**，见 §9）→ 与包发下来的值按 `mix` 混合
→ 换算回包的空间。**值的口径不需要猜矩阵**：包自己在顶点段把光照贴图换算成了"等级/15"
（`clamp((raw − 0.03125) * 1.06667, 0, 1)`），再把 `x` 夹到 0.9（包自己注释的 "reducing the max blocklight"）
⇒ 乘 15 就是等级、除 15 就回到包的空间。

**锚点为什么挑它**：这一行之后 `lmCoordM` 一路喂给 `DoLighting/GetLighting`，下游（方块光曲线、天空光、
阴影、AO、漫反射）**一个字都不用改**。锚点实测在 `program/gbuffers_entities.glsl:144`，
而实体程序的**所有变体**（solid/cutout/alpha/translucent/glowing/diffuse）都编译同一个文件
⇒ 一个锚点覆盖全部。

### 5.4 每个 draw 的 `mmtrModelMat` 与**全零哨兵**

车体顶点在 VBO 里是**模型局部坐标**，摆放全靠 MTR 每 draw 上传的矩阵（`ModelMat`，location 6..9）；
包的程序里 `gl_ModelViewMatrix` 被 Iris 改成**相机视图矩阵**，**不含**它 ⇒ 少了这一项，算出来的"世界坐标"
退化成局部坐标、采到的光与车体真实位置无关。所以 Java 侧在 `VertexAttributeState.apply()` 处
把 MTR 的矩阵按 draw 传进 uniform `mmtrModelMat`。

**哨兵**：MTR 的 draw 出口把它置成**全零**。因为包的那个程序是**MTR 与原版实体共用**的
（`gbuffers_entities`），原版实体没有 `ModelMat`，而且它们的光照/法线本来就是逐顶点正确的
⇒ `mmtrModelMat[3][3] == 0` 就原样返回。**忘了清就是"附近的生物/物品光照跟着车厢跑"**。

### 5.5 采样器绑定（不能写死 3/4/5）

无光影时我们用 `Sampler3/4/5`；**光影下 3/4/5 是 Iris 分给 colortex/shadowtex 的单元**，抢了会让整个画面
采样到我们的 LUT（实测整屏黑）。所以光影下：运行时**枚举该 program 的所有 sampler uniform 当前占了哪些单元**
（`GL_ACTIVE_UNIFORMS` + `glGetUniformiv`），从**高位**挑 3 个空闲的（`≥8`，上限取
`GL_MAX_TEXTURE_IMAGE_UNITS` —— 这些 sampler 是在片元阶段采样的，用 `GL_MAX_COMBINED_*` 可能挑到片元阶段
不存在的单元），在 MTR 每个批次开始（`setupShaderBatchState` RETURN，program 已 bind、Iris 也绑完了）
按缓存绑一次。

⚠️ `mmtrSolid`（AO 的实心位图）**允许不存在**：片元阶段不消费 AO，编译器完全可能把它判成死代码。
绑定判据只要求 `mmtrLut`/`mmtrAtlas` ≥ 0，`mmtrSolid < 0` 只跳过它自己那一份 ——
否则"AO 不可用"会被升级成"整条取光不可用"，而且是**静默**的。

### 5.6 失败一定是安全的

锚点找不到 ⇒ 只插函数、不改包源码（函数成死代码，包照旧编译）；
自己的 GLSL 读不到 / 版本标记不匹配 ⇒ 那一处不注入。两条都只记一行日志。
**注入文本读的是自己的 classpath**（`/assets/minecraft/shaders/include/...`）——光影包是在
`MinecraftClient` 构造期间装载的，那时 `getResourceManager()` 还是 null。

## 6. 与包无关性

- 数学只写一份：`assets/minecraft/shaders/include/mmtr_lightfield.glsl`（两个消费者各自 `#define`
  采样器名字后 `#moj_import` 它）。
- 两个薄封装：`mmtr_lightfield_mtr.glsl`（无光影：Sampler3/4/5 + 光照贴图色）、
  `mmtr_lightfield_pack_frag.glsl`（有光影：空闲单元 + 写回 `lmCoord`）。
- 注入只认**包的程序名**（`gbuffers_entities*`）与**包自己算好的那一个变量**（`lmCoordM`），
  不认包的内部命名风格；判据（强制点亮、哨兵、口径换算）都在共享核心里 ⇒ 两条路的"什么算强制点亮"
  永远是同一个答案。
- 唯一与包版本有关的东西是**锚点那一行的形态**，且它**失败即安全**（§5.6）。

## 7. 开关（`run/mmtr-lightfield.properties`，每 2 秒重读）

| 键 | 作用 | 影响哪条路 | 生效 |
| --- | --- | --- | --- |
| `enabled=true/false` | 光场总开关（false = MTR 原来的 per-draw 光） | 两条 | 2 s |
| `ao=0..1` | 世界 AO 强度（0 = 连那 27 次取位都不做） | **只有无光影包那条** | 2 s |
| `debug=true` | 假色片元着色器（看光场到底有没有数据） | 只有无光影包那条 | 2 s |
| `screenshot=N` | 自动截 N 张图 | — | 2 s（改了 N 才记数） |
| `reload=<新值>` | 手动触发一次资源重载 | — | 2 s |
| `normalFix=0/1` | 把 MTR 的模型局部法线转成包期待的视空间法线 | 只有有光影包那条 | 2 s |
| `probe=0..5` | 二分定位探针（见下） | 只有有光影包那条 | 2 s |
| `mix=0..1` | 光场占比（方块光与天空光一起混）：0 = 纯 per-draw，1 = 纯光场 | 只有有光影包那条 | 2 s |

`probe` 的取值：`0` 正常；`1` 光照满亮；`2` 只把法线钉成 (0,1,0)；`3` 两者都钉；
`4` = 方块光取 `max(包发来的值, 光场值)` 的**兜底版**（历史上试过，会把 per-draw 值变成整车亮度地板，故不作默认）；
`5` = 整条路关闭（等价 `mix=0`，用来做 A/B）。

**改注入文本（GLSL）要重启客户端**：Iris 只在启动/切换光影包/重载资源时重新解析包。
只有 uniform（`normalFix`/`probe`/`mix`）能在 2 秒内热改。

`check.ps1` 除了编译+链接，还会打**注入 uniform 的位置与类型**：位置出现 −1 就说明那段代码被优化掉了

### 8.2 实机：读哪几行、读到什么说明什么

| 日志（`[MMTR-LIGHT]`） | 读到什么说明什么 |
| --- | --- |
| `光影注入 /world0/gbuffers_entities.fsh：已注入片元段（… 锚点命中 1 处）` | 片元段进了包；命中 **0 处** = 锚点与包版本脱节（只插了函数、没改包源码 ⇒ 取光不生效但不会坏） |
| `光影采样器：program N 已用单元={…} → 光场用 8/9/10` | 采样器绑上了；`已用单元` 里**不应**出现 8/9/10 |
| `mmtrModelMat 回读（program N）：… [3][3]=1.00` | 每 draw 的矩阵**真的写进了那个 program**（`[3][3]=0` ⇒ 哨兵生效 ⇒ 一路退回 per-draw 光，看起来"稳定"但那不是逐片元） |
| `光场占比 mix=… （回读 …）program N` | 开关上传值 = 回读值（不等说明 uniform 不在这个 program 里） |
| `LUT: cells=… tracked=… GPU 读回非零=…` | `cells`（网格内有效格数）> 0 且 GPU 读回非零 > 0 ⇒ LUT 真的有数据 |
| `slots=… collecting=… | section(…) block a..b avg … / sky … / 实心 …%` | 采集到的世界光照是否合理（`实心 95%` + `sky 0` = 地下 section，正常） |
| `性能：平均帧时=… ms` | 与开/关光场对照（`enabled=false`）看开销 |
| `glError=0`（`GPU readback` 那行） | 上传/回读没有 GL 错误 |

⚠️ **`车心光场采样` 这行目前是"单点 + 差半格"**（`floor(world − 0.5)`，而 `真实光照` 是 `floor(world)`）：
两者可以合法地差一格（一个落在道床内部 ⇒ `0/0`，一个在空气里 ⇒ `6/15`），**不能**据此判断"光场里没数据"。
要判断请用 `debug=true` 的假色视图或 §8.1 的离线检查（§9 列了把它升级成三线性镜像的待办）。

## 9. 已知不足与后续

1. **光影包那条路还没有 AO**。片元每像素已经是 8 次图集取位（+ 最多 8 次 LUT），AO 还要再加 27 次实心取位；
   而且要和包的 `noVanillaAO`/`signMidCoordPos` 那套共存，得先想清楚（无光影那条路 AO 是有的）。
   `mmtrSampleFieldLightOnly` 已经把这个开关做成了"整段跳过"，接的时候只需要换回 `mmtrSampleField`。
2. **`车心光场采样` 诊断应升级成"与着色器逐字同构的三线性镜像"**（现在打的是单点、还差半格，见 §8.2）。
3. **诊断日志每 5 秒 5 行**，交付后如果要静音，需要加一个 `verbose=` 开关（默认保持现状）。
4. **只接了实体程序**：地形/水/手部程序里的世界光照本来由包自己按 `UV2 + 阴影` 处理，不需要我们；反过来，
   **如果将来 MTR 的车厢换成别的 RenderType**（Iris 映到别的 program），注入目标名单要跟着加。
5. `config/iris.properties` 的 `enableDebugOptions` 是**为看 dump 打开**的；不再需要时应关掉（每次装载都会
   把全部程序写到 `run/patched_shaders`，本轮是 123 个文件）。

## 11. 踩坑清单（每条都有实测证据，详见 notes/344）

| # | 坑 | 一句话 |
| --- | --- | --- |
| 1 | 宏影子属性名 | Iris 先预处理再 AST 改写 ⇒ `#define vaUV2` 结构性无效（连 uniform 一起被删） |
| 2 | 找 `void main` | 直接取第一个会命中**片元** main ⇒ 顶点代码进片元 ⇒ 车辆全黑 |
| 3 | `lightmapUV` 轴序 | `exchangeLightmapUVBits` 被 `apply()` 反序取回，净效果就是 vanilla 口径；多做一次交换 = 白天整车被火把光灌满 |
| 4 | 强制点亮 | 车灯/显示屏/车内照明是**约定常量**（`0xF000F0` / `0xF000B0`），用世界光覆盖 = 该发光的不发光 |
| 5 | 少乘 `ModelMat` | 世界坐标退化成局部坐标 ⇒ 车身明暗无逻辑（**最关键的一处**） |
| 6 | 多乘 `gl_ModelViewMatrix` | 相机旋转乘两遍 ⇒ 镜头一转整车明暗变 |
| 7 | 相机位置只给整数 | 格点差出 `frac(camera)` ⇒ 走动时光照图案滑动、走一格重置 |
| 8 | 采样器写死 3/4/5 | 光影下那是 colortex 的单元 ⇒ 整屏黑 |
| 9 | 要求三个 uniform 都在 | `mmtrSolid` 被优化掉 ⇒ 整条取光静默失效（把"AO 不可用"升级成"取光不可用"） |
| 10 | 逐顶点取光 | 大面片低模上"光对、面不对"；正解是与 held light 同一条路：**片元 + 包自己的 `playerPos`** |
| 11 | `max(per-draw, 光场)` | per-draw 是整车的常数 ⇒ 变成整车亮度地板，固定光源的衰减永远出不来 |
| 12 | 单点诊断 vs 真值 | `floor(world − 0.5)` 与 `floor(world)` 差半格 ⇒ 两者对不上并不代表数据错 |
