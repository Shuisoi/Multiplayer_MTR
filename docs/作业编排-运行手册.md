# MMTR 作业编排（consist jobs）运行手册

> 状态：引擎层闭环已通过自动化验证（207 tests / 0 fail / 0 skip，含合成世界与真实 dev 存档冒烟）。
> 本文教你如何在游戏/独立引擎里把"车底作业单"真正跑起来，以及哪些语义约束必须遵守。

## 1. 概念速记

- 一条**作业单（consist job）** = 一辆车底一天的作业编排：
  发车股道(sidingId) + 发车时刻(startTimeOfDayMs, HH:MM) + 编组车列(cars) + 有序步骤(steps)。
- 步骤类型：
  - **MOVE_TO**：运行到站台/股道（目标=64 位 id）。目标=本作业单股道时 = "退库"（回到车场即完成）。
  - **SERVE**：当前站台停站作业，关门离站完成。
  - **COUPLE**：引用**另一条作业单的 jobId**，在本作业单**刷车时**把其车列并入本编组（make-up）。
  - **UNCOUPLE**：车场**最终切分**（按 targetIndex 切开；切分后不再出库，尾部车列写回股道留场）。
- id 说明：站台/股道/编组引用都是引擎 64 位 id，web 一律走字符串防精度丢失；
  作业单 id 是稳定字符串（每日重启、车辆全部重生后引用依然有效）。

## 2. 数据在哪

- 作业单持久化为 **<引擎数据根>/<维度>/mmtr-jobs.json**。
  - 游戏内嵌：<存档>/mtr/minecraft/overworld/mmtr-jobs.json
  - 引擎独立：<root>/<dimension>/mmtr-jobs.json（-r/--root 指定）
- 引擎启动（或每次 upsert）时读取 registry 并挂调度器；**mmtrJobsMode=true** 时老 depot 时刻表不再
  自动发车，车辆只由作业单驱动（默认 false 迁移期行为）。
- 调度器时间基准为引擎操作时钟：dayTime = (当前-锚点) mod 1 天；编辑器里发车/截止按 HH:MM（毫秒
  数 = h*3600000 + m*60000）编辑。

## 3. 编排约束（违反会被引擎拒绝/运行失败，编辑器已有提示）

1. **COUPLE 必须先于目标作业单刷车**：make-up 语义是"本作业单刷车时把目标车列并入同一编组、一次
   由引擎生成"。把 COUPLE 作业单的发车时刻设得**早于**目标（挂车源）作业单；目标 job 会被标记
   consumed（不再单独刷车）。
2. **空步骤作业单 = 纯车底源**：不需要时可不建；挂车源 job 若真刷车会停场等待收集。
3. **UNCOUPLE = 车场最终切分**：其后不要再安排出库步骤（引擎目前只支持切分后停场/留场）。
4. **股道目标移动**：MOVE_TO 支持回到本作业单自己的股道（退库）；到其它车场/任务点股道的跨车场
   进路尚未实现（属 M2 路由范围）。
5. 编组（含合并后）总长必须 <= 股道长度；车数 <= TransportMode.maxLength。

## 4. 跑通一条完整宏（自动化已验证）

"挂车源 + 机车图"配对（引擎合成世界 file-e2e 与真实 dev 存档冒烟已跑通）：

1. 建**挂车源 job**：车列=若干挂车（如 8×flatcar），无步骤（或很晚才发车以便被 COUPLE 提前并入）。
2. 建**机车 job**（同一股道，发车早于挂车源）：
   - 步骤0 **COUPLE target=挂车源 jobId**（到期前把挂车并入，3 节/9 节真实编组刷出）；
   - MOVE_TO 站台 → SERVE → … → MOVE_TO（目标=本股道，**退库**）；
   - 最后 **UNCOUPLE targetIndex=…**：把挂车切下留场、机车停场。
3. 在 MMTR Ops 面板（游戏内 web 地图 → "MMTR 任务面板 / Ops"）观察：
   等待发车 PENDING → 运行中 RUNNING（步骤 x/y）→ 已完成 DONE；失败显示红字原因。

## 5. 真机（MC+Fabric）人工联调步骤

1. 在游戏内建 depot（画框）、股道、站台与路线（世界几何来源不变）。
2. 启动服务器并确认引擎已加载（日志 "MMTR: loaded N consist job(s)" 或 "[MMTR-DBG] dimension=…"）。
3. 打开 web 地图（引擎或游戏内嵌提供的地址）→ MMTR Ops 面板 → "作业单 / Consist Jobs" → "+ 新建作业单"。
4. 按第 3 节约束编排（编辑器会提示 COUPLE 时序 / UNCOUPLE 语义）。
5. 保存后引擎 upsert 写盘并重建调度器；到点自动刷车/发车；面板轮询显示状态 feed。
6. 观察点：PENDING→RUNNING（步骤进度）；make-up 日志 "make-up: coupled <源job> stock into <job>"；
   AUTO 服务日志 "MOVE_TO done at platform"/"back at yard"；切分日志 "uncoupled N car(s) off …"。
